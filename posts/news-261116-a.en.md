## What it is
A local tool that lets you look at a coding agent's plan or code changes in the browser, mark them up, and send your notes back to the agent. Instead of scrolling a long plan in the terminal and typing "drop step 3, do step 5 like this," you highlight lines, leave comments, and hit send.

It works with a lot of agents. The README lists Claude Code, Codex, Copilot CLI, Gemini CLI, OpenCode, Kiro, Droid, Amp, Pi, and more. There are four main parts.

1. Plan review: when the agent proposes a plan, a browser tab opens on its own. Approve and it goes ahead. Deny and your comments go back as structured feedback.
2. Annotating docs and HTML: `/plannotator-annotate` works on markdown, folders, URLs, and HTML files. `/plannotator-last` annotates the agent's last reply.
3. Code review: `/plannotator-review` shows uncommitted changes, a GitHub PR, or a GitLab MR as a diff you can comment on line by line.
4. Inbox: several agents leave questions, files, and decisions in one window, and you answer when you have time. It's the newest feature, at the top of the README.

## How it runs
The README spells out the plan review flow.

1. The agent calls `ExitPlanMode` to leave plan mode.
2. A hook fires. A hook is a script that runs automatically when the agent does a certain thing. In Claude Code you attach the `plannotator` command to the `PermissionRequest` hook.
3. A local server reads the plan from the hook input and opens the review page.
4. I mark it up and approve or deny.
5. On deny, structured feedback goes to the agent. When it sends a revised plan, a diff shows what changed.

The point is that it slips in exactly where the agent was already asking a person for permission. It doesn't change the agent, only uses the harness's hooks (the harness is the outer layer that wraps the agent and manages tools, permissions, and flow). That's why the same approach fits many agents. [More → Harness](#/post/ai-harness) [More → Agent loop](#/post/ai-agent-loop)

The Inbox works a bit differently. An agent can leave a question without holding its session open, and my reply arrives as that session's next turn. Claude Code, Pi, and OpenCode connect through plugins. Other agents connect over MCP with `plannotator inbox mcp`. [More → MCP](#/post/ai-mcp)

Plans, diffs, and comments stay local by default, and it says it collects no usage telemetry. Each page does check GitHub for the latest release when it loads, and the README says there's no opt-out for that yet. If you use Ask AI or review agents, that content goes to your configured model provider.

## Why people are talking about it
More people run several agents at once now, and "where does the human step in" has become the bottleneck. This tool pulls those moments into one screen. Most of the reactions I saw on X were about liking that you can answer asynchronously.

The release pace helps too. Between Nov 11 and 15 (Korea time), v0.28.61 through v0.28.65 came out, five releases. The latest, v0.28.65, added a Take back button for a reply the agent hasn't received yet. Before, fixing a reply meant sending a second message, which could leave two different instructions in the queue.

I couldn't check how much it's going around on Reddit or YouTube.

## From a beginner's side
As a PM, it reminded me that the cheapest moment to correct an agent is the plan. Writing "don't do this" on one line of a plan costs much less than fixing code afterward. Commenting on a document is the same as a spec review, so even without coding you get a way to check agent work.

For a beginner developer, the lightest start is probably `/plannotator-last` on your agent's last reply. If you're curious about the opposite direction, compare it with yesterday's post. There the model writes review comments. Here the person writes them and the model gets them back. [More → Open Code Review](#/post/news-261115-a)

DB 学习从表和 SQL 开始，涵盖快速查找、并发使用、数据建模、其他类型的数据库、缓存以及多服务器扩展等内容。如果逐字阅读容易混淆各部分关系，因此先列出八个主题，对想深入了解的内容通过链接跳转。顺序为：基础 → 快速 → 安全 → 建模 → 类型 → 扩展。

## 一览关系图

```
관계형 DB (테이블 + 키 + SQL)
 ├─ 읽기를 빠르게   → 인덱스 (DB 안에서 찾는 비용을 줄임)
 ├─ 동시에 써도 안전하게 → 트랜잭션·격리 수준
 └─ 테이블을 어떻게 나누나 → 정규화·모델링
관계형이 아닌 저장 방식 → NoSQL, 임베딩을 담는 벡터 DB
DB까지 가지 않게 → 캐시(Redis)
DB 한 대가 모자랄 때 → 복제·샤딩
```

## 1. 基础

**关系型数据库与 SQL**：将数据分存于多个表中并通过键关联，以及用于从表中检索和修改行的语言。仅用两个表和几行查询即可体验基础操作。
[详情 → 关系型数据库与 SQL 基础](#/post/db-rdb-sql)

## 2. 快速、安全且结构合理

**索引**：一种独立的结构，通过排序数据使符合条件的行无需从头扫描即可直接定位。但每次使用时需同步更新，因此选择在哪里创建索引是一项重要工作。
[详情 → 索引](#/post/db-index)

**事务与隔离级别**：事务是将多个查询全部成功或全部失败的最小单位；隔离级别则决定同时运行的事务块之间彼此可见的程度。锁和死锁也由此产生。
[详情 → 事务与隔离级别](#/post/db-transaction)

**规范化与建模**：遵循“同一事实只记录一处”的规则，1NF~3NF 是其分阶段的标准。ERD 与非规范化也在同一篇文章中讲解。
[详情 → 规范化与建模](#/post/db-normalization)

## 3. 关系型之外的存储

**NoSQL**：并非抛弃 SQL，而是根据数据存储形态调整存储方式的集合。包括 Key-Value、Document、Column、Graph 四种类型；涉及分布式时则引出 CAP 理论。
[详情 → NoSQL 类型与选择](#/post/db-nosql)

**向量数据库**：一种用于存储嵌入（embedding）并快速检索相似内容的数据库。它以牺牲部分精度换取速度，属于近似搜索结构；文中将对比 pgvector 等开源方案与专用向量数据库。嵌入技术本身见 [嵌入与向量搜索](#/post/ai-embedding)，将搜索结果附加给 LLM 的内容见 [RAG](#/post/ai-rag)。
[详情 → 向量数据库](#/post/db-vector)

## 4. 规模扩大后

**缓存与 Redis**：缓存是将频繁读取的数据复制到就近位置；Redis 是存储这些副本的键值对服务器。难点在于处理副本与原数据不一致的情况。如果说索引降低了数据库内部的查询成本，那么缓存则让部分请求无需访问数据库。
[详情 → 缓存与 Redis](#/post/db-cache-redis)

**复制与分片**：当单台数据库达到性能极限时，读取可通过将相同数据复制到多台服务器（复制）解决；写入和容量扩展则通过拆分数据（分片）实现。但分片越多，一致性与便利性往往需要妥协。
[详情 → 复制与分片](#/post/db-scaling)

## 从哪里开始阅读

初学者建议从上至下依次阅读。若已掌握 SQL 但遇到服务变慢的情况，可按“索引 → 缓存 → 复制与分片”的顺序排查问题。若纠结于如何拆分数据，可结合规范化与 NoSQL 内容对比学习。

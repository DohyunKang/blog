A/B 测试是将同一事物制作成两种形式，随机分配展示给不同用户，并用数据来揭示哪一方的反应更好。它为“感觉上这个更好”这样的主观判断提供了数字依据，常用于选择缩略图或文案时。

## 做什么

创建两个版本：A 是当前使用的版本（对照组），B 是尝试过的新版本。将访客或观众随机分成两半，一半展示 A，另一半展示 B。随后在相同的时间段内比较点击率 (CTR)、注册率等指标。

随机分配是关键所在。如果周一发布 A、周五发布 B 再进行比较，由于星期几的差异会混杂其中，无法判断结果变化的原因。必须在同一时间段内同时向两组用户展示，才能将两组之间的差异归因于版本本身。

## 实验设计：开始前需确定的事项

开始前需明确以下四点：

| 项目 | 示例 | 备注 |
|---|---|---|
| 假设 | 添加数字的标题能提高点击率 | 每次只改变一个变量 |
| 主要指标 | 缩略图点击率 | 仅设定一个 |
| 希望捕捉的最小差异 | 3% → 3.6% | 小于此差异则放弃 |
| 样本量 | 每组约 14,000 次曝光 | 开始前计算得出 |

“一次只改变一个变量”的含义是：如果同时更改缩略图颜色和文案，将无法判断究竟是哪个因素起了作用。若希望观察多个要素的影响，可采用多变量测试这一专门方法，但所需的样本量会大幅增加。

## 样本量与指标

样本量过小可能导致某一组偶然领先。因此需预先计算“需要多少数据才能令人信服”。Evan Miller 的文章中提供了一个估算公式：每组样本量 n ≈ 16σ²/δ²，其中 δ 是要捕捉的最小差异，对于比例类指标，σ² = p(1−p)。

我的理解如下：若目标差异减半，所需样本量将增至四倍。例如，在点击率为 3% 的情况下要捕捉 0.6 个百分点的差异，按上述公式计算每组需约 13,000 人；而在相同基准下捕捉 1.5 个百分点的差异则只需数千人。试图捕捉微小差异的实验，在流量较少的场景中实际上难以实施。

以下两个数值在阅读实验结果时会伴随出现：

- 显著性水平 (α，通常为 0.05)：实际上并无差异却错误地宣称存在差异的概率上限。
- 检验力（通常为 0.8）：当实际存在差异时能够检测出该差异的概率。

p 值是指“假设两个版本实际上相同的情况下，出现当前这种差异纯属偶然的概率”，而非 B 版本更好的概率。这一点最容易引起混淆。

## 自动化方法

在营销自动化领域，通常按以下流程执行：

1. 使用 [LLM](#/post/ai-llm) 或图像生成模型生成若干文案和缩略图候选方案。
2. 将候选方案部署到曝光系统，并随机分配曝光机会。
3. 累积点击与转化日志数据。
4. 达到预设样本量后运行一次检验，选出获胜版本。
5. 将获胜版本设为默认值，并进入下一个假设测试。

生成候选方案相对容易自动化；较难的部分在于第 4 步中通过代码实现“等待达到预定样本量”的规则。关于如何汇总结果以便一目了然地查看，请参阅 [仪表板](#/post/mk-dashboard) 文章；至于选择哪些素材进行测试，则可与 [内容日历](#/post/mk-content-calendar) 或 [趋势收集](#/post/mk-trend-collect) 功能衔接。

## 常见错误

中途查看结果并提前停止实验（peeking）最为常见。Evan Miller 指出，若在中间阶段停止实验，所报告的显著性水平会出现偏差。他举例说明：某值在观察十次后显示为 1%，但实际上约为 5%。我已亲自验证：设定两个版本的实际转化率均为 3%，分别收集每组 5,000 人的假想实验数据，重复运行 1,500 次。

| 方式 | 错误得出“存在差异”的比例 |
|---|---|
| 仅在结束时检验一次 | 约 5% |
| 分十次查看，一旦发现显著即停止 | 约 21% |

即使实际上并无差异，五次观察中也可能有一次被误判为“出现了获胜者”。对于不愿等待的情况，可采用序贯检验或贝叶斯方法；Miller 的文章也指出，若提前设定中间检查时间点，即便在这些时刻查看也是允许的。

此外还有一些频繁出现的错误。

- 同时比较多个变体：如果对 5 个变体分别进行 α=0.05 的检验，只要有一个出现错误显著性，其概率约为 1−0.95⁵ ≈ 23%。正如维基百科对多重比较问题的解释，最简单的校正方法是将 α 除以变量个数（即本杰罗尼方法，5 个变体时 α 为 0.01），但更保守且更好的方法是 Holm 校正。
- 事后选择指标：如果点击率数据缺失，就查看停留时间；若仍无结果，再尝试其他指标。这也属于多重比较问题。应在实验开始前确定单一主指标。
- 仅观察短期数据：由于星期几和时间段的影响差异，已知至少需要以一周为单位进行轮换才较为安全。这一点我尚未在官方来源中得到确认。
- 新奇效应：新的缩略图在初期会因引人注目而导致反应短暂升高，随后逐渐回落。
- 将微小差异解读为显著意义：“统计显著”与“具有实际意义”是两回事。当样本量极大时，即使 0.01%p 的差异也可能被判定为显著。

## 常见误解

- p 值小于 0.05 就确定 B 更好：在 5% 的显著性水平下，即使两组无差异，20 次试验中也会出现一次这样的结果。单次检验仅代表一项证据。
- 样本量越大越好：这会导致耗时更长，且在测试期间暴露于劣质版本的成本也会增加（约为一半）。
- 不显著就意味着两者相同：并非如此。可能是未能检测到差异。应首先检查样本量是否不足。

<summary>详细解析：每组样本量计算公式与 Python 代码</summary>

这是用于比较两个比例 p1 和 p2 的标准近似公式。代码已直接运行并验证了下方数值。

```python
import math
from statistics import NormalDist
N = NormalDist()

def n_per_group(p1, p2, alpha=0.05, power=0.8):
    za = N.inv_cdf(1 - alpha / 2)
    zb = N.inv_cdf(power)
    pb = (p1 + p2) / 2
    n = (za * math.sqrt(2 * pb * (1 - pb))
         + zb * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2 / (p1 - p2) ** 2
    return math.ceil(n)

print(n_per_group(0.03, 0.036))  # 13914
print(n_per_group(0.03, 0.045))  # 2518
```

要将 3% 提升至 3.6%，每组需 13,914 人；若从 3% 提升至 4.5%，则需 2,518 人。Miller 的近似公式（16σ²/δ²）在相同条件下计算结果约为 12,933，与精确公式相差约 7%。该近似公式仅用于粗略估算。

结果解读采用两个比例的 z 检验。

```python
def ztest(c1, n1, c2, n2):
    p = (c1 + c2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    z = (c2 / n2 - c1 / n1) / se
    return 2 * (1 - N.cdf(abs(z)))

print(ztest(150, 5000, 185, 5000))  # 약 0.052
```

展示各 5000 人后，A 组获得 150 次点击（3.0%），B 组获得 185 次点击（3.7%），p 值为 0.052，勉强未达到 5% 的阈值。因此，称"B 更好”尚显模糊，若需收集更多样本，应在实验初期即做好规划。

“窥视”模拟：从两个均为 3% 的组中各抽取 5,000 人，以每 500 人为单位进行 10 次检验，只要有一次 p<0.05 即计为“存在胜者”。重复 1,500 次后，结果约为 21%；若仅在实验结束时进行一次检验，则约为 5%。具体百分比会随随机种子和迭代次数波动。

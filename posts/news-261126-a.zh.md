今天早上 GitHub 每日趋势榜上有 cathrynlavery/diagram-design。今天一天 1,133 颗星,总共 73,004 颗(11月26日上午确认)。这是一个教编码代理画图的技能。说一句"用前端、后端、数据库、Redis 缓存画个架构图",代理会选好图的类型,用一句话说明计划,然后写出一个 HTML 文件,双击就能打开。我读了 README、SKILL.md、CHANGELOG、PRIVACY.md 和两个检查脚本的开头。没有自己安装来画。

## 它做什么
技能是代理做某件事时拿出来读的一组说明:一份 SKILL.md,加上参考文档和脚本。这个仓库按这个格式来,所以一行 `npx skills add cathrynlavery/diagram-design` 就能装进 Claude Code、Codex、Cursor、GitHub Copilot、Gemini CLI 等。

输出是一个内嵌 SVG 的 HTML 文件。SVG 用坐标记录点、线和文字,是矢量格式,放大也不会糊。它不加载外部文件,方便附在邮件里或放进文档。支持架构图、时序图、状态图、ER、甘特图、四象限、漏斗等 52 种。还有导出 PNG、独立 SVG、打印用 PDF 的脚本,以及把 draw.io、Mermaid、Excalidraw、PlantUML 文件按这个风格重画的功能。

README 的副标题是 "No shadows. No Mermaid slop."。让代理画图,常见结果是加阴影、什么都上色、箭头斜着缠在一起。它要避免的就是这个。

## 把品味写成规则
SKILL.md 把设计感觉换成了相当具体的数字。

- 强调色一张图只用在 1~2 处。涂五处,强调就没了。
- 密度目标是 10 分里的 4 分。节点超过 9 个就拆成两张图。
- 箭头只能直角转弯,转角半径 8px。斜线算失败。
- 箭头标签不超过 14 个字符,大写,离线 6~10px。
- 节点的位置、大小、间距都是 4 的倍数。

画之前还有一个问题:如果表格或一段文字就够了,就别画。理念部分第一句是"最好的一步通常是删掉"。画完后用清单再看一遍:能不能去掉一个节点,能不能合并两个,能不能删掉一条箭头。

在新项目里它不会马上画。颜色和字体还是默认值的话,它会停下来问:按网站地址、设计系统文件夹,还是直接粘贴的样式值来调。给它网站地址,它就取那个网站的配色和字体,之后的图都沿用。

## 最后一步由脚本检查
读下来最显眼的是这里。规则不只写在文档里,检查输出文件的 Python 脚本也一起放进了技能。

`self_check.py` 不依赖第三方库。它检查无障碍规则(`<svg>` 上的 `role="img"`、标题和描述标签),除了允许的字体外有没有加载外部文件,有没有可执行属性,内容有没有超出画面,文件有没有中途截断或乱码。无障碍指的是让使用读屏软件的人也能获取内容。

`verify_geometry.py` 检查箭头标签下面垫的底板有没有被后画的节点挡住,以及箭头是否遵守直角规则。代理画完就跑这些,不通过就改。在人说"这几条线重叠了"之前,机器先挡下来。

仓库本身也是这样运转的。按 CHANGELOG,CI 里有对比度检查(WCAG),还有在 Chromium 里渲染所有示例的检查。版本号不是人改的,每次合并到 main 由工作流自动加一,所以到 11月25日已经是 2.6.179。

## 从入门者的角度
在策划书或设计文档里放一张架构图,通常要打开工具拖半天框。这个是用说的就能出文件。不过我觉得这个仓库真正值得看的是做法,不是图本身:把"弄好看点"这种模糊要求换成数字和清单,能检查的交给脚本检查。把设计这类靠感觉的活交给代理时,这是个可以参考的框架。

作为 PM,"画之前先问表格够不够"这条规则可以直接拿来用。文档里图多不等于好读。

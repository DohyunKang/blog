오늘 아침 GitHub 트렌딩(daily)에 google-research/paper-orchestra가 올라와 있었다. 하루에 별 1,175개, 레포 전체 별은 2,956개다(11월 18일 오전 확인). 연구 아이디어와 실험 기록을 넣으면 학회 양식에 맞춘 LaTeX 논문 초안을 뽑아 주는 멀티 에이전트 파이프라인이다. 나는 README, arXiv 초록, 프로젝트 페이지, 그리고 `methods/` 아래 코드 몇 개를 읽었고 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
Google Cloud AI Research 팀이 4월에 낸 논문(arXiv 2604.05018)의 코드다. 입력은 두 가지다. 아이디어 요약(방법과 이론을 정리한 글)과 실험 로그(표 숫자와 그림에서 읽은 관찰을 적은 글). 여기에 CVPR이나 ICLR 같은 학회의 LaTeX 템플릿과 작성 가이드를 주면 참고문헌, 그래프, 개념도까지 들어간 원고 PDF가 나온다.

멀티 에이전트는 일을 여러 LLM 호출로 쪼개고, 각자 다른 역할 설명서를 들고 맡은 부분만 하게 하는 방식이다. [자세히 → 서브에이전트](#/post/ai-subagent) 여기선 다섯 명이 나온다.

## 어떻게 굴러가는지
`paper_writer_with_plotting.py`를 따라가면 순서가 이렇다.

1. 개요 에이전트가 입력을 읽고 `outline.json`을 만든다. 섹션 구성, 그림 계획, 관련 연구를 어떤 방향으로 찾을지가 여기 들어간다.
2. 문헌 조사 에이전트와 그림 에이전트가 동시에 돈다(스레드 두 개).
3. 섹션 작성 에이전트가 개요, 인용 목록, 그림 목록을 받아 논문 전체 LaTeX를 쓴다.
4. 다듬기 에이전트가 AI 리뷰어 점수를 보며 원고를 최대 3번 고친다.

재밌는 건 2번과 4번이다.

문헌 조사 쪽은 모델이 웹 검색(Gemini의 Google 검색 도구)으로 후보 논문을 찾고, 그 제목을 Semantic Scholar API에 다시 물어본다. 검색 결과 상위 3개와 제목을 퍼지 매칭(글자가 얼마나 비슷한지 0~100으로 매기는 것)해서 70점을 넘어야 인용 목록에 넣는다. 정해 둔 날짜 이후에 나온 논문은 빼고. 모델이 그럴듯한 가짜 논문을 지어내는 걸 코드 쪽 확인으로 막는 구조다. [자세히 → 환각](#/post/ai-hallucination)

다듬기 쪽은 단순한 규칙이 박혀 있다. 고친 원고를 컴파일해서 리뷰어 에이전트에게 다시 점수를 받고, 총점이 오르면 받아들이고 다음 바퀴로 간다. 총점이 떨어지면 이전 버전으로 되돌리고 멈춘다. 총점이 같으면 세부 항목에서 떨어진 합이 오른 합보다 클 때 멈춘다. 그림 에이전트도 비슷하게 그림을 만든 뒤 비평 에이전트가 "고칠 것 없음"이라고 할 때까지 최대 3번 다시 그린다. 기본 모델은 코드상 Gemini 3.1 Pro preview, 이미지 쪽은 Gemini 3 Pro Image preview로 되어 있고 OpenAI 키로도 돌릴 수 있다. [자세히 → 에이전트 루프](#/post/ai-agent-loop)

X에서 한 사람이 "AI 리뷰어 점수가 오를 때까지 고치는 게 영리한 부분이면서 함정"이라고 쓴 걸 봤는데 나도 그 생각이 들었다. 리뷰어도 모델이라, 점수가 오른 게 진짜 좋아진 건지 그 리뷰어 취향에 맞춘 건지는 이 루프 안에서 구분이 안 된다.

## 얼마나 잘 쓰는지
논문은 CVPR 2025, ICLR 2025 논문 각 100편에서 거꾸로 아이디어 요약과 실험 로그를 뽑아낸 벤치마크(PaperWritingBench)를 만들어 평가했다. AI 연구자 11명이 블라인드로 나란히 비교했을 때, 한 번에 다 쓰게 한 단일 에이전트와 AI Scientist-v2보다 문헌 조사 품질에서 승률 차이 50~68%p, 전체 원고 품질에서 14~38%p 앞섰다고 한다. 프로젝트 페이지에는 사람이 쓴 원본 논문과는 아직 차이가 있다고 적혀 있다. 벤치마크 데이터셋은 아직 레포에 없고 나중에 따로 푼다고 되어 있다.

## 왜 지금 화제인지
레포는 5월에 만들어졌고 첫 커밋도 5월 7일이다. 그 뒤 반년 가까이 조용하다가 11월 15일(UTC)에 외부 기여자의 수정 세 개(필요한 API 키만 요구하게, 빠진 의존성 추가, LaTeX 프롬프트 문자열 오류 수정)가 머지됐고, 이번 주 트렌딩에 올랐다. 왜 하필 지금 뜬 건지는 확인 못 함.

X에서 "PaperOrchestra"가 들어간 글(리트윗 제외)은 11월 13일(UTC)까지 하루 0건이다가 14일 14건, 15일 19건, 16일 17건, 17일 54건이었다. 일본어, 폴란드어, 아랍어, 중국어 글이 섞여 있었다. 논문 한 편에 Gemini API 비용이 10달러 넘게 든다는 글, 40분이면 된다는 글도 있었는데 둘 다 내가 확인한 숫자는 아니다. Reddit과 YouTube 반응은 확인 못 함.

## 입문자 입장에서
논문을 쓸 일이 없어도 구조는 가져다 쓸 만하다. 긴 문서를 한 번에 쓰게 하지 않고 개요, 자료 조사, 본문, 검토로 나눈 점. 모델이 지어내기 쉬운 부분(인용)은 외부 API로 확인하는 점. 고치기 루프에 "점수가 떨어지면 되돌리고 멈춤" 같은 규칙을 코드로 넣어 둔 점. PM 입장에선 기획서나 리서치 리포트 자동화를 볼 때 이 순서를 체크리스트로 써도 될 것 같다.

개발 입문자라면 `methods/agents/` 아래 파일 다섯 개가 짧아서 읽기 좋다. 개요 에이전트는 60줄이다. 돌려 보려면 Python 3.11 conda 환경, Gemini나 OpenAI 키, Semantic Scholar 키가 필요하고 `paper_writing_cli.py`에 재료 폴더와 템플릿 폴더를 넘기면 된다. README 마지막 줄은 "Google 공식 지원 제품이 아님"이고, 프로젝트 페이지 윤리 항목에는 사실 확인과 책임은 사람 연구자에게 있다고 적혀 있다. 에이전트 산출물을 사람이 검토하는 화면 얘기는 며칠 전 글과 같이 보면 좋다. [자세히 → Plannotator](#/post/news-261116-a)

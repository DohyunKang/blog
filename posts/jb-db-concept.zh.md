信息处理技术员考试的数据库部分主要分为三个板块：键、关系代数以及 ER 模型。后续的正则化和 SQL 内容都建立在这些术语之上，因此先掌握这部分是正确的选择。

## 什么是数据模型

创建数据库就是将现实世界的事物以表格的形式进行映射。此时，“按照何种规则表达什么内容”的框架即为数据模型。考试中通常会从三个组成部分进行提问。

| 组成部分 | 含义 |
|---|---|
| 结构 (structure) | 数据的排列形态 |
| 运算 (operation) | 如何检索和修改这些数据 |
| 约束条件 (constraint) | 不允许输入哪些值 |

在关系模型中，结构对应关系（表），运算对应关系代数，约束条件则对应键与完整性规则。本文的三个板块正好对应这三个部分。

数据建模通常遵循“概念 → 逻辑 → 物理”的顺序进行。概念阶段细节最少，主要确定范围；逻辑阶段在不依赖特定 DBMS 的情况下详细设计结构；物理阶段则被具体技术所限制，能够实际创建表、索引和约束条件。ER 模型是概念阶段常用的工具。物理阶段的内容将在 [详见 → 数据库物理设计与分布式数据库](#/post/jb-physical-design) 中继续介绍。

## 关系模型的术语

关系模型的术语中英文混杂，建议成对记忆以便理解。

| 术语 | 含义 | 在表中对应 |
|---|---|---|
| 关系 (relation) | 属性名（头部）与元组（正文）的集合 | 一张表 |
| 属性 (attribute) | 具有名称和类型的头部单元格 | 列 (column) |
| 元组 (tuple) | 每个属性对应一个值的单行 | 行 (row) |
| 域 (domain) | 单个属性可取值的所有集合 | 整数、字符串、日期等类型 |
| 度数 (degree) | 属性的数量 | 列数 |
| 基数 (cardinality) | 元组的数量 | 行数 |

度数和基数容易混淆。可以这样记忆：度数是横向（列），基数是纵向（行）。在 ER 模型中，“基数”有时也指代如一对多等关系的数量约束，因此需要注意同一单词在不同语境下含义不同。

## 键

键是用于区分各个元组的属性（组）。范围从宽到窄依次缩小，顺序便清晰了。

| 键 | 定义 |
|---|---|
| 超键 (superkey) | 在所有元组中取值组合唯一的属性集合 |
| 候选键 (candidate key) | 在超键中，若再减少任何属性则唯一性被破坏的最小集合 |
| 主键 (primary key) | 从候选键中选出的代表 |
| 替代键 (alternate key) | 未能成为主键的其余候选键 |
| 外键 (foreign key) | 必须与另一个关系的候选键值相匹配的属性集合 |

超键仅要求唯一性，而候选键则进一步要求最小性。例如在学生表中，若 {学号} 是候选键，则 {学号，姓名} 是超键但不是候选键，因为仅凭学号已足以区分记录。如果存在如身份证号等其他候选键，未被选为主键的即为替代键。

考试中常给出一个表，询问“有多少个候选键”或“该属性能否作为主键”。解题时，先删除取值重复的列，然后在剩余列中寻找唯一性独立的项，最后再检查组合情况。若在考虑组合前已有唯一列存在，则该组合并非最小，因此不属于候选键。

## 完整性

键与约束条件紧密相关。考试中会出现实体完整性、参照完整性和域完整性。

- **实体完整性**：主键不能为 NULL，且同一表中不能有重复值。
- **参照完整性**：外键的值必须存在于被参照关系中的实际值，或者为 NULL。
- **域完整性**：属性值必须符合预定义的域范围。

设置外键后，DBMS 会拒绝违反约束的变更。例如，试图将不存在的学号插入到选课记录表中将被阻止。

<details>
<summary>参照完整性被破坏的情况总结</summary>

假设父表为“学生”（学号为主键），子表为“选课”（学号为外键，科目代码）。

| 操作 | 问题情况 |
|---|---|
| 向子表插入 | 插入父表中不存在的学号 |
| 从父表删除 | 删除被子表引用的学号 |
| 修改父表键值 | 改变被子表引用的学号 |

在删除父表记录时，应对方式可分为限制（若存在子表则拒绝）、级联（同时删除子表记录）或设为 NULL 等模式，建议分类记忆。具体语法将在 [详见 → SQL 应用](#/post/jb-sql-basic) 中讲解。

## 关系代数

关系代数是一组以关系为输入并输出关系的运算。由于结果仍是关系，因此可以连续进行运算。基本的运算如下：

| 操作 | 符号 | 作用 |
|---|---|---|
| 选择 | σ | 仅筛选符合条件的元组（行） |
| 投影 | π (Π) | 仅保留指定的属性（列） |
| 重命名 | ρ | 仅更改属性名称 |
| 并集 | ∪ | 合并两个关系中的元组 |
| 差集 | − | 仅包含前一个关系中的元组 |
| 笛卡尔积 | × | 将两个关系的元组进行所有可能的配对 |

由此衍生的操作是交集（∩）和连接（⋈）。交集可以通过并集和差集实现，而连接则是将匹配的元组组合在一起。自然连接是将属性名称相同且值相等的元组进行合并。并集、差集和交集要求两个关系的属性结构必须一致才能使用。笛卡尔积要求两个关系的属性名称不能重叠。

为了方便记忆，我将内容分为两部分：选择和投影是在单个表内部进行的裁剪操作。记住“选择是横向（行）裁剪，投影是纵向（列）裁剪”，就能减少混淆。其余操作则是合并两个表的运算。

除法（÷）是一种用于类似“选修了所有课程的学生”这类条件的操作。其定义需要单独记忆教材内容。

<details>
<summary>使用 SQL 转换并实际运行的结果</summary>

由于难以直观理解操作，我用 SQLite 创建了小型表进行对应演示。学生表为 (1 kim cs, 2 lee ee, 3 park cs)，选课表为 (1 db, 1 os, 2 db, 3 db, 3 os)。

```sql
-- 셀렉션 σ 학과='cs'
select * from student where dept='cs';
-- → (1,kim,cs) (3,park,cs)

-- 프로젝션 π 학과 (중복 제거)
select distinct dept from student;
-- → cs, ee

-- 자연 조인
select name, cid from student natural join enroll;
-- → kim db, kim os, lee db, park db, park os

-- 카티전 프로덕트: 3행 × 5행
select count(*) from student, enroll;
-- → 15
```

我也运行了集合运算。当 old={1,2}, new={2,3} 时，union 结果为 1,2,3，except 结果为 1，intersect 结果为 2。

投影操作附加 distinct 的原因在于：在关系代数中，关系是元组的集合，因此不存在重复项；而 SQL 的 select 默认保留重复项，因此必须使用 distinct 才能使两者对应一致。

</details>

## ER 模型

ER 模型是一种通过实体和关系描绘现实的概念模型。其构成要素有三类：

- **实体**：可被识别的对象，通常是名词（如学生、课程）。
- **属性**：描述实体或关系的值（如学号、姓名）。用于区分实体的属性下方加下划线。
- **关系**：实体之间的连接，通常是动词（如选修）。

考试中常见的 Chen 记法通过图形进行区分：

| 要素 | 图形 |
|---|---|
| 实体 | 矩形 |
| 关系 | 菱形 |
| 属性 | 椭圆 |

关系上附有数量约束。若一名学生可修多门课程，而一门课程可有多名学生，则为多对多（N:M）关系；若一名教授可负责多门课程，但每门课程仅由一名教授负责，则为一对多（1:N）关系。这种数量约束也称为基数（cardinality）。在另一种记法 crow's foot 中，圆圈代表 0，竖线代表 1，三叉戟代表多数，两个符号组合表示最小值和最大值。

将 ER 图形转换为表格的规则常作为考题出现。基本对应规则是：实体变为表，属性变为列，带下划线的标识属性成为主键。关于多对多关系转换等具体规则，建议对照教材图表单独记忆以确保准确。

## 常见混淆点

| 易混淆概念 | 总结 |
|---|---|
| 超键 vs 候选键 | 候选键具有最小性 |
| 度数 vs 基数 | 列数 vs 行数 |
| 选择 vs 投影 | 行过滤 vs 列过滤 |
| 主键 vs 替代键 | 从候选键中选出 vs 未选出 |
| 两种基数含义 | 关系的元组数 vs ER 图中关系的数量约束 |

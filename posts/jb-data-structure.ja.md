情報処理技術者試験のデータ構造分野は、概念を暗記するよりも手書きで追跡する練習が得点に直結します。スタックに残っているのは何か、木を巡回するとどのような順序で要素が出るか、グラフからどこを訪問するかといったことを紙に描いて確認する問題が出題されます。本稿はこの流れに沿って整理しました。試験日程や受験に関する詳細は公式ウェブサイトでご確認ください。

## 概要

| 区分 | 種類 | 核心となる問い |
|---|---|---|
| 線形 | 配列、連結リスト、スタック、キュー、デキ | どちらの端から挿入・削除するか |
| 非線形 | ツリー、グラフ | どのような順序で訪問するか |

線形構造はデータが一直線に並んだものであり、非線形構造は一つのノードから複数の分岐へ伸びるものです。試験では「次のうち線形構造でないものはどれか」といった分類確認問題や、演算を順番に適用した結果を求める問題が出題されます。

## 線形構造

配列はインデックスで直接アクセスできますが、真ん中に挿入すると後ろの要素をシフトさせる必要があります。連結リストはノードが次のノードを指す方式なので、挿入にはポインタの変更だけで済みますが、代わりに i 番目の要素を探すには先頭から順に辿らなければなりません。

| | アクセス | 中間での挿入・削除 |
|---|---|---|
| 配列 | 速い（インデックス） | 遅い（シフトが必要） |
| 連結リスト | 遅い（辿る必要がある） | 速い（ポインタ変更） |

スタックは片側のみで挿入・削除を行う後入れ先出し（LIFO）、キューは後ろに追加して先頭から取り出す先入れ先出し（FIFO）、デキは両方の操作が可能です。スタックは関数呼び出し、巻き戻し、括弧のチェックなどに使用され、キューは順番に処理するタスク待ち行列に使われます。Python でキューを作成する際は、リストの `pop(0)` が O(n) であるため `deque` を使用します。公式ドキュメントにも、deque の両端での追加・削除が概ね O(1)、リストの `pop(0)` が O(n) と記載されています。コーディング問題に関する詳細は [詳しく → スタック・キュー・デキ](#/post/algo-stack-queue) に別途記述しています。

試験ではスタックはほぼ「数式の表記変換」の問題として出題されます。

### 数式の表記法

演算子の位置によって三種類あります。

| 名前 | 演算子の位置 | 例 (A+B) |
|---|---|---|
| 前位 (prefix) | 被演算子の前 | +AB |
| 中位 (infix) | 中央 | A+B |
| 後位 (postfix) | 後ろ | AB+ |

中位を後位に変換するルールは以下の通りです。被演算子はそのまま出力し、演算子はスタックに積みますが、スタックの頂部の演算子の優先順位が同じか高い場合は先に取り出して出力します。開き括弧はスタックに積み、閉じ括弧に出会ったら開き括弧まで全て取り出します。最後にスタックに残っているものを全て取り出します。このルールに従って手書きしたコードを実行した結果は以下の通りです。

| 中位式 | 後位式 |
|---|---|
| A+B*C | ABC*+ |
| (A+B)*C | AB+C* |
| A-B-C | AB-C- |

3 つ目の例のように優先順位が同じ場合は左側から順に処理されます（左結合）。後位式の計算はより簡単です。左から読み進め、数字はスタックに積み、演算子に出会ったら二つ取り出して計算し、結果を再度積みます。`3 4 2 * +` は 4*2=8 を作り、3+8=11 となります。取り出す際、最初に現れた値が右側の被演算子である点に注意してください（減算・除算では順序が逆になります）。

<details>
<summary>変換・計算コード（実際に実行して上記結果を確認）</summary>

```python
def topost(s):
    pr = {'+': 1, '-': 1, '*': 2, '/': 2}
    st, out = [], []
    for c in s:
        if c.isalnum():
            out.append(c)
        elif c == '(':
            st.append(c)
        elif c == ')':
            while st[-1] != '(':
                out.append(st.pop())
            st.pop()
        else:
            while st and st[-1] != '(' and pr[st[-1]] >= pr[c]:
                out.append(st.pop())
            st.append(c)
    while st:
        out.append(st.pop())
    return ''.join(out)

print(topost('A+B*C'), topost('(A+B)*C'), topost('A-B-C'))
# ABC*+ AB+C* AB-C-

def ev(s):
    st = []
    for c in s.split():
        if c in '+-*/':
            b = st.pop(); a = st.pop()
            st.append({'+': a+b, '-': a-b, '*': a*b, '/': a/b}[c])
        else:
            st.append(float(c))
    return st[0]

print(ev('3 4 2 * +'))  # 11.0
```

</details>

## ツリー

ツリーはサイクルのない連結構造です。用語は試験にそのまま出題されます。

| 用語 | 意味 |
|---|---|
| ルート | 親を持たない最上位のノード |
| 末端（リーフ） | 子を持たないノード |
| 次数 | 一つのノードの子の数（木の次数はノードの次数の最大値） |
| 深さ・高さ | ルートからの距離 / 最も深い場所までの長さ |

ノードが n 個あるツリーの辺数は n-1 です。二項木では各ノードに子として最大 2 つまであります。二項木のレベル i にはノードが最大 2^(i-1) 個あり（ルートがレベル 1 の場合）、高さ h の二項木のノード数は最大 2^h - 1 です。問題でルートをレベル 0 と見るか 1 と見るかで式が変わるため、条件から読む必要があります。

### 巡回（最も頻出する部分）

深さ優先の三つは「自分自身をいつ訪問するか」だけが異なります。左サブツリーを右サブツリーよりも先に訪問するのはすべて同じです。

| 名前 | 順序 | 暗記法 |
|---|---|---|
| 前位 | 自分 → 左 → 右 | 自分が先頭 (Preorder) |
| 中位 | 左 → 自分 → 右 | 自分が中央 |
| 後位 | 左 → 右 → 自分 | 自分が最後 |

レベル順巡回は上層から一階ずつ訪問し、キューで実装します。以下の木を実際に実行した結果です。

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

| 巡回 | 結果 |
|---|---|
| 前位 | A B D E C F |
| 中位 | D B E A C F |
| 後位 | D E B F C A |
| レベル | A B C D E F |

前위・中位・後位は単にノードを見るタイミングが異なるだけなので、各ノードを「3 回訪れる点」として捉えて読み進めればミスを減らせます。自分を通る瞬間に左側を記録すれば前位、下側を記録すれば中位、右側を記録すれば後位となります。

巡回の結果から 2 つで木を復元する問題もあります。値が重複しない木であれば、前位と中位のペアだけで木の形状は一意に定まります。一方、前位・後位のペアでは常にそうとは限りませんことも知られています。復元方法は以下の通りです。前位の最初の値がルートであり、その値を中位で検索すると左側にあるものが左部分木、右側にあるものが右部分木となります。これを再帰的に繰り返します。

<details>
<summary>巡回・復元コード（実行確認）</summary>

```python
from collections import deque

class N:
    def __init__(s, v, l=None, r=None):
        s.v, s.l, s.r = v, l, r

def pre(n):  return [] if not n else [n.v] + pre(n.l) + pre(n.r)
def ino(n):  return [] if not n else ino(n.l) + [n.v] + ino(n.r)
def post(n): return [] if not n else post(n.l) + post(n.r) + [n.v]

def level(n):
    q, out = deque([n]), []
    while q:
        x = q.popleft(); out.append(x.v)
        if x.l: q.append(x.l)
        if x.r: q.append(x.r)
    return out

t = N('A', N('B', N('D'), N('E')), N('C', None, N('F')))
print(pre(t), ino(t), post(t), level(t))

def build(p, i):                      # 전위 + 중위 -> 트리
    if not p: return None
    k = i.index(p[0])
    return N(p[0], build(p[1:k+1], i[:k]), build(p[k+1:], i[k+1:]))

print(post(build(list('ABDECF'), list('DBEACF'))))
# ['D', 'E', 'B', 'F', 'C', 'A']
```

</details>

### 二分探索木とヒープ

二分探索木 (BST) は左の子が親より小さく、右の子が大きいという規則を守った木です。この木を中位巡回すると値は昇順で出力されます。50, 30, 70, 20, 40, 60, 80 を順に加えて中位巡回すると 20 30 40 50 60 70 80 が得られました。

探索・挿入・削除は平均 O(log n) です。ただし形状が入力順序に左右されるため、10, 20, 30, 40 のようにソートされた状態で入れると片寄った連結リストの形になり最悪 O(n) となります。上の木の高さは 3 で、ソートされた 4 つは高さが 4 でした。この問題を避けるためにバランスを保つ木 (AVL など) が存在します。AVL は最初の自己平衡二分探索木として知られており、挿入・削除のたびに高さをチェックして修正します。

ヒープは親が子よりも常に大きく（最大ヒープ）または小さい（最小ヒープ）完全二分木です。最大値・最小値を素早く取り出す優先度キューで使われます。Python の `heapq` で 5, 3, 8, 1, 2 を追加して一つずつ取り出せば 1, 2, 3, 5, 8 が得られます。兄弟間には大小の規則がない点が BST と異なります。コーディング問題の観点については [詳細 → 木・ヒープ・優先度キュー](#/post/algo-tree-heap) を参照してください。

## グラフ

グラフは頂点と辺の集合です。方向がある場合は有向グラフ、ない場合は無向グラフです。頂点が n 個ある無向グラフの辺の数は最大 n(n-1)/2 です。木はサイクルがなく連結されたグラフの一種とみなせます。

表現方法は 2 つあります。下のグラフ（辺 1-2, 1-3, 2-4, 3-4, 4-5）で確認しました。

| 方式 | 形状 | 空間 | 特徴 |
|---|---|---|---|
| 隣接行列 | n×n の表に辺があれば 1 | O(n²) | 2 つの頂点が繋がっているか即座に確認可能 |
| 隣接リスト | 各頂点ごとに近傍リスト | O(n+辺) | 辺が少ない場合に空間が節約できる |

無向グラフの隣接行列は対角線基準で対称です。行列の 1 をすべて足して 2 で割ると辺の数 5 が得られました。頂点 4 の近傍は 2, 3, 5 なので次数は 3 です。

### グラフ巡回

深さ優先 (DFS) はスタック（または再帰）で、幅優先 (BFS) はキューで行います。頂点 1 から始まり番号の小さい近傍から訪問すると以下のようになります。

| 方式 | 訪問順序 |
|---|---|
| DFS | 1 2 4 3 5 |
| BFS | 1 2 3 4 5 |

試験では「近傍をどの順序で選ぶか」という条件が問題に書かれているのでそのまま従えばよいです。木巡回と同様に BFS = キュー、DFS = スタックというペアだけ覚えておけば解法の方向性は決まります。実装は [詳細 → BFS・DFS とグラフ](#/post/algo-graph-search) を参照してください。

<details>
<summary>グラフコード（実行確認）</summary>

```python
from collections import deque

E = [(1, 2), (1, 3), (2, 4), (3, 4), (4, 5)]
adj = {i: [] for i in range(1, 6)}
for a, b in E:
    adj[a].append(b); adj[b].append(a)

def dfs(g, s):
    seen, st = [], [s]
    while st:
        x = st.pop()
        if x in seen: continue
        seen.append(x)
        for y in sorted(g[x], reverse=True):   # 작은 번호가 먼저 나오도록
            st.append(y)
    return seen

def bfs(g, s):
    seen, q = [s], deque([s])
    while q:
        x = q.popleft()
        for y in sorted(g[x]):
            if y not in seen:
                seen.append(y); q.append(y)
    return seen

print(dfs(adj, 1), bfs(adj, 1))
# [1, 2, 4, 3, 5] [1, 2, 3, 4, 5]
```

</details>

## よく出るパターンと解く順序

| 種類 | 解く順序 |
|---|---|
| スタック・キューの演算結果 | 演算を一つずつ適用しながら現在の状態を紙に書き留める |
| 式表記変換・計算 | 優先順位と括弧 → スタック規則に従う |
| 木巡回結果 | 自分を訪れるタイミングを確認し左側から下へ進む |
| 巡回 2 つで復元 | 前位の最初の値 = ルート、中位で左右を区別する |
| 頂点・辺の数の計算 | 頂点 n の木は辺 n-1、高さ h の二分木は最大 2^h - 1 |
| グラフ巡回 | 開始頂点と近傍選択条件を確認、DFS=スタック BFS=キュー |
| 時間複雑度の比較 | BST の平均 O(log n) と最悪 O(n) を区別する |

## よくあるミス

- キューとスタックの取り出す側を逆に適用してしまう。
- 後置式計算で減算・除算の演算子の順序を逆にしてしまう。
- レベルを 0 から数えるか 1 から数えるか確認せずに 2^h の式を使う。
- 中位と後位巡回の結果を混同する。ノードがルートの場合、後位は最後、前位は最初にあるという点で区別できる。
- BST を「常に O(log n)」と暗記してしまう。形状が片寄ると O(n) になる。

ソート・探索と計算量は、[詳細 → ソート・探索とアルゴリズムの計算量](#/post/jb-algorithm-complexity) で続きます。過去問は原文をそのまま転記しておらず、出題形式のみを整理しました。実際の問題演習は、公式に公開された過去問資料を用いて行うことができます。

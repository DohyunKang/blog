오늘 아침 GitHub 트렌딩(daily)에 GoogleChrome/modern-web-guidance-src가 2위로 올라와 있었다. 오늘 하루 별 1,875개로 그날 목록에서 가장 많았고, 레포 전체 별은 4,806개였다. 실제로 설치하는 쪽 레포(GoogleChrome/modern-web-guidance)는 별 10,960개(11월 14일 오전 확인). X에서는 "modern web guidance"가 들어간 글이 11월 9일(UTC) 1건에서 10일 84건, 11일 342건으로 늘었다(리트윗 제외, X 집계 기준). 나는 README와 1.0.0 릴리스 노트, 에이전트가 읽는 SKILL.md, 가이드 하나를 읽었고 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
코딩 에이전트가 웹 화면 코드를 짤 때 옛날 방식 대신 요즘 브라우저 기능을 쓰게 도와주는 스킬 묶음이다. 스킬은 에이전트가 필요할 때 꺼내 읽는 작업 설명서 같은 파일이다. [자세히 → 스킬](#/post/ai-skills)

README가 짚는 문제는 이렇다. 모델이 학습한 코드 대부분이 옛날 코드라서, 지금은 브라우저에 기본으로 있는 기능을 두고 무거운 자바스크립트를 새로 짠다. 모달 창을 라이브러리로 만들거나 툴팁 위치를 스크립트로 계산하는 식이다. 그래서 Chrome, Edge, Firefox, MDN 팀이 정리한 가이드를 에이전트의 컨텍스트에 바로 넣어 준다. 1.0 기준 가이드 203개, 다루는 웹 기능 250개다.

## 어떻게 도는지
구조는 단순하다. 에이전트가 HTML·CSS·브라우저 쪽 작업을 받으면 스킬이 켜지고, 아래 순서로 움직이도록 SKILL.md에 적혀 있다.

1. search: "light dismiss dialog"처럼 2~5단어 질문으로 가이드를 찾는다. 프레임워크 이름이나 앱 고유 명사는 빼라고 되어 있다.
2. retrieve: 찾은 가이드 id로 본문을 받아 와서 컨텍스트에 넣는다.
3. 검증: 짠 코드가 가이드의 패턴과 대체 코드(fallback)를 따랐는지 다시 대조한다.
4. 공개: 답변 끝에 어떤 가이드를 써서 무엇을 바꿨는지 짧게 적는다.

검색은 내 컴퓨터에서만 돈다. 작은 임베딩 모델과 BM25를 섞어 쓰고 네트워크나 API 키가 필요 없다고 한다. 임베딩은 문장을 숫자 벡터로 바꿔 뜻이 비슷한 걸 찾는 방법이고, BM25는 단어가 얼마나 겹치는지로 점수를 매기는 전통적인 검색 방식이다. [자세히 → 임베딩](#/post/ai-embedding) 다만 `npx`로 최신 패키지를 받아 오는 단계에서는 네트워크가 필요하다.

가이드 하나를 열어 보니 꽤 구체적이었다. 내비게이션 서랍(navigation-drawer) 가이드는 `<dialog>`와 CSS 스크롤 스냅으로 스와이프를 브라우저에 맡기라고 하고, "스크린 리더용 이름은 반드시 달 것" 같은 필수 항목을 주석으로 박아 둔다.

브라우저 지원 처리도 규칙이 있다. Baseline(주요 브라우저가 충분히 지원하는 기능 목록)에서 "널리 사용 가능"인 기능은 그냥 쓰고, 아닌 건 가이드의 대체 코드를 꼭 따르게 한다. 나온 지 3개월이 안 됐거나 한 브라우저만 지원하는 기능, 실험 중인 기능은 검색에는 나오지만 `.mwgrc` 설정으로 허락해야 본문을 받을 수 있다.

## 왜 화제인지
11월 10일(한국 시간)에 미리보기 딱지를 떼고 1.0.0이 나왔다. 기존 코드에서 옛날 패턴을 찾아 바꿀 가이드를 붙여 주는 `legacy-scan`이 생겼고, 검색 엔진을 TensorFlow.js에서 바꿔 npm 패키지가 23.5MB에서 8.8MB로 줄었다. 같은 시기에 운영 주체가 Chrome 단독에서 Edge, Firefox, MDN 팀까지 넓어졌다. 오늘 트렌딩에 오른 건 가이드를 만들고 평가하는 소스 레포 쪽이다.

평가 방식이 같이 공개된 것도 눈에 띄었다. 실제 웹앱에 "이미지 좀 빨리 뜨게 해 줘" 같은 요청을 API 이름 없이 주고, 가이드 있을 때와 없을 때 에이전트의 통과율을 Playwright 검사로 비교한다. 채점기는 정답 코드에서 100% 통과, 손대지 않은 앱에서 100% 실패하도록 먼저 맞춰 둔다. README의 11월 8일 결과는 Claude Code(opus-5-5)가 57%에서 88%, Codex CLI(gpt-6.1-sol)가 54%에서 82%, Antigravity CLI(gemini-4-argon)가 58%에서 94%였다. 프로젝트가 직접 잰 숫자이고 나는 재현하지 않았다. [자세히 → 평가(evals)](#/post/ai-evals)

Reddit과 YouTube에서 얼마나 돌았는지는 확인 못 함.

## 입문자 입장에서
PM 입장에서는 "모델이 모르는 걸 학습으로 가르치지 않고 문서로 넣어 준다"는 접근이 와닿는다. 모델을 바꾸지 않고 필요한 순간에 짧은 가이드만 꺼내 주니까, 이미 모델이 잘하는 내용은 평가 결과를 보고 가이드에서 지운다고 한다. 개발 입문자라면 설치 전에 `npx modern-web-guidance@latest search "animate a dialog modal backdrop"`처럼 검색만 해 보거나, 내 작은 프로젝트에 `legacy-scan .`을 돌려 보는 정도로 시작하면 될 것 같다.

주의할 점. 익명 사용 통계를 수집한다. 설치 수, 호출한 에이전트 이름, 가이드 id, 에이전트가 만든 검색어가 들어가고 사용자 원문 프롬프트는 안 모은다고 적혀 있다. `DISABLE_TELEMETRY=1`로 끌 수 있다. `legacy-scan`은 전체 가이드의 약 20%만 검사한다. 프론트엔드 쪽 접근성이 궁금하면 이 글도 같이 보면 좋다. [자세히 → 접근성](#/post/fe-accessibility)

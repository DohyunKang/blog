ADsP 2 과목（データ分析企画）では、課題の発掘からマスタープラン、ガバナンス、成熟度、プロジェクト管理へと続く区間です。計算問題はなく、用語や分類を正確に区別できるかを問う内容ですので、表にまとめておけば選択肢を絞り込みやすいでしょう。試験日程や受験に関する内容は公式サイトで確認してください。

前単元は [分析企画の理解](#/post/adsp-planning) と [分析方法論](#/post/adsp-methodology) です。そこで分析対象と方法に応じてタイプを分類したのであれば、この稿ではそれらから導かれた課題を実際にどのような順序で実行するかを定める段階です。

## 課題はどのように見つけるか

課題を見つける方法は二つあります。

| | トップダウン | ボトムアップ |
|---|---|---|
| 出発点 | 解決すべき問題が既に存在する | 問題を知らず、データから見る |
| 適用場所 | 分析対象が明確な場合 | 新しいインサイトを見つける場合 |
| 進行 | 問題探索 → 問題定義 → 解決策の探索 → 妥当性検証 | 仮説生成 → 実験 → 実環境でのテスト → 仮説確認 |
| ツール | ビジネスモデル、外部参照モデル | 探索的データ分析、非教師あり学習、プロトタイピング |

トップダウン型の問題探索はさらに二つに分かれます。内部の業務・製品・顧客を見るビジネスモデルに基づくものと、類似業界を参照する外部参照モデルに基づくものです。探索結果は分析ユースケース（問題の説明と解決した際の期待効果）として整理します。このユースケースをデータ分析課題に変換し、適切かを評価する流れです。最後の妥当性検証では、経済的妥当性とデータ・技術の適用可能性を同時に検討します。

分析企画段階で事前に検討すべき事項は三つに整理されています。利用可能なデータ、適切なユースケース、障害要因（コスト、精度、組織能力、変化管理）に対する事前計画です。利用可能な人材については、この三つには含まれないとまとめた資料があるため、選択肢に混ざって出題された場合は注意が必要です。

課題を解決する方法は、既存システムが存在するか、分析能力があるかによって分かれます。

| 既存システム | 分析能力 | 方向性 |
|---|---|---|
| あり | あり | 既存システムと人材を活用 |
| あり | なし | 教育または採用 |
| なし | あり | システムの高度化 |
| なし | なし | 専門業者へのアウトソーシング |

## 優先順位：緊急性と難易度

見つけた課題を一度にすべて行うことはできないため、順序を定めます。基準は二つの軸です。

| 軸 | 見るもの |
|---|---|
| 緊急性 | 戦略的重要性、目標価値。今必要なか、後で必要なか |
| 難易度 | データの取得・保存・加工コスト、分析適用コスト、分析レベル |

二つの軸を掛け合わせると四つの領域が生まれます。

| 緊急性 | 難易度 | 備考 |
|---|---|---|
| 現在 | 簡単 | まず行う |
| 現在 | 困難 | 緊急性優先なら二位 |
| 未来 | 簡単 | 難易度優先なら二位 |
| 未来 | 困難 | 最後にする |

中央の二つの順序は、緊急性を先に見るか難易度を先に見るかによって変わります。ある整理資料（IT Wiki）では、四象限番号で緊急性優先が III → IV → II → I、難易度優先が III → II → IV → I と記していました。ただし、この資料でも番号は資料ごとに異なるため、属性として記憶するよう付け加えています。したがって暗記する際は番号ではなく、「現在・簡単が 1 位、未来・困難が最下位」と捉えました。問題で四象限図が出たら、番号ではなく軸名を先に確認します。

核心的な基準は緊急性です。難易度は会社の事情に合わせて調整可能です。今必要だが困難な課題については、データ量や分析範囲を減らして難易度を下げた上で先に着手することもできます。

## マスタープランとロードマップ

マスタープランは、確定した課題をいつ、どのような順序で実行するかを計画したものです。優先順位を定める際に考慮する要素は、戦略的重要性、ビジネス成果（ROI）、実行の容易性です。

適用範囲と方式を定める際には三つを確認します。

| 要素 | 水準を分ける問い |
|---|---|
| 業務内蔵化 | レポートや画面で提供するか、業務プロセスやシステムに組み込んで自動化して活用するか |
| 分析データ | 内部データのみを使うか、外部・非構造化データまで広げるか |
| 技術 | 既存システムと技術で済ませるか、新しい分析・ビッグデータ技術を導入するか |

移行ロードマップは 3 つの段階からなります。

1. データ分析体制の導入：分析機会の発掘、課題定義、ロードマップ策定
2. データ分析有効性の検証：アルゴリズム設計、アーキテクチャ設計、パイロット実行
3. データ分析の普及と高度化：変化管理、システム構築、関連システムの高度化

パイロットでまず効果を確認し、その後に普及させる順序が核心です。個人情報の匿名化などの項目は、この考慮要素には含まれません。

## ガバナンス体制

分析ガバナンスとは、組織が分析を継続的に実行し、業務に定着させるよう管理する体制です。構成要素は五つあります。

| 요소 | 내용 |
|---|---|
| Organization(組織) | 分析企画・管理組織の位置と形態 |
| Process(プロセス) | 課題発見、企画、実行、管理の手順 |
| System(システム) | 分析に使用する IT システムとツール |
| Data(データ) | 標準化、品質、セキュリティ管理（データガバナンス） |
| Human Resource(人的資源) | 人材確保、役割定義、教育体制 |

データガバナンスは、分析ガバナンスに含まれる要素の一つである。両者を同じ言葉で書いた選択肢は誤りである。

分析組織構造は 3 つのタイプに分けられる。

| タイプ | 特徴 | 弱点 |
|---|---|---|
| 集約型 | 専任組織が全社分析を担当する | 現場との業務が重複する可能性がある |
| 機能中心型 | 別組織なしで現場部署が直接分析を行う | 全社レベルでの核心分析が困難である |
| 分散型 | 分析人材を現場部署に配置する | その代わりベストプラクティスの共有は容易である |

課題管理は、課題発見（アイデア発見 → 課題候補提案 → 課題確定）と課題実行（チーム編成 → 実行 → 進行管理 → 結果共有・改善）の順序で行う。成果物と経験はプールに集め、次の課題で再利用する。

## 準備度と成熟度

組織の現在の分析レベルは 2 つの観点から診断する。

準備度は 6 つの領域を見る：分析業務、人材および組織、分析手法、分析データ、分析文化、IT インフラ。成熟度は導入 → 活用 → 普及 → 最適化の 4 つの段階のうちどこにあるかを、ビジネス、組織・能力、IT セグメントごとに評価する。

準備度と成熟度をそれぞれ「高い/低い」に分けると 4 つのタイプが生まれる。

| タイプ | 準備度 | 成熟度 | 方向性 |
|---|---|---|---|
| 準備型 | 低い | 低い | 分析準備から行う |
| 定着型 | 低い | 高い | 既に分析中なので体系的に定着させる |
| 導入型 | 高い | 低い | 準備ができているためすぐに導入できる |
| 普及型 | 高い | 高い | 継続的に普及させる |

定着型と導入型が混同しやすい。名前ではなく「準備度と成熟度のどちらが高いか」で判断する。定着型は成熟度が高く、導入型は準備度が高い。

## プロジェクト管理の 10 つの知識領域

分析課題もプロジェクトであるため、PMBOK の知識領域に基づいて管理する。PMBOK 6 版基準では 10 つある。

| 領域 | 行うこと |
|---|---|
| 統合 | プロジェクト全体の要素を一元化して調整する |
| 範囲 | プロジェクトに含まれる作業を定義し統制する |
| 工期 | 作業順序・所要時間を推定し統制する |
| コスト | 予算を推定し統制する |
| 品質 | 成果物が基準を満たすようにする |
| リソース | チームとリソースを確保し管理する |
| コミュニケーション | ステークホルダーへ向ける情報フローを管理する |
| リスク | リスクを特定・分析・対応・監視する |
| 調達 | 外部企業から物品・サービスを取得する |
| ステークホルダー | 影響を受ける人々を把握し参加させる |

PMBOK 7 版（2021）では、この知識領域の代わりに 8 つの成果領域に変更された。試験教材がどの版基準かについては、教材の説明も併せて確認する。

## よく出るタイプ

- トップダウンとボトムアップの区別：「問題が先に与えられる」場合はトップダウン、「データを先に見る」場合はボトムアップ。
- 優先順位ボックスの選び方：現在・容易さが先、未来・困難さが最後。中央は基準が緊急性か難易度か確認する。
- 適用範囲・方式要素の 3 つのうち欠落しているものを見つける：業務内実装、分析データ、技術。それ以外の項目が混ざっていると誤答。
- ガバナンス構成要素 5 つと組織構造 3 タイプの特徴を一致させる。
- 定着型・導入型のように準備度・成熟度の高低からタイプ名を見つける。
- ロードマップの順序：システム導入 → 有効性検証（パイロット）→ 普及・高度化。

解答する際は、選択肢のキーワードをまず見る。「パイロット」は 2 ステップ、「変化管理」は 3 ステップ、「アイデア発見」は 1 ステップでほぼ絞り込める。過去問は公式サイトや教材で直接解く方がよい。

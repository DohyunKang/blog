오늘은 개인 프로젝트에서 터미널 도구 하나에 로그인을 다시 하다가, 로그인이 생각보다 여러 겹이라는 걸 알게 된 날이었다.

## 코드를 받아서 브라우저에 넣는 로그인

점검을 맡길 AI 도구를 하나 더 붙여 보려는데, 그 도구가 로그인이 안 돼 있어서 아무것도 못 했다. 터미널 프로그램은 화면에 로그인 창을 띄울 수가 없다. 그래서 쓰는 게 기기 코드 방식이다. 터미널이 짧은 코드를 보여 주면, 나는 브라우저에서 그 코드를 넣고 승인한다. 그동안 터미널은 서버에 "승인됐어?"를 계속 물어보다가, 승인되면 토큰을 받아 간다. TV 앱에 로그인할 때 휴대폰으로 코드 넣는 거랑 같은 거다. OAuth 안에 있는 방식 중 하나라고 한다.

비밀번호는 터미널에 한 번도 안 들어간다. 터미널은 토큰만 받는다. 그게 이 방식의 좋은 점 같다.

## 엉뚱한 계정에 붙었다

그런데 로그인하고 보니 내 계정이 아니라 다른 계정으로 붙어 있었다. 이유는 단순했다. 코드를 넣은 브라우저가 이미 다른 계정으로 로그인돼 있었다. 기기 코드 방식은 "지금 브라우저에 로그인된 사람"이 승인하는 구조라서, 브라우저 쪽 계정이 그대로 따라온다. 공용 PC면 이런 일이 쉽게 생긴다.

고치는 순서는 이랬다. 먼저 로그아웃해서 저장된 토큰을 지운다. 한 번 받은 토큰은 파일로 저장돼서 다음에도 계속 쓰이니까, 지우지 않으면 다시 로그인해도 예전 계정이 남을 수 있다. 그다음 브라우저를 내 계정으로 바꾸고 나서 코드를 넣는다. 마지막으로 어떤 계정으로 붙었는지 확인하는 명령을 한 번 돌려 본다.

## 콜론 하나 때문에

로그아웃 명령을 치다가 뒤에 콜론이랑 이메일을 붙였더니, 로그아웃은 안 되고 프로그램 대화 화면이 새로 켜졌다. 터미널 프로그램은 첫 단어가 정해진 하위 명령(로그인, 로그아웃 같은)과 정확히 같아야 그 명령으로 알아듣는다. 글자가 하나라도 붙으면 그냥 "처음 보내는 질문"으로 받아들인다. 명령줄 인자는 생각보다 글자 그대로 읽힌다.

1. **기기 코드 방식**은 터미널이 코드를 보여 주고 브라우저에서 승인하는 로그인이다. 터미널은 토큰만 받는다.
2. **어느 계정으로 붙는지**는 코드를 넣는 브라우저가 정한다. 공용 PC면 먼저 확인한다.
3. **로그아웃**은 저장된 토큰을 지우는 일이다. 계정을 바꾸려면 이것부터.
4. **하위 명령**은 글자가 정확히 맞아야 한다. 뭔가 붙으면 다른 뜻이 된다.

로그인 한 번에 확인할 게 세 군데였다.

コーディングテストの問題を見ると「これはどんなタイプだろう」と途方に暮れてしまいます。そこで、アルゴリズムに関する 11 編の文章をタイプごとに要約しました。まずは計算量で時間内に解けるかを見極め、その後に「データ構造 → 探索 → グラフ → 最適化」の順に分類しています。解説とコードは各記事にあります。

## 問題を見て選ぶ順序

| 問題に見えるもの | まず思い浮かべるタイプ |
|---|---|
| 入力サイズが大きい、二重ループなら時間超過になる | 計算量で推定 → ハッシュ・累積和・両指針 |
| 「既に見た値か」、個数カウント | ハッシュ |
| 連続区間の和・長さ | 累積和、両指針、スライディングウィンドウ |
| 括弧、「右側から最初に出てくる大きい数」、順次処理 | スタック・キュー |
| ソート済みデータからの検索、「最大いくらまでか」 | バイナリサーチ、パラメトリックサーチ |
| すべてのケースを試すが詰まったら戻ってくる | 再帰・バックトラッキング |
| 格子・点・辺でつながった構造 | BFS・DFS |
| 辺にコストがあり、同じグループをまとめる、前後関係 | ダイクストラ、ユニオンファインド、トポロジカルソート |
| 小さな問題の答えを再利用する | DP |
| いつもっと最良のものを選ぶように見える | グリディ（反例確認） |
| 最小（最大）のものを繰り返し取り出す | ヒープ・優先度キュー |

## 1. 基礎：計算量

**時間計算量と Python の基本**: 入力サイズだけで「この解法なら時間内に終わるか」を推測する方法、Python で特に遅くなる箇所、コーディングテスト用の入出力の基本。
[詳しく → 時間計算量と Python の基本](#/post/algo-complexity)

## 2. データ構造で解くタイプ

**配列・文字列・ハッシュ**: 同じものを二度数えずに一度数えて記録しておくタイプです。記録する場所は累積和配列かハッシュ（dict, set）です。
[詳しく → 配列・文字列・ハッシュ](#/post/algo-array-hash)

**スタック・キュー・デッキ**: 最後に入れたものを取るか、最初に入れたものを取るかの違いです。括弧チェック、次大値、カードを回すような問題がここに出ます。Python ではリストと deque を区別できればほとんど解けます。
[詳しく → スタック・キュー・デッキ](#/post/algo-stack-queue)

**木・ヒープ・優先度キュー**: 木は巡回順序をコードですぐに書けるかが半分であり、ヒープは最小（最大）のものを続ける問題で heapq を使います。
[詳しく → 木・ヒープ・優先度キュー](#/post/algo-tree-heap)

## 3. 範囲を狭めていくタイプ

**両指針・スライディングウィンドウ・累積和**: 連続区間の問題で、区間を毎回足し直すのではなく端だけを動かして O(N) で解く三つの方法です。
[詳しく → 両指針・スライディングウィンドウ・累積和](#/post/algo-two-pointer)

**ソートとバイナリサーチ**: ソートはほぼ `sorted()` で終わりますが、練習すべきはソート済みデータから半分ずつ捨てるバイナリサーチと、答え自体をバイナリサーチするパラメトリックサーチです。
[詳しく → ソートとバイナリサーチ](#/post/algo-sort-search)

## 4. ケースを追うタイプ

**再帰とバックトラッキング**: 再帰は小さな同じ問題に変えること、バックトラッキングはその再帰で選択肢を一つずつ試して詰まったら戻ってくる探索です。順列・組合せ・N-Queens が代表題です。
[詳しく → 再帰とバックトラッキング](#/post/algo-recursion)

**BFS・DFS とグラフ**: 次に見る場所をキューに積むかスタックに積むかだけが異なります。連結成分、迷路の最短距離、領域サイズなどの格子問題も同じ枠組みで解けます。
[詳しく → BFS・DFS とグラフ](#/post/algo-graph-search)

**最短経路・ユニオンファインド・トポロジカルソート**: BFS・DFS の上でよく出る三つです。コストがついた道の探索（ダイクストラ）、同じグループをまとめる（ユニオンファインド）、順序を決める（トポロジカルソート）。
[詳しく → 最短経路・ユニオンファインド・トポロジカルソート](#/post/algo-shortest-path)

## 5. 答えを最適化するタイプ

**動的計画法 (DP)**: 同じ部分問題を二度解かないように答えを記録しておく方法です。漸化式を立てるだけでコードはついてきます。ナップサック、LIS、硬貨の問題を取り扱います。
[詳しく → 動的計画法 (DP)](#/post/algo-dp)

**グリディ**: 瞬間的に最も良さそうなものを選んで振り返らない方式です。この方式が正しい問題と間違える問題を区別することが核心なので、反例確認も併せて扱います。
[詳しく → グリディ](#/post/algo-greedy)

## 学習順序の提案

計算量で感覚を掴んだ後にデータ構造（ハッシュ、スタック・キュー）→ バイナリサーチ・両指針 → 再帰・BFS・DFS → DP・グリディ の順に見ると、前の記事が後の記事の材料になります。ダイクストラとヒープはグラフとデータ構造を見た後の方が良いでしょう。

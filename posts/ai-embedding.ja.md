埋め込み（Embedding）とは、文章（または画像）を数字のリストに変換し、「意味が似ていると数字も近くなる」ように事前に準備しておくことです。ベクトル検索は、その数字たちの中で近いものを探す作業です。

## 埋め込みとは何か

OpenAI のドキュメントでは、埋め込みを「テキストを表す浮動小数点数のベクトル（リスト）」として説明しています。2 つのベクトル間の距離がテキスト間の関連性を表し、距離が短いほど関連性が高いという仕組みです。

これを地図に例えると理解しやすいでしょう。ソウルと釜山の緯度・経度の 2 つの数字で位置が決まり、2 つの座標が近ければ 2 つの都市も近いのです。埋め込みは、この座標を文章に付与するものです。ただし、数字が 2 つではなく数百〜数千個です。OpenAI のドキュメントにあるモデル基準では、`text-embedding-3-small` は基本的な 1536 次元、`text-embedding-3-large` は 3072 次元です。次元数はモデルによって異なります。

この座標は人間が決めるものではありません。埋め込みモデルは学習プロセスを通じて、似た文脈で使われる文章を近くに配置するように学びます。この発想は、単語単位では 2013 年の word2vec 論文（Mikolov ら）で広く普及しました。Green の基準によると、大規模なデータから単語の連続ベクトル表現を安価に学習する構造を 2 つ提案し、単語類似度テストで当時の最高水準を達成したと主張しています。現在の文章・ドキュメント埋め込みはその延長線上にあると理解していますが、系譜を正確に追跡したわけではありません。

LLM が内部で単語を数字として扱う話は [詳細 → LLM](#/post/ai-llm) にあり、ここで言う埋め込みは「検索・比較用に 1 つの文章を 1 つのベクトルに変換したもの」に近いものです。

## コサイン類似度

2 つのベクトルの近さを測る方法はいくつかありますが、テキストではコサイン類似度が最もよく使われます。2 つのベクトルが作る角度を見ます。同じ方向なら 1、直角なら 0、反対方向なら -1 です。長さは見ず、方向のみをみます。

| 値 | 意味 |
|---|---|
| 1 に近い | 方向がほぼ同じ、意味が似ている |
| 0 の近く | 関連性がほとんどない |
| 負の値 | 反対方向（実際のテキスト埋め込みでは稀であると言われている） |

OpenAI のドキュメントはコサイン類似度を推奨しており、自社の埋め込みは長さが 1 に正規化されているため、内積を計算するだけで同じ結果が得られると記載しています。コサイン距離とユークリッド距離が同じ順位を与えるという話もあります。長さが 1 のベクトル同士であれば、角度の順序と距離の順序が一致するためです。そのため実際のコードでは「正規化して置いて内積」で終わることが多いです。

<details>
<summary>詳しい解説：コサイン類似度の式</summary>

2 つのベクトル a, b に対するコサイン類似度は以下の通りです。

cos(a, b) = (a · b) / (|a| × |b|)

a · b は各桁の数字を掛けて足し合わせたもの（内積）であり、|a| はベクトルの長さです。2 つのベクトルを事前に長さが 1 に合わせれば分母が 1 になり、内積そのものがコサイン類似度になります。正規化を保存する際、一度だけ行っておけば検索時に乗算・足算のみ残るため高速です。

</details>

## キーワード検索との違い

キーワード検索は、質問に含まれる単語がドキュメントにそのまま存在するかを見ます。正確な用語、製品コード、エラーメッセージを探す際にはよく合致します。ただし、単語が異なると見つかりません。

| | キーワード検索 | ベクトル検索 |
|---|---|---|
| 基準 | 単語が重なるか | 意味が近いのか |
| " 환불 방법" で "결제 취소 절차" ドキュメントを探す | 単語が違うため見逃しやすい | 意味が似ていれば捉える |
| エラーコード `E4012` を探す | 正確に捉える | 意味のない文字列なので弱い |
| 結果の理由 | どの単語が合致したか表示される | なぜ近いと言ったかを説明するのが難しい |
| 準備物 | インデックス | 埋め込みモデル + ベクトルストレージ |

そのため実務では両方を組み合わせるケースが多いと言われています（ハイブリッド検索）。この部分は公式ドキュメントを読んで確認したわけではなく、一般的にそう言われている程度として受け入れています。検索結果を LLM に付け加えて答えさせる方式は [詳細 → RAG](#/post/ai-rag) で続きます。

## 自分で動かしてみた最小限のコード

本物の埋め込みモデルを使わなくても、「ベクトルを作り、正規化し、近いものを探す」という骨格は numpy のみで確認できます。以下は軸を意図的に 3 つ（動物、食べ物、乗り物）に手作りで作った玩具です。実際のモデルはこの数字を直接生成する点だけが異なります。このコードは自分の PC で実行して動作を確認しました（numpy 2.5.4）。

```python
import numpy as np

# 손으로 만든 3차원 벡터 (축: 동물, 음식, 탈것)
docs = {
    "고양이가 잔다":     [0.9, 0.1, 0.0],
    "강아지가 뛴다":     [0.8, 0.1, 0.1],
    "김치찌개를 끓인다": [0.1, 0.9, 0.0],
    "자전거를 탄다":     [0.1, 0.0, 0.9],
}
names = list(docs)
M = np.array([docs[n] for n in names], dtype=float)
M /= np.linalg.norm(M, axis=1, keepdims=True)   # 길이 1로 정규화

def search(q, k=2):
    q = np.array(q, dtype=float)
    q /= np.linalg.norm(q)
    scores = M @ q                  # 정규화했으니 내적 = 코사인
    for i in np.argsort(-scores)[:k]:
        print(f"{scores[i]:.3f}  {names[i]}")

search([0.85, 0.15, 0.0])           # "동물 쪽" 질문
```

実行すると「猫が寝る」が約 0.998、「犬が走る」が約 0.991 で上位に現れます。食べ物・乗り物の文章は下に押し下げられます。

本物のモデルに変えるには、数字を作る部分だけを差し替えるだけで済みます。以下は sentence-transformers を使う形式です。

```python
# pip install sentence-transformers 필요
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("all-MiniLM-L6-v2")   # 모델 이름은 예시
vecs = model.encode(["환불 방법", "결제 취소 절차"], normalize_embeddings=True)
print(vecs @ vecs.T)   # 정규화했으니 내적 = 코사인 유사도 표
```

## ベクトル DB と ANN

このコードは、質問ベクトルを文書全体と比較します。文書が数百件であれば問題ありませんが、数百万件になると、各質問に対して全比較を行うのは遅くなります。そのため、「最も近いもの」ではなく「ほぼ最も近いもの」を非常に速く見つける手法を採用します。これが近似最近傍探索（ANN, Approximate Nearest Neighbor）です。精度を少し犠牲にして速度を得ます。

ベクトル DB はベクトルを保存し、ANN インデックスを作成しておき、近接したものを検索してくれるストレージです。日付や著者などのメタデータでフィルタリングする機能も通常付いています。製品名は多くありますが、本稿では特定の製品との比較を行っていません。

ANN アルゴリズムの中で頻繁に名前が挙がるのが HNSW です。2016 年の論文（Malkov & Yashunin）の要約によると、層状に積み重ねた近傍グラフで構成され、上位層では広く探索し、下位層では絞り込んでいく構造です。探索計算量は対数規模で増加すると主張しています。スキップリスト（skip list）との構造が似ているという説明もあります。

比喩を言えば、世界中の地図で道路を探す場合、まず高速道路マップで大まかに移動し、そこで街の地図に切り替えるようなものです。この比喩は私が理解するために付けたもので、論文の表現ではありません。

<details>
<summary>詳細な解説：精度を下げる代償</summary>

ANN は最も近いものを逃す可能性があります。そのため、「本当に近い上位 k 件中何件を見つけたか」を「再現率（recall）」という値で計測します。HNSW の要約では、近傍選択ヒューリスティックが高い再現率の区間で性能を大幅に向上させたとしています。インデックスパラメータを大きくすると、再現率は向上しますが、速度とメモリは悪化するといったトレードオフがあります。

</details>

## よくある誤解

- エンベッディングが意味を理解していることと同義である：学習データで似た文脈にあった文章が近接して配置されるという意味に近いです。「近い」という基準はモデルが学んだことに依存します。
- 類似度が 1 に近いなら同じ言葉である：反対の意味の文書でも同じ主題であれば近い結果になることがあるそうです。実際に実験することはできませんでした。
- ベクトル検索がキーワード検索を代替する：正確なコードや名称の検索ではキーワードの方が優れています。そのため、両方を組み合わせて使用します。
- 次元が大きければ必ずしも良いわけではない：OpenAI のドキュメントでは `dimensions` で次元を減らし保存容量に合わせることもできるとあります。大きければ情報量は多いですが、保存コストも高くなります。品質の差については文書以外で私が測定したものはありません。
- モデルを変えても既存のベクトルをそのまま使える：モデルごとに座標系が異なるため、混在して比較すべきではないと理解しました。これは原理上の推論であり、ドキュメントで直接確認することはできませんでした。

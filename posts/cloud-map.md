서비스를 만들고 나면 그걸 어디에 올리고, 어떻게 내보내고, 뜬 뒤에는 어떻게 지켜볼지가 남는다. 이 시리즈는 그 순서대로 여섯 개념을 다룬다. 큰 단어를 한 줄씩만 먼저 적고, 더 알고 싶은 건 아래 링크로 넘어가게 했다. 순서는 서버를 빌리는 것에서 시작해 운영 쪽으로 간다.

## 한눈에 보는 흐름

```
클라우드(서버를 빌린다)
   ├─ 앱을 묶어 옮긴다 ........ Docker·컨테이너
   └─ 서버 관리를 맡긴다 ...... 서버리스
코드 → 테스트 → 배포 ........... CI/CD
설정과 비밀번호를 코드 밖에 둔다 .. 환경변수·시크릿
뜬 뒤에 상태를 지켜본다 ........ 모니터링·로그·알림
```

## 1. 어디에 올리나

**클라우드 기초**: 서버를 사는 대신 쓴 만큼 빌려 쓰는 방식이다. 서버의 어느 층까지 내가 맡느냐에 따라 IaaS, PaaS, SaaS로 나뉘고, 리전·AZ라는 위치 개념과 쓴 만큼 내는 비용 구조가 붙는다.
[자세히 → 클라우드 기초](#/post/cloud-basics)

**Docker와 컨테이너**: 앱과 실행에 필요한 파일을 묶어 격리된 프로세스로 돌리는 도구다. 내 PC에서 되던 게 서버에서 안 되는 문제를 줄이려고 쓴다.
[자세히 → Docker와 컨테이너](#/post/cloud-docker)

**서버리스**: 서버가 없는 게 아니라 켜고 끄고 늘리는 일을 클라우드가 맡고, 나는 함수 코드만 올리는 방식이다. 요청이 올 때만 실행되고 돈도 그때만 나간다.
[자세히 → 서버리스](#/post/cloud-serverless)

## 2. 어떻게 내보내나

**CI/CD와 배포 전략**: 코드를 합치고 테스트하고 내보내는 과정을 자동으로 돌리는 것이다. 마지막 내보내는 단계를 안 터지게 하는 배포 방식 세 가지도 같이 다룬다.
[자세히 → CI/CD와 배포 전략](#/post/cloud-cicd)

**환경변수와 시크릿 관리**: 비밀번호나 키는 코드 밖에 두는 게 기본이다. .env로 시작해서 시크릿 매니저와 로테이션까지 단계가 있다.
[자세히 → 환경변수와 시크릿 관리](#/post/cloud-secrets)

## 3. 뜬 뒤에 어떻게 지키나

**모니터링·로그·알림**: 서비스가 아픈 걸 사용자보다 먼저 알기 위한 준비다. 메트릭·로그·트레이스를 나눠 보고, 알림은 무엇에 걸어야 하는지 정리했다.
[자세히 → 모니터링·로그·알림](#/post/cloud-observability)

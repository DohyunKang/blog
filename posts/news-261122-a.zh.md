## 它是什么
技能是代理需要时拿出来读的说明书。[详细 → 技能](#/post/ai-skills) 这个仓库把 83 个技能打包在一起，另有 15 个斜杠命令。不用点名调用，只要说出自己在做什么，比如"我在测这个目标"，对应主题的技能就会自动加载，README 是这么写的。

README 的分类大致如下。

1. 按 Web 漏洞类型分的 hunt-* 技能 58 个。据说是从 HackerOne 上公开的 681 份报告里提炼的模式。
2. M365、Okta、VPN 设备等企业平台相关技能 10 个。
3. 验证发现、写报告的技能 6 个。
4. 侦察与公开情报收集技能 5 个，方法论技能 4 个。

安装是在 Claude Code 里输入 `/plugin marketplace add` 和 `/plugin install` 两行。技能文件格式是通用的，所以也能复制到 OpenCode、Codex CLI 等其他代理工具里。不过斜杠命令和自动执行引擎只支持 Claude Code。

## 里面怎么运转
流程是 scope → recon → rank → hunt → validate → report。定范围、摸底、排出先看哪里、动手找、验证、写报告。

让我注意的是分工。engine.py 开头的说明写着：范围检查、状态保存、任务分派、排序、去重、报告整理都由固定的代码完成，模型只用于侦察、查找和验证。范围外的主机由代码从侦察结果里过滤掉，范围外的目标根本不会派代理过去。不是拜托模型"别碰范围外的东西"，而是代码直接拦住。每一步都会保存状态，中途断了也能接着跑。

另一个是 7-Question Gate。写报告之前按顺序问 7 个问题，有一个答不上来，这个发现就丢掉。第一个问题是"攻击者现在能一步步用上它吗"，还会问是否在范围内、是否属于项目认可的影响类型。文档里列了这道关卡拦下的误报例子：响应里出现了自己的输入，结果只是页面原样回显 URL；或者只有状态码变了，正文一模一样。算是防止模型硬说自己找到了像样东西的装置。

## 自己测的数字还很薄
eval 文件夹里有个装置，用同样的任务对比开启和关闭技能的效果，和之前看过的 SkillEvaluator 是一个思路。[详细 → SkillEvaluator](#/post/news-261119-a) 但 BASELINE.md 里最新的结果(8 月 25 日)只有故意做成有漏洞的练习站 OWASP Juice Shop 的 3 道题，开不开技能都全做出来了，开了反而多花了一点轮数和费用。作者自己也写了，这些题简单到模型可能早就记住了，测不出技能的效果。更难的题(PortSwigger 实验)因为账号问题还没跑。所以"装了技能就找得更好"这件事，在这个仓库里还没有用数字证实。

## 为什么现在火
仓库是 5 月建的，最后一个版本是 v2.1(6 月 5 日)，不是因为新版本才火的。不过这周提交很多：11 月 18 日加了 HackerOne MCP 服务器，到 20 日一直在修 Windows 兼容问题。X 上提到这个仓库的帖子(不含转推，按 UTC 日计)11 月 16 日 59 条，18 日 66 条，21 日 60 条。趋势介绍机器人帖子里的星数，11 月 15 日是 6,380，20 日是 13,043，一周翻了一倍多。具体起因没能确认。Reddit 上的反应也没能确认。

README 里有一段挺有意思。按 README 的说法，Anthropic 的模型默认会拦下攻击性安全工作的请求，有一部分会转给更低一级的模型来回答。所以即使是授权的工作也可能被拒，这时 README 建议去申请 Anthropic 的网络安全认证计划。它还写着，不要把攻击工作改说成防御工作来蒙混过关。模型这一侧的安全措施我之前整理过。[详细 → 护栏](#/post/ai-guardrails)

## 从入门者的角度
先说清楚：这是只能用在自己的、或者有书面授权的目标上的工具。README 也这么写，未经允许拿去对别人的服务用是违法的。

撇开这点，从 PM 的角度值得看的是结构。出错代价大的部分(范围、状态、去重)交给代码，只有需要判断的部分交给模型，然后再用一份问题清单把模型的结果筛一遍。这个套路放到安全以外的业务自动化里也一样能用。防守一方的类似工具，我之前看过 OpenAI 的 Codex Security。[详细 → Codex Security](#/post/news-261113-a)

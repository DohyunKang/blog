# 최단 경로·유니온 파인드·위상 정렬

[BFS·DFS](#/post/algo-graph-search)로 그래프를 도는 법은 익혔다. 이번 글은 그 위에서 자주 나오는 세 가지다. 간선에 비용이 붙었을 때 가장 싼 길을 찾는 다익스트라, 누가 누구와 같은 그룹인지 빠르게 판단하는 유니온 파인드, 선후 관계가 있는 일을 순서대로 나열하는 위상 정렬이다. 셋 다 코드는 짧은데 "언제 이걸 써야 하는지"를 알아보는 게 더 어렵다.

## 한눈에 비교

| 알고리즘 | 이럴 때 | 핵심 도구 | 시간 |
|---|---|---|---|
| 다익스트라 | 가중치(0 이상)가 있는 그래프에서 한 점에서 다른 점까지 최소 비용 | 우선순위 큐 | O(E log V) |
| 유니온 파인드 | 두 원소가 같은 집합인지, 집합 합치기 | 부모 배열 | 연산당 거의 O(1) |
| 위상 정렬 | 선후 관계가 있는 작업의 순서, 사이클 판별 | 진입차수 + 큐 | O(V+E) |

## 최단 경로: 다익스트라

### 유형 설명

BFS는 간선 하나를 1칸으로 셀 때만 최단 거리를 준다. 간선마다 비용이 다르면 "거친 간선 수"가 아니라 "비용 합"이 기준이어야 한다. 다익스트라는 시작점에서 가장 가까운 점부터 확정해 나간다.

원리는 이렇다. 시작점 거리를 0, 나머지는 무한대로 둔다. 아직 확정 안 된 점 중 거리가 제일 작은 점을 꺼내 확정하고, 그 점을 거쳐 가면 이웃이 더 가까워지는지 본다. 더 가까워지면 갱신한다. 비용이 음수가 아니면 꺼낸 시점의 거리가 이미 최소라서 다시 볼 필요가 없다. "가장 작은 것을 빨리 꺼내기"가 필요하니 힙(우선순위 큐)을 쓴다.

음수 간선이 있으면 이 가정이 깨진다. 위키피디아 예시로는 s→a 2, s→b 5, b→a −10인 경우, a를 2로 확정해 버리지만 s→b→a가 −5다. 이럴 땐 벨만-포드를 쓴다.

### 대표 문제

- 프로그래머스 배달: 마을 N개가 양방향 도로로 이어져 있고, 1번 마을에서 K시간 이내에 갈 수 있는 마을이 몇 개인지 센다. 1번 마을에서 모든 마을까지 최단 거리를 구해 K 이하를 세면 된다.
- 프로그래머스 합승 택시 요금: 출발점에서 두 목적지까지 공유 구간을 어떻게 나누면 싼지, 다익스트라를 여러 번 돌려 푼다.

### 풀이 생각 순서

1. 간선에 비용이 있고 음수가 아닌지 본다. 모두 1이면 BFS로 충분하다.
2. 한 시작점에서 전체인지, 모든 쌍인지 본다. 모든 쌍이고 정점이 작으면(수백 개) 플로이드-워셜도 후보다.
3. 인접 리스트를 만들고, 거리 배열을 무한대로 채우고, 힙에 (0, 시작점)을 넣는다.
4. 힙에서 꺼낸 거리가 현재 기록된 거리보다 크면 이미 낡은 항목이니 건너뛴다.
5. 이웃을 갱신하고 힙에 넣는다.

### Python 코드

```python
import heapq

def dijkstra(n, graph, start):
    INF = float('inf')
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:        # 이미 더 짧은 길로 처리된 낡은 항목
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

간선 (1,2,2) (1,3,5) (2,3,1) (2,4,7) (3,4,2) (4,5,1)을 양방향으로 넣고 1번에서 출발해 돌려 보니 `[inf, 0, 2, 3, 5, 6]`이 나왔다(0번 칸은 안 쓰는 칸). 1→2→3 경로가 5짜리 직행보다 싸게 잡힌 걸 볼 수 있다.

### 복잡도

힙을 쓰면 O((V+E) log V), 연결 그래프에서는 O(E log V)다. 위 코드는 갱신 때마다 새로 push하고 낡은 항목은 꺼낼 때 버리는 방식인데, 위키피디아에서도 decrease-key 대신 이렇게 하는 방법을 소개한다. 공간은 O(V+E).

## 유니온 파인드

### 유형 설명

"A와 B가 같은 그룹인가", "두 그룹을 합쳐라" 같은 질문이 계속 들어올 때 쓴다. 각 원소가 부모를 가리키고, 부모를 따라 올라가 루트에 닿으면 그게 대표다. 루트가 같으면 같은 그룹이다.

그냥 구현하면 한쪽으로 길게 늘어진 트리가 생겨 find가 O(n)까지 갈 수 있다. 그래서 두 가지를 얹는다. 경로 압축은 find할 때 지나간 노드를 루트에 바로 붙이는 것이고, 크기(또는 랭크) 기준 합치기는 작은 트리를 큰 트리 밑에 붙이는 것이다. 둘을 같이 쓰면 연산 m번에 Θ(m·α(n))이고, α는 역아커만 함수라 현실적인 n에서는 4 이하다. 사실상 상수로 본다.

### 대표 문제

- 프로그래머스 네트워크: 컴퓨터 연결 정보가 주어지고, 서로 통하는 컴퓨터 묶음이 몇 개인지 센다. 합친 뒤 루트가 몇 종류인지 세면 되는, 그룹 묶기의 가장 기본형이다.
- 프로그래머스 호텔 방 배정: 손님이 원하는 방이 차 있으면 그보다 번호가 큰 빈 방 중 가장 작은 곳을 준다. 방을 채울 때마다 "다음 빈 방"을 가리키게 이어 두는 식으로 유니온 파인드를 쓴다.
- 프로그래머스 섬 연결하기: 다리 건설 비용이 주어지고, 모든 섬이 서로 오갈 수 있게 하는 최소 비용을 구한다. 간선을 비용 순으로 정렬하고 사이클이 안 생기는 것만 고르는 크루스칼에 유니온 파인드가 들어간다.

### 풀이 생각 순서

1. "연결되어 있나?"만 묻고 경로는 안 묻는지 본다. 그렇다면 BFS 대신 유니온 파인드가 간단하다.
2. 합치기가 중간에 계속 일어나는지 본다(동적 연결). 한 번 만들고 끝이면 DFS도 된다.
3. find는 압축, union은 크기 기준으로 쓴다.
4. 크루스칼이면 union이 False를 돌려줄 때(이미 같은 그룹) 그 간선은 버린다.

### Python 코드

```python
def find(p, x):
    while p[x] != x:
        p[x] = p[p[x]]     # 경로 반으로 줄이기(path halving)
        x = p[x]
    return x

def union(p, size, a, b):
    a, b = find(p, a), find(p, b)
    if a == b:
        return False       # 이미 같은 집합
    if size[a] < size[b]:
        a, b = b, a
    p[b] = a
    size[a] += size[b]
    return True
```

5개 원소에서 (1,2) (2,3) (1,3) (4,5)를 차례로 합쳐 보니 `True, True, False, True`가 나왔다. 세 번째가 False인 건 1과 3이 이미 같은 집합이라서고, 크루스칼에서 "이 간선은 사이클을 만든다"는 신호로 그대로 쓴다. 마지막에 1과 3은 같은 집합, 1과 4는 다른 집합으로 확인했다.

재귀 find는 파이썬 재귀 한도에 걸릴 수 있어서 위처럼 반복문으로 쓰는 게 안전하다.

### 복잡도

연산당 거의 O(1)(정확히는 분할 상환 O(α(n))), 공간 O(n). 위키피디아에서는 이 하한이 증명되어 더 줄일 수 없다고 적는다.

## 위상 정렬

### 유형 설명

"A를 해야 B를 한다"는 선후 관계를 간선으로 둔 방향 그래프가 있을 때, 모든 간선이 앞에서 뒤로 향하게 일렬로 세우는 게 위상 정렬이다. 과목 선수 과목, 빌드 의존성, 작업 순서가 전형적이다. 방향 사이클이 없는 그래프(DAG)여야만 가능하다. 순서는 하나로 정해지지 않을 수도 있다.

카안 알고리즘이 가장 흔하다. 들어오는 간선이 0개인 노드를 큐에 넣고, 하나 꺼내 결과에 붙인 뒤 그 노드가 가리키던 간선을 지운다. 그 결과 진입차수가 0이 된 이웃을 큐에 넣는다. 끝났는데 결과 길이가 n보다 작으면 사이클이 있다는 뜻이라, 사이클 판별도 같이 된다.

### 대표 문제

- LeetCode 210 Course Schedule II: 선수 과목 관계가 주어질 때 모든 과목을 들을 수 있는 순서 하나를 돌려주고, 불가능하면 빈 배열을 돌려준다. 카안 알고리즘 그대로다.
- LeetCode 207 Course Schedule: 같은 입력에서 순서는 필요 없이 모든 과목을 들을 수 있는지(사이클이 없는지)만 판단한다.
- 선후 관계가 같을 때 번호가 작은 것부터 내보내라는 조건이 붙으면 큐 대신 힙을 쓰는 변형이 된다(아래 풀이 생각 순서 6번).

### 풀이 생각 순서

1. "순서", "선행", "먼저 해야" 같은 말이 나오는지 본다.
2. 간선 방향을 정한다(선행 → 후행). 방향을 반대로 잡는 실수가 많다.
3. 진입차수 배열을 만든다.
4. 진입차수 0인 노드를 큐에 넣고 꺼내며 줄인다.
5. 결과 개수가 n이 아니면 사이클이다.
6. 순서 조건이 더 붙으면(작은 번호 우선 등) 큐를 힙으로 바꾼다.

### Python 코드

```python
from collections import deque

def topo(n, edges):
    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for a, b in edges:          # a를 먼저 해야 b
        g[a].append(b)
        indeg[b] += 1
    q = deque(i for i in range(1, n + 1) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else None   # None이면 사이클
```

(1,2) (1,3) (2,4) (3,4)로 돌리면 `[1, 2, 3, 4]`, 1→2→3→1 사이클을 넣으면 `None`이 나왔다.

### 복잡도

O(V+E), 공간 O(V+E).

## 헷갈리는 것

- 다익스트라는 "가장 작은 걸 꺼내는" 그리디다. 음수 간선에서 틀리는 이유도 거기에 있다.
- 간선 비용이 전부 같거나 0/1이면 다익스트라까지 갈 필요가 없다. BFS나 0-1 BFS로 된다.
- 유니온 파인드는 그룹이 합쳐지기만 하고, 쪼개지지는 않는다. 간선이 지워지는 문제는 시간을 거꾸로 돌려 합치기로 바꿔 푸는 경우가 많다.
- 위상 정렬 결과는 하나가 아닐 수 있어서, 문제가 특정 순서를 요구하면 그 규칙(힙 등)을 따로 넣어야 한다.

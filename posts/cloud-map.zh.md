创建服务后，剩下的问题包括：将其部署到哪里、如何发布上线，以及上线后如何进行监控。本系列将按此顺序探讨六个核心概念。每个部分先列出一个大标题，若想了解更多内容，请点击下方链接跳转。流程从搭建服务器开始，逐步过渡到运维管理。

## 一览全貌流程图

```
클라우드(서버를 빌린다)
   ├─ 앱을 묶어 옮긴다 ........ Docker·컨테이너
   └─ 서버 관리를 맡긴다 ...... 서버리스
코드 → 테스트 → 배포 ........... CI/CD
설정과 비밀번호를 코드 밖에 둔다 .. 환경변수·시크릿
뜬 뒤에 상태를 지켜본다 ........ 모니터링·로그·알림
```

## 1. 部署到哪里

**云基础**：这是一种按需租用而非购买服务器的模式。根据你负责管理的服务器层级不同，可分为 IaaS、PaaS 和 SaaS；同时涉及“区域（Region）”与“可用区（AZ）”等位置概念，以及按使用量付费的成本结构。
[详情 → 云基础](#/post/cloud-basics)

**Docker 与容器**：这是一种将应用及其运行所需文件打包成隔离进程的工具。旨在减少在本地 PC 上能运行但在服务器上无法运行的问题。
[详情 → Docker 与容器](#/post/cloud-docker)

**无服务器（Serverless）**：并非没有服务器，而是由云平台负责服务器的启停与伸缩，你只需上传函数代码即可。仅在收到请求时执行代码，费用也仅在运行时产生。
[详情 → 无服务器](#/post/cloud-serverless)

## 2. 如何发布上线

**CI/CD 与部署策略**：自动化完成代码合并、测试及发布的流程。同时也会探讨三种防止最后发布阶段出错的部署方式。
[详情 → CI/CD 与部署策略](#/post/cloud-cicd)

**环境变量与密钥管理**：密码和密钥不应硬编码在代码中，这是基本规范。从 `.env` 文件开始，逐步演进到使用密钥管理器及密钥轮换机制。
[详情 → 环境变量与密钥管理](#/post/cloud-secrets)

## 3. 上线后如何守护

**监控·日志·告警**：这是在用户感知到服务异常之前提前发现问题所做的准备。内容涵盖指标（Metrics）、日志（Logs）和链路追踪（Traces）的分类分析，并整理了告警应针对哪些事件进行配置。
[详情 → 监控·日志·告警](#/post/cloud-observability)

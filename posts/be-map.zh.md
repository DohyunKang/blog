## 1. 对外如何交互

**API 与 REST**：通过 URL 指向资源，利用 HTTP 方法定义操作约定。同一请求可重复发送（幂等性）是设计中至关重要的一点。
[详情 → API 与 REST](#/post/be-api-rest)

**认证与授权**：登录（你是谁）与权限（你能做什么）是两个不同的问题。需分别厘清 Session、JWT、OAuth、RBAC 各自负责哪一部分。
[详情 → 认证与授权](#/post/be-auth)

## 2. 服务端内部如何流转

**请求处理流程**：客户端发出的请求经过中间件链，由路由分发至处理器，再访问数据库后，响应沿原路返回。
[详情 → 请求处理流程](#/post/be-request-flow)

**分层架构**：将代码划分为控制器、服务层和仓储层，并仅允许上层依赖下层的方式。对于小型项目而言可能略显过度设计。
[详情 → 分层架构](#/post/be-layered-architecture)

**模块内聚与耦合**：一个模块应专注于单一职责，且与其他模块保持松耦合的设计原则。
[详情 → 模块内聚与耦合](#/post/be-coupling-cohesion)

## 3. 处理慢请求或出错时

**异步处理与消息队列**：耗时任务可放入队列，由独立的工作进程处理。但需注意同一消息可能被重复投递的风险。
[详情 → 异步处理与消息队列](#/post/be-async-queue)

**错误处理与日志记录**：关键在于捕获错误的位置以及记录的内容。需统一处理重试、超时、日志格式及错误响应等整套机制。
[详情 → 错误处理与日志记录](#/post/be-error-logging)

## 4. 构建可信系统

**后端测试**：用于验证修复后原有功能是否依然正常的代码。基本策略是在单元测试、集成测试和端到端（E2E）测试中，优先采用成本低且执行快的测试类型。
[详情 → 后端测试](#/post/be-testing)

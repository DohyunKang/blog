今朝、GitHub のトレンド(weekly)の2番目に meta/astryx があった。今週だけでスター 13,501、レポ全体のスターは 29,564(11月17日朝に確認)。Meta が社内で8年使ってきたデザインシステムをオープンソースにしたもので、紹介文は "agent ready" だ。README、CLI の README、公式ブログを何本か読んだ。自分ではインストールしていない。

## どういうものか
デザインシステムは、ボタンや入力欄、表のような画面部品と、色・フォント・余白のルールをひとまとめにしたものだ。チームごとにボタンを作り直さずに済む。Astryx は React 19 以上向けのコンポーネント150個以上、テーマ7種、ページテンプレート、そして CLI でできている。README には Meta 社内で13,000以上のアプリが使っているとある。ライセンスは MIT、まだベータ。

スタイルは Meta の StyleX で書かれているが、使う側は知らなくていい。ビルド済みの CSS を import してテーマ provider で包めば終わりで、上書きは Tailwind でも普通の CSS でも `className` でやる。テーマは CSS 変数(色、フォント、角の丸みなど)の束なので、コンポーネントのコードを触らずにブランドの色を乗せられる。もっと深く変えたいなら `swizzle` でコンポーネントの元のコードを自分のプロジェクトにコピーして持つ。

## エージェント向けとは何か
ここがほかのデザインシステムと分かれるところだ。ドキュメントをウェブサイトだけに置かず、CLI がドキュメントの役をする。

1. `astryx search button` のように探すと、コンポーネント、フック、ドキュメント、テンプレートを一つのリストで返し、結果ごとに次に打つコマンドを添える。
2. `astryx component Button` で props と例を読む。全コマンドに `--json` があって、エージェントは決まった形の JSON で受け取る。打ち間違えるとエラーに「Button では?」のような候補がつく。
3. `astryx build "<作るページの説明>"` で、どのテンプレートから始めるかと足りない部品を教えてくれる。ページを一から書かずテンプレートから始めろ、ということだ。
4. 仕上げる前に、素の `<div>` や直書きの `#hex`・`px` をコンポーネントかトークンに置き換えるよう求める。

この流れがスキルファイル1枚に入っている。スキルは、エージェントが必要なときに読み込む作業の手引きだ。CLI をグローバルに入れると `~/.agents/skills/astryx/SKILL.md` に同じ内容が置かれ、Claude Code と Codex 用のプラグインもレポにある。スキルにはコンポーネントのドキュメントを入れず「astryx コマンドに聞け」とだけ書く。ドキュメントはインストールされたバージョンの CLI が答えるので、スキルが古くなりにくい。[詳しく → スキル](#/post/ai-skills) [詳しく → コンテキストエンジニアリング](#/post/ai-context)

ブログ記事の一本がこの設計をよく説明している。最初はエージェントが Astryx をほとんど使わず、div だらけのページを返してきた。調べたら自分たちのテンプレートがそういう形で、それをそのまま真似ていたらしい。そこでテンプレートの採点基準を作って整え直したら、出力もついてきたという。タイトルは "AI is a copycat so we gave it good examples to copy"。

もう一つは "vibe test" という自前の評価。前提知識のないエージェントに誘導のないプロンプトで画面を作らせ、同じ分析器で Astryx、Tailwind、shadcn、素の HTML の結果を同じように採点するという。最初は「Astryx を自分たちの望むように使ったか」を測っていたが、それは自分たちに有利な試験なので変えた、と書いてある。採点の数値はその記事では確認できなかった。

X で "astryx" を含む投稿は11月10日(UTC)の211件が最多で、その後は1日70〜130件ほど(リツイート除く)。同じ単語を別の意味で使った投稿が混ざっているかもしれない。Reddit と YouTube でどれだけ広まったかは確認できなかった。

## 入門者の目線で
PM として目についたのは、「AI が作る画面はなぜ同じように不格好なのか」の答えが、モデルではなく見せた例のほうにあったことだ。エージェントに画面を任せるなら、プロンプトを磨くより、良いテンプレートと禁止リストを先に渡すほうが安く済むかもしれない。

開発の入門者なら、インストール前に公式サイトの Playground や Storybook でコンポーネントを眺めて、プロジェクトで `npx @astryxdesign/cli search <探しているもの>` から打ってみるのが軽い始め方だと思う。README に注意が一つある。CLI を入れる前に `npx astryx` と短い名前で打つと、無関係な別の npm パッケージが動く。エージェントに今どきのウェブコードを書かせるスキルの話は、数日前の記事と合わせて読むといい。[詳しく → Modern Web Guidance](#/post/news-261114-a)

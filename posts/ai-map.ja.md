AI を勉強していると、用語が次々と溢れてきます。プロンプト、コンテキスト、RAG、MCP、ハネスといった言葉が絡み合っていて、一つずつ見ても理解できません。そのため、大きな単語を一行ずつ先に書き、さらに知りたいことは下のリンクから進めるようにしました。順序は下から上へ、モデル → 入力 → 記憶 → 外部接続の順です。

## 関係を一覧で見る

```
생성형 AI ⊃ LLM
LLM  ←  프롬프트(입력)  ←  컨텍스트(그 순간 모델이 보는 전체)
컨텍스트 = 컨텍스트 윈도우 안에 담기는 것 (토큰으로 센다)
컨텍스트에 외부 지식을 넣는 방법 = RAG (임베딩으로 찾는다)
컨텍스트에 도구를 연결하는 규격 = MCP
이 전부를 돌리고 관리하는 모델 바깥의 코드 = 하네스
모델이 틀린 말을 그럴듯하게 하는 현상 = 할루시네이션
```

## 1. モデルとは何か

**生成 AI**: 分類や予測しかできなかった AI と異なり、文章・画像・音を新たに作り出す AI です。
[詳しく → 生成 AI とは](#/post/ai-generative)

**LLM（大規模言語モデル）**: 文章の断片（トークン）の次に来る断片を続けるように非常に大きく学習したモデルです。チャットボットはその上に載せられた外見だけです。
[詳しく → LLM とは何か](#/post/ai-llm)

## 2. モデルに何を渡すか

**プロンプト**: モデルに与える入力のすべて。明確に、例を添えて、形式を決めて書くのが基本です。
[詳しく → プロンプトとプロンプトエンジニアリング](#/post/ai-prompt)

**コンテキスト**: モデルが答えを作る瞬間に一気に見る文章全体。プロンプトもその一部であり、何を載せておくかを設計することがコンテキストエンジニアリングです。
[詳しく → コンテキストとコンテキストエンジニアリング](#/post/ai-context)

**コンテキストウィンドウ・トークン**: コンテキストに収められる最大容量と、それを数える単位。対話が長くなると、各呼び出しごとに全体を再度送るため、費用と時間も増えます。
[詳しく → コンテキストウィンドウとトークン](#/post/ai-context-window)

## 3. わからないことはどう伝えるか

**埋め込み**: 文章を数値の座標に変換して、意味が近いものを検索できるようにする方式です。
[詳しく → 埋め込みとベクトル検索](#/post/ai-embedding)

**RAG**: モデルに本を広げて試験させるような方式です。必要な文書を先に探し出してコンテキストに入れて与えます。
[詳しく → RAG](#/post/ai-rag)

**ハルシネーション**: わからないのに答えるように作られた構造から生じる、 그럴듯한（説得力のある）が誤った答えです。
[詳しく → ハルシネーション](#/post/ai-hallucination)

## 4. 外部世界とどう繋がるか

**MCP**: AI アプリと外部ツールを繋ぐ接続規格です。ツールを一度作っておけば、複数のアプリで挿して使えます。
[詳しく → MCP](#/post/ai-mcp)

**ハネス**: モデルの外側でループ・ツール・権限・記録を担当するコードです。資料ごとに指し示す範囲が少しずつ異なります。
[詳しく → ハネスとハネスエンジニアリング](#/post/ai-harness)

## 6. 対話はどう続き、記憶されるか

**セッションと会話履歴**: チャットボットが私の話を覚えているのはモデルではなく、アプリが各呼び出しごとにこれまでの記録をまるごと再度送るからです。
[詳しく → セッションと会話履歴](#/post/ai-session)

**コンパクション・メモリ**: コンパクションとは、進行中の対話を要約に置き換える作業であり、メモリとは要約から外れても戻せるように窓の外に書き留めることです。
[詳しく → コンパクションとメモリ](#/post/ai-compaction)

**プロンプトキャッシング**: 各リクエストで同じ先頭部分を一度処理して再利用する機能です。最初から完全に一致する必要があります。
[詳しく → プロンプトキャッシング](#/post/ai-prompt-caching)

## 7. ツールとエージェント

**ツール呼び出し**: モデルが関数を直接動かすのではなく、「これをこの引数で実行して」という依頼書を書いて、実行は私のコードが行います。
[詳しく → ツール呼び出し (Function calling)](#/post/ai-tool-use)

**エージェント・エージェントループ**: モデルがツールを使い、結果を見て再度判断することを繰り返して終わる構造です。骨格は while 文です。
[詳しく → エージェントとエージェントループ](#/post/ai-agent-loop)

**サブエージェント・マルチエージェント**: 一部の作業を新しいコンテキストで依頼し、要約だけ受け取る方式です。仕事が並列に分かれ、要約だけで十分だった場合にのみメリットがありました。
[詳しく → サブエージェントとマルチエージェント](#/post/ai-subagent)

**スキル**: 特定のタスクの手順・資料・スクリプトを 1 つのフォルダに束ねておき、必要な時にだけ読み出す方式。常に上がっているのは名前と説明のみである。
[詳しく → スキル (Skills)](#/post/ai-skills)

**モデル・ツール別のスキル比較**: Claude、Codex、Gemini CLI、Cursor はいずれも指示ファイル → スキル → 配布パッケージという構造であり、名称は異なるが似ている。
[詳しく → モデル・ツール別のスキルと拡張の比較](#/post/ai-vendor-skills)

## 8. モデルの出力と入力形式

**サンプリング（温度・top-p）**: モデルが次の単語を確率表から選ぶ方法を調整する値。最近では Claude 側でこの値が使えなくなる傾向があるため、現状も合わせて整理した。
[詳しく → サンプリング：温度・top-p](#/post/ai-sampling)

**推論モデル・思考トークン**: 回答する前に独り言のように考える文章を先に書くモデル。画面に表示されなくても、出力トークンの料金と待ち時間で返ってくる。
[詳しく → 推論モデルと思考トークン](#/post/ai-reasoning)

**構造化出力**: 答えを既定の形（スキーマ）に合わせて出す機能。依頼することと強制することでは信頼できる程度が異なる。
[詳しく → 構造化出力 (JSON・スキーマ)](#/post/ai-structured-output)

**マルチモーダル**: 文章だけでなく、画像や音声も同時に扱うという意味。画像はトークンに変換され、文章と同じ画面に入る。
[詳しく → マルチモーダル](#/post/ai-multimodal)

## 9. 原理：モデルはどうやって作られるのか

**機械学習・ディープラーニングの基礎**: データを示し、規則に該当する数字（重み）をモデルが自ら合わせる方式。ディープラーニングは層を深く積み上げたニューラルネットワークを使う。
[詳しく → 機械学習・ディープラーニングの基礎](#/post/ml-basics)

**ニューラルネットワーク・バックプロパゲーション**: 掛け算と足し算と曲がる計算を層ごとに積み重ねた関数、そして重みをどちらに修正するか逆算する方法。
[詳しく → ニューラルネットワークとバックプロパゲーション](#/post/ml-neural-net)

**トランスフォーマー・アテンション**: 文内の単語同士がどれほど参照し合うかを点数で計算する構造。現在の LLM はほぼこれを骨格として使っている。
[詳しく → トランスフォーマーとアテンション](#/post/ml-transformer)

**事前学習から RLHF まで**: インターネットの文章で次の単語を当てる（事前学習）、回答法を示す（SFT）、人間が選んだ方へ押す（嗜好学習）という 3 つの段階。
[詳しく → 事前学習から RLHF まで](#/post/ml-pretraining)

**ファインチューニング**: 学習が終了したモデルを、自らのデータで一度さらに教えること。全体を直すか一部だけ載せるか（LoRA/QLoRA）によって必要な GPU が大きく異なる。
[詳しく → ファインチューニング：全体 vs LoRA/QLoRA](#/post/ml-finetuning)

**ローカルモデル**: 自分の PC で直接動かす方式。入れるかどうかはほとんど VRAM の計算だけで決まる。
[詳しく → ローカルモデルの起動](#/post/ml-local-models)

**推論最適化**: KV キャッシュ、バッチ処理、ストリーミング、投機的デコーディングが相互に接続された 1 つの塊であり、回答をより速く安く出す技術の集まり。
[詳しく → 推論最適化](#/post/ml-inference)

**画像生成（拡散）**: 純粋なノイズから始めて少しずつ削り取って画像を作るモデル。
[詳しく → 画像生成モデル（拡散）](#/post/ml-diffusion)

## 12. オープンソース分析

**vLLM**: KV キャッシュを細かく分割して利用し、スケジューラーが各ステップでトークンを割り当てるサーバーです。
[詳細 → オープンソース分析: vLLM](#/post/repo-vllm)

**simonw/llm**: モデル呼び出しは一元化し、残りはプラグインと while ループで構成された構造です。

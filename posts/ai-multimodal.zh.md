多模态（Multimodal）指的是模型不仅能处理文本，还能同时处理图像、声音等其他类型的输入（或输出）。最终，图像也会被转换为 token，进入与文本相同的上下文窗口。

## 什么是多模态

“模态”（modality）指的是信息的载体形式。文字、图像、声音、视频各自代表一种模态。仅接收文本的模型称为单模态，而能处理两种或以上模态的则被称为多模态。

如果先区分方向有两个维度，就会少一些困惑。

| | 输入（理解） | 输出（生成） |
|---|---|---|
| 图像 | 看图描述、读表、解析截图 | 绘图 |
| 语音 | 听写（将语音转为文字） | 朗读（将文字转为语音） |
| 视频 | 逐帧观看并总结 | 生成视频 |

当提到 LLM[LLM](#/post/ai-llm)“看”图像时，通常指的是左侧列，即输入方向。负责绘图的通常是另一类模型，相关内容会在 [扩散模型](#/post/ml-diffusion) 和 [生成式 AI](#/post/ai-generative) 的文章中单独整理。并非所有模型都同时具备这两种能力，具体取决于产品。

## 原理：如何将图像放入模型

文字会被切分为 token 并转换为数字向量，图像也遵循类似的流程。核心在于将图像切割成小块（patch）。

Vision Transformer (ViT) 论文的摘要指出，即使直接对“图像块序列”应用纯 Transformer 也能很好地完成图像分类任务。这意味着并不一定需要卷积神经网络。可以这样理解：Transformer 原本处理文字 token 的结构，现在直接用来处理图像块，将其视为 token 一样对待。

接下来的问题是让文字和图像在同一个空间中相遇。CLIP 是这方面的典型代表。根据 OpenAI 的论文摘要，他们利用从互联网收集的 4 亿个（图像，文本）对进行训练，通过判断某个描述是否匹配某张图像来学习。结果表明，无需预设标签列表，仅凭文本描述即可实现新的分类任务（zero-shot），并在超过 30 个数据集上进行了评估。这种“将文字和图像置于同一坐标系”的感觉与 [嵌入](#/post/ai-embedding) 紧密相关。

上述内容主要涉及单独放置图像编码器并连接到文本模型的一类架构。如今，大多数商用模型的内部结构并未公开。

## 示例：Claude 是这样感知图像的

这是从 Anthropic 的视觉文档中确认的内容。

- 图像被划分为 28×28 像素的块，每个块对应一个视觉 token。
- token 数量计算公式为：⌈宽度/28⌉ × ⌈高度/28⌉。
- 对于过大的图像，会先按比例缩小再进行处理。具体限制因模型代际而异。标准区间为长边 1,568px·最多 1,568 tokens；Claude 4.7 及后续模型的高分辨率区间为长边 2,576px·最多 4,784 tokens。
- 支持的格式包括 JPEG、PNG、GIF、WebP。不支持动画，仅使用第一帧。
- 每张请求的图像数量限制：根据 API 标准最多 600 张（对于上下文窗口为 20 万 token 的模型为 100 张）；claude.ai 每轮对话最多 20 张。单张图像的最大尺寸为 8000×8000px。
- 传输方式有三种：直接插入 base64、URL、以及 Files API 的 file_id。

文档中给出的示例表格整理如下：

| 图像尺寸 | 标准区间 token 数 | 高分辨率区间 token 数 |
|---|---|---|
| 200×200 | 64 | 64 |
| 1000×1000 | 1,296 | 1,296 |
| 1920×1080 | 1,560 (缩至 1456×819) | 2,691 |
| 3840×2160 | 1,560 | 4,784 |

对于 1000×1000 的图像，计算结果为 36×36=1,296，与公式一致。即使是相同的 4K 图像，在高分辨率区间模型中消耗的 token 数也接近标准区间的三倍。文档建议，如果不需要精细度，应预先缩小图像再发送。

## Token 成本感知

图像 token 与文字 token 一样占用 [上下文窗口](#/post/ai-context-window)，并按相同的输入单价计费。根据文档中的计算示例，在每 100 万 input tokens 收费 1 美元的模型中，处理 1,000 张 1000×1000 的图像约需 1.30 美元；而在每 100 万 tokens 收费 4 美元的高分辨率模型中，则约为 5.18 美元。这些价格基于文档撰写时的标准，使用时需重新查看最新价目表。

凭我的感觉，一张图像的 token 量大约相当于一千个文字 token。如果在对话中持续保留几张截图，每轮对话重新发送的输入量会相当大。文档也建议，如果使用 base64 插入图像，随着对话变长，每次请求都会再次携带图像字节数据；因此对于需要重复使用的图像，建议使用 Files API 上传。

## 常见误解

- **图像“用眼睛看”**：实际上是将图像切分成碎片并转换为 Token 后进行读取。对于较小、模糊或旋转的图像，容易产生误判。
- **准确计数图像中的物体数量**：文档会直接书写计数结果。当物体较多时，计数可能不准确。位置和坐标也仅为近似值。
- **图像是免费输入的**：如上所述，图像也是 Token 的一部分，因此会产生费用。
- **所见即所说**：图像解读也会产生 [幻觉](#/post/ai-hallucination)。文档指出模型不会识别人名，且不建议用于诊断性 CT、MRI 等解读。
- **多模态意味着也能处理语音和视频**：这取决于具体模型。Claude Vision 处理的对象是图像（及附件文档），GIF 仅使用第一帧。

<details>
<summary>详细解析：为何存在分辨率和 Token 上限</summary>

模型单次可处理的 Token 数量是固定的。图像尺寸越大，切分块的数量会按平方级增长（因为长宽同时增加）。因此，厂商会设定基于最长边和最大 Token 数的上限；一旦超出，便会按比例缩小图像以保持在限内。

一个实用的结论：发送更大的图像并不总是能提升识别效果。超出上限的部分无论如何都会被压缩处理，因此建议预先按照上限调整尺寸再发送，以减少传输量和延迟。文档也出于相同目的提供了相关指引。

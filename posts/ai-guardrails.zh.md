护栏（Guardrail）是用于防止大型语言模型（LLM）服务说出或做出不当言论与行为的统称。在提示词中写入“不要做某事”属于护栏，在模型前后添加检查代码、限制模型可使用工具的权限等也均属于护栏的范畴。

## 为什么需要它

[LLM](#/post/ai-llm) 同时接收指令和数据，且均以文本形式输入。开发者编写的指令、用户发送的内容以及从网页抓取的信息，最终都会作为一段整体文本输入给模型。因此，如果数据中混入了看似指令的句子，模型可能会遵循这些内容。护栏的必要性主要源于此。

企业在运营服务时，主要担忧三大问题：

| 担忧 | 可能发生的情况 | OWASP 项目 |
|---|---|---|
| 提示词注入（Prompt Injection） | 输入内容导致模型行为偏离预期 | LLM01 |
| 敏感信息泄露 | 个人信息、内部文档、密钥等内容混入回答中泄露出去 | LLM02 |
| 权限过大的代理（Agent） | 模型使用超出必要的工具和权限造成损害 | LLM06 |

OWASP 以发布 Web 安全 Top 10 而闻名，同时也专门发布了针对 LLM 应用程序的 Top 10。2025 年版除了上述三项外，还包含了供应链、数据与模型污染、不当输出处理（LLM05）、系统提示词泄露（LLM07）、向量/嵌入弱点（LLM08）、虚假信息（LLM09）以及无限制消耗（LLM10）等问题。本文将聚焦于表格中的前三项。

## 提示词注入

OWASP 将其定义为：输入内容导致 LLM 的行为或输出偏离预期方向。即使输入内容对人类肉眼不可见，只要模型能够读取，即属于此类问题。主要分为两类：

| 类型 | 来源 | 示例 |
|---|---|---|
| 直接注入 | 服务用户本人在输入框中输入 | 向聊天机器人发送“忽略前面的指令”等句子 |
| 间接注入 | 嵌入在模型读取的外部内容中 | 网页、邮件正文、上传文件、工具结果中包含了指令性文本 |

“越狱”（jailbreak）是直接注入的一种形式，旨在完全绕过模型的安全规则。

Anthropic 的文档指出，这两类威胁模型存在差异：直接注入的攻击者为用户；间接注入中用户是可信的，但攻击语句存在于模型读取的第三方内容中。使用 [RAG](#/post/ai-rag) 检索文档或通过 [工具调用](#/post/ai-tool-use) 读取网页的服务，其间接注入的比例会更高。

OWASP 指出，影响程度取决于服务上下文以及模型所拥有的权限大小，范围可从系统提示词泄露、错误输出到在关联系统中执行命令等。并且明确指出，目前尚无完全杜绝该问题的方法，重点在于减轻损害。

## 敏感信息泄露

OWASP 所指的敏感信息包括：个人信息、金融与健康记录、企业机密、认证凭证、法律文件等。问题在于模型已学习的内容，或服务附加到提示词中的内部文档，可能作为回答内容泄露出去。

OWASP 提出的应对措施如下：

- 在学习或输入数据中识别并删除敏感信息（如掩码处理、基于模式的删除）
- 仅允许用户和流程访问所需的最小数据集（最小权限原则）
- 限制模型可访问的外部数据源
- 告知用户不要输入敏感信息，并公开数据存储与使用政策
- 禁止或限制用户修改/查看系统初始配置

同一页面还提到：通过限制输出类型的系统提示词指令可能被提示词注入所绕过，因此不能仅依赖此类措施。与其在回答中添加“不要包含此类内容”的语句，不如从根本上防止模型接触到这些数据。

## 权限过大的代理

[代理](#/post/ai-agent-loop) 是指模型选择并使用工具来完成任务的过程。OWASP 将因模型输出超出预期、模糊不清或被操纵而导致的损害称为“过度权限”（Excessive Agency）。原因多样，包括幻觉、直接/间接注入、被污染的扩展功能或其他代理等。文档列出的根源主要有三点：

| 根源 | 含义 | 应对方向 |
|---|---|---|
| 功能过剩 | 附加了服务不需要的工具 | 减少工具数量与功能 |
| 权限过大 | 拥有超出必要的访问权限，或以具备全权能力的公共账号运行 | 采用只读等最小范围，并以用户自身权限运行 |
| 自主性过强 | 在未经验证或批准的情况下执行影响重大的操作 | 需经人工审批 |

尤其值得注意的是，建议优先使用目的明确、范围受限的专用工具，而非像 shell 执行那样开放范围的工具。不应将是否允许的判断交给模型，而应在关联系统中通过权限检查强制执行。在使用 [MCP](#/post/ai-mcp) 连接外部工具时，同样适用此标准。

## 多层防御

将官方指南并排列出，可将防御措施归纳为四层。

```
사용자 입력 → [1 입력 검사] → 모델 → [2 출력 검사] → 도구 실행 → [3 권한 최소화] → [4 사람 승인] → 실제 반영
```

| 层级 | 工作内容 | 依据 |
|---|---|---|
| 1 输入检查 | 过滤已知攻击模式、使用轻量模型对危险输入进行预分类、限制输入长度 | Anthropic, OpenAI, OWASP |
| 2 输出检查 | 用代码验证输出是否符合预期格式、评估相关性与依据性、内容审核、限制输出 token 数量 | OWASP, OpenAI |
| 3 权限最小化 | 仅提供必要工具、只读访问、运行于沙箱环境、完全不暴露秘密值 | OWASP, Anthropic |
| 4 人工审批 | 对高风险操作及高敏感领域的结果由人工确认 | OWASP, OpenAI |

### 1. 输入检查

Anthropic 文档建议，在用户输入进入主模型之前，应先通过轻量模型进行过滤。这种方法将响应限制为“是否危险”等简单分类，并接收结构化输出以引导代码分支执行。系统提示中也应包含对已知注入模式的过滤规则以及拒绝处理的方法。OpenAI 指南则指出，限制输入长度可降低注入风险；若能使用经过验证的下拉菜单替代自由文本输入，效果更佳。

间接注入的关键在于结构。归纳 Anthropic 文档的建议如下：

- 外部内容仅放入工具结果（tool_result）字段，而非系统提示或普通用户消息中
- 明确说明该内容的性质及其来源（通过工具描述或结果结构体现）
- 在系统提示中明确指出：工具、文档和搜索结果属于不可信数据，不应改变指令
- 用 JSON 包裹外部字符串，清晰界定数据与指令的边界
- 传递给模型的工具返回内容，也需先经过相同方式的轻量模型检查

### 2. 输出检查

OWASP 建议预先定义期望的输出格式，并用决定性代码进行验证。还需检查响应是否与问题相关、是否基于所提供资料。过滤无依据的回答也与应对 [幻觉](#/post/ai-hallucination) 的工作重叠。OpenAI 推荐使用免费的 Moderation API 并设置输出 token 上限；若可能，应返回经过验证的后端内容（如最匹配的帮助中心文档），而非模型新生成的文本。

### 3. 权限最小化

前文所述的过度授权问题即在此层级解决。Anthropic 也建议，为将成功注入造成的损害降至最低，应阻止模型访问不必要的秘密值，在沙箱中运行工具，并严格限制权限范围。OWASP 在此基础上进一步提出：在执行时应用用户认证范围、记录扩展功能活动的日志与监控、实施速率限制。

### 4. 人工审批

OWASP 建议对高风险操作引入人工审批（human-in-the-loop）。OpenAI 指南指出，在高敏感领域和代码生成场景中，必须由人工审查输出；审查人员应了解系统局限，并能对照原始资料进行核实。发送邮件、处理支付、删除数据等难以撤销的操作是典型的需人工审批场景。

## 运营中需同步实施的事项

- 部署前，故意使用包含攻击语句的文档、邮件或工具结果进行测试。Anthropic 建议直接对自家代理进行红队测试，OpenAI 和 OWASP 也推荐进行对抗性测试。此类测试可归类为 [评估](#/post/ai-evals) 的一种，并应反复执行。
- 定期分析输出，查找注入成功的痕迹，据此改进提示词与过滤器（Anthropic 的持续监控）。
- 对重复尝试相同绕过手段的用户实施限制或封禁（Anthropic 的重复违规者应对策略）。
- 要求用户提供账户信息，并在 API 请求中附带用户级稳定标识符（如 OpenAI 的 safety_identifier），以便在发生滥用时追踪到具体用户，而非整个组织。
- 设立举报渠道并由人工响应。

将这些组件整合进服务代码的框架被称为 [ Harness ](#/post/ai-harness)，而护栏则是其中位于模型前后及工具调用点的组件。

## 常见误解

- 在系统提示中写入“请勿忽略”会适得其反：虽然有一定帮助，但 OWASP 强调不存在一劳永逸的方法。提示词只是多层防御中的一层。
- 模型性能提升后就不需要护栏了：即便 Anthropic 文档承认 Claude 原生具备对某些攻击的抵抗力，仍建议增加额外防护步骤。
- 只需阻止输入即可：间接注入可通过工具结果或文档进入系统，无需经过输入框；因此输出和权限层面的防护同样必要。
- 护栏是模型的功能之一：OWASP 主张不应将权限判断交给模型，而应在关联系统中强制执行。

<details>
<summary>详细解析：为何间接注入难以防范</summary>

模型不会完全将指令与数据分离作为输入格式。系统提示、用户消息和工具结果均以 token 序列的形式进入。因此，模型必须自行判断外部内容中的指令是否确实来自用户，但这种判断具有概率性，无法达到 100% 的准确率。

Anthropic 推荐的隔离结构（仅将内容放入 `tool_result`、明确标注来源、使用 JSON 编码）是一种简化该判断机制的手段。文档中提到，通过闭合引号或标签以脱离指令区域的路径会被 JSON 转义所阻断。即便这些措施只能降低概率而无法将其降至零，因此仍需采取最小化成功攻击时损害的措施（如权限最小化），并将人工审核作为最后一道防线。这正是需要多层防御的原因。

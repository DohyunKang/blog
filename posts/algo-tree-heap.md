트리 문제는 순회 순서를 코드로 바로 쓸 수 있느냐가 절반이고, 힙은 "가장 작은(큰) 것을 반복해서 꺼내는" 문제의 도구라고 이해했다.

## 트리가 뭔지

트리는 노드가 부모-자식으로 이어진 구조다. 맨 위가 루트, 자식이 없는 노드가 리프다. 사이클이 없고 루트에서 어느 노드로든 길이 하나뿐이다. 자식이 최대 둘인 걸 이진 트리라고 한다. 코딩 테스트에서 트리는 거의 이진 트리이거나, 간선 목록으로 주어지는 일반 트리다. 일반 트리는 인접 리스트로 저장해서 [그래프 탐색](#/post/algo-graph-search)처럼 푼다.

용어는 몇 개만 알면 된다.

| 용어 | 뜻 |
|---|---|
| 깊이 | 루트에서 그 노드까지 간선 수 |
| 높이 | 루트에서 가장 깊은 리프까지의 깊이(노드 개수로 셀지 간선으로 셀지는 문제마다 다르니 확인) |
| 서브트리 | 어떤 노드를 루트로 보았을 때 그 아래 전체 |

트리의 거의 모든 문제는 "서브트리도 트리다"라는 성질에서 나온다. 왼쪽 서브트리를 같은 함수로 풀고, 오른쪽도 풀고, 합치면 된다. 그래서 [재귀](#/post/algo-recursion)와 궁합이 좋다.

## 이진 트리 순회

순회는 루트를 언제 방문하느냐로 나뉜다.

| 순회 | 순서 | 쓰임 |
|---|---|---|
| 전위 | 루트 → 왼쪽 → 오른쪽 | 트리 복사, 구조 출력 |
| 중위 | 왼쪽 → 루트 → 오른쪽 | 이진 탐색 트리에서 정렬된 순서 |
| 후위 | 왼쪽 → 오른쪽 → 루트 | 자식 결과를 모아 부모를 계산(높이, 합) |
| 레벨 | 위층부터 한 줄씩 | 최단 깊이, 층별 처리 |

앞의 셋은 깊이 우선(DFS)이라 재귀로 쓰고, 레벨 순회는 [큐](#/post/algo-stack-queue)를 쓰는 너비 우선(BFS)이다. 아래 트리로 직접 돌려 봤다.

```
        1
      /   \
     2     3
    / \     \
   4   5     6
```

```python
from collections import deque

class N:
    def __init__(s, v, l=None, r=None):
        s.v, s.l, s.r = v, l, r

t = N(1, N(2, N(4), N(5)), N(3, None, N(6)))

def pre(n):  return [] if not n else [n.v] + pre(n.l) + pre(n.r)
def ino(n):  return [] if not n else ino(n.l) + [n.v] + ino(n.r)
def post(n): return [] if not n else post(n.l) + post(n.r) + [n.v]

def level(n):
    q, out = deque([n]), []
    while q:
        x = q.popleft()
        out.append(x.v)
        if x.l: q.append(x.l)
        if x.r: q.append(x.r)
    return out

def height(n): return 0 if not n else 1 + max(height(n.l), height(n.r))
```

실행 결과(직접 돌려 확인함).

```
전위 [1, 2, 4, 5, 3, 6]
중위 [4, 2, 5, 1, 3, 6]
후위 [4, 5, 2, 6, 3, 1]
레벨 [1, 2, 3, 4, 5, 6]
높이 3
```

시간은 노드를 한 번씩 보니 O(N), 공간은 재귀 깊이만큼이라 O(높이)다. 한쪽으로 치우친 트리는 높이가 N이 되어 Python 재귀 한도(기본 1000 안팎)에 걸릴 수 있다. 그럴 땐 `sys.setrecursionlimit`을 올리거나 스택으로 바꾼다.

## 힙과 우선순위 큐

우선순위 큐는 "넣은 순서가 아니라 우선순위가 높은 것부터 나오는 큐"라는 개념이다. 힙은 그걸 구현하는 자료구조다. 둘이 같은 말처럼 쓰이는데, 하나는 역할이고 하나는 구현이다.

최소 힙은 "모든 부모가 자식보다 작거나 같다"는 조건을 지키는 완전 이진 트리다. 가장 작은 값이 항상 루트에 있다. 정렬되어 있는 건 아니고, 부모-자식 사이만 맞춰져 있다.

Python `heapq`는 리스트를 힙처럼 쓴다. 공식 문서 기준으로 `heap[0]`이 가장 작은 값이고, 인덱스 `k`의 자식은 `2k+1`, `2k+2`다. 그래서 트리를 따로 만들지 않고 배열 하나로 끝난다.

| 함수 | 하는 일 | 시간 |
|---|---|---|
| `heappush(h, x)` | 넣기 | O(log N) |
| `heappop(h)` | 최솟값 꺼내기 | O(log N) |
| `h[0]` | 최솟값 보기 | O(1) |
| `heapify(list)` | 리스트를 힙으로 | O(N) |

`heapify`가 O(N)이라는 건 문서에 "선형 시간"이라고 나온다. push를 N번 하면 O(N log N)이니, 이미 데이터가 다 있으면 heapify가 낫다.

```python
import heapq
a = [5, 3, 8, 1, 9, 2]
heapq.heapify(a)
print(a)  # [1, 3, 2, 5, 9, 8]  (직접 실행 확인)
```

결과가 정렬이 아닌 걸 볼 수 있다. 다만 `a[0]`은 1이다. 하나씩 pop하면 `[1, 2, 3, 5, 8, 9]` 순서로 나온다.

### 최대 힙은 부호를 뒤집는다

`heapq`는 최소 힙만 오래 제공했다. 문서를 보니 Python 3.14에 `heappush_max` 같은 `_max` 함수가 추가됐다. 그 이전 버전도 쓰일 테니 코딩 테스트에서는 값에 `-`를 붙여 넣고 꺼낼 때 다시 뒤집는 방식이 흔하다.

```python
m = []
for x in [5, 3, 8]:
    heapq.heappush(m, -x)
print(-heapq.heappop(m))  # 8
```

튜플을 넣으면 첫 원소 기준으로 비교한다. 문서는 우선순위가 같을 때 두 번째 원소끼리 비교가 되어야 하고, 안 되면 오류가 나니 카운터를 끼우라고 적는다.

## 대표 문제

번호와 이름만 적는다. 본문은 각 사이트에서 읽는 게 맞다.

- 백준 1991 트리 순회: 노드 정보가 주어지고 전위·중위·후위 결과를 출력. 위 세 함수를 그대로 쓴다.
- 백준 1927 최소 힙, 11279 최대 힙: 힙의 기본 연산을 그대로 구현. 입출력이 많아 `sys.stdin.readline`이 필요하다.
- 백준 11286 절댓값 힙: 절댓값이 작은 것 먼저, 같으면 값이 작은 것 먼저.
- 백준 1715 카드 정렬하기: 묶음 두 개를 합칠 때 드는 비용을 최소로. 항상 가장 작은 둘을 합치는 [그리디](#/post/algo-greedy)에 힙을 붙인다.
- 프로그래머스 더 맵게: 가장 안 매운 둘을 섞어 새 값을 다시 넣는 문제.

## 풀이 생각 순서

1. 문제가 "계속 가장 작은(큰) 것"을 꺼내고 새 값이 중간에 들어오는지 본다. 그렇다면 힙이다. 한 번만 정렬하면 되는 문제는 [정렬](#/post/algo-sort-search)로 끝난다.
2. 최대를 원하면 부호를 뒤집는다. 기준이 둘이면 `(기준1, 기준2)` 튜플로 넣는다.
3. 꺼낸 값으로 새 값을 만들어 다시 넣는지 확인한다. 카드 합치기, 더 맵게가 이 형태다.
4. 트리 문제는 "자식 결과로 부모를 계산"하면 후위, "부모 정보를 내려보내면" 전위, 층이 중요하면 레벨 순회를 고른다.

### 코드로 보기

```python
import heapq

# 카드 정렬하기 형태: 가장 작은 둘을 합치며 비용 누적
def merge_cost(cards):
    heapq.heapify(cards)
    total = 0
    while len(cards) > 1:
        s = heapq.heappop(cards) + heapq.heappop(cards)
        total += s
        heapq.heappush(cards, s)
    return total

print(merge_cost([10, 20, 40]))  # 100

# K번째로 큰 수: 크기 K짜리 최소 힙을 유지
def kth_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)
    return h[0]

print(kth_largest([3, 2, 1, 5, 6, 4], 2))  # 5

# 절댓값 힙 형태: (절댓값, 원래 값) 튜플
def abs_heap(ops):
    h, out = [], []
    for x in ops:
        if x:
            heapq.heappush(h, (abs(x), x))
        else:
            out.append(heapq.heappop(h)[1] if h else 0)
    return out

print(abs_heap([1, -1, 0, 0, 0, 2, -2, 0]))  # [-1, 1, 0, -2]
```

세 함수 모두 직접 실행해 출력을 확인했다.

## 복잡도

| 작업 | 시간 | 공간 |
|---|---|---|
| 트리 순회(전·중·후·레벨) | O(N) | 재귀 O(높이) / 레벨은 큐 O(폭) |
| 힙 N개 push·pop | O(N log N) | O(N) |
| K번째 큰 수(크기 K 힙) | O(N log K) | O(K) |

K번째 큰 수에서 전부 정렬하면 O(N log N)이지만, 크기를 K로 묶어 두면 힙이 작아져 log K가 된다. K가 작을 때 차이가 난다.

## 흔한 오해

- 힙은 정렬된 배열이다: 아니다. 위에서 본 대로 `heapify` 결과는 정렬이 아니고 루트만 보장된다.
- 힙에서 중간 값을 찾을 수 있다: 최솟값 외의 탐색은 O(N)이다. 특정 값을 빼야 하는 문제는 지연 삭제나 다른 구조를 고민해야 한다.
- 이진 트리와 이진 탐색 트리는 같다: 이진 탐색 트리는 왼쪽 < 루트 < 오른쪽이라는 조건이 더 붙는다. 힙은 이진 트리지만 그 조건이 없다.
- 레벨 순회에 재귀를 쓴다: 가능은 하지만 보통 큐로 쓴다.

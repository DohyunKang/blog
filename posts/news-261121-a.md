오늘 아침 GitHub 트렌딩(daily)에 HKUDS/CLI-Anything이 올라와 있었다. 오늘 별 774개, 레포 전체 별은 61,363개다(11월 21일 오전 확인). 홍콩대 HKUDS 연구실이 만든 건데, 사람이 마우스로 쓰라고 만든 데스크톱 프로그램(GIMP, Blender, LibreOffice 같은 것)에 AI 에이전트가 쓸 명령줄 도구를 붙여 주는 프로젝트다. 나는 README, 플러그인 폴더의 HARNESS.md, CLI-Hub 메타 스킬의 SKILL.md를 읽었고 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
CLI는 마우스 대신 글자로 명령을 쳐서 프로그램을 쓰는 방식이다. 에이전트는 원래 텍스트를 읽고 쓰는 쪽이라, 버튼을 찾아 누르는 것보다 명령을 치는 게 훨씬 잘 맞는다. 에이전트가 도구를 고르고 부르는 흐름은 예전에 정리해 뒀다. [자세히 → 도구 호출](#/post/ai-tool-use)

CLI-Anything은 두 가지로 나뉜다. 하나는 Claude Code 플러그인으로, `/cli-anything ./gimp`처럼 프로그램 소스 폴더를 주면 에이전트가 그 프로그램용 CLI를 새로 만든다. 다른 하나는 이미 만들어 둔 CLI를 모아 둔 CLI-Hub다. `pip install cli-anything-hub` 후 `cli-hub install gimp`처럼 깐다. 레포 안 레지스트리 파일 두 개에 각각 79개, 24개가 등록돼 있었다.

만들어진 CLI는 이렇게 쓴다. README 예시를 그대로 옮기면 `cli-anything-libreoffice document new -o report.json --type writer`로 문서를 만들고, 제목과 표를 명령으로 넣은 다음, `export render output.pdf`로 실제 LibreOffice를 화면 없이 돌려 PDF를 뽑는다. 모든 명령에 `--json`을 붙이면 결과가 JSON으로 나와서 에이전트가 바로 읽는다. 명령 없이 실행하면 대화형 모드(REPL)로 들어가 한 줄씩 칠 수도 있다.

## 안에서 어떻게 만드는지
`/cli-anything`을 부르면 7단계가 돈다. 소스 분석, 명령 구조 설계, 구현, 테스트 계획, 테스트 작성, 문서화, 설치 패키지 만들기 순이다. 마지막에 그 CLI 사용법을 적은 SKILL.md도 같이 생긴다. 스킬은 에이전트가 필요할 때 꺼내 읽는 설명서다. [자세히 → 스킬](#/post/ai-skills)

HARNESS.md가 사실상 설계 문서인데, 첫 단계가 재밌었다.

1. GUI 뒤에 있는 엔진을 찾는다. 화면은 껍데기고 실제 일은 안쪽 라이브러리가 한다. 문서는 영상 편집기 Shotcut 뒤의 MLT를 예로 든다.
2. 버튼 클릭, 메뉴 하나하나가 결국 어떤 함수 호출인지 짝을 맞춘다.
3. 프로젝트 파일 형식(XML, JSON 등)을 파악한다.
4. 프로그램에 실행 취소(undo)가 있으면 그게 곧 명령 단위다. 실행 취소가 되려면 동작이 명령 하나하나로 쪼개져 있어야 하니까, 그걸 그대로 CLI 명령으로 옮긴다.

원칙 중에 눈에 띈 건 진짜 프로그램을 꼭 부른다는 것이다. GIMP 대신 파이썬 이미지 라이브러리로 흉내 내지 않고, 프로젝트 파일을 만든 다음 렌더링은 실제 프로그램에 맡긴다. 프로그램이 안 깔려 있으면 테스트를 건너뛰지 않고 실패로 처리한다고 적혀 있다. 또 "종료 코드가 0이라고 내보내기가 된 걸로 믿지 말라"는 항목이 있다. PDF면 파일 맨 앞이 `%PDF-`인지, 오디오면 소리 크기가 0이 아닌지까지 확인하라는 거다. 이런 확인을 다 합쳐 README에 테스트 2,464개 통과라고 적혀 있다.

X에서 반복되는 말은 거의 하나였다. 스크린샷을 찍고 좌표를 눌러 앱을 쓰는 방식은 버튼 위치가 바뀌거나 팝업이 뜨면 깨진다는 것. 지난번에 본 agent-desktop은 접근성 트리로 화면 요소를 읽는 쪽이었는데, 이건 아예 화면을 거치지 않고 엔진에 바로 붙는 쪽이다. [자세히 → agent-desktop](#/post/news-261111-a)

## 입문자 입장에서
PM 입장에선 "이 프로그램을 에이전트가 쓸 수 있나"를 묻는 기준이 하나 생긴 셈이다. 화면 대신 명령과 JSON으로 다룰 수 있으면 자동화가 덜 깨진다. 다만 README 스스로 한계를 적어 놨다. 성능 좋은 최신 모델이 있어야 제대로 된 CLI가 나오고, 소스 코드가 없는 프로그램은 품질이 크게 떨어지며, 한 번에 다 안 되면 `/cli-anything:refine`을 여러 번 돌려야 한다고 한다.

개발 입문자라면 HARNESS.md를 기능 설계 연습 문서로 읽어도 좋을 것 같다. "보기 명령을 먼저 만들고 바꾸는 명령은 그 뒤에" 같은 순서는 에이전트가 아니어도 그대로 통하는 얘기다. 에이전트가 도구를 쓰는 다른 방식인 MCP와 비교해서 보면 차이가 더 잘 보인다. [자세히 → MCP](#/post/ai-mcp)

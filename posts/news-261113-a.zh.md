## 是什么
OpenAI 的一个工具，能在代码里找安全漏洞、确认是不是真的有问题、再把它修掉。可以在 Codex 里当插件用，也可以在终端用 `cs` 命令，或者用 TypeScript SDK 和 GitHub Action 自动化。漏洞就是攻击者能利用的代码缺口，比如 SQL 注入、漏了权限检查。

传统安全扫描器找的是符合固定规则(模式)的代码。这个是让编程代理边读代码边调查。代理就是模型一边用工具一边自己走好几步的程序。[详细 → 代理与代理循环](#/post/ai-agent-loop)

## 怎么运行
基本就是一行 `cs scan .`。跑完后文件夹里留下三个文件。

- `report.md`:把范围和发现整理成人能读的报告
- `findings.json`:每个发现的源码位置和依据
- `scan-manifest.json`:扫了什么、排除了什么

范围可以选整个仓库、指定路径(`--path`)、提交差异(`--diff origin/main`)或还没提交的改动(`--working-tree`)。审 PR 就用差异扫描。

模式有 Standard 和 Deep 两种。Deep 会重复多次 Standard 扫描。几个 worker 同时调查，可以互相请对方"看看这个位置",下一批会拿到前面发现的标题和位置，去挖别的路径。连续几次没有新发现就停(`--stop-after-no-new`)。文档里写的默认模型是 `gpt-5.6-sol`,推理强度 `xhigh`,一个父代理加最多8个委派 worker。[详细 → 子代理与多代理](#/post/ai-subagent)

找到之后的步骤，我觉得才是这个工具的重点。

- validate:重新审一个发现，判断是不是真的。这时工具只能读代码，网络和网页搜索都关掉。
- patch:为发现写修复补丁，需要的话还能建草稿 PR。可以附上补丁风险评估。
- verify-fix:修完再看一遍，回答 fixed、still_vulnerable 或 inconclusive。退出码也分成0、1、2,好接进 CI。

报告里会单独记下"看到了哪里",这点也挺显眼。文档写着，扫描完成是指流程跑完了，不代表每个文件、每种漏洞都看过了。排除的路径、推迟的工作、遗留的问题都会记录。

另外还有起草 `SECURITY.md`、保存威胁模型、导入 Semgrep・Snyk・Wiz 等其他扫描器的结果、发到 Linear・Jira・GitHub、导出 SARIF・JSON・CSV。威胁模型是整理"谁能从哪里攻击什么"的文档。

## 从入门者角度看
作为 PM,我喜欢它把"找到""确认""修好"分成不同步骤。不直接信 AI 的结果，而是把依据和范围一起留下，听汇报会比较省心。开发入门的话，可以先在小仓库里每个 PR 跑一次 `cs scan . --diff origin/main`。GitHub Action 示例按每次扫描预估上限5美元设置，并写明进行中的请求可能超出上限。

要注意的地方。需要登录或 API 密钥，模型使用要花钱。部分安全请求和受保护的发现需要 OpenAI 的 Trusted Access for Cyber 授权。据说也能用 Bedrock、OpenRouter、Fireworks AI 等其他提供商。实际检测准确率的数字没确认。仓库里有 evals 文件夹，但我没读结果。对按技能拆分的结构感兴趣的话，可以一起看这篇。[详细 → 技能](#/post/ai-skills)

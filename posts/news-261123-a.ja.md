## 何をするものか
スキルは、エージェントが必要なときに取り出して読む説明書だ。[詳しく → スキル](#/post/ai-skills) このリポジトリのスキルはすべて Stitch MCP サーバー経由で動く。MCP は、エージェントが外部サービスの機能をツールのように呼べるようにする接続規格だ。[詳しく → MCP](#/post/ai-mcp) だからスキルを入れるだけでは足りず、先に Stitch 側の MCP 設定が要る。

プラグインは三つに分かれている。

1. stitch-design:テキストや画像から画面を作る・直す、既存のフロントエンドコードを Stitch のデザインに移す、DESIGN.md をアップロードする。
2. stitch-build:Stitch の画面を React、React Native のコンポーネントにする、画面をめくって見せる紹介動画(Remotion)を作る。
3. stitch-utilities:ぼんやりした依頼を Stitch 向けプロンプトに整える、DESIGN.md・SITE.md を作る、複数ページのサイトを続けて作るループ。

インストールは Claude Code や Cursor なら `npx plugins add` 一行、Codex はマーケットプレイス登録。スキルの形式が公開標準(Agent Skills)なので、OpenCode にはフォルダをコピーすればいいと書いてある。

## DESIGN.md が真ん中にある
読んでみると、ほぼすべてのスキルが DESIGN.md というファイル一つを中心に回っている。色、フォント、余白、角の丸みといったデザインのルールを言葉で書いたファイルだ。design-md スキルの説明によると、Stitch はデザインを「目に見える描写」と具体的な色の値で理解する。だから新しい画面を作るたびにこのファイルの内容をプロンプトに入れて、前の画面とトーンを合わせる。

方向は二つある。デザインからコードへは、Stitch 画面の HTML を受け取ってコンポーネントに分ける。コードからデザインへは、code-to-design がすでに動いている Web アプリから HTML を一枚抜き出し、ソースから DESIGN.md を抜き出して、両方を Stitch に上げる。作った画面をもう一度デザインツールに戻して手直しできるようにしたわけだ。

## サイトを作り続けるループ
stitch-loop はバトンリレー方式だ。`.stitch/next-prompt.md` に次に作るページが書いてあり、エージェントはそれを読んでページを作り、サイトにつなぎ、サイトマップ(SITE.md)を直したあと、次のページの作業をまたそのファイルに書いて終わる。会話の記憶に頼らずファイルに状態を残すので、セッションが変わっても次のエージェントが引き継げる。Chrome DevTools MCP があれば、作ったページを開いてスクリーンショットを撮り、Stitch の元画像と比べる手順もある(任意)。

## ルールは文章で、一部はコードで止める
react-components スキルは口調がかなり強い。段階ごとに GATE があって、「この条件を満たすまで次に進むな」と書いてある。コンポーネントはファイルを分け、ロジックは hooks へ、文言や画像 URL は mockData へ出し、色は hex 値でなくテーマのクラスを使え、という。

このうち一部は validate.js が実際にチェックする。コードを構文木(AST、コードを構造の単位に分けた形)として読み、名前が Props で終わるインターフェースがあるか、className に `#1a2b3c` のような hex 色が埋め込まれていないかを見る。11月20日のコミットもこのチェックの修正だった。className を式で組み立てても hex を捕まえるようにし、React Native のコンポーネントに Web 専用タグが入ったら弾くようにした。すべてのルールがコードで止められるわけではない。私が読んだ validate.js の範囲では Props インターフェースと hex 色の二つで、残り(ファイル分割、hooks の分離など)はドキュメントでお願いしているレベルだ。

## 入門者の目線で
PM や開発の入門者にとって見どころは DESIGN.md のほうだ。デザインのルールを人が読める文章で書いておけば、人間のデザイナーにもエージェントにも同じ基準になる。エージェントが画面ごとに勝手に色を選ぶ問題を、プロンプト一行ではなくファイル一つで解くやり方だ。前に見た Meta の Astryx も、エージェントにデザインシステムの文書を先に読ませる方向だった。[詳しく → Astryx](#/post/news-261117-a)

Claude Code released versions 2.1.316, 2.1.317, and 2.1.318 between October 31 and November 4. The release pages are dated 31 Oct, 3 Nov, and 4 Nov respectively (the year is not shown). I reviewed the changelogs and extracted only the items that stood out from a personal user perspective. There are many entries related to Gateway and Bedrock; since those are for organization administrators, they are not covered here.

## Fixed Dates: Opus 4.8 Fast Mode

The entry for 2.1.316 notes that Opus 4.8's fast mode (fast mode) was deprecated as of October 30, 2026, and will be removed on November 30. After removal, requests using this mode will return an error, and users are directed to migrate to Opus 5.5. If you are currently using the fast mode setting, you must switch before November 30.

## Items for Fine-Tuning Effort

The `effort` setting determines how much thinking a model dedicates to a task. Several entries in these three releases adjust this setting.

| Version | Item | Description |
|---|---|---|
| 2.1.316 | `CLAUDE_CODE_SUBAGENT_EFFORT` | Specifies the effort level used by sub-agents |
| 2.1.316 | `CLAUDE_CODE_DISABLE_ULTRATHINK` | Disables the `ultrathink` keyword |
| 2.1.318 | mod's `$.model.fork` | Allows specifying `effort`, enabling short forked tasks to run with `low` effort |

This means you can now set a separate effort level for sub-agents via a single environment variable. While assigning low effort to sub-agents handling light tasks like research or file searching is expected to reduce token usage, I have not yet measured the exact reduction.

## Security-Related Changes

Version 2.1.317 includes the following items:

- Web tools and shell tools now prompt for confirmation before sending account email addresses over the network.
- A warning is issued in `/schedule` if a connector not requested by the user is attached to a new cloud job.
- The Agent SDK's hook callbacks now include `onFailure: "block"`, allowing hooks to block an action upon failure.
- `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID` was added for self-hosted runners.

Version 2.1.318 adds the ability to show when a saved claude.ai login expires in the JSON output of `claude auth status` and `claude -p`. Additionally, a warning is emitted to stderr starting 10 days before expiration. This allows automation scripts running `claude -p` to be alerted in advance if they might suddenly stop due to expiration.

## Miscellaneous

All three releases include fixes for issues such as settings/login storage corruption on network drives, MCP server connection drops, compaction, and Windows path validation. In 2.1.317, the Read tool was changed to no longer return a "file unchanged" stub.

The above content is based on the changelog entries; however, allowed values for each environment variable cannot be determined from the changelogs alone.

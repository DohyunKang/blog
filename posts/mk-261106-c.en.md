When you distribute content across multiple channels using marketing automation, you need to track where each visit originated. UTM parameters appended to links serve this purpose. However, manually typing these values is prone to errors. Therefore, I have standardized the process of generating links via code, based on Google Analytics documentation.

## UTM Parameters
The documentation defines them as follows:

| Parameter | Meaning |
|---|---|
| utm_source | Traffic source (e.g., search engine, newsletter) |
| utm_medium | Medium (e.g., cpc, banner, email) |
| utm_campaign | Product, slogan, or promotion code (e.g., spring_sale) |
| utm_id | Campaign ID. Match this with the ID used when uploading campaign data. |
| utm_term | Paid keyword |
| utm_content | Distinguishes assets, such as two CTAs within the same email |

The documentation states that `utm_source`, `utm_medium`, and `utm_campaign` should always be included. GA4 uses these values to treat sessions as custom campaigns, and the values map directly to the Source, Medium, and Campaign dimensions in reports.

## Problems Caused by Inconsistency
According to the documentation, values are case-sensitive. `utm_source=google` and `utm_source=Google` are aggregated differently. Similarly, `SpringSale` and `Spring_Sale` are treated as distinct values. The documentation recommends lowercase letters as the standard. It advises platforms to define a single source, a single medium per channel, and to match campaign names exactly. If a value is missing, reports will display "(not set)".

In automation workflows, where one piece of content is generated for multiple channels, links are created simultaneously. Manually entering values exacerbates the issues mentioned above.

## Fixing with Code
I have established three rules: normalize values to lowercase and underscores; block any medium not on an allowlist; remove existing `utm_` parameters and re-append them. The code below can be executed directly to verify the output.

```python
import re
from urllib.parse import urlsplit, urlunsplit, parse_qsl, urlencode

ALLOWED_MEDIUM = {"email", "cpc", "paid_social", "social", "referral"}

def slug(v):
    v = v.strip().lower()
    v = re.sub(r"[\s\-]+", "_", v)
    return re.sub(r"[^a-z0-9_]", "", v)

def build(url, source, medium, campaign, content=None):
    medium = slug(medium)
    if medium not in ALLOWED_MEDIUM:
        raise ValueError(f"medium not allowed: {medium}")
    p = urlsplit(url)
    q = [(k, v) for k, v in parse_qsl(p.query) if not k.startswith("utm_")]
    q += [("utm_source", slug(source)), ("utm_medium", medium), ("utm_campaign", slug(campaign))]
    if content:
        q.append(("utm_content", slug(content)))
    return urlunsplit((p.scheme, p.netloc, p.path, urlencode(q), p.fragment))
```

Here are the execution results:

```
build("https://example.com/launch?ref=a", "News Letter", "Email", "Spring Sale", "Top-CTA")
-> https://example.com/launch?ref=a&utm_source=news_letter&utm_medium=email&utm_campaign=spring_sale&utm_content=top_cta

build("https://example.com/launch", "Instagram", "paid-social", "SpringSale")
-> https://example.com/launch?utm_source=instagram&utm_medium=paid_social&utm_campaign=springsale

build("https://example.com/launch", "x", "Newsletter", "a")
-> ValueError: medium not allowed: newsletter
```

As in the third example, mediums not on the allowlist are blocked with an error. You can expand the list as needed for your specific channels. One point to note: normalizing `SpringSale` (as in the second result) yields `springsale`, whereas writing the same campaign as `Spring Sale` results in `spring_sale`. These become different values. Since normalization only handles case sensitivity and cannot manage word delimiters, campaign names must be retrieved from a single source (e.g., a campaign list).

## When Applying to Automation
- Store the campaign list in one file and reference only the name during content or video publication.
- Include an asset identifier in `utm_content` to distinguish versions of the same content.
- The documentation notes that UTM parameters are excluded from the Landing page + query string dimension but appear in the Page location dimension when creating reports. Ensure you view the appropriate dimensions when building your reports.

ADsP 2과목 데이터분석 기획의 첫 단원이다. 분석 기획은 어떤 분석 과제를 어떤 방식으로, 어떤 순서로 할지 미리 정하는 단계다. 데이터를 만지기 전에 하는 일이라 코드나 통계 공식은 안 나오고, 대신 분류와 용어를 정확히 묻는다. 시험 일정과 응시료는 공식 사이트에서 확인하면 된다. 이 글은 단원별 핵심 개념과 자주 나오는 유형, 푸는 방식 위주로 정리했다.

## 분석 기획이 하는 일

분석을 시작하기 전에 정해야 할 건 크게 두 가지다. 무엇을 분석할지(분석 대상)와 어떻게 분석할지(분석 방법)다. 이 두 가지를 이미 알고 있는지에 따라 접근이 달라진다. 이 단원 전체가 결국 이 구분에서 뻗어 나간다고 보면 된다.

과목 구성에서 데이터분석 기획은 10문항 정도의 과목이고, 데이터분석 기획의 이해와 분석 마스터 플랜 두 덩어리로 나뉜다. 이 글은 앞쪽인 기획의 이해를 다루고, 뒤쪽은 [자세히 → 분석 과제와 마스터플랜](#/post/adsp-task-masterplan)에서 이어진다. 방법론(KDD, CRISP-DM)은 [자세히 → 분석 방법론](#/post/adsp-methodology)에 따로 있다.

## 분석 대상·방법 4분면

가장 자주 나오는 그림이다. 대상과 방법을 각각 안다/모른다로 나누면 네 칸이 생긴다.

| 구분 | 분석 방법을 안다 | 분석 방법을 모른다 |
|---|---|---|
| 분석 대상을 안다 | 최적화 (Optimization) | 해결 (Solution) |
| 분석 대상을 모른다 | 통찰 (Insight) | 발견 (Discovery) |

외우는 요령은 대상 먼저, 방법 나중으로 읽는 것이다.

- 둘 다 안다 → 최적화. 이미 하던 분석을 더 낫게 다듬는 일이다.
- 대상은 아는데 방법을 모른다 → 해결. 풀 문제는 있는데 어떻게 풀지 새로 찾아야 한다.
- 대상은 모르는데 방법은 안다 → 통찰. 가진 분석 기법으로 데이터를 보다가 볼 만한 걸 찾는다.
- 둘 다 모른다 → 발견. 뭘 봐야 할지부터 모르는 상태라 새로운 대상을 찾는 일이다.

시험은 보통 "분석 대상은 알지만 방법을 모르는 경우는?" 같은 식으로 칸 하나를 말로 설명하고 이름을 고르게 한다. 통찰과 해결이 헷갈리기 쉬운데, 해결은 대상을 알고 통찰은 방법을 안다고 짝지어 두면 안 틀린다.

## 접근 방식: 하향식과 상향식

4분면에서 대상을 아느냐가 접근 방식과 이어진다. 풀 문제가 주어졌으면 하향식, 문제가 뭔지부터 모르면 상향식이다.

| 구분 | 하향식 | 상향식 |
|---|---|---|
| 출발점 | 문제가 주어졌다, 분석 대상이 명확하다 | 문제가 뭔지 모른다 |
| 방식 | 문제를 찾고 정의한 뒤 해법을 정한다 | 데이터를 먼저 보고 패턴에서 문제를 찾는다 |
| 대표 기법 | 문제 탐색 → 정의 → 해결방안 탐색 → 타당성 검토 | 탐색적 데이터 분석(EDA), 비지도 학습, 연관 규칙, 군집 분석, 프로토타이핑 |

하향식의 네 단계 순서는 그대로 나오니 외워 둔다.

1. 문제 탐색: 비즈니스 모델이나 외부 사례에서 문제를 찾고 분석 유스케이스를 정의한다.
2. 문제 정의: 비즈니스 문제를 데이터 분석 문제로 바꾼다.
3. 해결방안 탐색: 분석 기법, 시스템, 인력을 어떻게 확보할지 본다.
4. 타당성 검토: 경제적 타당성과 데이터·기술 타당성을 평가해 과제를 확정한다.

상향식은 프로토타이핑을 반복하면서 문제 자체를 정의해 간다. 가설을 세우고, 작게 실험하고, 실제 환경에서 시험하고, 결과에서 인사이트를 뽑는 식이다. 실무에서는 하향식과 상향식을 번갈아 쓰는 게 권장된다고 한다. 두 방식의 자세한 절차는 [자세히 → 분석 방법론](#/post/adsp-methodology)에서 더 본다.

<details>
<summary>하향식 문제 탐색의 두 갈래와 해결방안 탐색 표</summary>

문제 탐색은 어디서 문제를 찾느냐에 따라 둘로 나뉜다.

- 비즈니스 모델 기반: 조직 내부의 업무, 제품, 고객, 규제와 감사, 지원 인프라를 살펴본다.
- 외부 참조 모델 기반: 유사 업계의 사례를 벤치마킹해서 외부에서 기회를 찾는다. 벤치마킹은 내부가 아니라 외부 참조 모델에 속한다는 점이 보기에서 자주 바뀐다.

분석 유스케이스는 풀 문제의 설명과 풀었을 때의 기대 효과를 적어 둔 것이다. 이후 데이터 분석 문제로 바꾸고 적합한지 평가할 때 쓴다.

해결방안 탐색은 두 기준으로 갈린다. 기존 시스템으로 분석이 되는지, 분석 역량을 갖췄는지다.

| | 분석 역량 확보 | 분석 역량 미확보 |
|---|---|---|
| 기존 시스템 활용 가능 | 기존 시스템 개선 활용 | 교육 및 채용으로 역량 확보 |
| 신규 도입 필요 | 시스템 고도화 | 전문 업체 활용(아웃소싱) |

</details>

## 목표 시점별 접근

같은 분석이라도 얼마나 먼 시점을 보느냐에 따라 접근이 둘로 나뉜다.

| 구분 | 과제 중심 (당면 과제 해결) | 마스터 플랜 (지속적 분석 내재화) |
|---|---|---|
| 1차 목표 | 빠르게 시도하고 검증하기 | 정확하게 만들어 업무에 배포하기 |
| 과제 유형 | 짧은 기간에 눈에 보이는 성과 | 장기적 관점 |
| 접근 방식 | 주어진 문제를 해결 | 풀어야 할 문제 자체를 정의 |

둘 중 하나만 고르는 게 아니라 섞어 쓴다. 당면 과제로 빠른 성과를 내면서 마스터 플랜으로 장기 체계를 세우는 식이다. 보기에서 "과제 중심 접근은 문제 자체를 정의한다"처럼 두 열을 바꿔 놓은 문장이 자주 섞인다. 문제 자체를 정의하는 쪽이 마스터 플랜이다. 마스터 플랜의 우선순위 기준(전략적 중요도, ROI, 실행 용이성)은 [자세히 → 분석 과제와 마스터플랜](#/post/adsp-task-masterplan)에서 다룬다.

## 분석 기획 시 고려사항

기획할 때 미리 챙길 것은 세 가지로 묶인다.

1. 가용 데이터: 데이터가 있는지, 정형인지 비정형인지 반정형인지를 먼저 본다. 유형에 따라 쓸 솔루션과 분석 방법이 달라진다.
2. 적절한 활용 방안과 유스케이스: 유사 사례나 이미 있는 솔루션을 찾아 쓰면 사용자 공감을 얻기 쉽고 도입도 쉽다.
3. 장애요소 사전 계획: 비용, 결과의 정확도와 이해도, 조직 역량, 일회성으로 끝나지 않게 하는 변화 관리 같은 걸 미리 대비한다.

"가용 인력"은 이 세 가지에 들어 있지 않다. 보기에 끼워 넣어 틀린 걸 고르게 하는 유형이 나올 수 있으니 세 개를 이름 그대로 기억해 두는 게 낫다.

## 분석 활용 시나리오

분석 결과를 어떤 목적에 어떻게 쓸지 정한 계획이다. 분석 목표, 분석 방법, 예상 결과(기대 효과)를 담아 쓰고, 과제를 정의하거나 이해관계자와 방향을 맞출 때 쓴다. 중심은 분석 목적과 결과 활용 방안이고, 데이터는 시나리오를 실행하려고 검토하는 요소 중 하나다. 프로젝트 중에 데이터 상황이나 업무 요구가 바뀌면 시나리오도 바뀔 수 있다.

## 자주 틀리는 부분

- 해결과 통찰이 뒤바뀐 보기. 해결은 대상을 알고, 통찰은 방법을 안다.
- 벤치마킹을 비즈니스 모델 기반 문제 탐색으로 분류한 보기. 외부 참조 모델 기반이다.
- 고려사항에 가용 인력을 넣은 보기. 가용 데이터, 유스케이스, 장애요소 세 가지다.
- 과제 중심과 마스터 플랜의 특징을 서로 바꾼 보기.
- 하향식 4단계의 순서를 섞어 놓은 보기. 문제 탐색, 문제 정의, 해결방안 탐색, 타당성 검토 순이다.

기출문제는 원문을 옮기지 않고 유형만 적었다. 이 단원 문제는 계산 없이 용어를 짝짓는 쪽이라서, 4분면 표를 손으로 한 번 그려 보고 나서 보기 문장을 읽으면 풀리는 속도가 달랐다. 다음 단원은 [분석 방법론](#/post/adsp-methodology)이다.

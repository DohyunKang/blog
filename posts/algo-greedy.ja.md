貪欲法は、各ステップで現在最も良さそうな選択を行い、一度決めた選択は撤回しないアプローチです。コードは短いが、この手法が正解を与えるかを確認するのが問題の大半を占めます。

## グリディとは何か

탐욕 알고리즘이라고도 부른다. → 貪欲法（ 탐욕 알고리즘）とも呼ばれます。ウィキペディアの説明では、各ステップで局所的に最適な選択を行い、以前の選択を撤回しないアルゴリズムです。同じ文章中には、動的計画法の極端な形態、すなわち部分解を一つだけ持っていく方式とも説明されています。DP は複数の候補を持ちながら比較しますが、貪欲法は一つだけ残し、他は捨てます。

そのため速いです。代わりに間違える可能性があります。最大の数字を追って上がる道が最後には行き止まりになっていることもあります。

## 適用できる場合

2 つの条件を満たす必要があります。

| 条件 | 意味 |
| --- | --- |
| 탐욕 선택 속성 | 지금 제일 좋아 보이는 선택을 해도, 그걸 포함한 최적해가 존재한다 | 貪欲選択特性：今最も良さそうな選択をしても、その選択を含む最適解が存在する |
| 최적 부분 구조 | 그 선택을 하고 남은 문제도 같은 종류의 문제이고, 그 최적해를 붙이면 전체 최적해가 된다 | 最適部分構造：その選択を行った後の問題も同種の問題であり、その最適解を付け加えることで全体の最適解になる |

ウィキペディアの本文ではこの用語を直接使用せず、交換論法（exchange argument）で説明しています。最適解と貪欲解が初めて異なる地点で、最適解の選択を貪欲選択に変えても結果が悪化しなければ、帰納法によって貪欲法が最適であるという結論に至ります。

コーディングテストでは証明まで行うわけではありません。ソート基準を一つ決め、反例をいくつか手動で見つけ、見つからない場合はその基準を採用します。反例が見つからないことと証明したことは異なるため、少し不安を抱えたまま提出することになります。

## 代表的な問題

問題本文はそのまま転記せず、名前と一行の説明のみ記載します。

- 프로그래머스 단속카메라: 차량마다 진입·진출 지점이 주어질 때, 모든 차량이 카메라를 한 번은 지나도록 카메라를 최소로 둔다. 구간을 끝 지점순으로 정렬하는 회의실 배정과 같은 구조다.
  - プログラマーズ 監視カメラ：各車両の進入・退出地点が与えられたとき、すべての車両が少なくとも一度はカメラを通るように、カメラを最小限に配置する。区間を終了点順にソートする会議室割り当てと同じ構造です。
- 프로그래머스 큰 수 만들기: 숫자 문자열에서 k 자리를 지워 가장 큰 수를 만든다. 앞자리부터 큰 수를 남기는 그리디다.
  - プログラマーズ 大きな数を作る：数字の文字列から k 桁を削除して最大の数を生成する。先頭から大きな数を残す貪欲法です。
- 프로그래머스 디스크 컨트롤러: 작업의 요청 시각과 소요 시간이 주어질 때 평균 반환 시간을 최소로 한다. 짧은 작업부터 고르는 그리디에 힙을 같이 쓴다.
  - プログラマーズ ディスクコントローラー：タスクの要求時刻と所要時間が与えられたとき、平均返却時間を最小化する。短いタスクから選ぶ貪欲法にヒープを併用します。
- 프로그래머스 구명보트: 한 번에 최대 두 명, 무게 제한 안에서 보트를 최소로 쓴다.
  - プログラマーズ救命ボート：一度に最大 2 名、重量制限内でボートを最小限使用する。

## 解法の思考手順

1. 最適化問題か確認する（最大・最小）。
2. ソート基準の候補をいくつか挙げる。開始時刻、終了時刻、長さ、単価など。
3. 各基準について反例を手書きで描いてみる。小さな入力 3〜4 つであれば、ほとんどがフィルタリングされる。
4. 反例が見つからない基準が残っていれば、交換論法で一度検討する。
5. 最後まで不安なら、DP や全探索で小さな入力を比較してみる。

会議室割り当ては、最も早く終了する会議を先に取るのが正解です。早めに開始するものから取ると、(1,10) が (2,3)、(4,5) の 2 つを妨げます。長さから取るのも反例があります。交換論法はこうなります。最適解の最初の会議を終了時刻が最も早い会議に変えても重なることはなく個数も同じなので、貪欲選択を含む最適解が存在します。この問題はウィキペディアの activity selection problem ドキュメントでも同様の方法で出てきます。

## Python コード

以下のコードはすべて実際に実行して値を確認しました。会議室割り当ては、ランダムな小規模入力 300 で全探索の結果とも一致させました。

```python
def max_meetings(iv):
    iv.sort(key=lambda x: (x[1], x[0]))   # 끝나는 시각, 같으면 시작 시각
    cnt, end = 0, -1
    for s, e in iv:
        if s >= end:
            cnt += 1
            end = e
    return cnt

print(max_meetings([(1,4),(3,5),(0,6),(5,7),(3,8),(5,9),(6,10),(8,11),(8,12),(2,13),(12,14)]))  # 4
```

終了時刻が同じ場合は開始時刻でソートする必要があります。開始と終了が同じ会議（長さ 0）も正しく扱えます。会議室割り当て類の問題ではこのような入力が現れる可能性があるため、ソート基準に開始時刻も含めています。

硬貨問題は単位が倍数関係なので貪欲法になります。

```python
def coin_greedy(coins, k):
    cnt = 0
    for v in sorted(coins, reverse=True):
        cnt += k // v
        k %= v
    return cnt if k == 0 else -1

print(coin_greedy([500, 100, 50, 10], 1260))  # 6
```

ヒープを併用する形式も多いです。同時に何個の会議が重なるか数える会議室数の問題です。

```python
import heapq

def min_rooms(iv):
    iv.sort()                      # 시작 시각순
    h = []                         # 쓰고 있는 방들의 끝나는 시각
    for s, e in iv:
        if h and h[0] <= s:
            heapq.heapreplace(h, e)   # 비는 방 재사용
        else:
            heapq.heappush(h, e)      # 새 방
    return len(h)

print(min_rooms([(0, 30), (5, 10), (15, 20)]))  # 2
```

<details>
<summary>ハフマン符号合成コスト（優先度キュー・貪欲）</summary>

最も小さい 2 つを続けて合成する方式です。ウィキペディアにもハフマン木はこうしてできると記載されています。合成コストの合計は以下のようになります。

```python
import heapq

def merge_cost(ws):
    h = list(ws)
    heapq.heapify(h)
    total = 0
    while len(h) > 1:
        a, b = heapq.heappop(h), heapq.heappop(h)
        total += a + b
        heapq.heappush(h, a + b)
    return total

print(merge_cost([10, 20, 30, 40]))  # 190
```

10+20=30, 30+30=60, 40+60=100, 合計 190 です。

## 時間・空間計算量

ソートが支配的です。会議室割り当てはソート O(n log n) + 一度スキャン O(n) なので全体 O(n log n) で、空間はソートを就地で行えば O(1) です（Python の `sort` は内部で補助空間を使います）。ヒープを使う問題はプッシュ・ポップが O(log n) なので同様に O(n log n) です。[時間計算量の読み方 → 時間計算量と Python 基本](#/post/algo-complexity)

## よくある誤解と反例

貪欲法が成立しない代表的な例は硬貨の問題です。硬貨の単価が 1, 4, 5 원で合計 8 원を作る場合、貪欲法では 5+1+1+1 の 4 枚を使用しますが、正解は 4+4 の 2 枚です。上記の `coin_greedy` は単価が倍数関係にある場合のみ正しく動作し、この入力には使用できません。このような問題は [動的計画法](#/post/algo-dp) で解決します。以下の DP コードで答えが 2 になることを確認しました。

```python
def coin_dp(coins, k):
    INF = 10**9
    d = [0] + [INF] * k
    for i in range(1, k + 1):
        for v in coins:
            if i >= v:
                d[i] = min(d[i], d[i - v] + 1)
    return d[k] if d[k] < INF else -1

print(coin_dp([1, 4, 5], 8))  # 2
```

ナップサック問題も同様の構造です。分割可能な場合（分数ナップサック）は、単価あたりの価値の大きい順に詰める貪欲法が正しく、分割できない場合（0-1 ナップサック）は誤ります。物品が（重量、価値）= (10,60), (20,100), (30,120) で容量が 50 のとき、分数ナップサックなら 240、0-1 ナップサックなら 220 です。ウィキペディアには「0-1 ナップサックは NP-hard」と記載されています。上記の 2 つの値はコードを実行して確認しました。

また、重みが付与されると会議室割り当て問題でも貪欲法が破綻します。ウィキペディアの activity selection の項目にも、重み付きバージョンには貪欲法の解法が存在しないとあり、DP で解く必要があるとされています。

よくある誤解は「並べ替えさえすれば貪欲法になる」という考え方です。並べ替えは道具に過ぎず、その基準が正しいという根拠がない限り貪欲法とはなりません。問題を解いて貪欲法がまず思い浮かんだ場合は、DP で解けるか、反例が存在しないかも同時に確認したほうが良いでしょう。

貪欲法が適切に使えるアルゴリズムも多数あります。ダイクストラ（負の辺がない場合）、クラスカル・プリムの最小全域木、ハフマン符号化はウィキペディアで貪欲法の例として挙げられています。エドモンズはマトロイド構造を持つ問題において貪欲法が最適であることを示しており、その後グリーディッドによって一般化されたという説明もあります。[ダイクストラ → 最短経路・ユニオンファインド・位相順序](#/post/algo-shortest-path) / [ヒープ → ツリー・ヒープ・優先度キュー](#/post/algo-tree-heap) / [ソート → ソートと二分探索](#/post/algo-sort-search)

情報処理技術者試験の「オブジェクト指向」分野は、用語問題とコード出力問題が同時に登場する箇所であり、概念を暗記することとコードを手で追うことの両方をこなす必要があります。試験日程や受験要件は公式サイトで確認できるので、ここでは概念と解法のみ記載します。

## オブジェクト指向とは何か

プログラムを「データとそのデータを扱う動作を束ねた『オブジェクト』」たちの相互作用として捉える考え方です。手続き型プログラミングは関数を順番に呼び出すことに重点が置かれていますが、オブジェクト指向ではどのようなデータがどのような動作と結びつくべきかを最初に整理します。

まず基本用語から整理します。

| 用語 | 意味 |
|---|---|
| クラス | オブジェクトを作成するための設計図。属性（変数）とメソッド（関数）を定義 |
| オブジェクト（インスタンス） | クラスを用いて実際に作成されたもの |
| メソッド | オブジェクトが実行できる動作 |
| メッセージ | オブジェクトに対してメソッドを実行するよう送るリクエスト |
| 生成子（コンストラクタ） | オブジェクトを作成する際に最初に実行されるメソッド |

モデリングに関する話題（クラス図、関係など）は [詳しく → UML とオブジェクト指向分析](#/post/jb-uml) で別途記載します。

## 4 つの特徴

試験では以下の 4 つを説明と結びつける問題として出題されます。

| 特徴 | 一言でいうと | コードでの現れ方 |
|---|---|---|
| 情報カプセル化（カプセル化） | データと動作を束ね、内部は隠し必要なものだけを公開 | private 属性 + getter/setter |
| 継承 | 親の属性・メソッドが子に受け継がれる | `extends`, `class B(A)` |
| 多形性（ポリモーフィズム） | 同じ名前のリクエストがオブジェクトによって異なる動作をする | オーバーライド、オーバーロード |
| 抽象化 | 共通した核心だけを抽出して単純に表現する | 抽象クラス、インターフェース |

暗記で混同しやすいのは「情報隠蔽」と「カプセル化」です。情報隠蔽は「内部を隠す」という目的であり、カプセル化はそのために束ねる方法だと考えれば問題文と一致します。

## 多形性で間違えるポイント

多形性は用語が 2 つに分かれます。

| 分類 | オーバーロード | オーバーライド |
|---|---|---|
| 役割 | 同じ名前だが、引数の個数やタイプが異なる複数のメソッド | 親のメソッドを子が同じ名前で同じ引数で再定義する |
| 関係 | 同じクラス内 | 親子の間 |
| 決定タイミング | コンパイル時 | 実行時 |

Java の公式チュートリアルでは、この実行時の決断を「仮想メソッド呼び出し」と説明しています。変数の宣言されたタイプではなく、変数が実際に指し示すオブジェクトのクラスにあるメソッドが JVM によって呼び出されます。チュートリアルの例でも `Bicycle` タイプの変数に `MountainBike` オブジェクトを代入してメソッドを呼び出すと、`MountainBike` 側のメソッドが実行されるといった内容です。

Python のドキュメントはさらに進んで、Python のすべてのメソッドが事実上仮想であると記載しています。Python では宣言されたタイプという概念がないため、常に実際のオブジェクト基準で検索します。

出力問題ではこの規則がほぼすべてを占めます。変数のタイプは何であれ、オブジェクトが何であるかをみます。

<details>
<summary>実行した例 1 — オーバーライドと super</summary>

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."
    def intro(self):
        return self.name + ":" + self.speak()

class Dog(Animal):
    def speak(self):
        return "멍"

class Puppy(Dog):
    def speak(self):
        return super().speak() + "!"

for a in [Animal("a"), Dog("b"), Puppy("c")]:
    print(a.intro())
```

実行するとこうなります。

```
a:...
b:멍
c:멍!
```

`intro` は `Animal` のみにあるが、その中で `self.speak()` を呼び出すと self が指し示す実際のオブジェクトの `speak` が実行される。Python のドキュメントでも、親メソッドが self の別のメソッドを呼び出す場合、子のオーバーライドが代わりに呼ばれる可能性があるとしてある。`Puppy` は `super()` で親（`Dog`）の結果を受け取り "!" を付加した。
</details>

## コードを読むコツ

C、Java、Python がすべて登場します。文法は違っても読む順序は似ています。

1. どこから始まるかを見つける。C と Java は `main`、Python は最下段の実行文です。
2. 変数ごとに紙に枠を描いて値を一行ずつ書き込む。頭の中でやると必ず間違えます。
3. 反復処理（ループ）は最初の 2〜3 回だけ追うと規則が見え、その後は規則で飛ばします。
4. オブジェクトが登場したら「この変数が指し示す実際のオブジェクトは何か」を先に書き込みます。
5. 最後に出力形式（改行、空白）を再度確認します。

### 言語ごとのよく出るポイント

| 言語 | よくある落とし穴 |
|---|---|
| C | 整数同士で割ると小数点以下が捨てられる。前綴（`++i`）と後綴（`i++`）の違い。ポインタと配列名の関係。文字配列の末尾にはヌル文字が付く |
| Java | オーバーライドは実際のオブジェクト基準、オーバーロードは宣言されたタイプ基準で選ぶ。static メンバはクラスに 1 つだけ。親の生成子が先に実行される |
| Python | インデントがブロックを意味する。リスト・辞書は参照なので一緒に変わる。`//` は整数割算、`/` は実数除算。スライシング `a[1:3]` は末尾番号を含めない |

C と Java の項目は言語の基本的な規則であり、試験問題でも同じ形式で繰り返し出題される部分です。実際にコンパイルして確認する練習を別途しておくのが良いでしょう。

## 2 つの Python の落とし穴

Python はコードが短いため、かえって罠が隠れやすい。公式チュートリアルで直接警告されている箇所が 2 ヶ所あり、実際に実行してみた。

### クラス変数とインスタンス変数

```python
class Counter:
    total = 0
    def __init__(self):
        self.n = 0
    def add(self):
        self.n += 1
        Counter.total += 1

x, y = Counter(), Counter()
x.add(); x.add(); y.add()
print(x.n, y.n, Counter.total)
```

結果は `2 1 3` である。`n` は各オブジェクトごとに独立しており、`total` はクラスに 1 つしかないのですべてが加算される。Java の static 変数と同じ位置づけだ。

### リストをクラス変数として設定すると

```python
class Bag:
    items = []
    def put(self, v):
        self.items.append(v)

p, q = Bag(), Bag()
p.put(1); q.put(2)
print(p.items, q.items)
```

結果は `[1, 2] [1, 2]` となる。2 つのオブジェクトが同じリストを共有している。ドキュメントも同様の問題をトイ例 `tricks = []` で示しており、解決策は `__init__` で `self.items = []` とすることで各オブジェクトごとに作成する必要があると述べている。

<details>
<summary>多重継承とメソッド探索順序</summary>

Python では複数の親クラスを指定できる。探索順序は `クラス.__mro__` で確認できる。

```python
class A:
    def hi(self): return "A"
class B(A):
    def hi(self): return "B" + super().hi()
class C(A):
    def hi(self): return "C" + super().hi()
class D(B, C):
    def hi(self): return "D" + super().hi()
print(D().hi())
print([k.__name__ for k in D.__mro__])
```

```
DBCA
['D', 'B', 'C', 'A', 'object']
```

`super()` は「直上の親」ではなく、この順序における次のクラスを呼び出す。`D` の `super()` は `B` を、`B` の `super()` は `A` ではなく `C` を呼ぶため、結果は `DBCA` となる。ドキュメントでは単純なケースでは深さ優先・左側優先であると記載されているが、実際のルールはより複雑であることが付け加えられている。この順序を追う習慣は、一般的な多形の問題にもそのまま適用できる。
</details>

## アクセス制限とアンダースコア付きの名前

Python には真の private なメンバーはない。ドキュメントを基準にすると、`_spam` は「公開 API ではない」という慣習に過ぎず、`__spam` のようにアンダースコアが 2 つで始まると `_クラス名__spam` として名前が変更される（ネーミングエンタングルメント）。これは防ぐためではなく、子クラスが同じ名前を使用しても衝突しないようにするための仕組みである。カプセル化に関する問題で「Python はアクセスを完全に遮断する」という選択肢があれば、それは誤りの方だと判断すべきだ。

Java には `private`、`protected`、`public`、そして何も付けないデフォルトのアクセシビリティがある。この区別は用語の問題として頻繁に問われる。

## よくあるパターンのまとめ

| 型 | 解法 |
|---|---|
| 特徴・用語のペア合わせ | 上記 4 つの表とオーバーロード/オーバーライドの表を用いて解く |
| 継承・オーバーライドの出力 | 実際のオブジェクトのクラスから書き始め、そのクラスでメソッドを上へ探索して辿る |
| コンストラクタの呼び出し順序 | 親コンストラクタ → 子コンストラクタ の順に出力を繋げて書く |
| static・クラス変数 | オブジェクトごとのセルとクラス用のセルを別々に描いて値を追跡する |
| 演算子・ループの出力 | 変数のセル表を描き、行ごとに処理する |

## 它是做什么的
技能是代理需要时拿出来读的说明书。[详细 → 技能](#/post/ai-skills) 这个仓库的技能全都通过 Stitch MCP 服务器运行。MCP 是让代理像调用工具一样调用外部服务功能的连接规范。[详细 → MCP](#/post/ai-mcp) 所以光装技能不够，得先把 Stitch 那边的 MCP 配好。

插件分三组。

1. stitch-design:用文字或图片生成、修改界面，把现有前端代码搬进 Stitch 设计，上传 DESIGN.md。
2. stitch-build:把 Stitch 界面转成 React、React Native 组件，生成逐屏展示的介绍视频(Remotion)。
3. stitch-utilities:把模糊的需求整理成适合 Stitch 的提示词，生成 DESIGN.md、SITE.md,还有一个连续搭建多页网站的循环。

安装在 Claude Code 或 Cursor 里是一行 `npx plugins add`,Codex 则是注册插件市场。技能格式遵循公开标准(Agent Skills),README 说 OpenCode 直接复制文件夹进去就行。

## DESIGN.md 在中间
读下来，几乎所有技能都围着一个文件 DESIGN.md 转。它用文字写下颜色、字体、间距、圆角这些设计规则。按 design-md 技能的说法,Stitch 是通过"可见的描述"加上具体的颜色值来理解设计的。所以每做一个新界面，都把这个文件的内容放进提示词，让它和前面的界面风格一致。

方向有两条。从设计到代码，是拿 Stitch 界面的 HTML 拆成组件。从代码到设计,code-to-design 从正在运行的网页应用里抽出一张 HTML,从源码里抽出 DESIGN.md,再把两者传到 Stitch。等于让已经做好的界面能回到设计工具里再改。

## 连续搭网站的循环
stitch-loop 是接力棒的方式。`.stitch/next-prompt.md` 里写着下一个要做的页面，代理读它、做出页面、接进网站、更新网站地图(SITE.md),然后把下一页的任务写回这个文件就结束。状态留在文件里而不是对话记忆里，所以换了会话，下一个代理也能接着做。如果有 Chrome DevTools MCP,还有一个可选步骤：打开做好的页面截图，和 Stitch 原图对比。

## 规则写成文字，一部分用代码拦
react-components 技能的语气相当硬。每个阶段都有 GATE,写着"没满足这个条件之前不准往下走"。组件要拆成文件，逻辑放进 hooks,文案和图片地址放进 mockData,颜色用主题类而不是 hex 值。

其中一部分由 validate.js 真的检查。它把代码读成语法树(AST,把代码按结构拆开的形式),看有没有名字以 Props 结尾的接口,className 里有没有写死 `#1a2b3c` 这样的 hex 颜色。11 月 20 日的提交也是在修这个检查：即使 className 用表达式拼出来也能抓到 hex,React Native 组件里混进网页专用标签就拒绝。并不是所有规则都用代码拦。在我读到的 validate.js 范围里，只有 Props 接口和 hex 颜色两项，其余(拆文件、分离 hooks 等)还停留在文档里拜托的程度。

## 从入门者的角度
对 PM 或刚入门的开发者来说，值得看的是 DESIGN.md 这部分。把设计规则写成人能读的文字，人类设计师和代理就有了同一个标准。代理每个界面乱选颜色的问题，用一个文件来解决，而不是多加一行提示词。之前看过的 Meta 的 Astryx 也是让代理先读设计系统文档。[详细 → Astryx](#/post/news-261117-a)

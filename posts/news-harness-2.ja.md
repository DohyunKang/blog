Microsoft Agent Framework は、10 月を通じて Python と .NET のリリースを交互に発表しており、変更点から現在のエージェントフレームワークが注力している領域が見て取れます。承認処理、コンテキスト圧縮、MCP 互換性などがその代表例です。

## このフレームワークとは何か

GitHub リポジトリの説明は「AI エージェントとマルチエージェントワークフローを作成し、調整し、デプロイするためのフレームワーク」です。Python と .NET をサポートしており、ライセンスは MIT です。Go バージョンは別リポジトリ（agent-framework-go）にあり、公式概要文書には公開プレビューとして Go 1.26 以上が必要と記載されています。

文書概要では、このフレームワークを 4 つのパートに分けています。

| パート | 役割 |
| --- | --- |
| Agents | LLM で入力を処理し、ツールや MCP サーバーを呼び出し、回答を生成します |
| Harness Agent | 長期的な多段階タスク向けに計画・タスク追跡、コンテキスト圧縮、ファイルアクセスとメモリ、ツール承認、観測を統合したエージェントです |
| Workflows | エージェントと関数を明示的な実行パスで結ぶファンクション型およびグラフ型のフローです |
| Integrations | モデルプロバイダー、ツール、コンテキストプロバイダー、ミドルウェア、評価、UI への接続を提供します |

モデルプロバイダーとしては、Microsoft Foundry、Anthropic、Azure OpenAI、OpenAI、Ollama などが文書に登場しています。Microsoft モデルに限定されたものではありません。

## Semantic Kernel、AutoGen との関係

文書では Agent Framework を 2 つのプロジェクトの「直接的な後継」と説明しています。同じチームが開発しており、AutoGen の単純なエージェント抽象化に対し、Semantic Kernel のセッションベースの状態管理・型安全性・フィルター・テレメトリを組み合わせ、さらに実行パスを明示的に記述するワークフローを追加したという構成です。それぞれのプロジェクトからの移行ガイドも文書に別項目として用意されています。

エージェントとワークフローの使用タイミングも表で整理されており、オープンな対話や自律的なツール使用にはエージェント、ステップが定義済みで実行順序を直接制御するにはワークフローを使用します。その下にある一行には「関数で実装できることは AI エージェントではなく関数を使う」とあります。

## 興味深い変更点

3 つの点が目につきました。

第一はツール承認です。.NET 側では応答がない承認リクエストを自動的に拒否し、同じ ID の承認リクエストを受け付けません。Python 側ではローカル MCP ツールにデフォルト承認モードが追加されました。エージェントがツールを自由に使用できる状態よりも、人間が確認するポイントをより密にする方向へ進んでいるようです。

第二は MCP です。python-1.23.0 で MCP 2.x 互換性を導入するとともに、転送方式、エラー処理、ライフサイクル管理を移行しました。リリースノートではこれを breaking 項目として記載しており、MCP サーバーと連携するコードはアップロード前にノートを必ず読む必要があります。

[詳細 → MCP](#/post/ai-mcp)

第三はコンテキスト圧縮です。python-1.24.0 でエージェント自身が圧縮を引き起こしスキルを低下させる機能が実験として導入されました。概要文書の Harness Agent 説明にもコンテキスト圧縮が記載されており、同じ方向性です。

## 직접 사용해 보자면

개요 문서의 시작 예제는 몇 줄로 구성됩니다. Python 은 `pip install agent-framework`로 설치하고, `Agent` 객체에 클라이언트, 이름, 지시문을 전달하여 생성합니다. 실행은 `await agent.run("...")`입니다. 예제에서는 Foundry 클라이언트를 사용하지만, 다른 제공자 클라이언트로 쉽게 교체할 수 있는 구조입니다.

눈에 띄는 주의 사항이 하나 있습니다. Python 에서 `.env` 파일을 자동으로 읽지 않으므로, 사용할 경우 시작 시점에 직접 `load_dotenv()`를 호출해야 합니다. 환경 변수는 셸에서 직접 지정해도 됩니다.

릴리스 주기는 일주일 내외이며, breaking 변경 사항이 거의 매 릴리스마다 표시됩니다. 버전을 고정하지 않고 사용하면 각 릴리스마다 노트를 읽어야 할 것입니다. 저장소 별 수는 확인 시점 (11 월 2 일) 에 14.5k 였습니다.

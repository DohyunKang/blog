ソート、探索、および計算量は、暗記用の表一つと手書きでの練習を数回行うだけで点が取れる単元です。各ソートアルゴリズムの時間計算量と安定性をセットで覚え、二分探索とハッシュの動作は実際に一度ずつ図に描いておきましょう。試験日程と受験料は公式ウェブサイトにてご確認ください。

## この単元で学ぶ内容

大きく 4 つの塊に分かれます。

| 塊 | 問われる形式 |
|---|---|
| 時間計算量 | コードやアルゴリズムの Big-O の選び方、O 表記の大きさの順序 |
| ソート | アルゴリズムごとの平均・最悪計算量、安定ソートの選び方、1 ステップ後の配列の状態 |
| 探索 | 順次探索・二分探索の比較回数、二分探索の前提条件 |
| ハッシュ | ハッシュ関数の計算、衝突が発生した際の処理方法 |

データ構造については [データ構造の記事](#/post/jb-data-structure) で別途扱っており、Python に関する感覚は [時間計算量と Python の基礎](#/post/algo-complexity) にまとめてあります。

## 時間計算量

入力サイズ n が大きくなるにつれて演算回数がどのように増えるかを記述する方法です。定数倍や低い次数は無視し、通常は最悪の場合を基準として書きます。試験では大きさの順序を暗記しておくと便利です。

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

コードで出題された場合は、ループ構造のみを確認すればよいです。

- 単一ループ: n 回繰り返す。O(n)
- ネストしたループ 2 つ: どちらも n 回。O(n²)
- ループ内で変数を半分ずつ減らす (i = i // 2 など)。O(log n)
- 外側が n 回、内側は毎回半分ずつ減らせば O(n log n)
- ループが連続している場合は大きい方のみを残す。O(n) の後に O(n²) がある場合は O(n²)

Big-O 以外にも Ω (最良)・Θ (平均、正確な境界) の表記も名前程度は知っておきましょう。

## ソート比較表

最も頻出する表です。安定性とは、値が同じ要素の元の順序が保持されるかどうかを指します。

| アルゴリズム | 平均 | 最悪 | 安定 | 一言特徴 |
|---|---|---|---|---|
| バブル | O(n²) | O(n²) | 安定 | 隣同士を比較して交換、1 回で最大の値が末尾へ移動する |
| 選択 | O(n²) | O(n²) | 不安定 | 残っているものの中で最小値を選び、先頭と交換する |
| 挿入 | O(n²) | O(n²) | 安定 | 既にソートされた先頭に挿入する、ほぼソート済みの入力では O(n) に近い |
| シェル | 間隔によって異なる | O(n²) | 不安定 | 間隔を置いて挿入ソートを繰り返して間隔を減らす |
| クイック | O(n log n) | O(n²) | 不安定 | ピボット基準で分割して再帰、既にソート済みの入力で最初の要素をピボットに選んだ場合は最悪になる |
| マージ | O(n log n) | O(n log n) | 安定 | 半分に分けてソートした後で結合する、補助空間が必要 |
| ヒープ | O(n log n) | O(n log n) | 不安定 | ヒープを作成してルート要素を一つずつ取り出す |
| ラジカル (基数) | O(d(n+k)) | 同上 | 安定 | 桁ごとに分配し、比較を行わない |

比較ベースのソートは平均 O(n log n) よりも速くすることはできない点、マージ・ヒープは最悪でも n log n である点、クイックソートが最悪で n² になる点が問題として頻出します。

### 暗記のコツ

- 安定ソートは「バ挿並基」（バブル・挿入・マージ・基数）でグループ化して覚え、残りは不安定と見なす。
- n log n のソートはクイック（平均）・マージ・ヒープであり、そのうち最悪が n² になるのはクイックのみである。

## ソートを手書きで追う

試験では「1 ステップ後の配列」が出題されます。バブルソートで [5, 1, 4, 2, 8] を昇順にソートすると、以下のようになります。

```
시작     5 1 4 2 8
1회전    1 4 2 5 8   (5가 끝으로 이동)
2회전    1 2 4 5 8   (4와 2 교환, 이후 정렬 완료)
```

選択ソートの場合は、1 回目の回転で最小値 1 を先頭の 5 と交換します。同じ入力でもアルゴリズムによって中間状態が異なるため、何回転目かという情報とどのアルゴリズムかという情報を同時に読む必要があります。

<details>
<summary>Python 実装と検証（バブル・選択・挿入・マージ・クイック）</summary>

以下のコードは、ランダムな配列 200 個に対して内蔵 `sorted()` の結果と比較して確認しました。

```python
def bubble(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        changed = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                changed = True
        if not changed:
            break
    return a

def selection(a):
    a = a[:]
    for i in range(len(a) - 1):
        m = min(range(i, len(a)), key=a.__getitem__)
        a[i], a[m] = a[m], a[i]
    return a

def insertion(a):
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

def quick(a):
    if len(a) <= 1:
        return a
    p = a[len(a) // 2]
    return (quick([x for x in a if x < p])
            + [x for x in a if x == p]
            + quick([x for x in a if x > p]))
```

マージソートで `<=` で比較する理由は、値が等しい場合でも左側を先に取り出して安定性を保つためです。バブルソートの `changed` フラグは、既にソート済みの入力では 1 回で終了するようにして最良のケースを O(n) にします。

## 探索

順次探索は最初から順番に見ていきます。ソート済みかどうかに関係なく使用でき、最悪 n 回、平均はおよそ (n+1)/2 回の比較を行います。時間計算量は O(n) です。

二分探索はソート済みのデータで中央と比較して半分ずつ切り捨てます。ソート済みであるという前提が試験で最も頻出し、時間計算量は O(log n) です。要素が 1,000 個の場合、比較は最大 10 回以内で終了します (2¹⁰ = 1,024)。

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

binary_search([1, 3, 5, 7, 9, 11], 7)   # 3
```

この関数は、ランダムに並べ替えられた配列に含まれる値と含まれない値の両方をテストし、結果が正しいか確認しました。二分探索を行う順序は「中間値が検索対象より大きければ左側、小さければ右側」であり、試験では区間 [lo, hi] がどのように狭まっていくかを一行ずつ書き出せば解けます。Python で実際に使用する方法は [ソートと二分探索](#/post/algo-sort-search) にあります。

## ハッシュ

キーをハッシュ関数に投入して保存位置を即座に計算する方式であり、平均的に O(1) で検索できます。ただし、異なるキーが同じ位置に衝突すると速度が低下し、最悪の場合には O(n) になります。Python 公式ドキュメントの時間計算量表でも、dict の検索・挿入・削除と set の `in` が平均 O(1)、ハッシュがすべて衝突する最悪の場合は O(n) と記載されています。一方、リストの `x in l` は順次探索のため O(n) です。

ハッシュ関数の種類は、名称と意味をまとめておきます。

| 方式 | 内容 |
|---|---|
| 除算 (割り算) | キーをテーブルサイズで割った剰余 |
| 平方の中央 | キーを二乗して中央の数桁を使用 |
| フォルディング | キーをいくつかのブロックに分けて足したり XOR したり |
| 数字解析 | キーの桁のうち、均等に分布しているもののみを使用 |
| 基数変換 | 他の進法に変換した値を利用 |

衝突解決は二つの方法があります。

- オープンアドレス法: 空いている別のセルを探して格納します。線形探査、二次探査、ダブルハッシュがあります。
- チェーニング (連結リスト): 同じセルに連結リストでつなげます。

除算法の例として、テーブルサイズが 5 の場合、12, 17, 22, 7 を入れるとすべて剰余が 2 になります。チェーニングの場合、2 番目のセルに 12 → 17 → 22 → 7 と連なっています。この状況がハッシュが O(n) に低下する最悪のケースです。

## よく間違える部分

- 二分探索は O(log n) ですが、まずソートが必要です。ソートされていないデータには使用できません。
- クイックソートの「平均 n log n」だけ覚えていて、最悪 n²を見逃すことが多いです。
- 安定性は時間計算量とは無関係です。平均が同じでも (クイック・マージ) 安定性は異なります。
- ハッシュは「常に O(1)」ではなく、平均が O(1) です。
- ネストした反復文であっても、内側の範囲が半分ずつ減れば n²ではありません。

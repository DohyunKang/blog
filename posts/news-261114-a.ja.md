## どんなものか
コーディングエージェントが Web 画面のコードを書くとき、古いやり方ではなく今のブラウザ機能を使うよう手助けするスキルのセットだ。スキルは、エージェントが必要なときに取り出して読む作業マニュアルのようなファイル。[詳しく → スキル](#/post/ai-skills)

README が指摘する問題はこうだ。モデルが学習したコードの大半が古いので、今はブラウザに標準である機能を置いて重い JavaScript をわざわざ書く。モーダルをライブラリで作ったり、ツールチップの位置をスクリプトで計算したり。そこで Chrome、Edge、Firefox、MDN のチームがまとめたガイドを、エージェントのコンテキストに直接入れる。1.0 時点でガイド 203 本、扱う Web 機能は 250。

## どう動くか
仕組みは単純だ。エージェントが HTML・CSS・ブラウザまわりの作業を受けるとスキルが働き、SKILL.md には次の順で動くよう書いてある。

1. search:「light dismiss dialog」のような2〜5語でガイドを探す。フレームワーク名やアプリ固有の名詞は外せとある。
2. retrieve:見つけたガイドの id で本文を取ってきてコンテキストに入れる。
3. 検証:書いたコードがガイドのパターンと代替コード(fallback)に沿っているか照らし合わせる。
4. 開示:回答の最後に、どのガイドで何を変えたかを短く書く。

検索は自分のマシンの中だけで動く。小さな埋め込みモデルと BM25 を組み合わせ、ネットワークも API キーもいらないそうだ。埋め込みは文を数値ベクトルにして意味の近いものを探す方法で、BM25 は単語の重なりで点数をつける昔ながらの検索方式。[詳しく → 埋め込み](#/post/ai-embedding) ただ、`npx` で最新パッケージを取ってくる段階ではネットワークが必要だ。

ガイドをひとつ開いてみたら、かなり具体的だった。ナビゲーションドロワー(navigation-drawer)のガイドは、`<dialog>` と CSS スクロールスナップでスワイプをブラウザに任せろと言い、「スクリーンリーダー用の名前は必ず付けること」のような必須項目をコメントで書き込んでいる。

ブラウザ対応にもルールがある。Baseline(主要ブラウザが十分に対応している機能のリスト)で「広く利用可能」な機能はそのまま使い、それ以外はガイドの代替コードに必ず従わせる。出て3か月未満の機能、1つのブラウザしか対応していない機能、実験中の機能は検索には出るが、`.mwgrc` で許可しないと本文を取れない。

## なぜ話題か
11月10日(韓国時間)にプレビューの札が外れて 1.0.0 が出た。既存コードから古いパターンを見つけて置き換え用のガイドを紐づける `legacy-scan` が入り、検索エンジンを TensorFlow.js から切り替えて npm パッケージが 23.5MB から 8.8MB に減った。同じ頃、運営が Chrome 単独から Edge、Firefox、MDN のチームにまで広がった。今日トレンドに上がったのは、ガイドを作って評価するソースレポのほうだ。

評価のやり方が一緒に公開されているのも目についた。実際の Web アプリに「画像をもっと速く表示して」のような依頼を API 名なしで出し、ガイドありとなしでエージェントの合格率を Playwright のチェックで比べる。採点器はまず、正解コードで100%合格、手を加えていないアプリで100%不合格になるよう合わせておく。README の11月8日の結果では、Claude Code(opus-5-5)が 57% から 88%、Codex CLI(gpt-6.1-sol)が 54% から 82%、Antigravity CLI(gemini-4-argon)が 58% から 94% だった。プロジェクト自身が測った数字で、自分では再現していない。[詳しく → 評価(evals)](#/post/ai-evals)

Reddit や YouTube でどれくらい広まったかは確認できなかった。

## 入門者の目線で
PM の目線だと、「モデルが知らないことを学習で教えず、文書で渡す」というやり方がしっくりくる。モデルは変えずに、必要なときに短いガイドだけ渡すので、モデルがすでに得意な内容は評価結果を見てガイドから削るらしい。開発の入門者なら、インストール前に `npx modern-web-guidance@latest search "animate a dialog modal backdrop"` のように検索だけしてみるか、小さいプロジェクトで `legacy-scan .` を回してみるくらいから始めればよさそうだ。

気をつける点。匿名の利用統計を集めている。インストール数、呼び出したエージェント名、ガイド id、エージェントが作った検索語が入り、ユーザーのプロンプト原文は集めないと書いてある。`DISABLE_TELEMETRY=1` で切れる。`legacy-scan` が調べるのはガイド全体の約20%だけ。フロントエンドのアクセシビリティが気になるならこれも。[詳しく → アクセシビリティ](#/post/fe-accessibility)

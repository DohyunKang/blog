LLM으로 앱을 만들다 보면 모델 호출 자체보다 그 주변에서 손이 많이 간다. 구조를 어떻게 짤지, 외부 문서를 어떻게 붙일지, 돈은 얼마나 나가는지, 잘 되는지 어떻게 재는지, 어디서 막아야 하는지, 도구는 어떻게 연결하는지. 이 시리즈는 그 여섯 군데를 하나씩 직접 따라가 본 글이고, 이 글은 그 목차다. 개념 용어가 낯설면 [AI 개념 map](#/post/ai-map)를 먼저 보면 된다.

## 한눈에 보는 흐름

```
구조를 정한다   → 에이전트 설계 패턴
지식을 붙인다   → RAG 직접 만들기
도구를 붙인다   → MCP 서버 만들어 보기
돈을 계산한다   → AI 서비스 원가 구조
품질을 잰다     → LLM 앱 평가
바깥에서 막는다 → 가드레일과 안전장치
```

## 1. 만들기 전에 정할 것

**에이전트 설계 패턴**: 에이전트부터 만들기 전에, 정해진 순서로 짠 워크플로우로 되는지 먼저 보라는 얘기를 패턴별로 정리했다. LLM 호출 한 번으로 되는지, 안 되면 어디까지 정해 두고 어디부터 모델에게 맡기는지가 출발점이다.
[자세히 → 에이전트 설계 패턴](#/post/app-agent-design)

**AI 서비스 원가 구조**: 사용자가 쓸 때마다 토큰 요금이 나가는 구조라서, 호출 한 번의 값을 먼저 계산하고 횟수와 사용자 수를 곱해 한 달 원가를 본다.
[자세히 → AI 서비스 원가 구조](#/post/app-cost)

## 2. 기능을 붙이기

**RAG 직접 만들기**: 라이브러리 없이 파이썬 수십 줄로 RAG를 만들어 돌려 보고, 문서 자르기·벡터 만들기·검색·평가까지 손이 가는 다섯 군데를 따라간다. 개념은 [RAG](#/post/ai-rag) 글에 있다.
[자세히 → RAG 직접 만들기](#/post/app-rag-build)

**MCP 서버 만들어 보기**: 함수 몇 개에 이름과 설명을 붙여 바깥에 내놓는 일이라, 파이썬 파일 하나로 도구 두 개짜리 서버를 직접 돌려 봤다. 규격은 [MCP](#/post/ai-mcp) 글에 있다.
[자세히 → MCP 서버 만들어 보기](#/post/app-mcp-server)

## 3. 잘 되는지 보고 지키기

**LLM 앱 평가**: 프롬프트를 고칠 때마다 느낌으로 확인하면 어딘가가 조용히 깨지니까, 미리 정해 둔 문제 묶음과 채점 기준으로 점수를 매겨 같은 잣대로 비교한다.
[자세히 → LLM 앱 평가](#/post/app-eval)

**가드레일과 안전장치**: 모델한테 조심하라고 부탁하는 건 안전장치가 아니라서, 잘못된 입력이나 행동을 앱 쪽 코드에서 막는 지점을 따로 둔다. 모델의 말투를 고치는 게 아니라 바깥에 문을 다는 일이다.
[자세히 → 가드레일과 안전장치](#/post/app-guardrails)

## 읽는 순서

처음이면 설계 패턴 → 원가 → RAG → MCP 서버 → 평가 → 가드레일 순으로 읽으면 된다. 이미 만들고 있다면 막힌 곳 하나만 골라 읽어도 된다.

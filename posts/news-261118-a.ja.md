今朝、GitHub のトレンド(daily)に google-research/paper-orchestra が載っていた。1日でスター1,175、レポ全体で2,956(11月18日午前に確認)。研究アイデアと実験記録を入れると、学会の書式に合わせた LaTeX の論文草稿を出してくれるマルチエージェントのパイプラインだ。README、arXiv の要旨、プロジェクトページ、`methods/` の下のコードをいくつか読んだ。自分では動かしていない。

## 何をするものか
Google Cloud AI Research のチームが4月に出した論文(arXiv 2604.05018)のコードだ。入力は2つ。アイデア要約(手法と理論をまとめた文章)と実験ログ(表の数字と図から読んだ観察を書いたもの)。そこに CVPR や ICLR のような学会の LaTeX テンプレートと執筆ガイドを渡すと、参考文献、グラフ、概念図まで入った原稿 PDF が出てくる。

マルチエージェントは、仕事を複数の LLM 呼び出しに分け、それぞれ別の役割説明を持たせて担当部分だけやらせるやり方だ。[詳しく → サブエージェント](#/post/ai-subagent) ここでは5つ出てくる。

## どう回るか
`paper_writer_with_plotting.py` を追うと順番はこうだ。

1. アウトラインエージェントが入力を読み、`outline.json` を作る。章立て、図の計画、関連研究をどの方向で探すかが入る。
2. 文献調査エージェントと図エージェントが同時に動く(スレッド2本)。
3. 章執筆エージェントがアウトライン、引用リスト、図リストを受け取り、論文全体の LaTeX を書く。
4. 推敲エージェントが AI レビュアーの点数を見ながら原稿を最大3回直す。

面白いのは2と4だ。

文献調査では、モデルがウェブ検索(Gemini の Google 検索ツール)で候補論文を探し、そのタイトルを Semantic Scholar API にもう一度聞く。検索結果の上位3件とタイトルをファジーマッチ(文字列がどれだけ似ているかを0〜100で採点するもの)して、70点を超えたものだけ引用リストに入れる。決めた日付より後の論文は除く。モデルがそれらしい架空の論文をでっち上げるのを、コード側の確認で防ぐ仕組みだ。[詳しく → ハルシネーション](#/post/ai-hallucination)

推敲には単純なルールが組み込まれている。直した原稿をコンパイルしてレビュアーエージェントに再採点させ、総合点が上がれば採用して次の周へ。下がれば前の版に戻して止まる。同点なら、細かい項目で下がった合計が上がった合計より大きいときに止まる。図エージェントも似ていて、図を作ったあと批評エージェントが「直すところなし」と言うまで最大3回描き直す。コード上の既定モデルは Gemini 3.1 Pro preview、画像は Gemini 3 Pro Image preview で、OpenAI のキーでも動く。[詳しく → エージェントループ](#/post/ai-agent-loop)

X で「AI レビュアーの点が上がるまで直すのが賢いところであり、落とし穴でもある」と書いた人がいて、私も同じことを思った。レビュアーもモデルなので、点が上がったのが本当に良くなったからなのか、そのレビュアーの好みに合わせただけなのか、このループの中では区別できない。

## どれくらい書けるか
論文では、CVPR 2025 と ICLR 2025 の論文各100本からアイデア要約と実験ログを逆に抽出したベンチマーク(PaperWritingBench)を作って評価した。AI 研究者11人がブラインドで並べて比べたところ、一度に全部書かせる単一エージェントと AI Scientist-v2 に対して、文献調査の質で勝率差50〜68ポイント、原稿全体の質で14〜38ポイント上回ったという。プロジェクトページには、人が書いた元の論文とはまだ差があると書かれている。ベンチマークのデータセットはまだレポになく、後で別に公開するとのこと。

## 入門者の立場で
論文を書く予定がなくても、構造は借りる価値がある。長い文書を一度に書かせず、アウトライン、資料調査、本文、レビューに分けたこと。モデルがでっち上げやすい部分(引用)を外部 API で確かめること。直すループに「点が下がったら戻して止める」のようなルールをコードで入れたこと。PM としては、企画書やリサーチレポートの自動化を見るときにこの順番をチェックリストにしてもいいと思う。

開発の入門者なら、`methods/agents/` の下の5つのファイルが短くて読みやすい。アウトラインエージェントは60行だ。動かすには Python 3.11 の conda 環境、Gemini か OpenAI のキー、Semantic Scholar のキーが要り、`paper_writing_cli.py` に素材フォルダとテンプレートフォルダを渡せばいい。README の最後の行は「Google の公式サポート製品ではない」で、プロジェクトページの倫理の項には、事実確認と責任は人間の研究者にあると書かれている。エージェントの成果物を人がレビューする画面の話は、数日前の記事と一緒に読むといい。[詳しく → Plannotator](#/post/news-261116-a)

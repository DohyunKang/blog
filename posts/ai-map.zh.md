学习 AI 时，术语会扑面而来。诸如“提示词（Prompt）”、“上下文（Context）”、"RAG"、"MCP"、“Harness”等词汇相互交织，单独看一个往往难以理解。因此，我先列出核心大词，若想了解更多，请点击下方链接跳转。顺序遵循从基础到进阶：模型 → 输入 → 记忆 → 外部连接。

## 一览关系图

```
생성형 AI ⊃ LLM
LLM  ←  프롬프트(입력)  ←  컨텍스트(그 순간 모델이 보는 전체)
컨텍스트 = 컨텍스트 윈도우 안에 담기는 것 (토큰으로 센다)
컨텍스트에 외부 지식을 넣는 방법 = RAG (임베딩으로 찾는다)
컨텍스트에 도구를 연결하는 규격 = MCP
이 전부를 돌리고 관리하는 모델 바깥의 코드 = 하네스
모델이 틀린 말을 그럴듯하게 하는 현상 = 할루시네이션
```

## 1. 模型是什么

**生成式 AI**：与仅进行分类或预测的 AI 不同，它能创作出全新的文字、图像和声音。
[详情 → 什么是生成式 AI](#/post/ai-generative)

**LLM（大型语言模型）**：经过大规模训练，能够准确预测文本片段（Token）之后内容的模型。聊天机器人只是构建在其之上的界面。
[详情 → LLM 是什么](#/post/ai-llm)

## 2. 向模型提供什么

**提示词（Prompt）**：提供给模型的全部输入。基本做法是表述清晰、附带示例并确定格式。
[详情 → 提示词与提示工程](#/post/ai-prompt)

**上下文（Context）**：模型生成答案时一次性读取的全文内容。提示词也是其中一部分，而设计放置什么内容属于上下文工程。
[详情 → 上下文与上下文工程](#/post/ai-context)

**上下文窗口·Token**：上下文所能容纳的最大容量，以及用于计量的单位。随着对话变长，每次调用需重新发送全部内容，导致成本和时间随之增加。
[详情 → 上下文窗口与 Token](#/post/ai-context-window)

## 3. 如何告知模型未知信息

**嵌入（Embedding）**：将文本转换为数字坐标的方法，使语义相近的内容能够相互靠近。
[详情 → 嵌入与向量搜索](#/post/ai-embedding)

**RAG**：让模型像“查阅书籍”一样进行测试的方式。先检索所需文档并将其放入上下文中。
[详情 → RAG](#/post/ai-rag)

**幻觉（Hallucination）**：由于被设计为即使不知道也要生成答案的结构而产生的看似合理但错误的回答。
[详情 → 幻觉](#/post/ai-hallucination)

## 4. 如何与外部世界连接

**MCP**：AI 应用与外部工具之间的连接规范。只需制作一次工具，即可在多个应用中插拔使用。
[详情 → MCP](#/post/ai-mcp)

**Harness**：位于模型之外，负责处理循环、工具、权限和记录的代码。不同资料所指向的范围略有差异。
[详情 → Harness 与 Harness 工程](#/post/ai-harness)

## 6. 对话如何延续及记忆机制

**会话与对话记录**：聊天机器人记住我的话并非依靠模型本身，而是应用程序在每次调用时重新发送至今为止的全部记录。
[详情 → 会话与对话记录](#/post/ai-session)

**压缩·记忆**：压缩是将过往对话转换为摘要并替换的过程；记忆则是将可回退的摘要存储在窗口之外。
[详情 → 压缩与记忆](#/post/ai-compaction)

**提示词缓存（Prompt Caching）**：一种功能，对每次请求中完全相同的前缀部分进行一次处理并复用。必须从头开始完全一致才能生效。
[详情 → 提示词缓存](#/post/ai-prompt-caching)

## 7. 工具与代理

**工具调用**：模型并非直接运行函数，而是发出“请以此参数执行此操作”的请求书，实际执行由我的代码完成。
[详情 → 工具调用 (Function calling)](#/post/ai-tool-use)

**代理·代理循环**：一种结构，模型使用工具、查看结果并重新判断，直至任务结束。其骨架是 `while` 循环。
[详情 → 代理与代理循环](#/post/ai-agent-loop)

**子代理·多代理**：将部分任务委托至新上下文执行，仅接收摘要的方式。当工作可并行化且仅需汇总结果时，这种方式才有益处。
[详情 → 子代理与多代理](#/post/ai-subagent)

**技能**：将特定任务的流程、资料、脚本打包存放在一个文件夹中，仅在需要时取出读取。始终保留的只有名称和说明。
[详情 → 技能 (Skills)](#/post/ai-skills)

**模型·工具间技能对比**：Claude、Codex、Gemini CLI、Cursor 均采用“指令文件 → 技能 → 部署包”的结构，仅名称不同但架构相似。
[详情 → 模型与工具间的技能及扩展对比](#/post/ai-vendor-skills)

## 8. 模型输出与输入形式

**采样（温度·top-p）**：调节模型从概率表中抽取下一个词的方法。近期 Claude 方面已不再使用此参数，文中也一并整理了现状。
[详情 → 采样：温度·top-p](#/post/ai-sampling)

**推理模型·思考令牌**：在给出答案前先独自撰写思考过程的模型。即使不显示在界面上，也会产生输出令牌费用并占用等待时间。
[详情 → 推理模型与思考令牌](#/post/ai-reasoning)

**结构化输出**：一种让模型按照预设格式（Schema）生成回答的功能。请求与建议强制执行的可靠程度有所不同。
[详情 → 结构化输出 (JSON·Schema)](#/post/ai-structured-output)

**多模态**：指不仅处理文本，还同时处理图像、语音等。图像会被转换为令牌，与文本一同出现在同一窗口中。
[详情 → 多模态](#/post/ai-multimodal)

## 9. 原理：模型是如何构建的

**机器学习·深度学习基础**：通过展示数据并让模型自行匹配符合规则的数值（权重）来实现。深度学习使用深层堆叠的神经网络。
[详情 → 机器学习·深度学习基础](#/post/ml-basics)

**神经网络·反向传播**：一种层层堆叠了乘、加、弯曲等计算的函数，以及反向计算如何调整权重的方法。
[详情 → 神经网络与反向传播](#/post/ml-neural-net)

**Transformer·注意力机制**：一种通过分数计算句子中单词之间相互参考程度的结构。如今的 LLM 几乎都以它为基础架构。
[详情 → Transformer 与注意力机制](#/post/ml-transformer)

**从预训练到 RLHF**：包含三个阶段：利用互联网文本预测下一个词（预训练）、展示回答方法（SFT）、引导模型向人类偏好靠拢（偏好学习）。
[详情 → 从预训练到 RLHF](#/post/ml-pretraining)

**微调**：对已完成的模型使用自身数据进行再次训练。根据是修改整体还是仅叠加部分（LoRA/QLoRA），所需的 GPU 资源会有显著差异。
[详情 → 微调：全量 vs LoRA/QLoRA](#/post/ml-finetuning)

**本地模型**：在个人 PC 上直接运行的方式。能否运行主要取决于 VRAM 的计算结果。
[详情 → 运行本地模型](#/post/ml-local-models)

**推理优化**：KV 缓存、批处理、流式传输、投机解码等相互关联的技术集合，旨在更快速且低成本地生成答案。
[详情 → 推理优化](#/post/ml-inference)

**图像生成（扩散）**：从纯噪声开始，逐步去除以生成图像的模型。
[详情 → 图像生成模型 (扩散)](#/post/ml-diffusion)

## 12. 开源分析

**Ollama**：推理计算由独立进程处理，而 Ollama 是一个用 Go 编写的服务器，负责模型文件管理和 GPU 调度。
[详情 → 开源分析：Ollama](#/post/repo-ollama)

**llama.cpp**：一个由 GGUF 文件格式、ggml 计算库以及构建在其上的推理引擎循环组成的系统；量化操作直接作用于文件内部的张量格式。
[详情 → 开源分析：llama.cpp](#/post/repo-llama-cpp)

**vLLM**：一种将 KV 缓存细粒度切分，并由调度器为每个步骤的令牌分配资源的服务器。
[详情 → 开源分析：vLLM](#/post/repo-vllm)

**simonw/llm**：采用集中式模型调用架构，其余功能通过插件和 while 循环进行扩展的结构。
[详情 → 开源分析：simonw/llm](#/post/repo-simonw-llm)

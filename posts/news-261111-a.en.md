I picked vercel-labs/agent-desktop from this week's GitHub trending (weekly). The list showed 12,120 stars this week, and the repo had 21,362 stars in total (checked the morning of Nov 11). On X, a search counted 1,048 posts mentioning "agent-desktop" over the last 7 days (retweets excluded). I only read the README, CONCEPTS.md, and the release notes. I didn't install or run it.

## What it is
A CLI that lets an AI agent see and operate desktop apps. This is usually called computer use: a model handling apps through the screen, mouse, and keyboard like a person would. [More → Tool use](#/post/ai-tool-use)

The odd part is that it doesn't use screenshots. Instead of showing the model a picture and asking it to guess which pixel the login button sits on, it reads the OS accessibility tree. That's the structured data an OS exposes for screen readers and other assistive tools, roughly "a window, a button inside it, text inside that." macOS uses the AX API, Windows uses UI Automation, Linux uses AT-SPI.

There's no model inside agent-desktop. In the README's words, the loop lives in your agent. This thing is just the eyes and hands.

## How it runs
Three lines.

```bash
agent-desktop snapshot --app Finder -i   # tree with a ref on every clickable element
agent-desktop click @s8f3k2p9:e8         # click that ref
agent-desktop snapshot --app Finder -i   # read again to check the result
```

A snapshot returns the tree as JSON and tags each actionable element with a ref like `@s8f3k2p9:e8`. The first part is the snapshot ID, the second is the element. So a ref only works for its own snapshot. A bare `@e8` is rejected, and an old ref after the UI changed returns `STALE_REF`. Then the agent just takes a new snapshot.

What I liked is how it fails. Clicking by pixel coordinates hits the wrong spot when a window moves a little, and nobody notices. Here it fails out loud: this ref doesn't match anymore. The error JSON has `error.disposition.retry`, and the docs say to retry only when it's `safe`.

CONCEPTS.md goes further into this carefulness. Every property the OS reports is known, absent, or unknown, and a failed read never gets flattened into "absent." Window handles can be recycled by the OS, so a handle is paired with the process start time to confirm it's still the same window. In Chrome and Electron apps, layers of nameless wrapper elements are skipped in the depth count so the tree doesn't blow up.

It's headless by default. Ref actions go through the accessibility API without moving the pointer or stealing focus. For real mouse and keyboard input there's `--headed`.

## Why people are talking about it
Besides the trending numbers, I saw two reasons.

One is `agent-desktop mcp`, added in v1.2.0 on Nov 5 (KST). Each command shows up as an MCP tool, like `desktop_snapshot` and `desktop_click`. MCP is the spec that lets AI apps plug in outside tools the same way. [More → MCP](#/post/ai-mcp) Now it hooks into a harness like Claude Code with one config line.

The other is that it pairs with Vercel's agent-browser. The docs even live under agent-browser.dev. It takes the "read the tree, click a ref, read again" approach from the browser and stretches it to all desktop apps. Links in the release notes suggest it started as lahfir/agent-desktop and moved to vercel-labs, but I couldn't confirm when or why.

## For beginners
For a PM or someone new to development, I think the point is cost and reliability. The screenshot approach sends an image to the model at every step, which eats tokens, and guessing coordinates can just be wrong. The tree approach is text JSON, lighter, and leaves a record of what was clicked.

The catch is that if an app doesn't expose good accessibility info, there's less to work with. The README notes that each platform differs in what works headless, what needs `--headed`, and what refuses. How useful it is for games or canvas-drawn apps, I couldn't confirm.

The warning near the top of the README is worth remembering too. Snapshots, clipboard reads, and screenshots can contain private desktop content, so keep them out of public logs and uploads. It also suggests passing secrets through `--stdin` so they don't show up in process arguments.

- Apache-2.0, mostly Rust. Ships as a CLI and a C library (`libagent_desktop_ffi`).
- 60 command names, 56 operational. `key-down`, `key-up`, `mouse-down`, `mouse-up` refuse to run until a daemon can release a held key or button.
- Support: macOS 13+, Windows 10 1809+, Ubuntu 24.04+ (X11 and Wayland).
- Releases: v1.0.0 (Oct 28), v1.1.0 (Nov 3), v1.2.0 (Nov 5, MCP added). Dates in KST.
- Install with `npm install -g agent-desktop` or Homebrew.

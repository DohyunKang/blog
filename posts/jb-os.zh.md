## 进程与线程

程序是磁盘上的文件，而进程是已加载到内存并正在运行的实体。线程是进程内部的执行流。同一进程内的线程共享代码、数据和堆，仅各自拥有独立的栈和寄存器。

进程状态共有五种，需重点记忆：

| 状态 | 含义 | 后续状态转换 |
|---|---|---|
| 新建 (New) | 正在创建中 | 批准 → 就绪 |
| 就绪 (Ready) | 只要获得 CPU 即可执行 | 调度 → 运行 |
| 运行 (Running) | 正在使用 CPU | 时间片用完 → 就绪，I/O 请求 → 等待，终止 → 终止 |
| 等待/阻塞 (Waiting/Blocked) | 等待 I/O 等事件完成 | 事件完成 → 就绪 |
| 终止 (Terminated) | 已结束 | — |

容易混淆的两对概念是：从就绪到运行需经调度（dispatch），而从运行回到就绪是因为时间片耗尽（time out）。从等待直接转到运行是不可能的，必须经过就绪状态。

上下文切换（context switch）是指在切换执行进程时，将当前进程的状态（如寄存器、程序计数器等）保存到 PCB，并从下一个进程的 PCB 中读取其状态的过程。在此期间无法处理任务，因此属于纯粹的开销。PCB（进程控制块）包含进程 ID、状态、程序计数器、寄存器、内存信息及打开的文件信息等。

## CPU 调度

评估标准涉及三种时间：

- 等待时间：在就绪队列中等待的时间
- 周转时间（turnaround）：从到达至完成所经历的总时间 = 等待时间 + 执行时间
- 响应时间：从到达至首次获得 CPU 的时间

调度算法可分为抢占式与非抢占式两大类。

| 分类 | 算法 | 一句话总结 |
|---|---|---|
| 非抢占 | FCFS | 按到达顺序执行；若长作业排在短作业之前，平均等待时间会变差（护航效应） |
| 非抢占 | SJF | 优先执行短作业；平均等待时间较优，但可能导致长作业持续被推迟 |
| 非抢占 | HRN | 按 (等待时间 + 执行时间) / 执行时间从大到小排序；缓解 SJF 的饥饿问题 |
| 非抢占 | 优先级 | 高优先级优先执行；低优先级可能产生饥饿，可通过老化机制（等待越久优先级越高）解决 |
| 抢占 | SRT | 选择剩余执行时间最短的进程；即 SJF 的抢占版本 |
| 抢占 | 轮转法 | 按固定时间片轮流执行；时间片越大越接近 FCFS，过小则上下文切换频繁 |
| 抢占 | 多级队列/反馈队列 | 设置多个队列，根据优先级或使用情况在不同队列间迁移 |

同一问题用三种方式求解时，差异会非常明显。假设给定以下到达时间和执行时间：

| 进程 | 到达时间 | 执行时间 |
|---|---|---|
| P1 | 0 | 6 |
| P2 | 1 | 3 |
| P3 | 2 | 1 |

以下是通过直接模拟得出的结果：

| 方法 | 执行顺序 | 平均等待时间 | 平均周转时间 |
|---|---|---|---|
| FCFS | P1(0~6) → P2(6~9) → P3(9~10) | 4.0 | 7.33 |
| SJF | P1(0~6) → P3(6~7) → P2(7~10) | 3.33 | 6.67 |
| SRT | P1(0~1) → P2(1~2) → P3(2~3) → P2(3~5) → P1(5~10) | 1.67 | 5.0 |

解题步骤始终一致：绘制时间轴，记录每个时刻就绪队列中的进程，按规则选择一个执行，并在完成时刻用到达时间与执行时间之差计算等待时间和周转时间。在 SJF 中，关键点是 P1 于第 6 时刻结束时，P2 和 P3 均已到达，因此较短的 P3 优先执行。对于抢占式 SRT，当 P2 在第 1 时刻到达时，P1 剩余时间为 5，而 P2 仅需 3，故 CPU 交由 P2 执行。

轮转法的答案可能因新到达进程是插入队列前端还是后端而不同。题目通常会给出具体规则，应据此模拟队列变化进行求解。

HRN 的优先级数值越大越优先。例如：等待 5、执行 5 时，(5+5)/5 = 2；等待 10、执行 20 时，(10+20)/20 = 1.5，因此前者优先。请记住：执行时间越短、等待时间越长，优先级越高。

<details>
<summary>用 Python 运行相同的计算（SRT 部分）</summary>

```python
P = [("P1", 0, 6), ("P2", 1, 3), ("P3", 2, 1)]
rem = {n: b for n, a, b in P}
arr = {n: a for n, a, b in P}
t, fin = 0, {}
while rem:
    ready = [n for n in rem if arr[n] <= t]
    if not ready:
        t += 1
        continue
    n = min(ready, key=lambda x: rem[x])   # 남은 시간이 가장 짧은 것
    rem[n] -= 1
    t += 1
    if rem[n] == 0:
        fin[n] = t
        del rem[n]
for n, a, b in P:
    print(n, "반환", fin[n] - a, "대기", fin[n] - a - b)
```

结果显示：P1 返回 10·等待 4，P2 返回 4·等待 1，P3 返回 1·等待 0。
</details>

## 内存管理

### 连续分配与碎片化

在将程序整体作为一个块放入内存的方式中，问题在于空闲空间放在哪里。有三种分配策略，其名称即含义：

- **首次适应（First Fit）**：从前往后寻找第一个合适的空闲空间
- **最佳适应（Best Fit）**：在所有能容纳该请求的空闲空间中，选择最小的一个
- **最差适应（Worst Fit）**：选择最大的空闲空间

当空闲空间分别为 120、450、230、310、580，且请求按 200、400、100、450 的顺序到来时，我进行了手动计算。

| 策略 | 200 | 400 | 100 | 450 |
|---|---|---|---|---|
| 首次适应 | 450 | 580 | 120 | 无法分配 |
| 最佳适应 | 230 | 450 | 120 | 580 |
| 最差适应 | 580 | 450 | 380 | 无法分配 |

表格中的数字表示该请求被放入的空闲空间大小（以请求时刻为准）。在本例中，只有最佳适应策略成功分配了所有四个请求。并非总是如此，结果取决于输入顺序。

碎片化分为两种：内部碎片是指已分配块内未被使用的空间（通常由固定大小的单位划分导致）；外部碎片是指虽然总空闲空间足够，但由于分散而无法使用的空间（在可变大小分配时发生）。外部碎片可以通过紧凑（压缩）来减少。

### 分页与分段

分页是将地址空间划分为相同大小的页面，将物理内存划分为相同大小的帧，并将任意页面放入任意帧的方式。页表是从页号到帧号的映射表。每个进程都有一个这样的表。

虚拟地址被拆分为页号（VPN）和偏移量。偏移量表示页内的位置，因此转换后不会改变，只有页号变为帧号。OSTEP 的例子是将 64 字节的地址空间划分为 4 个 16 字节的页面，其中 6 位地址中，高 2 位为 VPN，低 4 位为偏移量。考试中会出现类似的计算形式。

- 如果是 32 位地址，页面大小为 4KB（= 2¹²），则偏移量为 12 位，VPN 为 20 位
- 因此页表项数量为 2²⁰个（约 100 万个）
- 页面越大，页表越小，但内部碎片会增大

分段是将程序按语义单位（如代码、数据、栈）划分为大小不同的段。由于大小不一致，会产生外部碎片；但另一方面，便于按语义单位进行保护和共享。分页对应内部碎片，分段对应外部碎片，建议这样配对记忆。

### 虚拟内存与页面置换

虚拟内存是一种技术，允许运行比实际内存大的程序，只需将所需的页面加载到内存中。如果所需页面不在内存中，则发生缺页（page fault），并从磁盘加载。当内存已满时，必须换出一个页面，决定换出哪个页面的规则称为置换算法。

| 算法 | 换出标准 |
|---|---|
| OPT | 未来最长时间不使用的页面（因需预知未来，仅作为比较基准） |
| FIFO | 最早进入的页面 |
| LRU | 最久未使用的页面 |
| LFU | 使用次数最少的页面 |
| NUR | 根据引用位和修改位区分最近未使用的页面 |

这是将参考串 `1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5` 在 3 个帧和 4 个帧下运行的结果。该参考串是 OSTEP 用于解释 Belady 悖论时使用的例子。

| 帧数 | FIFO 缺页 | LRU 缺页 | OPT 缺页 |
|---|---|---|---|
| 3 | 9 | 10 | 7 |
| 4 | 10 | 8 | 6 |

FIFO 在帧数从 3 增加到 4 时，缺页数反而从 9 增加到 10。这就是 Belady 悖论（Belady's anomaly）。LRU 由于具有“N+1 个帧的内容包含 N 个帧内容”的性质（栈性质），因此不会出现这种情况。考试中会问"FIFO 中增加帧数却导致缺页增加的现象”的名称。

解题步骤是逐个读取参考串，并在旁边记录帧的状态。若已存在则命中，否则计为缺页并按规则换出一个页面。LRU 在命中时也会更新该页面的最近使用时间，这一点容易遗漏。

<details>
<summary>用 Python 运行页面置换</summary>

```python
from collections import deque

def fifo(ref, n):
    m, f = deque(), 0
    for r in ref:
        if r not in m:
            f += 1
            if len(m) == n:
                m.popleft()
            m.append(r)
    return f

def lru(ref, n):
    m, f = [], 0
    for r in ref:
        if r in m:
            m.remove(r)          # 적중해도 최근 순서 갱신
        else:
            f += 1
            if len(m) == n:
                m.pop(0)
        m.append(r)
    return f

def opt(ref, n):
    m, f = [], 0
    for i, r in enumerate(ref):
        if r in m:
            continue
        f += 1
        if len(m) == n:
            later = ref[i + 1:]
            dist = [later.index(x) if x in later else 10**9 for x in m]
            m.pop(dist.index(max(dist)))   # 가장 늦게 다시 쓰는 것
        m.append(r)
    return f

ref = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
for n in (3, 4):
    print(n, fifo(ref, n), lru(ref, n), opt(ref, n))
```

输出为 `3 9 10 7`、`4 10 8 6`。
</details>

虚拟内存中还有一个概念需要区分。抖动（Thrashing）是指进程过多导致缺页异常频繁发生，CPU 忙于进行页面置换而无法执行实际工作的状态。局部性（Locality）是指程序倾向于再次访问最近使用过的区域的特性；工作集（Working Set）则是指在一段时间内被频繁引用的页面集合。只要将相当于工作集的页面保留在内存中，就能减少抖动。

## 死锁

死锁（Deadlock）是指进程们互相等待对方持有的资源而永远停滞的状态。只有以下四个条件同时成立时才会发生。OSTEP 也列举了同样的四点。

| 条件 | 含义 | 打破该条件的预防方法 |
|---|---|---|
| 互斥 | 资源一次只能被一个进程使用 | 采用无锁数据结构等方法使其可共享 |
| 占有且等待 | 持有资源的同时等待其他资源 | 一次性获取所需的所有资源 |
| 不可抢占 | 已占有的资源不能被强制剥夺 | 若无法获得则释放已占有的资源并重新尝试 |
| 循环等待 | 存在相互缠绕的环形链条 | 对资源进行编号，仅按顺序请求 |

考试中常将这四个名称与“打破哪个条件的方法”进行配对提问。对资源进行编号并按顺序请求的做法，就是打破了循环等待条件。

解决方法分为四类：

- **预防（Prevention）**：预先阻止上述四个条件中的某一个。虽然安全，但会降低资源利用率。
- **避免（Avoidance）**：每次收到资源请求时计算是否安全并决定是否允许。典型代表是戴克斯特拉的银行家算法。需要预先知道最大需求量。
- **检测（Detection）**：先放置不管，定期检查是否存在死锁（如使用资源分配图）。
- **恢复（Recovery）**：检测到死锁后，终止进程或剥夺资源以解除死锁。

安全状态是指至少存在一种顺序，使得所有进程都能顺利执行完毕；而不安全状态并不意味着一定会立即发生死锁。银行家算法的逻辑是：在当前剩余资源中选择一个能满足其最大需求的进程并让其运行结束，然后将其释放的资源合并到可用资源中，再选择下一个进程。若能一直延续到最后，则为安全状态。

## 同步

临界区（Critical Section）是指访问共享资源的代码段，同一时刻只能有一个进程进入。保证这一点的工具是信号量和互斥锁。

- **信号量**：使用一个整型变量以及 P(wait, 减) 和 V(signal, 加) 操作实现。值为 1 时称为二值信号量，大于 1 时称为计数信号量。
- **互斥锁**：是一种仅持有锁的一方才能解锁的互斥工具。
- **监视器（Monitor）**：将共享资源及其访问函数封装在一起，确保同一时刻只有一个进程执行的高层结构。

竞态条件（Race Condition）是指多个进程同时修改共享数据，导致执行顺序不同而产生不同结果的情况。与死锁不同，它不会导致程序停止，但会导致数据值错误。并发问题在数据库中也会出现类似问题。[详情 → 规范化与事务](#/post/jb-normalization-transaction)

## 常见题型总结

| 类型 | 提问形式 | 解题思路 |
|---|---|---|
| 调度平均时间 | 给出到达/执行时间表，求平均等待/周转时间 | 绘制时间线 + 就绪队列 |
| 算法名称配对 | “剩余时间短优先”、“等待越长优先级高”等描述 | 用关键词关联如 SRT、HRN 等 |
| 缺页次数 | 给出引用串和帧数 | 标注帧状态，仅统计缺页 |
| Belady 异常 | FIFO 算法中增加帧数反而可能导致缺页增加 | 直接根据名称作答 |
| 死锁四条件 | 条件名称、打破哪个条件的预防法 | 参照上表进行配对 |
| 碎片化 | 区分固定分区还是可变分区 | 内部 ↔ 固定，外部 ↔ 可变 |

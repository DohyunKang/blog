在 SQLD 建模课程中，关系与标识符是几乎每节课都会出现的章节，如果将术语整理为“以什么为标准划分”，即使选项变化也能解题。

## 本章节涉及的内容

确定了实体和属性后，接下来就是探讨实体之间如何关联，以及每个实体的行由什么来区分。前一章内容在 [实体与属性](#/post/sqld-entity-attr)，建模的整体流程在 [理解数据建模](#/post/sqld-modeling) 中。

| 分类 | 标准 | 出现的术语 |
|---|---|---|
| 关系 | 几个相互连接 | 1:1, 1:N, M:N (关系基数) |
| 关系 | 是否必须存在 | 强制，可选 (选择性) |
| 关系 | 父 PK 是否进入子 PK | 标识关系，非标识关系 |
| 标识符 | 扮演什么角色 | 主标识符，辅助标识符 |
| 标识符 | 来源何处 | 内部标识符，外部标识符 |
| 标识符 | 是否为单个列 | 单一，复合 |
| 标识符 | 是否原本存在 | 本质标识符，人造标识符 |

考试经常询问表中每一行“是基于什么标准分类的”。只要记住标准，陌生的句子也能解答。

## 关系的基础

关系意味着两个实体之间存在业务上的连接。像员工和部门那样，用“属于”这样的动词来读就是关系。由于阅读方向有两个，从部门角度看是“部门拥有多个员工”，从员工角度看是“员工属于一个部门”，尝试从两边构造句子。仅凭一方句子容易误判基数。

### 关系基数（几个相互连接）

- 1:1：一侧的一个行对应另一侧最多一个行
- 1:N：一侧的一个行对应另一侧多个行，反之则最多一个
- M:N：两侧都是多个

ER 图中使用的乌鸦脚表示法中，线末端的圆圈代表 0，竖线代表 1，分叉代表多。每个末端有两个符号，内侧是最小值，外侧是最大值 ([Wikipedia: Entity–relationship model](https://en.wikipedia.org/wiki/Entity%E2%80%93relationship_model))。

M:N 无法直接创建物理表，因此中间放置一个交叉（连接）实体将其分解为两个 1:N 关系。如果学生和课程是 M:N，则创建“选课”实体并获取学生 PK 和课程 PK。考试中若出现"M:N 关系如何化解”，答案就是这个交叉实体。

### 选择性（是否必须存在）

基数对应最大数量，而选择性对应最小数量。最小值为 0 表示可选 (optional)，为 1 表示强制 (mandatory)。

- 员工必须属于一个部门：员工侧强制
- 部门即使没有员工也可以创建：部门侧可选

这种选择性后来会延续到 FK 列是否允许 NULL。如果是强制，FK 为 NOT NULL；如果是可选，则允许 NULL。下面还会再次提到。

## 阅读关系的顺序

当问题给出关系句子时，按以下顺序阅读：

1. 从两个方向构造句子。
2. 记录每个方向的最大值（一个/多个）→ 基数
3. 记录每个方向的最小值（可以没有/必须有）→ 选择性
4. 子实体能否在没有父实体的情况下存在 → 进入标识/非标识判断

<details>
<summary>例：订单与订单项</summary>

- 订单 → 订单项：一个订单拥有多个商品行（最大 N）。假设没有商品行的订单不存在，则最小为 1。
- 订单项 → 订单：商品行必须属于一个订单（最大 1，最小 1）。

因此是 1:N，且子侧是强制的。由于不能只有订单项行而没有订单，它成为后续标识关系的候选。如果业务规则改变，最小数量也会随之变化，请牢记这一点。例如“订单可以在没有商品的情况下先创建”，则订单侧的最小值为 0。
</details>

## 标识符

标识符是实体内唯一指向一个行的属性（或属性组）。在建模中常称为标识符，在物理表中常称为键，考试中也按同一流程处理这两者。

### 主标识符的条件

要成为主标识符，通常需满足以下四个条件：

| 特性 | 含义 |
|---|---|
| 唯一性 | 每行的值必须不同 |
| 最小性 | 仅包含必要的最少属性 |
| 不变性 | 一旦确定不得更改 |
| 存在性 | 不能为 NULL，必须有值 |

特别是“不变性”常是陷阱。电话号码或邮箱看似唯一，但可能改变，因此不适合作为主标识符候选。关于最小性，记住“既然已经唯一，就不应再添加属性”。

### 按分类标准分别查看

- 代表性（主键标识符 vs 辅助标识符）：在与其它实体建立关系时，若用作代表则称为主键标识符；虽然能区分行，但若不作为代表使用，则称为辅助标识符。
- 自生性（内部标识符 vs 外部标识符）：若在自身实体内创建则为内部标识符，若从其他实体获取则为外部标识符。
- 属性数量（单一 vs 复合）：仅有一个属性即为单一，两个或以上则为复合。
- 可替代性（本质 vs 人造）：若为业务原本使用的则称为本质；若为方便起见新创建的则称为人造。

<details>
<summary>关于本质标识符与人造标识符的进一步说明</summary>

人造标识符类似于序列号，是由系统生成的值。其优点在于该值不承载业务含义且保持不变，因此外键（FK）可以仅由一个列构成。然而，由于该值缺乏业务意义，即使出现重复的业务数据也可能无法阻止，因此通常需要为原始业务键单独添加唯一性约束。这些优缺点在 surrogate key 的说明中也得到了相同的总结 ([Wikipedia: Surrogate key](https://en.wikipedia.org/wiki/Surrogate_key))。

复合标识符越长，随着向下延伸到子表，主键（PK）的长度也会持续增加。因此，在实际工作中有时会使用人造标识符，考试中则将其表述为“用单一人造标识符替代复合标识符”。
</details>

## 标识关系与非标识关系

这是本单元的核心内容。判断标准只有一个：父实体的 PK 是否进入子实体的 PK。

| 分类 | 父实体 PK 在子实体中 | 子实体的存在性 | ERD 连线 |
|---|---|---|---|
| 标识关系 | 成为子实体 PK 的一部分 | 必须依赖父实体才能存在 | 实线 |
| 非标识关系 | 成为子实体的普通属性（FK） | 即使没有父实体也能存在 | 虚线 |

在标识关系中，父实体的 PK 会进入子实体的 PK 作为其一部分，子实体的每一行必须连接到唯一的父实体。订单与订单项是典型的示例。订单项将订单号和行号组合起来作为主键，且在没有订单的情况下无法存在 ([Wikipedia: Weak entity](https://en.wikipedia.org/wiki/Weak_entity))。

```sql
-- 식별 관계: 부모 PK(order_no)가 자식 PK에 포함
CREATE TABLE orders (
  order_no INTEGER PRIMARY KEY,
  memo     TEXT
);
CREATE TABLE order_item (
  order_no INTEGER NOT NULL REFERENCES orders(order_no),
  line_no  INTEGER NOT NULL,
  item     TEXT,
  PRIMARY KEY (order_no, line_no)
);

-- 비식별 관계: 부모 PK(dept_id)는 일반 컬럼으로 FK, NULL 허용 = 선택
CREATE TABLE dept (dept_id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE emp (
  emp_id  INTEGER PRIMARY KEY,
  dept_id INTEGER REFERENCES dept(dept_id),
  name    TEXT
);
```

上述 DDL 已在 SQLite 中直接运行验证。尝试向 `order_item` 插入不存在的订单号（9）时，因违反外键约束而被阻止；而 `dept_id` 为 NULL 的员工记录则成功插入。标识关系意味着子实体无法在没有父实体的情况下存在，而可选的非标识关系则允许子实体在没有父实体的情况下存在，这与理论完全一致。（注意：SQLite 需开启 `PRAGMA foreign_keys=ON` 才能检查外键。）

### 非标识关系分为两类

在非标识关系中，可根据外键（FK）是否允许 NULL 进一步细分。

- 强制性非标识关系：FK 不允许为 NULL，子实体必须拥有父实体。
- 可选性非标识关系：FK 允许为 NULL，即使没有父实体，子实体也可以存在。

前面提到的“可选性”在这里转化为 FK 是否为 NULL 的问题。考试中若出现“可以在没有父实体的情况下创建子实体”的表述，即可将其归类为可选性非标识关系。

### 如何判断归属

- 若无父实体则子实体无意义（如订单与订单项）：属于标识关系
- 若子实体可独立使用且仅引用父实体（如员工与部门）：属于非标识关系
- 若子实体需获取多个父实体的 PK，会导致主键过长，此时可选择将其分解为非标识关系并使用人造标识符

<details>
<summary>使用标识关系时产生的问题</summary>

当标识关系以多级形式延续时，最底层实体的 PK 将继承自顶层父实体的 PK。在进行 JOIN 操作时需要匹配更多列，且索引也会变大。相反，仅通过查看主键即可知道数据属于哪个父实体之下，并且非常适合在删除父实体时同步清理子实体的业务场景。这是优缺点分化的关键点，因此在考试中，题目往往不会直接询问单一正确答案，而是要求考生根据“标识关系的特征”来区分选项。
</details>

## 常见题型

| 类型 | 解题方向 |
|---|---|
| 判断关系基数 | 用双向语句写出最大数量 |
| M:N 关系的解决方法 | 设置交叉（连接）实体，将其拆分为两个 1:N 关系 |
| 选择标识符条件 | 与唯一性、最小性、不变性、存在性这四个标准进行比较 |
| 标识符分类区分 | 首先确认“依据什么标准进行分类”（代表性、生成位置、属性数量、可替代性） |
| 标识/非标识判断 | 若父实体 PK 包含在子实体中则为标识关系，若是普通属性则为非标识关系 |
| ERD 标注 | 实线/虚线、乌鸦脚符号、圆圈（0）/竖条（1）的解读 |

在选择题中，错误句子的识别题型通常会替换术语。例如，“在非标识关系中，父主键成为子主键的一部分”这类说法就颠倒了定义。如果逐条背诵定义，就能有效排除干扰项。直接练习时，与其死记硬背历年真题原文，不如尝试用文字解释上述表格中的标准，这样效果更好。考试时间和报名费用请查阅官方网站确认。

## 容易混淆的概念

- 基数（Degree）和选择性（Selectivity）是不同的：基数指最大值，选择性指最小值。
- 标识符与外键（FK）不同。外键是指向其他实体的属性；若该属性成为主键的一部分，则构成标识关系，否则为非标识关系。
- 使用代理标识符后就不需要业务键了吗？并非如此。业务上必须唯一的值仍需通过唯一性约束单独维护。
- 复合标识符虽然包含多个属性，但“最小”条件依然适用：即使去掉某些属性后仍保持唯一性，那些属性就是不必要的。

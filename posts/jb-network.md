정보처리기사 네트워크 단원은 외울 것의 중심이 계층 구분이고, 문제로는 "이 기능은 몇 계층 일인가"와 "이 IP 대역에서 호스트가 몇 개인가"가 반복해서 나온다. 이 두 가지를 먼저 잡았다. 시험 일정과 응시료는 공식 사이트에서 확인하면 된다.

## 먼저 큰 그림

네트워크는 한 덩어리로 보면 막막하고 층으로 나눠서 보면 정리된다. 위쪽 층은 "무슨 내용을 주고받나"를 다루고, 아래쪽 층은 "어떻게 실어 나르나"를 다룬다. 각 층은 바로 아래 층이 해 주는 일만 믿고 자기 일을 한다.

- 응용 계층의 HTTP는 요청과 응답을 주고받는 규칙이다.
- 전송 계층의 TCP는 그 요청이 빠짐없이 순서대로 가게 책임진다.
- 네트워크 계층의 IP는 어느 컴퓨터로 가는지 주소를 붙이고 길을 고른다.

브라우저에 주소를 쳤을 때 이 층들이 실제로 어떤 순서로 일하는지는 [자세히 → 네트워크 기초(CS)](#/post/cs-network)와 [자세히 → 요청 한 번의 여정](#/post/infra-request-journey)에 따로 정리해 뒀다. 여기서는 시험에 나오는 쪽으로 좁혀서 본다.

## OSI 7계층

OSI 7계층은 통신을 일곱 단계로 나눈 참조 모델이다. 위에서 아래로 응용, 표현, 세션, 전송, 네트워크, 데이터 링크, 물리 순서다. 시험 문제는 대부분 "다음 설명이 가리키는 계층은?" 형태라서, 계층마다 키워드를 하나씩 붙여 두면 빠르다.

| 계층 | 맡은 일 | 키워드 |
|---|---|---|
| 7 응용 | 사용자가 쓰는 서비스의 규칙 | HTTP 같은 프로토콜 |
| 6 표현 | 데이터 표현 방식 변환 | 변환, 압축, 암호화 |
| 5 세션 | 통신 연결의 시작과 끝 관리 | 세션, 동기화 |
| 4 전송 | 끝과 끝 사이 전달 | TCP, UDP, 포트 |
| 3 네트워크 | 주소 지정과 경로 선택 | IP, 라우팅 |
| 2 데이터 링크 | 바로 옆 장비까지 전달 | 프레임, 오류 검출 |
| 1 물리 | 신호를 전기·빛으로 보냄 | 케이블, 전송 매체 |

외우는 요령은 두 가지였다. 첫째, 번호는 아래가 1이다. 물리가 1계층이고 응용이 7계층이다. 둘째, 문제에서 "경로", "주소"가 나오면 3계층, "포트", "신뢰성"이 나오면 4계층으로 먼저 거른다.

<details>
<summary>OSI와 TCP/IP를 나란히 놓으면</summary>

실제 인터넷은 OSI보다 층이 적은 TCP/IP 모델로 설명하는 경우가 많다. 보통 응용, 전송, 인터넷, 네트워크 접근의 네 층으로 묶는다. OSI의 5·6·7을 응용 하나로, 1·2를 네트워크 접근 하나로 합친 모양이다.

| OSI | TCP/IP |
|---|---|
| 응용·표현·세션 | 응용 |
| 전송 | 전송 |
| 네트워크 | 인터넷 |
| 데이터 링크·물리 | 네트워크 접근 |

시험에서는 두 모델을 나란히 주고 "어느 층에 해당하나"를 묻는 식으로 나온다. 위 표처럼 합쳐지는 방향만 기억하면 된다.
</details>

## 전송 계층: TCP

TCP는 애플리케이션에 순서가 보장된 신뢰할 수 있는 바이트 흐름을 준다. RFC 9293 기준으로 신뢰성은 세 가지 장치로 만든다. 순번(sequence number)으로 빠진 데이터를 알아채고, 세그먼트마다 붙는 체크섬으로 오류를 찾고, 재전송으로 둘 다 바로잡는다.

또 하나 중요한 게 포트 번호다. 포트는 어떤 응용 서비스로 보낼 데이터인지 구분하고, 같은 두 컴퓨터 사이에 여러 흐름이 동시에 있어도 섞이지 않게 해 준다. IP 주소가 컴퓨터를 찾는 번호라면 포트는 그 컴퓨터 안의 서비스를 찾는 번호다.

### 3-way handshake

TCP는 데이터를 보내기 전에 연결부터 맺는다. 시험에 거의 매번 나오는 부분이다.

1. 먼저 연결을 열려는 쪽이 SYN을 보낸다. 자기 초기 순번이 들어 있다.
2. 받는 쪽이 SYN-ACK로 답한다.
3. 처음 쪽이 ACK를 보내면 연결이 완성된다.

그래서 이름이 세 번 주고받는 악수다. 순서를 SYN, SYN-ACK, ACK로 통째로 외워 두면 된다.

닫을 때는 방향마다 FIN을 보내고 상대가 그걸 확인(ACK)해 준다. 먼저 닫은 쪽은 TIME-WAIT 상태로 2×MSL 동안 기다린다. RST를 받으면 연결 상태를 바로 버린다. 시험에서는 "연결 종료 때 FIN을 쓴다", "RST는 강제로 끊는다" 정도의 구분으로 나온다.

[자세히 → 운영체제](#/post/jb-os)에서 다루는 프로세스와 포트가 어떻게 이어지는지도 같이 보면 이해가 쉽다.

<details>
<summary>TCP와 UDP를 문제로 구분하는 법</summary>

문제에서 "연결을 먼저 맺고 순서와 재전송을 보장"이라고 하면 TCP다. 반대로 "연결 설정 없이 그냥 보낸다, 빠르지만 보장은 없다"는 문장이면 UDP로 답한다. 두 프로토콜 모두 전송 계층이라는 점은 같다. 보장하느냐 마느냐가 갈리는 지점이다.
</details>

## 응용 계층: HTTP

HTTP는 응용 계층 프로토콜이다. MDN 설명으로는 보통 TCP 위에서, 또는 TLS로 암호화한 TCP 위에서 동작한다. 클라이언트-서버 구조에서 요청은 늘 클라이언트가 먼저 시작한다. 서버가 먼저 말을 거는 일은 없다.

요청에는 메서드, 경로, 버전, 헤더(선택), 본문(선택)이 들어가고, 응답에는 버전, 상태 코드, 상태 메시지, 헤더, 본문(선택)이 들어간다. HTTP는 무상태(stateless)라서 같은 연결 위의 연속된 요청 사이에 아무 연결 고리가 없다. 로그인 상태 같은 걸 유지하려면 쿠키가 그 위에 얹힌다. "HTTP는 stateless이고 쿠키로 상태를 보완한다"는 문장은 보기 문항으로 자주 나올 만한 내용이다.

API 쪽에서 이걸 어떻게 쓰는지는 [자세히 → 통합 구현과 인터페이스](#/post/jb-integration-api)로 이어진다.

## IP 주소와 서브넷

네트워크 계층의 핵심은 IP 주소다. IPv4는 32비트, IPv6는 128비트다. 파이썬 `ipaddress` 문서에서도 IPv4의 `max_prefixlen`이 32, IPv6가 128로 나온다.

서브넷 문제는 계산이 정해져 있다. `192.168.10.77/26`이면 앞 26비트가 네트워크 부분이고 뒤 6비트가 호스트 부분이다.

- 서브넷 마스크: 앞 26비트가 1이므로 255.255.255.192
- 주소 개수: 호스트 비트 6개이므로 2의 6제곱, 64개
- 쓸 수 있는 호스트: 64에서 네트워크 주소와 브로드캐스트 주소를 빼서 62개
- 네트워크 주소: 64 단위로 끊으니 77이 속한 구간의 시작인 192.168.10.64
- 브로드캐스트 주소: 구간의 끝인 192.168.10.127

이 계산이 맞는지 파이썬으로 돌려서 확인했다.

```python
import ipaddress

def info(cidr):
    n = ipaddress.ip_network(cidr, strict=False)
    hosts = list(n.hosts())
    print(cidr, "mask", n.netmask, "network", n.network_address,
          "broadcast", n.broadcast_address, "hosts", len(hosts))

info("192.168.10.77/26")
info("10.0.0.0/24")
```

```
192.168.10.77/26 mask 255.255.255.192 network 192.168.10.64 broadcast 192.168.10.127 hosts 62
10.0.0.0/24 mask 255.255.255.0 network 10.0.0.0 broadcast 10.0.0.255 hosts 254
```

`hosts()`는 문서대로 IPv4에서 네트워크·브로드캐스트 주소를 뺀 목록을 돌려준다. 시험에서 "사용 가능한 호스트 수"를 물으면 항상 2의 n제곱에서 2를 빼는 값이다.

### 서브넷 나누기

한 대역을 더 잘게 쪼개는 문제도 나온다. `192.168.10.0/24`를 `/26`으로 나누면 네 개가 나온다.

```python
import ipaddress
print(list(ipaddress.ip_network("192.168.10.0/24").subnets(new_prefix=26)))
```

```
[IPv4Network('192.168.10.0/26'), IPv4Network('192.168.10.64/26'), IPv4Network('192.168.10.128/26'), IPv4Network('192.168.10.192/26')]
```

프리픽스를 2비트 늘리면 네 조각이 되고, 각 조각의 주소는 64개씩이다. 비트를 하나 늘릴 때마다 조각은 두 배, 조각당 주소는 절반이 된다. 이 관계를 알면 표를 외우지 않아도 된다.

<details>
<summary>서브넷 문제 풀이 순서</summary>

1. 프리픽스 길이에서 호스트 비트 수를 구한다. 32에서 프리픽스를 뺀다.
2. 2의 호스트 비트 제곱이 한 구간의 주소 개수다.
3. 주소 마지막 옥텟이 몇 번째 구간에 드는지 구간 크기로 나눠서 본다.
4. 그 구간의 첫 주소가 네트워크 주소, 마지막 주소가 브로드캐스트 주소다.
5. 사용 가능한 호스트는 구간 개수에서 2를 뺀 값이다.

위 예에서 구간 크기가 64이므로 77은 64 이상 127 이하 구간에 든다. 그래서 네트워크 주소는 .64, 브로드캐스트는 .127이다.
</details>

## 라우팅

라우팅은 목적지 주소를 보고 다음에 어느 쪽으로 보낼지 고르는 일이고, 3계층이 맡는다. 데이터는 여러 장비를 거치며 조금씩 목적지에 가까워지고, 각 장비는 자기 앞의 다음 길만 판단한다. 시험에서는 라우팅 프로토콜 이름을 보고 분류하는 문제가 자주 나오는 편이라, 교재의 프로토콜 목록은 따로 한 번 훑어 두는 게 좋다.

## 흔한 헷갈림

- 3계층과 4계층 구분: 주소·경로는 3계층, 포트·신뢰성은 4계층이다.
- 포트와 IP: IP는 컴퓨터를 고르고 포트는 그 안의 서비스를 고른다.
- 서브넷 호스트 수: 2의 n제곱에서 2를 빼야 한다. 빼는 걸 잊는 실수가 제일 흔하다.
- HTTP가 무상태라는 말: 쿠키를 쓰면 세션을 만들 수 있지만 프로토콜 자체는 무상태다.

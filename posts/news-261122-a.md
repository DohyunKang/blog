## 뭐 하는 물건인지
스킬은 에이전트가 필요할 때 꺼내 읽는 설명서다. [자세히 → 스킬](#/post/ai-skills) 이 레포는 그 스킬을 83개 묶어 놨다. 슬래시 명령은 15개다. 이름을 불러서 쓰는 게 아니라, "이 대상 점검 중이다"처럼 하고 있는 일을 말하면 주제에 맞는 스킬이 알아서 붙는다고 적혀 있다.

README의 분류를 옮기면 이렇다.

1. 웹 취약점 종류별 hunt-* 스킬 58개. HackerOne에 공개된 신고 보고서 681건에서 패턴을 뽑아 만들었다고 한다.
2. M365, Okta, VPN 장비 같은 기업용 플랫폼 쪽 스킬 10개.
3. 찾은 걸 검증하고 보고서로 쓰는 스킬 6개.
4. 정찰과 공개 정보 수집 스킬 5개, 방법론 스킬 4개.

설치는 Claude Code 안에서 `/plugin marketplace add`와 `/plugin install` 두 줄이다. 스킬 파일 형식이 공통이라 OpenCode, Codex CLI 같은 다른 에이전트 도구에도 복사해 넣을 수 있다고 한다. 다만 슬래시 명령과 자동 실행 엔진은 Claude Code 전용이다.

## 안에서 어떻게 도는지
흐름은 scope → recon → rank → hunt → validate → report다. 범위를 정하고, 대상을 훑고, 어디부터 볼지 순위를 매기고, 찾고, 검증하고, 보고서를 쓴다.

눈에 띈 건 역할 분담이다. engine.py 첫 줄 설명에 범위 확인, 상태 저장, 작업 분배, 순위, 중복 제거, 보고서 정리는 정해진 코드로 하고, 모델은 정찰·탐색·검증에만 쓴다고 적혀 있다. 범위 밖 호스트는 정찰 결과에서 코드가 걸러내고, 범위 밖 대상에는 에이전트를 아예 보내지 않는다. 모델한테 "범위 밖은 건드리지 마"라고 부탁하는 게 아니라 코드가 막는 구조다. 상태는 단계마다 저장돼서 중간에 끊겨도 이어서 돌릴 수 있다.

다른 하나는 7-Question Gate다. 보고서를 쓰기 전에 질문 7개를 순서대로 묻고, 하나라도 답이 안 나오면 그 발견은 버린다. 첫 질문이 "공격자가 지금 이걸 단계별로 쓸 수 있나"이고, 범위 안인지, 프로그램이 인정하는 피해 종류인지도 묻는다. 문서에는 이 관문이 잡아낸 오탐 예시가 있다. 응답에 내 입력이 보이는데 알고 보니 응답이 원래 URL을 그대로 돌려주는 페이지였다든가, 상태 코드만 달라지고 본문은 똑같았다든가 하는 경우다. 모델이 그럴듯한 걸 찾았다고 우기는 걸 막는 장치인 셈이다.

## 직접 잰 숫자는 아직 약하다
eval 폴더에 스킬을 켰을 때와 껐을 때를 같은 과제로 비교하는 장치가 있다. 지난번에 본 SkillEvaluator와 같은 생각이다. [자세히 → SkillEvaluator](#/post/news-261119-a) 그런데 BASELINE.md에 적힌 최신 결과(8월 25일)는 연습용 취약 사이트 OWASP Juice Shop 과제 3개뿐이고, 스킬을 켜든 끄든 3개 다 풀었다. 켰을 때가 오히려 턴과 비용이 조금 더 들었다. 작성자도 이 과제는 모델이 이미 외우고 있을 만큼 쉬워서 스킬 효과를 못 잰다고 적어 놨다. 더 어려운 과제(PortSwigger 실습)는 계정 문제로 아직 못 돌렸다고 한다. 그러니까 "스킬을 넣으면 더 잘 찾는다"는 건 이 레포 안에서 아직 숫자로 확인되지 않았다.

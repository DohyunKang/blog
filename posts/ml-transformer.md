트랜스포머는 문장 안의 단어들이 서로를 얼마나 참고할지 점수로 계산하는 구조다. 요즘 [LLM](#/post/ai-llm)이 거의 다 이걸 뼈대로 쓴다.

## 먼저 쉬운 말로

"은행에 가서 돈을 찾았다"와 "강 은행에 앉아 쉬었다"에서 은행은 같은 글자지만 뜻이 다르다. 뜻을 정하는 건 주변 단어다. 사람은 문장을 읽으면서 자연스럽게 주변을 훑는데, 어텐션(attention)이 이걸 계산으로 만든 것이다.

단어 하나를 처리할 때 문장 속 모든 단어를 쳐다보고, 관련이 큰 단어에는 큰 가중치를, 작은 단어에는 작은 가중치를 준 뒤 가중 평균을 낸다. 이 평균이 "문맥이 섞인 그 단어의 새 표현"이 된다. 같은 방식으로 문장 안 모든 단어를 한꺼번에 처리한다.

## 어디서 나온 건가

2017년 논문 "Attention Is All You Need"(Vaswani 등 8명)에서 나왔다. 초록 기준으로 순환(recurrence)이나 합성곱(convolution) 없이 어텐션만으로 만든 모델이고, 기존 구조보다 병렬화가 쉽고 학습이 빠르다고 적는다. 영어-독일어 번역(WMT 2014)에서 28.4 BLEU, 영어-프랑스어에서는 GPU 8장으로 3.5일 학습해 41.8 BLEU를 냈다고 한다.

이전에는 RNN 계열이 단어를 앞에서부터 하나씩 읽었다. 앞 단어를 처리해야 다음 단어를 처리할 수 있어서 병렬로 돌리기 어려웠다. 트랜스포머는 모든 단어를 동시에 계산해서 GPU에 잘 맞는다. [신경망과 역전파](#/post/ml-neural-net)에서 본 학습 방식은 그대로 쓰고, 층의 모양만 바뀐 셈이다.

## 셀프 어텐션: Q, K, V

입력은 단어마다 [임베딩](#/post/ai-embedding) 벡터 하나다. 이 벡터에 학습되는 행렬 세 개(W^Q, W^K, W^V)를 각각 곱해서 세 가지 벡터를 만든다.

| 이름 | 역할 | 비유 |
|---|---|---|
| Q (query) | 이 단어가 찾는 것 | 검색어 |
| K (key) | 이 단어가 내세우는 것 | 문서 제목 |
| V (value) | 이 단어가 실제로 건네는 내용 | 문서 본문 |

계산은 네 단계다.

1. 내 Q와 모든 단어의 K를 내적한다. 값이 클수록 둘이 잘 맞는다는 뜻이다.
2. 점수를 √d_k로 나눈다. Illustrated Transformer 글의 예에서는 K 차원이 64라서 8로 나눈다.
3. softmax를 씌워 합이 1인 가중치로 바꾼다.
4. 그 가중치로 V들을 가중합한다. 이게 이 단어의 출력이다.

식으로 쓰면 softmax(QKᵀ/√d_k)V 한 줄이다. 문장 전체를 행렬 하나로 묶어서 한 번에 계산한다.

[ 입력 X ] → X·Wq = Q, X·Wk = K, X·Wv = V → Q·Kᵀ ÷ √d_k → softmax → ×V → [ 출력 ]

Q와 K는 같은 입력에서 나오기 때문에 "셀프" 어텐션이라고 부른다. 문장이 자기 자신을 보는 것이다.

## 멀티 헤드

어텐션을 한 번만 하면 한 가지 관계만 잡는다. 논문은 이걸 8개 헤드로 나눠 병렬로 돌린다. 헤드마다 자기 Wq, Wk, Wv를 따로 갖고, 결과를 이어 붙인 뒤 W^O 행렬로 원래 크기로 되돌린다. 헤드별로 서로 다른 위치, 다른 표현 공간을 보게 하려는 설계라고 한다. 헤드 하나가 정확히 무슨 역할을 하는지는 모델마다 다르고, 사람이 읽어서 딱 떨어지는 경우만 있는 건 아니다.

## 위치 인코딩

어텐션만 쓰면 단어 순서 정보가 없다. "개가 사람을 물었다"와 "사람이 개를 물었다"가 같은 단어 묶음이 되어 버린다. 그래서 입력 임베딩에 위치마다 다른 벡터를 더해 준다.

논문 방식은 사인·코사인 함수다. 위치와 차원에 따라 주기가 다른 파형을 쓰고, 값은 -1에서 1 사이다. 학습된 값이 아니라 공식으로 정해지는 값이라, 학습 때 본 것보다 긴 문장에도 이론상 늘릴 수 있다고 설명한다. 요즘 모델은 다른 위치 방식(회전 방식 등)을 쓰는 경우가 많은데, 그쪽은 이번에 확인 못 했다.

## 인코더와 디코더

원래 논문은 번역용이라 두 덩어리로 되어 있다.

| | 인코더 | 디코더 |
|---|---|---|
| 층 수(논문) | 6개 | 6개 |
| 층 안 구성 | 셀프 어텐션 → 피드포워드 | 마스크 셀프 어텐션 → 인코더-디코더 어텐션 → 피드포워드 |
| 하는 일 | 입력 문장을 이해한 표현으로 | 그 표현을 보면서 출력을 한 단어씩 생성 |

각 서브층마다 잔차 연결(입력을 출력에 더함)과 층 정규화가 붙는다. 인코더-디코더 어텐션에서는 Q가 디코더에서, K와 V가 인코더 맨 위 출력에서 온다.

디코더의 첫 어텐션에는 마스크가 있다. 단어를 하나씩 생성하는 중에는 아직 안 나온 뒤쪽 단어를 볼 수 없으니, 미래 위치의 점수를 −∞로 만들어서 softmax 뒤 가중치가 0이 되게 한다. 학습할 때는 정답 문장 전체를 한 번에 넣어도 각 위치가 자기 앞만 보게 되니 병렬로 학습할 수 있다.

GPT 계열처럼 글을 이어 쓰는 LLM은 이 중 디코더 쪽만 쓰는 구조(decoder-only)로 알려져 있다. 이 글에서 각 모델의 정확한 구성까지는 확인하지 않았다. 이렇게 만든 모델을 어떻게 키우는지는 [사전학습에서 RLHF까지](#/post/ml-pretraining)에 이어진다.

## 최소 numpy 예시

실행해서 확인한 코드다. 토큰 4개, 차원 8로 셀프 어텐션과 마스크를 직접 계산한다.

```python
import numpy as np
np.random.seed(0)

def softmax(x):
    x = x - x.max(axis=-1, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=-1, keepdims=True)

def attention(x, Wq, Wk, Wv, causal=False):
    Q, K, V = x @ Wq, x @ Wk, x @ Wv
    scores = Q @ K.T / np.sqrt(K.shape[-1])
    if causal:
        mask = np.triu(np.ones_like(scores), k=1) == 1
        scores = np.where(mask, -1e9, scores)
    w = softmax(scores)
    return w @ V, w

def pos_enc(n, d):
    pos = np.arange(n)[:, None]
    i = np.arange(d // 2)[None, :]
    ang = pos / (10000 ** (2 * i / d))
    pe = np.zeros((n, d))
    pe[:, 0::2] = np.sin(ang)
    pe[:, 1::2] = np.cos(ang)
    return pe

n, d = 4, 8
x = np.random.randn(n, d) + pos_enc(n, d)
Wq, Wk, Wv = (np.random.randn(d, d) * 0.5 for _ in range(3))

out, w = attention(x, Wq, Wk, Wv)
print(out.shape)            # (4, 8)
print(np.round(w, 2))
print(w.sum(axis=1))        # 각 행 합 = 1

out_c, w_c = attention(x, Wq, Wk, Wv, causal=True)
print(np.round(w_c, 2))     # 위쪽 삼각형이 0
```

돌려 보면 가중치 행렬의 각 행 합이 1이고, causal=True일 때는 대각선 위쪽이 전부 0이 된다. 첫 단어는 자기 자신만 보니 가중치가 [1, 0, 0, 0]이다. Wq, Wk, Wv가 랜덤이라 가중치 값 자체에는 뜻이 없다. 학습이 이 행렬들을 채우는 일이다.

<details>
<summary>위치 인코딩 공식과 어텐션 비용</summary>

논문 3.5절의 위치 인코딩은 다음과 같은 꼴이다(위 코드와 같다).

- PE(pos, 2i) = sin(pos / 10000^(2i/d))
- PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

차원 번호 i가 커질수록 주기가 길어진다. 짝수 차원에 사인, 홀수 차원에 코사인을 번갈아 넣는다.

어텐션은 모든 단어 쌍의 점수를 만드니까 점수 행렬이 n×n이다. 문장이 길어지면 계산량과 메모리가 길이의 제곱으로 는다. 긴 [컨텍스트 윈도우](#/post/ai-context-window)가 비싼 이유 중 하나다. 이걸 줄이는 방법들은 [추론 최적화](#/post/ml-inference)에서 다룬다. 제곱으로 는다는 점은 구조에서 바로 나오는 얘기지만, 실제 모델이 쓰는 최적화 수준은 확인 못 했다.
</details>

## 흔한 오해

- 어텐션 가중치가 곧 "모델이 이유로 삼은 단어"라는 해석은 조심해야 한다. 가중치는 계산 중간값이고, 헤드와 층이 여러 겹이라 한 장의 가중치 그림으로 설명이 끝나지는 않는다.
- 트랜스포머가 문장을 이해한다는 말은 편한 표현일 뿐, 계산은 행렬곱과 softmax의 반복이다.
- 트랜스포머는 언어 전용이 아니다. 같은 구조가 이미지, 음성 등에 쓰이는 것으로 알려져 있지만 이번에는 확인 못 했다. 이미지 쪽은 [이미지 생성 모델(확산)](#/post/ml-diffusion)에서 이어서 본다.
- 인코더와 디코더가 항상 둘 다 있는 건 아니다. 원래 번역용 구조였을 뿐이다.

## 정리

- 단어마다 Q·K·V를 만들고, QKᵀ/√d_k → softmax → V 가중합으로 문맥을 섞는다.
- 헤드를 여러 개 두고, 순서는 위치 인코딩으로 넣고, 미래는 마스크로 가린다.
- 순서대로 읽지 않아 병렬 학습이 되고, 대신 길이의 제곱만큼 비용이 든다.

## 확인 못 함

- 논문 본문 PDF를 직접 열지 못했다. 초록(arXiv 페이지)과 Illustrated Transformer 글에서 확인한 수치(6층, 8헤드, 64차원, 512차원 임베딩)만 적었다.
- √d_k로 나누는 이유를 논문 본문에서 직접 확인하지 못했다.
- 요즘 모델의 위치 방식, decoder-only 구성, 비전·음성 적용은 확인 못 했다.

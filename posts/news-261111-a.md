이번 주 GitHub 트렌딩(weekly)에서 vercel-labs/agent-desktop을 골랐다. 목록에는 이번 주 별 12,120개로 나와 있었고, 레포 전체 별은 21,362개였다(11월 11일 오전 확인). X에서도 최근 7일 동안 "agent-desktop"이 들어간 글이 1,048개 잡혔다(리트윗 제외, X 검색 집계 기준). README, CONCEPTS.md, 릴리스 노트만 읽었고 직접 설치해 돌려 보지는 않았다.

## 뭐 하는 물건인지
AI 에이전트가 데스크톱 앱을 보고 조작하게 해 주는 CLI다. 이런 걸 보통 computer use라고 부른다. 모델이 사람처럼 화면을 보고 마우스·키보드로 앱을 다루는 기능이다. [자세히 → 도구 사용](#/post/ai-tool-use)

특이한 건 스크린샷을 안 쓴다는 점이다. 화면 사진을 찍어 모델에게 보여 주고 "로그인 버튼이 몇 번째 픽셀에 있다"를 맞히게 하는 대신, 운영체제의 접근성 트리를 읽는다. 접근성 트리는 화면 낭독기 같은 보조 기술을 위해 OS가 앱 화면을 "창 안에 버튼, 그 안에 글자" 식의 구조로 내주는 데이터다. macOS는 AX API, Windows는 UI Automation, 리눅스는 AT-SPI를 쓴다.

agent-desktop 안에는 모델이 없다. README 표현대로 "루프는 내 에이전트에 있다". 이건 그냥 눈과 손 역할만 한다.

## 어떻게 도는지
흐름은 세 줄이다.

```bash
agent-desktop snapshot --app Finder -i   # 누를 수 있는 요소마다 ref가 붙은 트리
agent-desktop click @s8f3k2p9:e8         # 그 ref를 누른다
agent-desktop snapshot --app Finder -i   # 다시 읽어서 결과를 확인
```

snapshot은 트리를 JSON으로 돌려주고, 누를 수 있는 요소마다 `@s8f3k2p9:e8` 같은 ref를 붙인다. 앞부분이 스냅샷 ID, 뒷부분이 요소 번호다. 그래서 ref는 그 스냅샷에서만 유효하다. `@e8`처럼 스냅샷 ID 없이 쓰면 거부하고, 화면이 바뀐 뒤 옛 ref를 쓰면 `STALE_REF`를 돌려준다. 그럼 에이전트가 다시 snapshot을 찍으면 된다.

이 설계가 마음에 들었던 건 실패 방식이다. 픽셀 좌표로 클릭하면 창이 조금만 움직여도 엉뚱한 곳을 누르고, 누른 줄도 모른다. 여기는 "이 ref는 이제 안 맞는다"고 명시적으로 실패한다. 에러 JSON에 `error.disposition.retry`가 있고, `safe`일 때만 다시 시도하라고 적혀 있다.

CONCEPTS.md에는 이런 신중함이 더 자세히 나온다. OS가 알려 준 속성은 "있음 / 없음 / 모름" 세 가지로 구분하고, 읽기에 실패한 걸 "없음"으로 뭉개지 않는다. 창 핸들은 OS가 재활용할 수 있어서, 핸들에 프로세스 시작 시각을 묶어 같은 창인지 다시 확인한다고 한다. 크롬·일렉트론 앱처럼 이름 없는 껍데기 요소가 겹겹이 쌓인 화면은 그 껍데기를 깊이 계산에서 빼서 트리가 너무 깊어지지 않게 한다.

기본은 headless다. ref로 하는 동작은 마우스 포인터를 움직이거나 포커스를 뺏지 않고 접근성 API로 처리한다. 진짜 마우스·키보드 입력이 필요하면 `--headed`를 켠다.

## 왜 화제인지
트렌딩 숫자 말고 내가 본 이유는 두 가지 정도다.

하나는 11월 5일(한국 시간) 나온 v1.2.0에서 `agent-desktop mcp`가 생긴 것이다. 명령 하나하나가 MCP 도구(`desktop_snapshot`, `desktop_click` 같은)로 노출된다. MCP는 AI 앱이 외부 도구를 같은 방식으로 붙이게 해 주는 규격이다. [자세히 → MCP](#/post/ai-mcp) Claude Code 같은 하네스에 설정 한 줄로 붙일 수 있게 됐다.

다른 하나는 Vercel의 agent-browser와 짝이라는 점이다. 문서도 agent-browser.dev 아래에 있다. 브라우저용으로 하던 "트리 읽기 → ref 누르기 → 다시 읽기" 방식을 데스크톱 앱 전체로 넓힌 셈이다. 릴리스 노트의 링크를 보면 원래 lahfir/agent-desktop이었다가 vercel-labs로 옮겨 온 것 같은데, 언제 왜 옮겼는지는 확인 못 함.

## 입문자 입장에서
PM이나 개발 입문자에게 와닿는 건 비용과 신뢰성 쪽일 것 같다. 스크린샷 방식은 매 단계 이미지를 모델에 보내야 해서 토큰이 많이 들고, 좌표를 맞히는 것 자체가 틀릴 수 있다. 트리 방식은 텍스트 JSON이라 가볍고, 무엇을 눌렀는지가 기록에 남는다.

대신 앱이 접근성 정보를 제대로 내주지 않으면 할 수 있는 게 줄어든다. README도 플랫폼마다 headless로 되는 것, `--headed`가 필요한 것, 거부하는 것이 다르다고 따로 적어 뒀다. 게임이나 캔버스로 그리는 앱에서 얼마나 쓸 만한지는 확인 못 함.

README 앞부분의 경고도 기억해 둘 만하다. 스냅샷, 클립보드, 스크린샷에는 내 데스크톱의 개인 정보가 그대로 들어갈 수 있으니 공개 로그나 업로드에 넣지 말라고 한다. 비밀번호 같은 건 `--stdin`으로 넘겨 프로세스 인자에 안 남기라는 안내도 있다.

<details><summary>읽은 범위와 수치 (11월 11일 확인, 직접 재현하지 않음)</summary>

- 라이선스 Apache-2.0, 주 언어 Rust. CLI와 C 라이브러리(`libagent_desktop_ffi`)로 배포.
- 명령 이름 60개 중 실제로 도는 건 56개. `key-down`, `key-up`, `mouse-down`, `mouse-up`은 눌린 키를 놓아 줄 데몬이 생길 때까지 실행을 거부한다고 한다.
- 지원: macOS 13 이상, Windows 10 1809 이상, Ubuntu 24.04 이상(X11·Wayland).
- 릴리스: v1.0.0(10월 28일), v1.1.0(11월 3일), v1.2.0(11월 5일, MCP 추가). 날짜는 한국 시간.
- 설치는 `npm install -g agent-desktop` 또는 Homebrew.
</details>

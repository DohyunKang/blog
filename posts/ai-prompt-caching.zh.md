Prompt Caching 是一项功能，它预先处理请求中重复的前缀部分，并在后续请求中复用。其核心原则是“前缀必须完全一致”。

## 从定义开始

LLM API 会在每次对话交互时，重新发送整个系统提示（System Prompt）、工具定义以及之前的所有对话历史。（[详情 → 上下文](#/post/ai-context)）其中相当大一部分内容在每次请求中都是相同的。Prompt Caching 就是服务器暂时保存这部分相同前缀的处理结果；当下一次请求的前缀再次出现时，直接复用该结果，而无需从头计算。

输出不会因此改变。Anthropic 和 OpenAI 的文档均指出，缓存不会影响输出内容的生成。真正发生变化的是处理输入所需的时间以及输入费用。

## 原理：前缀（prefix）匹配

根据 OpenAI 的文档说明，服务器存储的不是具体的 Token 字符，而是在处理前缀过程中生成的 KV 状态。可以将其理解为模型内部计算过程中的中间值。由于后续值取决于前面的 Token，因此只有当前缀相同时才能复用。（注：此结构解释基于我的理解；文档仅强调“整个前缀必须完全一致”。）

因此规则很简单：

- 缓存仅在从开头开始、没有任何 Token 差异的区间内有效。
- 若中间某处出现一个 Token 不同，则其后所有内容均需重新计算。
- 图像内容也被视为输入的一部分；相同的图像必须出现在相同的位置。

Anthropic 将按 `tools` → `system` → `messages` 顺序拼接的整个 Prompt 视为一个前缀。由于工具定义位于最前端，修改任意一个工具会导致后续全部内容失效。

```text
[도구 정의][시스템 프롬프트][문서/예시][지난 대화......][이번 질문]
|<------------ 매번 같음 (캐시) ------------>|<-- 달라짐 -->|
```

## 成本与延迟优势

根据 Anthropic 文档，相对于基本输入单价，各项操作的倍数如下：

| 项目 | 倍数 |
|---|---|
| 5 分钟缓存写入 | 1.25 倍 |
| 1 小时缓存写入 | 2 倍 |
| 缓存读取（命中） | 0.1 倍为基础（部分模型为 0.05 倍或 0.025 倍） |

写入成本略高，但读取成本极低。我们来算一笔账：假设前缀部分为 20,000 tokens，且以相同前缀发起 10 次请求。若将单价设为 1，则结果如下：

| | 计算方式 | 输入成本（tokens × 倍数） |
|---|---|---|
| 无缓存 | 20,000 × 10 | 200,000 |
| 5 分钟缓存 | 20,000×1.25 + 20,000×0.1×9 | 43,000（约 21.5%） |

从第二次请求起即可获益。即使只写入一次、读取九次，总成本为 1.25 + 0.1 = 1.35 倍，仍低于直接发送两次的 2 倍成本。但需注意，此计算仅考虑前缀部分，未包含当前问题等后段内容及输出费用。

关于延迟，文档指出：“首 Token 生成时间减少，且文档越长效果越显著”。然而两份文档均未提供具体减少了多少秒的数值，故此处不作赘述。OpenAI 的文档也未提供延迟数据。

此外，根据 Anthropic 文档，缓存命中的请求可豁免速率限制（rate limit）；而 OpenAI 则相反，指出被缓存的 Token 仍计入速率限制。各公司政策不同，使用时需查阅对应文档。

成本视角将在 [详情 → 成本设计](#/post/app-cost) 中进一步探讨。

## 导致缓存失效的操作

由于要求前缀一致，以下操作会导致缓存失效：

- 在系统提示的最上方添加当前时间或请求 ID。因每次请求不同，导致后续全部无效。
- 每次请求时增删工具定义或改变其顺序。工具位于最前端。
- 对历史对话进行摘要或截断后重新发送。这会导致前缀发生变化。（[详情 → 上下文压缩](#/post/ai-compaction)）
- 在中间插入或删除图像。根据 Anthropic 的表格，添加或删除图像会使 `tools` 和 `system` 缓存均失效。
- 更改 `tool_choice` 的值。在同一表格中，这将使 `tools` 和 `system` 缓存全部失效。

OpenAI 文档的建议方向一致：将不变的内容置于前端，将变化的内容（如时间、用户特定数据）置于后端。文档还建议，与其删除工具，不如使用 `tool_choice: "none"` 或 `allowed_tools`。

## TTL：缓存的有效期

缓存并非永久有效。Anthropic 默认设置为 5 分钟，且每次写入可免费延长有效期。若指定 `ttl: "1h"`，则有效期为 1 小时，但写入成本翻倍。文档指出：若请求频率约为每 5 分钟一次，则适用 5 分钟缓存；若间隔超过 5 分钟但未达到 1 小时，则适用 1 小时缓存。

OpenAI 的做法则不同。根据文档，GPT-5.6 之后的模型默认最少保留 30 分钟，且可通过 `prompt_cache_options.ttl` 延长至 12 小时（但会增加写入成本）。在此之前的模型则提供了 `in_memory`（约 5~10 分钟不活跃后失效）和 `24h` 两种选项。这部分最让人困惑的是规则因模型代际而异。

## API 使用方法

Anthropic 提供两种方式：一种是在顶层添加单个 `cache_control` 的自动方式（随着对话变长，标记会向前移动），另一种是每个块直接指定标记的显式方式（最多支持 4 处）。简化文档中的 Python 示例如下：

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-opus-5-5",   # 문서 예시의 모델 이름
    max_tokens=1024,
    system=[
        {"type": "text", "text": "You are an AI assistant tasked with analyzing legal documents."},
        {
            "type": "text",
            "text": "Here is the full text of a complex legal agreement: [...]",
            "cache_control": {"type": "ephemeral"},  # 여기까지를 캐시
        },
    ],
    messages=[{"role": "user", "content": "What are the key terms and conditions in this agreement?"}],
)
print(response.usage)
```

此代码是迁移自文档的示例。

是否命中缓存需查看响应中的 `usage` 字段：

- `cache_creation_input_tokens`：本次写入缓存使用的令牌数
- `cache_read_input_tokens`：从缓存读取的令牌数
- `input_tokens`：标记之后未命中缓存的令牌数

总输入量为上述三者之和。若前两项为 0，则表示未命中缓存；通常是因为长度短于最小阈值。此时也不会报错，只是静默地未命中缓存，因此养成检查 usage 的习惯很有必要。

OpenAI 几乎无需额外代码：支持缓存的模型默认已启用，且可通过响应中的 `cached_tokens` 确认是否命中。

<details>
<summary>详细解析：最小长度与查看窗口 (lookback)</summary>

Anthropic 对不同模型设定的可缓存最小长度各不相同。根据文档表格，512 令牌（Opus 5.5, Sonnet 5.5, Haiku 5.5 等）、1,024 令牌（Sonnet 5, Sonnet 4.6 等）、2,048 令牌（Opus 4.7 等）以及 4,096 令牌（Opus 4.6, Haiku 4.5 等）均有区分。由于模型频繁更新，使用时需重新查阅表格。OpenAI 自 GPT-5.6 起默认标准为 1,024 令牌。

Anthropic 仅在标记点（breakpoint）使用缓存。收到请求时，会检查该点的哈希值；若不存在，则向前最多回溯 20 个位置以查找之前请求中使用的项。若对话单次长度超过 20 个位置，文档提示需提前在更靠前的位置添加标记。若在每次请求变化的块（如时间戳）中添加标记，会导致哈希不匹配，从而每次都产生写入费用。

此外还支持预填充（pre-warming）。发送 `max_tokens: 0` 可仅使用缓存而不生成输出。此功能不能与流式输出、扩展思考或结构化输出等同时使用。我尚未尝试过此功能。

“思考”（thinking）块无法直接添加标记，但会作为之前助手回合的一部分被缓存。部分最新模型默认保留思考块以延续缓存，而旧版模型则会在特定用户输入到达时将其剥离，并从该点起失效（见文档）。

## 常见误解

- **使用缓存会缩小上下文窗口**：错误。仅降低费用，窗口大小保持不变。（[详情 → 上下文窗口](#/post/ai-context-window)）
- **相同问题会得到相同的缓存回答**：错误。存储的是输入处理结果，答案每次均重新生成。
- **仅添加标记即可始终生效**：若长度短于最小阈值，则会在无错误的情况下未命中缓存。
- **缓存是永久的**：错误。保留时间通常为 5 分钟或 1 小时，最长为数小时（以 OpenAI 文档为准），且无法手动删除。
- **写入费用为零**：错误。Anthropic 的写入成本为 1.25 倍或 2 倍。对于仅使用一次的提示词而言，反而不划算。

对于像 Agent 一样持续循环相同工具列表和指令的场景，此效果尤为显著。Hana 以何种顺序堆叠提示词似乎决定了命中率。（[详情 → Hana](#/post/ai-harness)）

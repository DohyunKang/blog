メールニュースレターは、マーケティングオートメーションにおいて最も歴史のあるチャネルです。リストの収集、テンプレートへのコンテンツ埋め込み、予約送信という流れはスクリプトで簡単に構築できます。難しいのは「送ること」ではなく、「受信トレイに届くこと」であり、そのためには遵守すべき要件が定められています。ここでは Google が発信者ガイドラインに記載した内容を基準に整理します。

## 全体フロー

1. サブスクライバーリスト（同意を得た人物のみ）からセグメントを選択する。
2. テンプレートにコンテンツを埋め込みメッセージを作成し、人間による確認ポイントを設ける。
3. 送信サービス（または SMTP）へ送信する。この際、ドメイン認証とヘッダーが付与される。
4. 反応（閲覧、クリック、受信拒否、スパム報告）を集約し、次の送信対象を決定する。

1、2、4 はコンテンツカレンダーやダッシュボードの自動化と同様の構造である。3 がメール固有の部分だ。

## すべての発信者が遵守すべき事項

Google ガイドラインは 2024 年 2 月 1 日からすべての発信者に対し、以下の事項を求めていると記載している。

- 送信ドメインに SPF または DKIM 認証を設定する。
- Postmaster Tools で確認されるスパム報告率を 0.3% 未満に維持する。
- 送信に TLS 接続を使用する。
- 送信ドメインまたは IP に、正方向・逆方向 DNS (PTR) レコードが存在しなければならない。
- メッセージを RFC 5322 フォーマットに準拠させる。

スパム報告率については、要件（0.3% 未満）と推奨目標（0.10% 未満）が異なる。0.30% を超えることは避けるよう記載されている。

## 大規模送信者にはさらに追加要件がある

1 日あたり 5,000 通を超える送信量を持つ発信者には、以下の事項が加わる。

| 項目 | 要件 |
|---|---|
| 認証 | SPF と DKIM の他に DMARC。DMARC ポリシーは `none` でも可 |
| ドメイン整合性 | From: ドメインが SPF または DKIM ドメインと一致している必要がある |
| 受信拒否 | マーケティング・サブスクライブメッセージはワンクリック受信拒否を支援し、本文に目立つ受信拒否リンクを設ける |
| DKIM キー | 個人 Gmail から送信する場合は 1024 ビット以上、推奨は 2048 ビット |

個人ニュースレターは 1 日 5,000 通には満たないが、すべての発信者要件（SPF または DKIM、スパム報告率）はそのまま適用される。

## ワンクリック受信拒否はヘッダーで実装する

ワンクリック受信拒否は RFC 8058 で定められた方式である。メッセージに 2 つのヘッダーを挿入する。

```
List-Unsubscribe: <https://example.com/u/abc123>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```

受信側のメールサービスは、ユーザーが受信拒否ボタンを押すと `List-Unsubscribe` の HTTPS アドレスに対して POST リクエストを送信する。本文は `List-Unsubscribe=One-Click` である。したがって、送信側はこのアドレスを受け取り、該当するサブスクライバーをリストから除外するエンドポイントが必要になる。

RFC 8058 に記載されている条件にはさらにいくつかある。

- メッセージに有効な DKIM 署名が少なくとも 1 つ含まれており、その署名が両方のヘッダーをすべてカバーしている必要がある（`h=` タグに含まれる）。署名がない場合、受信側はワンクリック受信拒否を提供してはならない。
- URI には改ざん困難な値を含め、サーバーがそれを検証しなければならない。
- この POST に対して HTTPS リダイレクトで応答してはならない。

<details>
<summary>Python でヘッダーを付与してみる（直接実行して確認）</summary>

標準ライブラリ `email` を用いてメッセージを作成し、2 つのヘッダーを付与したものである。出力に 2 つのヘッダーがそのまま表示されることを確認している。実際の送信と DKIM 署名はこのコードには含まれていない。署名は送信サービスやメールサーバー側で行う段階だ。

```python
from email.message import EmailMessage

m = EmailMessage()
m["From"] = "news@example.com"
m["To"] = "reader@example.org"
m["Subject"] = "weekly"
m["List-Unsubscribe"] = "<https://example.com/u/abc123>"
m["List-Unsubscribe-Post"] = "List-Unsubscribe=One-Click"
m.set_content("hello")
print(m.as_string())
```

</details>

## 自動化時に見落としやすいこと

- 受信拒否処理を後回しにするとスパム報告率が上昇する可能性がある。報告率の上限があるため、受信拒否エンドポイントを先に作成する。
- ドメイン認証（SPF・DKIM・DMARC）は DNS 設定のため、コードの外で一度行う作業である。パイプラインには「認証通過確認」程度の段階のみ設ける。
- 全リストに一度に送信する構造の代わりに、少数の人へ先に送信して報告率を確認する段階を設ける方法もある。これは上記文書の内容ではなく、運用手法の一例だ。

AI を活用する場合、タイトル・本文の草案やセグメントごとの文言変換程度の箇所に入れるのが適切だ。送信対象と最終確認は人間が行う方が安全である。

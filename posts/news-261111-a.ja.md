## 何をするものか
AI エージェントがデスクトップアプリを見て操作できるようにする CLI だ。こういうのを一般に computer use と呼ぶ。モデルが人のように画面を見て、マウスとキーボードでアプリを扱う機能のこと。[詳しく → ツール使用](#/post/ai-tool-use)

変わっているのはスクリーンショットを使わないところ。画面の画像をモデルに見せて「ログインボタンは何ピクセル目か」を当てさせる代わりに、OS のアクセシビリティツリーを読む。アクセシビリティツリーは、スクリーンリーダーなどの支援技術のために OS がアプリ画面を「ウィンドウの中にボタン、その中に文字」という構造で渡すデータだ。macOS は AX API、Windows は UI Automation、Linux は AT-SPI を使う。

agent-desktop の中にモデルはない。README の言い方だと、ループは自分のエージェント側にある。これは目と手の役割だけだ。

## どう動くか
流れは3行。

```bash
agent-desktop snapshot --app Finder -i   # 操作できる要素ごとに ref が付いたツリー
agent-desktop click @s8f3k2p9:e8         # その ref を押す
agent-desktop snapshot --app Finder -i   # もう一度読んで結果を確認
```

snapshot はツリーを JSON で返し、操作できる要素に `@s8f3k2p9:e8` のような ref を付ける。前半がスナップショット ID、後半が要素番号。だから ref はそのスナップショットでしか通じない。`@e8` のように ID なしで使うと拒否され、画面が変わった後に古い ref を使うと `STALE_REF` が返る。そうしたらエージェントがもう一度 snapshot を撮ればいい。

いいなと思ったのは失敗の仕方だ。ピクセル座標でクリックすると、ウィンドウが少し動いただけで別の場所を押し、押し間違えたことにも気づかない。ここでは「この ref はもう合わない」とはっきり失敗する。エラーの JSON に `error.disposition.retry` があり、`safe` のときだけ再試行するよう書かれている。

CONCEPTS.md にはこの慎重さがもっと詳しく書いてある。OS から読んだ属性は「ある/ない/わからない」の3つに分け、読み取りの失敗を「ない」にまとめない。ウィンドウハンドルは OS が再利用することがあるので、プロセスの開始時刻と組み合わせて同じウィンドウか確かめ直すという。Chrome や Electron のアプリで名前のないラッパー要素が何重にも重なる画面では、そのラッパーを深さの計算から外してツリーが深くなりすぎないようにしている。

デフォルトは headless。ref での操作はポインタを動かさず、フォーカスも奪わず、アクセシビリティ API で処理する。本物のマウス・キーボード入力が必要なら `--headed` を付ける。

## なぜ話題か
トレンドの数字以外に、自分が見た理由は2つくらい。

1つは11月5日(韓国時間)の v1.2.0 で `agent-desktop mcp` が入ったこと。コマンドひとつひとつが `desktop_snapshot`、`desktop_click` のような MCP ツールとして公開される。MCP は AI アプリが外部ツールを同じやり方でつなげるための規格だ。[詳しく → MCP](#/post/ai-mcp) Claude Code のようなハーネスに設定1行でつなげるようになった。

もう1つは Vercel の agent-browser と対になっていること。ドキュメントも agent-browser.dev の下にある。ブラウザでやっていた「ツリーを読む → ref を押す → また読む」をデスクトップアプリ全体に広げた形だ。リリースノートのリンクを見ると元は lahfir/agent-desktop で、vercel-labs に移ったようだが、いつ、なぜ移ったかは確認できなかった。

## 入門者から見ると
PM や開発の入門者に響くのはコストと信頼性の話だと思う。スクリーンショット方式は毎ステップ画像をモデルに送るのでトークンを多く使い、座標の当て推量自体が外れることもある。ツリー方式はテキストの JSON なので軽く、何を押したかが記録に残る。

その代わり、アプリがアクセシビリティ情報をきちんと出していないとできることが減る。README にも、プラットフォームごとに headless でできること、`--headed` が要ること、拒否されることが違うと別に書いてある。ゲームやキャンバスで描くアプリでどれくらい使えるかは確認できなかった。

README 冒頭の注意も覚えておきたい。スナップショット、クリップボード、スクリーンショットにはデスクトップの個人情報がそのまま入りうるので、公開ログやアップロードに含めないこと。パスワードなどは `--stdin` で渡してプロセス引数に残さないようにという案内もある。

- リリース: v1.0.0(10月28日)、v1.1.0(11月3日)、v1.2.0(11月5日、MCP 追加)。日付は韓国時間。
- インストールは `npm install -g agent-desktop` か Homebrew。

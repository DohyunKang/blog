오늘 아침 GitHub 트렌딩(daily)에 backnotprop/plannotator가 올라와 있었다. 오늘 하루 별 860개, 레포 전체 별은 11,819개(11월 16일 오전 확인). 레포는 작년 12월 말에 만들어졌는데, X에서 이름이 들어간 글이 11월 13일(UTC) 47건, 14일 103건, 15일 136건으로 이번 주 들어 확 늘었다(리트윗 제외, X 집계 기준). 나는 README와 최근 릴리스 노트를 읽었고 직접 깔아 보지는 않았다.

## 뭐 하는 물건인지
코딩 에이전트가 낸 계획이나 코드 변경을 사람이 브라우저에서 보고 표시하고, 그 의견을 다시 에이전트에게 돌려보내는 로컬 도구다. 터미널에서 긴 계획을 스크롤하며 "3번 단계는 빼고, 5번은 이렇게"라고 타이핑하는 대신, 문서에 형광펜 긋듯 줄마다 코멘트를 달고 보내기를 누르는 식이다.

붙는 에이전트가 많다. README에 Claude Code, Codex, Copilot CLI, Gemini CLI, OpenCode, Kiro, Droid, Amp, Pi 등이 적혀 있다. 기능은 크게 넷이다.

1. 계획 리뷰: 에이전트가 계획을 내면 브라우저가 자동으로 열린다. 승인하면 진행, 거절하면 내 코멘트가 정리된 피드백으로 넘어간다.
2. 문서·HTML 표시: `/plannotator-annotate`로 마크다운, 폴더, URL, HTML 파일에 코멘트를 단다. `/plannotator-last`는 에이전트의 마지막 답변에 바로 단다.
3. 코드 리뷰: `/plannotator-review`로 커밋 안 한 변경이나 GitHub PR, GitLab MR을 diff 화면에서 보고 줄 단위로 코멘트한다.
4. Inbox: 여러 에이전트가 질문, 파일, 결정 요청을 한 창에 남겨 두고, 나는 시간 날 때 답한다. 최근 README 맨 위에 걸린 새 기능이다.

## 어떻게 도는지
계획 리뷰 흐름이 README에 그대로 나와 있다.

1. 에이전트가 계획 모드를 끝내려고 `ExitPlanMode`를 부른다.
2. 그 순간 훅이 실행된다. 훅은 에이전트가 특정 동작을 할 때 끼어들어 자동으로 도는 스크립트다. Claude Code에서는 `PermissionRequest` 훅에 `plannotator` 명령을 걸어 둔다.
3. 로컬 서버가 훅 입력에서 계획 내용을 읽고 브라우저에 리뷰 화면을 띄운다.
4. 내가 표시하고 승인하거나 거절한다.
5. 거절하면 구조화된 피드백이 에이전트에게 가고, 에이전트가 고친 계획을 다시 내면 이전과 무엇이 바뀌었는지 diff로 보여 준다.

핵심은 에이전트가 원래 사람에게 허락을 구하는 지점에 끼어든다는 거다. 에이전트 자체를 바꾸지 않고 하네스(에이전트를 감싸고 도구·권한·흐름을 관리하는 바깥 틀)의 훅만 쓴다. 그래서 여러 에이전트에 같은 방식으로 붙일 수 있다. [자세히 → 하네스](#/post/ai-harness) [자세히 → 에이전트 루프](#/post/ai-agent-loop)

Inbox는 조금 다르다. 에이전트가 질문을 남겨도 세션을 붙잡고 기다리지 않고, 내 답은 그 질문을 한 세션의 다음 턴으로 들어간다고 적혀 있다. Claude Code, Pi, OpenCode는 플러그인으로 붙고, 그 밖의 에이전트는 `plannotator inbox mcp`로 MCP를 통해 붙는다. [자세히 → MCP](#/post/ai-mcp)

계획, diff, 코멘트는 기본적으로 로컬에 남고 사용 통계는 수집하지 않는다고 한다. 다만 화면을 열 때마다 GitHub에 최신 릴리스를 확인하는 요청이 가고, 이건 아직 끌 수 없다고 README에 적혀 있다. Ask AI나 리뷰 에이전트를 쓰면 그 내용이 설정한 모델 제공자로 간다.

## 왜 화제인지
요즘 에이전트를 여러 개 동시에 돌리는 사람이 많아지면서 "사람이 어디서 끼어드냐"가 병목이 됐다. 이 도구는 그 지점을 화면 하나로 모은다. X에서 보이는 반응도 대부분 "비동기로 답할 수 있어서 좋다"는 쪽이었다.

릴리스 속도도 한몫한다. 11월 11일부터 15일(한국 시간) 사이에 v0.28.61부터 v0.28.65까지 다섯 번 나왔다. 가장 최근 v0.28.65에는 에이전트가 아직 받지 않은 답장을 회수하는 Take back 버튼이 들어갔다. 보낸 답을 고치려고 두 번째 메시지를 보내면 서로 다른 지시가 큐에 쌓이는 문제가 있어서였다고 한다.

Reddit과 YouTube에서 얼마나 돌았는지는 확인 못 함.

## 입문자 입장에서
PM 입장에서는 에이전트에게 일을 맡길 때 가장 싸게 방향을 바로잡을 수 있는 순간이 계획 단계라는 게 다시 보였다. 코드가 나온 뒤에 고치는 것보다 계획 문서 한 줄에 "이건 하지 마"를 다는 게 훨씬 싸다. 문서에 코멘트를 다는 방식은 기획 리뷰랑 똑같아서, 개발을 몰라도 에이전트 작업을 검토할 수 있는 통로가 생긴다.

개발 입문자라면 쓰고 있는 에이전트에서 `/plannotator-last`로 마지막 답변에 코멘트를 달아 보는 게 제일 가벼운 시작 같다. AI가 대신 리뷰하는 쪽이 궁금하면 어제 글과 비교해 보면 좋다. 그쪽은 모델이 코멘트를 쓰고, 이쪽은 사람이 쓴 코멘트를 모델에게 돌려준다. [자세히 → Open Code Review](#/post/news-261115-a)

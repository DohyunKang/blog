情報セキュリティの単元は用語が多く、名前が似ている攻撃が次々と出てくるため、暗記すると混同してしまいます。まず、各ツールが守ろうとしているものが異なることを整理しておけば理解しやすくなります。試験日程や受験料については公式サイトで確認し、ここでは概念と問題の解き方のみ記載します。

## 暗号化

暗号化とは、読み取れない形式に変換することで機密性を保つ手法です。試験では使用する鍵の数によって分類して問われます。

| 区分 | キー | 特徴 | 例 |
|---|---|---|---|
| 対称鍵 | 暗号化・復号化に同じ鍵を使用 | 高速だが、鍵を事前に共有する必要がある | DES, AES |
| 非対称鍵（公開鍵） | 公開鍵と秘密鍵のペア | 公開鍵は配布してもよいが、秘密鍵は秘匿する | RSA, ECC |

対称鍵ではユーザーペアごとに秘密鍵が必要となるため、利用者が増えるほど鍵管理が困難になります。公開鍵方式は事前に秘密を共有する必要がない代わりに、その公開鍵が本当にその人物のものか確認する必要があります。この確認は PKI などの仕組みが担当します。

公開鍵における鍵の役割は目的によって逆転します。試験でほぼ毎回出題されるポイントです。

| 目的 | 作成側 | 復号・検証側 |
|---|---|---|
| 暗号化（機密性） | 相手の公開鍵で暗号化 | 相手の秘密鍵で復号化 |
| 電子署名（完全性・否認防止） | 自分の秘密鍵で署名 | 自分の公開鍵で検証 |

[暗号・ハッシュ・署名の詳細 → 暗号化・ハッシュ・認証の基礎](#/post/sec-authn-crypto)

<details>
<summary>小さな数字で RSA を試す</summary>

RSA は、大きな 2 つの素数の積を因数分解することが困難であるという性質を利用した方式です。非常に小さな素数を使って手順を追ってみました。p=61, q=53 の場合 n=3233 となり、公開指数 e=17 に対応する秘密指数 d は 2753 です。

```python
p, q = 61, 53
n = p * q
phi = (p - 1) * (q - 1)
e = 17
d = pow(e, -1, phi)
c = pow(65, e, n)       # 평문 65를 공개키(e, n)로 암호화
print(n, d, c, pow(c, d, n))
# 3233 2753 2790 65
```

平文 65 が 2790 に変わり、秘密鍵 d で復号すると 65 に戻ります。実際にはこのような小さな数ではなく、非常に大きな数が使用されます。

</details>

### ハッシュ

ハッシュとは、入力データの長さがどれだけあっても、固定された長さの値に変換する関数です。元に戻せない一方方向性のため「復号化」という概念はなく、ファイルやメッセージが変更されたかどうかを確認する完全性のチェックに使用します。入力が 1 つの文字だけ異なると結果も完全に異なります。

```python
import hashlib
print(hashlib.sha256(b"password").hexdigest()[:16])  # 5e884898da280471
print(hashlib.sha256(b"passworD").hexdigest()[:16])  # 9e78de733c6a51c0
```

SHA-256 は 256 ビット、MD5 は 128 ビットの長さの値を出力します。どちらも長さは入力と無関係に固定されています。

パスワードを保存する際には、ハッシュにソルト（ユーザーごとに異なるランダムな値）を混ぜます。同じパスワードでも結果が異なるため、事前に計算しておいた表を使って即座に一致させる攻撃が困難になります。

```python
print(hashlib.sha256(b"s1" + b"password").hexdigest()[:16])  # 33453fb858dcac18
print(hashlib.sha256(b"s2" + b"password").hexdigest()[:16])  # bd22d1631a4e4c66
```

<details>
<summary>ハッシュと暗号化が混同される点</summary>

- 暗号化は鍵があれば元に戻せますが、ハッシュは戻せません。
- ハッシュに秘密鍵を組み合わせてメッセージが改ざんされていないか確認する方式を「メッセージ認証コード (MAC)」と呼びます。アクセス制御の MAC（強制アクセス制御）と略称が同じで、問題文の文脈から区別する必要があります。
- 電子署名は通常、メッセージ全体ではなく、メッセージのハッシュ値に秘密鍵で署名する形で作成されます。

</details>

## 認証とアクセス制御

認証 (Authentication) は「あなたが誰か」を確認することであり、認可 (Authorization) は「その人が何をできるか」を定めることです。アクセス制御とは、認可を実際に強制する装置を指します。

認証手段は通常、3 つの要素に分類されます。

| 種類 | 例 |
|---|---|
| 知識（知っていること） | パスワード、PIN |
| 所有物（持っているもの） | OTP デバイス、スマートフォン、証明書 |
| 特性（本人自身） | 指紋、顔認証 |

異なる種類の要素を 2 つ以上組み合わせるのが多要素認証です。パスワード 2 つは同じ種類のため、多要素認証にはなりません。

### アクセス制御モデル

| モデル | 権限を誰が決めるか | 概要 |
|---|---|---|
| DAC（任意） | リソースの所有者 | 所有者が誰に開くかを決定する |
| MAC（強制） | システムポリシー | 機密レベル（秘密・極秘など）とユーザーの許可レベルで判断する |
| RBAC（役割ベース） | 組織の役割 | 職務にふさわしい権限のみを束ねて付与する |

最小権限の原則とは、各ユーザーに業務に必要な範囲の権限のみを与えることです。RBAC はこの原則を守るのに適しています。人事担当者がネットワークアカウントを作成できないように設定するなどです。

## 攻撃の種類

攻撃名だけでは何の攻撃か思い浮かべにくい場合が多く、動作を一行ずつまとめて暗記しました。

| 攻撃 | 動作 |
|---|---|
| SYN フラッディング | 宛先を偽装した SYN パケットを大量に送り出し、応答がない半開接続でサーバーのリソースを枯渇させる |
| スマーフ | ブロードキャストアドレス宛てに、被害者アドレスを送信元として偽装したパケットを送り、複数のホストからの応答が被害者に集中させます |
| デス・ピン | 不正な ping パケットで脆弱なシステムをダウンさせる |
| テアードロップ | 重複し不正な IP フラグメントを送信し、再組み立て時にエラーを引き起こす |
| DDoS | 感染した多数のホスト（ボットネット）が同時に攻撃し、帯域幅やリソースを枯渇させる |

[TCP 接続と IP フラグメントの仕組み → ネットワーク](#/post/jb-network)

DoS はサービスを利用不能にするのが目的であり、可用性に影響を与えます。送信元が単一ではないため、DDoS は単一の送信元をブロックするだけでは解決しません。試験では名前と動作を一致させる問題が出ます。送信元偽装（スプーフィング）が SYN フラッディングとスマーフの両方で使用される点も併せて覚えておくと良いでしょう。

### ウェブ攻撃：SQL インジェクションと XSS

SQL インジェクションは、入力値に SQL コードを埋め込みクエリの意図を変更する攻撃です。以下は sqlite メモリ DB を直接用いて確認したものです。

```python
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("create table u(n,p)")
db.execute("insert into u values('kim','pw')")

n = "kim' --"
q = "select * from u where n='%s' and p='bad'" % n
print(db.execute(q).fetchall())      # [('kim', 'pw')]  비밀번호가 틀렸는데 통과
print(db.execute("select * from u where n=? and p=?", (n, 'bad')).fetchall())  # []
```

文字列を連結すると `--` 以降の条件がコメントアウトされ、パスワードチェックが回避されます。値をプレースホルダー（`?`）として渡すと、入力は SQL コードではなく単なる値として扱われブロックされます。[SQL の基礎 → データベースの概念](#/post/jb-db-concept)

XSS は、信頼できるサイトに悪意のあるスクリプトを埋め込み、訪問者のブラウザで実行させる攻撃です。ブラウザがそのサイトを信頼するため、スクリプトはクッキーやセッショントークンなどのデータにアクセスしたり、画面を変更したりできます。入力が即座に応答として返される場合は反射型、サーバーに保存され閲覧する全員に実行される場合は持続型です。防御の基本は入力検証と出力エンコーディングです。

```python
import html
print(html.escape("<script>x</script>"))  # &lt;script&gt;x&lt;/script&gt;
```

<details>
<summary>解法のポイント</summary>

セキュリティ問題は、通常説明を与えて用語を選ばせるか、用語を与えて説明を選ばせる形式です。このように解きます。

1. 説明から守ろうとしている性質（機密性・完全性・可用性）をまず特定します。
2. キーの話が出たら、何個あるか、誰のキーかを確認します。署名の場合は送信側の秘密鍵です。
3. 攻撃名は動作の一行とペアにして消去します。ブロードキャストと送信元偽装が見えればスマーフ、半開接続が見えれば SYN フラッディングです。
4. アクセス制御は「誰が決定するか」を見ます。所有者なら DAC、等級なら MAC、職務なら RBAC です。

</details>

## よくある誤解

- ハッシュを「暗号化したもの」と呼ぶのは間違いです。解読不可能な一方方向の要約です。
- 公開鍵で署名するわけではありません。署名は秘密鍵、検証は公開鍵で行います。
- パスワードを 2 つ求められても同じ種類であれば多要素認証ではありません。
- アクセス制御の MAC とメッセージ認証コードの MAC は名前だけが似ています。

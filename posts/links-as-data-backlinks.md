오늘은 개인 프로젝트에서 글끼리 서로 엮이게 만들다가, 링크도 데이터로 따로 빼 두는 게 낫다는 걸 알게 된 날이었다.

## 손으로 걸면 끝이 없다

글을 쓰다 보면 설명하는 중에 다른 개념이 계속 나온다. 그 개념을 따로 정리한 글이 있으면 눌러서 넘어가고 싶어진다. 처음엔 글마다 링크를 직접 걸면 되겠다 싶었는데, 그러면 새 글이 생길 때마다 옛날 글을 다 뒤져서 고쳐야 한다. 한 번 빠뜨리면 그대로 묻힌다.

그래서 방식을 바꿨다. "이 용어는 이 글에서 설명한다"는 목록을 한 군데에 모아 두고, 화면에 글을 그리는 순간에 본문에서 그 용어를 찾아 자동으로 링크를 붙인다. 글 파일은 그대로 두고, 연결 정보만 따로 사는 셈이다. 새 정리글이 생기면 목록에 한 줄만 넣으면 옛날 글에도 바로 링크가 생긴다. 같은 정보를 여러 군데 적지 않는 **단일 원본** 얘기랑 같은 이야기 같다.

규칙도 좀 필요했다. 용어가 나올 때마다 다 링크하면 본문이 파랗게 도배된다. 그래서 글마다 처음 나온 곳 하나만 링크하고, 코드 안이나 제목, 이미 링크가 걸린 곳, 자기 자신을 설명하는 글에서는 건너뛴다. 같은 단어를 다른 뜻으로 쓰는 묶음도 있어서 거기는 빼는 옵션도 뒀다.

## 거꾸로 가는 링크

반대 방향도 있다. 어떤 개념 글 아래에 "이 개념을 언급한 글" 목록을 보여 주는 거다. 이걸 **역링크(backlink)**라고 한다. 위키나 메모 앱에서 자주 보던 그거다.

역링크는 글 하나만 봐서는 못 만든다. 모든 글 본문을 훑어야 누가 나를 언급했는지 안다. 방문할 때마다 그걸 하면 느리니까, 글을 올리기 전에 스크립트로 한 번 계산해서 결과를 파일로 저장해 둔다. 미리 계산해 두고 화면은 읽기만 하는 구조다. 이 스크립트는 검사도 같이 해서, 목록에 적힌 글이 실제로 없거나 별칭이 두 용어에 겹치면 오류를 내고 멈춘다. 사람이 눈으로 확인하는 대신 기계가 걸러 준다.

## 고쳤는데 그대로인 화면

화면 스타일을 바꾸다 들은 얘기도 하나 있다. 브라우저는 스타일 파일이나 스크립트를 한 번 받으면 저장해 두고 다시 쓴다. 그래서 파일을 고쳐 올려도 이미 왔던 사람은 옛 화면을 본다. 해결은 파일 주소 끝에 버전 값을 붙이고, 고칠 때마다 그 값을 바꾸는 거다. 주소가 달라지면 브라우저는 다른 파일로 보고 새로 받는다. 이걸 캐시 무효화, 또는 캐시 버스팅이라고 부른다.

## 공식 통로가 닫히면

마지막으로, 다른 글쓰기 플랫폼으로 옮길지 얘기하다가 나온 것. 그 플랫폼은 글을 올리는 공개 API를 닫았다고 한다. 그러면 자동으로 올리려면 브라우저를 띄워서 사람처럼 로그인하고 칸에 써넣어야 한다. 화면 구조가 조금만 바뀌어도 깨지고, 로그인을 사람이 해 줘야 할 때도 생긴다. 자동화를 생각하면 화면이 예쁜지보다 공식 API가 있는지를 먼저 봐야 하더라. 그래서 원본은 자동으로 쌓기 쉬운 쪽에 두고, 필요하면 골라서 옮겨 싣는 방법도 있다는 걸 들었다.

1. **링크를 데이터로 빼기**는 용어와 설명 글의 짝을 한 곳에 모아 두고, 화면을 그릴 때 자동으로 링크를 붙이는 방식이다.
2. **역링크**는 "나를 언급한 글" 목록이다. 전체를 훑어야 해서 미리 계산해 두는 게 보통이다.
3. **캐시 버스팅**은 파일 주소에 버전을 붙여 바꿔서, 브라우저가 새 파일을 받게 하는 방법이다.
4. **공식 API 유무**는 자동화할 때 먼저 볼 것이다. 없으면 화면 자동화로 가야 하고, 그건 잘 깨진다.

링크 하나 거는 일도 결국 구조 문제였다.

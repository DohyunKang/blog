This morning google-research/paper-orchestra was on GitHub's daily trending page. 1,175 stars in a day, 2,956 in total (checked the morning of November 18). It's a multi-agent pipeline that takes research ideas and experiment notes and produces a LaTeX paper draft in a conference's format. I read the README, the arXiv abstract, the project page, and a few files under `methods/`. I didn't run it myself.

## What it is
It's the code for a paper Google Cloud AI Research put out in April (arXiv 2604.05018). There are two inputs: an idea summary (the method and theory written down) and an experimental log (table numbers plus observations read off the figures). Add a LaTeX template and author guidelines for a venue like CVPR or ICLR, and out comes a manuscript PDF with references, plots, and concept diagrams.

Multi-agent here means splitting the job into several LLM calls, each holding its own role description and doing only its part. [More → Subagents](#/post/ai-subagent) There are five of them.

## How it runs
Following `paper_writer_with_plotting.py`, the order is:

1. An outline agent reads the inputs and writes `outline.json`: section layout, figure plan, and which directions to search for related work.
2. A literature agent and a plotting agent run at the same time (two threads).
3. A section-writing agent takes the outline, the citation list, and the figure list and writes the whole paper in LaTeX.
4. A refinement agent revises the draft up to three times while watching an AI reviewer's score.

Steps 2 and 4 are the interesting parts.

For literature, the model finds candidate papers through web search (Gemini's Google Search tool), then asks the Semantic Scholar API about each title again. It fuzzy-matches the title (a 0–100 score for how similar two strings are) against the top three results, and only adds it to the citations if the score is over 70. Papers published after a set cutoff date are dropped. It's a code-side check that keeps the model from citing plausible papers that don't exist. [More → Hallucination](#/post/ai-hallucination)

Refinement has a plain rule baked in. The revised draft is compiled and scored again by a reviewer agent. If the overall score goes up, the revision is accepted and it loops again. If it goes down, it reverts to the previous version and stops. If it stays the same, it stops when the sub-score drops add up to more than the gains. The plotting agent works similarly: a critic agent looks at each figure and it's redrawn up to three times until the critic says nothing needs changing. In the code the default model is Gemini 3.1 Pro preview, Gemini 3 Pro Image preview for images, and it can also run on an OpenAI key. [More → Agent loop](#/post/ai-agent-loop)

Someone on X wrote that rewriting until an AI reviewer scores it higher is both the clever part and the catch, and I thought the same. The reviewer is a model too, so inside this loop you can't tell whether a higher score means a better paper or one tuned to that reviewer's taste.

## How well it writes
For evaluation they built a benchmark (PaperWritingBench) by reverse-engineering idea summaries and experiment logs from 100 CVPR 2025 and 100 ICLR 2025 papers. In blind side-by-side comparisons by 11 AI researchers, it beat a single agent that writes everything in one call and AI Scientist-v2 by a win-rate margin of 50–68 points on literature review quality and 14–38 points on overall quality. The project page says there's still a gap compared with the human-written originals. The benchmark dataset isn't in the repo yet and is supposed to be released separately later.

## For beginners
Even if you never write papers, the structure is worth borrowing. It doesn't write a long document in one shot but splits it into outline, research, body, and review. It checks the part models love to make up (citations) against an outside API. And it puts rules like "if the score drops, revert and stop" in code. As a PM, this order could work as a checklist when looking at automating planning docs or research reports.

If you're new to development, the five files under `methods/agents/` are short and easy to read. The outline agent is 60 lines. To run it you need a Python 3.11 conda env, a Gemini or OpenAI key, and a Semantic Scholar key, then pass a materials folder and a template folder to `paper_writing_cli.py`. The last line of the README says it's not an officially supported Google product, and the ethics section on the project page says human researchers stay responsible for facts and claims.

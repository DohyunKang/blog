推論モデルは、回答を出す前に独自に思考する文章（思考トークン）をまず生成するモデルであり、その文章が画面に表示されなくても、出力トークンの料金と待ち時間としてはそのまま返ってきます。

## まず簡単な言葉で

数学の問題を暗算ですぐに解く人と、紙に計算過程を書きながら解く人がいます。一般的な LLM は前者に近い一方、推論モデルは後者に近いです。質問を受けると、回答の前に「思考」を長く書き込み、それに基づいて最終的な回答を作成します。この計算過程部分が思考トークン（thinking tokens、OpenAI 用語では reasoning tokens）です。

[LLM](#/post/ai-llm) はもともと次のトークンを一つずつ続けて生成する方式なので、回答に到達するために使用できる文章の量がそのまま「計算可能な量」になります。中間の計算過程を書かせるようにすると、難しい問題をよりよく解けます。これをモデル内部に完全に実装したものが推論モデルです。

## 原理：思考をさせることでなぜ良くなるのか

根拠となる論文は Wei らによる 2022 年の chain-of-thought です。例題に中間の推論段階も示すと、モデルがそれを模倣し、十分に大きなモデルでは算術・常識・記号推論のパフォーマンスが向上しました。論文によると、540B モデルに例題を 8 つ与えるだけで、GSM8K（小学生向け数学文章問題）で当時の最高レベルの成績を収めたとのことです。ここでは人間がプロンプトに計算過程の例示を入力しましたが、推論モデルはこの計算過程をプロンプトではなく、モデル自身が自発的に行うように設計されています。本稿では API 上でどのように表示され、どのように課金されるかについてのみ扱います。

## API での表示

Anthropic と OpenAI のドキュメントで言及されている共通点は以下の通りです。

| | Claude(thinking) | OpenAI(reasoning) |
|---|---|---|
| 名前 | 思考ブロック、thinking tokens | reasoning tokens |
| 表示可否 | 要約版が返されるか省略（omitted）可能 | API では表示されない |
| 課金 | 出力トークン | 出力トークン |
| ウィンドウ占有 | 行う（`max_tokens` に含まれる） | 行う |
| 深さ調整 | effort(low~max) | reasoning.effort(none~max など、モデル依存) |

Anthropic のドキュメントで目立つ点は課金部分です。画面に表示されるのは要約された思考ですが、料金は要約版ではなく、実際にモデルが生成した全思考トークンに基づいて計算されます。ドキュメントの表現では、「請求される出力トークン数」と「応答に表示されるトークン数」は一致しないとしています。`display` を `omitted` に設定して全く受け取らなくても、請求額は同じです。どれだけ使用したかは、応答の `usage.output_tokens_details.thinking_tokens` で確認できます。

OpenAI のドキュメントも同様です。推論トークンは API では表示されませんが、コンテキストウィンドウを使用し、出力トークンとして課金されます。また、開始時に推論と出力のために少なくとも 25,000 トークン程度を確保しておくことを推奨しています。この数値のため、ウィンドウが満杯になると、回答が一つも出力されないまま `incomplete` で終了する可能性があるとしています。

[コンテキストウィンドウ](#/post/ai-context-window) の観点から見ると、思考トークンは私が書いた文章ではありませんが、入力・出力としてスペースを占めています。

## 費用と遅延：なぜ気にすべきか

思考トークンが出力トークンであるため、両者は同時に増加します。

- **費用**: 出力トークンは通常、入力トークンよりも単価が高い（単価はモデルによって異なるため具体的な数字は記載しません）。質問は一行程度ですが、思考が数千トークンに及ぶ場合、料金は思考部分が支配的になります。機能単位の原価については [AI サービスの原価](#/post/app-cost) で別途扱います。
- **時間**: 回答の最初の文字が出る前に思考を先に生成するため、体感的な待ち時間が長くなります。ストリーミングで受け取っても、思考区間が過ぎるまで本文は出力されません。

そのため、深さを調整するレバーがあります。

## 深さの調整：budget から effort へ

Anthropic のドキュメントで示された変化が興味深かったです。以前の方式（extended thinking）では `budget_tokens` で思考予算を直接設定していました。最小 1,024 トークンであり、`max_tokens` より小さくする必要がありましたが、これは目標値に過ぎず厳密な上限ではありませんでした。しかし、この方式は現在 deprecated として表示されており、ドキュメントによると Claude 4.7 以降のモデルはこの方式を完全に拒否（400 エラー）します。

代わりに採用されているのが適応型（adaptive）思考です。モデルが各リクエストごとに思考を行うか、どれだけ行うかを自ら決定し、私は `effort`(low, medium, high, xhigh, max) で傾向のみを設定します。ドキュメントから読み取った特徴を要約すると以下のようになります。

- 簡単な質問は、考えずに即座に答えられるため、「すべてのターンに思考ブロックがある」と仮定してコードを書くべきではありません。
- コストの上限は `max_tokens` が担当します。思考と回答を合わせた総量のハードキャップです。思考が長くなり、これが先に埋まると回答が切り捨てられるため、思考なしの回答を基準とした値は小さすぎる可能性があります。
- 思考量を減らしたい場合は、「もっと考えずに」というプロンプトを使う前に `effort` を下げることをドキュメントが推奨しています。一部のモデルではプロンプトだけでは十分に減らないとも書かれています。
- 途中から `effort` を変更するとプロンプトキャッシュが壊れます。1 つの会話内では値を固定するのが望ましいです。これは [プロンプトキャッシング](#/post/ai-prompt-caching) と関連する部分です。

デフォルトの `effort` はモデルによって異なります（ドキュメントには一部のモデルは high、他のモデルは medium などとあります）ので、使用时にはドキュメントのモデルごとの表を確認する必要があります。

## いったいいつ使うのか

OpenAI のドキュメントでは、複雑な問題解決、コーディング、科学的推論、複数の段階を要するエージェントタスクに推論モデルの使用を推奨しています。[エージェントループ](#/post/ai-agent-loop) では、ツール結果を受け取るたびに次の行動を考える方が有利であり、Anthropic のドキュメントもツール呼び出しの間に思考が挟まる（interleaved）動作について説明しています。逆に、文章の推敲、分類、単純な抽出のように即座に答えが出るような作業には思考は不要です。これは私が上記の内容を見て整理した基準であり、ドキュメントが直接比較した文ではありません。

## よくある誤解

- 推論モデルは幻覚がない：思考を行うことで [幻覚](#/post/ai-hallucination) が消えるという根拠は知られていません。
- 表示される要約が実際の思考全体ではない：これは要約版です。料金の基準も要約ではなく全体です。
- 長く考えるほど常に良いわけではない：ドキュメントには予算が大きくなるほど収益の体感値が低下すると書かれています（Anthropic、タスクによります）。遅延とコストは確実に増加します。
- 思考トークンは無料の付加機能ではない：出力トークンとして課金されます。
- [サンプリング](#/post/ai-sampling) 設定（temperature など）がそのまま適用されるわけではない：モデルごとの制限があるためドキュメントを確認する必要があります。

<details>
<summary>詳細な解説：Anthropic の課金構造</summary>

ドキュメントの基準では、思考を使用すると以下の 3 つが請求されます。

1. 思考中に使用したトークン（出力トークンとして請求）。
2. 以前のターンの思考ブロックのうちコンテキストに残っているもの（入力トークンとして請求）。モデルによってはすべてのターンを残す場合と最後のターンだけを残す場合があります。
3. 通常の回答出力トークン。

思考要約を作成するコストは別途請求しないとのことです。`output_tokens` が請求基準の合計であり、`thinking_tokens` はその内の内訳（読み取り専用）です。サンプルレスポンスでは `output_tokens` 348 のうち `thinking_tokens` が 312 でした。これはドキュメントの例示数字に過ぎず、平均ではありません。

</details>

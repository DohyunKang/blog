## 加密

加密是将信息转换为不可读的形式以保护机密性的方法。考试中常根据使用密钥的数量进行提问。

| 分类 | 密钥 | 特点 | 示例 |
|---|---|---|---|
| 对称密钥 | 加密与解密使用同一把密钥 | 速度快，但需预先分发密钥 | DES, AES |
| 非对称密钥（公钥） | 一对公钥和私钥 | 公钥可公开传播，私钥必须保密 | RSA, ECC |

对称密钥方案中，每对用户都需要一个共享密钥，因此随着用户数量增加，密钥管理难度也随之上升。非对称密钥方案无需预先交换秘密，但必须验证该公钥确实属于声称的持有者，这一验证工作通常由 PKI 等体系承担。

在非对称加密中，密钥的作用会根据目的而互换，这是考试中几乎每道题都会涉及的考点。

| 目的 | 生成方 | 解密/验证方 |
|---|---|---|
| 加密（机密性） | 使用接收方的公钥进行加密 | 使用接收方的私钥进行解密 |
| 数字签名（完整性·防抵赖） | 使用发送方的私钥进行签名 | 使用发送方的公钥进行验证 |

[关于加密、哈希与签名的更多细节 → [加密、哈希与认证基础](#/post/sec-authn-crypto)]

<details>
<summary>用极小数字演示 RSA</summary>

RSA 算法基于“对两个大素数的乘积进行因数分解非常困难”这一原理。此处仅跟随流程使用极小的素数演示：若 p=61，q=53，则 n=3233；与公开指数 e=17 对应的私有指数 d 为 2753。

```python
p, q = 61, 53
n = p * q
phi = (p - 1) * (q - 1)
e = 17
d = pow(e, -1, phi)
c = pow(65, e, n)       # 평문 65를 공개키(e, n)로 암호화
print(n, d, c, pow(c, d, n))
# 3233 2753 2790 65
```

明文 65 被加密为 2790，再用私钥 d 解密后恢复为 65。实际应用中使用的数字远大于此。

</details>

### 哈希

哈希函数无论输入多长，都会输出固定长度的值。它是一种单向函数，无法逆向还原，因此不存在“解密”概念，主要用于检测文件或消息是否被篡改（完整性校验）。即使输入仅相差一个字符，输出结果也会完全不同。

```python
import hashlib
print(hashlib.sha256(b"password").hexdigest()[:16])  # 5e884898da280471
print(hashlib.sha256(b"passworD").hexdigest()[:16])  # 9e78de733c6a51c0
```

SHA-256 输出 256 位长度，MD5 输出 128 位长度，两者输出长度均与输入无关且固定不变。

存储密码时，会在哈希值中加入盐（salt，即每个用户不同的随机值）。即使密码相同，因盐不同导致哈希结果也不同，从而使得攻击者无法通过预先计算的彩虹表一次性匹配破解。

```python
print(hashlib.sha256(b"s1" + b"password").hexdigest()[:16])  # 33453fb858dcac18
print(hashlib.sha256(b"s2" + b"password").hexdigest()[:16])  # bd22d1631a4e4c66
```

<details>
<summary>哈希与加密的混淆点</summary>

- 加密在拥有密钥时可还原原始内容；哈希则不可还原。
- 将秘密密钥加入哈希值以验证消息未被篡改的方式称为消息认证码（MAC）。需注意：此处的 MAC 缩写与访问控制中的“强制访问控制”（Mandatory Access Control, 也常简写为 MAC）相同，解题时需根据上下文区分。
- 数字签名通常不是对整个消息进行签名，而是对消息的哈希值使用私钥签名。

</details>

## 认证与访问控制

认证（Authentication）是确认“你是谁”的过程；授权（Authorization）则是决定“此人能做什么”。访问控制是指实际强制执行授权的机制。

认证手段通常分为三类：

| 类型 | 示例 |
|---|---|
| 所知（知识） | 密码、PIN 码 |
| 所拥（拥有物） | OTP 设备、智能手机、数字证书 |
| 所是（生物特征） | 指纹、面部识别 |

组合两种或以上不同类别的认证方式称为多因素认证。仅使用两个相同类型的认证（如两个密码）不属于多因素认证。

### 访问控制模型

| 模型 | 权限由谁决定 | 简述 |
|---|---|---|
| DAC（自主访问控制） | 资源所有者 | 所有者自行决定向谁开放权限 |
| MAC（强制访问控制） | 系统策略 | 依据安全等级（如绝密、机密等）和用户许可等级进行判断 |
| RBAC（基于角色的访问控制） | 组织角色 | 根据职务分配相应权限集合 |

最小权限原则是指仅授予用户完成工作所需的最小权限。RBAC 较易遵循该原则，例如禁止人事专员创建网络账户。

## 攻击类型

由于仅凭名称往往难以联想到具体行为，因此我将每种攻击的动作概括为一句话进行记忆。

| 攻击名称 | 动作描述 |
|---|---|
| SYN Flood | 发送伪造源地址的 SYN 数据包，使服务器资源被大量半开连接耗尽 |
| Smurf | 向广播地址发送以受害者地址为源 IP 的数据包，导致多个主机的响应汇聚到受害者身上 |
| Ping of Death | 利用异常大的 ICMP 回显请求（Ping）数据包使脆弱系统崩溃 |
| Teardrop | 发送重叠且异常的 IP 分片，导致系统在重组过程中发生错误并崩溃 |
| DDoS | 大量被感染的宿主（僵尸网络）同时发起攻击，耗尽目标带宽与资源 |

[TCP 连接与 IP 分片的形成机制 → 网络](#/post/jb-network)

DoS 攻击的目的是使服务不可用，因此影响的是可用性。由于 DoS 的源地址并非单一，仅封锁一个发送源无法彻底防御 DDoS。考试中常出现将攻击名称与其动作进行匹配的题型。此外，记住“源地址伪造（Spoofing）”这一技术同时应用于 SYN Flood 和 Smurf 攻击也很有帮助。

### Web 攻击：SQL 注入与 XSS

SQL 注入是一种通过将 SQL 代码片段插入输入值中，从而改变查询逻辑的攻击方式。下方是在 SQLite 内存数据库中直接运行的示例。

```python
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("create table u(n,p)")
db.execute("insert into u values('kim','pw')")

n = "kim' --"
q = "select * from u where n='%s' and p='bad'" % n
print(db.execute(q).fetchall())      # [('kim', 'pw')]  비밀번호가 틀렸는데 통과
print(db.execute("select * from u where n=? and p=?", (n, 'bad')).fetchall())  # []
```

通过字符串拼接，`--` 之后的内容会被视为注释，导致密码验证失效。若将参数作为占位符（`?`）传递，则输入仅被视为数据而非 SQL 代码，从而被阻止。[SQL 基础 → 数据库概念](#/post/jb-db-concept)

XSS（跨站脚本攻击）是将恶意脚本注入到受信任的网站中，使其在访客浏览器中执行。由于浏览器信任该网站，这些脚本可以访问或修改 Cookie、会话令牌等数据，甚至篡改页面内容。若输入直接反射到响应中，称为反射型 XSS；若存储于服务器并在所有查看该内容时执行，则称为存储型 XSS。防御的基本手段是输入验证与输出编码。

```python
import html
print(html.escape("<script>x</script>"))  # &lt;script&gt;x&lt;/script&gt;
```

<details>
<summary>解题技巧</summary>

安全类问题通常有两种形式：给出描述要求选择术语，或给出术语要求解释其含义。解题步骤如下：

1. 首先从描述中识别需要保护的安全属性（机密性、完整性、可用性）。
2. 若涉及密钥，需判断密钥的数量及归属：签名使用发送方的私钥，验证使用公钥。
3. 将攻击名称与其动作描述进行匹配记忆。例如，出现“广播地址”和“源地址伪造”即对应 Smurf 攻击；出现“半开连接”则对应 SYN Flood。
4. 访问控制需判断由谁决定权限：若由所有者决定则为 DAC（自主访问控制），基于等级则为 MAC（强制访问控制），基于角色则为 RBAC（基于角色的访问控制）。

</details>

## 常见误区

- 将哈希称为“加密”是错误的。哈希是不可逆的单向摘要算法。
- 并非使用公钥进行签名。签名应使用私钥，验证则使用公钥。
- 即使要求两个密码，若类型相同也不构成多因素认证。
- 访问控制中的 MAC 与消息认证码（MAC）虽名称相同，但含义完全不同。

샘플링은 모델이 계산한 다음 단어 확률표에서 실제로 한 단어를 뽑는 방법이고, 온도와 top-p는 그 뽑기를 얼마나 보수적으로 할지 정하는 값이다. 그런데 최근 Claude 쪽에서는 이 값들을 아예 못 쓰게 되고 있어서, 개념과 현황을 같이 정리했다.

## 먼저 한 줄로

같은 질문을 두 번 했는데 답이 다르게 나온 적이 있다. 모델이 고장 난 게 아니라 원래 그렇게 만들어진 것이다. [LLM](#/post/ai-llm)은 글을 쓸 때 다음 토큰마다 "어떤 토큰이 얼마나 그럴듯한지" 점수를 계산하고, 그 점수를 확률로 바꾼 다음, 그 확률대로 하나를 뽑는다. 이 마지막 "뽑기"가 샘플링이다.

그래서 온도(temperature), top-p, top-k는 모델의 지식이나 똑똑함을 바꾸는 값이 아니다. 이미 계산된 확률표를 어떻게 뽑을지만 건드린다.

## 원리: 점수에서 한 단어가 나오기까지

모델이 내놓는 점수를 로짓(logit)이라고 부른다. 단어마다 하나씩 있고, 아직 확률이 아니다. 이걸 softmax라는 함수에 넣으면 합이 1인 확률이 된다. 흐름은 이렇다.

| 단계 | 하는 일 | 건드리는 값 |
|---|---|---|
| 1 | 단어마다 점수(로짓) 계산 | 모델 자체 |
| 2 | 점수를 온도로 나눈다 | temperature |
| 3 | softmax로 확률표를 만든다 | |
| 4 | 확률이 낮은 후보를 잘라낸다 | top-k, top-p |
| 5 | 남은 후보에서 확률대로 하나 뽑는다 | |

글자 하나가 아니라 토큰 단위로, 이 과정을 토큰마다 반복한다. 답 하나에 수백 번 뽑기를 하니 중간에 한 번 다르게 뽑히면 뒤 문장이 통째로 달라진다. 같은 질문에 답이 갈리는 이유가 이거다.

## 온도

온도는 2단계에서 점수를 나누는 값이다. 낮으면 점수 차이가 더 벌어져서 1등이 확률을 거의 다 가져가고, 높으면 차이가 줄어서 확률이 고르게 퍼진다. 0에 가까우면 거의 늘 1등만 뽑는다(그리디라고 부른다).

직접 숫자로 확인하려고 간단한 Python을 돌려 봤다(아래 접기). 후보 여섯 개에 점수를 `[3.0, 2.5, 1.5, 1.0, 0.5, -1.0]`로 주고 온도만 바꿨다.

| 온도 | 1등 | 2등 | 3등 | 나머지 합 |
|---|---|---|---|---|
| 0.2 | 92.4% | 7.6% | 0.1% | 0% |
| 1.0 | 48.4% | 29.4% | 10.8% | 11.5% |
| 2.0 | 32.9% | 25.6% | 15.5% | 26.0% |

온도 0.2에서는 사실상 정해진 답이고, 2.0에서는 꼴찌 후보도 4.5%쯤 뽑힌다. 내 눈으로 이 표를 보니 "온도가 높으면 창의적"이라는 말이 이해됐다. 창의적이라기보다 확률 낮은 단어를 뽑을 기회가 늘어나는 것이다.

## top-k와 top-p

온도를 높이면 가끔 말도 안 되는 단어가 뽑힌다. 그래서 꼬리를 잘라내는 장치가 따로 있다.

- top-k: 확률 높은 순으로 k개만 남기고 나머지는 버린다. k=2면 위 예시에서 1, 2등만 남는다. 단순하지만 상황과 상관없이 개수가 고정이라는 게 약점이다. 1등이 99%인 자리에도 k개를 남기고, 후보가 고만고만한 자리에서는 너무 많이 자른다.
- top-p(nucleus sampling): 확률 높은 순으로 더해 가다가 합이 p에 닿으면 거기까지만 남긴다. 후보 수가 상황에 따라 달라진다. 1등이 확신에 차 있으면 한두 개만 남고, 애매하면 여러 개가 남는다.

top-p는 Holtzman 등이 2019년 논문에서 제안했다. 초록에 따르면 확률이 가장 높은 쪽만 계속 고르면 글이 밋밋하고 반복적이 되고, 이를 피하려고 확률 분포의 "동적인 핵(nucleus)"에서만 뽑아 신뢰도 낮은 꼬리를 잘라낸다. 같은 모델이어도 디코딩 방식만으로 품질이 크게 달라진다는 것도 이 논문의 주장이다.

위 예시(온도 1.0)에서 top-p를 0.9로 하면 1~3등 합이 88.6%라 아직 0.9에 못 미쳐서 4등까지 남고, 5등과 6등은 잘린다. 남은 후보의 확률은 다시 합이 1이 되게 맞춘다.

<details>
<summary>자세한 풀이: 직접 돌려 본 코드</summary>

```python
import math, random

def softmax(logits, T=1.0):
    z = [x / T for x in logits]
    m = max(z)                       # 오버플로 방지
    e = [math.exp(x - m) for x in z]
    s = sum(e)
    return [x / s for x in e]

def top_k(p, k):
    keep = set(sorted(range(len(p)), key=lambda i: -p[i])[:k])
    q = [p[i] if i in keep else 0 for i in range(len(p))]
    s = sum(q)
    return [x / s for x in q]

def top_p(p, P):
    order = sorted(range(len(p)), key=lambda i: -p[i])
    keep, c = set(), 0
    for i in order:
        keep.add(i)
        c += p[i]
        if c >= P:
            break
    q = [p[i] if i in keep else 0 for i in range(len(p))]
    s = sum(q)
    return [x / s for x in q]

logits = [3.0, 2.5, 1.5, 1.0, 0.5, -1.0]
p = softmax(logits, 1.0)
print(top_k(p, 2))      # [0.622, 0.378, 0, 0, 0, 0]
print(top_p(p, 0.9))    # [0.509, 0.309, 0.114, 0.069, 0, 0]
```

실행 결과 온도별 확률은 T=0.2에서 `[0.924, 0.076, 0.001, 0, 0, 0]`, T=1.0에서 `[0.484, 0.294, 0.108, 0.066, 0.04, 0.009]`, T=2.0에서 `[0.329, 0.256, 0.155, 0.121, 0.094, 0.045]`였다. 온도 0.7로 먼저 줄이고 top-p 0.9를 걸면 `[0.622, 0.305, 0.073, 0, 0, 0]`이 나왔다. 즉 온도와 top-p를 같이 쓰면 효과가 겹친다.

위 코드는 개념을 보려고 만든 장난감이다.

</details>

## 언제 어떻게 조절하나

OpenAI API 참조(Chat Completions)는 temperature를 0에서 2 사이 값으로 설명한다. 0.8 같은 높은 값은 출력을 더 무작위로, 0.2 같은 낮은 값은 더 집중되고 결정적으로 만든다고 적는다. top_p는 온도의 대안이고, 0.1이면 확률 질량 상위 10%에 드는 토큰만 고려한다고 한다. 그리고 "둘 중 하나만 바꾸고 둘 다 바꾸지는 말라"고 권한다. 이유는 위에서 봤듯 둘이 같은 방향의 효과를 내서 겹치기 때문이라고 이해했다(이 이유 자체가 문서에 있는 건 아니다).

경험칙으로 흔히 말하는 건 이렇다. 이 부분은 공식 문서에서 확인한 게 아니라 일반적으로 알려진 방식이다.

| 하려는 일 | 낮게 | 높게 |
|---|---|---|
| 요약, 추출, 분류, 코드 | O | |
| 브레인스토밍, 이름 짓기, 글쓰기 | | O |
| 같은 입력에 같은 출력이 필요한 테스트 | O | |

## 흔한 오해

온도 0이면 항상 같은 답이 나온다? 거의 그렇지만 보장은 아니다. 이 부분은 직접 검증하지 못했다. 서버 쪽 계산(부동소수점 순서, 배치 처리 등) 때문에 완전히 같지 않을 수 있다는 말이 많지만, 이 글에서 출처를 열어 확인한 건 아니다.

온도를 낮추면 [할루시네이션](#/post/ai-hallucination)이 줄어든다? 그렇지 않다. 온도는 확률표를 어떻게 뽑느냐만 바꾸고 모델이 모르는 걸 알게 만들지는 못한다. 1등 후보가 틀린 답이면 낮은 온도는 그 틀린 답을 더 확실하게 내놓는다.

온도가 높으면 똑똑해진다? 아니다. 다양해질 뿐이다. 그리고 [추론 모델](#/post/ai-reasoning)처럼 긴 생각 과정을 거치는 모델에서는 이런 값이 어떻게 작동하는지가 모델마다 다르다.

## Claude는 이 값들을 없애는 중

여기서 놀랐다. 샘플링 값을 조절하는 게 당연한 줄 알았는데, Anthropic 문서의 모델 지원 중단 페이지(API parameter deprecations)를 열어 보니 `temperature`, `top_p`, `top_k`가 API 버전 `2026-10-21`에서 제거됐다고 적혀 있다. 이 버전으로 요청하면 이 값을 보낸 순간 400 오류가 난다. 문서가 권하는 대체 방법은 "빼고, 프롬프트로 모델 행동을 유도하라"는 것이다.

정리하면 이렇다.

| 상황 | 동작 (문서 기준) |
|---|---|
| API 버전 2026-10-21 | 세 값 모두 제거, 보내면 400 |
| 이전 버전 + Claude 4.7 이후 모델 | 기본값이 아닌 값을 보내면 400 |
| 이전 버전 + 그 외 모델 | 해당 문서에는 따로 적혀 있지 않았다 |

한 블로그(Enjoy Agentic Industries)는 이전 버전이 계속 동작하고 종료일은 공지된 게 없다고 쓴다. 공식 글이 아니라 2차 자료라서 참고만 했다. 같은 블로그는 Claude Sonnet 4.6 같은 이전 모델에서 낮은 온도로 결과를 안정시키던 코드는 새 버전에서 그 효과를 잃으니 이전 버전에 남겨 두라고 권한다.

내가 이해한 건, 이제 "같은 답이 나오게 해 달라"는 요구는 온도가 아니라 프롬프트나 [구조화 출력](#/post/ai-structured-output) 쪽으로 풀어야 한다는 것이다. 다른 제공사(OpenAI 등)는 위에서 본 대로 아직 이 값들을 문서에 두고 있다. 모델·제공사마다 지원이 다르니 쓰기 전에 해당 모델 문서를 확인하는 게 맞다. 모델별 차이는 [AI 모델 map](#/post/ai-models)에서 이어서 볼 수 있다. 입력이 얼마나 들어가는지 같은 다른 한도는 [컨텍스트 윈도우](#/post/ai-context-window) 글에 있다.

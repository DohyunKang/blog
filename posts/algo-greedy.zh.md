贪心算法在每一步都选择当前看起来最好的方案，且一旦做出选择就不再回退。代码通常很短，但验证这种策略是否能得到正确答案往往是解题的关键部分。

## 什么是贪心算法

也称为“贪婪算法”。维基百科将其描述为：一种在每个阶段都做出局部最优选择，且不回头重选之前决策的算法。同一篇文章中称其为动态规划的极端形式，即只保留一个子解的方式。动态规划会同时保留多个候选解进行比较，而贪心算法则只保留一个，其余全部舍弃。

因此它运行速度快，但也容易出错。例如，一直沿着数字最大的路径前进，最后可能遇到死胡同。

## 何时适用

必须同时满足以下两个条件：

| 条件 | 含义 |
| --- | --- |
| 贪心选择性质 | 即使当前做出看似最优的选择，也存在包含该选择的整体最优解 |
| 最优子结构 | 做出该选择后剩余的问题仍属于同类问题，且将各部分的最优解组合起来即可得到整体最优解 |

维基百科正文并未直接使用这些术语，而是通过“交换论证（exchange argument）”进行解释。如果在贪心解与最优解首次出现差异的点上，将最优解的选择替换为贪心选择后结果并未变差，则可通过归纳法得出贪心策略即为最优的结论。

在编程竞赛中通常不需要写出完整证明。只需确定一个排序标准，手动构造几个反例验证；若找不到反例，则按该标准提交。虽然找不到反例与严格证明并不等同，因此仍会带着一丝不安提交代码。

## 典型问题

此处仅列出题目名称及一行简要说明，不复制原题内容。

- 프로그래머스 단속카메라：给定每辆车的进入和离开位置，以最少摄像头数量确保所有车辆至少经过一次摄像头。其结构与按结束时间降序排序的会议室分配问题类似。
- 프로그래머스 큰 수 만들기：从数字字符串中删除 k 位字符，构造最大的数。这是一种从前向后保留较大数字的贪心策略。
- 프로그래머스 디스크 컨트롤러：给定任务的请求时间和耗时，使平均返回时间最小。采用优先选择短任务的贪心策略，并配合使用堆（heap）。
- 프로그래머스 구명보트：每次最多载两人，在重量限制下使用最少数量的船。

## 解题思路步骤

1. 判断是否为优化问题（求最大或最小值）。
2. 列举可能的排序标准候选项，如开始时间、结束时间、持续时间、单价等。
3. 针对每个标准手动绘制反例；对于小规模输入（3~4 个），通常能排除大部分错误策略。
4. 若某标准无法构造反例，可尝试用交换论证进一步分析。
5. 若仍不放心，可对小规模输入使用动态规划或暴力搜索进行比较验证。

会议室分配问题的正确答案是优先安排最早结束的会议。若按开始时间排序，则 (1,10) 会占用 (2,3) 和 (4,5) 两个时段；若按持续时间排序也存在反例。交换论证的思路如下：即使将最优解中的第一个会议替换为结束时间最早的会议，也不会产生冲突且会议数量不变，因此存在包含贪心选择的整体最优解。该问题在维基百科的 activity selection problem 条目中也是以相同方式讲解的。

## Python 代码

以下代码均已实际运行并验证结果正确。会议室分配问题已用随机生成的小规模输入（300 条记录）与暴力搜索结果进行了比对。

```python
def max_meetings(iv):
    iv.sort(key=lambda x: (x[1], x[0]))   # 끝나는 시각, 같으면 시작 시각
    cnt, end = 0, -1
    for s, e in iv:
        if s >= end:
            cnt += 1
            end = e
    return cnt

print(max_meetings([(1,4),(3,5),(0,6),(5,7),(3,8),(5,9),(6,10),(8,11),(8,12),(2,13),(12,14)]))  # 4
```

当结束时间相同时，需按开始时间排序，以避免处理开始和结束时间相同的会议（长度为 0）时出错。由于会议室分配类问题可能出现此类输入，因此排序标准中一并加入开始时间。

硬币问题是单位之间呈倍数关系，因此适用贪心策略。

```python
def coin_greedy(coins, k):
    cnt = 0
    for v in sorted(coins, reverse=True):
        cnt += k // v
        k %= v
    return cnt if k == 0 else -1

print(coin_greedy([500, 100, 50, 10], 1260))  # 6
```

也有很多问题需要配合使用堆。例如统计同时重叠的会议数量的会议室数量问题。

```python
import heapq

def min_rooms(iv):
    iv.sort()                      # 시작 시각순
    h = []                         # 쓰고 있는 방들의 끝나는 시각
    for s, e in iv:
        if h and h[0] <= s:
            heapq.heapreplace(h, e)   # 비는 방 재사용
        else:
            heapq.heappush(h, e)      # 새 방
    return len(h)

print(min_rooms([(0, 30), (5, 10), (15, 20)]))  # 2
```

<details>
<summary>哈夫曼编码合并成本（优先队列贪心）</summary>

持续合并最小的两个元素。维基百科也指出哈夫曼树正是以此方式构建。合并成本的总和计算如下：

```python
import heapq

def merge_cost(ws):
    h = list(ws)
    heapq.heapify(h)
    total = 0
    while len(h) > 1:
        a, b = heapq.heappop(h), heapq.heappop(h)
        total += a + b
        heapq.heappush(h, a + b)
    return total

print(merge_cost([10, 20, 30, 40]))  # 190
```

10+20=30, 30+30=60, 40+60=100，总计 190。

## 时间与空间复杂度

排序起主导作用。会议室分配问题为排序 O(n log n) + 单次遍历 O(n)，总体时间复杂度为 O(n log n)；若原地排序则空间复杂度为 O(1)（尽管 Python 的 `sort` 内部会使用辅助空间）。使用堆的问题中，每次 push/pop 操作为 O(log n)，因此同样为 O(n log n)。[阅读时间复杂度指南 → 时间复杂度与 Python 基础](#/post/algo-complexity)

## 常见误解与反例

贪心算法失效的典型例子是硬币问题。假设硬币面值为 1、4、5，要凑出金额 8：贪心策略会选取 5+1+1+1（共 4 枚），但正确答案是 4+4（仅 2 枚）。上述 `coin_greedy` 仅在面值成倍数关系时成立，对此类输入不可使用。此类问题应使用 [动态规划](#/post/algo-dp) 解决。下面的 DP 代码验证了结果为 2。

```python
def coin_dp(coins, k):
    INF = 10**9
    d = [0] + [INF] * k
    for i in range(1, k + 1):
        for v in coins:
            if i >= v:
                d[i] = min(d[i], d[i - v] + 1)
    return d[k] if d[k] < INF else -1

print(coin_dp([1, 4, 5], 8))  # 2
```

背包问题也具有类似结构：若物品可分割（分数背包），按单位重量价值从高到低选取的贪心策略是正确的；若不可分割（0-1 背包），则贪心会失败。当物品为 (重量，价值) = (10,60), (20,100), (30,120)，容量为 50 时，分数背包的最优解为 240，而 0-1 背包为 220。维基百科指出 0-1 背包问题是 NP-hard 问题。上述两个值已通过代码验证。

此外，一旦引入权重，会议室安排问题中的贪心策略也会失效。维基百科关于活动选择问题的文档也明确指出：带权重的版本不存在贪心解法，需使用动态规划求解。

常见的误解是认为“只要排序就是贪心”。排序只是工具之一，必须证明所选的排序依据才是正确的，才能称之为贪心算法。当解题时首先想到贪心策略时，最好同时检查是否存在反例或能否用动态规划解决。

还有许多算法正确使用了贪心策略。例如：戴克斯特拉算法（在无负权边的情况下）、克鲁斯卡尔和普里姆的最小生成树、哈夫曼编码，维基百科均将其列为贪心算法的范例。埃德蒙兹证明了对于具有拟阵结构的问题，贪心策略能得到最优解；此后该结论被推广至更一般的情形。

今天早上 GitHub 趋势榜(daily)上有 HKUDS/CLI-Anything。今天新增 774 颗星，仓库总共 61,363 颗(11 月 21 日上午确认)。它来自香港大学的 HKUDS 实验室，做的事情是给那些为人用鼠标设计的桌面程序(GIMP、Blender、LibreOffice 等)配上 AI 代理能用的命令行工具。我读了 README、插件目录里的 HARNESS.md,以及 CLI-Hub 元技能的 SKILL.md,没有自己跑过。

## 它是什么
CLI 就是不用鼠标，而是敲文字命令来使用程序的方式。代理本来就是读写文本的，所以比起找按钮去点，敲命令要合适得多。代理怎么挑选和调用工具，我之前整理过。[详细 → 工具调用](#/post/ai-tool-use)

CLI-Anything 分两部分。一部分是 Claude Code 插件，像 `/cli-anything ./gimp` 这样给它程序的源码目录，代理就会为这个程序做一个 CLI。另一部分是 CLI-Hub,收集了已经做好的 CLI。先 `pip install cli-anything-hub`,再 `cli-hub install gimp` 这样安装。仓库里的两个注册表文件分别登记了 79 个和 24 个。

做好的 CLI 这样用。照搬 README 的例子:用 `cli-anything-libreoffice document new -o report.json --type writer` 新建文档，用命令加标题和表格，再用 `export render output.pdf` 在没有界面的情况下调用真正的 LibreOffice 导出 PDF。任何命令加上 `--json`,结果就以 JSON 返回，代理可以直接读。不带命令运行会进入交互模式(REPL),可以一行一行地敲。

## 里面怎么做出来的
调用 `/cli-anything` 会跑 7 个阶段：分析源码、设计命令结构、实现、规划测试、编写测试、写文档、打包安装。最后还会生成一个写着这个 CLI 用法的 SKILL.md。技能就是代理需要时拿出来读的说明书。[详细 → 技能](#/post/ai-skills)

HARNESS.md 基本上就是设计文档，第一阶段挺有意思。

1. 找到 GUI 背后的引擎。界面只是外壳，真正干活的是里面的库。文档举的例子是视频编辑器 Shotcut 背后的 MLT。
2. 把每个按钮点击、每个菜单项对应到它实际调用的函数。
3. 弄清楚项目文件的格式(XML、JSON 等)。
4. 如果程序有撤销(undo),那就是命令的单位。能撤销说明操作已经拆成了一条条命令，把它们直接搬成 CLI 命令。

原则里最显眼的是一定要调用真正的程序。不用 Python 图像库去模仿 GIMP,而是生成项目文件后把渲染交给真正的应用。如果没装那个应用，测试不会跳过，而是直接算失败。还有一条说：不要因为退出码是 0 就相信导出成功了。PDF 要检查文件开头是不是 `%PDF-`,音频要检查音量是不是 0。把这些检查都算上，README 写着通过了 2,464 个测试。

## 从入门者的角度
对 PM 来说，等于多了一个问题可以问：这个程序代理能用吗？如果能用命令和 JSON 而不是界面来操作，自动化就没那么容易坏。不过 README 自己也写了局限：要有性能强的新模型才能做出像样的 CLI,没有源码的程序质量会大幅下降，一次做不完整时往往要多跑几次 `/cli-anything:refine`。

对入门开发者来说,HARNESS.md 也可以当作功能设计的练习材料来读。"先做查看的命令，再做修改的命令"这种顺序，不用代理也一样适用。和代理使用工具的另一种常见方式 MCP 对比着看，区别会更清楚。[详细 → MCP](#/post/ai-mcp)

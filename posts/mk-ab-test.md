A/B 시험은 같은 걸 두 가지 모양으로 만들어 무작위로 나눠 보여 주고, 어느 쪽 반응이 더 좋은지 숫자로 가리는 방법이다. 썸네일이나 카피를 고를 때 "느낌상 이게 낫다"를 숫자로 바꿔 준다.

## 뭘 하는 건지

두 버전을 만든다. A는 지금 쓰던 것(대조군), B는 바꿔 본 것이다. 방문자나 시청자를 무작위로 반반 나눠 한쪽엔 A, 다른 쪽엔 B를 보여 준다. 그다음 같은 기간 동안 클릭률(CTR)이나 가입률 같은 지표를 비교한다.

무작위로 나누는 게 핵심이다. A를 월요일에, B를 금요일에 올리고 비교하면 요일 차이가 섞여서 뭐 때문에 달라졌는지 알 수 없다. 같은 시간대에 동시에 나눠 보여 줘야 두 그룹의 차이가 버전 하나로 좁혀진다.

## 실험 설계: 시작 전에 정할 것

시작 전에 네 가지를 정해 둔다.

| 항목 | 예시 | 비고 |
|---|---|---|
| 가설 | 숫자를 넣은 제목이 클릭률을 올린다 | 한 번에 바꾸는 건 하나만 |
| 주 지표 | 썸네일 클릭률 | 하나만 정한다 |
| 최소로 잡고 싶은 차이 | 3% → 3.6% | 이보다 작은 차이는 포기 |
| 표본 크기 | 그룹당 약 1만 4천 노출 | 시작 전에 계산 |

한 번에 하나만 바꾸라는 말은 썸네일 색과 문구를 같이 바꾸면 뭐가 먹혔는지 모르기 때문이다. 여러 요소를 동시에 보고 싶으면 다변량 시험이라는 별도 방법이 있는데, 필요한 표본이 훨씬 늘어난다.

## 표본 크기와 지표

표본이 작으면 우연히 한쪽이 앞서 보일 수 있다. 그래서 "얼마나 모아야 믿을 수 있나"를 미리 계산한다. Evan Miller의 글에 나오는 어림 공식이 있다. 그룹당 표본 n ≈ 16σ²/δ², 여기서 δ는 잡아내고 싶은 최소 차이이고 비율 지표는 σ² = p(1−p)로 쓴다.

내가 이해한 감각은 이렇다. 차이가 절반으로 줄면 필요한 표본은 네 배가 된다. 클릭률 3%에서 0.6%p 차이를 잡으려면 위 공식으로 그룹당 약 1만 3천 명이 나온다. 같은 기준에서 1.5%p 차이면 몇천 명이면 된다. 작은 차이를 잡으려는 시험은 트래픽이 적은 곳에서는 사실상 못 한다.

아래 두 값이 시험을 읽을 때 따라붙는다.

- 유의수준(α, 보통 0.05): 실제로는 차이가 없는데 있다고 잘못 말할 확률의 상한.
- 검정력(보통 0.8): 실제로 차이가 있을 때 그걸 잡아낼 확률.

p값은 "두 버전이 실제로 같다고 가정했을 때 지금 같은 차이가 우연히 나올 확률"이다. B가 더 좋을 확률이 아니다. 이 부분이 제일 많이 헷갈린다.

## 자동화하는 방법

마케팅 자동화 쪽에서는 보통 이런 순서로 돌린다.

1. [LLM](#/post/ai-llm)이나 이미지 생성 모델로 카피·썸네일 후보를 몇 개 뽑는다.
2. 후보를 노출 시스템에 올리고, 노출을 무작위로 배분한다.
3. 클릭·전환 로그를 쌓는다.
4. 미리 정한 표본에 도달하면 검정을 한 번 돌려 승자를 고른다.
5. 승자를 기본값으로 바꾸고 다음 가설로 넘어간다.

후보를 만드는 건 자동화가 쉽다. 어려운 쪽은 4번에서 "정해 둔 표본까지 기다리는" 규칙을 코드로 막아 두는 것이다. 결과를 모아 한눈에 보는 건 [대시보드](#/post/mk-dashboard) 글에서 다루고, 어떤 소재를 시험할지는 [콘텐츠 캘린더](#/post/mk-content-calendar)나 [트렌드 수집](#/post/mk-trend-collect)과 이어진다.

유튜브에는 썸네일·제목 시험 기능이 따로 있다고 알려져 있지만, 이번에 공식 도움말을 열어 보지는 않았다.

## 흔한 오류

중간에 결과를 훔쳐보고 멈추는 것(peeking)이 가장 흔하다. Evan Miller는 유의 수준을 보고 중간에 멈추면 보고되는 유의수준이 틀어진다고 쓴다. 열 번 보고 1%로 보이는 값이 실제로는 약 5%라는 예를 든다. 직접 확인해 봤다. 두 버전의 실제 전환율을 똑같이(3%) 두고 각 5천 명씩 모은 가짜 시험을 1,500번 돌렸다.

| 방식 | "차이 있음"으로 잘못 나온 비율 |
|---|---|
| 끝에서 한 번만 검정 | 약 5% |
| 10번 나눠서 보다가 유의하면 멈춤 | 약 21% |

차이가 없는데 다섯 번 중 한 번은 "승자가 나왔다"고 하게 된다. 기다리기 싫을 때 쓰는 방법으로 순차 검정이나 베이지안 방법이 있고, 중간 확인 시점을 미리 정해 두면 멈춰도 된다고 Miller의 글은 말한다.

그 밖에 자주 나오는 것들.

- 여러 개를 한꺼번에 비교: 5개 변형을 각각 α=0.05로 검정하면 하나라도 잘못 유의하게 나올 확률이 1−0.95⁵ ≈ 23%다. 위키피디아의 다중 비교 문제 설명대로 가장 단순한 보정은 α를 개수로 나누는 본페로니 방법이고(5개면 0.01), 보수적이라 더 나은 방법으로 Holm 보정이 있다.
- 지표를 시험 끝나고 고르기: 클릭률이 안 나오면 체류 시간을 보고, 그것도 안 나오면 다른 걸 보는 식이다. 이것도 다중 비교다. 주 지표는 시작 전에 하나로 박는다.
- 짧은 기간만 보기: 요일·시간대 차이가 있어서 최소 한 주 단위로 돌리는 게 안전하다고 알려져 있다. 이건 내가 공식 출처로 확인하진 못했다.
- 신기함 효과: 새 썸네일이 처음엔 눈에 띄어서 잠깐 반응이 높다가 가라앉을 수 있다.
- 작은 차이를 큰 의미로 읽기: 유의하다는 것과 쓸 만큼 크다는 것은 다르다. 표본이 아주 크면 0.01%p 차이도 유의하게 나온다.

## 흔한 오해

- p값이 0.05보다 작으면 B가 낫다는 게 확정이다: 유의수준 5%면 차이가 없어도 20번 중 1번은 이렇게 나온다. 한 번의 시험은 증거 하나일 뿐이다.
- 표본이 많을수록 무조건 좋다: 그만큼 오래 걸리고, 시험하는 동안 나쁜 버전에 노출이 반이 가는 비용이 있다.
- 유의하지 않으면 둘이 같다: 아니다. 차이를 못 잡은 것일 수 있다. 표본이 모자랐는지 먼저 본다.

<summary>자세한 풀이: 그룹당 표본 크기 계산식과 파이썬 코드</summary>

두 비율 p1, p2를 비교하는 표준 근사식이다. 코드는 직접 실행해서 아래 숫자를 확인했다.

```python
import math
from statistics import NormalDist
N = NormalDist()

def n_per_group(p1, p2, alpha=0.05, power=0.8):
    za = N.inv_cdf(1 - alpha / 2)
    zb = N.inv_cdf(power)
    pb = (p1 + p2) / 2
    n = (za * math.sqrt(2 * pb * (1 - pb))
         + zb * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2 / (p1 - p2) ** 2
    return math.ceil(n)

print(n_per_group(0.03, 0.036))  # 13914
print(n_per_group(0.03, 0.045))  # 2518
```

3% → 3.6%를 잡으려면 그룹당 13,914, 3% → 4.5%면 2,518이 나왔다. Miller의 어림식(16σ²/δ²)은 같은 조건에서 약 12,933으로, 정확한 식과 7% 정도 차이가 났다. 어림식은 대략의 감을 잡는 용도다.

결과 읽기는 두 비율 z 검정이다.

```python
def ztest(c1, n1, c2, n2):
    p = (c1 + c2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    z = (c2 / n2 - c1 / n1) / se
    return 2 * (1 - N.cdf(abs(z)))

print(ztest(150, 5000, 185, 5000))  # 약 0.052
```

5천 명씩 보여 줘서 A 150클릭(3.0%), B 185클릭(3.7%)이 나왔는데 p는 0.052로 겨우 5%선을 못 넘었다. 이 시험은 "B가 낫다"로 말하기엔 애매하고, 표본을 더 모으려면 처음부터 계획했어야 한다.

peeking 시뮬레이션은 같은 3%인 두 그룹에서 각 5,000명을 뽑고, 500명 단위로 10번 검정해서 한 번이라도 p<0.05면 "승자 있음"으로 세었다. 1,500번 반복해서 약 21%, 끝에서 한 번만 검정하면 약 5%였다. 시드와 반복 수에 따라 몇 %p는 흔들린다.

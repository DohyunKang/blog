## どういうものか
スキルは、エージェントが必要なときに取り出して読む説明書だ。[詳しく → スキル](#/post/ai-skills) このリポジトリはそれを 83 個まとめている。スラッシュコマンドは 15 個。名前を呼んで使うのではなく、「この対象を点検している」のようにやっていることを話すと、テーマに合うスキルが自動で付く、と書いてある。

README の分類はだいたいこう。

1. Web の脆弱性の種類ごとの hunt-* スキルが 58 個。HackerOne で公開された報告 681 件からパターンを抜き出して作ったそうだ。
2. M365、Okta、VPN 機器など企業向けプラットフォームのスキルが 10 個。
3. 見つけたものを検証してレポートにするスキルが 6 個。
4. 偵察と公開情報収集のスキルが 5 個、方法論のスキルが 4 個。

インストールは Claude Code の中で `/plugin marketplace add` と `/plugin install` の 2 行。スキルのファイル形式が共通なので、OpenCode や Codex CLI など他のエージェントツールにもコピーして入れられるらしい。ただしスラッシュコマンドと自動実行エンジンは Claude Code 専用。

## 中でどう動くのか
流れは scope → recon → rank → hunt → validate → report。範囲を決めて、対象を調べて、どこから見るか順位を付けて、探して、検証して、レポートを書く。

目を引いたのは役割分担だ。engine.py 冒頭の説明には、範囲チェック、状態の保存、作業の振り分け、順位付け、重複除去、レポート整理は決まったコードでやり、モデルは偵察・探索・検証にだけ使うと書いてある。範囲外のホストは偵察結果からコードが除き、範囲外の対象にはエージェントをそもそも送らない。モデルに「範囲外は触らないで」と頼むのではなく、コードが止める作りだ。状態はステップごとに保存されるので、途中で止まっても続きから回せる。

もうひとつは 7-Question Gate。レポートを書く前に 7 つの質問を順に聞き、ひとつでも答えられなければその発見は捨てる。最初の質問は「攻撃者が今これを手順どおりに使えるか」で、範囲内か、プログラムが認める被害の種類かも聞く。文書にはこの関門が弾いた誤検知の例がある。応答に自分の入力が見えたが、実はそのページが URL をそのまま返しているだけだった、ステータスコードだけ変わって本文はまったく同じだった、といったケースだ。モデルがそれらしいものを見つけたと言い張るのを防ぐ仕組みと言える。

## 自分で測った数字はまだ弱い
eval フォルダには、スキルをオンにしたときとオフにしたときを同じ課題で比べる仕組みがある。前に見た SkillEvaluator と同じ考え方だ。[詳しく → SkillEvaluator](#/post/news-261119-a) ただ BASELINE.md の最新結果(8月25日)は、練習用のわざと脆弱なサイト OWASP Juice Shop の課題 3 つだけで、オンでもオフでも 3 つとも解けた。オンのほうがむしろターン数と費用が少し多かった。作者自身、この課題はモデルが覚えているほど簡単なのでスキルの効果は測れないと書いている。もっと難しい課題(PortSwigger の演習)はアカウントの都合でまだ回せていないそうだ。つまり「スキルを入れるとよく見つかる」は、このリポジトリの中ではまだ数字で確かめられていない。

## 入門者の立場から
まずはっきりさせておくと、これは自分のもの、または書面で許可を得た対象にだけ使うためのツールだ。README もそう書いているし、許可なく他人のサービスに使えば違法になる。

それを除いて PM の立場で見るべきは構造だと思う。間違えると大ごとになる部分(範囲、状態、重複)はコードに任せ、判断が要る部分だけモデルに渡す。そしてモデルの出した結果を質問リストでもう一度ふるいにかける。セキュリティ以外の業務自動化にもそのまま使える型だ。守る側の似たツールとしては OpenAI の Codex Security を前に見た。[詳しく → Codex Security](#/post/news-261113-a)

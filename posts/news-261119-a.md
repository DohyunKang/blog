오늘 아침 GitHub 트렌딩(daily)에 NVIDIA/SkillEvaluator가 올라와 있었다. 오늘 별 323개, 레포 전체 별은 3,705개다(11월 19일 오전 확인). 코딩 에이전트용 스킬이나 플러그인을 넣으면 형식과 보안을 검사하고, 마지막엔 "이 스킬을 넣었을 때 에이전트가 실제로 일을 더 잘하냐"를 숫자로 재 주는 도구다. 나는 README, `docs/` 아래 문서 몇 개, arXiv 초록을 읽었고 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
스킬은 에이전트가 필요할 때 꺼내 읽는 설명서 폴더다. SKILL.md 하나에 지시와 예시, 보조 스크립트가 붙는다. [자세히 → 스킬](#/post/ai-skills) 요즘 스킬 모음 레포가 트렌딩에 자주 뜨는데, 막상 그 스킬이 도움이 되는지는 써 본 사람 감으로만 판단하고 있었다. SkillEvaluator는 그걸 세 단계로 나눠 검사한다.

1. 1단계(검증): 형식, 버전, 개인정보, 라이선스, 숨은 유니코드 문자, 비밀키 노출, 스크립트 보안 같은 정적 검사. README 기준 500개 넘는 규칙과 탐지 패턴이 들어 있고 모델 키 없이 돈다. 품질 점수는 100점 만점, 기본 통과선은 70점.
2. 2단계(중복): 임베딩으로 스킬 안의 지시가 서로 겹치는지, 다른 스킬과 겹치는지 본다. 임베딩은 글의 뜻을 숫자 벡터로 바꿔 가까운 정도를 재는 방법이다.
3. 3단계(실전 평가): 같은 과제를 Docker 샌드박스에서 스킬 있이 한 번, 없이 한 번 에이전트에게 시킨다. 그 차이가 Skill Lift다.

1단계 안에 Harness Check라는 게 따로 있는 게 재밌었다. Claude Code, Codex, OpenCode, Copilot CLI 같은 에이전트마다 스킬을 읽는 폴더 위치와 설명 길이 제한이 다르다. 그래서 "설명이 1,024 길이 제한을 4 넘어서 Copilot CLI에선 아예 안 읽힘" 같은 걸 에이전트를 돌리지 않고 알려 준다. 스킬이 안 먹는 이유가 내용이 아니라 이런 데 있을 때가 꽤 있을 것 같다.

## Skill Lift는 어떻게 재는지
3단계는 시도 하나마다 여섯 개 신호를 0~1로 매긴다. 보안, 스킬을 제대로 찾아 썼는지(skill_execution), 스킬을 효율적으로 썼는지, 정답과 맞는지(accuracy), 목표를 이뤘는지(goal_accuracy), 해야 할 행동을 했는지(behavior_check). 토큰 효율은 보고만 하고 점수엔 안 넣는다. 일부는 LLM이 채점자 역할을 하는 방식이다. [자세히 → 평가(Evals)](#/post/ai-evals)

공식은 단순하다. `Skill Lift = 스킬 있을 때 총점 - 스킬 없을 때 총점`. 대신 두 쪽이 모두 돈 과제와 모두 채점된 신호만 비교한다. +0.05 이상이면 PASS, -0.10 이하면 FAIL, 그 사이는 NEUTRAL이다. 과제 수가 적으면 결과가 흔들리니 과제 단위로 다시 뽑는 부트스트랩으로 95% 구간도 같이 낸다. 과제가 하나뿐이면 구간을 안 낸다. 폭이 0인 구간이 확정된 결과처럼 보일까 봐 그렇다고 적혀 있다.

문서에 "아직 확인되지 않은 것"이라는 절이 따로 있는 게 좋았다. 사람 채점과 얼마나 일치하는지 연구한 적 없음, 통과선 0.50이나 lift 구간 같은 숫자는 근거 있는 값이 아니라 정해 둔 관례임, 그리고 비교가 "스킬 vs 스킬 없음"이라 스킬 내용 덕분인지 지시가 하나 더 붙은 덕분인지 구분이 안 됨. 마지막 건 나도 읽으면서 궁금했던 부분이다.

## 논문에서 나온 숫자
같은 방법을 정리한 논문(arXiv 2608.20614, 8월 제출)이 있다. 초록에 따르면 실제 스킬 145개에서 구조 검사 점수와 LLM 채점 점수의 상관이 0.14로 낮았다. 정적 검사와 실제 효과는 서로 다른 걸 본다는 뜻이다. 실서비스 스킬 58개, 짝지은 과제 947개에서 평균 Skill Lift는 0.2134였고 72.8%의 과제에서 lift가 양수였다. 차이가 가장 큰 건 정답률보다 스킬을 찾아 쓰고 순서를 따르는 쪽이었다고 한다. 이건 문서만 읽어서는 볼 수 없는 부분이라는 게 논문의 주장이다.

## 왜 지금 화제인지
레포는 6월에 만들어졌는데 릴리스가 몰려 있다. v0.9.0이 11월 13일, v1.0.0이 11월 17일, v1.0.1이 11월 18일(모두 UTC)에 나왔고 커밋도 11월 16~18일에 50개 가까이 찍혔다. X에서 "SkillEvaluator"가 들어간 글(리트윗 제외)은 11월 12일 7건, 15일 37건, 16일 149건, 17일 92건, 18일 39건(UTC 하루 단위)이었다. 1.0 출시 전후로 늘어난 건 맞는데, 정확한 계기는 확인 못 함. Reddit 반응도 확인 못 함. README에 YouTube 라이브 방송 링크가 있지만 보지는 않았다.

## 입문자 입장에서
PM 입장에선 "스킬을 넣으면 좋아지겠지"를 "넣고 안 넣고를 같은 과제로 비교해 봤다"로 바꾸는 틀이 쓸 만하다. A/B 테스트를 에이전트 설명서에 거는 셈이다. 과제 10개 미만이면 충분하지 않다고 보는 기본값도 기준으로 삼을 만하다.

개발 입문자라면 1단계만 먼저 써 보는 게 부담이 적다. `pip install skillevaluator` 후 `skillevaluator quality-check ./my-skill`은 키, GPU, Docker 없이 돈다. `harness-check`도 마찬가지다. 3단계는 모델 키와 Docker가 필요하고 모델 사용료가 나올 수 있다고 적혀 있다. 지원 수준은 Experimental, NVIDIA 공식 지원은 없다. 이미 써 본 스킬 모음 얘기는 예전 글과 같이 보면 좋다.

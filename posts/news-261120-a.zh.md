今天早上 GitHub 趋势榜(daily)上有 mvanhorn/last30days-skill。今天新增 952 星，总共 70,777 星(11月20日早上确认)。给它一个话题，它会从 Reddit、X、YouTube、Hacker News、GitHub 等地方一次性找出最近30天的帖子，按人们实际的反应排序、归组并总结。这是一个代理技能。我读了 README、CONCEPTS.md、CONFIGURATION.md 的一部分和 CHANGELOG,没有自己跑过。

## 这是什么
技能是代理需要时拿出来读的说明书文件夹。[详细 → 技能](#/post/ai-skills) 在 Claude Code 里用 `/last30days 话题` 调用，也能用 `npx skills add` 装进 Codex、Cursor 等其他代理。作者写道，他做这个是为了跟上 AI 圈的动态。模型的训练数据总是晚几个月，新的窍门先在 Reddit 和 X 上流传。

README 的主张用一句话说是这样：搜索引擎收集的是编辑过的文章，这个收集的是人的反应。所以排序时用 Reddit 的赞、X 的点赞、YouTube 字幕内容、Polymarket 赔率这类参与信号。Polymarket 是给事件结果押钱的预测市场，赔率就是人们给出的概率。

## 里面怎么运转
结构分成两部分。SKILL.md 是告诉模型用什么参数调用引擎的说明书，真正的搜索由 Python 引擎 `scripts/last30days.py` 完成。引擎按固定格式输出结果，模型照原样接过来再总结。

1. 从话题里取出核心对象。像"某某 价格"这样的话题，会去掉"价格"只留某某。先找好这个对象的 X 账号、GitHub 仓库、子版块和 YouTube 频道。
2. 把问题拆成几个子查询，对每个来源分别同时搜索。
3. 同一个帖子出现在多个搜索里时，按规范化后的 URL 合并成一条。不同平台在说同一件事时，归成一个簇。
4. 没提到对象名字的帖子，反应再大也会被大幅降权。剩下的按参与度、相关度、新鲜度排序。
5. 模型按簇附上出处，写成一份简报。

第4步挺有意思。文档里叫 Entity grounding,只看对象名字的第一个词。后面的词大多是搜索修饰语，全都要求的话会把对题的帖子也筛掉。反过来，如果对象是 "ai"、"new" 这种常见词，就提高门槛，不让无关的爆款帖子占位置。

相关度要不要用 LLM 判断可以自己选。放入 OpenAI、xAI、Gemini 等的密钥后，它会把话题和找到的帖子片段发给那个模型重新排序，也就是重排序。没有密钥就退回本地打分。文档写着不用密钥 Reddit、HN、Polymarket、GitHub 也能直接用。拿检索到的帖子当依据来写答案，这一点和 RAG 的流程很像。[详细 → RAG](#/post/ai-rag)

还有不给话题也能跑的 Discovery 模式，自己找最近在涨的东西。只展示在多个来源同时出现、或者在一个地方涨得特别猛的话题。过不了门槛就不硬凑，而是回答"没有确定的东西"。文档把这一条写成了原则，我觉得不错。

## 从入门者的角度
对 PM 来说，它把以前一个个开标签页手动去查"大家现在怎么聊这个"的活一次汇总起来。例子有开会前了解对方、做功能前找人们遇到的问题。不过排序标准是反应多少，声音大的帖子不一定是对的。简报当起点用，原文还是另外打开看比较好。

如果是开发入门者，可以先注意每个来源的认证方式都不一样。X 默认优先走读取浏览器已登录会话 Cookie 的路径，用 API 密钥的路径排在后面。读 Cookie 之前会征求同意，也可以用 `--no-browser-cookies` 关掉。对于使用 Reddit 登录会话的选项，文档自己写着可能违反 Reddit 的条款。运行前可以先用 `--preflight` 确认它会读写什么，这点也值得参考。其他技能合集可以和以前的文章一起看。[详细 → 常用 Claude 技能合集](#/post/claude-popular-skills)

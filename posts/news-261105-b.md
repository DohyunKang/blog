## 어떤 문제를 푸나

코딩 에이전트를 둘 이상 동시에 돌리면 각자 다른 작업 폴더가 필요하다. 같은 폴더에서 같이 파일을 고치면 서로 덮어쓰기 때문이다. git에는 이 용도의 `git worktree`가 이미 있다. 한 저장소에서 브랜치별로 폴더를 따로 만들어 주는 기능이다.

다만 쓰기가 번거롭다. 프로젝트 사이트는 새 worktree 하나를 만들려면 브랜치 이름을 세 번 쳐야 한다고 설명한다. `git worktree add -b feat ../repo.feat`로 만들고, 그다음 `cd ../repo.feat`로 들어가는 식이다. Worktrunk는 worktree를 "브랜치만큼 쉽게" 다루는 걸 목표로 한다. worktree를 브랜치 이름으로 가리키고, 폴더 경로는 설정 가능한 템플릿으로 계산한다.

## 명령 몇 가지

README와 사이트에 나오는 명령은 이렇다.

| 명령 | 하는 일 |
|---|---|
| `wt switch --create feature-auth` | 브랜치와 worktree를 만들고 그 폴더로 이동 |
| `wt switch -x claude -c feature-a -- 'Add user authentication'` | worktree를 만들고 거기서 바로 `claude`를 실행 |
| `wt list` | worktree 목록과 상태 (`--full`이면 CI 상태와 AI가 만든 요약까지) |
| `wt step commit` | 스테이징한 변경을 커밋. LLM으로 커밋 메시지를 만들 수도 있음 |
| `wt merge main` | squash, rebase, merge, 정리를 한 번에 |
| `wt remove` | 머지가 끝난 worktree 삭제 |
| `wt switch pr:123` | PR 브랜치를 체크아웃 |

두 번째 줄이 이 도구의 용도를 잘 보여 준다. 에이전트마다 `-x`로 worktree를 하나씩 열면, 한 저장소에서 기능 A, B, C를 각자 다른 에이전트에 맡기는 구성이 명령 세 줄로 끝난다.

## 설치와 설정

설치는 Homebrew(`brew install worktrunk && wt config shell install`), Cargo, conda/pixi, Arch Linux 패키지가 README에 있다. Windows는 `winget install max-sixty.worktrunk`이고, Windows Terminal의 `wt`와 이름이 겹치지 않도록 `git-wt`라는 이름으로 설치된다고 한다. 폴더 이동을 하려면 셸 통합(`wt config shell install`)이 필요하다.

그 밖에 README가 언급하는 기능은 다음과 같다.

- 훅: worktree를 만들 때, 머지 전후 같은 시점에 명령을 실행한다. 만든 직후(post-start) 의존성 설치나 개발 서버 실행을 걸어 두라고 권한다.
- `hash_port` 템플릿 필터: worktree마다 개발 서버 포트를 다르게 잡는 용도.
- `target/`, `node_modules/` 같은 빌드 캐시를 APFS, btrfs, XFS에서 copy-on-write로 공유.

## 써 볼 때 생각할 점

worktree를 나눠도 같은 파일을 두 에이전트가 고치면 머지 때 충돌이 난다. 도구가 줄여 주는 건 폴더를 만들고 정리하는 번거로움이고, 작업을 어떻게 쪼갤지는 여전히 사람 몫이다. 위 내용은 README와 사이트에 적힌 설명 기준이며, 기본 경로 템플릿과 훅 종류 전체는 이 글에 쓰지 않았다.

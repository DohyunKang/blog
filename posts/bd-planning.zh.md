在大数据分析师笔试目录中，“数据分析计划”分为两部分：分析方案制定（包括分析路线图设定、分析问题定义、数据分析方案）与分析工作计划（包括数据获取计划、分析流程及作业计划）。由于这是在开始分析之前决定解决什么问题、按什么顺序进行以及如何处理和规避风险与数据的阶段，因此考试更侧重考察术语和顺序，而非计算问题。具体的考试时间与报名费用可在官方网站查询。本文主要围绕各单元的核心概念、选项中容易混淆的知识点以及解题思路进行了整理。

如果先看过 ADsP（数据分析计划），会发现内容有很多重叠。关于任务发掘与优先级，详见 [详细 → 分析任务与主计划](#/post/adsp-task-masterplan)；关于方法论整体，详见 [详细 → 分析方法论](#/post/adsp-methodology)。本文则是按照大数据分析师笔试目录重新调整了顺序。

## 一览无余

| 部分 | 考察内容 | 关键词 |
|---|---|---|
| 分析问题定义 | 要解决什么任务 | 自下而上、自上而下、用例 |
| 分析路线图 | 按什么顺序进行 | 紧迫性、难度、三阶段实施 |
| 分析流程 | 分哪些步骤推进 | 方法论五步、任务、产出物 |
| 数据获取计划 | 如何获取所需数据 | 需求数据定义、收集、一致性 |
| 风险计划 | 出现问题怎么办 | 识别、规避·转移·缓解·接受 |

## 分析问题定义

寻找任务的方式主要有两种。

| | 自上而下 | 自下而上 |
|---|---|---|
| 出发点 | 已有待解决的问题 | 未知问题，从数据入手 |
| 适用场景 | 分析对象明确时 | 寻求新洞察时 |
| 流程 | 问题探索 → 问题定义 → 解决方案探索 → 可行性审查 | 假设生成 → 实验 → 实际环境测试 → 假设验证 |

自上而下法可将问题探索分为基于商业模型和基于外部参考模型两类。

在分析规划阶段，需提前评估的三个要素为：可用数据、合适的用例以及障碍因素。其中障碍因素包括成本、准确度、组织能力和变革管理。

<details>
<summary>四种解决方案：现有系统与分析能力的组合</summary>

解决任务的方法取决于是否存在现有系统以及是否具备分析能力。

| 现有系统 | 分析能力 | 方向 |
|---|---|---|
| 有 | 有 | 利用现有系统与人员 |
| 有 | 无 | 培训或招聘 |
| 无 | 有 | 升级系统 |
| 无 | 无 | 外包给专业厂商 |

</details>

## 分析路线图：确定顺序

由于不能一次性处理所有任务，因此需要确定优先级。考虑的因素包括战略重要性、业务成果（ROI）和可执行性。若以这两个维度为轴，则对应紧迫性和难度。

| 轴 | 观察内容 | ROI 视角 |
|---|---|---|
| 紧迫性 | 与战略目标关联度、KPI 目标价值；当前需要还是未来需要 | 业务效果 |
| 难度 | 数据获取·存储·加工成本、分析应用成本、分析水平 | 投资成本 |

将两个轴相乘，可得到四个象限。

| 紧迫性 | 难度 | 顺序 |
|---|---|---|
| 当前 | 简单 | 最先执行 |
| 当前 | 困难 | 若优先考虑紧迫性则为第二顺位 |
| 未来 | 简单 | 若优先考虑难度则为第二顺位 |
| 未来 | 困难 | 最后执行 |

中间两个象限的顺序取决于优先关注紧迫性还是难度。由于每个资料对四象限的编号（Ⅰ~Ⅳ）可能不同，因此建议通过“紧迫性”和“难度”这两个属性来记忆，而非死记硬背编号。对于当前需要但难度高的任务，也可通过减少数据量或缩小分析范围来降低难度后优先实施。

若将上述顺序规则用 pandas 实现，效果如下所示（基于紧迫性优先原则，并已通过实际运行验证）：

```python
import pandas as pd

tasks = pd.DataFrame({
    "과제": ["이탈 예측", "재고 수요 예측", "고객 군집", "챗봇 로그 분석"],
    "시급성": ["미래", "현재", "미래", "현재"],
    "난이도": ["어려움", "어려움", "쉬움", "쉬움"],
})

# 시급성 우선: 현재가 먼저, 같으면 쉬운 것이 먼저
tasks["u"] = tasks["시급성"].map({"현재": 0, "미래": 1})
tasks["d"] = tasks["난이도"].map({"쉬움": 0, "어려움": 1})
tasks = tasks.sort_values(["u", "d"]).drop(columns=["u", "d"]).reset_index(drop=True)
tasks.index += 1
print(tasks)
```

执行结果如下：

```
         과제 시급성  난이도
1  챗봇 로그 분석  현재   쉬움
2  재고 수요 예측  현재  어려움
3     고객 군집  미래   쉬움
4     이탈 예측  미래  어려움
```

若要改为以难度为优先标准，只需在排序键中交换 u 和 d 的位置即可。虽然考试中不会出现代码，但理解排序键的顺序对应两个轴的优先级，就能轻松明白为何中间两个象限的顺序会发生变化。

路线图通常分为三个阶段实施：

| 阶段 | 内容 |
|---|---|
| 1. 引入数据分析体系 | 发掘分析机会、定义任务、制定路线图 |
| 2. 验证数据分析有效性 | 设计分析算法、架构设计、执行试点项目 |
| 3. 推广与深化数据分析 | 变革管理、系统构建、相关系统升级 |

在确定应用范围和方式时，需考虑业务内化程度、分析数据应用范围（仅使用内部数据还是扩展至外部及非结构化数据）以及技术应用程度（利用现有技术还是引入新技术）。详细的执行计划具有反复打磨的特性，因此通常采用混合模式：数据收集与准备按顺序进行，而建模阶段则进行迭代。

访问方式也分为两类：任务导向型侧重于 Speed & Test、Quick-Win 和 Problem Solving；主计划型侧重于 Accuracy & Deploy、Long Term View 和 Problem Definition。由于两者的关键词容易混淆，建议将左侧三个归为“快速”类，右侧三个归为“长期”类以便区分。

## 分析流程：五步方法论

在分析工作计划中，分析流程按方法论的五个阶段处理。层级顺序为：阶段 (Phase) → 任务 (Task) → 步骤 (Step)。阶段用于产出成果，任务是构成阶段的单元活动，步骤则由输入、处理和输出组成的单元过程构成。

| 序号 | 阶段 | 主要任务 | 主要产出物 |
|---|---|---|---|
| 1 | 分析策划 | 业务理解及范围设定、项目定义及计划制定、项目风险计划制定 | 项目工作说明书 (SOW)、项目计划书 |
| 2 | 数据准备 | 所需数据定义、数据存储设计、数据收集及一致性检查 | 数据定义书、数据存储 |
| 3 | 数据分析 | 分析用数据准备、文本分析、探索性分析、建模、模型评估与验证 | 分析数据集、模型评估报告 |
| 4 | 系统实现 | 设计与实现、系统测试及运营 | 系统设计书、操作手册 |
| 5 | 评估与部署 | 模型演进计划制定、项目评估及报告 | 模型演进计划书、最终报告 |

分析策划排在最前，且在数据准备之前。系统实现在评估与部署之前。各阶段以基线 (baseline) 为准进行版本控制。若单独查看分析策划阶段内的任务与步骤，情况如下：

| 任务 | 步骤 |
|---|---|
| 业务理解及范围设定 | 业务理解 → 项目范围设定 (编写 SOW) |
| 项目定义及计划制定 | 数据分析项目定义 → 项目执行计划制定 |
| 项目风险计划制定 | 数据分析风险识别 → 风险应对计划制定 |

可参考 [详情 → 分析方法论](#/post/adsp-methodology) 将 CRISP-DM 或 KDD 等其他方法论进行对比。

## 数据获取计划

目录中，数据获取计划位于分析工作计划之下，旨在确定如何获取所需数据。若将其移至五步方法论中，则对应第 2 阶段“数据准备”的任务：所需数据定义、数据存储设计、数据收集及一致性检查。因此，将所需数据定义和数据存储设计列为分析策划阶段任务的选项是错误的。数据获取计划在分析策划中制定，但实际执行所需数据定义和存储设计的任务属于数据准备阶段。

采集方式（抓取、ETL、API、日志采集）和存储库将在下一单元 [详情 → 数据采集与存储](#/post/bd-collection-storage) 中单独讨论。

## 风险计划

项目风险计划制定任务包含两个步骤：首先识别数据分析风险，随后制定应对计划。应对措施有四种：

| 应对 | 含义 |
|---|---|
| 规避 (Avoid) | 消除或避开风险因素本身 |
| 转移 (Transfer) | 将因风险产生的责任或影响转嫁给第三方 |
| 减轻 (Mitigate) | 降低风险发生的可能性或影响 |
| 接受 (Accept) | 承担风险并照单全收 |

管理 (Management) 并非应对方法的类型。若选项中包含“风险管理”作为应对措施，则为错误选项。

<details>
<summary>应对方式配对练习：示例情境</summary>

通过构建一个情境并将其与四种应对方式匹配，可以更快速地区分它们。以下仅为示例，与考试题目无关。

| 风险 | 应对 | 原因 |
|---|---|---|
| 包含个人信息的混合数据 | 规避 | 完全不使用该数据 |
| 数据加载可能延迟 | 减轻 | 预留时间缓冲，先部分加载数据 |
| 模型准确率可能未达目标 | 接受 | 照常推进并汇报结果 |
| 分析人力不足 | 转移 | 委托给外部公司 |

</details>

## WBS 在哪里使用

工作分解结构（WBS）是在项目定义与计划制定阶段的项目执行计划编制步骤中编写的。它与进度、人力和预算计划一同制定。方法论中的步骤对应于 WBS 的工作包。定义分析主题或制定建模方案不属于编写 WBS 的步骤。

## 常见错误选项

- 将必要数据定义或数据存储设计误认为是分析规划阶段的任务，实际上属于数据准备阶段。
- 在风险应对方法选项中混入了“管理”。风险应对包括四种策略：规避、转移、减轻和接受。
- 混淆了任务导向与主计划的关键术语。
- 仅凭四象限编号死记硬背紧迫性与难度两个维度的顺序，导致不同资料间出现差异。
- 打乱了自上而下四阶段的顺序。正确顺序为：问题探索、问题定义、解决方案探索、可行性审查。
- 打乱了方法论五阶段的顺序。正确顺序为：分析规划、数据准备、数据分析、系统实现、评估与部署。

历年真题仅记录了选项中的分歧点，并未直接复制原文。解题方法是先列出五阶段表，然后确认选项中出现的任务属于哪个阶段的单元格。风险应对部分只需记住四个术语即可。

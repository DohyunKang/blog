セキュリティの範囲が広いため、用語を個別に見ても相互の関係性が把握しにくい。そこで、情報セキュリティシリーズの 5 編について各一行ずつ先に記載し、さらに詳しく知りたい場合は以下のリンクから詳細へ誘導する構成としている。順序は、基礎となる暗号化 → ウェブでの突破点 → キー管理 → AI 関連のリスク → 個人情報保護である。

## 関係性をひと目で把握

```
암호화·해시·서명 (바탕 도구)
   ├─ 웹 앱은 어디서 뚫리나 ........ 웹 취약점과 OWASP
   ├─ 비밀 값은 어떻게 다루나 ...... 키·시크릿 관리
   ├─ AI가 읽는 글이 명령이 되면 ... 프롬프트 인젝션
   └─ 사람 정보는 어떻게 지키나 .... 개인정보와 데이터 보호
```

## 1. 基盤ツール

**暗号化・ハッシュ・認証の基礎**: 暗号化は隠蔽と復元、ハッシュは復元せず同一性を確認するもの、署名は作成者と改ざんの有無を確認するものである。それぞれ解決すべき課題が異なるため、用途ごとに整理すると TLS まで一貫して理解できる。
[詳細 → 暗号化・ハッシュ・認証の基礎](#/post/sec-authn-crypto)

## 2. ウェブでの突破点

**ウェブ脆弱性と OWASP**: OWASP Top 10 はウェブアプリケーションで頻発するリスクのカテゴリ一覧である。その中の SQL インジェクション・XSS・CSRF の原因を見ると、共通の原因は「データがコマンドとして解釈されてしまうこと」であり、記事では簡易なデモコードを用いて確認している。
[詳細 → ウェブ脆弱性と OWASP](#/post/sec-owasp)

## 3. 機密値の扱い

**キー・シークレット管理**: API キーやデータベースパスワードなどのシークレットは、完全に隠蔽するよりも、漏洩した瞬間に即時廃棄し再発行できるようにしておくことが肝要である。保存、ローテーション、最小権限、Git にアップロードされた場合の対応について扱う。
[詳細 → キー・シークレット管理](#/post/sec-keys)

## 4. AI 関連のリスク

**プロンプトインジェクションと AI セキュリティ**: モデルは指示とデータを区別できないため、読み込む文章内の一行が命令として実行されてしまう可能性がある。完全に防ぐ方法がまだないため、実行されても被害を最小限に抑える、すなわち権限を制限することが防御の中心となる。
[詳細 → プロンプトインジェクションと AI セキュリティ](#/post/sec-prompt-injection)

## 5. 個人情報の保護

**個人情報とデータ保護**: 個人情報は名前だけでなく、他の情報と組み合わせられて特定可能なものであればすべて該当する。そのため、暗号化よりも先に収集を減らし、保有期間を短くすることが中心となる。
[詳細 → 個人情報とデータ保護](#/post/sec-privacy)

## どの順序で読むべきか

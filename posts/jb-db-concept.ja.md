情報処理技術者試験のデータベースパートは、キー、関係演算子、ER モデルという 3 つの塊に分かれます。後に出てくる正規化と SQL がすべてこれらの用語の上に成り立っているので、ここを先に押さえておくのが正解です。

## データモデルとは何か

データベースを作るということは、現実の世界の事象を「表（テーブル）」の形に変換することです。この際、「何を」「どのような規則で表現するか」を決めた枠組みがデータモデルです。試験では構成要素を 3 つに問われます。

| 構成要素 | 意味 |
|---|---|
| 構造 (structure) | データがどのような形になっているか |
| 演算 (operation) | そのデータをどのように抽出し、変更するか |
| 制約条件 (constraint) | どのような値が入ってはいけないか |

関係型モデルでは、構造はリレーション（表）、演算は関係演算子、制約条件はキーと整合性規則です。本書の 3 つの塊はこの 3 つの欄にそのまま当てはまります。

データモデリングは通常、概念 → 論理 → 物理という順序で進みます。概念段階では詳細が最も少なく範囲を定めます。論理段階では特定の DBMS と関係なく構造を詳細に作ります。物理段階ではテーブル、インデックス、制約条件まで実際に作成可能なレベルまで技術的に縛られます。ER モデルは主に概念段階で使われるツールです。物理段階については [詳しく → データベースの物理設計と分散データベース](#/post/jb-physical-design) で続きます。

## リレーションの用語

関係型モデルの用語は日本語と英語が混ざって出てくるため、ペアを覚えると便利です。

| 用語 | 意味 | テーブルでは |
|---|---|---|
| リレーション (relation) | 属性名（ヘッダー）とタプル（本文）の集合 | 表一つ |
| 属性 (attribute) | 名前とタイプを持つヘッダーの一つ | 列 (column) |
| タプル (tuple) | 各属性に値が一つある一行 | 行 (row) |
| ドメイン (domain) | 一つの属性が持つことができる値の集合 | 整数、文字列、日付などのタイプ |
| 次数 (degree) | 属性の数 | 列数 |
| カルディナリティ (cardinality) | タプルの数 | 行数 |

次数とカルディナリティは混同しやすいです。次数は横（列）、カルディナリティは縦（行）と覚えました。ER モデルにおける「カルディナリティ」は一対多などの関係の数の制約を意味することもあり、同じ言葉が二つの場所で異なる意味で使われる点も知っておく必要があります。

## キー

キーはタプルを互いに区別するために与える属性（複数）です。範囲が広いものから狭いものへと絞り込んでいくと順序が整います。

| キー | 定義 |
|---|---|
| スーパーキー | すべてのタプルで一意な値の組み合わせを持つ属性の集合 |
| 候補キー | スーパーキーの中で、さらに減らせば一意性が崩れる最小の集合 |
| プライマリーキー（基本キー） | 候補キーの中から代表として選んだもの |
| アルターネイトキー（代替キー） | 候補キーのうち、プライマリーキーにならなかった残り |
| フォーランキー（外래キー） | 他のリレーションの候補キーの値と一致しなければならない属性の集合 |

スーパーキーは一意性のみを、候補キーは一意性と最小性を両方要求します。学生テーブルで {学号} が候補キーであれば、{学号、名前} はスーパーキーですが候補キーではありません。学号だけで既に区別されるためです。住民票番号などの他の候補キーが存在すれば、プライマリーキーに選ばれなかった方が代替キーになります。

試験では一つの表を与えて「候補キーは何個あるか」「この属性はプライマリーキーになれるか」を問うような問題が多いです。解く際は、値が重複する列をまず消去し、残った列の中で単独で一意なものを発見した後に、その組み合わせを見る順序で行います。組み合わせを見た時点で既に一意な列が含まれている場合、その組み合わせは最小ではないため候補キーから除外されます。

## 整合性

キーは制約条件の方へと繋がります。試験には実体整合性、参照整合性、ドメイン整合性が登場します。

- 実体整合性：プライマリーキーは NULL になれず、同じ値が二つあることもできません。
- 参照整合性：フォーランキーは参照するリレーションに実際に存在する値か、NULL でなければなりません。
- ドメイン整合性：属性の値は定められたドメイン内にある必要があります。

フォーランキーを設定しておくと、DBMS が制約に違反する変更を拒否します。学生テーブルに存在しない学号で受講記録を入力しようとしてもブロックされるようなものです。

<details>
<summary>参照整合性が崩れる状況の整理</summary>

親テーブルは学生（学号プライマリーキー）、子テーブルは受講（学号フォーランキー、科目コード）としましょう。

| 動作 | 問題となる場合 |
|---|---|
| 子への挿入 | 親に存在しない学号を入力する |
| 親からの削除 | 子が指し示している学号を消す |
| 親キーの修正 | 子が指し示している学号を変更する |

親削除時の対応は、制限（子があれば拒否）、連鎖（子も一緒に削除）、NULL に変更など、このように分けて覚えると便利です。実際の文法については [詳しく → SQL アプリケーション](#/post/jb-sql-basic) で扱います。

</details>

## 関係演算子

関係演算子はリレーションを入力として受け取り、リレーションを出力する演算の集まりです。結果がまたリレーションであるため、演算を連結して行うことができます。基本的な演算は以下の通りです。

| 연산 | 기호 | 하는 일 |
|---|---|---|
| 셀렉션 | σ | 조건에 맞는 튜플 (행) 만 고름 |
| 프로젝션 | π (Π) | 지정한 속성 (열) 만 남김 |
| 리네임 | ρ | 속성 이름만 바꿈 |
| 합집합 | ∪ | 두 릴레이션의 튜플을 합침 |
| 차집합 | − | 앞 릴레이션에만 있는 튜플 |
| 카티전 프로덕트 | × | 두 릴레이션의 튜플을 모든 쌍으로 짝지음 |

여기서 파생되는 연산이 교집합 (∩) 과 조인 (⋈) 이다. 교집합은 합집합과 차집합으로 만들 수 있고, 조인은 짝이 맞는 튜플끼리 결합한 결과를 낸다. 자연 조인은 이름이 같은 속성의 값이 같은 튜플끼리 붙인다. 합집합·차집합·교집합은 두 릴레이션의 속성 구성이 같아야 쓸 수 있다는 조건이 붙는다. 카티전 프로덕트는 두 릴레이션의 속성 이름이 겹치지 않아야 한다.

외우기용으로 둘로 나눠 봤다. 셀렉션과 프로젝션은 한 표 안에서 자르는 연산이다. 셀렉션은 가로로 (행), 프로젝션은 세로로 (열) 자른다고 기억하면 헷갈릴 일이 줄었다. 나머지는 두 표를 합치는 연산이다.

디비전 (÷) 은 "전체 과목을 다 수강한 학생" 같은 조건에 쓰는 연산이다. 정의는 교재에서 따로 외워야 한다.

<details>
<summary>SQL 로 옮겨서 직접 돌려 본 결과</summary>

연산이 눈에 안 들어와서 SQLite 로 작은 표를 만들어 대응시켜 봤다. 학생 (1 kim cs, 2 lee ee, 3 park cs) 과 수강 (1 db, 1 os, 2 db, 3 db, 3 os) 이다.

```sql
-- 셀렉션 σ 학과='cs'
select * from student where dept='cs';
-- → (1,kim,cs) (3,park,cs)

-- 프로젝션 π 학과 (중복 제거)
select distinct dept from student;
-- → cs, ee

-- 자연 조인
select name, cid from student natural join enroll;
-- → kim db, kim os, lee db, park db, park os

-- 카티전 프로덕트: 3행 × 5행
select count(*) from student, enroll;
-- → 15
```

집합 연산도 같이 돌렸다. old={1,2}, new={2,3} 일 때 union 은 1,2,3, except 는 1, intersect 는 2 가 나왔다.

프로젝션에 distinct 가 붙은 이유가 있다. 관계대수에서 릴레이션은 튜플의 집합이라 중복이 없다. SQL 의 select 는 중복을 그대로 두는 게 기본이라서 distinct 를 써야 둘이 맞아떨어진다.

</details>

## ER 모델

ER 모델은 현실을 엔티티와 관계로 그리는 개념 모델이다. 구성은 세 가지다.

- 엔티티: 식별할 수 있는 대상. 보통 명사다 (학생, 과목).
- 속성: 엔티티나 관계를 설명하는 값 (학번, 이름). 엔티티를 구분하는 속성에는 밑줄을 긋는다.
- 관계: 엔티티 사이의 연결. 보통 동사다 (수강한다).

시험에서 자주 나오는 Chen 표기법은 도형으로 구분한다.

| 요소 | 도형 |
|---|---|
| 엔티티 | 사각형 |
| 관계 | 마름모 |
| 속성 | 타원 |

관계에는 개수 제약이 붙는다. 학생 한 명이 과목 여러 개를 듣고 과목 하나에 학생이 여럿이면 다대다 (N:M) 다. 교수 한 명이 과목 여러 개를 맡고 과목은 교수 한 명만 있으면 일대다 (1:N) 다. 이 개수 제약을 카디널리티라고도 부른다. 다른 표기법인 crow's foot 에서 고리가 0, 막대가 1, 갈퀴가 다수를 뜻하고, 두 기호를 짝지어 최소·최대를 나타낸다.

ER 도형을 표로 바꾸는 규칙은 문제로 자주 나온다. 기본 대응은 엔티티가 표가 되고 속성이 열이 되고 밑줄 친 식별 속성이 기본키가 된다는 대응이다. 다대다 관계의 변환과 같은 세부 규칙은 교재 표를 따로 보면서 외우는 쪽이 정확하다.

## 흔한 헷갈림

| 헷갈리는 것 | 정리 |
|---|---|
| 슈퍼키 vs 후보키 | 후보키는 최소성이 붙는다 |
| 차수 vs 카디널리티 | 열 수 vs 행 수 |
| 셀렉션 vs 프로젝션 | 행을 거름 vs 열을 거름 |
| 기본키 vs 대체키 | 후보키 중 뽑힘 vs 안 뽑힘 |
| 카디널리티 두 가지 | 릴레이션의 튜플 수 vs ER 의 관계 개수 제약 |

여기까지가 모델의 뼈대고, 이 키를 기준으로 표를 쪼개는 규칙이 [자세히 → 정규화와 트랜잭션](#/post/jb-normalization-transaction) 이다. 풀이 연습은 키 개수 세기, 관계대수 결과 릴레이션의 차수·카디널리티 구하기, 기호 이름 맞히기 세 가지로 해 두면 된다. 시험 일정과 응시 정보는 공식 사이트에서 확인한다.

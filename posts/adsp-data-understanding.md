ADsP 1과목 첫 단원인 데이터의 이해는 계산이 없고 용어와 구분을 묻는 문제가 대부분이다. 외울 덩어리는 네 개다. 데이터·정보·지식·지혜의 구분, 데이터 유형, 데이터베이스의 특징, 데이터 웨어하우스의 특징. 여기에 빅데이터의 3V가 붙는다. 전체 순서는 [ADsP 지도](#/post/adsp-map)에 정리해 뒀다.

## 데이터, 정보, 지식, 지혜

DIKW는 Data, Information, Knowledge, Wisdom의 앞글자다. 피라미드로 그리면 맨 아래가 데이터, 맨 위가 지혜다. 아래 단계가 가공되어 위 단계가 된다.

| 단계 | 뜻 | 예시(편의점) |
|---|---|---|
| 데이터 | 관찰하거나 측정한 값 그대로. 그 자체로는 쓸모를 말하기 어렵다 | A 편의점 우산 3,000원, B 편의점 우산 5,000원 |
| 정보 | 데이터를 목적에 맞게 가공·정리해 의미가 생긴 것 | A 편의점 우산이 B보다 싸다 |
| 지식 | 정보를 구조화해서 이해하고 쓸 수 있게 된 것 | 비 오는 날에는 A에서 우산을 사는 편이 낫다 |
| 지혜 | 무엇을 해야 하는지에 대한 판단 | 비싼 우산을 파는 B는 다음에 안 가고, 다른 물건도 A 쪽을 먼저 본다 |

문제는 보통 "다음 사례 중 정보에 해당하는 것은?" 식으로 나온다. 풀이 요령은 하나다. 값만 나열돼 있으면 데이터, 두 값을 비교하거나 정리해서 결론 한 줄이 나오면 정보, 그 정보를 바탕으로 앞으로 어떻게 하겠다는 예측·규칙이 나오면 지식, 거기서 한 걸음 더 나아가 판단·창의적 아이디어가 나오면 지혜로 본다.

<details>
<summary>DIKW 모델은 어디서 온 말인가</summary>

출처가 딱 하나로 정해진 모델은 아니다. 1980년대 후반에 여러 사람이 다루면서 널리 알려졌고, 피라미드 모양으로 그린 것도 그 무렵이다. 이 이야기는 시험에 나오지 않으므로 흘려 읽어도 된다. 시험에서는 네 단계의 순서와 각 단계 사례 구분만 본다.
</details>

## 데이터의 유형

모양(구조)으로 나누면 세 가지다.

| 유형 | 특징 | 예 |
|---|---|---|
| 정형 데이터 | 고정된 틀(스키마)이 있고 표로 바로 다룬다 | 관계형 DB 테이블, 엑셀, CSV |
| 반정형 데이터 | 형식은 있지만 값마다 구조가 다를 수 있다 | JSON, XML, HTML |
| 비정형 데이터 | 정해진 틀이 없다 | 텍스트 문서, 이미지, 음성, 영상 |

헷갈리는 건 반정형이다. 태그나 키로 구조를 표시하긴 하지만 행과 열의 표로 딱 떨어지지 않는다고 외우면 된다. 관계형 DB가 어떻게 정형 데이터를 다루는지는 [관계형 DB와 SQL 기본](#/post/db-rdb-sql), 정형이 아닌 쪽을 다루는 방식은 [NoSQL 종류와 선택](#/post/db-nosql)에서 이어진다.

## 데이터베이스의 특징 네 가지

데이터베이스는 여러 사람이 함께 쓰려고 모아 놓은 데이터의 집합이다. 시험에서는 아래 네 가지 이름과 뜻을 맞추게 한다.

| 특징 | 핵심 |
|---|---|
| 통합된 데이터 | 같은 내용이 중복되지 않게 모은다 |
| 저장된 데이터 | 컴퓨터가 접근할 수 있는 저장 매체에 보관한다 |
| 공용 데이터 | 여러 사용자와 여러 응용 시스템이 함께 쓴다 |
| 변화되는 데이터 | 삽입·삭제·갱신으로 계속 바뀌지만 항상 현재 상태가 정확해야 한다 |

자주 나오는 함정은 "통합된 데이터는 같은 데이터의 중복을 허용한다"처럼 틀린 문장을 섞는 유형이다. 통합은 중복을 없애는 쪽이다. 변화되는 데이터도 "한 번 저장하면 바꾸지 않는다"는 식으로 뒤집어서 나올 수 있다.

## 데이터 웨어하우스

데이터베이스가 일상 업무를 처리하는 곳이라면 데이터 웨어하우스는 분석하려고 데이터를 모아 둔 창고다. 여러 업무 시스템의 데이터를 가져와서(추출), 형식을 맞추고(변환), 창고에 넣는다(적재). 이 흐름을 ETL이라고 부른다.

데이터 웨어하우스의 특징은 네 가지다.

| 특징 | 뜻 |
|---|---|
| 주제 지향 | 개별 업무 처리가 아니라 판매·고객 같은 핵심 주제 중심으로 구성한다 |
| 통합 | 여러 시스템의 이름·단위·코드 체계 차이를 맞춰서 일관되게 한다 |
| 시계열 | 오랜 기간의 과거 데이터를 쌓아 두고 시간 흐름에 따라 본다 |
| 비휘발성 | 한 번 들어온 데이터는 읽기 전용으로 두고 함부로 바꾸거나 지우지 않는다 |

데이터 마트는 특정 주제나 부서 하나에 맞춰 작게 만든 데이터 웨어하우스다. 전사 단위가 웨어하우스, 부서 단위가 마트라고 구분하면 된다. 마트는 R 실습과도 이어지는 부분이라 [R 기초와 데이터 마트](#/post/adsp-r-datamart)에서 다시 나온다.

<details>
<summary>DB와 웨어하우스를 한 줄로 비교</summary>

| 구분 | 데이터베이스 | 데이터 웨어하우스 |
|---|---|---|
| 목적 | 일상 업무 처리 | 분석·의사결정 지원 |
| 데이터 | 현재 상태 중심, 계속 갱신 | 과거 이력 중심, 읽기 전용에 가깝다 |
| 구성 | 업무 단위 | 주제 단위 |

"웨어하우스는 시계열이면서 비휘발성이다"를 DB 특징 "변화되는 데이터"와 섞어서 묻는 보기가 있다. DB는 계속 바뀌고, 웨어하우스는 쌓아 두고 안 바꾼다.
</details>

## 빅데이터

빅데이터는 1990년대부터 쓰인 말이고 처음에는 세 가지 V로 설명했다.

| V | 뜻 |
|---|---|
| Volume(규모) | 테라바이트·페타바이트 이상의 양 |
| Variety(다양성) | 정형·반정형·비정형이 섞여 있다 |
| Velocity(속도) | 생성과 처리가 빠르다, 실시간에 가깝다 |

이후 정확성(Veracity)이 네 번째로 붙었고, 가치(Value)를 더해 5V로 설명하는 자료도 있다. 어디까지를 V에 넣느냐는 교재마다 조금 다를 수 있어서, 공부하는 교재의 목록을 기준으로 외우는 게 안전하다. 문제 풀이에서는 보기 문장이 어느 V를 가리키는지 맞히는 유형이 많다. "처리 속도"면 Velocity, "자료 형태가 여러 종류"면 Variety, "양이 크다"면 Volume이다.

빅데이터가 왜 생겼고 어디에 쓰이는지는 다음 단원 [데이터의 가치와 미래](#/post/adsp-data-value), 데이터 사이언티스트가 하는 일은 [데이터 사이언스와 인재](#/post/adsp-ds-bigdata)에서 이어진다.

## 풀이할 때 보는 순서

1. 보기 문장이 DIKW 사례면 값 나열, 비교·정리, 규칙·예측, 판단 순으로 단계를 찾는다.
2. 용어 정의 문제면 '중복', '읽기 전용', '여러 사용자' 같은 키워드로 어느 특징인지 매칭한다.
3. 틀린 것을 고르는 문제면 중복 허용, 수정 불가, 비정형을 표로 정리 가능 같은 뒤집힌 표현부터 의심한다.

시험 일정과 응시 관련 내용은 공식 사이트에서 확인하면 된다.

LLM API 요금은 쓴 토큰 양에 단가를 곱한 값이다. 그래서 비용을 줄이는 방법도 곱셈의 양쪽을 건드리는 것으로 정리된다. 단가가 낮은 모델을 쓰거나, 할인 받는 방식으로 부르거나, 토큰 자체를 줄이거나.

## 요금은 어떻게 계산되나

[LLM](#/post/ai-llm) API는 입력 토큰과 출력 토큰을 따로 센다. 단가는 보통 100만 토큰(MTok) 기준이고, 출력이 입력보다 비싸다. 아래는 Anthropic 공식 가격 페이지의 표준 가격이다(2026-11-04에 확인한 값, 가격은 바뀐다).

| 모델 | 입력 | 출력 | 배치 입력 | 배치 출력 |
|---|---|---|---|---|
| Claude Opus 5.5 | $4 | $20 | $2 | $10 |
| Claude Sonnet 5.5 | $2 | $10 | $1 | $5 |
| Claude Haiku 5.5 (프롬프트 10만 토큰 이하) | $0.10 | $0.50 | $0.05 | $0.25 |

같은 페이지 기준으로 Opus와 Haiku는 입력이 40배, 출력도 40배 차이가 난다. 모델 하나를 바꾸는 것만으로 한 자릿수가 아니라 두 자릿수 배수가 움직이는 셈이다. 모델별 특징은 [AI 모델 지도](#/post/ai-models)에 따로 정리해 뒀다.

계산 감을 잡으려고 가정을 하나 세웠다. 하루 1,000건, 요청당 입력 2,000토큰·출력 500토큰이다.

```
하루 입력 = 1,000 × 2,000 = 200만 토큰
하루 출력 = 1,000 × 500  =  50만 토큰
```

이 숫자에 위 표를 곱하면 이렇게 나온다.

| 모델 | 하루 비용 | 30일 |
|---|---|---|
| Opus 5.5 | $8 + $10 = $18 | $540 |
| Sonnet 5.5 | $4 + $5 = $9 | $270 |
| Haiku 5.5 | $0.2 + $0.25 = $0.45 | $13.5 |

입력 토큰 수는 프롬프트에 [컨텍스트](#/post/ai-context)를 얼마나 채우느냐로 정해진다. 대화가 길어질수록, 문서를 많이 붙일수록 요청당 입력이 불어난다. [컨텍스트 창](#/post/ai-context-window)이 크다는 건 많이 넣을 수 있다는 뜻이지 공짜라는 뜻은 아니다.

## 모델 라우팅

요청마다 난이도가 다르다. 분류, 짧은 추출, 형식 변환 같은 건 작은 모델로도 되고, 긴 추론이나 코드 작성은 큰 모델이 필요하다. 라우팅은 들어온 요청을 보고 어느 모델에 보낼지 정하는 앞단이다.

```
요청 → [라우터: 난이도 판단] ─ 쉬움 → 작은 모델 (Haiku급)
                            └ 어려움 → 큰 모델 (Sonnet·Opus급)
```

위 가정에서 요청의 80%를 Haiku, 20%를 Sonnet으로 보내면 하루 비용이 이렇게 된다.

```
0.8 × $0.45 + 0.2 × $9 = $0.36 + $1.80 = $2.16
```

전부 Sonnet일 때 $9였으니 4분의 1 수준이다. 큰 모델 비중이 비용 대부분을 차지한다는 것도 보인다. 20%밖에 안 보냈는데 비용의 80%가 거기서 나온다.

라우터를 만드는 방법은 몇 가지 있다.

- 규칙: 입력 길이, 요청 종류(분류냐 작문이냐), 사용자 등급 같은 걸로 나눈다. 가장 단순하고 디버깅이 쉽다.
- 작은 모델에게 판단 시키기: 요청을 보고 "쉬움/어려움"만 답하게 한다. 이 호출 자체가 비용이라 아주 싼 모델이어야 한다.
- 작은 모델 먼저, 실패하면 큰 모델: 작은 모델이 답하고 형식 검사나 신뢰도 점검을 통과하지 못하면 큰 모델로 다시 보낸다. 실패한 시도의 비용이 얹히는 게 단점이다.

라우터가 어려운 요청을 쉬운 것으로 잘못 보내면 품질이 떨어진다. 비용만 보고 바꾸면 이걸 알아채지 못하니, 바꿀 때마다 [평가 세트](#/post/ai-evals)로 점수를 비교해야 한다.

## 캐싱

반복되는 앞부분의 처리 결과를 재사용하는 프롬프트 캐싱은 입력 쪽 단가를 크게 낮춘다. 가격 페이지의 Sonnet 5.5 행에서 캐시 히트 가격은 $0.10/MTok으로, 표준 입력 $2의 20분의 1이다. 대신 캐시에 쓰는 요청은 $2.50/MTok(5분 캐시 기준)으로 표준보다 약간 비싸다. 원리와 쓰는 법은 [프롬프트 캐싱](#/post/ai-prompt-caching) 글에 정리했으니 여기서는 비용 수단으로서의 위치만 적는다. 시스템 프롬프트나 긴 문서처럼 요청마다 똑같이 붙는 덩어리가 클수록 효과가 크다.

같은 질문이 그대로 반복되는 서비스라면 답 자체를 저장해 두는 방법도 있다. 이건 모델을 부르지 않으니 비용이 0이다. 다만 질문이 똑같아야 해서, 사용자마다 표현이 달라지는 서비스에서는 적중률이 낮다.

## 배치 API

즉시 답이 필요 없는 일은 배치로 보낸다. 위 표의 배치 열이 그것이고, Anthropic 페이지는 입력과 출력 모두 50% 할인이라고 적는다. OpenAI 배치 가이드도 동기 API 대비 50% 비용 할인이라 하고, 24시간 안에 완료되며(더 빨리 끝나는 경우가 많다고) 평가 실행, 대량 데이터 분류, 콘텐츠 임베딩 같은 작업에 맞는다고 한다.

야간 분류, 문서 대량 요약, 평가 세트 돌리기처럼 사람이 기다리지 않는 작업이 해당한다. 사용자가 화면 앞에서 기다리는 요청에는 쓸 수 없다. 가격 페이지에는 이 할인이 캐시 같은 다른 가격 조정과 겹쳐서 적용된다는 문장도 있다.

위 Sonnet 5.5 하루 $9가 배치로 가면 $4.5다.

## 출력을 줄이기

출력 단가가 입력의 5배(Sonnet 5.5 기준 $10 대 $2)라서, 출력 토큰 한 개를 줄이는 게 입력 토큰 한 개를 줄이는 것보다 값어치가 크다.

- 최대 출력 길이(`max_tokens`)를 업무에 맞게 제한한다.
- 프롬프트에서 형식을 못 박는다. "한 단어로 분류", "JSON만 출력"처럼 말이다.
- 불필요한 서론과 요약을 달지 않도록 지시한다.

길이만 줄이면 답이 잘릴 수 있으니, 잘려도 되는 작업에 적용한다.

## 호출 자체를 줄이기

모델을 부르지 않아도 되는 건 부르지 않는 게 가장 싸다.

- 규칙이나 일반 코드로 되는 처리(정규식, 조건문, DB 조회)는 모델에 넘기지 않는다.
- 같은 입력의 결과를 저장해 재사용한다.
- 여러 항목을 한 번에 처리할 수 있으면 묶는다. 시스템 프롬프트가 요청마다 반복 청구되는 걸 줄여 준다.
- [에이전트 루프](#/post/ai-agent-loop)는 한 요청이 모델을 여러 번 부른다. 반복 횟수 상한을 두지 않으면 비용이 예상보다 크게 나올 수 있다.
- [RAG](#/post/ai-rag)로 문서를 통째로 붙이는 대신 필요한 조각만 붙이면 입력 토큰이 줄어든다.

## 오픈소스 모델을 직접 돌리면

오픈소스 모델을 자기 GPU에서 돌리면 토큰당 요금은 없어진다. 대신 GPU 비용이 고정으로 나간다. 클라우드 GPU는 시간당 요금이고, 자기 장비라면 구입비와 전기료다. 어느 쪽이든 쓰든 안 쓰든 나간다.

그래서 비교는 이런 식이 된다.

```
API 비용      = 월 토큰 수 × 단가            (쓴 만큼 늘어남)
자체 운영 비용 = GPU 월 비용 + 운영 인력·시간   (거의 고정)

손익분기 월 토큰 ≈ 자체 운영 월 비용 ÷ API 토큰당 단가
```

자체 운영 월 비용이 정해지면 그걸 위의 단가로 나눠서, 월 몇 토큰 넘게 쓸 때부터 자체 운영이 싸지는지 계산해 볼 수 있다. 다만 이 계산에는 빠지기 쉬운 항목이 있다. GPU가 놀고 있는 시간, 서빙 소프트웨어를 맞추고 고치는 시간, 모델 성능이 API의 큰 모델에 못 미칠 가능성이 그렇다. 하루 몇 백 건 정도의 사용량에서는 위 표처럼 Haiku급이 월 십몇 달러라서 GPU 고정비를 넘지 못하는 경우가 많을 것이다. 반대로 트래픽이 크고 꾸준하며 작은 모델로 충분한 작업이면 자체 운영이 맞을 수 있다. 어디가 분기점인지는 실제 GPU 요금과 처리량을 넣어 직접 계산해야 한다.

<details>
<summary>자세한 풀이: 위 계산을 한 번에 보기</summary>

가정: 하루 1,000건, 요청당 입력 2,000토큰·출력 500토큰, 30일.

| 구성 | 하루 | 30일 |
|---|---|---|
| 전부 Sonnet 5.5 | $9 | $270 |
| 전부 Sonnet 5.5 배치 | $4.5 | $135 |
| 80% Haiku + 20% Sonnet | $2.16 | $64.8 |
| 전부 Haiku 5.5 | $0.45 | $13.5 |

라우팅과 배치는 겹쳐 쓸 수 있다. 라우팅한 뒤 비동기 가능한 요청만 배치로 돌리는 식이다. 캐시는 입력 단가를 따로 낮추니 위 표보다 더 내려갈 수 있다.

</details>

## 어디서부터 줄이나

순서는 대략 이렇게 잡는 게 무난하다. 먼저 어떤 요청이 토큰을 많이 쓰는지 로그로 센다. 그다음 호출 자체와 출력 길이를 줄이고, 반복 앞부분이 크면 캐시를 쓰고, 사람이 안 기다리는 작업은 배치로 옮기고, 마지막에 라우팅을 얹는다. 모델을 바꾸는 건 품질 영향이 가장 커서 평가 세트가 있을 때 한다.

## 흔한 오해

- 싼 모델이면 무조건 이득이다: 작은 모델이 틀려서 재시도·재요청이 늘면 절약분이 사라진다.
- 캐시는 쓰기만 하면 항상 싸다: 캐시에 쓰는 요청은 표준보다 비싸고, 다시 읽히지 않으면 손해다.
- 입력이 길어도 요금은 비슷하다: 입력은 토큰 수만큼 청구되고, 길수록 선형으로 늘어난다.
- 자체 GPU는 공짜다: 토큰당 요금이 없을 뿐 고정비가 있다.

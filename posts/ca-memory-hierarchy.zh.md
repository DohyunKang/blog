CPU 很快，但内存很慢。为了掩盖这种差异，在大型存储设备前层层叠加小型高速存储设备，构成了内存层次结构，而中间的那些层级就是缓存（Cache）。在《操作系统概览》(#/post/cs-os)中已经讨论了虚拟内存和页面错误，而本文则从更底层的硬件角度探讨相同的问题。

## 层次结构的形态

向上层：速度越快、容量越小、价格越贵。  
向下层：速度越慢、容量越大、价格越便宜。

| 层级 | 大致特性 |
|---|---|
| 寄存器 | 位于 CPU 内部，速度最快，数量极少 |
| L1, L2, L3 缓存 | CPU 内外部的 SRAM，层级越低容量越大但速度越慢 |
| 主存储器 (RAM) | 程序实际运行的地方 |
| 磁盘 (SSD, HDD) | 断电后数据不丢失的大容量存储设备 |

寄存器是如《CPU 与指令》(#/post/ca-cpu)中所见，由指令直接读写的位置。其下各层并非由程序直接管理，而是由硬件自动填充和清空。因此代码中看不到缓存的存在，但其对速度影响显著。

## 为何缓存有效：局部性

小容量缓存之所以能模拟大内存的速度，是因为程序的访问模式并不均匀。这种特性被称为“局部性”（locality of reference）。

- **时间局部性**：一旦使用过的数据，很快会被再次使用。例如循环中的变量。
- **空间局部性**：若访问某个地址，邻近的地址也很可能被紧接着访问。例如按顺序遍历数组的情况。

由于空间局部性，缓存不会只加载所需的 1 字节，而是以块为单位进行加载。这个块称为“缓存行”（cache line）。维基百科关于 CPU 缓存的文档指出，例如 Pentium 4 和 K8 的 L1 数据缓存使用 64 字节的缓存行。下方的模拟也采用了 64 字节对齐。

## 命中与未命中，以及平均访问时间

当 CPU 查找的数据存在于缓存中时称为“命中”（hit），否则为“未命中”（miss）。发生未命中时，需从下层获取数据，耗时较长。设命中率为 $h$，平均访问时间通常表示为：

平均访问时间 = 命中时间 + (1 − h) × 未命中时额外花费的时间

假设命中耗时 1 单位，未命中额外耗时 100 单位（注：此处数字仅为假设，非真实硬件数值），计算结果如下表：

| 命中率 | 平均访问时间 |
|---|---|
| 99% | 2 |
| 95% | 6 |
| 90% | 11 |

命中率仅下降 9%，平均访问时间却增加了超过 5 倍。这正是缓存讨论中对命中率百分比如此敏感的原因所在。

<details>
<summary>平均访问时间计算解析</summary>

设定命中时间为 1，未命中额外时间为 100，使用 Python 进行计算：

```python
for h in (0.99, 0.95, 0.9):
    print(h, 1 + (1 - h) * 100)
# 0.99 2.0 / 0.95 6.0 / 0.9 11.0
```

（实际输出因浮点数精度问题可能显示为 2.000000000000001 等形式。）

## 数据在缓存中的放置策略

决定将内存地址映射到缓存中哪个位置的方法有三种：

- **直接映射（direct-mapped）**：每个地址只能映射到一个固定位置。结构简单且快速，但若多个地址频繁访问同一位置，会相互驱逐。
- **组相联（set-associative）**：可在 N 个位置中的任意一个放置，称为 N-way。
- **全相联（fully associative）**：可放置在任意位置。未命中率最低，但仅在条目较少时具有实际可行性。

根据维基百科文档，2-way 的命中率与两倍大小的直接映射缓存相近；超过 4-way 后收益递减。

写入策略有两种：  
- **写直达（write-through）**：每次向缓存写入时同时更新内存。  
- **写回（write-back）**：仅在缓存行中写入，并标记该行为“脏”（dirty），待其被替换时才写回内存。

## 直接进行模拟

使用 Python 模拟一个小型缓存（1KB，每行 64 字节），并尝试不同的访问模式。当缓存行满时，采用淘汰最久未使用的策略（LRU）。

```python
def sim(addrs, size=1024, line=64, ways=1):
    sets = size // line // ways
    st = [[] for _ in range(sets)]
    hit = 0
    for a in addrs:
        b = a // line
        s = b % sets
        if b in st[s]:
            hit += 1
            st[s].remove(b); st[s].append(b)
        else:
            if len(st[s]) >= ways:
                st[s].pop(0)
            st[s].append(b)
    return hit / len(addrs)

print(sim([i * 4 for i in range(4096)]))      # 0.9375
print(sim([i * 64 for i in range(4096)]))     # 0.0
```

按顺序读取 4 字节整数时，每行（64 字节）可容纳 16 个整数，因此首次访问为未命中，后续 15 次均为命中。命中率为 15/16 = 0.9375。反之，若每次跳过 64 字节读取，则每次都访问新行，命中率为 0。即使读取相同数量的数据，顺序不同也会导致巨大差异。

此外，还模拟了在缓存中交替读取地址 0 和 1024 共 1000 次的情况。由于这两个地址映射到同一位置，直接映射的命中率为 0.0，而 2-way 相联缓存则达到 0.998。上述提到的相互驱逐（冲突未命中）正是如此产生的。

## 二维数组是按行还是按列读取？

使用相同的模拟器观察了因数组存储方向不同带来的差异。假设一个 64×64 的整数数组以行优先方式存储，并使用 4KB、4-way 相联缓存进行模拟。

| 遍历方式 | 命中率 |
|---|---|
| 行顺序（按存储顺序） | 0.9375 |
| 列顺序（跨行访问） | 0.0 |

维基百科关于“局部性”的文档也指出，由于 C 语言以行优先方式存储数组，因此行顺序遍历能连续读取内存，效率更高；而列顺序遍历则需要频繁跳转至相距较远的内存位置，导致缓存未命中增多。此外，也有说法认为当矩阵足够小、能完全装入缓存时，两者差异会减小。

<details>
<summary>在真实计算机上的实测</summary>

使用 numpy 对 5000×5000 的 int32 数组（行优先存储）分别计算行和与列和，各重复 5 次并选取最快结果。在我的 PC 上，行求和耗时约 0.029 秒，列求和耗时约 0.086 秒，相差约 3 倍。该结果受限于当前 PC 硬件环境与 numpy 实现，在其他环境下可能不同。

```python
import numpy as np, time
a = np.ones((5000, 5000), dtype=np.int32)
def best(f):
    r = []
    for _ in range(5):
        t = time.perf_counter(); f(); r.append(time.perf_counter() - t)
    return min(r)
rows = best(lambda: [a[i].sum() for i in range(5000)])
cols = best(lambda: [a[:, j].sum() for j in range(5000)])
print(rows, cols, cols / rows)
```
</details>

## 常见误解

- 缓存越大越快：实际上，随着容量增大，查找所需时间也会增加，因此需要分层设计。
- 缓存与程序员无关：虽然由硬件自动管理，但正如上文所示，仅改变访问顺序即可显著影响命中率。
- RAM 与虚拟内存的磁盘换页不同于缓存机制：二者原理方向一致。RAM 可被视为磁盘的缓存，而页面置换策略本质上与缓存替换策略属于同一类问题。

오늘 아침 GitHub 트렌딩(daily)에 alibaba/open-code-review가 올라와 있었다. 오늘 하루 별 897개, 레포 전체 별은 51,413개(11월 15일 오전 확인). 레포는 5월에 만들어졌으니 아주 새 물건은 아닌데, 이번 주 들어 다시 크게 돌고 있다. X에서 이름이 들어간 글이 11월 12일(UTC) 11건, 13일 56건, 14일 135건으로 늘었다(리트윗 제외, X 집계 기준). 나는 README와 최근 릴리스 노트 세 개, 벤치마크 표를 읽었고 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
AI로 코드 리뷰를 해 주는 CLI다. 알리바바 사내에서 2년 동안 쓰던 리뷰 도우미를 오픈소스로 푼 거라고 README에 적혀 있다. Git diff를 읽고, 바뀐 파일을 LLM 에이전트에게 넘기고, 줄 단위로 위치가 찍힌 리뷰 코멘트를 돌려준다. 에이전트는 파일 전체를 읽거나 코드베이스를 검색해서 diff 밖의 맥락도 본다. 에이전트는 모델이 도구를 쓰면서 스스로 다음 할 일을 정하는 방식이다. [자세히 → 에이전트 루프](#/post/ai-agent-loop)

`npm install -g @alibaba-group/open-code-review`로 깔고, 모델 제공자를 설정한 다음 `ocr review`를 치면 된다. diff 없이 폴더 전체를 훑는 `ocr scan`도 있다.

## 어떻게 도는지
재밌는 건 설계 쪽 주장이다. README는 Claude Code 같은 범용 에이전트에 스킬을 붙여 리뷰를 시키면 세 가지가 문제라고 한다. 변경이 크면 일부 파일만 보고 넘어가고, 지적한 줄 번호가 실제 코드와 어긋나고, 프롬프트를 조금만 바꿔도 품질이 출렁인다. 원인은 과정 전체를 말로만 지시해서 강제할 장치가 없다는 것.

그래서 틀리면 안 되는 단계는 모델 말고 일반 코드가 맡는다.

1. 파일 고르기: 어떤 파일을 리뷰하고 어떤 걸 거를지 코드로 정한다. 모델이 빼먹을 여지를 없앤다.
2. 묶기: 관련 파일을 한 단위로 묶는다. 예를 들면 `message_en.properties`와 `message_zh.properties`. 묶음마다 맥락이 분리된 서브에이전트가 따로 돈다. [자세히 → 서브에이전트](#/post/ai-subagent)
3. 규칙 매칭: 파일 성격에 맞는 리뷰 규칙만 템플릿 엔진으로 골라 넣는다. 모델이 읽는 정보를 줄이는 쪽이다.
4. 위치 잡기와 되돌아보기: 코멘트가 가리키는 줄을 맞추는 모듈과 코멘트 내용을 다시 점검하는 모듈이 모델 밖에 따로 있다.

모델은 그 사이에서 "어떤 맥락을 더 찾아볼지" 같은 판단만 한다. 도구 목록도 실제 사용 기록에서 어떤 도구가 얼마나 자주, 몇 번씩 반복 호출되는지 분석해서 줄였다고 한다. [자세히 → 도구 사용](#/post/ai-tool-use)

실행 모드가 둘인 것도 눈에 띄었다. 기본은 OCR이 직접 설정된 모델 API를 부른다. 위임 모드(Delegation Mode)에서는 OCR이 파일 고르기와 규칙 정리만 하고, 리뷰 자체는 내가 쓰던 코딩 에이전트가 자기 모델로 한다. 이때는 OCR용 API 키가 따로 필요 없다고 적혀 있다.

## 왜 화제인지
숫자 하나가 눈에 띈다. 50개 오픈소스 레포의 실제 PR 200개에서 사람이 표시한 문제 1,505개를 정답으로 놓고 비교한 표다(AACR-Bench, 프로젝트가 만든 벤치마크). 같은 Claude-4.8-Opus로 돌렸을 때 OCR은 정밀도 37.8%, 재현율 11.7%, 리뷰 한 번에 토큰 352K, 1분 6초. Claude Code는 정밀도 15.93%, 재현율 12.70%, 토큰 2,062K, 5분 38초였다. 정밀도는 지적한 것 중 진짜 문제의 비율, 재현율은 진짜 문제 중 찾아낸 비율이다. README도 재현율이 낮은 건 헛지적을 줄이려고 고른 트레이드오프라고 인정한다. 표의 OCR 버전이 v1.3.1로 지금(v1.13.9)보다 한참 옛날이고, 프로젝트가 직접 잰 숫자라 나는 재현하지 않았다. [자세히 → 평가(evals)](#/post/ai-evals)

릴리스도 부지런하다. 11월 10일, 12일, 13일에 v1.13.7~v1.13.9가 나왔고, 12일 릴리스에 GitHub Copilot CLI 연동이 들어갔다.

Reddit과 YouTube에서 얼마나 돌았는지는 확인 못 함.

## 입문자 입장에서
PM 입장에서는 "모델에게 다 맡기지 말고, 틀리면 안 되는 부분은 코드로 고정한다"는 설계가 와닿았다. 에이전트 품질이 들쭉날쭉할 때 프롬프트를 더 다듬는 대신 어느 단계를 모델 밖으로 뺄지 보는 관점이다. 리뷰에서 헛지적이 많으면 사람이 결국 안 읽게 되니까, 덜 찾더라도 정확한 쪽을 고른 것도 이해가 된다.

개발 입문자라면 내 작은 프로젝트에서 커밋 하나에 `ocr review --commit <해시>`를 돌려 보는 정도로 시작하면 될 것 같다. Claude Code 같은 에이전트를 이미 쓰고 있으면 위임 모드로 키 없이 붙여 볼 수 있다. 보안 취약점을 찾는 쪽 도구가 궁금하면 이 글도 같이 보면 좋다. [자세히 → Codex Security](#/post/news-261113-a)

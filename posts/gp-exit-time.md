공모전이 끝나고 나서도 주차 앱이 계속 눈에 밟혔다. 발표용으로는 잘 돌아갔는데, 혼자 다시 열어 보니 **"출차 시간 예측"** 부분이 영 마음에 안 들었기 때문이다.

## 뭐가 문제였냐면

빌라 주차장은 데이터가 정말 적다. 같은 칸에 같은 차가 매일 들락날락하긴 하지만, 기록이 쌓여 봐야 요일별로 몇 건이다. 그런데 처음엔 "데이터를 모아서 학습시키면 되겠지" 하는 단순한 생각으로 접근했다.

해 보니 이렇더라.

- 데이터가 적으면 모델이 **조금만 바뀌어도 예측이 널뛰기**한다
- 예측값만 덜렁 나오니까 **얼마나 믿어도 되는지**를 모른다
- 사용자 입장에선 "3시 10분 출차 예정"이라고 떴는데 3시 40분에 나가면 그냥 틀린 앱이다

여기서 한참 헤맸다. 모델을 더 복잡하게 바꿀수록 오히려 더 불안정해졌다. 돌이켜보면 **"왜 안 되지?"를 따라가다 보니 질문 자체가 틀렸던 것**이다. 필요한 건 더 똑똑한 모델이 아니라, 데이터가 적어도 버티는 모델이었다.

## 가우시안 프로세스로 바꾼 이유

찾다 보니 가우시안 프로세스(GP)가 이런 상황에 잘 맞는다고 해서 써 봤다. 내가 이해한 만큼만 정리하면:

> 값 하나를 찍어 주는 게 아니라 **"이 정도 범위 안에 있을 것"** 이라는 분포를 준다.

이게 생각보다 컸다.

| | 기존 방식 | GP |
|---|---|---|
| 데이터 적을 때 | 예측이 흔들림 | 불확실하다고 **솔직하게** 말함 |
| 결과 | 숫자 하나 | 숫자 + 신뢰 범위 |
| 새 기록이 들어오면 | 다시 학습 | 자연스럽게 반영 |

데이터가 적은 구간에선 범위가 넓게 나오고, 기록이 쌓일수록 좁아진다. 앱에서도 "대략 3시 전후"처럼 보여 줄 수 있게 됐다. 정확한 한 점을 맞히려 애쓰던 때보다 사용자한테 훨씬 정직한 화면이 됐다.

## 하면서 느낀 것

1. **데이터가 적을 땐 모델을 키우지 말고 가정을 줄이는 쪽이 낫다.**
2. 예측은 맞히는 것만큼 **얼마나 확신하는지 같이 보여 주는 게** 중요하다.
3. 공모전용으로 "돌아가는 것"과 계속 쓸 수 있는 것은 완전히 다르다.

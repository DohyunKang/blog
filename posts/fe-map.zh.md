学习前端时，渲染、状态、组件、可访问性、性能等术语会扑面而来。这些看似不同的话题，归根结底都指向同一个核心问题：“浏览器如何构建画面？我们该如何编写代码？用户最终看到的是什么？”因此，我将这七个主题按此顺序整理成七篇文章，并先简要写下每篇的开头。若想了解更多，请点击相应链接跳转。

## 一览关系图

```
브라우저가 그린다  ←  HTML을 누가·언제 만드나 (CSR·SSR·SSG)
        ↑
만든다: 컴포넌트로 쪼개고, 상태를 어디에 둘지 정한다
        ↑
쓰는 사람 쪽: 쓰기 쉬운가(사용성) · 누구나 쓸 수 있나(접근성) · 빠른가(성능)
```

## 1. 画面是如何生成的

**浏览器渲染过程**：浏览器接收 HTML 和 CSS，依次构建 DOM、CSSOM、渲染树、布局（Layout）和绘制（Paint），最终呈现画面。不同阶段之间的切换成本差异巨大，决定了页面更新的开销。
[详情 → 浏览器的渲染过程](#/post/fe-browser-render)

**CSR·SSR·SSG**：这三种方式的区别仅在于“谁在何时生成页面的 HTML"。评判哪种更好，不应一概而论，而应依据页面数据更新频率来决定。
[详情 → CSR·SSR·SSG](#/post/fe-rendering-modes)

## 2. 如何构建应用

**状态管理**：决定哪些值需要被画面“记住”，以及由谁来修改这些值。在选型库之前，先对数据的类型进行分类更为关键。
[详情 → 状态管理](#/post/fe-state)

**组件设计**：将界面按照数据流动的结构拆分成独立模块。设计的重点不在于拆分得有多细，而在于在哪里停止拆分、由谁持有状态。
[详情 → 组件设计](#/post/fe-component)

## 3. 对用户意味着什么

**可用性原则（UX）**：衡量界面是否易于使用。尼尔森提出的十大启发式原则是检查这一点的常用清单。
[详情 → 可用性原则 (UX)](#/post/fe-usability)

**Web 可访问性**：构建产品时不能仅假设用户拥有鼠标和视力。大多数问题可通过正确使用 HTML 解决，ARIA 则是在此基础上必要的补充手段。
[详情 → Web 可访问性](#/post/fe-accessibility)

**前端性能**：“快”的感觉可以通过三个核心指标来量化，即 Core Web Vitals（加载、响应、稳定性）。只有先了解这些数值，才能确定需要优化的方向。
[详情 → 前端性能](#/post/fe-performance)

## 阅读顺序建议

如果你是初学者，建议按照“渲染过程 → CSR·SSR·SSG → 状态 → 组件”的顺序阅读，这样逻辑更连贯。而可用性、可访问性和性能这三个主题，无论何时阅读都可以独立理解。若对“画面变慢的原因”感到好奇，可将“渲染过程”与“性能”两篇文章结合阅读。

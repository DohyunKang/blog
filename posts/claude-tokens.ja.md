Claude の使用量は、私が記した文章よりも、各リクエストごとに再送される会話履歴やツール結果から多く消費され、節約方法も大半はその文脈を軽く扱う方です。

この記事は、Anthropic 公式ドキュメントの 3 つ（Claude Code のコスト管理、Claude Code のプロンプトキャッシング、API のプロンプトキャッシング）を開いて整理したものです。私がどのように使うかは記載しておらず、ドキュメントで確認した内容のみを記述しました。

## トークンはどこから出ていくのか

Claude Code ドキュメントは以下のように説明しています。モデルはリクエスト間で何も記憶しておらず、メッセージを送るたびにシステムプロンプト、プロジェクト文脈（CLAUDE.md など）、これまでのすべてのメッセージとツール結果、新しいメッセージをまるごと再送します。[詳細 → コンテキスト](#/post/ai-context)

ここで 2 つの点が目立ちました。

- ツールを 1 回使うたびにリクエストが 1 つ増え、そのリクエストにもこれまでの記録全体が含まれます。
- 一日中開いておいたセッションで 1 行だけ質問しても、そのセッション全体の会話に対する使用量が計上されます。キャッシングのおかげで単価は下がりますが 0 ではありません。

そのためトークンコストは「私が何文字書いたか」ではなく「現在の文脈がどれだけ大きいか × リクエストが何回出たか」に近いと言えます。これはドキュメントの内容を合わせるとそう読み取れるという整理です。[詳細 → コンテキストウィンドウ](#/post/ai-context-window)

ドキュメントで挙げられている、セッションが長くなることで使用量が増える理由を表にすると以下のようになります。

| 原因 | ドキュメントの説明 |
|---|---|
| 長い文脈 | 全体の会話が各リクエストに含まれます |
| キャッシュミス | キャッシュの寿命よりも長く待っていると、最初のメッセージで文脈全体を再処理します |
| スケジュールタスク・他のセッションのメッセージ | セッションがアイドル状態でも新しいターンが発生すれば、文脈全体が含まれます |
| サブエージェント | 各自が別々にリクエストを送るため、メイン会話の上に追加されます |
| 圧縮 | `/compact` も要約する対話を読む必要があるため、長い文脈は大きなリクエストになります |

画像についてはドキュメントでコストの話よりもキャッシュの話から出てきます。リクエストに含まれることのできる画像や PDF の数・サイズには制限があり、それを越えると Claude Code が古いものから 1 つずつまとめて削除して送ります。削除するとそのメッセージから再処理が必要になるため、そのターンは遅く高価になります。

## プロンプトキャッシング

キャッシングとは、リクエストの先頭部分（prefix）が以前のリクエストと同じであれば、その部分を再度計算せず安価な単価で読み取る機能です。API ドキュメントを基準にすると prefix は `tools → system → messages` の順序であり、一致させるのは文字だけでなく画像まで 100% 同じ必要があります。出力はキャッシングを使うかどうかに関わらず同じです。

単価はモデルによって異なりますが、ドキュメントの表を見ると概ね以下のようになります。

| 項目 | 基本入力に対する倍率 |
|---|---|
| キャッシュ読み取り | 基本 0.1 倍。ただし Opus 5.5・Sonnet 5.5 は 0.05 倍、Fable 5.1・Mythos 5.1 は 0.025 倍、Haiku 5.5 はモデル表に別途記載された固定単価 |
| 5 分キャッシュ書き込み | 1.25 倍 |
| 1 時間キャッシュ書き込み | 2 倍 |

この倍率は、バッチ割引などの他の割引と重ねて適用されるという記載があります。5 分キャッシュは毎回使用することで寿命が無料で延長されます。そのため継続して作業中は安く読み取れますが、5 分以上席を離れると再び高価になるように設定されます。Claude Code ドキュメントでは、サブスクリプションプランの包含使用量内ではメイン会話に 1 時間の TTL を、API キーやクラウドプロバイダーで使う場合は 5 分を基本としているとあります。

Claude Code はこれを自動的に処理してくれ、私がやるべきことはキャッシュを無効化する行動を覚えていることです。ドキュメントで挙げられているものは以下の通りです。

- `/model` でモデルを変更する：モデルごとにキャッシュが別々であるため、次のリクエストは全体をキャッシュなしで読み取ります。
- 努力レベル（effort）を変更する：ほとんどのモデルでも同様です。Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1 は API キーやサブスクリプションで使用する場合にキャッシュが維持されると記載されています（Bedrock などの一部の環境は例外）。モデルリストは頻繁に変化するため、使用前にドキュメントを再確認するのが望ましいです。
- MCP サーバーの接続・切断、ツールの全否定：ツール定義がシステム層にあるため変更するとキャッシュが破られます。ただしツール検索（tool search）がデフォルトでオンになっているモデルではツールが遅延ロードされるため影響がないとされています。
- 圧縮：会話層が変化します。それでもシステムプロンプトやプロジェクト文脈はキャッシュに残すことができます。

逆にキャッシュを守る行動もあります。ファイルの修正、権限モードの切り替え、スキル呼び出し、`/recap`、`/rewind` は会話の末尾に追加したり、すでにキャッシュされた先頭部分に戻ったりするためキャッシュが維持されます。CLAUDE.md をセッション中に修正してもキャッシュは破れないですが反映もされません。次の `/clear`、`/compact`、再起動時に読み取られます。

ドキュメントのヒント 1 つ：セッションの最初でモデルと努力レベルを設定し、`/compact` は作業間の自然な中断に使うよう推奨されています。

## モデルを分けて使う

コストに関するドキュメントでは、Sonnet はコーディング作業の大部分を得意とし Opus より安価である一方、Opus は複雑な設計判断や多段階の推論に留保すべきであるとされています。単純なサブエージェントタスクについては `model: haiku` と指定するよう指示もあります。ドキュメントで挙げられている「想定外の高額な支出」の一般的な原因として、長期間空けずに放置されたセッションと、Opus をデフォルトモデルとしている点が挙げられています。[詳細 → モデルマップ](#/post/ai-models)

注意すべき点は、前節の内容と衝突する部分です。モデルを変更するとキャッシュが破損するため、作業の途中でモデルを切り替えるよりも、サブエージェントにモデルを割り当てて分担させる方がキャッシュへの悪影響は小さいとされています。ドキュメントによれば、サブエージェントは独自の会話とキャッシュを持ち、親のキャッシュには影響を与えないとしています。

思考 (thinking) トークンも存在します。拡張思考はデフォルトでオンになっており、出力トークンで課金され、リクエストあたりの予算が数万トークンに達する可能性があるとのことです。単純な作業であれば `/effort` で努力レベルを下げたり、`/config` でオフにしたりできます。ただし、ドキュメントでは一部のモデル（Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable シリーズ）はオフにできないと記載されています。

## 空け、圧縮、セッションの分割

- `/clear`: 関連のない話題に移る際に使用します。ドキュメントの表現では、陳腐なコンテキストが以降のすべてのメッセージでトークンを浪費するとあります。コストは 0 です。後で戻りたい場合は、空ける前に `/rename` を使い、その後 `/resume` を実行します。
- `/compact`: 対話を要約してコンテキストを削減します。`/compact Focus on code samples and API usage` のように残す内容を指示でき、CLAUDE.md に "Compact instructions" という項目を設ける方法もあります。ただし、圧縮自体は大きなリクエストです。キャッシュが温かい時（作業中）は先頭部分をキャッシュから読み込んで安価に処理できますが、長時間放置した後で古いセッションを続けて圧縮するとキャッシュが存在しないため最も高価になります。
- `/rewind`（または Esc キー 2 回）：間違えた道筋を戻します。すでにキャッシュされた先頭部分を切り取って戻すため、圧縮よりもキャッシュに有利だとドキュメントは述べています。
- プランモード (Shift+Tab): 実装前に方向性を承認して無駄な作業を減らす方法として紹介されています。

また、リクエスト自体を具体的に書くよう指示します。「このコードベースを改善してください」というのは広範な探索を呼びかけますが、「auth.ts のログイン関数に入力検証を追加」は読み込むファイルが少なくなります。テストや期待出力も併せて与えれば、自ら検証して修正する往復が減るともされています。

## 大きなファイルとログは削減して

ドキュメントで挙げられた例は 1 万行のログです。Claude が丸ごと読む代わりに、フックが `ERROR` 行のみを選別すれば、コンテキストは数万トークンから数百トークンに削減されます。ドキュメントには PreToolUse フックを使って `npm test`, `pytest`, `go test` の出力で失敗した部分だけを残すよう命令するサンプルスクリプトがあります。

もう一つはサブエージェントです。テスト実行、ドキュメント取得、ログ処理のように出力が大きい作業をサブエージェントに任せておけば、汚い出力はその側のコンテキストに残り、要約だけがメインに戻ってきます。ただし、サブエージェントのリクエストも利用量から引かれます。したがって、隔離で得られるのは「メインコンテキストの清潔化」であり、「無料」ではありません。小さなモデルを指定すればその負担は軽減されます。[詳細 → ハネス](#/post/ai-harness)

<summary>詳細な解説：ドキュメントのエージェントチームのコスト</summary>

エージェントチームは、各メンバーが個別の Claude Code インスタンスとコンテキストを持っています。ドキュメントでは、プランモードで回るチームメンバーがいる場合、標準セッションよりも約 7 倍のトークンを使用すると記載されています。削減方法としては、チームメンバーに Sonnet を使用し、チームを小さく保ち、開始プロンプトを短くし、終了したメンバーは終了させることです。エージェントチームはデフォルトでオフになっており、環境変数でオンにするとのことです。私は実際に試していません。

</details>

## CLAUDE.md と MCP

CLAUDE.md はセッション開始時にコンテキストにアップロードされるため、特定の作業手順（PR レビュー、DB 移行など）が長く記述されていれば、関連のない作業を行う際にもそのトークンが持ち去られます。ドキュメントの推奨事項は 2 つあります。CLAUDE.md には必須項目のみを含めて 200 行以内にし、特定のタスク向けの指示はスキルに移します。スキルは呼び出す際にのみロードされます。スキルがプロジェクト構造を事前に教えてくれるため、Claude が複数のファイルを読み込んで把握するトークンを節約する用途としても紹介されています。[詳細 → スキル・設定](#/post/claude-skills)

MCP はツール定義がデフォルトで遅延読み込みされるため、ツール名とサーバー指示だけがコンテキストに入り、実際に使用する際に定義を取得します。それでもドキュメントでは 2 つの推奨事項を挙げています。

- `gh`, `aws`, `gcloud`, `sentry-cli` などの CLI があれば、MCP よりもコンテキスト効率が良くなります。ツールごとのリストが追加されないためです。
- `/mcp` で設定されたサーバーを見て使わないものは停止します。コンテキストを何が占めているかは `/context` で確認できます。

オフにするのもツール定義の変更であり、ツール検索がオフの環境ではキャッシュが破損するという点は前述のとおりです。[詳細 → MCP](#/post/ai-mcp)

## よくある誤解

- キャッシュを利用すれば長いセッションでも問題ない: 単価は安くなるだけでコンテキストサイズは変わらず、5 分または 1 時間以上休憩すると最初のメッセージで全体を再処理します。
- 圧縮すれば必ず安い: 圧縮自体が大きなリクエストになる可能性があります。文書では、休息して戻ってきた古いセッションからのリクエストは特に高コストであると述べています。
- モデルを頻繁に切り替えて使う方が節約になる: むしろ頻繁に変えない方が節約になります。変更するたびにキャッシュが破損してしまうためです。モデルの割り当てはセッション開始時やサブエージェントで行うのが望ましいです。これは「コスト管理」と「プロンプトキャッシング」の 2 つの文書を統合して導いた結論です。
- サブエージェントはトークンを消費しない: コンテキストは分離されるだけで、リクエストは自分の使用量から計上されます。

<details>
<summary>詳細な解説：使用量の確認方法と平均値</summary>

`/usage` はセッションごとのトークン使用量を表示し、サブスクリプションプランではスキル、サブエージェント、プラグイン、MCP サーバーごとの使用割合と削減の推奨事項も表示されます。コストの数字は、サブスクライバーに対して請求用のものではありません。最新バージョンでは `Prompt cache (main)` という行にキャッシュヒット率、ミス回数、キャッシュが「温かい」かどうか（有効か）も表示されます。ステータスバーにもコンテキスト使用量を継続して表示することも可能です。

企業デプロイメントの基準となる平均は、開発者 1 人あたりアクティブな日数で約 13 ドル、月額 150〜250 ドルであり、文書では 90% が 1 日 30 ドル未満であると記載されています。これはチーム単位の話であり、個人サブスクリプションにそのまま適用できる数字ではありません。

</details>

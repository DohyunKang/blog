# 変数選択と次元削減

変数が 30 個あるデータと 5 個あるデータがある場合、同じモデルであれば通常、少ない方が扱いやすいです。学習が早く、解釈も容易で、過学習のリスクも低いためです。そのため、モデルを作成する前に変数を減らす段階を入れます。減らす方法は大きく 2 つに分かれます。

| 区分 | 行うこと | 結果変数 | 代表的な手法 |
|---|---|---|---|
| 変数選択 | 元の変数の一部のみを選択する | 元の変数をそのまま使用 | フィルター・ラッパー・インベード |
| 次元削減 | 変数を結合して新しい変数を作成する | 新しく作成した変数 | PCA など |

試験では、この 2 つの区別と、変数選択における 3 つの方式を区別する問題が頻出します。暗記すべきは「どのような基準で選ぶか」を把握しておくことです。

[前処理](#/post/bd-preprocessing) で欠損値とスケールを整えた後、モデルを選ぶ前 ([モデル設計](#/post/bd-model-design)) にこの段階が来るものと考えられます。

## フィルター：統計量だけでフィルタリングする

変数一つ一つに統計量をスコアとして付け、高いもののみを残します。モデルを回さないので高速です。scikit-learn のドキュメントでは、分散の小さい変数を捨てる `VarianceThreshold`、スコア上位 k 個を残す `SelectKBest` をフィルター系として紹介しています。スコア関数は分類では `chi2`, `f_classif`, `mutual_info_classif`、回帰では `f_regression` などです。

- 分散がほぼ 0 の変数は情報を持っていない。
- 相関係数が高い変数のペアは片方だけを残す ([相関分析](#/post/bd-eda-stats) を参照)。独立変数が互いに似すぎると多重共線性が生じる。
- 変数と目的変数の関係を検定統計量（F 値、カイ二乗など）でスコア化する。

弱点は変数を個別に見ている点です。単独では弱くても 2 つ合わせると効果がある変数の組み合わせを見逃します。

## ラッパー：モデルを回しながら選ぶ

変数の部分集合を変えながらモデルを反復して学習させ、性能の良い組み合わせを選びます。正確ですが高価です。ドキュメントでは `RFE`（再帰的変数除去）をラッパーとして扱っています。係数や重要度を出力するモデルを学習させ、最も弱い変数を除外し、希望する個数が残るまで反復します。交差検証で個数を決定してくれる `RFECV` もあります。

試験でよく見られる名称は別にあります。

| 方式 | 動き |
|---|---|
| 順次選択 | 空の状態から最も役立つ変数を一つずつ追加 |
| 逆順除去 | 全て入れて最も役立たない変数を一つずつ除外 |
| ステップ選択 | 追加した後に不要になった変数は再度除外 |

## インベード：学習しながら同時に選ぶ

モデルが学習する過程で変数の重要度が決定され、それに基づいて切り捨てます。ドキュメントでは `SelectFromModel` をメタトランスフォーマーとして紹介しています。重要度が閾値以上のもののみを残しますが、閾値は数値や `"mean"`, `"median"` などの文字列で指定します。

- L1 規制（ラッソ）：係数の一部を正確に 0 にして変数が除外されます。規制を強くするほど残る変数は減ります。ドキュメントの基準では、Lasso は alpha が大きいほど、分類モデルは C が小さいほど変数が減ります。
- L2 規制（リッジ）：係数を小さく抑えますが 0 に作りません。そのため変数選択というよりは係数の安定化に近い。
- ツリー系：ランダムフォレストなどのアンサンブルの変数の重要度を使います。

3 つの方式を一行で覚えるなら、フィルターのモデルの前、ラッパーはモデルを反復学習しながら、インベードはモデル学習の中で選ぶ、となります。速度はフィルターが速く、ラッパーが遅いです。

## 実際に回してみた結果

乳がん診断データ (`load_breast_cancer`, 569 行、変数 30 個) で試しました。訓練 70%、試験 30% に分割し、変数選択は訓練データのみで合わせました。試験データを見て変数を選べば評価が膨らむためです。

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.feature_selection import SelectKBest, f_classif, RFE, SelectFromModel
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
Xtr, Xte, ytr, yte = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y)

# 필터: 상관 0.9 넘는 쌍에서 하나씩 제거
corr = Xtr.corr().abs()
up = corr.where(np.triu(np.ones(corr.shape), k=1).astype(bool))
drop = [c for c in up.columns if (up[c] > 0.9).any()]
print(len(drop), Xtr.shape[1] - len(drop))   # 11 19

# 필터: F검정 점수 상위 5개
skb = SelectKBest(f_classif, k=5).fit(Xtr, ytr)

# 래퍼: RFE (표준화 후 로지스틱)
sc = StandardScaler().fit(Xtr)
rfe = RFE(LogisticRegression(max_iter=1000), n_features_to_select=5)
rfe.fit(sc.transform(Xtr), ytr)

# 임베디드: 랜덤포레스트 중요도 (평균 이상)
sfm = SelectFromModel(
    RandomForestClassifier(n_estimators=200, random_state=42)).fit(Xtr, ytr)
```

各方式で選んだ変数でロジスティック回帰を再度学習させ、試験データの精度を計りました。

| 変数構成 | 変数数 | 試験精度 |
|---|---|---|
| 全体 | 30 | 0.988 |
| 相関の高い変数の除外（フィルター） | 19 | 0.977 |
| RFE（ラッパー） | 5 | 0.953 |
| ランダムフォレスト重要度（インベード） | 10 | 0.936 |
| SelectKBest（フィルター） | 5 | 0.924 |

変数を 30 から 5 に減らしても精度は大きく低下しませんでした。ただし、この表はシードと分割のそれぞれ一つの結果であり、順位が常にこうなるわけではありません。目についたのは、SelectKBest が選んだ 5 つの変数のうち `mean perimeter`、`worst radius`、`worst perimeter` の 3 つがすべてサイズを表す類似した変数である点です。フィルタは変数を個別に評価するため、似たような変数が同時に選ばれました。一方、RFE は `area error` や `worst texture` のように性質の異なる変数が混ざっていました。このデータセットでは、その違いが精度の違いとして現れました。

<details>
<summary>変数の重要度上位値と分散フィルタ</summary>

ランダムフォレストの重要度上位 5 つは `worst perimeter`(0.141)、`worst area`(0.132)、`worst concave points`(0.122)、`worst radius`(0.085)、`mean concave points`(0.077) の順でした。半径・周長・面積は互いにほぼ同じ情報を表しているため、重要度が分散して割り当てられています。

`VarianceThreshold(threshold=1.0)` を適用すると 10 つが残り、残った変数はすべて値の単位が大きい変数（周長や面積など）でした。分散は単位に敏感なため、スケールが異なる変数の間で分散でフィルタリングすると、重要度とは無関係に単位の大きい変数だけが生き残ります。分散フィルタは標準化を行う前に使用する際は注意が必要です。

## 次元削減と PCA

選択はもともとの変数を選ぶことですが、PCA（主成分分析）は変数を線形結合して互いに直交する新しい軸を作成します。最初の軸が最も多くの分散を説明し、次いで 2 つ目の軸、といった具合です。文書の説明では、PCA は各変数の平均を引き算しますが、スケールは調整しません。単位が異なる変数が混ざっている場合は、まず標準化を行う必要があります。

同じデータで確認しました。標準化を行った後に PCA を適用したところ、説明分散の比率は PC1 で 0.452、PC2 で 0.196、PC3 で 0.089 でした。累積 90% に達するには 7 つ、95% に達するには 10 つの主成分が必要でした。標準化を行わずに PCA を適用すると、PC1 が全体の分散の 0.985 を占めました。単位が大きい変数（面積など）が一つの軸を独占したことになります。

```python
from sklearn.decomposition import PCA

pca = PCA(n_components=0.95).fit(sc.transform(Xtr))   # 누적 95%까지
print(pca.n_components_)                              # 10
Ztr = pca.transform(sc.transform(Xtr))
Zte = pca.transform(sc.transform(Xte))
m = LogisticRegression(max_iter=1000).fit(Ztr, ytr)
print(round(m.score(Zte, yte), 3))                    # 0.971
```

`n_components` に 0 と 1 の間の実数を指定すると、累積説明分散がその値に達する最小個数の主成分を選出します。30 つの変数が 10 つの主成分となり、精度は 0.971 でした。

試験では主成分の数を決定する基準が出ます。累積説明分散の比率が一定レベル（例えば 80〜90%）に達する地点、またはスクリープロットで曲がる「肘」の地点を使用します。計算の側面では、共分散（または相関）行列の固有値分解と結びついています。固有値が大きいほど、その軸が説明する分散が大きくなります。

PCA の欠点も併せて記載しておきます。

- 新しい軸は元の変数の混合であるため、意味を解釈するのが難しい。
- 分散の大きい方向を見つけるだけであり、目的変数との関連性までは見ていない。
- 線形変換であるため、曲線的な構造は捉えられない。

クラスタリングや可視化で PCA を使うのは、[非教師あり学習](#/post/bd-unsupervised) の項で続けます。

## 派生変数

既存の変数を組み合わせることで新しい変数を作ることも、特徴量エンジニアリングです。身長と体重から BMI を作ったり、日付から曜日・月を抽出したり、購入回数と金額から平均購入額を作ったりするなどが該当します。カテゴリ型はダミー（ワンホット）変数に変え、連続型は区間化（ビンニング）に変えることができます。派生変数はドメイン知識から生まれることが多く、モデルが自ら見つけにくい比率や差などの関係を直接与える効果があります。作成した変数が既存の変数とほぼ重複している場合は、再度相関分析でフィルタリングする必要があります。

## 試験対策としてまとめると

- フィルター・ラッパー・エンベッディングは「モデルを使うか、いつ使うか」で区別できます。
- 前進選択、後退除去、段階的選択はラッパー側の名称です。
- ラッソは L1 正則化なので変数が 0 になり、リッジは L2 正則化なので 0 になりません。
- PCA は選択ではなく新しい変数を作る方法であり、標準化が先です。
- 主成分の数は累積説明分散やスクリープロットで決定します。
- 特徴量選択は訓練データだけで学習し、試験データにはそのまま適用します。

実技では上記コードのように `train_test_split` の後に、`fit` は訓練データのみ、`transform` は両方に使う順序が基本です。特徴量選択と PCA も同じルールです。試験日程や受験方法は公式サイトで確認してください。

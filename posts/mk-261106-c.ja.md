マーケティング自動化でコンテンツを複数のチャネルに展開すると、どのリンクから訪問が流入したかを区別する課題が生じます。その解決策としてリンクの末尾に追加する UTM パラメータがあります。しかし、値を手動で入力するとすぐに誤りが生じやすいため、コードによってリンク生成を固定する方法を整理しました。根拠は Google Analytics のヘルプページです。

## UTM パラメータ
ヘルプページで定義されている内容は以下の通りです。

| パラメータ | 意味 |
|---|---|
| utm_source | 流入元。検索エンジン、ニュースレターなど |
| utm_medium | メディア。CPC、バナー、メールなど |
| utm_campaign | プロダクト・スローガン・プロモーションコード。spring_sale など |
| utm_id | キャンペーン ID。キャンペーンデータをアップロードする際に使用する ID と一致させます |
| utm_term | 有料キーワード |
| utm_content | 同じメール内の CTA 2 つのように素材を区別するために使用します |

ヘルプページでは、パラメータを付与する際 `utm_source`、`utm_medium`、`utm_campaign` は必ず使用するよう指示されています。GA4 ではこれらの値が存在する場合、セッションをカスタムキャンペーンとして処理し、値がレポートのソース・メディア・キャンペーン次元にそのまま対応します。

## 誤りによって生じる問題
ヘルプページによると、値は大文字小文字を区別します。`utm_source=google` と `utm_source=Google` は異なる集計結果となります。また `SpringSale` と `Spring_Sale` も異なる値です。ヘルプページでは小文字を標準として推奨しています。プラットフォームごとに source を 1 つに統一し、チャネルごとに medium を 1 つに定め、campaign はキャンペーン名と正確に一致させるよう指示されています。値が欠落するとレポートには "(not set)" が表示されます。

自動化の文脈では、1 つのコンテンツを複数のチャネル向けに作成するため、リンクも一度に生成されます。この際、手動で入力すると上記の問題がそのまま拡大します。

## コードによる固定
ルールは 3 つに定めました。値は小文字とアンダースコアで正規化します。medium は許可リストに含まれていない場合はブロックします。既存の `utm_` パラメータは削除して再度追加します。以下のコードを実行して出力を確認しました。

```python
import re
from urllib.parse import urlsplit, urlunsplit, parse_qsl, urlencode

ALLOWED_MEDIUM = {"email", "cpc", "paid_social", "social", "referral"}

def slug(v):
    v = v.strip().lower()
    v = re.sub(r"[\s\-]+", "_", v)
    return re.sub(r"[^a-z0-9_]", "", v)

def build(url, source, medium, campaign, content=None):
    medium = slug(medium)
    if medium not in ALLOWED_MEDIUM:
        raise ValueError(f"medium not allowed: {medium}")
    p = urlsplit(url)
    q = [(k, v) for k, v in parse_qsl(p.query) if not k.startswith("utm_")]
    q += [("utm_source", slug(source)), ("utm_medium", medium), ("utm_campaign", slug(campaign))]
    if content:
        q.append(("utm_content", slug(content)))
    return urlunsplit((p.scheme, p.netloc, p.path, urlencode(q), p.fragment))
```

実行結果です。

```
build("https://example.com/launch?ref=a", "News Letter", "Email", "Spring Sale", "Top-CTA")
-> https://example.com/launch?ref=a&utm_source=news_letter&utm_medium=email&utm_campaign=spring_sale&utm_content=top_cta

build("https://example.com/launch", "Instagram", "paid-social", "SpringSale")
-> https://example.com/launch?utm_source=instagram&utm_medium=paid_social&utm_campaign=springsale

build("https://example.com/launch", "x", "Newsletter", "a")
-> ValueError: medium not allowed: newsletter
```

3 つ目の例のように、許可リストにない medium はエラーでブロックされます。リストは使用するチャネルに合わせて拡張可能です。注意点として、2 つ目の結果のように `SpringSale` を正規化すると `springsale` になり、同じキャンペーンを `Spring Sale` と記述すると `spring_sale` となり、互いに異なる値になります。正規化は大文字小文字の一致のみ対応するため、単語区符の調整はできません。したがって、campaign 名は 1 か所（キャンペーンリスト）から取得する必要があります。

## 自動化に適用する際
- キャンペーンリストを 1 つのファイルに置き、記事・動画の公開段階でその名前のみを使用します。
- `utm_content` には素材識別子を埋め込み、同じ記事のバージョンを区別します。
- ヘルプページでは UTM パラメータが Landing page + query string 次元では欠落し、Page location 次元に表示されると記載されています。レポート作成時にどの次元を見るかに合わせてください。

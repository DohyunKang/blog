정렬·탐색·복잡도는 외울 표 하나와 손으로 따라가는 연습 몇 번이면 점수가 나오는 단원이다. 정렬마다 시간복잡도와 안정성을 짝지어 두고, 이진 탐색과 해시는 동작을 직접 한 번씩 그려 보면 된다. 시험 일정과 응시료는 공식 사이트에서 확인한다.

## 이 단원에서 나오는 것

크게 네 덩어리다.

| 덩어리 | 물어보는 모양 |
|---|---|
| 시간복잡도 | 코드나 알고리즘의 Big-O 고르기, O 표기 크기 순서 |
| 정렬 | 알고리즘별 평균·최악 복잡도, 안정 정렬 고르기, 한 단계 뒤의 배열 상태 |
| 탐색 | 순차·이진 탐색의 비교 횟수, 이진 탐색의 전제 조건 |
| 해시 | 해시 함수 계산, 충돌이 났을 때 처리 방식 |

자료구조는 [자료구조 글](#/post/jb-data-structure)에서 따로 다뤘고, 파이썬 쪽 감각은 [시간복잡도와 파이썬 기본](#/post/algo-complexity)에 적어 뒀다.

## 시간복잡도

입력 크기 n이 커질 때 연산 횟수가 늘어나는 모양을 적는 방법이다. 상수배와 낮은 차수는 버리고, 보통 최악의 경우를 기준으로 쓴다. 시험에서는 크기 순서를 외워 두면 편하다.

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

코드로 나오면 반복문 구조만 본다.

- 단일 반복문, n번 돈다. O(n)
- 중첩 반복문 두 겹, 둘 다 n번. O(n²)
- 반복마다 변수를 절반으로 줄인다(i = i // 2 같은 것). O(log n)
- 바깥은 n번, 안쪽은 매번 절반으로 줄면 O(n log n)
- 반복문이 연달아 있으면 큰 쪽만 남긴다. O(n) 뒤에 O(n²)가 있으면 O(n²)

Big-O 외에 Ω(최선)·Θ(평균, 정확한 경계) 표기도 이름 정도는 알아 둔다.

## 정렬 비교표

가장 자주 나오는 표다. 안정성은 값이 같은 원소의 원래 순서가 유지되는지를 말한다.

| 알고리즘 | 평균 | 최악 | 안정 | 한 줄 특징 |
|---|---|---|---|---|
| 버블 | O(n²) | O(n²) | 안정 | 이웃끼리 비교해 교환, 한 바퀴에 가장 큰 값이 끝으로 간다 |
| 선택 | O(n²) | O(n²) | 불안정 | 남은 것 중 최솟값을 골라 앞자리와 교환 |
| 삽입 | O(n²) | O(n²) | 안정 | 이미 정렬된 앞부분에 끼워 넣는다, 거의 정렬된 입력엔 O(n)에 가깝다 |
| 쉘 | 간격에 따라 다름 | O(n²) | 불안정 | 간격을 두고 삽입 정렬을 반복해서 줄인다 |
| 퀵 | O(n log n) | O(n²) | 불안정 | 피벗 기준으로 나눠서 재귀, 이미 정렬된 입력에 첫 원소를 피벗으로 잡으면 최악 |
| 병합 | O(n log n) | O(n log n) | 안정 | 반으로 나눠 정렬한 뒤 합친다, 보조 공간이 필요 |
| 힙 | O(n log n) | O(n log n) | 불안정 | 힙을 만들고 루트를 하나씩 꺼낸다 |
| 기수 | O(d(n+k)) | 동일 | 안정 | 자릿수별로 분배, 비교를 하지 않는다 |

비교 기반 정렬은 어떻게 해도 평균 O(n log n)보다 빨라지지 않는다는 점, 병합·힙은 최악도 n log n이라는 점, 퀵이 최악에 n²이 된다는 점이 문제로 자주 나온다.

### 외우는 요령

- 안정 정렬은 "버삽병기"(버블·삽입·병합·기수)로 묶어 두고 나머지는 불안정으로 본다.
- n log n 정렬은 퀵(평균)·병합·힙이고, 그 셋 중 최악이 n²인 건 퀵뿐이다.

## 정렬은 손으로 따라가기

시험에는 "한 단계 후의 배열"이 나온다. 버블 정렬로 [5, 1, 4, 2, 8]을 오름차순으로 정렬하면 이렇게 된다.

```
시작     5 1 4 2 8
1회전    1 4 2 5 8   (5가 끝으로 이동)
2회전    1 2 4 5 8   (4와 2 교환, 이후 정렬 완료)
```

선택 정렬이면 1회전에서 최솟값 1을 맨 앞 5와 바꾼다. 같은 입력도 알고리즘마다 중간 상태가 달라서, 몇 회전째인지와 어느 알고리즘인지를 같이 읽어야 한다.

<details>
<summary>파이썬 구현과 검증(버블·선택·삽입·병합·퀵)</summary>

아래 코드는 무작위 배열 200개로 내장 `sorted()` 결과와 같은지 비교해서 확인했다.

```python
def bubble(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        changed = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                changed = True
        if not changed:
            break
    return a

def selection(a):
    a = a[:]
    for i in range(len(a) - 1):
        m = min(range(i, len(a)), key=a.__getitem__)
        a[i], a[m] = a[m], a[i]
    return a

def insertion(a):
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

def quick(a):
    if len(a) <= 1:
        return a
    p = a[len(a) // 2]
    return (quick([x for x in a if x < p])
            + [x for x in a if x == p]
            + quick([x for x in a if x > p]))
```

병합 정렬에서 `<=`로 비교하는 이유는 값이 같을 때 왼쪽을 먼저 꺼내 안정성을 지키기 위해서다. 버블의 `changed` 플래그는 이미 정렬된 입력에서 한 바퀴로 끝내게 해서 최선이 O(n)이 되게 한다.
</details>

## 탐색

순차 탐색은 처음부터 차례로 찾는다. 정렬 여부와 상관없이 쓸 수 있고, 최악 n번, 평균은 대략 (n+1)/2번 비교한다. 시간복잡도는 O(n).

이진 탐색은 정렬된 데이터에서 가운데와 비교해 절반씩 버린다. 정렬되어 있어야 한다는 전제가 시험에 가장 자주 나오고, 시간복잡도는 O(log n)이다. 원소가 1,000개면 비교는 최대 10번 안쪽으로 끝난다(2¹⁰ = 1,024).

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

binary_search([1, 3, 5, 7, 9, 11], 7)   # 3
```

위 함수는 무작위 정렬 배열에서 있는 값과 없는 값을 모두 넣어 결과가 맞는지 확인했다. 이진 탐색을 도는 순서는 "가운데 값이 찾는 값보다 크면 왼쪽, 작으면 오른쪽"이고, 시험에서는 구간 [lo, hi]가 어떻게 줄어드는지를 한 줄씩 적어 보면 풀린다. 파이썬에서 실제로 쓰는 방법은 [정렬과 이분 탐색](#/post/algo-sort-search)에 있다.

## 해시

키를 해시 함수에 넣어 저장 위치를 바로 계산하는 방식이라, 평균적으로 O(1)에 찾는다. 다만 서로 다른 키가 같은 자리로 가는 충돌이 나면 느려지고, 최악에는 O(n)이 된다. 파이썬 공식 문서의 시간복잡도 표도 dict의 조회·삽입·삭제와 set의 `in`이 평균 O(1), 해시가 전부 충돌하는 최악엔 O(n)이라고 적고 있다. 반면 리스트의 `x in l`은 순차 탐색이라 O(n)이다.

해시 함수 종류는 이름과 뜻을 묶어 둔다.

| 방식 | 내용 |
|---|---|
| 제산(나누기) | 키를 테이블 크기로 나눈 나머지 |
| 제곱 가운데 | 키를 제곱해서 가운데 몇 자리를 사용 |
| 폴딩 | 키를 몇 조각으로 나눠 더하거나 XOR |
| 숫자 분석 | 키의 자릿수 중 고르게 퍼진 자리만 사용 |
| 기수 변환 | 다른 진법으로 바꾼 값을 이용 |

충돌 해결은 두 갈래다.

- 개방 주소법: 비어 있는 다른 칸을 찾아 넣는다. 선형 조사, 이차 조사, 이중 해시가 있다.
- 체이닝(분리 연결): 같은 칸에 연결 리스트로 이어 붙인다.

제산법 예시로, 테이블 크기 5에서 12, 17, 22, 7을 넣으면 전부 나머지가 2다. 체이닝이면 2번 칸에 12 → 17 → 22 → 7이 줄줄이 달린다. 이 상황이 해시가 O(n)으로 떨어지는 최악의 모습이다.

## 자주 틀리는 부분

- 이진 탐색은 O(log n)이지만 정렬이 먼저다. 정렬이 안 된 데이터에는 쓸 수 없다.
- 퀵 정렬의 "평균 n log n"만 외우고 최악 n²을 놓치는 경우가 많다.
- 안정성은 시간복잡도와 별개다. 평균이 같아도(퀵·병합) 안정성이 다르다.
- 해시는 "항상 O(1)"이 아니라 평균이 O(1)이다.
- 중첩 반복문이어도 안쪽 범위가 절반씩 줄면 n²이 아니다.

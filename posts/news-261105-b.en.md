## What Problem Does It Solve?

When running multiple coding agents simultaneously, each requires its own working directory; otherwise, they overwrite each other's files when modifying the same folder. Git already provides `git worktree` for this purpose, which creates separate folders per branch within a single repository.

However, using it can be cumbersome. The project site notes that creating a new worktree requires typing the branch name three times: first with `git worktree add -b feat ../repo.feat`, then navigating into it with `cd ../repo.feat`. Worktrunk aims to make working with worktrees "as easy as branches." It allows referencing worktrees by branch name and calculates folder paths using configurable templates.

## Key Commands

Here are the commands listed in the README and on the site:

| Command | Function |
|---|---|
| `wt switch --create feature-auth` | Creates a branch and worktree, then moves into that folder |
| `wt switch -x claude -c feature-a -- 'Add user authentication'` | Creates a worktree and immediately runs `claude` within it |
| `wt list` | Lists worktrees and their status (with `--full`, includes CI status and AI-generated summaries) |
| `wt step commit` | Commits staged changes; can also generate commit messages via LLM |
| `wt merge main` | Performs squash, rebase, merge, and cleanup in one go |
| `wt remove` | Deletes worktrees after merging is complete |
| `wt switch pr:123` | Checks out a PR branch |

The second line of the table clearly illustrates the tool's purpose. By opening a new worktree for each agent using `-x`, you can delegate features A, B, and C to different agents within a single repository with just three commands.

## Installation and Setup

Installation options listed in the README include Homebrew (`brew install worktrunk && wt config shell install`), Cargo, conda/pixi, and Arch Linux packages. For Windows, use `winget install max-sixty.worktrunk`. To avoid name conflicts with Windows Terminal's `wt`, it is installed as `git-wt`. Shell integration (`wt config shell install`) is required for folder navigation.

Additional features mentioned in the README include:

- **Hooks**: Execute commands at specific points, such as when creating a worktree or before/after merging. It recommends setting up dependency installation and starting development servers immediately after creation (post-start).
- **`hash_port` template filter**: Assigns different ports for development servers to each worktree.
- **Build cache sharing**: Shares build caches like `target/` and `node_modules/` across APFS, btrfs, and XFS using copy-on-write.

## Things to Consider When Using It

Even with separate worktrees, conflicts will still occur if two agents modify the same file; merging them will fail. The tool reduces the hassle of creating and cleaning up folders, but deciding how to split tasks remains a human responsibility.

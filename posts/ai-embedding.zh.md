嵌入是将文本（或图像）转换为数字列表，使得“语义相近的内容在数值上也彼此接近”；而向量搜索则是在这些数字中寻找彼此接近的项。

## 什么是嵌入

OpenAI 文档将嵌入描述为表示文本的浮点数向量（列表）。两个向量之间的距离反映了文本之间的相关性：距离越近，相关性越高。

用地图来类比就容易理解了。首尔和釜山的位置由纬度和经度这两个数字确定，如果两个坐标相近，那么这两座城市也就彼此接近。嵌入就是将这种坐标附加到句子上的过程。只不过这里的数字不是 2 个，而是数百甚至数千个。根据文档中提到的 OpenAI 模型标准，text-embedding-3-small 的基础维度为 1536，text-embedding-3-large 则为 3072。不同模型的维度数量各不相同。

这些坐标并非由人工设定。嵌入模型在学习过程中被训练将具有相似语境的文本放置在彼此附近。这一理念最早在 2013 年 word2vec 论文（Mikolov 等）中通过单词级别的向量表示广泛传播。根据绿色标准，该论文提出了两种从大数据中以低成本学习单词连续向量表达的结构，并声称在当时达到了单词相似度测试的最高水平。目前的句子和文档嵌入可被视为这一思路的延伸，尽管我尚未完全追溯其完整的谱系。

关于 LLM 在内部将单词处理为数字的内容，请参阅 [详细说明 → LLM](#/post/ai-llm)；此处所指的嵌入更接近于“为搜索和比较用途，将一篇文章转换为一个向量”。

## 余弦相似度

衡量两个向量接近程度的方法有几种，在文本领域最常用的是余弦相似度。它考察两个向量之间的夹角：方向相同时为 1，垂直时为 0，方向相反时为 -1。我们不看向量的长度，只看方向。

| 值 | 含义 |
|---|---|
| 接近 1 | 方向几乎相同，语义相似 |
| 接近 0 | 相关性较弱 |
| 负数 | 方向相反（在文本嵌入中较为罕见） |

OpenAI 文档推荐使用余弦相似度，并指出其自身的嵌入向量长度已归一化为 1，因此只需计算内积即可得到相同结果。也有说法称余弦距离与欧几里得距离会给出相同的排序。这是因为长度均为 1 的向量之间，角度顺序与距离顺序是一致的。因此在实际代码中，常见做法是“先归一化再计算内积”。

<details>
<summary>详细解析：余弦相似度公式</summary>

对于两个向量 a 和 b，余弦相似度如下：

cos(a, b) = (a · b) / (|a| × |b|)

其中 a · b 表示将对应位置的数字相乘后求和（即内积），|a| 表示向量的长度。如果预先将两个向量的长度调整为 1，则分母变为 1，此时内积即为余弦相似度。在存储归一化结果时只需进行一次处理，搜索时仅需进行乘法和加法运算，速度更快。

</details>

## 与关键词搜索有何不同

关键词搜索检查问题中的单词是否原样存在于文档中。在查找确切术语、产品代码或错误消息时效果良好。但如果用词不同则无法找到。

| | 关键词搜索 | 向量搜索 |
|---|---|---|
| 依据 | 单词是否重叠 | 语义是否接近 |
| 用“退款方法”查找“支付取消流程”文档 | 因用词不同容易遗漏 | 语义相近即可捕获 |
| 查找错误代码 `E4012` | 能精确匹配 | 对无明确含义的字符串效果较差 |
| 结果原因 | 显示哪些单词匹配成功 | 难以解释为何判定为接近 |
| 所需准备 | 索引 | 嵌入模型 + 向量存储库 |

因此，在实际工作中，两者混合使用的情况很常见（混合搜索）。这部分内容并非来自官方文档的确认，而是基于普遍说法的理解。将搜索结果附加给 LLM 以生成回答的方式，将在 [详细说明 → RAG](#/post/ai-rag) 中继续介绍。

## 无需真正嵌入模型即可运行的最小代码示例

即使不使用真正的嵌入模型，仅用 numpy 也能实现“创建向量、归一化、寻找相近项”的核心逻辑。下方是一个人为构造的玩具示例，其维度被刻意设置为 3（动物、食物、交通工具）。真正的嵌入模型则是直接生成这些数字。此代码已在本地 PC 上运行并验证通过（numpy 2.5.4）。

```python
import numpy as np

# 손으로 만든 3차원 벡터 (축: 동물, 음식, 탈것)
docs = {
    "고양이가 잔다":     [0.9, 0.1, 0.0],
    "강아지가 뛴다":     [0.8, 0.1, 0.1],
    "김치찌개를 끓인다": [0.1, 0.9, 0.0],
    "자전거를 탄다":     [0.1, 0.0, 0.9],
}
names = list(docs)
M = np.array([docs[n] for n in names], dtype=float)
M /= np.linalg.norm(M, axis=1, keepdims=True)   # 길이 1로 정규화

def search(q, k=2):
    q = np.array(q, dtype=float)
    q /= np.linalg.norm(q)
    scores = M @ q                  # 정규화했으니 내적 = 코사인
    for i in np.argsort(-scores)[:k]:
        print(f"{scores[i]:.3f}  {names[i]}")

search([0.85, 0.15, 0.0])           # "동물 쪽" 질문
```

运行后，“猫睡觉”得分约为 0.998，“狗奔跑”得分约为 0.991，排名靠前；而食物和交通工具相关的句子则被排到后面。

若要替换为真正的模型，只需替换生成数字的部分即可。下方是使用 sentence-transformers 的示例：

```python
# pip install sentence-transformers 필요
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("all-MiniLM-L6-v2")   # 모델 이름은 예시
vecs = model.encode(["환불 방법", "결제 취소 절차"], normalize_embeddings=True)
print(vecs @ vecs.T)   # 정규화했으니 내적 = 코사인 유사도 표
```

## 向量数据库与 ANN

这段代码将查询向量与整个文档集进行比较。如果文档数量在数百个，这不成问题；但如果达到数百万个，对每个查询都进行全量比较就会非常缓慢。因此，我们采用一种更快的方法：不是寻找“绝对最近”的邻居，而是迅速找到“足够接近”的邻居。这种方法称为近似最近邻搜索（ANN, Approximate Nearest Neighbor）。它以牺牲少量精度为代价来换取速度。

向量数据库用于存储向量、构建 ANN 索引，并提供查找最近邻居的功能。通常还附带基于元数据（如日期、作者等）进行过滤的功能。市面上有许多产品名称，但本文并未对特定产品进行比较。

在常见的 ANN 算法中，HNSW 出现的频率很高。根据 2016 年的论文（Malkov & Yashunin）摘要，HNSW 由分层近邻图构成，其结构是从高层粗略扫描，再逐层向下细化搜索。论文声称其搜索复杂度呈对数级增长。也有解释称其结构与跳表（skip list）相似。

打个比方，就像在全世界地图上寻找道路时，先大致沿高速公路行驶，然后再切换到当地街道地图。这个比喻是我为了便于理解而添加的，并非论文原文表述。

<details>
<summary>详细解析：精度的代价</summary>

ANN 可能会遗漏真正的最近邻居。因此，我们使用“召回率（recall）”这一指标来衡量“在真正最近的 top-k 个结果中找到了多少个”。HNSW 的摘要指出，其邻居选择启发式方法在高召回率区间能显著提升性能。增大索引参数会提高召回率，但会导致速度和内存占用变差，这是一种典型的权衡（trade-off）。

</details>

## 常见误区

- **嵌入即理解语义**：这更接近于表示在训练数据中具有相似上下文的文本被放置在相近位置。“相近”的标准取决于模型所学的内容。
- **相似度接近 1 就意味着意思相同**：据说即使是反义词的句子，只要主题相同也可能表现出较高的相似度。我尚未亲自进行实验验证。
- **向量搜索可完全替代关键词搜索**：对于精确的代码或名称检索，关键词搜索往往更好。因此通常将两者结合使用。
- **维度越高越好**：OpenAI 文档指出可以通过 `dimensions` 参数降低维度以适配存储空间。虽然高维包含更多信息，但也会增加存储成本。关于质量差异有多大，除了本文档外，我并未进行独立测量。
- **更换模型后可直接复用旧向量**：由于每个模型拥有不同的坐标系，混合比较是不允许的。这是基于原理的推断，我在文档中并未直接验证这一点。

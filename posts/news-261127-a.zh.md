这一周在 X 和 YouTube 上看到最多的模型名字是 Inkling 2 Mini。这是 Thinking Machines Lab 在11月20日连权重一起公开的小模型,算是他们本月初发布的 [Inkling 2 Small](#/post/news-261106-a) 的弟弟。我读了官方发布文章和 Hugging Face 上的模型卡,没有自己下载运行。基准分数都是公司在自己页面上写的。

## 哪里不一样
光看规格,它是现在常见的小型 MoE 模型。MoE(Mixture of Experts)是指模型里有很多叫"专家"的小网络,每个 token 只挑其中几个来用。总共26.4B参数,每个 token 只激活3.4B,从128个专家里选8个。输入文本和图片,输出文本,上下文窗口最大1M token。文件约20GB,据说内存32GB以上的 Mac 或显存相近的 GPU 能跑。许可证是 Apache 2.0。

不一样的是模型卡"模型类型"一栏里的一个词:looped transformer。循环 Transformer 就是让每个 token 多次重复经过同一组层的 Transformer。公司说这是他们第一次公开这种模型。

## 中间的层跑三遍
一共24层,每6层一块,分成四块。第一块和最后一块只跑一次。中间两块(12层)用同一套权重跑三遍。所以存下来的是24层,一个 token 实际经过的是48次。

为什么是中间:直觉是前面和后面的层主要在 token 和内部表示之间做翻译,抽象的思考发生在中间。实验里,循环中间12层比循环最后12层,在28项评估中有27项更好。

每一圈的结果不是直接覆盖。上一圈中间层的输出叫"消息",下一圈从第一块的输出和这条消息混合后开始。混合比例由一个学出来的门控决定。训练一开始完全挡住消息,之后慢慢打开,这样模型一开始就和不循环的模型一样,训练不会崩。这是我觉得最有意思的地方。改结构的同时,很小心地安排了不把训练搞坏的办法。

当然不是免费的。中间跑三遍,每个 token 的计算量比激活的3.4B要多,按公司的算法大约5.4B。模型卡的局限部分也写了:不要只看激活参数量来估计计算量。

## 怎么变小的
它不是一开始就小。训练到中期为止有384个专家。某个时间点把用得最少的三分之二砍掉,只留128个。然后用从更大的内部 Inkling 模型蒸馏出来的1T token 重新训练,让剩下的专家接手被删掉的那部分工作。蒸馏是让小模型模仿大模型的回答来学习的方法。公司把这个过程叫 pruning and healing。

大部分权重从训练时就用 NVFP4(4位),只有最后4层是 MXFP8(8位)。发布也用同样格式,所以没有事后量化带来的损失。

## 少写思考也能解
公司对循环好处的说法是:同一组层多跑几遍,在输出一个 token 之前内部能做的计算就多了,所以用更少的思考 token 就能得到同样的答案。官方文章的例子里,循环1次时因为出错又回头,用的思考 token 是循环5次时的两倍多。

接着公司自己提出了担心。现在我们靠读模型写出的思考过程(CoT)来监督它有没有做奇怪的事。内部计算变多,不写出来就跳过的推理也可能变多。于是他们一起公开了一个可以把循环次数设成1到5次的研究模型(TML-d24-varloop-research)来做实验。在不允许 CoT 的情况下,模型能完成的任务长度(按人类耗时算)从循环1次的16秒增加到3次的37秒,再往上基本持平。不过在需要连续查好几张表的题目上,一直到训练时没用过的10次循环都还在变好。CoT 仍然保持人能读懂的状态,在这个规模上监督并没有明显变难,这是公司的结论。有没有独立验证,我没能确认。

循环做不到的事也写了。想得更深,但知道的不会变多。事实知识基本取决于总参数量,所以闭卷事实问答的分数几乎不随循环次数变化。他们说这个空缺靠用好搜索和工具来补。

## 为什么这么火
按官方表格,DeepSWE v1.1 48.2%,SWE-bench Verified 79.2%,在100B以下的开放模型里智能体编程基准最高。很多项和对比对象 Qwen3.8-27B 不相上下。再加上"笔记本上能跑"。官方文章里还有研究员在飞行模式的 MacBook Pro 上做飞行模拟器的演示视频。

YouTube 上每天都有好几个"在我的 GPU 上跑了一下""和 Qwen 3.8 27B 编程对决"之类的视频。也有在12GB、16GB 显存上跑的,但那是量化版,和官方推荐配置不一样。Reddit 的反应没能确认。

模型卡的局限部分挺坦白。说调试代码时有时会反复做同样的检查走不出来,用工具时可能不经确认就删除或覆盖文件,所以要在沙箱里跑。英语以外质量可能下降。没有提到韩语,所以没能确认。

## 作为初学者
让小模型变聪明,以前主要是先训大再缩小。这个是靠重复使用同一组层来换深度。内存省一点,计算多花一点的交易。也学到了:挑本地模型时只看"多少B",可能会把速度估错。

从 PM 的角度,局限部分可以直接当检查清单用:给输出 token 和智能体轮数设上限,删除类操作前先要确认。模型越小,这些护栏越应该是默认设置。

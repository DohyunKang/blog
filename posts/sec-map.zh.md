## 1. 基础工具

**加密、哈希与认证基础**：加密是隐藏信息并可还原的过程；哈希是将信息转换为固定长度且不可逆的摘要，仅用于比对一致性；签名则是验证信息来源及内容是否被篡改。由于各自解决的问题不同，明确其应用场景后，即可一次性理解直至 TLS 的完整流程。
[详情 → 加密、哈希与认证基础](#/post/sec-authn-crypto)

## 2. 网络攻击入口

**Web 漏洞与 OWASP**：OWASP Top 10 列出了 Web 应用中高频出现的风险类别。深入分析其中的 SQL 注入、XSS 和 CSRF，其共同根源在于“数据被当作命令执行”。文中已通过简洁的演示代码加以验证。
[详情 → Web 漏洞与 OWASP](#/post/sec-owasp)

## 3. 敏感值管理

**密钥与秘密管理**：对于 API 密钥、数据库密码等敏感信息（Secrets），核心策略并非追求绝对隐藏，而是确保一旦泄露能立即废弃并重新颁发。内容涵盖存储、轮换、最小权限原则以及应对 Git 泄露场景的措施。
[详情 → 密钥与秘密管理](#/post/sec-keys)

## 4. AI 相关风险

**提示词注入与 AI 安全**：AI 模型难以区分指令与数据，导致输入文本中的某一行可能被误当作命令执行。目前尚无完全防御的方法，因此即使发生注入，也应将损害控制在最小范围，即通过限制权限作为防御的核心。
[详情 → 提示词注入与 AI 安全](#/post/sec-prompt-injection)

## 5. 个人信息保护

**个人信息与数据保护**：个人信息不仅指姓名，任何能与其他信息结合识别特定自然人的数据均属于此类。因此，相较于加密，首要原则是“最小化收集”和“缩短持有时间”。
[详情 → 个人信息与数据保护](#/post/sec-privacy)

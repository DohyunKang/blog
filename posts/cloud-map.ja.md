サービスを作成した後、どこにデプロイし、どのように公開し、公開後はどのように監視すべきかが残ります。このシリーズは、その順序に沿って 6 つの概念を取り扱います。大きな用語を一行ずつ先に記載し、さらに詳しく知りたい場合は下のリンクへ進みます。順序はサーバーをレンタルすることから始まり、運用へと向かいます。

## 全体の流れ

```
클라우드(서버를 빌린다)
   ├─ 앱을 묶어 옮긴다 ........ Docker·컨테이너
   └─ 서버 관리를 맡긴다 ...... 서버리스
코드 → 테스트 → 배포 ........... CI/CD
설정과 비밀번호를 코드 밖에 둔다 .. 환경변수·시크릿
뜬 뒤에 상태를 지켜본다 ........ 모니터링·로그·알림
```

## 1. どこにデプロイするか

**クラウドの基礎**: サーバーを購入するのではなく、使用量に応じてレンタルする方式です。サーバーのどのレイヤーを担当するかによって IaaS、PaaS、SaaS に分類され、リージョン・AZ という位置の概念と、使用量に応じた課金構造が付きます。
[詳しく → クラウドの基礎](#/post/cloud-basics)

**Docker とコンテナ**: アプリケーションと実行に必要なファイルを束ねて、隔離されたプロセスとして動作させるツールです。自分の PC では動いていたのにサーバーでは動かない問題を減らすために使います。
[詳しく → Docker とコンテナ](#/post/cloud-docker)

**サーバーレス**: サーバーがないわけではなく、オン・オフやスケーリングの作業をクラウドが引き受け、私は関数のコードだけをアップロードする方式です。リクエストが来る时才動し、費用もその時だけ発生します。
[詳しく → サーバーレス](#/post/cloud-serverless)

## 2. どう公開するか

**CI/CD とデプロイ戦略**: コードをマージし、テストして公開するプロセスを自動化するものです。最後の公開段階で失敗しないためのデプロイ方式の 3 つも同時に扱います。
[詳しく → CI/CD とデプロイ戦略](#/post/cloud-cicd)

**環境変数とシークレット管理**: パスワードやキーはコードの外に置くのが基本です。.env から始まり、シークレットマネージャーやローテーションまでの段階があります。
[詳しく → 環境変数とシークレット管理](#/post/cloud-secrets)

## 3. 公開後どう守るか

**モニタリング・ログ・通知**: サービスが不調であることをユーザーより先に知るための準備です。メトリクス・ログ・トレースに分けて扱い、通知はどのような対象に設定すべきか整理しました。
[詳しく → モニタリング・ログ・通知](#/post/cloud-observability)

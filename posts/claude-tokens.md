Claude 사용량은 내가 친 글보다, 매 요청마다 다시 실려 가는 대화 기록과 도구 결과에서 더 많이 나가고, 아끼는 법도 대부분 그 맥락을 가볍게 두는 쪽이다.

이 글은 Anthropic 공식 문서 세 군데(Claude Code 비용 관리, Claude Code의 프롬프트 캐싱, API의 프롬프트 캐싱)를 열어 보고 정리한 것이다. 내가 어떻게 쓰는지는 적지 않았고, 문서에서 확인한 것만 적었다.

## 토큰이 어디서 나가나

Claude Code 문서는 이렇게 설명한다. 모델은 요청 사이에 아무것도 기억하지 못해서, 메시지를 보낼 때마다 시스템 프롬프트, 프로젝트 맥락(CLAUDE.md 등), 지금까지의 모든 메시지와 도구 결과, 새 메시지를 통째로 다시 보낸다. [자세히 → 컨텍스트](#/post/ai-context)

여기서 두 가지가 눈에 띄었다.

- 도구를 한 번 쓸 때마다 요청이 하나 더 나가고, 그 요청에도 지금까지의 기록 전체가 실린다.
- 하루 종일 열어 둔 세션에서 한 줄만 물어도, 그 세션의 대화 전체에 대한 사용량이 잡힌다. 캐싱 덕에 단가는 낮지만 0은 아니다.

그래서 토큰 비용은 "내가 몇 글자 썼나"가 아니라 "지금 맥락이 얼마나 큰가 × 요청이 몇 번 나갔나"에 가깝다. 이건 문서 내용을 합쳐 보면 그렇게 읽힌다는 정리다. [자세히 → 컨텍스트 윈도우](#/post/ai-context-window)

문서가 꼽는 긴 세션에서 사용량이 늘어나는 이유를 표로 줄이면 이렇다.

| 원인 | 문서 설명 |
|---|---|
| 긴 맥락 | 전체 대화가 매 요청에 실린다 |
| 캐시 미스 | 캐시 수명보다 오래 쉬고 오면 첫 메시지가 맥락 전체를 다시 처리한다 |
| 예약 작업·다른 세션 메시지 | 세션이 놀고 있어도 새 턴이 생기면 전체 맥락이 실린다 |
| 하위 에이전트 | 각자 요청을 따로 보내므로 메인 대화 위에 더해진다 |
| 압축 | `/compact`도 요약할 대화를 읽어야 해서 큰 맥락이면 큰 요청이다 |

이미지는 문서에서 비용 얘기보다 캐시 얘기로 나온다. 요청에 실을 수 있는 이미지와 PDF 수·크기에 한도가 있고, 넘으면 Claude Code가 오래된 것부터 한 묶음씩 빼서 보낸다. 빼면 그 메시지부터 다시 처리해야 해서 그 턴이 느리고 비싸진다.

## 프롬프트 캐싱

캐싱은 요청의 앞부분(prefix)이 이전 요청과 똑같으면 그 부분을 다시 계산하지 않고 싼 단가로 읽는 기능이다. API 문서 기준으로 prefix는 `tools → system → messages` 순서이고, 일치는 글자와 이미지까지 100% 같아야 한다. 출력은 캐싱을 쓰든 안 쓰든 같다.

단가는 모델마다 다르지만 문서 표를 보면 윤곽은 이렇다.

| 항목 | 기본 입력 대비 |
|---|---|
| 캐시 읽기 | 기본 0.1배. 단 Opus 5.5·Sonnet 5.5는 0.05배, Fable 5.1·Mythos 5.1은 0.025배, Haiku 5.5는 모델 표에 따로 적힌 고정 단가 |
| 5분 캐시 쓰기 | 1.25배 |
| 1시간 캐시 쓰기 | 2배 |

이 배율은 배치 할인 같은 다른 할인과 겹쳐 적용된다고 문서에 나온다. 5분 캐시는 쓸 때마다 수명이 무료로 연장된다. 그러니 계속 일하는 동안은 싸게 읽고, 5분 넘게 자리를 비우면 다시 비싸게 쓰게 된다. Claude Code 문서는 구독 요금제의 포함 사용량 안에서는 메인 대화에 1시간 TTL을, API 키나 클라우드 제공자로 쓸 땐 5분을 기본으로 쓴다고 한다.

Claude Code는 이걸 자동으로 처리해 주고, 내가 할 일은 캐시를 깨는 행동을 알아 두는 것이다. 문서가 꼽은 것들이다.

- `/model`로 모델 바꾸기: 모델마다 캐시가 따로라서 다음 요청이 전체를 캐시 없이 읽는다.
- 노력 수준(effort) 바꾸기: 대부분의 모델에서 마찬가지다. Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1은 API 키나 구독으로 쓸 때 캐시가 유지된다고 적혀 있다(Bedrock 등 일부 환경은 예외). 모델 목록이 계속 바뀌니 쓰기 전에 문서를 다시 보는 게 좋다.
- MCP 서버 연결·제거, 도구 통째로 deny: 도구 정의가 system 층에 있어서 바뀌면 캐시가 깨진다. 다만 도구 검색(tool search)이 기본으로 켜진 모델에서는 도구가 지연 로딩이라 영향이 없다고 한다.
- 압축: 대화 층이 바뀐다. 그래도 시스템 프롬프트와 프로젝트 맥락은 캐시에 남을 수 있다.

반대로 캐시를 지키는 행동도 있다. 파일 수정, 권한 모드 전환, 스킬 호출, `/recap`, `/rewind`는 대화 끝에 덧붙이거나 이미 캐시된 앞부분으로 되돌아가는 것이라 캐시가 유지된다. CLAUDE.md를 세션 중에 고치면 캐시는 안 깨지지만 반영도 안 된다. 다음 `/clear`, `/compact`, 재시작 때 읽힌다.

문서의 팁 한 줄: 세션 맨 앞에서 모델과 노력 수준을 정하고, `/compact`는 작업 사이 자연스러운 끊김에 쓰라고 한다.

## 모델을 나눠 쓰기

비용 문서는 Sonnet이 대부분의 코딩 작업을 잘 하면서 Opus보다 싸고, Opus는 복잡한 설계 결정이나 여러 단계 추론에 아껴 두라고 한다. 단순한 하위 에이전트 일은 `model: haiku`로 지정하라고도 한다. 문서가 예로 든 "예상 밖으로 높은 지출"의 흔한 원인이 오래 안 비운 세션과, Opus를 기본 모델로 둔 것이다. [자세히 → 모델 map](#/post/ai-models)

주의할 점은 앞 절 내용과 부딪히는 부분이다. 모델을 바꾸면 캐시가 깨지니까, 작업 중간에 왔다 갔다 하기보다 하위 에이전트에 모델을 지정해서 나누는 쪽이 캐시에는 덜 해롭다. 하위 에이전트는 자기만의 대화와 캐시를 가지고, 부모의 캐시에는 영향이 없다고 문서에 나온다.

생각(thinking) 토큰도 있다. 확장 사고는 기본으로 켜져 있고 출력 토큰으로 과금되며, 요청당 기본 예산이 수만 토큰일 수 있다고 한다. 단순한 일이면 `/effort`로 노력 수준을 낮추거나 `/config`에서 끌 수 있다. 다만 문서는 일부 모델(Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 계열)은 끌 수 없다고 적는다.

## 비우기, 압축, 세션 나누기

- `/clear`: 관련 없는 일로 넘어갈 때 쓴다. 문서 표현으로는 낡은 맥락이 이후 모든 메시지에서 토큰을 낭비한다. 비용은 0이다. 나중에 돌아오려면 비우기 전에 `/rename`, 이후 `/resume`.
- `/compact`: 대화를 요약해 맥락을 줄인다. `/compact Focus on code samples and API usage`처럼 남길 것을 지시할 수 있고, CLAUDE.md에 "Compact instructions" 항목을 두는 방법도 있다. 단 압축 자체가 큰 요청이다. 캐시가 따뜻할 때(작업 중간)는 앞부분을 캐시에서 읽어서 싸고, 오래 쉰 뒤 옛 세션을 이어서 압축하면 캐시가 없어서 가장 비싸다.
- `/rewind`(또는 Esc 두 번): 잘못 간 길을 되돌린다. 이미 캐시된 앞부분으로 잘라 되돌리는 거라 압축보다 캐시에 유리하다고 문서가 말한다.
- 계획 모드(Shift+Tab): 구현 전에 방향을 승인받아 헛수고를 줄이는 방법으로 소개된다.

그리고 요청 자체를 구체적으로 쓰라고 한다. "이 코드베이스 개선해 줘"는 넓은 탐색을 부르고, "auth.ts의 로그인 함수에 입력 검증 추가"는 읽는 파일이 적다. 테스트나 기대 출력을 같이 주면 스스로 검증해서 고쳐 달라는 왕복이 줄어든다고도 한다.

## 큰 파일과 로그는 줄여서

문서가 드는 예는 1만 줄짜리 로그다. Claude가 통째로 읽는 대신, 훅이 `ERROR` 줄만 골라 주면 맥락이 수만 토큰에서 수백 토큰으로 줄어든다. 문서에 PreToolUse 훅으로 `npm test`, `pytest`, `go test` 출력을 실패한 부분만 남기도록 명령을 바꿔 쓰는 예제 스크립트가 있다.

또 하나는 하위 에이전트다. 테스트 실행, 문서 가져오기, 로그 처리처럼 출력이 큰 일은 하위 에이전트에 맡기면 지저분한 출력은 그쪽 맥락에 남고 요약만 메인으로 돌아온다. 단 하위 에이전트의 요청도 내 사용량에서 나간다. 그러니 격리로 얻는 건 "메인 맥락이 깨끗해지는 것"이고 "공짜"는 아니다. 작은 모델을 지정하면 그 부담이 줄어든다. [자세히 → 하네스](#/post/ai-harness)

<summary>자세한 풀이: 문서의 에이전트 팀 비용</summary>

에이전트 팀은 동료마다 별도 Claude Code 인스턴스와 맥락을 가진다. 문서는 계획 모드로 도는 팀원이 있을 때 표준 세션보다 대략 7배 토큰을 쓴다고 적는다. 줄이는 방법으로는 팀원에 Sonnet을 쓰기, 팀을 작게 유지, 시작 프롬프트를 짧게, 끝난 팀원은 종료하기를 든다. 에이전트 팀은 기본으로 꺼져 있고 환경 변수로 켠다고 한다. 나는 직접 써 보지 않았다.

## CLAUDE.md와 MCP

CLAUDE.md는 세션 시작 때 맥락에 올라가므로, 특정 작업 절차(PR 리뷰, DB 이전 같은)가 그 안에 길게 있으면 상관없는 일을 할 때도 그 토큰이 실려 간다. 문서의 권고는 두 가지다. CLAUDE.md는 필수만 담아 200줄 아래로 두고, 특정 작업용 지시는 스킬로 옮긴다. 스킬은 호출할 때만 로드된다. 스킬이 프로젝트 구조를 미리 알려 줘서 Claude가 여러 파일을 읽으며 파악하는 토큰을 아끼는 용도로도 소개된다. [자세히 → 스킬·설정](#/post/claude-skills)

MCP는 도구 정의가 기본적으로 지연 로딩이라서 도구 이름과 서버 지침만 맥락에 들어가고, 실제로 쓸 때 정의를 가져온다. 그래도 문서는 두 가지를 권한다.

- `gh`, `aws`, `gcloud`, `sentry-cli` 같은 CLI가 있으면 MCP보다 맥락 효율이 좋다. 도구별 목록이 추가되지 않기 때문이다.
- `/mcp`로 설정된 서버를 보고 안 쓰는 건 끈다. 맥락을 뭐가 차지하는지는 `/context`로 본다.

끄는 것도 도구 정의가 바뀌는 일이라 도구 검색이 꺼진 환경에서는 캐시가 깨진다는 점은 위에서 적은 대로다. [자세히 → MCP](#/post/ai-mcp)

## 흔한 오해

- 캐싱을 쓰면 긴 세션도 괜찮다: 단가가 싸질 뿐 맥락 크기는 그대로고, 5분 또는 1시간 넘게 쉬면 첫 메시지가 전체를 다시 처리한다.
- 압축하면 무조건 싸다: 압축 자체가 큰 요청이 될 수 있다. 문서는 쉬었다 돌아온 옛 세션에서 특히 비싸다고 한다.
- 모델을 수시로 바꿔 가며 쓰는 게 절약이다: 오히려 수시로 바꾸지 않는 쪽이 절약이다. 바꿀 때마다 캐시가 깨지기 때문이다. 모델 분담은 세션 시작이나 하위 에이전트에서 하는 편이 낫다. 이건 문서 두 곳(비용 관리, 프롬프트 캐싱)을 합쳐서 내린 결론이다.
- 하위 에이전트는 토큰이 안 든다: 맥락이 분리될 뿐, 요청은 내 사용량에서 나간다.

<details>
<summary>자세한 풀이: 사용량 확인 방법과 평균 수치</summary>

`/usage`가 세션별 토큰 사용량을 보여 주고, 구독 요금제에서는 스킬, 하위 에이전트, 플러그인, MCP 서버별 사용 비중과 줄이는 추천도 나온다. 비용 숫자는 구독자에게는 청구용이 아니다. 최근 버전에서는 `Prompt cache (main)` 줄로 캐시 적중률, 미스 횟수, 캐시가 따뜻한지도 보인다. 상태 표시줄에 맥락 사용량을 계속 띄울 수도 있다.

기업 배포 기준 평균은 개발자 한 명당 활성일 하루 약 13달러, 한 달 150~250달러이고, 90%는 하루 30달러 미만이라고 문서는 적는다. 팀 단위 얘기라 개인 구독에 그대로 적용되는 숫자는 아니다.

</details>

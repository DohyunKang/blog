CPU の仕事は単純だ。メモリから命令を一つ取り出し、何をすべきか解釈し、実行する。これを電源が切れるまで繰り返す。レジスタ、命令セットアーキテクチャ、パイプラインとは、この反復処理をいかに速く正確に行うかという話である。オペレーティングシステムがこの CPU をどのように分割して使うかは [オペレーティングシステム概論](#/post/cs-os) にあり、ここでは CPU の内部構造に焦点を当てる。

## ヴォン・ノイマン構造

プログラム（命令）とデータを同じメモリに格納しておき、CPU がそこから命令を一つずつ読み出して実行する構造をフォン・ノイマン構造と呼ぶ。現在使用されているコンピュータのほとんどはこの枠組みの上に構築されている。命令も結局はメモリ内の数字なので、プログラムを変更することはメモリの内容を変更することである。数字がどのようにビットで保存されるかは [データ表現](#/post/ca-data-representation) で扱われる。

CPU には大きく分けて三つの部品がある。

| 構成要素 | 役割 |
|---|---|
| コントローラ | 命令を解釈し、他の装置に「今からこれを」という信号を送る |
| ALU | 加算・減算などの算術演算や AND・OR などの論理演算を行う |
| レジスタ | CPU 内部にある非常に小さく高速な記憶領域 |

メモリは CPU の外部にあり、レジスタよりもはるかに遅い。そのため、ほとんどの演算は値をレジスタに載せて行い、結果を再びメモリに書き戻す。この速度差は [メモリ階層とキャッシュ](#/post/ca-memory-hierarchy) に繋がっている。

## 命令サイクル

一つの命令を処理する過程は三つの段階に分けられる。

1. **フェッチ（取り出し）**: プログラムカウンタ (PC) が指し示すアドレスの命令をメモリから読み込み、命令レジスタに入れる。PC は次の命令のアドレスに進む。
2. **デコード（解釈）**: コントローラが命令を読み、どのような演算か、オペランドは何かを見極める。
3. **実行（execute）**: ALU が計算を行ったり、メモリを読み書きしたり、結果をレジスタに保存する。

PC は通常 1 つずつ増えるが、分岐やジャンプ命令が出ると別のアドレスに変わる。`if` やループは機械レベルでは PC を変更する命令である。

小さな仮想的な CPU を Python で実装してこのサイクルを実際に動かしてみた。1 から 5 までの合計を求めるプログラムだ。

<details>
<summary>レジスタマシンを直接動かしてみる（実行確認済み）</summary>

```python
prog = [
    ("LOADI", 0, 0),   # r0 = 0 (합)
    ("LOADI", 1, 5),   # r1 = 5 (카운터)
    ("LOADI", 2, 1),   # r2 = 1
    ("ADD", 0, 1),     # r0 += r1
    ("SUB", 1, 2),     # r1 -= r2
    ("JNZ", 1, 3),     # r1 != 0 이면 PC = 3
    ("HALT", 0, 0),
]
reg = [0] * 4
pc = 0
cycles = 0
while True:
    ins = prog[pc]          # fetch
    pc += 1
    op, a, b = ins          # decode
    cycles += 1
    if op == "LOADI": reg[a] = b             # execute
    elif op == "ADD": reg[a] += reg[b]
    elif op == "SUB": reg[a] -= reg[b]
    elif op == "JNZ":
        if reg[a] != 0: pc = b
    elif op == "HALT": break
print(reg[0], cycles)
# 15 19
```

結果は 15 であり、実行された命令は 19 個だった。最初の 3 つ + ループ本体の 3 つを 5 回繰り返す + HALT 1 つである。ループが「PC を 3 に戻すジャンプ」に過ぎないことがコードからそのまま見える。
</details>

## 命令はどのような形か

実際の命令もビットの塊である。通常、どのような演算を行うかを表すオペコード (opcode) と、どのレジスタやどの定数を使うかを表すオペランドフィールドに分けられる。上記の例の `("ADD", 0, 1)` はその形状を文字列で表現したものである。

これらの命令に関する約束事全体を命令セットアーキテクチャ (ISA) という。どのような命令があるか、レジスタがいくつあるか、メモリアドレスをどのように指定するかが ISA に含まれる。x86、ARM、RISC-V が ISA の名称である。同じ ISA を守ればプログラムはチップの製造業者に関係なく動作し、チップ内部の設計は自由になる。コンパイラがソースコードから生成する最終的な出力物がこの ISA の命令列である。

ISA は大きく二つの方向に議論される。RISC は命令を単純で規則的にすることでハードウェアを高速に回すようにし、CISC は一つの命令でより多くの作業を行わせる。パイプラインの説明でよく使われる古典的な RISC パイプラインは RISC 側の構造である。

## パイプライン

三つの段階を一つの命令ずつ完了させてから次の命令を開始すると、フェッチユニットは実行中に待機することになる。洗濯機と乾燥機がある場合、最初の洗濯物を乾燥機に入れると、洗濯機に次の洗濯物を入れることと同じ考えだ。命令処理を段階に分け、異なる命令が同時に異なる段階にあるようにしたのがパイプラインである。

古典的な RISC パイプラインは 5 段階ある。

| 段階 | 役割 |
|---|---|
| IF | メモリから命令を取り出す |
| ID | 解釈し、レジスタを読み取る |
| EX | ALU が計算を行う（メモリアドレスの計算もここで行う） |
| MEM | データメモリを読み書きする |
| WB | 結果をレジスタに書き込む |

パイプラインが一度満杯になると、各サイクルで命令が一つ完了する。一つの命令の処理時間（遅延）は変わらないが、単位時間あたりの完了数（スループット）が増える。

<details>
<summary>サイクル数を計算してみる（実行確認済み）</summary>

命令 n 個、段階 5 個の場合、パイプラインがない場合は 5n サイクル、ある場合は 5 + (n-1) サイクルである。遅延が発生すればそれだけ増える。

```python
def cycles(n, stall=0, stages=5):
    return stages + (n - 1) + stall
n = 100
print("파이프라인 없음:", n * 5)        # 500
print("파이프라인:", cycles(n))          # 104
print("load-use 20번:", cycles(n, stall=20))  # 124
print(5 / (cycles(n)/n))                 # 4.80...
```

100 命令で 500 サイクルが 104 サイクルに短縮され、約 4.8 倍の高速化となります。ただし、段数は 5 に近づきつつも超えることはありません。途中で停止する回数が 20 回ある場合、124 サイクルとなり、速度向上は約 4 倍まで低下します。
</details>

## ハザード：重ねて実行すると発生する問題

命令を重ねて実行すると、前の命令が完了する前に次の命令が開始され、問題が発生することがあります。このような状況を「ハザード」と呼びます。

- データハザード：次の命令は前の命令の結果が必要だが、まだレジスタに書き込まれていない場合です。`ADD r1, r2, r3` の直後に `r1` を使用する命令が来るケースです。解決策としてフォワーディング（バイパス）を行います。結果をレジスタに書き込むのを待たずに、ALU の出力から次の命令の入力へ直接送ります。ただし、メモリから読み取る `load` 命令は値が遅れて返ってくるため、直後の命令で使う場合は 1 サイクル分空けておく（バブル、ストール）必要があります。
- 制御ハザード：分岐命令がどちらの先頭アドレスに行くかを判明する前に、次の命令をすでにフェッチしてしまっている場合です。予測が外れたらフェッチしたものを破棄し、再度フェッチする必要があります。分岐予測は結果を事前に推測することでこの無駄を減らす方法です。初期の MIPS では、分岐の直後のスロット（遅延スロット）をコンパイラで埋める方式も採用していました。
- 構造ハザード：2 つの命令が同時に同じハードウェアを使用しようとする場合です。例えば、メモリアクセス装置が 1 つしかない場合、読み込みとデータアクセスが衝突します。

## よくある誤解

- クロック周波数が高いほど必ず高速である：サイクルあたりの実行命令数（IPC）や命令数も速度に影響します。パイプラインが停止すれば、クロック周波数が同じでも低速になります。
- パイプラインが深いほど良い：段数を増やすと各段階が短くなり、クロック周波数を上げられますが、分岐予測が外れた際に破棄する量も同時に増加します。
- 1 つの命令は 1 サイクルで完了する：パイプラインでは 1 つの命令が複数のサイクルにわたって通過し、複数の命令が重なるだけです。
- メモリ読み取りは CPU 内部の処理である：メモリは CPU の外部にあるため、読み取りが最も遅い部分の一つです。デバイスと CPU がどのように接続されデータをやり取りするかについては [入出力とバス](#/post/ca-io-bus) で続きます。

## What it is
FFmpeg is an old command-line program for cutting and converting video and audio files. It does a lot, but its options are messy, so an agent writing the commands by hand gets them wrong easily. The README's "Why" section names this directly. Even an agent that "knows FFmpeg" guesses the frame rate, picks a codec the container can't hold, and reports "done" without opening the result.

So this repo doesn't let the agent write FFmpeg commands. Cutting (cut), joining (join), dropping silence (silence), fitting an aspect ratio (fit), captions (caption), loudness (loudness), platform exports (export) and so on are each a Python script. 42 in total. The agent passes only the script name and fixed arguments. Nothing goes through a shell, and the caller can't hand in a raw FFmpeg filter string. It uses only the Python standard library, with no cloud and no API keys.

A skill is a set of instructions an agent pulls out when it needs them. [More → Skills](#/post/ai-skills) The same tools are also served as an MCP server. MCP is a connection standard that lets an agent call an outside program's features like tools. [More → MCP](#/post/ai-mcp)

## Measure, do it, measure again
The flow in the README goes like this. A request comes in, the agent reads SKILL.md and picks a script. Before running, the script checks that the FFmpeg features it needs exist on this machine, runs FFmpeg, measures the file it wrote, and returns JSON.

The first design principle is "Probe first." Probing means actually opening the file and measuring its length, frame rate, resolution, color info and audio tracks. Don't decide from the file name. Every tool also has `--dry-run`, which prints the FFmpeg commands it would run and writes nothing. Replacing an existing file needs an explicit `--overwrite`.

The part I liked was the `unverified` list in each result. A tool only counts what it can measure as verified. Length, codec and loudness get measured again and compared. But what's in the frame, whether captions are readable, whether a removed span held speech, whether lips match sound: file measurements can't tell. Those come back listed separately as not checked. A value it can't read fails as `not_measured` instead of passing. When the picture changed, it says to make a contact sheet (one image of several frames) with look.py and look at it.

## The contract comes from the code
Run `contract --json` and you get a document saying, for each of the 42 tools, what it takes, what it returns, which FFmpeg parts it needs and how its result is verified. The README calls it a machine-readable contract. Nobody maintains it by hand. It's generated from each script's argument definitions (argparse). The MCP server's tool list comes from it too, so adding an argument to a script changes the MCP side with no edit there. A test checks this, according to the README.

Numbers drifting between documents are blocked by a test as well. Per contract.md, the "42" written in the README, SKILL.md and package.json is compared on every run to the real tool count in the scripts folder. It was added after SKILL.md kept an old "28" through twelve new tools.

The agent doesn't see all 42. The default MCP list shows the 12 common ones, and the other 30 are called by name when needed. Since 4.0 those 12 are stable (no renamed arguments or outputs until the next major version) and the rest are beta.

## From a beginner's side
The structure was more interesting than the video editing itself. Instead of asking the agent in words to "be careful," the error-prone work goes to scripts, results get measured again, and what can't be measured comes back labeled that way. Alibaba's Open Code Review, which I looked at before, also gave the steps that must not go wrong to code. [More → Open Code Review](#/post/news-261115-a)

For a PM, the useful idea is something like `unverified`. Instead of a single "done," you get what was checked and what a person still has to look at. It narrows where to look when reviewing an agent's work. The README draws the line too: the tool only executes an edit, and where to cut or whether the result is good is for a person or another agent to decide.

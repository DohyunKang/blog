10 月 7 日、Anthropic が Claude Haiku 5.5 をリリースしました。Haiku は Claude ラインナップの中で最も小さく高速なモデルであり、今回の発表資料ではこれを「これまで発表した小規模モデルの中で最も安価で、最も高速かつ最も賢い」と紹介しています。数字を一つずつ確認していくと、価格面が特に目立ちました。

## どのような用途に使うべきか

発表資料で挙げられた用途は、要約、圧縮（コンパクション）、データベースクエリ、分類など、データ量は多いながら単価あたりのコストを抑える必要がある作業です。コーディングエージェントにおいては、Opus 5.5 や Sonnet 5.5 が大きな判断を行い、Haiku 5.5 がサブエージェントとして横で働くという構成が示されています。また、リアルタイムカスタマーサポートやブラウザ操作など、応答速度が重要な場面も言及されています。

モデル概要文書の一行説明も同様です。大量かつ遅延に敏感な作業、例えば分類・抽出・ルーティングなどが該当します。逆に、複雑なエージェントコーディングについては Sonnet 5.5 や Opus 5.5 の方が優れていると発表資料が直接述べています。

関連概念については別途まとめた記事があります。コンパクションについては [詳細 → コンパクションとメモリ](#/post/ai-compaction)、サブエージェントについては [詳細 → サブエージェントとマルチエージェント](#/post/ai-subagent) を参照してください。

## スペック

モデル概要文書に記載されている値です。文書は変更される可能性があるため、2026 年 11 月 2 日時点の基準で記載します。

| 項目 | Claude Haiku 5.5 |
|---|---|
| API モデル ID | claude-haiku-5-5 |
| コンテキストウィンドウ | 1M トークン |
| 最大出力 | 128K トークン |
| 知識の基準時点 | 2026 年 6 月 |
| 思考 (thinking) | 適応型 (adaptive) |
| デフォルト effort | medium |
| 提供元 | Claude Platform, AWS, Google Cloud, Microsoft Azure |

効果調整段階が存在するという点は Haiku としては初めてであるとのことです。発表資料の基準では Low、Med、High、Xhigh、Max の 5 つの段階です。小規模モデルでも「どのくらい考えるか」を設定できるようになったことになります。思考トークンとは何かについては [詳細 → 推論モデルと思考トークン](#/post/ai-reasoning)、ウィンドウサイズの話については [詳細 → コンテキストウィンドウとトークン](#/post/ai-context-window) にあります。

## 価格

発表資料の表を百万トークン基準で転記すると以下のようになります。Haiku 5.5 はリクエスト長が 10 万トークン以下の場合とそれを超える場合で単価が異なります。

| 区分 | Haiku 5.5 (10 万以下) | Haiku 5.5 (10 万超過) | Haiku 4.5 | Sonnet 5.5 |
|---|---|---|---|---|
| 入力 | $0.10 | $0.50 | $1.00 | $2.00 |
| 出力 | $0.50 | $2.50 | $5.00 | $10.00 |
| キャッシュ読み取り | $0.01 | $0.05 | $0.10 | $0.10 |
| キャッシュ書き込み | $0.125 | $0.625 | $1.25 | $2.50 |

発表資料では Haiku 4.5 より平均で約 75% 安価であると記載されています。脚注によると、10 万トークン未満のリクエストは 90% 安価で、それ以上は 50% 安価であるとしています。新しいトークナイザーのため、同じ作業でも少し多くのトークンを使用する傾向があると付け加えられています。したがって、表の単価だけを比較すると実際の請求書よりも楽観的に見えてしまいます。

バッチ API は 50% の割引であり、キャッシュ読み取りは基本入力価格の 10% とモデル概要文書に記載されています。キャッシュがどのように機能するかについては [詳細 → プロンプトキャッシング](#/post/ai-prompt-caching) で別途見ています。

<summary>簡単な計算例</summary>

リクエスト 1 万件、件あたりの入力 2,000 トークン・出力 300 トークンと仮定します。すべて 10 万トークン未満の区間であり、キャッシュやバッチ処理は使用しません。トークナイザーの違いも無視した単純な計算です。

- 入力合計 2,000 万トークン、出力合計 300 万トークン
- Haiku 5.5: 20 × $0.10 + 3 × $0.50 = $3.50
- Haiku 4.5: 20 × $1.00 + 3 × $5.00 = $35
- Sonnet 5.5: 20 × $2.00 + 3 × $10.00 = $70

Sonnet を使用していたサービスで、分類や要約の段階だけを Haiku に切り替えた場合、その区間のコストは単価基準で 20 分の 1 になります。もちろん品質が支えなければ意味がありません。

## パフォーマンスの数値

発表資料に掲載されたベンチマークは、Haiku 4.5、GPT-6 Luna、Sonnet 5.5 と並べて示されています。すべて Anthropic が発表した値です。

| ベンチマーク | Haiku 5.5 | Haiku 4.5 | GPT-6 Luna | Sonnet 5.5 |
|---|---|---|---|---|
| OSWorld 2.1 (オフライン一部) | 72.4% | 15.7% | 48.9% | 83.9% |
| Humanity's Last Exam (ツールなし) | 45.9% | 10.2% | - | 56.9% |
| Humanity's Last Exam (ツールあり) | 57.4% | 18.7% | - | 64.5% |
| Terminal-Bench 4.0 | 39.2% | 0.0% | 16.4% | 70.6% |
| FrontierCode 1.1 (Main) | 46.4% | - | 42.4% | 52.1% (Xhigh) |

世代間の差が大きい。コンピュータ操作ベンチマークである OSWorld は 15.7% から 72.4% に向上し、Terminal-Bench も 4.5 の 0.0% から 39.2% となった。それでもターミナル作業については Sonnet 5.5 の 70.6% とまだ大きな差がある。発表文で複雑なエージェントコーディングを大規模モデルに委ねるべきだとした理由は、この項目から読み取れる。

## その他発表された内容

Sonnet 5.5 のキャッシュ読み取り料金は、100 万トークンあたり $0.20 から $0.10 に引き下げられた。これは、ほとんどのエージェントタスクにおいてコストが約 20% 削減されるという説明である。Max、Ultra、Team のサブスクリプションユーザーには月間 API クレジットが付与されるという（Max は $100、Ultra は $200、Team は合計最大 $500）。また、Python・TypeScript SDK にコンピューター使用およびブラウザ使用のベータ機能が追加された。

## セキュリティに関する話

発表文では、Haiku 4.5 よりも不適切な行動が大幅に減少し、悪用リクエストへの協力的な傾向も低下したと記載されている。サイバーセキュリティ対策は Haiku 4.5 より厳格でありながら Sonnet 5.5 よりも緩やかで、ハッキングテストなどの攻撃者視点の手法は引き続きブロックされる。生物学分野については Sonnet 5、Sonnet 5.5、Opus 5 と同等のレベルである。より広範なアプローチが必要な組織は、Life Sciences や Cyber Verification プログラムへの申請が可能だ。

## 読みながら思ったこと

小型モデルが安価になったことよりも、小型モデルが「サブエージェント・コンパクション・分類」などの役割として明確に紹介された点が目についた。一つの大きなモデルですべてを行う構造から、各段階でモデルを分担して使う構造へ移行するべきだというシグナルのように読める。モデルがどのような役割を果たすものなのかを再確認したい場合は、[詳細 → LLM とは何か](#/post/ai-llm) を参照のこと。

ただし、私の作業において品質が十分かどうかは実際に試してみないとわからない。ベンチマークは発表側が選んだ表である。

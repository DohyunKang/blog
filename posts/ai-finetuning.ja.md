ファインチューニングは、すでに学習済みのモデルをサンプルデータを用いて再度学習させ、わずかに重みを調整する方法です。プロンプトや [RAG](#/post/ai-rag) がモデルに提示する入力を変更することに比べ、ファインチューニングはモデルそのものを変更します。LoRA はこれを安価に行うための手法の一つです。

## プロンプト、RAG、ファインチューニングのどれを選ぶか

これら三つはすべて「モデルを望む通りに動作させる方法」ですが、変化する点は異なります。

| | プロンプト | RAG | ファインチューニング |
|---|---|---|---|
| 変更されるもの | 指示文 | モデルが読み取る資料 | モデルの重み |
| 準備物 | 数行の文章 | ドキュメント + 検索システム | サンプルデータ + 学習環境 |
| 修正までの速度 | 即時 | ドキュメントのみを修正すればよい | 再学習が必要 |
| 適している問題 | 指示・形式・役割 | 未知の知識、頻繁に変わるドキュメント | 一貫した口調・出力形式・繰り返される行動 |

OpenAI のファインチューニング文書では、ファインチューニングはサンプルを通じて行動を教えるための用途であると説明されており、分類、微妙な翻訳、特定の形式の出力生成、指示に従えない場合の修正などが適切な例として挙げられています。知識を注入する用途はこのリストには含まれていません。

選ぶ順序は通常、軽いものから行うのが一般的です。[プロンプト](#/post/ai-prompt) をまず整え、未知の情報に問題がある場合は RAG、同じミスを繰り返す行動の問題の場合はファインチューニングを検討します。ドキュメントにも評価基準を先に作り、ファインチューニングの結果を基本モデルと比較するよう指示があります。ファインチューニングが適切かどうかは [評価](#/post/ai-evals) で確認するという意味です。

## ファインチューニングが行うこと

事前学習済みモデルの重みは数十億個の数値です。ファインチューニングは入力と望ましい出力がペアになったサンプルを示し、これらの数値を少しずつ修正します。学習が完了するとその変化が重みに反映されるため、プロンプトに長いサンプルを付けなくても似たような行動をとります。

手法は大きく二つに分けられます。

- 全体ファインチューニング: すべての重みを学習します。最も自由度が高いですが、更新する数値がモデルサイズと同じであるため、メモリとストレージの容量が多く必要になります。LoRA の論文では GPT-3 175B を例に挙げ、モデルごとに 175B のコピーを別途配布するのは大きな負担であると問題を提起しています。
- パラメータ効率化方式 (PEFT): 重みの大部分は凍結し、一部または新たに追加された小さな部分のみを学習します。LoRA が代表的です。アダプタなどの他の手法もあります。

なお、[LLM](#/post/ai-llm) を直接サービスする側ではなく API で利用する側であれば、重みを操作する代わりに提供元のファインチューニング機能を使用することになります。OpenAI の文書にはこのプラットフォームを段階的に終了中であるという案内があり（既存顧客は 2027 年 1 月 6 日まで作業生成が可能）、使用前に現在利用可能か確認しておくのが良いでしょう。

## LoRA の原理

論文は Hu らが 2021 年に発表した "LoRA: Low-Rank Adaptation of Large Language Models"(arXiv 2106.09685) です。アイデアは以下の通りです。事前学習済みの重み行列 W0 はそのまま置き、学習によって生じる変化量を二つの小さな行列の積で制限します。

```
W0: d × k  (얼려 둠, 학습 안 함)
B : d × r  (학습)
A : r × k  (학습)
r : 랭크, d·k보다 훨씬 작은 수

출력 h = W0·x + B·A·x
```

変化量 ΔW の全量を学習する場合 d×k 個の数値が必要ですが、B と A に分割すると r×(d+k) 個に削減されます。論文がこのようにしてもよいと主張する根拠は、モデルを特定のタスクに適応させる際に必要な変化は低いランクでも十分であるという観察です。

初期値が重要です。A はランダムなガウス分布で、B は 0 で始まります。そのため学習開始時点では BA が 0 となり、モデルは元のモデルと同じように動作します。変化量には α/r というスケーリング係数が掛けられていますが、論文によると α は最初の実験値を固定し、別途チューニングしていません。r を変更しても他のハイパーパラメータの再調整が少なくなります。

適用位置は、論文の実験のほとんどでアテンションのクエリ (Wq) とバリュー (Wv) プロジェクション行列です。MLP 部分は凍結し、それまでの拡張は後続のタスクとして残されています。Hugging Face PEFT の文書でも、Transformer では通常アテンションブロックのみに対して LoRA を適用すると記載されています。

デプロイ時には W = W0 + BA を事前に計算しておくと、推論速度が元のモデルと同じになります。アダプタ層を挟む方式は層が一つ増えるため遅延が増加しますが、LoRA は統合すれば消えます。PEFT では `merge_and_unload()` がこの作業を行います。

数値も論文にあります。GPT-3 175B で r=4、クエリ・バリュー行列のみを適用した場合、チェックポイントは約 350GB から約 35MB に削減され（約 10,000 倍）、学習に必要な GPU メモリは約 1.2TB から 350GB に減少しました。学習対象外のパラメータはオプティマイザの状態を保存する必要がないためです。緑色のセクションでは、RoBERTa、DeBERTa、GPT-2、GPT-3 で全体ファインチューニングと同じかそれ以上の品質が得られたと書かれています。

1 層の重みが 4096 × 4096 とします。全学習の場合、パラメータ数は 16,777,216 です。LoRA の場合は r × (d + k) です。

| ランク r | LoRA 学習パラメータ | 全体に対する割合 |
|---|---|---|
| 4 | 32,768 | 約 0.2% |
| 8 | 65,536 | 約 0.4% |
| 16 | 131,072 | 約 0.8% |

## LoRA の長所と限界

長所は、基本モデル 1 つに対してタスクごとに軽量な LoRA ファイルを複数重ねることができる点です。PEFT ドキュメントも、フリーズされた事前学習重みのおかげで、多様なタスク用の軽量でポータブルな LoRA モデルを複数作成できると述べています。タスクを変更する際は、BA を引いて別の B'A'を加えるだけです。

限界についても論文に記されています。遅延をなくすために A と B を W に合体させてしまうと、異なるタスクの入力を 1 つのバッチに混ぜて処理しにくくなります。遅延が重要でなければ、サンプルごとに LoRA モジュールを選択する方法があるそうです。

## データ準備に必要なこと

OpenAI ドキュメントを基準に整理すると以下のようになります。

- 形式：JSONL で、1 行に JSON 1 つです。チャットメッセージ形式を使用します。
- 量：最小 10 行が必要で、ドキュメントは 50〜100 の例示で改善が見られたとされ、良質な例示 50 で始めて結果を見るよう推奨されています。
- 評価用分離：学習用に収集したデータの一部分を別途取り出し、対照群として使用するとあります。このホールドアウトを用いてファインチューニングしたモデルと基本モデルを比較します。
- 順序：まず「良い答え」が何かを定義するデータセットと評価を作成し、ファイルをアップロードしてタスクを作成し、評価して繰り返します。

「良い答えが何か」を記述した例示自体が学習信号となるため、例示の品質は量よりも優先されます。例示に誤った答えやバラバラな形式が混在していると、モデルはそのまま学習してしまいます。学習データに個人情報や社内秘密が含まれているかもこの段階でフィルタリングする必要があります。モデルを安全に回答させる側については [ガードレール](#/post/ai-guardrails) で別途扱っています。

## よくある誤解

- ファインチューニングすれば自社の文書を覚える：ドキュメントにあるファインチューニングの用途は行動を教えることです。知識が頻繁に変化したり出典が必要なら RAG の方が適しています。
- ファインチューニングすればハルシネーションが消える：モデルが作り出す問題（[ハルシネーション](#/post/ai-hallucination)）はファインチューニングで減らすこともできますが、消えると断言する根拠はありません。評価で直接測る方が良いでしょう。
- LoRA は品質は低いが安価な方法：論文では複数のモデルにおいて全量ファインチューニングと同様かそれ以上の品質を報告しています。すべてのタスクでそうであるという意味ではありません。
- ファインチューニングには大量のデータが必要：OpenAI ドキュメントでは 50〜100 の例示でも改善が見られたと述べています。ただしタスクによって異なります。
- LoRA を使うと推論が遅くなる：合体させてデプロイすれば、元のモデルと同じ速度になります。
- モデルを変えればそのまま使える：LoRA は特定の基本モデルの重みの形状に合わせて学習したものであり、基本モデルが変わると再学習する必要があります。これは LoRA 構造（W0 に加える行列）から導かれる話です。モデル選択については [AI モデルガイド](#/post/ai-models) を参照してください。

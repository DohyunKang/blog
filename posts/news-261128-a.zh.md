这周在 Hugging Face 热门、X 和 YouTube 本地模型视频里,继 [Inkling 2 Mini](#/post/news-261127-a) 之后最常看到的名字是 Ternary Bonsai 2.5 27B。这是 PrismML 在韩国时间 11月25日凌晨发布的模型。它基于 Qwen3.8-27B,把原本 53.8GB 的模型压成了一个 5.93GB 的文件。我读了 Hugging Face 模型卡和两份白皮书(2.5,以及最早讲清楚格式的 Bonsai 2)。我没有自己跑。文中的基准分数都是公司自己公布的。

## 只用三个值
模型权重通常每个数用 16 位(FP16)存。量化就是把它压到更少的位数,比如 8 位、4 位。Bonsai 几乎压到了头:每个权重只能是 -1、0、+1 之一。这叫 ternary(三值)权重。三选一,所以信息量是 log₂3,约 1.585 位。

只有三个值表达不了大小,所以每 128 个权重共用一个 FP16 缩放系数。实际值是"缩放系数 × (-1, 0, +1)"。16 位的系数分摊到 128 个权重上,每个多 0.125 位,约 1.71 位。发布的文件因为打包方式,是每个权重 1.76 位、5.93GB,大约是 FP16 的九分之一。

没压缩的那部分挺有意思。只有归一化层和 linear attention 层状态通路的一部分,一共 2,620 万个参数(语言模型的 0.0976%,52MB)保留原精度。上一个版本连这些也压成了三值。对体积几乎没影响的地方,他们就没去硬省。

## 先旋转再取整
取整之前还有一步。先把权重矩阵按 1,024 一块做阿达马(Hadamard)旋转,再变成三个值。阿达马矩阵是只由 +1 和 -1 组成的正交矩阵。这类旋转常见的用意,是把少数特别大的值摊到很多格子里,让分组缩放系数不被它们带偏(比如 QuaRot 这类研究)。Bonsai 白皮书只写了公式,没怎么讲原因。

旋转事先合进了存储的权重里,所以不多占位数。但推理时要在输入(激活值)那一侧做同样的变换,运行程序必须认得它。普通 llama.cpp 从 b11556 版本起支持这个变换。模型卡上写着,更早的版本会不报警地载入文件,然后输出乱码。这是我读到的最实用的一句话。

文件有三种:PTQ1_0(5.93GB,需要 PrismML 的 llama.cpp 分支)、PQ2_0(每个值放进一个 2 位格子,7.25GB,需要分支)、Q2_0(普通 llama.cpp 的 2 位格式)。三个都是同一个模型。

## 2.5 改了什么
格式和 Bonsai 2 完全一样,变的是智能体任务的成绩。按公司的表,5 个工具调用基准的平均分,FP16 原模型 77.7,Bonsai 2.5 77.2。3 个编码智能体基准从 FP16 分数的 63% 提到了 90%。DeepSWE 从 0 到 27.0,SWE-bench Verified 从 60.8 到 75.6。具体怎么重新训练的,模型卡和白皮书里都没写,没能确认。

有一个对比很显眼。同一个 Qwen3.8-27B 用常规方法压到 2.5 位的 GGUF(GSQ-RCO IQ2_XS),τ²-Bench 有 79.5,AppWorld 却掉到 46.5。大约五次里有一次,它在看到任何结果之前就写一长段脚本把所有 API 调用都猜好,然后宣布完成。公司的意思是,其他分数里看不出这种失败。

MTP 版本也一起发布了,多加了一层用来先猜接下来几个 token。用投机解码,主模型一次检查这些猜测,只留下自己本来也会输出的 token。所以输出不变,只是在 NVIDIA GPU 上解码快 1.5~1.8 倍。即使不用 MTP,模型卡的表里 RTX 5090 也有每秒 163 个 token(PTQ1_0)。

## 为什么火
卖点是"27B 编码模型能装进 16GB 显卡"。按一个视频简介的说法,4 位版本也要 17GB 左右,16GB 的卡装不下,而这个只有 6GB。三天里 YouTube 上接连出了在 RTX 4060 Ti 16GB 上跑的视频、在 RTX 4090 上跑 86 个编码任务的视频,还有在 M5 Max Mac 上跑的视频。

反应也不全是好的。4090 那个视频的标题是 "Strong quant; not up to the hype"。简介里写着,它的通过率比同一张卡能装下的另外几个模型低,在把 Python 移植成 C 的任务里不停地输出 0。也注明了各自条件不同、结果是初步的。视频播放量和 Reddit 反应没能确认。

白皮书的局限一节也说了类似的话:Terminal-Bench 2.1 仍然离 FP16 最远,持续好几个小时的长智能体任务还没测过。

## 作为入门者
我原来把量化理解成"丢一点精度换体积"。取整之前还有一步把数值摊匀,而且因为这一步,连运行程序的版本都得对上,这点是新学到的。不是下载完模型文件就完事了。

作为 PM,看到"接近 FP16"这种话,要一起看是哪些基准的平均,以及有没有平均分里看不出来的失败。这家公司自己就在表里放了这样的例子。

## どんなものか
AI でコードレビューをする CLI だ。README によると、アリババ社内で2年間使っていたレビュー支援ツールをオープンソースにしたもの。Git の diff を読み、変わったファイルを LLM エージェントに渡し、行単位で位置を示したレビューコメントを返す。エージェントはファイル全体を読んだりコードベースを検索したりして、diff の外の文脈も見る。エージェントは、モデルがツールを使いながら次にやることを自分で決めるやり方だ。[詳しく → エージェントループ](#/post/ai-agent-loop)

`npm install -g @alibaba-group/open-code-review` で入れて、モデル提供元を設定し、`ocr review` を打てばいい。diff なしでフォルダ全体を見る `ocr scan` もある。

## どう動くか
面白いのは設計の主張だ。README は、Claude Code のような汎用エージェントにスキルを付けてレビューさせると問題が出るという。変更が大きいと一部のファイルだけ見て終わる、指摘した行番号が実際のコードとずれる、プロンプトを少し変えるだけで品質が揺れる。原因は、工程全体を言葉だけで指示していて強制する仕組みがないこと。

だから間違えてはいけない段階はモデルではなく普通のコードが受け持つ。

1. ファイル選び: どのファイルをレビューし、どれを外すかをコードで決める。モデルが見落とす余地をなくす。
2. まとめ: 関係するファイルを1つの単位にまとめる。たとえば `message_en.properties` と `message_zh.properties`。まとまりごとに文脈を分けたサブエージェントが別々に動く。[詳しく → サブエージェント](#/post/ai-subagent)
3. ルールの割り当て: ファイルの性質に合うレビュールールだけをテンプレートエンジンで選んで入れる。モデルが読む情報を減らす方向だ。
4. 位置合わせと振り返り: コメントが指す行を合わせるモジュールと、コメントの中身を見直すモジュールがモデルの外に別にある。

モデルはその間で「どの文脈をもっと探すか」のような判断だけをする。ツール一覧も、実際の利用記録でどのツールがどれだけ呼ばれ、何回繰り返されるかを分析して絞ったという。[詳しく → ツール使用](#/post/ai-tool-use)

実行モードが2つあるのも目に付いた。標準では OCR が設定済みのモデル API を直接呼ぶ。委任モード(Delegation Mode)では OCR はファイル選びとルール整理だけをして、レビュー自体は普段使っているコーディングエージェントが自分のモデルで行う。このときは OCR 用の API キーは要らないと書かれている。

## なぜ話題か
目を引く表が1つある。50のオープンソースレポの実際の PR 200件で、人が印を付けた問題1,505件を正解として比べたものだ(AACR-Bench、プロジェクトが作ったベンチマーク)。同じ Claude-4.8-Opus で動かすと、OCR は適合率37.8%、再現率11.7%、レビュー1回でトークン352K、1分6秒。Claude Code は適合率15.93%、再現率12.70%、トークン2,062K、5分38秒だった。適合率は指摘したもののうち本当の問題の割合、再現率は本当の問題のうち見つけた割合だ。README も、再現率が低いのは誤指摘を減らすために選んだトレードオフだと認めている。表の OCR は v1.3.1 で今(v1.13.9)よりかなり古く、プロジェクト自身が測った数字なので自分では再現していない。[詳しく → 評価(evals)](#/post/ai-evals)

リリースもまめだ。11月10日、12日、13日に v1.13.7〜v1.13.9 が出て、12日のリリースで GitHub Copilot CLI 連携が入った。

## 入門者の目線で
PM としては「全部モデルに任せず、間違えてはいけない部分はコードで固定する」という設計がしっくりきた。エージェントの品質がばらつくとき、プロンプトをさらに磨く代わりに、どの段階をモデルの外に出すかを見る視点だ。レビューで誤指摘が多いと結局誰も読まなくなるので、見つける数が減っても正確な方を選んだのも納得がいく。

開発入門者なら、小さなプロジェクトのコミット1つに `ocr review --commit <ハッシュ>` を回してみるくらいから始めればよさそう。Claude Code のようなエージェントをもう使っているなら、委任モードでキーなしで試せる。セキュリティの脆弱性を探す側のツールが気になるなら、この記事も一緒にどうぞ。[詳しく → Codex Security](#/post/news-261113-a)

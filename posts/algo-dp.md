DP는 큰 문제를 작은 문제로 쪼갠 뒤, 같은 작은 문제를 두 번 풀지 않도록 답을 적어 두고 재사용하는 방법이다. 코드보다 "작은 문제를 어떻게 정의하고 서로 어떻게 잇느냐"를 정하는 게 거의 전부였다.

## DP가 뭔지

이름은 어렵게 들리는데 하는 일은 단순하다. 위키피디아 설명으로는 리처드 벨먼이 1950년대 초 RAND에서 만든 용어이고, 큰 결정 문제 안에 작은 결정 문제가 겹겹이 들어 있는 구조를 푸는 방법을 가리킨다. 이름의 "programming"은 코딩이 아니라 표(계획)를 채운다는 뜻에 가깝다.

DP가 먹히려면 두 조건이 있어야 한다.

| 조건 | 뜻 | 예 |
|---|---|---|
| 최적 부분 구조 | 큰 문제의 최적해가 작은 문제의 최적해로 만들어진다 | 최단 경로의 일부분도 최단 경로다 |
| 부분 문제 중복 | 같은 작은 문제가 여러 번 다시 나온다 | fib(5)를 구하면 fib(2)가 여러 번 불린다 |

두 번째 조건이 없으면 그냥 분할 정복이고, 첫 번째가 없으면 DP로 못 푼다. 중복이 있을 때 한 번만 계산하게 만드는 것이 DP의 이득이다.

## 두 가지 구현

피보나치로 보면 가장 쉽다. 그냥 재귀로 짜면 같은 값을 계속 다시 계산해서 n이 커지면 못 쓴다. 두 가지 방식으로 고친다.

- 메모이제이션(top-down): 재귀는 그대로 두고, 한 번 구한 값은 저장해 두었다가 다음에 꺼내 쓴다.
- 타뷸레이션(bottom-up): 작은 것부터 반복문으로 표를 채워 올라간다.

```python
from functools import lru_cache

def fib_memo(n):
    @lru_cache(None)
    def f(k):
        return k if k < 2 else f(k - 1) + f(k - 2)
    return f(n)

def fib_tab(n):
    dp = [0, 1] + [0] * max(0, n - 1)
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_memo(50), fib_tab(50))  # 12586269025 12586269025
```

코딩 테스트에서는 보통 타뷸레이션을 쓴다. 재귀 깊이 제한(파이썬 기본 약 1000)을 신경 안 써도 되기 때문이다. 다만 어떤 상태가 실제로 필요한지 모르겠을 땐 메모이제이션이 쓰기 편했다. 필요한 것만 계산하니까.

## 풀이 생각 순서

문제를 보고 DP인지 감을 잡은 뒤 이 순서로 적어 봤다.

1. 상태 정의: `dp[i]`가 무엇을 뜻하는지 한 문장으로 쓴다. 여기서 막히면 뒤는 다 막힌다.
2. 점화식: `dp[i]`를 더 작은 상태로 어떻게 만드는지 쓴다.
3. 초기값: 점화식이 기댈 가장 작은 값(`dp[0]` 등)을 정한다.
4. 계산 순서: 점화식이 참조하는 값이 먼저 채워지도록 순서를 정한다.
5. 답 위치: `dp[n]`이 답인지, 표 전체의 최댓값이 답인지 확인한다.

"이 문제 DP인가?"는 보통 "최대/최소/경우의 수를 묻는데, 앞에서 한 선택이 뒤에 영향을 준다"는 느낌으로 알아챘다. 완전 탐색이 지수로 폭발하는데 상태 수는 작다면 DP를 의심한다.

## 대표 문제 1: 배낭 (0/1 knapsack)

백준 12865번 "평범한 배낭". 물건마다 무게와 가치가 있고, 무게 합이 K 이하가 되게 골라 가치 합을 최대로 하는 문제다.

- 상태: `dp[c]` = 무게 한도 c일 때 얻을 수 있는 최대 가치
- 점화식: 물건 (w, v)를 넣어 보면 `dp[c] = max(dp[c], dp[c-w] + v)`
- 주의: 같은 물건을 두 번 쓰면 안 되니까 c를 큰 쪽에서 작은 쪽으로 돈다.

```python
def knapsack(items, cap):
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(cap, w - 1, -1):   # 거꾸로 돌아야 한 물건을 한 번만 쓴다
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]

print(knapsack([(6, 13), (4, 8), (3, 6), (5, 12)], 7))  # 14
```

시간 O(N·K), 공간 O(K). 반대로 c를 작은 쪽에서 큰 쪽으로 돌리면 물건을 여러 번 쓸 수 있는 무한 배낭이 된다. 방향 하나로 문제 종류가 바뀐다는 게 신기했다.

## 대표 문제 2: 가장 긴 증가하는 부분 수열 (LIS)

백준 11053번 "가장 긴 증가하는 부분 수열". 수열에서 순서를 유지하며 골라낸 증가 수열 중 가장 긴 길이를 구한다.

- 상태: `dp[i]` = i번째 원소로 끝나는 가장 긴 증가 부분 수열의 길이
- 점화식: `dp[i] = max(dp[j] + 1)` (j < i 이고 a[j] < a[i]), 없으면 1
- 답: `dp` 전체의 최댓값. 마지막 칸이 답이 아니라는 점을 자주 놓친다.

```python
import bisect

def lis_n2(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

def lis_fast(a):
    tails = []
    for x in a:
        p = bisect.bisect_left(tails, x)
        if p == len(tails):
            tails.append(x)
        else:
            tails[p] = x
    return len(tails)

print(lis_n2([10, 20, 10, 30, 20, 50]), lis_fast([10, 20, 10, 30, 20, 50]))  # 4 4
```

O(N²) 풀이는 시간 O(N²), 공간 O(N). N이 100만처럼 크면 위의 `lis_fast`가 필요하고 O(N log N)이다. 위키피디아 LIS 문서도 이진 탐색을 쓰는 O(n log n) 알고리즘을 설명한다. `tails[k]`는 "길이 k+1인 증가 수열의 끝값 중 가장 작은 값"이고, 이 배열이 항상 정렬돼 있어서 이진 탐색이 된다. 주의할 점은 `tails` 자체가 실제 LIS는 아니라는 것이다. 길이만 맞다.

<details>
<summary>lis_fast가 왜 맞는지 (접기)</summary>

새 원소 x를 볼 때 `tails`에서 x 이상인 첫 칸을 찾는다.

- 그런 칸이 없으면 x가 가장 긴 수열 뒤에 붙을 수 있으니 길이가 1 늘어난다.
- 있으면 그 길이의 끝값을 x로 바꾼다. 끝값이 작을수록 뒤에 더 많은 수가 붙을 수 있어서 손해가 없다.

`bisect_left`를 쓰는 이유는 같은 값이 나왔을 때 "증가"(엄격하게 커야 함)를 유지하려는 것이다. 같거나 커도 되는 비감소 수열이면 `bisect_right`를 쓴다. 임의 배열 300개로 `lis_n2`와 `lis_fast`가 같은 길이를 내는지 돌려 확인했다.
</details>

## 대표 문제 3: 동전 (최소 개수)

백준 2294번 "동전 2". 동전 종류가 주어지고, 합이 k가 되는 최소 동전 개수를 구한다. 불가능하면 -1.

- 상태: `dp[i]` = 합 i를 만드는 최소 동전 수
- 점화식: `dp[i] = min(dp[i - c] + 1)` (모든 동전 c)
- 초기값: `dp[0] = 0`, 나머지는 아주 큰 값

```python
def coin(coins, k):
    INF = 10**9
    dp = [0] + [INF] * k
    for i in range(1, k + 1):
        for c in coins:
            if i >= c and dp[i - c] + 1 < dp[i]:
                dp[i] = dp[i - c] + 1
    return dp[k] if dp[k] < INF else -1

print(coin([1, 5, 12], 15), coin([2], 3))  # 3 -1
```

시간 O(k × 동전 종류 수), 공간 O(k). 동전 [1, 5, 12]로 15를 만들 때 큰 동전부터 쓰는 그리디는 12+1+1+1로 4개지만, 답은 5+5+5로 3개다. 그리디가 안 되고 DP가 필요한 전형적인 예라서 [그리디](#/post/algo-greedy)와 같이 보면 구분이 된다.

<details>
<summary>보너스: LCS (두 문자열의 최장 공통 부분 수열)</summary>

백준 9251번 "LCS". 2차원 표를 쓴다. `dp[i][j]`는 a의 앞 i글자와 b의 앞 j글자의 LCS 길이이고, 두 글자가 같으면 `dp[i-1][j-1] + 1`, 다르면 `max(dp[i-1][j], dp[i][j-1])`.

```python
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("ACAYKP", "CAPCAK"))  # 4
```

시간·공간 O(N·M). 한 줄만 쓰는 식으로 공간을 O(M)까지 줄일 수 있다(이 글에서는 코드로 확인 안 함).
</details>

## 복잡도를 어떻게 보나

DP의 시간은 대체로 (상태 수) × (상태 하나를 계산하는 데 드는 전이 수)다. 배낭은 상태 K개 × 물건 N번, 동전은 상태 k개 × 동전 종류 수. 이걸로 "이 풀이가 제한 시간 안에 되나"를 먼저 어림한다. 공간은 점화식이 바로 앞 몇 칸만 보면 배열 전체 대신 몇 개 변수로 줄일 수 있다. 위키피디아 피보나치 예시도 필요한 값만 들고 있으면 공간을 상수로 줄일 수 있다고 적고 있다.

## 흔한 실수

- 상태 정의가 모호하다: "dp[i]는 i까지의 답"이라고만 쓰면 점화식이 안 나온다. "i번째로 끝나는", "정확히 i원을 만드는"처럼 조건을 박아야 했다.
- 초기값을 빼먹는다: 최솟값 문제는 INF, 경우의 수는 `dp[0] = 1`처럼 문제에 맞는 값이 따로 있다.
- 배낭에서 순회 방향을 틀린다: 위에서 말한 것처럼 0/1 배낭은 거꾸로.
- 무조건 DP로 풀려고 한다: 그리디나 [BFS/DFS](#/post/algo-graph-search)로 되는 문제도 많다. 부분 문제가 겹치는지부터 본다.
- 재귀 메모이제이션에서 깊이 제한에 걸린다: 파이썬에서 깊이가 크면 `sys.setrecursionlimit`을 올리거나 bottom-up으로 바꾼다.

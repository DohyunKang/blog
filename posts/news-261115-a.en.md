## What it is
A CLI that does code review with AI. The README says it's Alibaba's internal review assistant, used for two years, now open sourced. It reads a Git diff, hands the changed files to an LLM agent, and returns review comments pinned to specific lines. The agent can read whole files and search the codebase, so it sees context outside the diff. An agent is a model that uses tools and decides its own next step. [More → Agent loop](#/post/ai-agent-loop)

Install with `npm install -g @alibaba-group/open-code-review`, set up a model provider, then run `ocr review`. There's also `ocr scan`, which goes through a whole folder without a diff.

## How it runs
The interesting part is the design argument. The README says that when you give a general agent like Claude Code a review skill, three things go wrong. On big changes it only looks at some files, the line numbers it points to drift from the real code, and small prompt changes swing the quality a lot. The cause, they say, is that the whole process is driven by words, with nothing to enforce it.

So the steps that must not go wrong are handled by ordinary code, not the model.

1. Picking files: code decides which files get reviewed and which get filtered out, so the model can't skip any.
2. Bundling: related files are grouped into one unit, like `message_en.properties` and `message_zh.properties`. Each bundle runs in its own sub-agent with separate context. [More → Sub-agents](#/post/ai-subagent)
3. Rule matching: a template engine picks only the review rules that fit each file, so the model reads less noise.
4. Positioning and reflection: separate modules outside the model fix which line a comment points to and re-check what the comment says.

The model only makes calls in between, like what extra context to look up. They also trimmed the tool list based on real usage logs: how often each tool gets called and how often calls repeat. [More → Tool use](#/post/ai-tool-use)

It has two modes. By default OCR calls a configured model API itself. In Delegation Mode, OCR only picks files and gathers rules, and the coding agent I already use does the review with its own model. The README says no separate OCR API key is needed then.

## Why people are talking about it
One table stands out. It uses 200 real PRs from 50 open-source repos, with 1,505 issues marked by people as the answer key (AACR-Bench, built by the project). With the same Claude-4.8-Opus model, OCR got 37.8% precision, 11.7% recall, 352K tokens and 1m6s per review. Claude Code got 15.93% precision, 12.70% recall, 2,062K tokens and 5m38s. Precision is how many flagged issues are real; recall is how many real issues got found. The README admits the lower recall is a deliberate trade-off to cut false alarms. The OCR version in the table is v1.3.1, far behind today's v1.13.9, and these are the project's own numbers. I didn't reproduce them. [More → Evals](#/post/ai-evals)

Releases come often too: v1.13.7 to v1.13.9 shipped on Nov 10, 12 and 13, and the 12th added GitHub Copilot CLI support.

## From a beginner's point of view
As a PM, the idea that stuck with me is "don't leave everything to the model; pin the parts that can't be wrong in code." When agent quality is uneven, instead of polishing the prompt again, you ask which step to move out of the model. And if a reviewer cries wolf a lot, people stop reading, so picking accuracy over coverage makes sense.

If you're new to coding, running `ocr review --commit <hash>` on one commit in a small project seems like a fine start. If you already use an agent like Claude Code, you can try Delegation Mode without a key. If you're curious about tools that hunt security bugs, this post goes well with it.

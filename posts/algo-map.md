코딩 테스트 문제를 보면 "이게 무슨 유형이지"부터 막힌다. 그래서 알고리즘 글 열한 편을 유형별로 한 줄씩만 적었다. 먼저 복잡도로 시간 안에 되는지 가늠하고, 그다음 자료구조 → 탐색 → 그래프 → 최적화 순서로 묶었다. 풀이와 코드는 각 글에 있다.

## 문제를 보고 고르는 순서

| 문제에서 보이는 것 | 먼저 떠올릴 유형 |
|---|---|
| 입력 크기가 크다, 이중 반복이면 시간 초과가 난다 | 복잡도로 어림하기 → 해시·누적합·투 포인터 |
| "이미 본 값인가", 개수 세기 | 해시 |
| 연속 구간의 합·길이 | 누적합, 투 포인터, 슬라이딩 윈도우 |
| 괄호, "오른쪽에서 처음 나오는 더 큰 수", 순서대로 처리 | 스택·큐 |
| 정렬된 데이터에서 찾기, "최대 얼마까지 되나" | 이분 탐색, 파라메트릭 서치 |
| 모든 경우를 해 보되 막히면 되돌아가기 | 재귀·백트래킹 |
| 칸·점·간선으로 이어진 구조 | BFS·DFS |
| 간선에 비용, 같은 편 묶기, 선후 관계 | 다익스트라, 유니온 파인드, 위상 정렬 |
| 작은 문제의 답을 재사용 | DP |
| 매번 가장 좋은 것만 고르면 되는 것 같다 | 그리디(반례 확인) |
| 가장 작은(큰) 것을 반복해서 꺼내기 | 힙·우선순위 큐 |

## 1. 바탕: 복잡도

**시간복잡도와 파이썬 기본**: 입력 크기만 보고 "이 풀이로 시간 안에 되나"를 어림하는 법과, 파이썬에서 자주 느려지는 자리, 코테용 입출력 기본.
[자세히 → 시간복잡도와 파이썬 기본](#/post/algo-complexity)

## 2. 자료구조로 푸는 유형

**배열·문자열·해시**: 같은 걸 또 세지 말고 한 번 세어서 적어 두는 유형이다. 적어 두는 자리가 누적합 배열이거나 해시(dict, set)다.
[자세히 → 배열·문자열·해시](#/post/algo-array-hash)

**스택·큐·덱**: 마지막에 넣은 걸 꺼내느냐, 먼저 넣은 걸 꺼내느냐의 차이. 괄호 검사, 오큰수, 카드 돌리기 같은 문제가 여기 나온다. 파이썬에서는 리스트와 deque만 구분해도 대부분 풀린다.
[자세히 → 스택·큐·덱](#/post/algo-stack-queue)

**트리·힙·우선순위 큐**: 트리는 순회 순서를 코드로 바로 쓸 수 있는지가 절반이고, 힙은 가장 작은(큰) 것을 계속 꺼내는 문제에서 heapq로 푼다.
[자세히 → 트리·힙·우선순위 큐](#/post/algo-tree-heap)

## 3. 범위를 줄여 가는 유형

**투 포인터·슬라이딩 윈도우·누적합**: 연속 구간 문제에서 구간을 매번 다시 더하지 않고 끝만 밀어서 O(N)에 푸는 세 가지 방법.
[자세히 → 투 포인터·슬라이딩 윈도우·누적합](#/post/algo-two-pointer)

**정렬과 이분 탐색**: 정렬은 거의 `sorted()`로 끝나고, 연습할 건 정렬된 데이터에서 절반씩 버리는 이분 탐색과 답 자체를 이분 탐색하는 파라메트릭 서치다.
[자세히 → 정렬과 이분 탐색](#/post/algo-sort-search)

## 4. 경우를 따라가는 유형

**재귀와 백트래킹**: 재귀는 작은 같은 문제로 바꾸기이고, 백트래킹은 그 재귀로 선택지를 하나씩 해 보다가 막히면 되돌아오는 탐색이다. 순열·조합·N-Queens가 대표 문제다.
[자세히 → 재귀와 백트래킹](#/post/algo-recursion)

**BFS·DFS와 그래프**: 다음에 볼 곳을 큐에 쌓느냐 스택에 쌓느냐만 다르다. 연결 요소, 미로 최단 거리, 영역 크기 같은 격자 문제까지 같은 틀로 푼다.
[자세히 → BFS·DFS와 그래프](#/post/algo-graph-search)

**최단 경로·유니온 파인드·위상 정렬**: BFS·DFS 위에서 자주 나오는 셋이다. 비용이 붙은 길 찾기(다익스트라), 같은 편 묶기(유니온 파인드), 순서 정하기(위상 정렬).
[자세히 → 최단 경로·유니온 파인드·위상 정렬](#/post/algo-shortest-path)

## 5. 답을 최적화하는 유형

**동적 계획법(DP)**: 같은 부분 문제를 두 번 풀지 않으려고 답을 적어 두는 방법이다. 점화식만 세우면 코드는 따라온다. 배낭, LIS, 동전 문제를 다룬다.
[자세히 → 동적 계획법(DP)](#/post/algo-dp)

**그리디**: 매 순간 제일 좋아 보이는 걸 고르고 돌아보지 않는 방식이다. 이 방식이 맞는 문제와 틀리는 문제를 가르는 게 핵심이라, 반례 확인을 같이 다룬다.
[자세히 → 그리디](#/post/algo-greedy)

## 공부 순서 제안

복잡도로 감을 잡은 뒤 자료구조(해시, 스택·큐) → 이분 탐색·투 포인터 → 재귀·BFS·DFS → DP·그리디 순으로 보면 앞 글이 뒤 글의 재료가 된다. 다익스트라와 힙은 그래프와 자료구조를 본 다음이 편하다.

今週、Hugging Face のトレンド、X、YouTube のローカルモデル動画で [Inkling 2 Mini](#/post/news-261127-a) の次によく見かけた名前は Ternary Bonsai 2.5 27B だった。PrismML が韓国時間 11月25日未明に公開したモデルだ。Qwen3.8-27B をもとに、本来 53.8GB のモデルを 5.93GB のファイル1つに縮めている。私は Hugging Face のモデルカードとホワイトペーパー2本(2.5 と、形式を最初に説明した Bonsai 2)を読んだ。自分では動かしていない。ベンチマークの数字はすべて会社が出した値だ。

## 3つの値だけ使う
ふつうモデルの重みは数字1つを16ビット(FP16)で持つ。量子化はそれを8ビットや4ビットのように少ないビットに詰める方法だ。Bonsai はほぼ行き着くところまで行く。重み1つが -1、0、+1 のどれかになる。これを ternary(三値)重みと呼ぶ。3つのうち1つなので情報量は log₂3、約1.585ビット。

3つの値だけでは大きさを表せないので、重み128個ごとに FP16 のスケールを1つ持つ。実際の値は「スケール × (-1, 0, +1)」だ。16ビットのスケールを128個で割ると1個あたり0.125ビット増えて約1.71ビット。配布ファイルは詰め方の都合で1重みあたり1.76ビット、5.93GB。FP16 の約9分の1だ。

圧縮せずに残した部分が面白かった。正規化層と linear attention 層の状態経路の一部、合わせて2,620万個(言語モデルの0.0976%、52MB)だけを元の精度で残す。前のバージョンはここまで三値にしていたそうだ。サイズにほとんど効かないところで、無理に削らなかったわけだ。

## 回してから丸める
丸める前にもう1段ある。重み行列を1,024個単位のブロックでアダマール回転してから三値にする。アダマール行列は +1 と -1 だけでできた直交行列だ。こういう回転を使うよくある理由は、飛び抜けて大きい値をいくつかのマスに均して、グループのスケールがその値に引っ張られないようにすること(QuaRot などの研究)。Bonsai のホワイトペーパーは式を書いているだけで、理由はあまり説明していない。

回転は保存された重みに前もって織り込まれているので、余分なビットはかからない。そのかわり推論時には入力(活性値)側に同じ変換をかける必要があり、実行プログラムがそれを知っていないといけない。通常の llama.cpp は b11556 ビルドからこの変換に対応した。それより古いビルドは警告なしにファイルを読み込み、でたらめな文字を出すとモデルカードに書いてある。読んだ中でいちばん実用的な一文だった。

ファイルは3種類。PTQ1_0(5.93GB、PrismML の llama.cpp フォークが必要)、PQ2_0(値1つを2ビットのマスに入れた 7.25GB、フォークが必要)、Q2_0(通常の llama.cpp の2ビット形式)。3つとも同じモデルだ。

## 2.5で変わったこと
形式は Bonsai 2 と同じ。変わったのはエージェント作業の成績だ。会社の表では、ツール呼び出しのベンチマーク5つの平均が FP16 の元モデルで77.7、Bonsai 2.5 で77.2。コーディングエージェントのベンチマーク3つは FP16 のスコアの63%から90%に上がった。DeepSWE は0から27.0、SWE-bench Verified は60.8から75.6。どう再学習して上げたのかはモデルカードにもホワイトペーパーにもなく、確認できなかった。

目に留まった比較が1つある。同じ Qwen3.8-27B をふつうの方法で2.5ビットまで縮めた GGUF(GSQ-RCO IQ2_XS)は、τ²-Bench では79.5なのに AppWorld では46.5まで落ちる。5回に1回くらい、結果を見る前に API 呼び出しを全部推測した長いスクリプトを書いて、終わったと宣言するという。ほかのスコアにはこの失敗が出てこない、というのが会社の説明だ。

MTP 版も一緒に出た。次のトークンをいくつか先に推測する層を1つ足したものだ。投機的デコーディングで、本体のモデルがその推測を一度に確かめ、自分が出したはずのトークンだけを受け取る。だから出力は変わらず、デコードだけが NVIDIA GPU で1.5〜1.8倍速くなるという。MTP なしでも、モデルカードの表では RTX 5090 で毎秒163トークン(PTQ1_0)だ。

## なぜ話題なのか
「27B のコーディングモデルが16GB の GPU に入る」という話だ。動画の説明欄によると4ビット版でも17GB ほどで16GB のカードには収まりきらないが、これは6GB。YouTube には RTX 4060 Ti 16GB で動かした動画、RTX 4090 でコーディング課題86個を回した動画、M5 Max の Mac で動かした動画が3日のあいだに続けて上がった。

反応がすべて良かったわけではない。4090 の動画のタイトルは "Strong quant; not up to the hype" だった。説明欄には、同じカードに入るほかのモデルいくつかより通過率が低く、Python を C に移す課題で0を延々と出し続けたとある。条件がそれぞれ違い、暫定の結果だという断りも付いていた。動画の再生数と Reddit の反応は確認できなかった。

ホワイトペーパーの限界の項目も似たことを書いている。Terminal-Bench 2.1 がまだ FP16 からいちばん遠く、何時間も続く長いエージェント作業はまだ測っていないそうだ。

## 入門者として
量子化は「精度を少し捨ててサイズを縮めること」くらいに思っていた。丸める前に値を均しておく段階があって、そのせいで実行プログラムのバージョンまで合わせないといけないのは新しかった。モデルファイルを落とせば終わり、ではなかった。

PM としては、「FP16 と同等」という文を見たら、どのベンチマークの平均なのか、平均に出てこない失敗がないかを一緒に見たい。その例をこの会社が自分の表に入れていた。

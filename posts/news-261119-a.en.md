## What it is
A skill is a folder of instructions an agent pulls in when it needs them: one SKILL.md with directions and examples, sometimes helper scripts. [More → Skills](#/post/ai-skills) Skill collection repos show up on trending a lot lately, but whether a skill helps has mostly been a gut call. SkillEvaluator splits the check into three tiers.

1. Tier 1 (validation): static checks for format, version, personal data, license, hidden Unicode, leaked secrets, script safety. The README says 500+ rules and detection patterns, and it runs without a model key. Quality is scored out of 100, passing at 70 by default.
2. Tier 2 (deduplication): uses embeddings to see whether instructions overlap inside a skill or with other skills. Embeddings turn text into number vectors so you can measure how close two pieces of meaning are.
3. Tier 3 (live evaluation): runs the same tasks in a Docker sandbox, once with the skill and once without. The difference is Skill Lift.

Tier 1 has a separate Harness Check, which I liked. Claude Code, Codex, OpenCode, Copilot CLI and others each scan different folders and cap description length differently. So it can tell you, without running an agent, things like "the description is 4 over the 1,024 limit, so Copilot CLI never loads it." I suspect a lot of "the skill doesn't work" is this kind of thing, not the content.

## How Skill Lift is measured
Tier 3 scores six signals from 0 to 1 per attempt: security, whether the skill was found and used (skill_execution), how efficiently it was used, matching the expected output (accuracy), reaching the goal (goal_accuracy), and doing the required actions (behavior_check). Token efficiency is reported but not scored. Some of these use an LLM as the grader. [More → Evals](#/post/ai-evals)

The formula is plain: `Skill Lift = overall with skill - overall without skill`, computed only on cases both arms ran and signals both arms scored. +0.05 or more is PASS, -0.10 or less is FAIL, in between is NEUTRAL. Small case counts are noisy, so it also reports a 95% interval by resampling whole cases (bootstrap). With a single case it reports no interval, because a zero-width one would look final.

The docs have a section called "What has not been established," which I appreciated. No study of agreement with human raters. Thresholds like the 0.50 pass line and the lift bands are conventions, not derived values. And since the comparison is skill vs no skill, it can't separate the skill's content from the effect of just getting one more instruction. That last one was my question too while reading.

## Numbers from the paper
There's a paper on the same method (arXiv 2608.20614, submitted in August). Per the abstract, across 145 real skills the structural score and LLM-judge score correlate weakly (ρ = 0.14), so static checks and real effect look at different things. Across 947 paired cases from 58 production skills, mean Skill Lift was 0.2134, and lift was positive in 72.8% of cases. The biggest gains were in finding the skill and following its workflow rather than raw accuracy, which the paper says document scans can't see.

## For beginners
For a PM, the useful part is turning "adding the skill will probably help" into "we compared with and without on the same tasks." It's basically an A/B test on an agent's instructions. The default that fewer than 10 cases isn't enough is a decent rule of thumb too.

For a beginner developer, tier 1 alone is the easy start. After `pip install skillevaluator`, `skillevaluator quality-check ./my-skill` runs with no key, GPU or Docker, and so does `harness-check`. Tier 3 needs a model key and Docker and can cost model usage. Support level is Experimental, no official NVIDIA support. Pairs well with my older post on popular skills.

今週の GitHub トレンドリストは、ほぼエージェントスキルとハネス関連でしたが、その中に一風変わったレポジトリがありました。TauricResearch の TradingAgents です。これは、トレーディング会社の役割分担を LLM エージェントに移したプロジェクトです。

## 今週のトレンドで見たもの

週間トレンドの上位 15 つのうち、13 つが AI 関連でした。ほとんどはコーディングエージェントに追加するスキル、CLAUDE.md、メモリ、ハネスなどのツールでした。その中で、エージェント同士が役割分担して働く構造自体がテーマとなっているのは TradingAgents のほうでした。

確認した時点は 2026 年 11 月 2 日で、この時点での GitHub ページ基準ではスター数は約 11 万 9,000（ヘッダー表示は 12 万）、フォーク数は 2 万 2,900 です。これらの数値は毎日変化します。ライセンスは Apache-2.0、最新リリースの表記は v0.7.1（2026 年 10 月）でした。

## プロジェクトの内容

README はこれを、LLM と LangGraph の上に構築したマルチエージェントトレーディングフレームワークとして紹介しています。実際のトレーディング会社の組織を模倣していることが核心です。エージェントたちが市場状況について議論の後に意思決定を行います。

役割は以下の通り分担されています。

| 段階 | 役割 | 行うこと |
|---|---|---|
| アナリストチーム | ファンダメンタルズ、センチメント（ニュース・StockTwits・Reddit）、マクロ経済、テクニカル指標（MACD、RSI など） | 並列でそれぞれ資料を確認しレポートを作成する |
| リサーチャートーム | 強気リサーチャー、弱気リサーチャー | アナリストのレポートについて議論を行う |
| トレーダー | トレーダー | レポートを統合して売買タイミングと規模を決定する |
| リスク・運用 | リスク管理、ポートフォリオマネージャー | 提案を評価し承認または却下する。承認された注文はシミュレーション取引所向けに送られる |

一言で言えば、分析 → 議論 → 意思決定 → リスクレビュー → 承認という順序です。一つのモデルが一度に答えを出すのではなく、同じ問題を複数の視点に分けて互いに反論させる構造になっています。

この構造は、エージェント設計の論文で言及されているパターンと大きく重なります。アナリストたちが同時に作業する部分は並列化であり、強気と弱気が対峙する部分は、あるエージェントの結果を別のエージェントが評価するレビュー段階に近いものです。このようなパターンは [詳細 → エージェント設計パターン](#/post/app-agent-design) に別途整理しています。役割ごとにコンテキストを別々に記述する点は、[詳細 → サブエージェントとマルチエージェント](#/post/ai-subagent) とも繋がります。

## どのモデルで動かせるか

サポートされているプロバイダーのリストが長かったです。OpenAI、Google、Anthropic、xAI、DeepSeek、Qwen、GLM、MiniMax、OpenRouter、Mistral、Kimi、Groq、NVIDIA NIM、AWS Bedrock、Azure OpenAI があり、ローカルモデルは Ollama で接続します。OpenAI 互換エンドポイントであれば何でも使用でき、ChatGPT Plus・Pro のサブスクリプションでも対応していると記載されています。

一つのレポジトリがこれほど多くのプロバイダーをサポートしていることは、エージェント構造そのものはそのままにしてモデルだけを差し替えることが一般的な使用方法になったことを示唆しています。各エージェントは [LLM](#/post/ai-llm) を呼び出す薄い層であるという話でもあります。

## 試すには

README の基準では Python 3.11 以上が必要で、例では 3.13 を使用します。レポジトリを取得して `pip install .`（または `uv pip install .`）でインストールし、`tradingagents` または `python -m cli.main` で CLI を起動します。Python コードでは `TradingAgentsGraph` をインポートして利用することもできます。Docker で動かすには `.env.example` を `.env` にコピーしてキーを埋め、`docker compose run --rm tradingagents` を実行します。

その他に、永続メモリログ、チェックポイントからの継続、銘柄・日付グリッドでのバックテスト、ポートフォリオを考慮した実行、Yahoo Finance テイカーによる米国以外の市場サポートなどが機能リストに含まれています。

## 関連するヒント

この README は、本プロジェクトが研究目的で作成されたものであり、金融・投資・取引に関する助言ではないことを明記しています。また、性能はモデルの選定、温度パラメータ、データの品質、そして結果が毎回変動する性質によって左右されるとも記載されています。同じ入力でも議論の内容が変わる可能性があるため、一度得られた結果を根拠として用いるのは困難です。

議論の構造を構築した理由もこの点に関連しているようです。単一の呼び出しよりも、複数回にわたり相互検証を行う方が揺らぎが少ないという期待があります。その代わり、呼び出し回数は役割の数に応じて増え、コストもそれだけ高くなります。[エージェントループ](#/post/ai-agent-loop) が何周するかによって、1 回の実行あたりのトークン数が大きく変わる構造です。

私はこのレポを投資ツールというよりは、マルチエージェント構造の例題として読みました。役割をどのように分割し、どのような順序で衝突させるかを観察するには優れたサンプルでした。実際に動かす場合は、模擬取引所向けに限定するのが適切でしょう。

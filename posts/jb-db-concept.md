정보처리기사 데이터베이스 파트는 키, 관계대수, ER 모델 세 덩어리로 나뉜다. 뒤에 나오는 정규화와 SQL이 전부 이 용어 위에서 돌아가서, 여기를 먼저 눌러 두는 게 맞았다.

## 데이터 모델이 뭔지

데이터베이스를 만든다는 건 현실의 일을 표 모양으로 옮기는 일이다. 이때 "무엇을 어떤 규칙으로 표현할지"를 정해 둔 틀이 데이터 모델이다. 시험에서는 구성 요소 세 가지로 묻는다.

| 구성 요소 | 뜻 |
|---|---|
| 구조(structure) | 데이터가 어떤 모양으로 놓이는지 |
| 연산(operation) | 그 데이터를 어떻게 꺼내고 바꾸는지 |
| 제약조건(constraint) | 어떤 값이 들어오면 안 되는지 |

관계형 모델에서는 구조가 릴레이션(표), 연산이 관계대수, 제약조건이 키와 무결성 규칙이다. 이 글의 세 덩어리가 그대로 이 세 칸에 들어간다.

데이터 모델링은 보통 개념 → 논리 → 물리 순으로 내려간다. 개념 단계는 세부 사항이 가장 적고 범위를 잡는다. 논리 단계는 특정 DBMS와 상관없이 구조를 상세하게 만든다. 물리 단계는 테이블, 인덱스, 제약조건까지 실제로 만들 수 있을 만큼 기술에 묶인다. ER 모델은 개념 단계에서 주로 쓰는 도구다. 물리 단계는 [자세히 → DB 물리 설계와 분산 DB](#/post/jb-physical-design)에서 이어진다.

## 릴레이션의 용어

관계형 모델의 용어는 한글과 영어가 섞여 나와서 짝을 외워 두면 편하다.

| 용어 | 뜻 | 표에서는 |
|---|---|---|
| 릴레이션(relation) | 속성 이름들(헤더)과 튜플들(본문)의 묶음 | 표 하나 |
| 속성(attribute) | 이름과 타입이 있는 헤더의 한 칸 | 열(column) |
| 튜플(tuple) | 속성마다 값이 하나씩 있는 한 줄 | 행(row) |
| 도메인(domain) | 한 속성이 가질 수 있는 값의 집합 | 정수, 문자열, 날짜 같은 타입 |
| 차수(degree) | 속성의 개수 | 열 수 |
| 카디널리티(cardinality) | 튜플의 개수 | 행 수 |

차수와 카디널리티는 헷갈리기 쉽다. 차수는 가로(열), 카디널리티는 세로(행)로 기억했다. ER 모델에서 "카디널리티"는 일대다 같은 관계의 개수 제약을 뜻하기도 해서, 같은 단어가 두 군데서 다른 뜻으로 나온다는 점도 알아 둬야 한다.

## 키

키는 튜플을 서로 구분해 주는 속성(들)이다. 범위가 넓은 것부터 좁은 것으로 줄여 가면 순서가 잡힌다.

| 키 | 정의 |
|---|---|
| 슈퍼키 | 값 조합이 모든 튜플에서 유일한 속성 집합 |
| 후보키 | 슈퍼키 중에서 더 줄이면 유일성이 깨지는 최소 집합 |
| 기본키 | 후보키 중에서 대표로 고른 것 |
| 대체키 | 후보키 중 기본키가 되지 못한 나머지 |
| 외래키 | 다른 릴레이션의 후보키 값과 짝이 맞아야 하는 속성 집합 |

슈퍼키는 유일성만, 후보키는 유일성에 최소성까지 요구한다. 학생 표에서 {학번}이 후보키면 {학번, 이름}은 슈퍼키이지만 후보키는 아니다. 학번만으로도 이미 구분되기 때문이다. 주민번호 같은 다른 후보키가 있으면 기본키로 안 뽑힌 쪽이 대체키가 된다.

시험에서는 표를 하나 주고 "후보키가 몇 개인가", "이 속성은 기본키가 될 수 있는가"를 묻는 식이 많다. 풀 때는 값이 겹치는 열을 먼저 지우고, 남은 열 중에서 혼자 유일한 것을 찾은 뒤, 그다음 조합을 보는 순서로 했다. 조합까지 봤을 때 이미 유일한 열이 들어 있으면 그 조합은 최소가 아니라서 후보키에서 빠진다.

## 무결성

키는 제약조건 쪽으로 이어진다. 시험에는 개체 무결성, 참조 무결성, 도메인 무결성이 나온다.

- 개체 무결성: 기본키는 NULL이 될 수 없고, 같은 값이 둘 있을 수도 없다.
- 참조 무결성: 외래키는 참조하는 릴레이션에 실제로 있는 값이거나 NULL이어야 한다.
- 도메인 무결성: 속성 값은 정해 둔 도메인 안에 있어야 한다.

외래키를 걸어 두면 DBMS가 제약을 어기는 변경을 거절한다. 학생 표에 없는 학번으로 수강 기록을 넣으려 하면 막히는 식이다.

<details>
<summary>참조 무결성이 깨지는 상황 정리</summary>

부모 표는 학생(학번 기본키), 자식 표는 수강(학번 외래키, 과목 코드)이라고 하자.

| 동작 | 문제가 되는 경우 |
|---|---|
| 자식에 삽입 | 부모에 없는 학번을 넣음 |
| 부모에서 삭제 | 자식이 가리키고 있는 학번을 지움 |
| 부모 키 수정 | 자식이 가리키는 학번을 바꿈 |

부모 삭제 때의 대응은 제한(자식이 있으면 거절), 연쇄(자식도 같이 삭제), NULL로 변경 같은 방식으로 나눠 외워 두면 된다. 실제 문법은 [자세히 → SQL 응용](#/post/jb-sql-basic)에서 다룬다.

</details>

## 관계대수

관계대수는 릴레이션을 입력으로 받아 릴레이션을 내놓는 연산 모음이다. 결과가 또 릴레이션이라서 연산을 이어 붙일 수 있다. 기본이 되는 연산은 이렇다.

| 연산 | 기호 | 하는 일 |
|---|---|---|
| 셀렉션 | σ | 조건에 맞는 튜플(행)만 고름 |
| 프로젝션 | π (Π) | 지정한 속성(열)만 남김 |
| 리네임 | ρ | 속성 이름만 바꿈 |
| 합집합 | ∪ | 두 릴레이션의 튜플을 합침 |
| 차집합 | − | 앞 릴레이션에만 있는 튜플 |
| 카티전 프로덕트 | × | 두 릴레이션의 튜플을 모든 쌍으로 짝지음 |

여기서 파생되는 연산이 교집합(∩)과 조인(⋈)이다. 교집합은 합집합과 차집합으로 만들 수 있고, 조인은 짝이 맞는 튜플끼리 결합한 결과를 낸다. 자연 조인은 이름이 같은 속성의 값이 같은 튜플끼리 붙인다. 합집합·차집합·교집합은 두 릴레이션의 속성 구성이 같아야 쓸 수 있다는 조건이 붙는다. 카티전 프로덕트는 두 릴레이션의 속성 이름이 겹치지 않아야 한다.

외우기용으로 둘로 나눠 봤다. 셀렉션과 프로젝션은 한 표 안에서 자르는 연산이다. 셀렉션은 가로로(행), 프로젝션은 세로로(열) 자른다고 기억하면 헷갈릴 일이 줄었다. 나머지는 두 표를 합치는 연산이다.

디비전(÷)은 "전체 과목을 다 수강한 학생" 같은 조건에 쓰는 연산이다. 정의는 교재에서 따로 외워야 한다.

<details>
<summary>SQL로 옮겨서 직접 돌려 본 결과</summary>

연산이 눈에 안 들어와서 SQLite로 작은 표를 만들어 대응시켜 봤다. 학생(1 kim cs, 2 lee ee, 3 park cs)과 수강(1 db, 1 os, 2 db, 3 db, 3 os)이다.

```sql
-- 셀렉션 σ 학과='cs'
select * from student where dept='cs';
-- → (1,kim,cs) (3,park,cs)

-- 프로젝션 π 학과 (중복 제거)
select distinct dept from student;
-- → cs, ee

-- 자연 조인
select name, cid from student natural join enroll;
-- → kim db, kim os, lee db, park db, park os

-- 카티전 프로덕트: 3행 × 5행
select count(*) from student, enroll;
-- → 15
```

집합 연산도 같이 돌렸다. old={1,2}, new={2,3}일 때 union은 1,2,3, except는 1, intersect는 2가 나왔다.

프로젝션에 distinct가 붙은 이유가 있다. 관계대수에서 릴레이션은 튜플의 집합이라 중복이 없다. SQL의 select는 중복을 그대로 두는 게 기본이라서 distinct를 써야 둘이 맞아떨어진다.

</details>

## ER 모델

ER 모델은 현실을 엔티티와 관계로 그리는 개념 모델이다. 구성은 세 가지다.

- 엔티티: 식별할 수 있는 대상. 보통 명사다(학생, 과목).
- 속성: 엔티티나 관계를 설명하는 값(학번, 이름). 엔티티를 구분하는 속성에는 밑줄을 긋는다.
- 관계: 엔티티 사이의 연결. 보통 동사다(수강한다).

시험에서 자주 나오는 Chen 표기법은 도형으로 구분한다.

| 요소 | 도형 |
|---|---|
| 엔티티 | 사각형 |
| 관계 | 마름모 |
| 속성 | 타원 |

관계에는 개수 제약이 붙는다. 학생 한 명이 과목 여러 개를 듣고 과목 하나에 학생이 여럿이면 다대다(N:M)다. 교수 한 명이 과목 여러 개를 맡고 과목은 교수 한 명만 있으면 일대다(1:N)다. 이 개수 제약을 카디널리티라고도 부른다. 다른 표기법인 crow's foot에서는 고리가 0, 막대가 1, 갈퀴가 다수를 뜻하고, 두 기호를 짝지어 최소·최대를 나타낸다.

ER 도형을 표로 바꾸는 규칙은 문제로 자주 나온다. 기본 대응은 엔티티가 표가 되고 속성이 열이 되고 밑줄 친 식별 속성이 기본키가 된다는 대응이다. 다대다 관계의 변환과 같은 세부 규칙은 교재 표를 따로 보면서 외우는 쪽이 정확하다.

## 흔한 헷갈림

| 헷갈리는 것 | 정리 |
|---|---|
| 슈퍼키 vs 후보키 | 후보키는 최소성이 붙는다 |
| 차수 vs 카디널리티 | 열 수 vs 행 수 |
| 셀렉션 vs 프로젝션 | 행을 거름 vs 열을 거름 |
| 기본키 vs 대체키 | 후보키 중 뽑힘 vs 안 뽑힘 |
| 카디널리티 두 가지 | 릴레이션의 튜플 수 vs ER의 관계 개수 제약 |

여기까지가 모델의 뼈대고, 이 키를 기준으로 표를 쪼개는 규칙이 [자세히 → 정규화와 트랜잭션](#/post/jb-normalization-transaction)이다. 풀이 연습은 키 개수 세기, 관계대수 결과 릴레이션의 차수·카디널리티 구하기, 기호 이름 맞히기 세 가지로 해 두면 된다. 시험 일정과 응시 정보는 공식 사이트에서 확인한다.

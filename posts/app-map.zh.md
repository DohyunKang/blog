在开发 LLM 应用时，往往比模型调用本身更费心的是其周边环节：如何设计架构、如何挂载外部文档、成本是多少、如何评估效果、在哪里设置拦截点、以及如何连接工具。本系列将逐一深入这六个方面进行实践，本文即为该系列的目录。如果概念术语感到陌生，请先阅读 [AI 概念地图](#/post/ai-map)。

## 一览全貌的流程图

```
구조를 정한다   → 에이전트 설계 패턴
지식을 붙인다   → RAG 직접 만들기
도구를 붙인다   → MCP 서버 만들어 보기
돈을 계산한다   → AI 서비스 원가 구조
품질을 잰다     → LLM 앱 평가
바깥에서 막는다 → 가드레일과 안전장치
```

## 1. 构建前需确定的事项

**Agent 设计模式**：在开始构建 Agent 之前，先按既定顺序梳理工作流是否可行。针对每种模式进行了整理。一次 LLM 调用能否完成？若不能，应明确界定到哪一步为止，以及从何处将任务交给模型，这是出发点。
[详情 → Agent 设计模式](#/post/app-agent-design)

**AI 服务成本结构**：由于用户每次使用时都会产生 Token 费用，因此需先计算单次调用的价值，再乘以调用次数和用户数量，得出月度总成本。
[详情 → AI 服务成本结构](#/post/app-cost)

## 2. 添加功能

**直接构建 RAG**：无需依赖库，仅用数十行 Python 代码实现并运行 RAG，依次实践文档切片、向量化、检索、评估等五个关键环节。相关概念见 [RAG](#/post/ai-rag) 文章。
[详情 → 直接构建 RAG](#/post/app-rag-build)

**尝试构建 MCP 服务器**：这相当于为几个函数添加名称和描述并对外暴露，因此直接用单个 Python 文件运行了一个包含两个工具的服务器。规范请参考 [MCP](#/post/ai-mcp) 文章。
[详情 → 尝试构建 MCP 服务器](#/post/app-mcp-server)

## 3. 验证效果与防护

**LLM 应用评估**：每次修改提示词仅凭感觉检查，往往会在某处悄然出错；因此应使用预先定义的问题集和评分标准进行打分，以便在同一标准下进行比较。
[详情 → LLM 应用评估](#/post/app-eval)

**护栏与安全机制**：向模型请求“小心行事”并非真正的安全机制，而应在应用代码中专门设置拦截错误输入或行为的点位。这并非修正模型的措辞，而是为外部加装门锁。
[详情 → 护栏与安全机制](#/post/app-guardrails)

## 阅读顺序

如果是初次接触，建议按以下顺序阅读：设计模式 → 成本 → RAG → MCP 服务器 → 评估 → 护栏。如果已有应用正在开发，只需挑选遇到的瓶颈点单独阅读即可。

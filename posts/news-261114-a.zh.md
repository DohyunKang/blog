## 是什么
一套技能，让编程代理写网页界面代码时用现在的浏览器功能，而不是老写法。技能就是代理需要时拿出来读的操作说明文件。[详细 → 技能](#/post/ai-skills)

README 说的问题是这样：模型学过的代码大多是旧代码，所以明明浏览器已经自带的功能，它还是去写一堆很重的 JavaScript。比如用库做弹窗，用脚本算提示框的位置。于是把 Chrome、Edge、Firefox、MDN 团队整理的指南直接塞进代理的上下文。1.0 时有 203 篇指南，覆盖 250 个网页功能。

## 怎么运行
结构很简单。代理接到 HTML、CSS 或浏览器相关的任务时技能就会启用，SKILL.md 里写着按下面的顺序做。

1. search:用 "light dismiss dialog" 这样 2~5 个词去找指南。要求去掉框架名和应用自己的名词。
2. retrieve:用找到的指南 id 取回正文，放进上下文。
3. 核对：检查写好的代码是否按指南的写法和兜底代码(fallback)来。
4. 说明：在回答末尾简短写明用了哪篇指南、改了什么。

搜索只在本机跑。据 README 说，它把一个小的嵌入模型和 BM25 混在一起用，不需要网络也不需要 API 密钥。嵌入是把句子变成数字向量来找意思相近的内容,BM25 是按词语重合程度打分的传统检索方法。[详细 → 嵌入](#/post/ai-embedding) 不过用 `npx` 拉最新包这一步还是要联网。

打开一篇指南看，写得挺具体。导航抽屉(navigation-drawer)指南让你用 `<dialog>` 加 CSS 滚动吸附，把滑动交给浏览器处理，还把"一定要给屏幕阅读器一个名字"这类必做项写在注释里。

浏览器支持也有规则。在 Baseline(主流浏览器都已充分支持的功能列表)里属于"广泛可用"的功能直接用，其他的必须按指南的兜底代码来。上线不到3个月、只有一个浏览器支持、或者还在实验中的功能，搜索能搜到，但要在 `.mwgrc` 里允许才能取正文。

## 为什么火
11月10日(韩国时间)摘掉预览标签，发布了 1.0.0。新增了 `legacy-scan`,能在现有代码里找出老写法并对应到替换用的指南；搜索引擎也不再用 TensorFlow.js,npm 包从 23.5MB 缩到 8.8MB。差不多同时，维护方从 Chrome 一家扩大到 Edge、Firefox、MDN 团队。今天上榜的是编写和评测指南的源码仓库。

评测方法一起公开了，这点挺显眼。他们给真实的网页应用提"让图片加载快一点"这类需求，不提任何 API 名，用 Playwright 检查对比有指南和没指南时代理的通过率。评分器先调好，保证标准答案 100% 通过、没改过的应用 100% 不通过。README 里 11月8日的结果:Claude Code(opus-5-5)从 57% 到 88%,Codex CLI(gpt-6.1-sol)从 54% 到 82%,Antigravity CLI(gemini-4-argon)从 58% 到 94%。这是项目自己测的数字，我没有复现。[详细 → 评测(evals)](#/post/ai-evals)

在 Reddit 和 YouTube 上传得多广，没能确认。

## 从入门者角度看
站在 PM 的角度，"模型不懂的东西不靠训练教，而是递文档"这个思路很好懂。模型不变，只在需要的时候给一小段指南，据说模型本来就擅长的内容，会根据评测结果从指南里删掉。开发新手可以先不装，跑一下 `npx modern-web-guidance@latest search "animate a dialog modal backdrop"` 这样的搜索，或者在自己的小项目上跑 `legacy-scan .`,从这里开始就行。

要注意的地方。它会收集匿名使用数据：安装次数、调用的代理名、指南 id、代理生成的搜索词，写着不收集用户的原始提示词。用 `DISABLE_TELEMETRY=1` 可以关掉。`legacy-scan` 只检查大约 20% 的指南。对前端无障碍感兴趣的话，这篇也可以看看。[详细 → 无障碍](#/post/fe-accessibility)

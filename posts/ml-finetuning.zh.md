微调（Fine-tuning）是对预训练完成的模型使用自身数据进行再次训练的过程。根据是修改整个模型还是仅调整部分参数，所需的 GPU 资源会有显著差异。

## 什么是微调

[LLM](#/post/ai-llm) 首先通过海量文本进行预训练。在此阶段，模型学习语言的整体规律，这部分工作个人难以独立完成。相关内容在 [从预训练到 RLHF](#/post/ml-pretraining) 中已有总结。微调是在此之后进行的第二次学习：向已经具备说话能力的模型额外教授特定的语气、特定格式或特定领域的解题方法。

总结如下：

| | 预训练 | 微调 |
|---|---|---|
| 数据 | 海量通用文本 | 数百至数万个目标数据 |
| 目的 | 奠定语言与知识基础 | 实现特定行为、格式或语气 |
| 起点 | 随机权重 | 已学习的权重 |
| 成本 | 个人难以承担 | 视模型和方法而定 |

数据通常由“输入和期望输出”的配对组成，例如问题与答案、长文档与摘要等。通过向模型展示这些配对并逐步调整权重来完成学习。学习方式与预训练相同的 [神经网络学习](#/post/ml-neural-net)，不同之处仅在于数据和起点。

## 为什么全量微调如此沉重

全量微调（full fine-tuning）会更新模型的所有权重。问题在于内存占用。为了进行训练，除了权重外，还必须同时保存梯度和优化器状态。以 Adam 系列优化器为例，它需要为每个参数额外存储两个值。因此，训练所需的内存往往是模型大小的数倍。

仅举一个数字为例：即使将拥有 70 亿参数的模型以 16 位（2 字节）加载，权重本身也约占 14GB。而在训练过程中，还需加上梯度和优化器状态。具体的倍数取决于精度设置和优化器的配置。

另一个问题是副本问题。如果为不同用途分别进行微调，就会为每个用途生成一份完整的模型副本。如果 7B 模型的单份副本占用 14GB，那么十个用途就需要 140GB。

## LoRA 的创意

LoRA（Low-Rank Adaptation）源自 Hu 等人于 2021 年发表的论文。其方法是将预训练的权重冻结（freeze），并在每一层插入可学习的小矩阵。论文摘要指出，以 GPT-3 175B 为基准，所需学习的参数减少了约 1/10,000，GPU 内存需求减少了约 1/3。性能方面，在 RoBERTa、DeBERTa、GPT-2 和 GPT-3 上，LoRA 的表现与全量微调相当甚至更好。摘要还提到，推理时的延迟不会增加。

原理如下：与其直接修改单个权重（矩阵 W，大小为 d×k），不如将变化量 ΔW 表示为两个小矩阵的乘积。

```
W' = W + (alpha / r) * B @ A
     W: d x k (고정)
     B: d x r, A: r x k (이것만 학습, r은 d, k보다 훨씬 작다)
```

其中 r 是秩（rank）。若 d=k=4096 且 r=8，则 W 的大小约为 1,678 万，而 A 和 B 之和约为 6.5 万。仅看这一个矩阵，其大小仅为原来的 256 分之一。PEFT 文档解释说，学习参数数量“由秩 r 和原始矩阵的形状决定”。r 越小，矩阵就越小。

初始值也值得关注：B 初始化为 0，A 则随机初始化。因此，在学习开始时 B@A 为 0，模型行为与原模型完全一致，随后才逐渐偏离。下面用 numpy 进行了直接验证。

<details>
<summary>详细解析：使用 numpy 验证 LoRA 的代码</summary>

```python
import numpy as np
rng = np.random.default_rng(0)
d, k, r, alpha = 64, 64, 4, 8
W = rng.normal(size=(d, k))
A = rng.normal(size=(r, k)) * 0.01
B = np.zeros((d, r))
x = rng.normal(size=(k,))

# 1) B가 0이면 LoRA를 붙여도 출력이 그대로
print(np.allclose(W @ x, (W + (alpha / r) * B @ A) @ x))   # True

# 2) 학습 후라고 치고 B를 바꾸면, 따로 계산한 것과 합쳐서 계산한 것이 같다
B = rng.normal(size=(d, r)) * 0.1
y_split  = W @ x + (alpha / r) * (B @ (A @ x))
y_merged = (W + (alpha / r) * B @ A) @ x
print(np.allclose(y_split, y_merged))                       # True
print(W.size, A.size + B.size)                              # 4096 512
```

运行结果为 True, True, 4096 512。第二次确认对应“合并后效果相同”的部分。关于合并的讨论将在下文展开。

</details>

## 附加在哪里以及选择什么

根据 PEFT 文档，LoRA 可以附加到任何权重矩阵上，但在 Transformer 架构中，通常仅附加到注意力（attention）块上。[Transformer 与注意力](#/post/ml-transformer) 中提到的查询（query）、键（key）、值（value）投影矩阵即为目标。选择在哪一层附加 LoRA 可通过 `target_modules` 参数指定。

常用的配置参数有三个：

| 设置 | 作用 |
|---|---|
| `r` | 秩。数值越小参数越少，数值越大表达能力越强 |
| `lora_alpha` | 缩放因子。默认情况下会乘以 alpha / r |
| `target_modules` | 附加 LoRA 的层 |

哪个值更优取决于具体模型和数据，文档也未对数值做出绝对判断。

## 合并与适配器

训练完成后，B 和 A 会被保存为容量较小的独立文件（即适配器）。使用方法主要有两种：

- 适配器是叠加在基础模型之上的。只需更换一个基础模型上的适配器，即可适应不同用途，无需为每种场景准备多个副本。
- 使用 `merge_and_unload()` 将 W 合并到普通模型中。正如 numpy 第二个检查所示，结果一致，因此合并后没有额外的延迟。这就是 PEFT 文档声称"LoRA 不增加推理延迟”的原因。

副本问题也得到了解决。适配器文件比基础模型小得多，其确切大小取决于 r 值和目标层。

## QLoRA：进一步压缩基础模型

LoRA 虽然减少了需要学习的参数，但基础模型仍需以 16 位精度载入内存。QLoRA（Dettmers 等，2023）则将基础模型量化为 4 位并载入内存，仅在此基础上训练 LoRA 适配器。梯度流经冻结的 4 位模型，最终流向适配器。

论文摘要中提出的技术主要有三种：

- 4 位 NormalFloat (NF4)：一种针对服从正分布权重的 4 位数据类型
- 双重量化（double quantization）：对用于量化的常数也进行量化，从而进一步节省内存
- 分页优化器（paged optimizers）：管理训练过程中内存波动较大的部分

论文声称可在单张 48GB GPU 上微调 650 亿参数模型，并保持与 16 位微调相当的性能。这一对比结果是在作者设定的实验条件下得出的。采用此方法构建的 Guanaco 模型系列在 Vicuna 基准测试中表现优于当时公开的其他模型；据称仅用单张 GPU 训练 24 小时即可达到 ChatGPT 水平的 99.3%。但需注意，这仅基于单一基准测试结果，在其他任务上是否同样出色是另一回事。将模型量化为 4 位的技术思路与 [本地运行模型](#/post/ml-local-models) 中讨论的内容属于同一类理念。

## 何时进行微调，何时使用 RAG

两者解决的问题不同。[RAG](#/post/ai-rag) 针对每个问题检索相关文档并附加到 [提示词](#/post/ai-prompt) 中，以补充未知信息；而微调则是直接改变模型的行为本身。

| | RAG | 微调 |
|---|---|---|
| 适用场景 | 最新信息、内部资料、提供出处 | 语气风格、输出格式、特定任务方式 |
| 信息变更时 | 仅需更新文档 | 需重新训练 |
| 所需准备 | 文档与检索环境 | 输入输出对数据与 GPU |
| 推理阶段 | 涉及检索成本及较长提示词 | 提示词可更简短 |

许多人试图将知识注入模型，因此倾向于使用微调，但需谨慎判断。无法保证模型能准确记住所学内容，也无法说明某句话源自哪篇文档。此外，[幻觉](#/post/ai-hallucination) 问题——即模型自信地输出错误信息——依然存在。

通常的处理流程是：首先优化提示词；若信息不足则采用 RAG；若仍无法掌握格式或语气，再考虑微调。两者结合使用的情况也非常普遍。

## 常见误解

- LoRA 是缩小模型的技术：基础模型大小保持不变，仅训练部分变小；推理时仍需基础模型。真正用于减小模型规模的是量化技术。
- QLoRA 性能低于 LoRA：论文虽声称保持 16 位微调性能，但这属于条件性结论，并非普遍成立。
- 微调即可注入新知识：在调整语气和格式方面确实有效，但在知识注入方面，RAG 往往更为稳定可靠。
- 数据越多越好：实际上，质量比数量更常被强调。

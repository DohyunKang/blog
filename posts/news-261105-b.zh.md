## 解决了什么问题

运行多个编码代理时，每个代理都需要独立的工作目录。如果在同一文件夹中共同修改文件，会导致相互覆盖。Git 本身已有用于此目的的 `git worktree`，它可以在一个仓库中为每个分支创建独立的文件夹。

然而，使用方式较为繁琐。项目网站指出，创建一个新的 worktree 需要输入三次分支名称：首先执行 `git worktree add -b feat ../repo.feat` 创建，然后执行 `cd ../repo.feat` 进入目录。Worktrunk 的目标是让处理 worktree 像操作分支一样简单：它通过分支名称引用 worktree，并基于可配置的模板计算文件夹路径。

## 常用命令

README 和网站上列出的命令如下：

| 命令 | 功能 |
|---|---|
| `wt switch --create feature-auth` | 创建分支和 worktree，并切换至该文件夹 |
| `wt switch -x claude -c feature-a -- 'Add user authentication'` | 创建 worktree 并立即在其中运行 `claude` |
| `wt list` | 列出 worktree 及其状态（使用 `--full` 时包含 CI 状态和 AI 生成的摘要） |
| `wt step commit` | 提交暂存的更改。也可利用 LLM 生成提交信息 |
| `wt merge main` | 一次性完成 squash、rebase、merge 及清理操作 |
| `wt remove` | 删除已完成合并的 worktree |
| `wt switch pr:123` | 检出 PR 分支 |

第二行命令很好地展示了该工具的用途：为每个代理通过 `-x` 打开一个 worktree，即可在单个仓库中，将功能 A、B、C 分别分配给不同的代理，仅需三条命令即可完成配置。

## 安装与设置

README 中提供了多种安装方式，包括 Homebrew（`brew install worktrunk && wt config shell install`）、Cargo、conda/pixi 以及 Arch Linux 包。Windows 用户可使用 `winget install max-sixty.worktrunk` 安装；为避免与 Windows Terminal 中的 `wt` 命令冲突，建议在 Windows 上将其命名为 `git-wt`。若需进行文件夹切换，则必须安装 Shell 集成（`wt config shell install`）。

此外，README 还提到了以下功能：

- Hooks（钩子）：在创建 worktree 时、合并前后等特定时间点执行命令。建议在刚创建后（post-start）设置依赖安装或启动开发服务器。
- `hash_port` 模板过滤器：用于为每个 worktree 分配不同的开发服务器端口。
- 构建缓存共享：支持将 `target/`、`node_modules/` 等构建缓存以 copy-on-write 方式在 APFS、btrfs、XFS 文件系统间共享。

## 使用时的注意事项

即使划分了 worktree，若两个代理修改同一文件，合并时仍会产生冲突。该工具主要简化了创建和整理文件夹的繁琐工作，至于如何将任务拆分，仍需人工决定。以上内容基于 README 和网站说明，未涵盖所有默认路径模板及钩子类型。

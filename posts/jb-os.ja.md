情報処理技術者試験の OS 分野は、概念の暗記と手計算が半々です。概念問題は用語を区別するもので、計算問題はスケジューリングによる平均時間とページフォールト回数が出題されます。どちらも「OS が CPU とメモリを割り当てる仕組み」という一点でまとめられるので、その順序に合わせて記述しておきます。試験日程や受験料は公式サイトで確認してください。

OS 自体をもっと詳しく見たい場合は [詳細 → OS 基礎](#/post/cs-os) にまとめてあります。この記事は試験で問われる形式に合わせてまとめたものです。

## プロセスとスレッド

プログラムはディスク上のファイルであり、プロセスはメモリ上にロードされて実行中のものです。スレッドはプロセス内の実行フローです。同じプロセス内のスレッドはコード・データ・ヒープを共有し、スタックとレジスタのみを個別に持っています。

プロセスの状態は 5 つで覚えます。

| 状態 | 意味 | 次の遷移 |
|---|---|---|
| 新規 (New) | 作成中 | 承認 → 準備 |
| 準備 (Ready) | CPU を割り当てられれば実行可能 | ディスパッチ → 実行 |
| 実行 (Running) | CPU を使用中 | タイムアウト → 準備、I/O リクエスト → 待機、終了 → 終了 |
| 待機 (Waiting/Blocked) | I/O などイベントを待機中 | イベント完了 → 準備 |
| 終了 (Terminated) | 完了 | |

混同しやすいペアは 2 つです。準備状態から実行状態へ CPU を割り当てる動作はディスパッチ（dispatch）であり、実行状態から準備状態へ時間切れで引き上げられる動作はタイムアウト（time out）です。待機状態から実行状態へは直接行くことができず、必ず準備状態を経由します。

コンテキストスイッチング（context switch）は、実行するプロセスを変更する際に、現在の状態（レジスタ、プログラムカウンタなど）を PCB に保存し、次のプロセスの PCB から読み込む作業です。この間は何も処理できないため、純粋なオーバーヘッドとなります。PCB（プロセス制御ブロック）にはプロセス ID、状態、プログラムカウンタ、レジスタ、メモリ情報、オープンファイル情報などが含まれます。

## CPU スケジューリング

評価基準は 3 つの時間です。

- 待機時間：準備キューで待った時間
- ターンアラウンド時間（turnaround）：到着から終了まで。待機時間 + 実行時間
- レスポンスタイム：到着から初めて CPU を割り当てられるまで

スケジューリングは、CPU を奪うことができるかどうかの 2 つに分けられます。

| 分類 | アルゴリズム | 一言で言うと |
|---|---|---|
| 非先占 | FCFS | 到着順。長い作業の後に短い作業が並ぶと平均が悪化する（ホース効果） |
| 非先占 | SJF | 実行時間が短いものから。平均待機時間は良いが、長い作業がずっと遅れる可能性がある |
| 非先占 | HRN | （待機時間 + 実行時間）÷ 実行時間の大きいものから。SJF の飢餓を軽減する |
| 非先占 | 優先順位 | 優先順位の高いものから。低いものは飢餓が生じ、エイジング（待ち時間が長くなるほど優先順位を上げる）で解決 |
| 先占 | SRT | 残り時間が最も短いものに切り替える。SJF の先占版 |
| 先占 | ラウンドロビン | 時間スロット分回す。スロットが大きいと FCFS に近く、小さすぎるとコンテキストスイッチが増える |
| 先占 | マルチレベルキュー・フィードバックキュー | キューを複数置き、優先順位や使用量に応じて移動させる |

同じ問題を 3 つの方法で解くと違いがはっきりします。到着時刻と実行時間がこのように与えたとします。

| プロセス | 到着 | 実行時間 |
|---|---|---|
| P1 | 0 | 6 |
| P2 | 1 | 3 |
| P3 | 2 | 1 |

これは直接シミュレーションして得た値です。

| 方式 | 実行順序 | 平均待機時間 | 平均ターンアラウンド時間 |
|---|---|---|---|
| FCFS | P1(0~6) → P2(6~9) → P3(9~10) | 4.0 | 7.33 |
| SJF | P1(0~6) → P3(6~7) → P2(7~10) | 3.33 | 6.67 |
| SRT | P1(0~1) → P2(1~2) → P3(2~3) → P2(3~5) → P1(5~10) | 1.67 | 5.0 |

解法の順序はいつも同じです。時間軸を描き、その瞬間に準備キューにいるプロセスを記述し、規則に従って 1 つ選び、終了時刻で到着時刻と実行時間を引き引いて待機・ターンアラウンドを求めます。SJF では P1 が終わる 6 の時点で P2 と P3 がどちらも到着しており、短い P3 が先に進むことがポイントです。先占になる SRT は、P2 が到着した時点（1）で P1 の残り時間が 5 なので、P2(3) が CPU を奪います。

ラウンドロビンは、到着と時間スロットが重なる場合、新しく来たプロセスをキューの先頭に置くか末尾に置くかで答えが変わることがあります。問題に条件が書かれているので、その規則に従ってキューを記述しながら解きます。

HRN の優先順位は値が大きいほど先です。待機 5・実行 5 なら (5+5)/5 = 2、待機 10・実行 20 なら (10+20)/20 = 1.5 なので前者が先に進みます。実行時間が短いほど、長く待つほど値が大きくなることを併せて覚えておきます。

<details>
<summary>같은 계산을 Python 으로 돌려보기 (SRT 부분)</summary>

```python
P = [("P1", 0, 6), ("P2", 1, 3), ("P3", 2, 1)]
rem = {n: b for n, a, b in P}
arr = {n: a for n, a, b in P}
t, fin = 0, {}
while rem:
    ready = [n for n in rem if arr[n] <= t]
    if not ready:
        t += 1
        continue
    n = min(ready, key=lambda x: rem[x])   # 남은 시간이 가장 짧은 것
    rem[n] -= 1
    t += 1
    if rem[n] == 0:
        fin[n] = t
        del rem[n]
for n, a, b in P:
    print(n, "반환", fin[n] - a, "대기", fin[n] - a - b)
```

P1 은 반환 10·대기 4, P2 는 반환 4·대기 1, P3 는 반환 1·대기 0 이 나온다.
</details>

## 메모리 관리

### 연속 할당과 단편화

프로그램을 메모리에 통째로 한 덩어리로 올리는 방식에서는 빈 공간을 어디에 넣을지가 문제가 된다. 세 가지 배치 전략은 이름이 곧 뜻이다.

- 최초 적합 (First Fit): 앞에서부터 처음 맞는 빈 공간에 넣는다
- 최적 적합 (Best Fit): 들어갈 수 있는 빈 공간 중 가장 작은 곳에 넣는다
- 최악 적합 (Worst Fit): 가장 큰 빈 공간에 넣는다

빈 공간이 120, 450, 230, 310, 580 이고 요청이 200, 400, 100, 450 순서로 올 때를 직접 계산해 봤다.

| 전략 | 200 | 400 | 100 | 450 |
|---|---|---|---|---|
| 최초 적합 | 450 | 580 | 120 | 못 넣음 |
| 최적 적합 | 230 | 450 | 120 | 580 |
| 최악 적합 | 580 | 450 | 380 | 못 넣음 |

칸의 숫자는 그 요청이 들어간 빈 공간의 크기 (요청 시점 기준) 다. 이 예에서는 최적 적합만 네 개 모두 넣었다. 늘 그런 건 아니고 입력에 따라 순서가 바뀐다.

단편화는 두 종류다. 내부 단편화는 할당받은 덩어리 안에서 안 쓰고 남는 공간 (고정 크기로 나눴을 때), 외부 단편화는 전체 빈 공간 합은 충분한데 흩어져서 못 쓰는 공간 (가변 크기일 때) 이다. 외부 단편화는 조각 모음 (압축) 으로 줄인다.

### 페이징과 세그먼테이션

페이징은 주소 공간을 같은 크기의 페이지로, 물리 메모리를 같은 크기의 프레임으로 나눠서 페이지를 아무 프레임에나 넣는 방식이다. 페이지 테이블이 페이지 번호에서 프레임 번호로 가는 대응표다. 이 표는 프로세스마다 하나씩 있다.

가상 주소는 페이지 번호 (VPN) 와 오프셋으로 쪼갠다. 오프셋은 페이지 안의 위치라서 변환해도 바뀌지 않고, 페이지 번호만 프레임 번호로 바뀐다. OSTEP 의 예는 64 바이트 주소 공간을 16 바이트 페이지 4 개로 나눠서, 6 비트 주소 중 위 2 비트가 VPN 이고 아래 4 비트가 오프셋이다. 같은 계산이 시험에서는 이런 모양으로 나온다.

- 32 비트 주소, 페이지 크기 4KB (= 2¹²) 라면 오프셋 12 비트, VPN 20 비트다
- 그러면 페이지 테이블 항목 수는 2²⁰ 개 (약 100 만 개) 다
- 페이지 크기가 커지면 테이블은 작아지지만 내부 단편화는 커진다

세그먼테이션은 프로그램을 코드·데이터·스택처럼 의미 단위로 쪼개 크기가 다른 세그먼트로 올린다. 같은 크기가 아니라서 외부 단편화가 생기고, 대신 의미 단위로 보호·공유가 쉽다. 페이징은 내부 단편화, 세그먼테이션은 외부 단편화 쪽이라고 짝지어 외운다.

### 가상 메모리와 페이지 교체

가상 메모리는 실제 메모리보다 큰 프로그램을 돌리려고 필요한 페이지만 메모리에 올리는 기법이다. 필요한 페이지가 메모리에 없으면 페이지 부재 (page fault) 가 나고, 디스크에서 가져온다. 메모리가 꽉 찼으면 하나를 내보내야 하는데, 누구를 내보낼지 정하는 규칙이 교체 알고리즘이다.

| 알고리즘 | 내보내는 기준 |
|---|---|
| OPT | 앞으로 가장 오래 안 쓸 페이지 (미래를 알아야 해서 비교 기준으로만 쓴다) |
| FIFO | 가장 먼저 들어온 페이지 |
| LRU | 가장 오래 전에 쓴 페이지 |
| LFU | 사용 횟수가 가장 적은 페이지 |
| NUR | 참조 비트·변경 비트로 최근에 안 쓴 것 구분 |

참조열 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 를 프레임 3 개와 4 개로 돌린 결과다. 이 열은 OSTEP 이 벨라디의 모순을 설명할 때 쓴 것이다.

| 프레임 수 | FIFO 부재 | LRU 부재 | OPT 부재 |
|---|---|---|---|
| 3 | 9 | 10 | 7 |
| 4 | 10 | 8 | 6 |

FIFO 는 프레임을 3 개에서 4 개로 늘렸는데 부재가 9 에서 10 으로 오히려 늘었다. 이게 벨라디의 모순 (Belady's anomaly) 이다. LRU 는 프레임 N+1 개의 내용이 N 개의 내용을 포함하는 성질 (스택 성질) 이 있어서 이런 일이 없다. 시험에서는 'FIFO 에서 프레임이 늘었는데 부재가 늘 수 있는 현상'을 이름으로 묻는다.

풀이 순서는 참조열을 하나씩 읽으면서 프레임 상태를 옆에 적는다. 이미 있으면 적중, 없으면 부재로 세고 규칙대로 하나를 내보낸다. LRU 는 적중했을 때도 그 페이지의 최근 사용 순서가 갱신된다는 점을 빼먹기 쉽다.

<details>
<summary>페이지 교체를 Python 으로 돌려보기</summary>

```python
from collections import deque

def fifo(ref, n):
    m, f = deque(), 0
    for r in ref:
        if r not in m:
            f += 1
            if len(m) == n:
                m.popleft()
            m.append(r)
    return f

def lru(ref, n):
    m, f = [], 0
    for r in ref:
        if r in m:
            m.remove(r)          # 적중해도 최근 순서 갱신
        else:
            f += 1
            if len(m) == n:
                m.pop(0)
        m.append(r)
    return f

def opt(ref, n):
    m, f = [], 0
    for i, r in enumerate(ref):
        if r in m:
            continue
        f += 1
        if len(m) == n:
            later = ref[i + 1:]
            dist = [later.index(x) if x in later else 10**9 for x in m]
            m.pop(dist.index(max(dist)))   # 가장 늦게 다시 쓰는 것
        m.append(r)
    return f

ref = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
for n in (3, 4):
    print(n, fifo(ref, n), lru(ref, n), opt(ref, n))
```

출력은 `3 9 10 7`, `4 10 8 6` 이다.
</details>

仮想メモリに関する追加の話題があります。スラッシング（Thrashing）とは、プロセスが多すぎてページフォールトが頻発し、CPU が処理を行えずにページ交換のみを行う状態を指します。局所性（Locality）は、プログラムが最近使用した場所付近を再度使用する性質であり、ワーキングセット（Working Set）とは一定期間内に頻繁に参照されるページの集合です。ワーキングセット分だけメモリ上に保持しておけばスラッシングを軽減できます。

## デッドロック

デッドロック（Deadlock）は、プロセス同士が互いに保持している資源を待ち続け、永遠に停止した状態です。以下の 4 つの条件が同時に成立することで発生します。OSTEP も同じ 4 つを挙げています。

| 条件 | 意味 | この条件を破る予防策 |
|---|---|---|
| 相互排他 | 資源を一度に一つしか使用しない | ロックを使わないデータ構造などの方法で共有可能にする |
| 占有と待機 | 資源を保持したまま他のものを待つ | 必要な資源を一括して取得する |
| 非先占性 | 保持している資源を強制的に奪えない | 取得できない場合は保持しているものを解放して再試行する |
| 循環等待 | 互いに尾を引く円形の鎖が存在する | 資源に番号を割り当てて順番にのみ要求する |

試験では、この 4 つの名前と「どの条件を破る方法か」をセットにして問われます。資源に番号を割り当てて順番に要求させるのは循環等待を破ることです。

解決策は 4 つのカテゴリーに分けられます。

- **予防（Prevention）**: 上記の 4 つの条件の一つを事前に防ぐ。安全だが資源利用率が低下する
- **回避（Avoidance）**: リソース要求が来るたびに安全性を計算して許可する。代表例はダイクストラの銀行家アルゴリズム。最大要求量を事前に知る必要がある
- **検出（Detection）**: 一旦放置し、定期的にデッドロックが発生しているか確認する（資源割り当てグラフなど）
- **回復（Recovery）**: 検出した後、プロセスを終了するか資源を奪って解決する

安全状態とは、すべてのプロセスが最後まで実行できる順序が少なくとも一つ存在する状態であり、不安全状態だからといって直ちにデッドロックであるわけではありません。銀行家アルゴリズムの問題は、現在の残存資源で最大要求を満たせるプロセスを一つ選び、終了させ、そのプロセスが返却する資源を合わせて次に選ぶという手順で解きます。最後まで順序がついていれば安全です。

## 同期化

臨界セクション（Critical Section）は共有資源を操作するコード区間であり、一度に一つのプロセスしか入れない必要があります。これを保証するための道具にはセマフォとミューテックスがあります。

- **セマフォ**: 整数変数一つと P(wait, 減少)・V(signal, 増加) 演算を用いて記述します。値が 1 の場合は二進セマフォ、それ以上なら計数セマフォです
- **ミューテックス**: ロックを保持している側のみ解放可能な相互排他用の道具です
- **モニター**: 共有資源とそのアクセス関数を束ねて一度に一つしか実行させない高水準構造です

競合状態（Race Condition）は、複数のプロセスが共有データを同時に書き換えることで実行順序によって結果が変わる状況です。デッドロックとは異なり停止するのではなく値が誤ってしまいます。並行性はデータベースでも同様の問題として再登場します。[詳細 → 正規化とトランザクション](#/post/jb-normalization-transaction)

## よく出る出題形式のまとめ

| 出題タイプ | 問われる形 | 解法 |
|---|---|---|
| スケジューリング平均時間 | 到着・実行時刻表を与え、平均待機・ターンアラウンド時間を求める | 時間軸＋準備キューを書く |
| アルゴリズム名の一致合わせ | 「残り時間が短いもの」「待機が長いほど優先」などの説明 | SRT, HRN などのキーワードで結びつける |
| ページフォールト回数 | 参照列とフレーム数を与える | フレーム状態を横に書き、フォールトのみをカウントする |
| ベラディの矛盾 | FIFO でフレームが増えるとフォールトが増える可能性があること | 名前だけで答える |
| デッドロック 4 条件 | 条件名、どの条件を破る予防策 | 上記の表で一致合わせる |
| フラグメンテーション | 固定分割か可変分割か | 内部 ↔ 固定、外部 ↔ 可変 |

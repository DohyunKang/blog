정보처리기사 운영체제 단원은 개념 암기와 손으로 하는 계산이 반반이다. 개념은 용어를 구분하는 문제로, 계산은 스케줄링 평균 시간과 페이지 부재 횟수로 나온다. 둘 다 운영체제가 CPU와 메모리를 나눠 주는 방식이라는 한 줄로 묶이니, 그 순서대로 적어 둔다. 시험 일정과 응시료는 공식 사이트에서 확인한다.

OS 자체를 더 풀어서 보고 싶으면 [자세히 → 운영체제 기초](#/post/cs-os)에 정리해 뒀다. 이 글은 시험에서 묻는 모양에 맞춘 판이다.

## 프로세스와 스레드

프로그램은 디스크의 파일이고, 프로세스는 메모리에 올라가 실행 중인 것이다. 스레드는 프로세스 안의 실행 흐름이다. 같은 프로세스의 스레드는 코드·데이터·힙을 같이 쓰고 스택과 레지스터만 따로 가진다.

프로세스 상태는 다섯 개로 외운다.

| 상태 | 뜻 | 다음으로 가는 길 |
|---|---|---|
| 생성(New) | 만들어지는 중 | 승인 → 준비 |
| 준비(Ready) | CPU만 받으면 실행 가능 | 디스패치 → 실행 |
| 실행(Running) | CPU를 쓰는 중 | 시간 만료 → 준비, 입출력 요청 → 대기, 종료 → 종료 |
| 대기(Waiting/Blocked) | 입출력 같은 사건을 기다림 | 사건 완료 → 준비 |
| 종료(Terminated) | 끝남 | |

헷갈리는 쌍은 둘이다. 준비에서 실행으로 CPU를 주는 동작이 디스패치(dispatch)이고, 실행에서 준비로 시간이 다 돼서 뺏기는 동작이 타임아웃(time out)이다. 대기에서 실행으로 바로 가는 길은 없고 반드시 준비를 거친다.

문맥 교환(context switch)은 실행할 프로세스를 바꿀 때 지금 상태(레지스터, 프로그램 카운터 등)를 PCB에 저장하고 다음 프로세스의 PCB에서 불러오는 일이다. 이 시간 동안은 일을 못 하므로 순수한 오버헤드다. PCB(프로세스 제어 블록)에는 프로세스 번호, 상태, 프로그램 카운터, 레지스터, 메모리 정보, 열린 파일 정보 등이 들어 있다.

## CPU 스케줄링

평가 기준은 세 가지 시간이다.

- 대기 시간: 준비 큐에서 기다린 시간
- 반환 시간(turnaround): 도착해서 끝날 때까지. 대기 시간 + 실행 시간
- 응답 시간: 도착해서 처음 CPU를 받을 때까지

스케줄링은 CPU를 뺏을 수 있는지로 둘로 나눈다.

| 구분 | 알고리즘 | 한 줄 요약 |
|---|---|---|
| 비선점 | FCFS | 도착 순서대로. 긴 작업 뒤에 짧은 작업이 줄 서면 평균이 나빠진다(호위 효과) |
| 비선점 | SJF | 실행 시간이 짧은 것부터. 평균 대기 시간은 좋지만 긴 작업이 계속 밀릴 수 있다 |
| 비선점 | HRN | (대기 시간 + 실행 시간) ÷ 실행 시간이 큰 것부터. SJF의 기아를 줄인다 |
| 비선점 | 우선순위 | 우선순위 높은 것부터. 낮은 건 기아가 생기고, 에이징(오래 기다릴수록 우선순위 올림)으로 해결 |
| 선점 | SRT | 남은 시간이 가장 짧은 것으로 바꾼다. SJF의 선점판 |
| 선점 | 라운드 로빈 | 시간 할당량만큼 돌아가며. 할당량이 크면 FCFS에 가까워지고, 너무 작으면 문맥 교환이 늘어난다 |
| 선점 | 다단계 큐·피드백 큐 | 큐를 여러 개 두고 우선순위나 사용량에 따라 이동 |

같은 문제를 세 가지 방식으로 풀면 차이가 눈에 들어온다. 도착 시각과 실행 시간이 이렇게 주어졌다고 하자.

| 프로세스 | 도착 | 실행 시간 |
|---|---|---|
| P1 | 0 | 6 |
| P2 | 1 | 3 |
| P3 | 2 | 1 |

직접 시뮬레이션해서 얻은 값이다.

| 방식 | 실행 순서 | 평균 대기 시간 | 평균 반환 시간 |
|---|---|---|---|
| FCFS | P1(0~6) → P2(6~9) → P3(9~10) | 4.0 | 7.33 |
| SJF | P1(0~6) → P3(6~7) → P2(7~10) | 3.33 | 6.67 |
| SRT | P1(0~1) → P2(1~2) → P3(2~3) → P2(3~5) → P1(5~10) | 1.67 | 5.0 |

풀이 순서는 늘 같다. 시간선을 그리고, 매 순간 준비 큐에 누가 있는지 적고, 규칙대로 하나 고르고, 끝난 시각에서 도착 시각과 실행 시간을 빼서 대기·반환을 구한다. SJF에서는 P1이 끝나는 6 시점에 P2, P3가 둘 다 와 있어서 짧은 P3가 먼저 가는 것이 핵심이다. 선점이 되는 SRT는 P2가 도착한 시점(1)에 P1의 남은 시간이 5라서 P2(3)가 CPU를 가져간다.

라운드 로빈은 도착과 시간 할당량이 겹칠 때 새로 온 프로세스를 큐 앞에 넣는지 뒤에 넣는지에 따라 답이 달라질 수 있다. 문제에 조건이 적혀 있으니 그 규칙대로 큐를 적어 가며 푼다.

HRN 우선순위는 값이 클수록 먼저다. 대기 5·실행 5이면 (5+5)/5 = 2, 대기 10·실행 20이면 (10+20)/20 = 1.5라서 앞의 것이 먼저 간다. 실행 시간이 짧을수록, 오래 기다릴수록 커지는 식이라는 걸 같이 기억해 둔다.

<details>
<summary>같은 계산을 파이썬으로 돌려 보기(SRT 부분)</summary>

```python
P = [("P1", 0, 6), ("P2", 1, 3), ("P3", 2, 1)]
rem = {n: b for n, a, b in P}
arr = {n: a for n, a, b in P}
t, fin = 0, {}
while rem:
    ready = [n for n in rem if arr[n] <= t]
    if not ready:
        t += 1
        continue
    n = min(ready, key=lambda x: rem[x])   # 남은 시간이 가장 짧은 것
    rem[n] -= 1
    t += 1
    if rem[n] == 0:
        fin[n] = t
        del rem[n]
for n, a, b in P:
    print(n, "반환", fin[n] - a, "대기", fin[n] - a - b)
```

P1 반환 10·대기 4, P2 반환 4·대기 1, P3 반환 1·대기 0이 나온다.
</details>

큐 같은 기본 자료구조가 여기서 준비 큐로 쓰인다. [자세히 → 자료구조](#/post/jb-data-structure)

## 메모리 관리

### 연속 할당과 단편화

프로그램을 메모리에 통째로 한 덩어리로 올리는 방식에서는 빈 공간을 어디에 넣을지가 문제가 된다. 세 가지 배치 전략은 이름이 곧 뜻이다.

- 최초 적합(First Fit): 앞에서부터 처음 맞는 빈 공간에 넣는다
- 최적 적합(Best Fit): 들어갈 수 있는 빈 공간 중 가장 작은 곳에 넣는다
- 최악 적합(Worst Fit): 가장 큰 빈 공간에 넣는다

빈 공간이 120, 450, 230, 310, 580이고 요청이 200, 400, 100, 450 순서로 올 때를 직접 계산해 봤다.

| 전략 | 200 | 400 | 100 | 450 |
|---|---|---|---|---|
| 최초 적합 | 450 | 580 | 120 | 못 넣음 |
| 최적 적합 | 230 | 450 | 120 | 580 |
| 최악 적합 | 580 | 450 | 380 | 못 넣음 |

칸의 숫자는 그 요청이 들어간 빈 공간의 크기(요청 시점 기준)다. 이 예에서는 최적 적합만 네 개 모두 넣었다. 늘 그런 건 아니고 입력에 따라 순서가 바뀐다.

단편화는 두 종류다. 내부 단편화는 할당받은 덩어리 안에서 안 쓰고 남는 공간(고정 크기로 나눴을 때), 외부 단편화는 전체 빈 공간 합은 충분한데 흩어져서 못 쓰는 공간(가변 크기일 때)이다. 외부 단편화는 조각 모음(압축)으로 줄인다.

### 페이징과 세그먼테이션

페이징은 주소 공간을 같은 크기의 페이지로, 물리 메모리를 같은 크기의 프레임으로 나눠서 페이지를 아무 프레임에나 넣는 방식이다. 페이지 테이블이 페이지 번호에서 프레임 번호로 가는 대응표다. 이 표는 프로세스마다 하나씩 있다.

가상 주소는 페이지 번호(VPN)와 오프셋으로 쪼갠다. 오프셋은 페이지 안의 위치라서 변환해도 바뀌지 않고, 페이지 번호만 프레임 번호로 바뀐다. OSTEP의 예는 64바이트 주소 공간을 16바이트 페이지 4개로 나눠서, 6비트 주소 중 위 2비트가 VPN이고 아래 4비트가 오프셋이다. 같은 계산이 시험에서는 이런 모양으로 나온다.

- 32비트 주소, 페이지 크기 4KB(= 2¹²)라면 오프셋 12비트, VPN 20비트다
- 그러면 페이지 테이블 항목 수는 2²⁰개(약 100만 개)다
- 페이지 크기가 커지면 테이블은 작아지지만 내부 단편화는 커진다

세그먼테이션은 프로그램을 코드·데이터·스택처럼 의미 단위로 쪼개 크기가 다른 세그먼트로 올린다. 같은 크기가 아니라서 외부 단편화가 생기고, 대신 의미 단위로 보호·공유가 쉽다. 페이징은 내부 단편화, 세그먼테이션은 외부 단편화 쪽이라고 짝지어 외운다.

### 가상 메모리와 페이지 교체

가상 메모리는 실제 메모리보다 큰 프로그램을 돌리려고 필요한 페이지만 메모리에 올리는 기법이다. 필요한 페이지가 메모리에 없으면 페이지 부재(page fault)가 나고, 디스크에서 가져온다. 메모리가 꽉 찼으면 하나를 내보내야 하는데, 누구를 내보낼지 정하는 규칙이 교체 알고리즘이다.

| 알고리즘 | 내보내는 기준 |
|---|---|
| OPT | 앞으로 가장 오래 안 쓸 페이지(미래를 알아야 해서 비교 기준으로만 쓴다) |
| FIFO | 가장 먼저 들어온 페이지 |
| LRU | 가장 오래 전에 쓴 페이지 |
| LFU | 사용 횟수가 가장 적은 페이지 |
| NUR | 참조 비트·변경 비트로 최근에 안 쓴 것 구분 |

참조열 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5를 프레임 3개와 4개로 돌린 결과다. 이 열은 OSTEP가 벨라디의 모순을 설명할 때 쓴 것이다.

| 프레임 수 | FIFO 부재 | LRU 부재 | OPT 부재 |
|---|---|---|---|
| 3 | 9 | 10 | 7 |
| 4 | 10 | 8 | 6 |

FIFO는 프레임을 3개에서 4개로 늘렸는데 부재가 9에서 10으로 오히려 늘었다. 이게 벨라디의 모순(Belady's anomaly)이다. LRU는 프레임 N+1개의 내용이 N개의 내용을 포함하는 성질(스택 성질)이 있어서 이런 일이 없다. 시험에서는 'FIFO에서 프레임이 늘었는데 부재가 늘 수 있는 현상'을 이름으로 묻는다.

풀이 순서는 참조열을 하나씩 읽으면서 프레임 상태를 옆에 적는다. 이미 있으면 적중, 없으면 부재로 세고 규칙대로 하나를 내보낸다. LRU는 적중했을 때도 그 페이지의 최근 사용 순서가 갱신된다는 점을 빼먹기 쉽다.

<details>
<summary>페이지 교체를 파이썬으로 돌려 보기</summary>

```python
from collections import deque

def fifo(ref, n):
    m, f = deque(), 0
    for r in ref:
        if r not in m:
            f += 1
            if len(m) == n:
                m.popleft()
            m.append(r)
    return f

def lru(ref, n):
    m, f = [], 0
    for r in ref:
        if r in m:
            m.remove(r)          # 적중해도 최근 순서 갱신
        else:
            f += 1
            if len(m) == n:
                m.pop(0)
        m.append(r)
    return f

def opt(ref, n):
    m, f = [], 0
    for i, r in enumerate(ref):
        if r in m:
            continue
        f += 1
        if len(m) == n:
            later = ref[i + 1:]
            dist = [later.index(x) if x in later else 10**9 for x in m]
            m.pop(dist.index(max(dist)))   # 가장 늦게 다시 쓰는 것
        m.append(r)
    return f

ref = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
for n in (3, 4):
    print(n, fifo(ref, n), lru(ref, n), opt(ref, n))
```

출력은 `3 9 10 7`, `4 10 8 6`이다.
</details>

가상 메모리에서 하나 더 구분할 말이 있다. 스래싱(thrashing)은 프로세스가 너무 많아서 페이지 부재가 계속 터져 CPU가 일은 못 하고 페이지 교체만 하는 상태다. 지역성(locality)은 프로그램이 최근에 쓴 곳 가까이를 다시 쓴다는 성질이고, 워킹 셋은 일정 시간 동안 자주 참조하는 페이지 집합이다. 워킹 셋만큼은 메모리에 올려 두면 스래싱이 줄어든다.

## 교착상태

교착상태(deadlock)는 프로세스들이 서로 상대가 가진 자원을 기다리며 영원히 멈춘 상태다. 아래 네 조건이 동시에 성립해야 생긴다. OSTEP도 같은 네 가지를 든다.

| 조건 | 뜻 | 이걸 깨는 예방법 |
|---|---|---|
| 상호 배제 | 자원을 한 번에 하나만 쓴다 | 락 없는 자료구조 같은 방법으로 공유 가능하게 한다 |
| 점유와 대기 | 자원을 쥔 채로 다른 걸 기다린다 | 필요한 자원을 한꺼번에 얻는다 |
| 비선점 | 쥔 자원을 강제로 못 뺏는다 | 못 얻으면 쥔 걸 놓았다가 다시 시도한다 |
| 환형 대기 | 서로 꼬리를 무는 원형 사슬이 있다 | 자원에 번호를 매겨 순서대로만 요청한다 |

시험에서는 이 네 이름과 '어느 조건을 깨는 방법이냐'를 짝지어 묻는다. 자원에 번호를 매겨 순서대로 요청하게 하는 것은 환형 대기를 깬다.

해결 방법은 네 갈래로 구분한다.

- 예방(Prevention): 위 네 조건 중 하나를 미리 막는다. 안전하지만 자원 이용률이 떨어진다
- 회피(Avoidance): 자원 요청이 올 때마다 안전한지 계산해서 허락한다. 대표가 다익스트라의 은행가 알고리즘이다. 최대 요구량을 미리 알아야 한다
- 발견(Detection): 일단 두고 주기적으로 교착상태가 있는지 확인한다(자원 할당 그래프 등)
- 회복(Recovery): 발견한 뒤 프로세스를 종료하거나 자원을 뺏어서 푼다

안전 상태는 모든 프로세스가 끝까지 실행할 수 있는 순서가 하나라도 있는 상태이고, 불안전 상태라고 해서 곧바로 교착상태인 것은 아니다. 은행가 알고리즘 문제는 현재 남은 자원으로 최대 요구를 채울 수 있는 프로세스를 하나 골라 끝내고, 그 프로세스가 돌려주는 자원을 합쳐 다음을 고르는 식으로 풀린다. 끝까지 순서가 이어지면 안전이다.

## 동기화

임계 구역(critical section)은 공유 자원을 만지는 코드 구간이고, 한 번에 하나의 프로세스만 들어가야 한다. 이걸 보장하는 도구가 세마포어와 뮤텍스다.

- 세마포어: 정수 변수 하나와 P(wait, 감소)·V(signal, 증가) 연산으로 쓴다. 값이 1이면 이진 세마포어, 그 이상이면 계수 세마포어다
- 뮤텍스: 락을 잡은 쪽만 풀 수 있는 상호 배제용 도구다
- 모니터: 공유 자원과 그 접근 함수를 묶어서 한 번에 하나만 실행되게 하는 고수준 구조다

경쟁 상태(race condition)는 여러 프로세스가 공유 데이터를 동시에 바꿔서 실행 순서에 따라 결과가 달라지는 상황이다. 교착상태와 달리 멈추지는 않고 값이 틀어진다. 동시성은 DB에서도 같은 문제로 다시 나온다. [자세히 → 정규화와 트랜잭션](#/post/jb-normalization-transaction)

## 자주 나오는 유형 정리

| 유형 | 물어보는 모양 | 풀이 방식 |
|---|---|---|
| 스케줄링 평균 시간 | 도착·실행 시간표를 주고 평균 대기·반환 시간 | 시간선 + 준비 큐를 적는다 |
| 알고리즘 이름 짝짓기 | '남은 시간이 짧은 것', '대기가 길수록 우선' 같은 설명 | SRT, HRN처럼 키워드로 연결 |
| 페이지 부재 횟수 | 참조열과 프레임 수 | 프레임 상태를 옆에 적고 부재만 센다 |
| 벨라디의 모순 | FIFO에서 프레임이 늘면 부재가 늘 수 있음 | 이름으로 답한다 |
| 교착상태 4조건 | 조건 이름, 어느 조건을 깨는 예방법 | 위 표로 짝짓기 |
| 단편화 | 고정 분할인지 가변 분할인지 | 내부 ↔ 고정, 외부 ↔ 가변 |

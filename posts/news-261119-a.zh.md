今天早上 GitHub 趋势榜(daily)上有 NVIDIA/SkillEvaluator。今天新增 323 星，总共 3,705 星(11月19日早上确认)。把给编程代理用的技能或插件交给它，它会检查格式和安全，最后用数字回答"装了这个技能，代理是不是真的干得更好"。我读了 README、`docs/` 下几篇文档和 arXiv 摘要，没有自己跑。

## 是个什么东西
技能是代理需要时会读进来的说明书文件夹，一个 SKILL.md 加上指示、示例，有时还有辅助脚本。[详细 → 技能](#/post/ai-skills) 最近技能合集仓库常上趋势榜，但技能到底有没有用，基本靠用过的人凭感觉。SkillEvaluator 把检查分成三层。

1. 第一层(验证):格式、版本、个人信息、许可证、隐藏的 Unicode 字符、密钥泄露、脚本安全等静态检查。README 说有 500 多条规则和检测模式，不需要模型密钥。质量满分 100,默认 70 分及格。
2. 第二层(去重):用嵌入检查技能内部的指示是否重复，或与其他技能重叠。嵌入就是把文字的意思变成数字向量来衡量远近。
3. 第三层(实测):在 Docker 沙箱里让代理做同样的任务，装技能一次、不装一次。差值就是 Skill Lift。

第一层里还单独有个 Harness Check,我觉得挺有意思。Claude Code、Codex、OpenCode、Copilot CLI 等读取技能的文件夹位置和描述长度上限各不相同。所以它不用跑代理就能告诉你"描述超出 1,024 上限 4 个单位,Copilot CLI 根本不会加载"这类问题。技能不起作用，很多时候可能不是内容问题，而是这种地方。

## Skill Lift 怎么算
第三层每次尝试给六个信号打 0~1 分：安全、是否找到并用了技能(skill_execution)、用得是否高效、与期望输出是否一致(accuracy)、是否达成目标(goal_accuracy)、是否做了该做的动作(behavior_check)。token 效率只报告不计分。其中一部分由 LLM 当评分者。[详细 → 评估(Evals)](#/post/ai-evals)

公式很简单:`Skill Lift = 有技能时总分 - 无技能时总分`,只比较两边都跑过的任务和两边都打了分的信号。≥ +0.05 为 PASS,≤ -0.10 为 FAIL,中间为 NEUTRAL。任务少时结果会抖，所以还用按任务重抽样的 bootstrap 给出 95% 区间。只有一个任务时不给区间，文档说是怕宽度为零的区间看起来像定论。

文档里专门有一节"尚未确立的东西",这点我挺喜欢。没有和人工评分一致性的研究;0.50 及格线和 lift 区间这些数字是约定，不是推导出来的;而且比较的是"有技能 vs 没技能",分不清是技能内容起的作用，还是多给了一条指示起的作用。最后这点我读的时候也在想。

## 论文里的数字
有一篇讲同一方法的论文(arXiv 2608.20614,8月提交)。按摘要，在 145 个真实技能上，结构检查分和 LLM 评分的相关性只有 0.14,说明静态检查和实际效果看的是不同的东西。在 58 个生产技能、947 个配对任务上，平均 Skill Lift 为 0.2134,72.8% 的任务 lift 为正。差距最大的不是正确率，而是找到技能、按流程使用的部分，论文说这是只看文档看不出来的。

## 对入门者来说
对 PM 来说，有用的是把"加了技能应该会更好"变成"在同样任务上比较过加和不加"这个框架，相当于给代理的说明书做 A/B 测试。任务少于 10 个就算不充分的默认值，也可以当个参考。

对入门开发者，先只用第一层最轻松。`pip install skillevaluator` 之后，`skillevaluator quality-check ./my-skill` 不需要密钥、GPU 或 Docker,`harness-check` 也一样。第三层需要模型密钥和 Docker,文档说可能产生模型费用。支持级别是 Experimental,没有 NVIDIA 官方支持。和我以前写的常用技能那篇一起看更好。[详细 → 常用 Claude 技能合集](#/post/claude-popular-skills)

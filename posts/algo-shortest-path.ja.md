# 最短経路・ユニオンファインド・トポロジカルソート

[BFS・DFS](#/post/algo-graph-search) でグラフを回す方法は学んだ。今回はその上でよく出てくる三つだ。辺にコストが付き、最も安い道を見つけるダイクストラ、誰と誰が同じグループか素早く判断するユニオンファインド、前後関係のある作業を順番に並べるトポロジカルソートである。どれもコードは短いのに「いつこれをやるべきか」を見極める方が難しい。

## 一目で比較

| アルゴリズム | こんな時 | 核心ツール | 時間 |
|---|---|---|---|
| ダイクストラ | 重み（0 以上）のあるグラフで、一点から他の点への最小コスト | 優先度キュー | O(E log V) |
| ユニオンファインド | 二つの要素が同じ集合か、集合を合併する | 親配列 | 演算あたりほぼ O(1) |
| トポロジカルソート | 前後関係のある作業の順序、サイクル判定 | 入次数 + キュー | O(V+E) |

## 最短経路：ダイクストラ

### 問題類型の説明

BFS は辺を 1  칸（マス）とみなす場合のみ最短距離を与える。辺ごとにコストが異なれば「粗い辺の数」ではなく「コストの合計」が基準になる必要がある。ダイクストラは開始点から最も近い点から確定させていく。

原理はこうだ。開始点までの距離を 0、残りは無限大とする。まだ確定していない点の中で距離が最小の点を抜き出して確定させ、その点を介して隣接する点がより近くなるか見る。より近ければ更新する。コストが負でなければ、抜いた時点での距離は既に最小なので再度見る必要がない。「最も小さいものを素早く出す」必要があるためヒープ（優先度キュー）を使う。

負の辺があればこの仮定が崩れる。ウィキペディアの例では s→a 2, s→b 5, b→a −10 の場合、a を 2 で確定させてしまうが s→b→a は −5 だ。このような時はベルマン・フォードを使う。

### 代表問題

- プログラ머스 配達：村 N 個が双方向の道路で繋がっており、村 1 から K 時間以内に到着できる村の数を数える。村 1 からすべての村までの最短距離を求め、K 以下のものを数えればよい。
- プログラ머스 乗り合いタクシー料金の計算：出発地点から二つの目的地までの共有区間をどのように分割すれば安いか、ダイクストラを複数回実行して解く。

### 解法思考の順序

1. 辺にコストがあり、負でないか確認する。すべて 1 であれば BFS で十分だ。
2. 一つの開始点から全体か、すべてのペアか確認する。すべてのペアで頂点が少ない場合（数百個）ならフロイド・ワーシャルも候補になる。
3. 隣接リストを作成し、距離配列を無限大で埋め、ヒープに (0, 開始点) を入れる。
4. ヒープから抜いた距離が現在記録されている距離より大きければ既に古くなった項目なのでスキップする。
5. 隣接点を更新し、ヒープに入れる。

### Python コード

```python
import heapq

def dijkstra(n, graph, start):
    INF = float('inf')
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:        # 이미 더 짧은 길로 처리된 낡은 항목
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

辺 (1,2,2) (1,3,5) (2,3,1) (2,4,7) (3,4,2) (4,5,1) を双方向に追加し、村 1 から出発して実行すると `[inf, 0, 2, 3, 5, 6]` が得られた（0 番のマスは使用しない）。1→2→3 の経路が 5 マスの直行より安価に捉えられていることがわかる。

### 複雑度

ヒープを使えば O((V+E) log V)、連結グラフでは O(E log V) だ。上記コードは更新するたびに新しく push し、古くなった項目は抜く際に捨てる方式だが、ウィキペディアでも decrease-key の代わりにこの方法を導入している。空間は O(V+E)。

辺が多い問題は `input()` の代わりに `sys.stdin.readline` を使う。Python の heapq は最小ヒープであり、タプルは先頭要素から比較するため、(距離, 頂点) の順に入れて距離基準でソートされるようにする必要がある。この部分は混乱して時々失敗する。経路そのものを復元する必要がある場合は更新時に `prev[v] = u` も一緒に保存しておき、到着地点から逆方向に辿る。

## ユニオンファインド

### 問題類型の説明

「A と B は同じグループか」「二つのグループを合併せよ」といった質問が連続して入る時に使う。各要素は親を指し示し、親を追って上がるとルートに到達し、それが代表となる。ルートが同じであれば同じグループだ。

ただ実装すると片側に長く伸びた木ができ、find が O(n) まで行ってしまう可能性がある。そこで二つの工夫を重ねる。パス圧縮は find の時に通ったノードをルートに直接つなぐものであり、サイズ（またはランク）基準の合併は小さい木を大きな木の元に付けるものである。両方を使うと演算 m 回で Θ(m·α(n)) となり、α は逆アークマン関数なので現実的な n では 4 より小さい。実質的に定数として扱う。

### 代表問題

- 프로그래머스 네트워크: 컴퓨터 연결 정보가 주어지고, 서로 통하는 컴퓨터 묶음이 몇 개인지 센다. 합친 뒤 루트가 몇 종류인지 세면 되는, 그룹 묶기의 가장 기본형이다.
- 프로그래머스 호텔 방 배정: 손님이 원하는 방이 차 있으면 그보다 번호가 큰 빈 방 중 가장 작은 곳을 준다. 방을 채울 때마다 "다음 빈 방"을 가리키게 이어 두는 식으로 유니온 파인드를 쓴다.
- 프로그래머스 섬 연결하기: 다리 건설 비용이 주어지고, 모든 섬이 서로 오갈 수 있게 하는 최소 비용을 구한다. 간선을 비용 순으로 정렬하고 사이클이 안 생기는 것만 고르는 크루스칼에 유니온 파인드가 들어간다.

### 풀이 생각 순서

1. "연결되어 있나?"만 묻고 경로는 안 묻는지 본다. 그렇다면 BFS 대신 유니온 파인드가 간단하다.
2. 합치기가 중간에 계속 일어나는지 본다 (동적 연결). 한 번 만들고 끝이면 DFS 도 된다.
3. find 는 압축, union 은 크기 기준으로 쓴다.
4. 크루스칼이면 union 이 False 를 돌려줄 때 (이미 같은 그룹) 그 간선은 버린다.

### Python 코드

```python
def find(p, x):
    while p[x] != x:
        p[x] = p[p[x]]     # 경로 반으로 줄이기(path halving)
        x = p[x]
    return x

def union(p, size, a, b):
    a, b = find(p, a), find(p, b)
    if a == b:
        return False       # 이미 같은 집합
    if size[a] < size[b]:
        a, b = b, a
    p[b] = a
    size[a] += size[b]
    return True
```

5 개 원소에서 (1,2) (2,3) (1,3) (4,5) 를 차례로 합쳐 보니 `True, True, False, True` 가 나왔다. 세 번째가 False 인 건 1 과 3 이 이미 같은 집합이라서고, 크루스칼에서 "이 간선은 사이클을 만든다"는 신호로 그대로 쓴다. 마지막에 1 과 3 은 같은 집합, 1 과 4 는 다른 집합으로 확인했다.

재귀 find 는 파이썬 재귀 한도에 걸릴 수 있어서 위처럼 반복문으로 쓰는 게 안전하다.

### 복잡도

연산당 거의 O(1)(정확히는 분할 상환 O(α(n))), 공간 O(n). 위키피디아에서는 이 하한이 증명되어 더 줄일 수 없다고 적는다.

## 위상 정렬

### 유형 설명

"A 를 해야 B 를 한다"는 선후 관계를 간선으로 둔 방향 그래프가 있을 때, 모든 간선이 앞에서 뒤로 향하게 일렬로 세우는 게 위상 정렬이다. 과목 선수 과목, 빌드 의존성, 작업 순서가 전형적이다. 방향 사이클이 없는 그래프 (DAG) 여야만 가능하다. 순서는 하나로 정해지지 않을 수도 있다.

카안 알고리즘이 가장 흔하다. 들어오는 간선이 0 개인 노드를 큐에 넣고, 하나 꺼내 결과에 붙인 뒤 그 노드가 가리키던 간선을 지운다. 그 결과 진입차수가 0 이 된 이웃을 큐에 넣는다. 끝났는데 결과 길이가 n 보다 작으면 사이클이 있다는 뜻이라, 사이클 판별도 같이 된다.

### 대표 문제

- LeetCode 210 Course Schedule II: 선수 과목 관계가 주어질 때 모든 과목을 들을 수 있는 순서 하나를 돌려주고, 불가능하면 빈 배열을 돌려준다. 카안 알고리즘 그대로다.
- LeetCode 207 Course Schedule: 같은 입력에서 순서는 필요 없이 모든 과목을 들을 수 있는지 (사이클이 없는지) 만 판단한다.
- 선후 관계가 같을 때 번호가 작은 것부터 내보내라는 조건이 붙으면 큐 대신 힙을 쓰는 변형이 된다 (아래 풀이 생각 순서 6 번).

### 풀이 생각 순서

1. "순서", "선행", "먼저 해야" 같은 말이 나오는지 본다.
2. 간선 방향을 정한다 (선행 → 후행). 방향을 반대로 잡는 실수가 많다.
3. 진입차수 배열을 만든다.
4. 진입차수 0 인 노드를 큐에 넣고 꺼내며 줄인다.
5. 결과 개수가 n 이 아니면 사이클이다.
6. 순서 조건이 더 붙으면 (작은 번호 우선 등) 큐를 힙으로 바꾼다.

### Python 코드

```python
from collections import deque

def topo(n, edges):
    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for a, b in edges:          # a를 먼저 해야 b
        g[a].append(b)
        indeg[b] += 1
    q = deque(i for i in range(1, n + 1) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else None   # None이면 사이클
```

(1,2) (1,3) (2,4) (3,4) 로 돌리면 `[1, 2, 3, 4]`, 1→2→3→1 사이클을 넣으면 `None` 이 나왔다.

### 복잡도

O(V+E), 공간 O(V+E).

## 헷갈리는 것

- 다익스트라는 "가장 작은 걸 꺼내는" 그리디다. 음수 간선에서 틀리는 이유도 거기에 있다.
- 간선 비용이 전부 같거나 0/1 이면 다익스트라까지 갈 필요가 없다. BFS 나 0-1 BFS 로 된다.
- 유니온 파인드는 그룹이 합쳐지기만 하고, 쪼개지지는 않는다. 간선이 지워지는 문제는 시간을 거꾸로 돌려 합치기로 바꿔 푸는 경우가 많다.
- 위상 정렬 결과는 하나가 아닐 수 있어서, 문제가 특정 순서를 요구하면 그 규칙 (힙 등) 을 따로 넣어야 한다.

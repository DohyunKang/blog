정보 보안 단원은 용어가 많고 비슷한 이름의 공격이 줄줄이 나와서 외우다 보면 섞인다. 도구마다 지키려는 게 다르다는 걸 먼저 갈라 놓으면 정리가 된다. 시험 일정·응시료는 공식 사이트에서 확인하고, 여기서는 개념과 문제 푸는 방식만 적는다.

## 먼저 큰 그림

| 지키려는 것 | 쓰는 도구 | 이 글의 절 |
|---|---|---|
| 기밀성(남이 못 읽게) | 암호화 | 암호화 |
| 무결성(바뀌지 않게) | 해시, 전자서명 | 암호화 |
| 누가 무엇을 할 수 있나 | 인증, 접근통제 | 인증과 접근통제 |
| 서비스가 계속 돌게 | 공격 유형 파악과 대응 | 공격 유형 |

## 암호화

암호화는 읽을 수 없는 형태로 바꿔서 기밀성을 지키는 방법이다. 시험에서는 키를 몇 개 쓰느냐로 나눠 묻는다.

| 구분 | 키 | 특징 | 예 |
|---|---|---|---|
| 대칭키 | 암호화·복호화에 같은 키 | 빠르다, 키를 미리 나눠 가져야 한다 | DES, AES |
| 비대칭키(공개키) | 공개키와 개인키 한 쌍 | 공개키는 퍼뜨려도 된다, 개인키만 숨긴다 | RSA, ECC |

대칭키는 사용자 쌍마다 비밀 키가 필요해서 사람이 늘수록 키 관리가 어려워진다. 공개키 방식은 미리 비밀을 나눌 필요가 없는 대신, 이 공개키가 정말 그 사람 것인지 확인해야 한다. 이 확인을 PKI 같은 체계가 맡는다.

공개키에서 키의 역할은 목적에 따라 뒤집힌다. 시험에 거의 매번 나오는 포인트다.

| 목적 | 만드는 쪽 | 푸는 쪽 |
|---|---|---|
| 암호화(기밀성) | 받는 사람의 공개키로 암호화 | 받는 사람의 개인키로 복호화 |
| 전자서명(무결성·부인방지) | 보내는 사람의 개인키로 서명 | 보내는 사람의 공개키로 검증 |

[암호·해시·서명을 더 자세히 → 암호화·해시·인증 기초](#/post/sec-authn-crypto)

<details>
<summary>작은 숫자로 RSA 해 보기</summary>

RSA는 큰 두 소수의 곱을 인수분해하기 어렵다는 점에 기대는 방식이다. 아주 작은 소수로 흐름만 따라가 봤다. p=61, q=53이면 n=3233이고, 공개 지수 e=17에 대응하는 개인 지수 d는 2753이다.

```python
p, q = 61, 53
n = p * q
phi = (p - 1) * (q - 1)
e = 17
d = pow(e, -1, phi)
c = pow(65, e, n)       # 평문 65를 공개키(e, n)로 암호화
print(n, d, c, pow(c, d, n))
# 3233 2753 2790 65
```

평문 65가 2790으로 바뀌고, 개인키 d로 풀면 65로 돌아온다. 실제로는 이런 작은 수가 아니라 아주 큰 수를 쓴다.

</details>

### 해시

해시는 입력이 얼마나 길든 정해진 길이의 값으로 줄이는 함수다. 되돌릴 수 없는 일방향이라 복호화라는 개념이 없고, 파일이나 메시지가 바뀌었는지 확인하는 무결성 점검에 쓴다. 입력이 한 글자만 달라도 결과가 완전히 달라진다.

```python
import hashlib
print(hashlib.sha256(b"password").hexdigest()[:16])  # 5e884898da280471
print(hashlib.sha256(b"passworD").hexdigest()[:16])  # 9e78de733c6a51c0
```

SHA-256은 256비트, MD5는 128비트 길이의 값을 내놓는다. 둘 다 길이가 입력과 무관하게 고정이다.

비밀번호를 저장할 때는 해시에 솔트(사용자마다 다른 임의 값)를 섞는다. 같은 비밀번호라도 결과가 달라져서 미리 계산해 둔 표로 한 번에 맞춰 보는 공격이 어려워진다.

```python
print(hashlib.sha256(b"s1" + b"password").hexdigest()[:16])  # 33453fb858dcac18
print(hashlib.sha256(b"s2" + b"password").hexdigest()[:16])  # bd22d1631a4e4c66
```

<details>
<summary>해시와 암호화가 섞이는 지점</summary>

- 암호화는 키가 있으면 원래대로 풀 수 있고, 해시는 풀 수 없다.
- 해시에 비밀 키를 넣어 메시지가 위조되지 않았는지 보는 방식을 메시지 인증 코드(MAC)라고 한다. 접근통제의 MAC(강제적 접근통제)과 약어가 같아서 문제에서 문맥으로 구분해야 한다.
- 전자서명은 보통 메시지 전체가 아니라 메시지의 해시값에 개인키로 서명하는 식으로 만든다.

</details>

## 인증과 접근통제

인증(Authentication)은 "당신이 누구냐"를 확인하는 일이고, 인가(Authorization)는 "그 사람이 무엇을 할 수 있느냐"를 정하는 일이다. 접근통제는 인가를 실제로 강제하는 장치를 말한다.

인증 수단은 보통 세 가지로 묶는다.

| 종류 | 예 |
|---|---|
| 지식(알고 있는 것) | 비밀번호, PIN |
| 소유(가진 것) | OTP 기기, 스마트폰, 인증서 |
| 속성(본인 자체) | 지문, 얼굴 |

서로 다른 종류를 두 개 이상 섞는 게 다중 인증이다. 비밀번호 두 개는 같은 종류라서 다중 인증이 아니다.

### 접근통제 모델

| 모델 | 누가 권한을 정하나 | 한 줄 |
|---|---|---|
| DAC(임의적) | 자원의 소유자 | 소유자가 누구에게 열어 줄지 정한다 |
| MAC(강제적) | 시스템 정책 | 보안 등급(기밀·비밀 등)과 사용자 허가 등급으로 판단한다 |
| RBAC(역할 기반) | 조직의 역할 | 직무에 맞는 권한만 묶어서 준다 |

최소 권한 원칙은 각 사용자에게 업무에 필요한 만큼만 주라는 것이다. RBAC는 이 원칙을 지키기 쉬운 편이다. 인사 담당자가 네트워크 계정을 만들 수 없게 하는 식이다.

## 공격 유형

공격 이름은 이름만 보고는 뭘 하는지 안 떠오르는 경우가 많아서, 동작을 한 줄로 붙여 외웠다.

| 공격 | 동작 |
|---|---|
| SYN 플러딩 | 출처를 속인 SYN 패킷을 쏟아 보내 응답 없는 반쯤 열린 연결로 서버 자원을 채운다 |
| 스머프 | 브로드캐스트 주소로 피해자 주소를 출발지로 속인 패킷을 보내 여러 호스트의 응답이 피해자에게 몰리게 한다 |
| 죽음의 핑 | 비정상 핑 패킷으로 취약한 시스템을 다운시킨다 |
| 티어드롭 | 겹치고 비정상인 IP 조각을 보내 재조립 과정에서 오류를 낸다 |
| DDoS | 감염된 수많은 호스트(봇넷)가 동시에 몰려가 대역폭·자원을 소진시킨다 |

[TCP 연결과 IP 조각이 어떻게 생기는지 → 네트워크](#/post/jb-network)

DoS는 서비스를 못 쓰게 만드는 게 목적이라 가용성을 건드린다. 출처가 하나가 아니라서 DDoS는 발신지 하나를 막는 것으로는 안 끝난다. 시험에서는 이름과 동작을 짝짓는 문제로 나온다. 출처 위조(스푸핑)가 SYN 플러딩과 스머프에 모두 쓰인다는 점도 같이 기억해 두면 좋다.

### 웹 공격: SQL 삽입과 XSS

SQL 삽입은 입력값에 SQL 조각을 끼워 쿼리의 뜻을 바꾸는 공격이다. 아래는 sqlite 메모리 DB로 직접 돌려 본 것이다.

```python
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("create table u(n,p)")
db.execute("insert into u values('kim','pw')")

n = "kim' --"
q = "select * from u where n='%s' and p='bad'" % n
print(db.execute(q).fetchall())      # [('kim', 'pw')]  비밀번호가 틀렸는데 통과
print(db.execute("select * from u where n=? and p=?", (n, 'bad')).fetchall())  # []
```

문자열을 이어 붙이면 `--` 뒤의 조건이 주석이 되어 비밀번호 검사가 사라진다. 값을 자리표시자(`?`)로 넘기면 입력이 SQL이 아니라 값으로만 취급되어 막힌다. [SQL 기본기 → 데이터베이스 개념](#/post/jb-db-concept)

XSS는 신뢰하는 사이트에 악성 스크립트를 넣어 방문자 브라우저에서 실행시키는 공격이다. 브라우저가 그 사이트를 믿으니 스크립트가 쿠키·세션 토큰 같은 데이터에 접근하거나 화면을 바꿀 수 있다. 입력이 곧바로 응답에 되돌아오면 반사형, 서버에 저장되어 그 내용을 보는 모두에게 실행되면 저장형이다. 방어의 기본은 입력 검증과 출력 인코딩이다.

```python
import html
print(html.escape("<script>x</script>"))  # &lt;script&gt;x&lt;/script&gt;
```

<details>
<summary>풀이 요령</summary>

보안 문제는 보통 설명을 주고 용어를 고르거나, 용어를 주고 설명을 고르는 형태다. 이렇게 푼다.

1. 설명에서 지키려는 성질(기밀성·무결성·가용성)부터 짚는다.
2. 키 얘기가 나오면 몇 개인지, 누구의 키로 하는지를 본다. 서명이면 보내는 쪽 개인키다.
3. 공격 이름은 동작 한 줄과 짝지어 지워 간다. 브로드캐스트와 출처 위조가 보이면 스머프, 반쯤 열린 연결이 보이면 SYN 플러딩이다.
4. 접근통제는 "누가 정하나"를 본다. 소유자면 DAC, 등급이면 MAC, 직무면 RBAC다.

</details>

## 자주 하는 착각

- 해시를 "암호화한 것"이라고 부르면 틀리다. 풀 수 없는 일방향 요약이다.
- 공개키로 서명하는 게 아니다. 서명은 개인키, 검증은 공개키다.
- 비밀번호 두 개를 요구해도 같은 종류면 다중 인증이 아니다.
- 접근통제의 MAC과 메시지 인증 코드의 MAC은 이름만 같다.

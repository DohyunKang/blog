Email newsletters are the oldest channel in marketing automation. The flow of collecting a list, populating templates with content, and scheduling sends can be easily built with scripts. However, the challenging part is not sending the email but ensuring it reaches the recipient's inbox; this requires adhering to specific requirements. This summary is based on Google's Sender Guidelines.

## Overall Flow

1. Select a segment from the subscriber list (consenting users only).
2. Populate the template with content to create the message and include a point for human review.
3. Send via a sending service (or SMTP), attaching domain authentication and headers at this stage.
4. Collect responses (opens, clicks, unsubscribes, spam reports) to determine the target audience for the next send.

Steps 1, 2, and 4 follow structures similar to content calendars and dashboard automation, while step 3 is unique to email.

## Requirements for All Senders

Google guidelines state that starting February 1, 2024, all senders must comply with the following:

- Configure SPF or DKIM authentication for the sending domain.
- Maintain a spam complaint rate below 0.3% as measured in Postmaster Tools.
- Use TLS connections for transmission.
- Ensure forward and reverse DNS (PTR) records exist for the sending domain or IP.
- Format messages according to RFC 5322.

Note that the spam complaint rate requirement (<0.3%) differs from the recommended target (<0.10%). The guidelines explicitly advise avoiding rates of 0.30% or higher.

## Additional Requirements for High-Volume Senders

Senders exceeding 5,000 emails per day must also meet these additional criteria:

| Item | Requirement |
|---|---|
| Authentication | In addition to SPF and DKIM, implement DMARC. The DMARC policy may be set to `none`. |
| Domain Alignment | The From: domain must match the SPF or DKIM domain. |
| Unsubscribe | Marketing and subscription messages must support one-click unsubscribe and include a visible unsubscribe link in the body. |
| DKIM Key | For personal Gmail accounts, use keys of at least 1024 bits; 2048 bits is recommended. |

While personal newsletters may not reach 5,000 emails per day, all sender requirements (SPF or DKIM, spam complaint rate) still apply.

## Implementing One-Click Unsubscribe via Headers

One-click unsubscribe is implemented according to RFC 8058 by adding two headers to the message.

```
List-Unsubscribe: <https://example.com/u/abc123>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```

When a recipient clicks the unsubscribe button, their mail service sends a POST request to the `List-Unsubscribe` HTTPS address with the body `List-Unsubscribe=One-Click`. Therefore, the sending side needs an endpoint that receives this address and removes the corresponding subscriber from the list.

RFC 8058 specifies additional conditions:

- The message must include at least one valid DKIM signature that covers both headers (included in the `h=` tag). If no signature is present, the receiving service must not offer one-click unsubscribe functionality.
- The URI must contain tamper-resistant values, which the server must verify.
- Do not respond to this POST with an HTTPS redirect.

<summary>Example of adding headers in Python (run directly to verify)</summary>

This example creates a message using the standard `email` library and attaches the two headers. The output confirms that both headers appear correctly. Note that actual sending and DKIM signing are not included in this code; signing is handled by the sending service or mail server.

```python
from email.message import EmailMessage

m = EmailMessage()
m["From"] = "news@example.com"
m["To"] = "reader@example.org"
m["Subject"] = "weekly"
m["List-Unsubscribe"] = "<https://example.com/u/abc123>"
m["List-Unsubscribe-Post"] = "List-Unsubscribe=One-Click"
m.set_content("hello")
print(m.as_string())
```

## Things Often Overlooked During Automation

- Delaying unsubscribe handling can cause the spam complaint rate to rise. Since there is a limit on the complaint rate, create the unsubscribe endpoint first.
- Domain authentication (SPF, DKIM, DMARC) involves DNS configuration and should be set up once outside the code pipeline; include only an "authentication check" step in the pipeline.
- Instead of sending to the entire list at once, consider a two-step approach: send first to a small subset to monitor the complaint rate before proceeding. This is not from the referenced document but an example of an operational strategy.

If using AI, include placeholders for title/body drafts and per-segment text variations. However, it is safer for humans to handle the target audience selection and final review.

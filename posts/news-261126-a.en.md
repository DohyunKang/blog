## What it does
A skill is a bundle of instructions an agent pulls out when it does a certain job: one SKILL.md plus reference docs and scripts. This repo follows that format, so one line, `npx skills add cathrynlavery/diagram-design`, installs it into Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI and others.

The output is one HTML file with SVG inside. SVG describes points, lines and text as coordinates, so it stays sharp when zoomed. Nothing external gets loaded, which makes it easy to attach or drop into a doc. It covers 52 types: architecture, sequence, state, ER, Gantt, quadrant, funnel and so on. There are scripts to export PNG, standalone SVG and print PDF, and importers that redraw draw.io, Mermaid, Excalidraw and PlantUML files in this style.

The README tagline is "No shadows. No Mermaid slop." Ask an agent for a diagram and you usually get drop shadows, everything colored, arrows tangled diagonally. This is meant to stop that.

## Taste written down as rules
SKILL.md turns design sense into fairly specific numbers.

- The accent color goes on 1–2 elements per diagram. Put it on five and the emphasis disappears.
- Target density is 4 out of 10. Past 9 nodes, split it into two diagrams.
- Arrows bend at right angles only, with 8px rounded corners. Diagonals count as a failure.
- Arrow labels are 14 characters max, uppercase, 6–10px off the line.
- Node positions, sizes and gaps are all multiples of 4.

There's also a question before drawing: if a table or paragraph would do, don't draw. The first line of the philosophy section says the best move is usually deletion. After drawing, a checklist asks whether a node, a merge, or an arrow could go.

In a new project it doesn't draw right away. If colors and fonts are still default, it stops and asks whether to match a website, a design-system folder or pasted tokens. Give it a URL and it takes that site's palette and fonts for every diagram after.

## Scripts do the last check
This was the part that stood out. The rules aren't only in docs. Python scripts that check the output file ship inside the skill.

`self_check.py` runs with no dependencies. It checks accessibility rules (`role="img"` on `<svg>`, title and description tags), that nothing external loads besides the allowed fonts, that there are no executable attributes, that content stays inside the frame, and that the file wasn't cut off or garbled. Accessibility here means people using screen readers can still get the content.

`verify_geometry.py` checks that the plate behind an arrow label isn't hidden by a node drawn later, and that arrows follow the right-angle rule. The agent runs these after drawing and fixes what fails. A machine catches "those lines overlap" before a person has to say it.

The repo itself works the same way. Per the CHANGELOG, a WCAG contrast check runs in CI and every example is rendered in Chromium. Versions aren't bumped by hand; a workflow bumps them on each merge to main, which is how it reached 2.6.179 as of Nov 25.

## For beginners
Putting one diagram in a spec usually means opening a tool and dragging boxes around for a while. Here you ask and a file comes out. But I think the real thing to look at is how it's built: vague asks like "make it look good" turned into numbers and checklists, and whatever can be checked gets checked by a script. It's a useful frame for handing an agent work that normally runs on taste.

As a PM, the "ask whether a table is enough before drawing" rule is usable as is. More diagrams don't make a doc easier to read.

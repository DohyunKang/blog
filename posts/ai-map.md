AI 공부를 하다 보면 용어가 한꺼번에 쏟아진다. 프롬프트, 컨텍스트, RAG, MCP, 하네스 같은 말이 서로 얽혀 있어서 하나만 따로 보면 안 읽힌다. 그래서 큰 단어를 한 줄씩만 먼저 적고, 더 알고 싶은 건 아래 링크로 넘어가게 했다. 순서는 바닥에서 위로, 모델 → 입력 → 기억 → 바깥 연결 순이다.

## 한눈에 보는 관계

```
생성형 AI ⊃ LLM
LLM  ←  프롬프트(입력)  ←  컨텍스트(그 순간 모델이 보는 전체)
컨텍스트 = 컨텍스트 윈도우 안에 담기는 것 (토큰으로 센다)
컨텍스트에 외부 지식을 넣는 방법 = RAG (임베딩으로 찾는다)
컨텍스트에 도구를 연결하는 규격 = MCP
이 전부를 돌리고 관리하는 모델 바깥의 코드 = 하네스
모델이 틀린 말을 그럴듯하게 하는 현상 = 할루시네이션
```

## 1. 모델이 뭔가

**생성형 AI**: 분류·예측만 하던 AI와 달리 글·그림·소리를 새로 만들어 내는 AI.
[자세히 → 생성형 AI란](#/post/ai-generative)

**LLM(대형 언어 모델)**: 글 조각(토큰) 다음에 올 조각을 계속 맞히도록 아주 크게 학습한 모델. 챗봇은 그 위에 얹은 겉모습이다.
[자세히 → LLM이란 무엇인가](#/post/ai-llm)

## 2. 모델에게 뭘 주나

**프롬프트**: 모델에게 주는 입력 전부. 명확하게, 예시를 곁들여, 형식을 정해서 쓰는 게 기본이다.
[자세히 → 프롬프트와 프롬프트 엔지니어링](#/post/ai-prompt)

**컨텍스트**: 모델이 답을 만드는 순간 한 번에 보는 글 전체. 프롬프트도 그 일부고, 뭘 올려 두느냐를 설계하는 일이 컨텍스트 엔지니어링이다.
[자세히 → 컨텍스트와 컨텍스트 엔지니어링](#/post/ai-context)

**컨텍스트 윈도우·토큰**: 컨텍스트가 담길 수 있는 최대 분량, 그리고 그걸 세는 단위. 대화가 길어지면 매 호출마다 전체를 다시 보내서 돈과 시간이 같이 는다.
[자세히 → 컨텍스트 윈도우와 토큰](#/post/ai-context-window)

## 3. 모르는 걸 어떻게 알려 주나

**임베딩**: 글을 숫자 좌표로 바꿔서 뜻이 가까운 것끼리 찾게 해 주는 방식.
[자세히 → 임베딩과 벡터 검색](#/post/ai-embedding)

**RAG**: 모델한테 책을 펴 놓고 시험 보게 하는 방식. 필요한 문서를 먼저 찾아서 컨텍스트에 넣어 준다.
[자세히 → RAG](#/post/ai-rag)

**할루시네이션**: 모르면 찍도록 만들어진 구조 때문에 생기는, 그럴듯한 틀린 답.
[자세히 → 할루시네이션](#/post/ai-hallucination)

## 4. 바깥 세상과 어떻게 이어지나

**MCP**: AI 앱과 외부 도구를 잇는 연결 규격. 도구를 한 번 만들어 두면 여러 앱에서 꽂아 쓸 수 있다.
[자세히 → MCP](#/post/ai-mcp)

**하네스**: 모델 바깥에서 루프·도구·권한·기록을 맡는 코드. 자료마다 가리키는 범위가 조금씩 다르다.
[자세히 → 하네스와 하네스 엔지니어링](#/post/ai-harness)

AI 공부를 하다 보면 용어가 한꺼번에 쏟아진다. 프롬프트, 컨텍스트, RAG, MCP, 하네스 같은 말이 서로 얽혀 있어서 하나만 따로 보면 안 읽힌다. 그래서 큰 단어를 한 줄씩만 먼저 적고, 더 알고 싶은 건 아래 링크로 넘어가게 했다. 순서는 바닥에서 위로, 모델 → 입력 → 기억 → 바깥 연결 순이다.

## 한눈에 보는 관계

```
생성형 AI ⊃ LLM
LLM  ←  프롬프트(입력)  ←  컨텍스트(그 순간 모델이 보는 전체)
컨텍스트 = 컨텍스트 윈도우 안에 담기는 것 (토큰으로 센다)
컨텍스트에 외부 지식을 넣는 방법 = RAG (임베딩으로 찾는다)
컨텍스트에 도구를 연결하는 규격 = MCP
이 전부를 돌리고 관리하는 모델 바깥의 코드 = 하네스
모델이 틀린 말을 그럴듯하게 하는 현상 = 할루시네이션
```

## 1. 모델이 뭔가

**생성형 AI**: 분류·예측만 하던 AI와 달리 글·그림·소리를 새로 만들어 내는 AI.
[자세히 → 생성형 AI란](#/post/ai-generative)

**LLM(대형 언어 모델)**: 글 조각(토큰) 다음에 올 조각을 계속 맞히도록 아주 크게 학습한 모델. 챗봇은 그 위에 얹은 겉모습이다.
[자세히 → LLM이란 무엇인가](#/post/ai-llm)

## 2. 모델에게 뭘 주나

**프롬프트**: 모델에게 주는 입력 전부. 명확하게, 예시를 곁들여, 형식을 정해서 쓰는 게 기본이다.
[자세히 → 프롬프트와 프롬프트 엔지니어링](#/post/ai-prompt)

**컨텍스트**: 모델이 답을 만드는 순간 한 번에 보는 글 전체. 프롬프트도 그 일부고, 뭘 올려 두느냐를 설계하는 일이 컨텍스트 엔지니어링이다.
[자세히 → 컨텍스트와 컨텍스트 엔지니어링](#/post/ai-context)

**컨텍스트 윈도우·토큰**: 컨텍스트가 담길 수 있는 최대 분량, 그리고 그걸 세는 단위. 대화가 길어지면 매 호출마다 전체를 다시 보내서 돈과 시간이 같이 는다.
[자세히 → 컨텍스트 윈도우와 토큰](#/post/ai-context-window)

## 3. 모르는 걸 어떻게 알려 주나

**임베딩**: 글을 숫자 좌표로 바꿔서 뜻이 가까운 것끼리 찾게 해 주는 방식.
[자세히 → 임베딩과 벡터 검색](#/post/ai-embedding)

**RAG**: 모델한테 책을 펴 놓고 시험 보게 하는 방식. 필요한 문서를 먼저 찾아서 컨텍스트에 넣어 준다.
[자세히 → RAG](#/post/ai-rag)

**할루시네이션**: 모르면 찍도록 만들어진 구조 때문에 생기는, 그럴듯한 틀린 답.
[자세히 → 할루시네이션](#/post/ai-hallucination)

## 4. 바깥 세상과 어떻게 이어지나

**MCP**: AI 앱과 외부 도구를 잇는 연결 규격. 도구를 한 번 만들어 두면 여러 앱에서 꽂아 쓸 수 있다.
[자세히 → MCP](#/post/ai-mcp)

**하네스**: 모델 바깥에서 루프·도구·권한·기록을 맡는 코드. 자료마다 가리키는 범위가 조금씩 다르다.
[자세히 → 하네스와 하네스 엔지니어링](#/post/ai-harness)

## 5. 어떤 모델을 쓰나, 어떻게 잘 쓰나

**AI 모델 지도**: 회사별 주요 모델과 열린·닫힌 모델, 크기 계열, 고르는 기준(2026-11-02 기준).
[자세히 → AI 모델 지도](#/post/ai-models)

**Claude 토큰 아끼는 법**: 토큰이 어디서 나가는지, 캐싱과 `/clear`·`/compact`, 모델 분담.
[자세히 → Claude 토큰 아끼는 법](#/post/claude-tokens)

**Claude 스킬·설정**: `CLAUDE.md`, 스킬, 훅, 서브에이전트, 권한, MCP를 언제 뭘 쓰는지.
[자세히 → Claude Code 스킬·설정](#/post/claude-skills)

## 6. 대화는 어떻게 이어지고 기억되나

**세션과 대화 기록**: 챗봇이 내 말을 기억하는 건 모델이 아니라, 앱이 매 호출마다 지금까지의 기록을 통째로 다시 보내서다.
[자세히 → 세션과 대화 기록](#/post/ai-session)

**컴팩션·메모리**: 컴팩션은 차 가는 대화를 요약으로 바꿔 끼우는 일이고, 메모리는 요약에서 빠져도 되돌릴 수 있게 창 밖에 적어 두는 것이다.
[자세히 → 컴팩션과 메모리](#/post/ai-compaction)

**프롬프트 캐싱**: 요청마다 똑같은 앞부분을 한 번 처리해 두고 재사용하는 기능. 앞에서부터 완전히 같아야 한다.
[자세히 → 프롬프트 캐싱](#/post/ai-prompt-caching)

## 7. 도구와 에이전트

**도구 호출**: 모델이 함수를 직접 돌리는 게 아니라 "이걸 이 인자로 실행해 줘"라는 요청서를 쓰고, 실행은 내 코드가 한다.
[자세히 → 도구 호출(Function calling)](#/post/ai-tool-use)

**에이전트·에이전트 루프**: 모델이 도구를 쓰고 결과를 보고 다시 판단하는 걸 끝날 때까지 반복하는 구조. 뼈대는 while 문이다.
[자세히 → 에이전트와 에이전트 루프](#/post/ai-agent-loop)

**서브에이전트·멀티에이전트**: 일부 작업을 새 컨텍스트에서 시키고 요약만 받아 오는 방식. 일이 병렬로 나뉘고 요약으로 충분할 때만 이득이었다.
[자세히 → 서브에이전트와 멀티에이전트](#/post/ai-subagent)

**스킬**: 특정 작업의 절차·자료·스크립트를 폴더 하나에 묶어 두고 필요할 때만 꺼내 읽게 하는 방식. 항상 올라가 있는 건 이름과 설명뿐이다.
[자세히 → 스킬(Skills)](#/post/ai-skills)

**모델·도구별 스킬 비교**: Claude, Codex, Gemini CLI, Cursor 모두 지침 파일 → 스킬 → 배포 패키지 구조로 이름만 다르고 닮았다.
[자세히 → 모델·도구별 스킬과 확장 비교](#/post/ai-vendor-skills)

## 8. 모델 출력과 입력 형태

**샘플링(온도·top-p)**: 모델이 다음 단어를 확률표에서 뽑는 방법을 조절하는 값. 최근 Claude 쪽에서는 이 값을 못 쓰게 되는 추세라 현황도 같이 정리했다.
[자세히 → 샘플링: 온도·top-p](#/post/ai-sampling)

**추론 모델·생각 토큰**: 답하기 전에 혼자 생각하는 글을 먼저 쓰는 모델. 화면에 안 보여도 출력 토큰 요금과 대기 시간으로 돌아온다.
[자세히 → 추론 모델과 생각 토큰](#/post/ai-reasoning)

**구조화 출력**: 답을 정해 둔 모양(스키마)에 맞춰 내게 하는 기능. 부탁하는 것과 강제하는 것은 믿을 수 있는 정도가 다르다.
[자세히 → 구조화 출력(JSON·스키마)](#/post/ai-structured-output)

**멀티모달**: 글 말고 이미지·음성도 같이 다룬다는 뜻. 이미지는 토큰으로 바뀌어 글과 같은 창에 들어간다.
[자세히 → 멀티모달](#/post/ai-multimodal)

## 9. 원리: 모델은 어떻게 만들어지나

**머신러닝·딥러닝 기초**: 데이터를 보여 주고 규칙에 해당하는 숫자(가중치)를 모델이 스스로 맞추게 하는 방식. 딥러닝은 층을 깊게 쌓은 신경망을 쓴다.
[자세히 → 머신러닝·딥러닝 기초](#/post/ml-basics)

**신경망·역전파**: 곱하고 더하고 휘는 계산을 층층이 쌓은 함수, 그리고 가중치를 어느 쪽으로 고칠지 거꾸로 계산하는 방법.
[자세히 → 신경망과 역전파](#/post/ml-neural-net)

**트랜스포머·어텐션**: 문장 안 단어들이 서로를 얼마나 참고할지 점수로 계산하는 구조. 요즘 LLM이 거의 이걸 뼈대로 쓴다.
[자세히 → 트랜스포머와 어텐션](#/post/ml-transformer)

**사전학습에서 RLHF까지**: 인터넷 글로 다음 단어 맞히기(사전학습), 답하는 법 보여 주기(SFT), 사람이 고른 쪽으로 밀어 주기(선호 학습) 세 단계.
[자세히 → 사전학습에서 RLHF까지](#/post/ml-pretraining)

**파인튜닝**: 학습이 끝난 모델을 내 데이터로 한 번 더 가르치는 일. 전체를 고치느냐 일부만 얹느냐(LoRA/QLoRA)에 따라 필요한 GPU가 크게 달라진다.
[자세히 → 파인튜닝: 전체 vs LoRA/QLoRA](#/post/ml-finetuning)

**로컬 모델**: 내 PC에서 직접 돌리는 방식. 들어가느냐는 대부분 VRAM 계산 하나로 정해진다.
[자세히 → 로컬 모델 돌리기](#/post/ml-local-models)

**추론 최적화**: KV 캐시, 배치, 스트리밍, 투기적 디코딩이 서로 연결된 한 덩어리로, 답을 더 빠르고 싸게 뽑는 기법 모음.
[자세히 → 추론 최적화](#/post/ml-inference)

**이미지 생성(확산)**: 순수한 노이즈에서 시작해 조금씩 걷어 내며 이미지를 만드는 모델.
[자세히 → 이미지 생성 모델(확산)](#/post/ml-diffusion)

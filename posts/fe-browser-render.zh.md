浏览器接收 HTML 和 CSS，并按照 DOM、CSSOM、渲染树、布局、绘制的顺序构建屏幕。其中哪个阶段需要重新执行，决定了屏幕变更的成本。

## 输入地址之后

在绘制画面之前，必须先接收 HTML。根据 MDN 文档，顺序如下：将主机名通过 DNS 转换为 IP 地址，建立 TCP 连接（三次握手），如果是 HTTPS 则进行 TLS 协商。随后发送 HTTP GET 请求，当收到第一份 HTML 片段时开始解析。从第一个数据包到达所需的时间称为 TTFB。这一阶段属于网络范畴，详见 [详情 → 网络](#/post/cs-network)。此处将从第一份 HTML 片段到达之后开始讨论。

## 整体流程

| 阶段 | 执行内容 | 结果物 |
|---|---|---|
| 解析 (HTML) | 将文本拆分为标记并构建为节点树 | DOM |
| 解析 (CSS) | 按从通用到具体的顺序堆叠规则并构建为树 | CSSOM |
| 样式合并 | 合并 DOM 和 CSSOM，仅筛选可见节点 | 渲染树 |
| 布局 | 计算每个盒子的位置和尺寸 | 盒子模型 |
| 绘制 | 将盒子绘制为像素（文字、颜色、边框、阴影） | 分层位图 |
| 合成 | 叠加图层并显示在屏幕上 | 画面 |

上述前五个阶段通常被称为关键渲染路径。web.dev 文档将“优化此路径”解释为“减少在这些阶段所花费的时间”。

## DOM 与 CSSOM

HTML 被拆分为标记后，形成以 `<html>` 为根的节点树，这就是 DOM。CSS 也独立构建成一棵树，即 CSSOM。浏览器从默认样式表开始，按照从通用规则到具体规则的覆盖结构进行组织，因此称为树。

两者是独立的对象。DOM 包含内容信息，而 CSSOM 包含应用于该内容的样式规则。因此，仅有 HTML 即可构建 DOM，但要绘制画面则必须让两者结合。

在解析过程中遇到 `<script>` 标签时情况会有所不同。根据 MDN 文档，没有 `async` 或 `defer` 属性的脚本在下载和执行期间会暂停 HTML 解析。CSS 不会暂停 HTML 解析，但已计算出的样式会被 JavaScript 读取并阻塞。因此，脚本通常添加 `defer` 属性或放置在文档末尾。

```html
<!-- 파싱을 멈추고 내려받아 실행 -->
<script src="a.js"></script>
<!-- 병렬로 내려받고, 끝나는 대로 실행(순서 보장 없음) -->
<script src="b.js" async></script>
<!-- 병렬로 내려받고, 파싱이 끝난 뒤 문서 순서대로 실행 -->
<script src="c.js" defer></script>
```

此外，在解析器后端，预加载扫描器会先行运行，提前下载 CSS、JS、字体和图片。即使解析被脚本阻塞，下载仍可从之前开始。

## 渲染树

合并 DOM 和 CSSOM 后形成渲染树。从根节点开始遍历，仅访问屏幕上可见的节点，附加适用的 CSS 规则，并输出为具有计算样式的节点。

不可见的节点会被移除。例如 `<head>`、`<script>`、`<meta>` 等标签以及 `display: none` 的元素即属此类。此处容易混淆的是 `visibility: hidden`。它保留在渲染树中，占据位置但不可见。而 `display: none` 会从渲染树中移除，因此不参与布局计算。

## 布局

遍历渲染树，从根节点开始，以视口为基准计算每个元素的精确位置和尺寸。这是将百分比等相对值转换为像素的阶段。web.dev 的示例非常直观：若父元素占视口的 50%，其子元素占父元素的 50%，则子元素占视口宽度的 25%。

首次计算称为布局，之后再次计算的计算称为重排（MDN）。本质是同一计算，仅根据时间点命名不同。

## 绘制与合成

布局完成后，将盒子转换为像素。文字、颜色、边框、阴影和图片在此时绘制。根据样式不同，成本各异。web.dev 指出纯色较便宜，而渐变则计算昂贵。

随后进入合成阶段。带有 `opacity`、3D `transform`、`will-change` 的元素或 `<video>`、`<canvas>` 会提升为独立图层，可在 GPU 上进行合成。MDN 指出，若分层过多虽可仅重绘单个图层，但图层占用内存，因此不应滥用。同一文档还提到，包括样式、布局和绘制在内的主线程工作必须在 16.67ms 内完成，以确保滚动和动画流畅。

## 重排与重绘

当 DOM 或 CSSOM 发生变化时，浏览器会重新执行部分流程，以确定需要重新绘制哪些像素。区分这两个术语如下：

| | Reflow | Repaint |
|---|---|---|
| 含义 | 重新计算大小和位置 | 仅重新绘制形状 |
| 几何信息 | 已改变 | 未改变 |
| 后续步骤 | 触发重绘与合成 | 该图层的绘制与合成 |
| 示例 | 添加/删除元素，修改宽度或字体大小 | 更改背景色、字体颜色 |

MDN 指出，一旦发生回流（Reflow），就会随之引发重绘（Repaint）和重新合成。因此，回流的成本更高。上表中的示例是基于“几何信息是否改变”这一定义得出的；关于哪些属性确切属于哪一类，MDN 在此文档中并未提供完整列表，如有需要请另行查阅。

MDN 举出的一个实际案例是图片。如果 `<img>` 标签没有设置 `width` 和 `height`，浏览器会先在不占位的情况下进行布局；当图片加载完成并得知其实际尺寸后，才会从头开始重新布局。若通过属性预先指定尺寸，则位置已确定，无需触发回流。

```html
<!-- 크기 없음: 로딩되면 리플로우 -->
<img src="a.jpg" alt="설명">
<!-- 크기 있음: 자리가 미리 잡힘 -->
<img src="a.jpg" alt="설명" width="800" height="600">
```

## 常见误解

- 渲染树就是 DOM：并非如此。渲染树是从 DOM 中剔除不可见元素后，附加了计算样式的结果。
- `display: none` 和 `visibility: hidden` 效果相同：前者会从渲染树中移除，后者则保留其占用的位置。
- CSS 与解析无关：CSS 不会阻止 HTML 解析，但会阻止脚本读取样式；且渲染树的构建依赖于 CSSOM 的存在。
- 页面显示即意味着已完成：MDN 指出，即使页面看似已加载完成，若主线程正忙于执行大型脚本，仍可能导致滚动和标签页无响应。衡量这一现象的指标是 TTI（Time to Interactive）。
- 不改变尺寸就没有成本：仅更改颜色也会触发重绘，但其成本低于回流。

<details>
<summary>深入解析：通过 JS 查看多次循环的情况</summary>

仅从概念上理解与实际代码行为存在差异。当读写操作混合时，同一事件可能重复发生多次，这是普遍存在的模式。

```js
const items = document.querySelectorAll('.item');

// 읽기와 쓰기를 번갈아 하는 경우
items.forEach((el) => {
  const w = el.offsetWidth;      // 레이아웃 값을 읽음
  el.style.width = (w + 10) + 'px'; // 레이아웃이 바뀜
});

// 읽기를 먼저 몰아서 하고, 쓰기를 나중에 하는 경우
const widths = [...items].map((el) => el.offsetWidth);
items.forEach((el, i) => {
  el.style.width = (widths[i] + 10) + 'px';
});
```

第一种方式会在每次读取值时迫使浏览器更新最新布局，从而导致布局反复执行；第二种方式则是批量读取以减少读取次数。

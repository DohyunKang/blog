10월 7일에 Anthropic이 Claude Haiku 5.5를 냈다. Haiku는 Claude 라인업에서 가장 작고 빠른 모델이고, 이번 발표문은 이걸 "지금까지 낸 작은 모델 중 가장 싸고, 가장 빠르고, 가장 똑똑하다"고 소개한다. 숫자를 하나씩 보니 가격 쪽이 제일 눈에 띄었다.

## 어디에 쓰라는 모델인가

발표문이 꼽은 용도는 요약, 컴팩션, 데이터베이스 쿼리, 분류처럼 양은 많고 건당 단가는 낮아야 하는 일이다. 코딩 에이전트에서는 Opus 5.5나 Sonnet 5.5가 큰 판단을 하고, Haiku 5.5가 서브에이전트로 옆에서 일하는 그림을 든다. 실시간 고객 지원이나 브라우저 조작처럼 응답 속도가 중요한 곳도 언급한다.

모델 개요 문서의 한 줄 설명도 비슷하다. 대량이면서 지연에 민감한 작업, 예를 들면 분류·추출·라우팅. 반대로 복잡한 에이전트 코딩은 Sonnet 5.5나 Opus 5.5가 낫다고 발표문이 직접 말한다.

관련 개념은 따로 정리해 둔 글이 있다. 컴팩션은 [자세히 → 컴팩션과 메모리](#/post/ai-compaction), 서브에이전트는 [자세히 → 서브에이전트와 멀티에이전트](#/post/ai-subagent).

## 스펙

모델 개요 문서에서 읽은 값이다. 문서는 바뀔 수 있어서 2026년 11월 2일에 본 기준으로 적는다.

| 항목 | Claude Haiku 5.5 |
|---|---|
| API 모델 ID | claude-haiku-5-5 |
| 컨텍스트 윈도우 | 1M 토큰 |
| 최대 출력 | 128K 토큰 |
| 지식 기준 시점 | 2026년 6월 |
| 생각(thinking) | 적응형(adaptive) |
| 기본 effort | medium |
| 제공처 | Claude Platform, AWS, Google Cloud, Microsoft Azure |

효과 조절 단계가 있다는 점이 Haiku로서는 처음이라고 한다. 발표문 기준으로 Low, Med, High, Xhigh, Max 다섯 단계다. 작은 모델에도 "얼마나 오래 생각할지"를 정할 수 있게 된 셈이다. 생각 토큰이 뭔지는 [자세히 → 추론 모델과 생각 토큰](#/post/ai-reasoning)에, 창 크기 얘기는 [자세히 → 컨텍스트 윈도우와 토큰](#/post/ai-context-window)에 있다.

## 가격

백만 토큰 기준으로 발표문 표를 옮기면 이렇다. Haiku 5.5는 요청 길이가 10만 토큰 이하일 때와 초과일 때 단가가 다르다.

| 구분 | Haiku 5.5 (10만 이하) | Haiku 5.5 (10만 초과) | Haiku 4.5 | Sonnet 5.5 |
|---|---|---|---|---|
| 입력 | $0.10 | $0.50 | $1.00 | $2.00 |
| 출력 | $0.50 | $2.50 | $5.00 | $10.00 |
| 캐시 읽기 | $0.01 | $0.05 | $0.10 | $0.10 |
| 캐시 쓰기 | $0.125 | $0.625 | $1.25 | $2.50 |

발표문은 Haiku 4.5보다 평균 약 75% 싸게 돈다고 적는다. 각주로는 10만 토큰 이하 요청은 90% 저렴하고 그 이상은 50% 저렴하다고 한다. 새 토크나이저 때문에 같은 일에 토큰을 조금 더 쓰는 편이라는 말도 붙어 있다. 그러니 표의 단가만 비교하면 실제 청구서보다 낙관적으로 나온다.

배치 API는 50% 할인이고, 캐시 읽기는 기본 입력가의 10%라고 모델 개요 문서에 나온다. 캐시가 어떻게 먹히는지는 [자세히 → 프롬프트 캐싱](#/post/ai-prompt-caching)에서 따로 봤다.

<details>
<summary>간단 계산 예시</summary>

요청 1만 건, 건당 입력 2,000토큰·출력 300토큰이라고 가정한다. 전부 10만 이하 구간이고 캐시와 배치는 쓰지 않는다. 토크나이저 차이도 무시한 단순 계산이다.

- 입력 합계 2,000만 토큰, 출력 합계 300만 토큰
- Haiku 5.5: 20 × $0.10 + 3 × $0.50 = $3.50
- Haiku 4.5: 20 × $1.00 + 3 × $5.00 = $35
- Sonnet 5.5: 20 × $2.00 + 3 × $10.00 = $70

같은 일을 Sonnet으로 하던 서비스라면 분류나 요약 단계만 Haiku로 내려도 그 구간 비용은 단가 기준으로 스무 분의 일이 된다. 물론 품질이 받쳐 줘야 의미가 있다.

</details>

## 성능 숫자

발표문에 나온 벤치마크는 Haiku 4.5, GPT-6 Luna, Sonnet 5.5와 같이 놓여 있다. 전부 Anthropic이 발표한 값이다.

| 벤치마크 | Haiku 5.5 | Haiku 4.5 | GPT-6 Luna | Sonnet 5.5 |
|---|---|---|---|---|
| OSWorld 2.1 (오프라인 일부) | 72.4% | 15.7% | 48.9% | 83.9% |
| Humanity's Last Exam (도구 없음) | 45.9% | 10.2% | - | 56.9% |
| Humanity's Last Exam (도구 있음) | 57.4% | 18.7% | - | 64.5% |
| Terminal-Bench 4.0 | 39.2% | 0.0% | 16.4% | 70.6% |
| FrontierCode 1.1 (Main) | 46.4% | - | 42.4% | 52.1% (Xhigh) |

세대 간 차이가 크다. 컴퓨터 조작 벤치마크인 OSWorld가 15.7%에서 72.4%로 올랐고, Terminal-Bench는 4.5의 0.0%에서 39.2%가 됐다. 그래도 터미널 작업은 Sonnet 5.5의 70.6%와 거리가 꽤 있다. 발표문이 복잡한 에이전트 코딩은 큰 모델에 맡기라고 한 이유가 이 칸에서 보인다.

<details>
<summary>고객 사례로 나온 수치</summary>

발표문에 실린 고객 쪽 결과다. 각자 자기 평가 환경에서 잰 값이라 서로 비교하기는 어렵다.

- Asana: 작업 완료 지연이 30% 넘게 줄고, 에이전트 한 턴의 추론이 최대 2.5배 빨라졌다고 한다.
- HubSpot: 자체 CRM 평가에서 세 번 평균 92.8%.
- AlphaSense: 400개 질의에서 0.84, Haiku 4.5는 0.76.
- Box: Haiku 4.5보다 11점 높고 지연은 절반 정도.
- Cognition: Devin Fusion에서 보조 모델로 쓸 때 FrontierCode 66.2.

</details>

## 같이 발표된 것들

Sonnet 5.5의 캐시 읽기 가격이 백만 토큰당 $0.20에서 $0.10으로 내렸다. 대부분의 에이전트 작업에서 비용이 20% 정도 준다는 설명이다. Max, Ultra, Team 구독자에게는 월 API 크레딧이 붙는다고 한다(Max $100, Ultra $200, Team은 합쳐서 최대 $500). 그리고 Python·TypeScript SDK에 컴퓨터 사용과 브라우저 사용 베타 지원이 들어갔다.

## 안전 쪽 얘기

발표문은 Haiku 4.5보다 오정렬 행동이 크게 줄었고 오용 요청에 협조하는 경향도 줄었다고 쓴다. 사이버 보안 안전장치는 Haiku 4.5보다 엄격하고 Sonnet 5.5보다는 느슨한데, 침투 테스트 같은 공격자 관점 기법은 여전히 막는다. 생물학 쪽은 Sonnet 5, Sonnet 5.5, Opus 5와 같은 수준이다. 더 넓은 접근이 필요한 조직은 Life Sciences나 Cyber Verification 프로그램에 신청할 수 있다.

## 읽고 든 생각

작은 모델이 싸진 것보다, 작은 모델이 "서브에이전트·컴팩션·분류" 같은 역할로 명확하게 소개된 게 눈에 들어왔다. 큰 모델 하나로 다 하는 구조에서, 단계마다 모델을 나눠 쓰는 구조로 가라는 신호처럼 읽힌다. 모델이 뭘 하는 물건인지부터 다시 보고 싶으면 [자세히 → LLM이란 무엇인가](#/post/ai-llm)가 있다.

다만 내 작업에서 품질이 충분한지는 직접 돌려 봐야 안다. 벤치마크는 발표한 쪽이 고른 표다.

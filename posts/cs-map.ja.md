```

  네트워크(DNS → TCP → TLS → HTTP)    운영체제(CPU·메모리를 나눠 쓰게 하는 관리자)

```

## 1. コードをどのように分割するか

**手続き型とオブジェクト指向**: 同じ問題をコードで分割する基準が異なります。手続き型は関数（やるべきこと）で、オブジェクト指向はオブジェクト（データとそのデータを扱う動作）で分割します。「どのような順序で行うか」から始めるのか、「このデータを誰が責任を持つか」から始めるのかの違いです。
[詳しく → 手続き型とオブジェクト指向](#/post/cs-procedural-oop)

**SOLID の原則**: オブジェクト指向設計において、コードが変わった際に壊れにくくするための 5 つの基準です。ルール集というより、コードが不自然な時に理由を見つけるためのチェックリストとして読むのが良かったです。
[詳しく → SOLID の原則](#/post/cs-solid)

**デザインパターン**: オブジェクト指向設計で頻繁に出会う問題とその解決策に名前を付けて集めたものです。名前と分類だけ見ると混乱しますが、どのような状況で使用されるかを含めて見れば、それほど混乱しませんでした。
[詳しく → デザインパターン](#/post/cs-design-patterns)

## 2. コードが動く土台

**ネットワークの基礎**: 階層に分けてみると整理できます。アドレスを IP に変換し (DNS)、接続を確立し (TCP)、暗号化を構築し (TLS)、その上でリクエストとレスポンスをやり取りします (HTTP)。この 4 つの段階が順番に起こります。
[詳しく → ネットワークの基礎](#/post/cs-network)

**オペレーティングシステムの基礎**: CPU やメモリといった限られた資源を複数のプログラムで共有できるようにする管理者です。プロセス、スケジューリング、仮想メモリ、同期化は、この一つの仕事を異なる側面から見た名前でした。
[詳しく → オペレーティングシステムの基礎](#/post/cs-os)

## 3. 作る過程

**ソフトウェア工学の基礎**: コードをうまく書く方法よりも、何をどのような順序で作成し、どのように確認し、どのように修正していくかを扱う分野です。手法、要件、UML、テスト、バージョン管理について大きな柱だけを概観しました。
[詳しく → ソフトウェア工学の基礎](#/post/cs-sw-engineering)

**Git**: 変更履歴を蓄えるツールというより、コミットというスナップショットを繋ぎ合わせ、ブランチはその中の一つを指すラベルと考えると、マージ、リベース、衝突が一つの図で整理できます。
[詳しく → Git を正しく知る](#/post/cs-git)

보안은 범위가 넓어서 용어를 따로 보면 서로 어떻게 이어지는지 잘 안 보인다. 그래서 정보보안 시리즈 다섯 편을 한 줄씩만 먼저 적고, 더 알고 싶은 건 아래 링크로 넘어가게 했다. 순서는 바탕이 되는 암호 → 웹에서 뚫리는 곳 → 키 관리 → AI 쪽 위험 → 개인정보 순이다.

## 한눈에 보는 관계

```
암호화·해시·서명 (바탕 도구)
   ├─ 웹 앱은 어디서 뚫리나 ........ 웹 취약점과 OWASP
   ├─ 비밀 값은 어떻게 다루나 ...... 키·시크릿 관리
   ├─ AI가 읽는 글이 명령이 되면 ... 프롬프트 인젝션
   └─ 사람 정보는 어떻게 지키나 .... 개인정보와 데이터 보호
```

## 1. 바탕 도구

**암호화·해시·인증 기초**: 암호화는 숨기고 되돌리는 것, 해시는 되돌리지 않고 같은지만 보는 것, 서명은 누가 만들었고 안 바뀌었는지 확인하는 것이다. 각자 푸는 문제가 달라서 어디에 뭘 쓰는지 갈라 놓으면 TLS까지 한 번에 이어진다.
[자세히 → 암호화·해시·인증 기초](#/post/sec-authn-crypto)

## 2. 웹에서 뚫리는 곳

**웹 취약점과 OWASP**: OWASP Top 10은 웹 앱에서 자주 터지는 위험 범주 목록이다. 그 안의 SQL 인젝션·XSS·CSRF가 왜 되는지 보면 공통 원인이 "데이터가 명령으로 해석되는 것"이고, 글에 간단한 데모 코드로 확인한 내용이 있다.
[자세히 → 웹 취약점과 OWASP](#/post/sec-owasp)

## 3. 비밀 값 다루기

**키·시크릿 관리**: API 키나 DB 비밀번호 같은 시크릿은 완벽하게 숨기기보다, 새는 순간 바로 폐기하고 새로 발급할 수 있게 해 두는 게 핵심이다. 저장, 회전, 최소 권한, 깃에 올라갔을 때 대응을 다룬다.
[자세히 → 키·시크릿 관리](#/post/sec-keys)

## 4. AI 쪽 위험

**프롬프트 인젝션과 AI 보안**: 모델은 지시와 데이터를 구분하지 못해서 읽는 글 속 한 줄이 명령처럼 먹힐 수 있다. 완벽히 막는 방법이 아직 없어서 먹혀도 피해가 작게, 즉 권한을 줄이는 쪽이 방어의 중심이다.
[자세히 → 프롬프트 인젝션과 AI 보안](#/post/sec-prompt-injection)

## 5. 사람 정보 지키기

**개인정보와 데이터 보호**: 개인정보는 이름만이 아니라 다른 정보와 합쳐서 사람을 알아볼 수 있으면 다 해당한다. 그래서 암호화보다 먼저 덜 모으고 짧게 갖고 있는 게 중심이다.
[자세히 → 개인정보와 데이터 보호](#/post/sec-privacy)

## 어떤 순서로 읽을까

| 궁금한 것 | 먼저 볼 글 |
|---|---|
| 암호·해시가 뭐가 다른지 | 암호화·해시·인증 기초 |
| 웹 서비스를 만들고 있다 | 웹 취약점과 OWASP → 키·시크릿 관리 |
| LLM 앱에 도구를 붙인다 | 프롬프트 인젝션과 AI 보안 |
| 사용자 데이터를 받는다 | 개인정보와 데이터 보호 |

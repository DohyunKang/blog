## どんなものか
コードのセキュリティ脆弱性を見つけて、本当に脆弱か確かめて、直すところまでやる OpenAI のツール。Codex の中でプラグインとして使うか、ターミナルで `cs` コマンドとして使うか、TypeScript SDK と GitHub Action で自動化できる。脆弱性は攻撃者に悪用されうるコードの穴のこと。SQL インジェクションや権限チェック漏れなど。

従来のセキュリティスキャナは決まったルール(パターン)に合うコードを探す。これはコーディングエージェントがコードを読みながら調べるやり方だ。エージェントは、モデルがツールを使いながら自分で何段階も進めるプログラム。[詳しく → エージェントとエージェントループ](#/post/ai-agent-loop)

## どう動くか
基本は `cs scan .` の一行。終わるとフォルダに三つのファイルが残る。

- `report.md`: 範囲と見つかった内容を人が読めるようにまとめたレポート
- `findings.json`: 発見ごとのソース位置と根拠
- `scan-manifest.json`: 何をスキャンして何を外したか

範囲はリポジトリ全体、特定パス(`--path`)、コミット差分(`--diff origin/main`)、未コミットの変更(`--working-tree`)から選ぶ。PR レビューなら差分スキャンを使う。

モードは Standard と Deep の二つ。Deep は Standard スキャンを何度も繰り返す。複数のワーカーが同時に調べながら「この場所を見て」とお互いに頼めて、次のバッチは前に見つかったもののタイトルと位置を受け取って別の経路を掘る。新しい発見のないスキャンが何回か続くと止まる(`--stop-after-no-new`)。ドキュメントにあるデフォルトのモデルは `gpt-5.6-sol`、推論の強さは `xhigh` で、親一つに委任ワーカー最大8つまで動く。[詳しく → サブエージェントとマルチエージェント](#/post/ai-subagent)

見つけた後のステップがこのツールの核心に思えた。

- validate: 発見を一つ見直して本物か判定する。このときツールはコードを読むだけで、ネットワークとウェブ検索はオフ。
- patch: 発見を直すパッチを作り、必要なら下書き PR まで作る。パッチのリスク評価も付けられる。
- verify-fix: 直した後にもう一度見て、fixed、still_vulnerable、inconclusive のどれかで答える。終了コードも0、1、2に分かれていて CI に組み込みやすい。

レポートに「どこまで見たか」を別に残すのも目についた。ドキュメントには、スキャン完了は作業が終わったという意味で、すべてのファイルとすべての脆弱性を見たという意味ではないと書いてある。外したパス、後回しにした作業、残った質問が記録される。

ほかに `SECURITY.md` の下書き、脅威モデルの保存、Semgrep・Snyk・Wiz など他のスキャナ結果の取り込み、Linear・Jira・GitHub への送信、SARIF・JSON・CSV の書き出しがある。脅威モデルは「誰がどこを攻撃できるか」をまとめた文書。

## 入門者の目線で
PM としては、「見つけた」「確かめた」「直した」を段階ごとに分けているのがいい。AI の結果をそのまま信じず、根拠と範囲を一緒に残す設計なので報告を受けやすそう。開発入門者なら、小さなリポジトリで PR ごとに `cs scan . --diff origin/main` をかけるくらいから始めればよさそう。GitHub Action の例はスキャン一回あたり見積もり上限5ドルで、進行中のリクエストは上限を超えることがあると書いてある。

注意点。ログインか API キーが必要で、モデルの利用料がかかる。一部のセキュリティ依頼や保護された発見には OpenAI の Trusted Access for Cyber の承認が要る。Bedrock、OpenRouter、Fireworks AI など他のプロバイダも使えるらしい。実際の検出精度の数字は確認できず。リポジトリに evals フォルダはあったが結果は読んでいない。スキルで分かれた構成が気になるならこの記事も。[詳しく → スキル](#/post/ai-skills)

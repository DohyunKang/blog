분석 방법론은 분석 프로젝트를 어떤 단계로, 어떤 산출물을 남기며 진행할지 정해 둔 틀이고, ADsP에서는 KDD, CRISP-DM, 계층적 프로세스, 상향식·하향식 접근이 한 묶음으로 나온다.

## 방법론이 왜 필요한가

분석은 데이터를 받아서 모델 하나 돌리면 끝나는 일이 아니다. 목표를 정하고, 데이터를 모으고, 다듬고, 분석하고, 쓸 수 있게 만들고, 결과를 평가하는 일이 줄줄이 붙는다. 이 순서와 산출물을 미리 정해 두면 사람이 바뀌어도 같은 방식으로 일할 수 있다. 방법론은 그걸 문서로 만든 것이다.

시험에서는 크게 네 덩어리로 나뉜다고 보면 편하다.

| 덩어리 | 핵심 질문 |
|---|---|
| KDD | 데이터에서 지식을 뽑는 전체 과정은 어떤 5단계인가 |
| CRISP-DM | 데이터 마이닝 프로젝트의 6단계는 무엇이고 어디로 되돌아가나 |
| 계층적 프로세스 | 단계, 태스크, 스텝은 각각 무엇인가 |
| 상향식·하향식 | 분석 과제를 어디서부터 찾아 들어가나 |

과제를 고르는 쪽 얘기는 [자세히 → 분석 기획의 이해](#/post/adsp-planning)에 있고, 고른 뒤 우선순위를 정하는 건 [자세히 → 분석 과제와 마스터플랜](#/post/adsp-task-masterplan)에서 다룬다.

## KDD: 다섯 단계

KDD는 Knowledge Discovery in Databases의 약자다. 대량의 데이터에서 유용한 지식을 찾아내는 전체 과정을 가리키고, 데이터 마이닝은 그 과정 안의 한 단계다. 이 구분이 자주 헷갈린다. 데이터 마이닝이 KDD 전체가 아니라 4번째 단계라는 점을 기억하면 된다. 단계 구성은 Fayyad 등(1996)을 인용한 설명을 따른다.

| 순서 | 단계 | 하는 일 |
|---|---|---|
| 1 | 선택 | 분석 목적에 맞는 자료를 골라 목표 데이터셋을 만든다 |
| 2 | 전처리 | 누락된 값과 잡음을 다듬는다 |
| 3 | 변환 | 분석하기 좋은 형태로 바꾸고 변수 수를 줄인다 |
| 4 | 데이터 마이닝 | 알고리즘을 적용해 숨은 패턴을 찾는다 |
| 5 | 해석·평가 | 찾은 패턴이 의미 있는지 검토하고 지식으로 정리한다 |

5단계에서 기준에 못 미치면 전처리와 마이닝 단계로 다시 돌아간다. 한 줄로 흐름을 외우려면 "선택, 전처리, 변환, 마이닝, 해석"이다. 데이터 마이닝 단계에서 쓰는 기법(분류, 군집, 연관분석)은 [자세히 → 정형 데이터 마이닝](#/post/adsp-datamining)에서 따로 정리했다.

## CRISP-DM: 여섯 단계

CRISP-DM은 Cross-Industry Standard Process for Data Mining의 약자다. 1996년에 구상되어 EU의 ESPRIT 지원 프로젝트로 이어졌고, 1999년 3월 브뤼셀 워크숍에서 첫 버전이 발표된 뒤 같은 해 단계별 가이드로 나왔다. 여러 설문에서 데이터 마이닝 하는 사람들이 가장 많이 쓴다고 답한 방법론이기도 하다.

| 순서 | 단계 | 주요 태스크 |
|---|---|---|
| 1 | 업무 이해(Business Understanding) | 업무 목적 파악, 상황 파악, 데이터 마이닝 목표 설정, 프로젝트 계획 수립 |
| 2 | 데이터 이해(Data Understanding) | 초기 데이터 수집, 데이터 기술 분석, 데이터 탐색, 데이터 품질 확인 |
| 3 | 데이터 준비(Data Preparation) | 분석용 데이터셋 선택, 정제, 편성, 통합, 포맷팅 |
| 4 | 모델링(Modeling) | 모델링 기법 선택, 테스트 계획 설계, 모델 작성, 모델 평가 |
| 5 | 평가(Evaluation) | 분석 결과 평가, 모델링 과정 평가, 모델 적용성 평가 |
| 6 | 전개(Deployment) | 전개 계획, 모니터링·유지보수 계획, 종료 보고서 작성, 프로젝트 리뷰 |

KDD와 나란히 놓으면 대응이 보인다. KDD의 선택·전처리·변환이 CRISP-DM에서는 데이터 준비 한 단계로 묶이고, CRISP-DM에는 앞에 업무 이해가 있고 뒤에 전개가 붙는다. 다만 두 방법론의 단계가 정확히 일대일로 맞는 건 아니라서, 표를 억지로 맞춰 외우기보다 각각의 단계 이름과 순서를 따로 아는 편이 안전하다.

### 순서가 고정이 아니다

CRISP-DM에서 제일 많이 나오는 포인트가 이거다. 단계는 번호 순서대로 한 방향으로만 흐르지 않는다. 단계 사이를 오가는 게 보통이고, 모델링 중에 데이터가 부족하다는 걸 알면 데이터 이해나 준비로 돌아간다. 평가 결과가 미흡하면 업무 이해로 돌아간다. 전개가 끝난 뒤에도 거기서 얻은 교훈이 새로운 질문을 만들어 다음 프로젝트로 이어진다. 그림으로는 단계들을 둘러싼 바깥 원이 이 순환을 나타낸다.

<details>
<summary>자세한 풀이: CRISP-DM의 4단계 계층</summary>

CRISP-DM은 스스로를 계층 구조로 설명한다. 맨 위가 단계(Phase), 그 아래가 일반화 태스크(Generic Task), 그 아래가 세분화 태스크(Specialized Task), 마지막이 프로세스 실행(Process Instance)이다. 일반화 태스크는 어떤 프로젝트에나 통하게 쓴 이름이고, 세분화 태스크는 실제 상황에 맞게 구체화한 것이다. 위 표의 "주요 태스크"가 일반화 태스크 수준이다.

시험 준비에서는 단계 6개와 각 단계의 대표 태스크 한두 개를 말할 수 있으면 충분하다. 세분화 태스크 이하는 이름 정도만 알아 둔다.

</details>

## 계층적 프로세스: 단계, 태스크, 스텝

국내 교재에서 말하는 빅데이터 분석 방법론은 단계(Phase), 태스크(Task), 스텝(Step)이라는 세 계층으로 구성된다. 정의가 비슷해 보여서 구분 문제가 나온다.

| 계층 | 정의 |
|---|---|
| 단계 | 최상위 계층. 완성된 산출물을 기준선으로 잡고 버전 관리로 통제한다 |
| 태스크 | 단계를 이루는 단위 활동. 품질 검토의 대상이 된다 |
| 스텝 | WBS의 워크 패키지에 해당하는 단위 프로세스. 입력, 처리 및 도구, 출력으로 이뤄진다 |

스텝이 입력·처리 및 도구·출력을 갖는다는 점은 단골이다. 태스크의 정의를 이렇게 쓴 선택지는 틀린 쪽이다.

이 방법론의 5단계와 대표 산출물은 아래와 같다. 순서가 중요하다. 분석 기획이 맨 앞이고, 시스템 구현이 평가 및 전개보다 앞선다.

| 순서 | 단계 | 주요 태스크 | 대표 산출물 |
|---|---|---|---|
| 1 | 분석 기획 | 비즈니스 이해 및 범위 설정, 프로젝트 정의 및 계획 수립, 프로젝트 위험 계획 수립 | 프로젝트 범위 정의서(SOW), 프로젝트 계획서 |
| 2 | 데이터 준비 | 필요 데이터 정의, 데이터 스토어 설계, 데이터 수집 및 정합성 점검 | 데이터 정의서, 데이터 스토어 |
| 3 | 데이터 분석 | 분석용 데이터 준비, 텍스트 분석, 탐색적 분석, 모델링, 모델 평가 및 검증 | 분석용 데이터셋, 모델 평가 보고서 |
| 4 | 시스템 구현 | 설계 및 구현, 시스템 테스트 및 운영 | 시스템 설계서, 운영 매뉴얼 |
| 5 | 평가 및 전개 | 모델 발전 계획 수립, 프로젝트 평가 및 보고 | 모델 발전 계획서, 최종 보고서 |

CRISP-DM의 업무 이해, 데이터 이해·준비, 모델링, 평가, 전개와 이름은 다르지만 훑어 보면 같은 흐름이다. 데이터 이해 쪽 개념이 약하면 [자세히 → 데이터의 이해](#/post/adsp-data-understanding)부터 보는 게 낫다.

## 상향식과 하향식

분석 과제를 어디서 찾느냐에 따른 구분이다.

| 구분 | 출발점 | 어울리는 상황 |
|---|---|---|
| 하향식 | 기업 목표나 현안에서 문제를 쪼개 과제를 도출 | 해결할 비즈니스 문제가 비교적 분명할 때 |
| 상향식 | 가진 데이터에서 출발해 패턴·관계로 새 과제를 찾음 | 문제가 무엇인지 아직 모를 때 |

실무에서는 두 방식을 섞어 쓰는 경우가 많다고 설명된다.

### 하향식 4단계

문제 탐색, 문제 정의, 해결방안 탐색, 타당성 검토 순서다.

| 단계 | 하는 일 |
|---|---|
| 문제 탐색 | 경영목표, 업무 프로세스, 고객 요구, 시장환경을 검토해 해결할 문제나 분석 기회를 찾는다. 기업 전체 관점이 중요하다 |
| 문제 정의 | 비즈니스 문제를 데이터 문제로 바꾼다. 예를 들면 "고객 이탈 증가"를 "이탈 가능성이 높은 고객 예측"으로 바꾸는 식이다 |
| 해결방안 탐색 | 분석 기법, 시스템, 인력 확보 방안을 검토한다. 기존 시스템 활용 여부와 분석 역량 보유 여부의 조합으로 방안이 갈린다 |
| 타당성 검토 | 비용 대비 편익 같은 경제적 타당성과 데이터·기술적 타당성을 평가해 과제를 확정한다 |

문제 탐색에서 쓰는 방법은 내부 업무를 보는 비즈니스 모델 기반 방식과, 타사 사례를 참고하는 외부 참조 모델 기반 방식이 있다. 벤치마킹은 외부 참조 모델 쪽이다. 이걸 내부 쪽으로 바꿔 놓은 보기가 틀린 선택지로 자주 나온다.

### 상향식

탐색적 데이터 분석으로 데이터의 특징을 훑고, 군집이나 연관 규칙 같은 비지도 학습으로 숨은 패턴을 찾고, 프로토타이핑으로 시행착오를 반복하면서 문제 자체를 정의해 간다. 프로토타이핑은 가설 생성, 실험, 실제 환경 테스트, 결과 확인을 되풀이하는 방식을 가리킨다.

## 자주 나오는 유형과 풀이 방식

기출 문장을 옮기지는 않고, 어떤 모양으로 물어보는지만 정리한다.

- 단계 순서 맞히기: KDD 5단계, CRISP-DM 6단계, 5단계 방법론의 순서를 섞어 놓고 고르게 한다. 각 방법론 첫 단계와 마지막 단계만 정확히 알아도 소거가 된다. KDD는 선택으로 시작해 해석·평가로 끝나고, CRISP-DM은 업무 이해로 시작해 전개로 끝난다.
- 단계별 활동 연결하기: "데이터 품질 확인"이 데이터 이해인지 데이터 준비인지 같은 문제다. 품질을 살펴보는 건 이해, 고치고 합치는 건 준비로 가른다.
- 계층 정의 구분: 단계, 태스크, 스텝 정의가 서로 뒤바뀐 보기를 찾는다. 스텝은 입력·처리·출력, 태스크는 단계를 이루는 단위 활동으로 기억한다.
- 접근법 구분: 문제가 정해져 있으면 하향식, 데이터부터 보면 상향식. 비지도 학습이 나오면 상향식 쪽이다.
- 틀린 설명 고르기: 순서가 고정이라거나, 데이터 마이닝이 KDD 전체라는 식의 문장이 오답이 된다.

## 흔한 오해

- CRISP-DM은 한 번 지나가면 끝나는 직선 절차다: 단계 사이를 오가는 게 기본이고, 전개 뒤에도 다음 질문으로 이어진다.
- 데이터 마이닝과 KDD는 같은 말이다: 마이닝은 KDD의 한 단계다.
- 계층적 프로세스의 태스크와 스텝은 같은 말이다: 스텝이 더 작은 단위이고, 입력·처리·출력을 갖는다.
- 상향식은 하향식보다 낫거나 못하다: 문제가 보이는지에 따라 고르고, 섞어 쓰기도 한다.

<details>
<summary>자세한 풀이: 같은 일을 세 방법론으로 놓고 보기</summary>

예를 들어 쇼핑몰의 이탈 고객을 줄이는 프로젝트가 있다고 하자. 같은 일을 세 가지 틀로 읽으면 이렇다.

KDD로 읽으면, 구매 이력에서 필요한 컬럼을 골라(선택), 빈 값과 이상한 기록을 정리하고(전처리), 변수를 합치거나 줄이고(변환), 이탈을 예측하는 알고리즘을 돌리고(마이닝), 나온 패턴이 정말 의미 있는지 해석한다.

CRISP-DM으로 읽으면, 먼저 이탈을 줄인다는 업무 목표와 데이터 마이닝 목표를 따로 적고(업무 이해), 가진 데이터를 훑어 품질을 본 뒤(데이터 이해), 분석용 데이터셋을 만들고(데이터 준비), 모델을 만들고 평가하고(모델링), 결과가 업무 목표에 맞는지 다시 본다(평가). 맞으면 운영에 붙이고 모니터링 계획을 세운다(전개). 평가에서 목표와 어긋나면 업무 이해로 돌아간다.

5단계 방법론으로 읽으면, 범위 정의서와 계획서를 쓰고(분석 기획), 필요한 데이터를 정의해 모으고(데이터 준비), 분석용 데이터셋과 모델 평가 보고서를 만들고(데이터 분석), 시스템에 구현해 운영하고(시스템 구현), 최종 보고서와 모델 발전 계획서로 마무리한다(평가 및 전개).

세 틀은 이름만 다르고 데이터를 준비하고 모델을 만들어 평가한 뒤 쓴다는 줄기는 같다.

</details>

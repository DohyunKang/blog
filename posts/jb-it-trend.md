신기술 용어 단원은 범위가 정해져 있지 않아서 제일 막막하다. 클라우드, 빅데이터, AI, 블록체인, IoT가 한 문제에 보기로 같이 나오기도 한다. 이 단원은 깊이 이해하기보다 "이 용어는 어떤 문제를 풀려고 나왔나"를 한 줄로 붙여 두는 쪽이 효율이 좋다. 시험 일정·응시료는 공식 사이트에서 확인하고, 여기서는 개념과 문제 푸는 방식만 정리한다.

## 먼저 큰 그림

| 묶음 | 대표 용어 | 풀려는 문제 |
|---|---|---|
| 인프라 | 클라우드, 가상화, 컨테이너 | 서버를 사고 설치하는 시간·비용 |
| 데이터 | 빅데이터, NoSQL, 데이터 레이크 | 기존 DB로 담기 어려운 많고 다양한 데이터 |
| 지능 | 인공지능, 머신러닝, 딥러닝 | 규칙을 사람이 일일이 짜기 어려운 판단 |
| 신뢰 | 블록체인 | 중앙 기관 없이 기록을 믿게 하기 |
| 연결 | IoT, 5G, 엣지 컴퓨팅 | 사물에서 나오는 데이터를 가까이서 빨리 처리 |

문제에서는 보통 정의 문장을 주고 용어를 고르게 한다. 그래서 용어 이름보다 정의 문장의 핵심 단어를 같이 기억해 두는 게 낫다.

## 클라우드 컴퓨팅

클라우드의 정의로 가장 많이 인용되는 건 미국 NIST의 정의다. 공유된 컴퓨팅 자원(네트워크, 서버, 저장소, 애플리케이션, 서비스)을 어디서나 필요할 때 네트워크로 가져다 쓰고, 최소한의 관리로 빌리고 반납할 수 있는 모델이라고 한다. 이 정의에는 특징 5개, 서비스 모델 3개, 배포 모델 4개가 붙어 있다.

[자세히 → 클라우드 기초](#/post/cloud-basics)

### 필수 특징 5개

| 특징 | 한 줄 |
|---|---|
| 주문형 셀프서비스 | 사람 손을 거치지 않고 사용자가 알아서 자원을 할당받는다 |
| 광범위한 네트워크 접근 | 표준 방식으로 네트워크를 통해 여러 종류의 단말에서 접근한다 |
| 자원 풀링 | 제공자의 자원을 여러 고객이 나눠 쓰고(멀티테넌트), 수요에 따라 배정이 바뀐다 |
| 빠른 탄력성 | 수요에 맞게 빠르게 늘리고 줄인다 |
| 측정 가능한 서비스 | 사용량을 재서 통제·보고하고, 보통 쓴 만큼 낸다 |

늘었다 줄었다 하는 쪽은 오토스케일링과 연결해서 보면 이해가 빠르다. [자세히 → 오토스케일링](#/post/infra-autoscaling)

### 서비스 모델 3개

세 모델은 "고객이 어디까지 관리하느냐"로 구분한다.

| 모델 | 고객이 쓰는 것 | 고객이 관리하는 것 | 예 |
|---|---|---|---|
| IaaS | 서버·저장소·네트워크 같은 기본 자원 | OS, 저장소, 배포한 앱 | 가상 서버 빌려 쓰기 |
| PaaS | 앱을 올려 돌리는 개발·실행 환경 | 배포한 앱과 환경 설정 | 코드만 올리면 돌아가는 플랫폼 |
| SaaS | 제공자가 만든 완성된 애플리케이션 | 사용자별 설정 정도 | 웹 메일 |

IaaS, PaaS, SaaS 순으로 고객이 관리할 범위가 줄어든다. 문제에서 "OS까지 직접 관리"가 나오면 IaaS, "애플리케이션만 올림"이면 PaaS, "브라우저로 쓰기만 함"이면 SaaS로 거의 정리된다.

### 배포 모델 4개

| 모델 | 한 줄 |
|---|---|
| 프라이빗 | 한 조직만 쓰도록 구성한 클라우드 |
| 커뮤니티 | 보안 요구나 규정처럼 공통 관심사가 있는 여러 조직이 같이 쓴다 |
| 퍼블릭 | 일반 대중이 쓸 수 있게 열어 둔 클라우드 |
| 하이브리드 | 둘 이상의 클라우드를 표준·고유 기술로 묶어 데이터와 앱을 옮길 수 있게 한 것 |

<details>
<summary>시험에서 헷갈리는 짝</summary>

- 프라이빗과 온프레미스는 같은 말이 아니다. NIST 정의상 프라이빗 클라우드는 조직 안에 있어도, 제3자가 운영하는 외부에 있어도 된다.
- 퍼블릭은 "대중이 쓴다"가 핵심이고, 하이브리드는 "둘 이상을 묶었다"가 핵심이다.
- 서버리스는 서버가 없다는 뜻이 아니라 서버 관리를 제공자가 맡는다는 뜻으로 쓴다. [자세히 → 서버리스](#/post/cloud-serverless)

</details>

## 가상화와 컨테이너

가상화는 물리 서버 한 대 위에 여러 대의 가상 서버를 올리는 기술이다. 가상 서버마다 OS가 따로 돈다. 컨테이너는 OS 커널을 같이 쓰면서 애플리케이션과 그 실행에 필요한 것만 묶어 격리하는 방식이라, 가상 서버보다 가볍게 뜬다고 설명하는 게 일반적이다. 이 차이는 OS 단원의 프로세스·커널 개념과 이어진다. [자세히 → 운영체제](#/post/jb-os)

컨테이너가 많아지면 배치, 재시작, 교체를 자동으로 해 줄 도구가 필요한데, 그 역할을 하는 게 쿠버네티스다. 쿠버네티스 공식 문서는 컨테이너화된 워크로드와 서비스를 관리하는 이식성 있는 오픈소스 플랫폼이라고 소개한다. 기능으로는 서비스 디스커버리와 로드 밸런싱, 응답 없는 컨테이너를 되살리는 셀프 힐링, 원하는 상태를 선언하면 실제 상태를 맞춰 가는 자동 롤아웃·롤백이 나온다. [자세히 → 도커와 컨테이너](#/post/cloud-docker)

## 블록체인

블록체인은 비트코인 논문에서 시작했다. 논문은 은행 같은 신뢰 기관 없이 당사자끼리 바로 돈을 보내려면 이중 지불을 막아야 하는데, 이걸 P2P 네트워크로 풀겠다고 제안한다. 거래를 해시로 묶어 작업 증명(proof-of-work)이 이어진 사슬로 타임스탬프를 찍고, 이 사슬은 작업 증명을 다시 하지 않고는 바꿀 수 없다. 노드들은 가장 긴 사슬을 정답으로 받아들인다.

시험용으로 줄이면 이렇다.

| 용어 | 한 줄 |
|---|---|
| 블록 | 거래 묶음과 이전 블록의 해시를 담은 단위 |
| 작업 증명 | 연산 작업을 해냈다는 걸 보여 사슬에 블록을 잇는 방식 |
| 분산 원장 | 한 곳이 아니라 참여 노드들이 같은 기록을 나눠 갖는 구조 |
| 이중 지불 | 같은 돈을 두 번 쓰는 것 |

해시와 암호 개념은 보안 단원과 겹친다. [자세히 → 정보 보안](#/post/jb-security)

## 데이터와 AI 용어

이 묶음은 문제에서 정의를 묻는 방식이 대부분이라 표로 정리해 둔다.

| 용어 | 한 줄 |
|---|---|
| 빅데이터 | 기존 방식으로 저장·처리·분석하기 어려울 만큼 크고 다양하고 빠르게 생기는 데이터 |
| NoSQL | 관계형 표 모델이 아닌 방식(키-값, 문서 등)으로 데이터를 다루는 DB |
| 데이터 웨어하우스 | 분석용으로 정리해서 쌓아 둔 통합 저장소 |
| 데이터 레이크 | 정리하지 않은 원본 데이터를 그대로 쌓아 두는 저장소 |
| 인공지능 | 사람의 지능이 하는 일을 컴퓨터가 하게 하는 기술의 총칭 |
| 머신러닝 | 규칙을 직접 짜지 않고 데이터에서 패턴을 학습하게 하는 방식 |
| 딥러닝 | 여러 층의 신경망으로 학습하는 머신러닝의 한 갈래 |
| 생성형 AI | 글·이미지 같은 새 결과물을 만들어 내는 AI |

포함 관계는 인공지능 안에 머신러닝, 그 안에 딥러닝이다. 이 순서를 거꾸로 묻는 보기가 자주 나온다. 요즘 LLM 얘기는 AI 용어사전 쪽에 따로 정리해 뒀다. [자세히 → LLM](#/post/ai-llm), [자세히 → 생성형 AI](#/post/ai-generative), [자세히 → NoSQL](#/post/db-nosql)

## 연결 기술

| 용어 | 한 줄 |
|---|---|
| IoT | 사물에 센서와 통신 기능을 붙여 인터넷으로 연결하고 데이터를 주고받는 것 |
| 엣지 컴퓨팅 | 데이터가 생기는 곳 가까이에서 처리해서 먼 데이터센터로 가는 양과 지연을 줄이는 방식 |
| 5G | 이동통신 세대 중 하나로, 많은 기기를 연결하고 지연을 줄이는 쪽을 강조한다 |

네트워크 쪽 기본기는 별도 단원에 있다. [자세히 → 네트워크](#/post/jb-network)

## 문제 푸는 방식

1. 보기에 용어 이름이 영어 약자면 풀어 쓴 이름부터 떠올린다. IaaS는 Infrastructure as a Service, 이런 식이다.
2. 정의 문장에서 핵심 단어를 찾는다. "관리 범위", "중앙 기관 없이", "원본 그대로" 같은 말이 답을 가른다.
3. 비슷한 쌍은 차이 한 줄로 정리해 둔다. 웨어하우스와 레이크, 프라이빗과 퍼블릭, 머신러닝과 딥러닝이 대표적이다.
4. 새 용어는 해마다 바뀔 수 있으니 기출보다 최근 공식 출제 기준과 교재의 용어 목록을 같이 본다. 기출 원문은 베끼지 않고 개념으로 다시 정리해 두는 편이 오래 남는다.

<details>
<summary>외울 때 쓴 짝 만들기</summary>

- IaaS는 "집터", PaaS는 "집 짓는 공방", SaaS는 "완성된 집"으로 놓으면 관리 범위가 눈에 들어온다.
- 블록체인은 "공용 장부, 한 장 찢으면 뒷장이 다 어긋나는 장부"로 떠올리면 해시 연결이 기억난다.
- 컨테이너는 "OS를 같이 쓰는 이삿짐 박스", 가상 서버는 "집 한 채를 통째로 쪼갠 것".

</details>

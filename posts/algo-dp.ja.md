DP は、大きな問題を小さな問題に分割し、同じ小さな問題を二度解かないように答えを記録して再利用する方法です。コードよりも「小さな問題をどのように定義し、互いにどうつなげるか」を決めることがほとんど全てでした。

## DP とは何か

名前は難しく聞こえますが、行うことは単純です。ウィキペディアの説明によると、リチャード・ベルマンが 1950 年代初頭に RAND で考案した用語であり、大きな決定問題の中に小さな決定問題が重なり合っている構造を解く方法を指します。名称の「programming」はコーディングではなく、「表（計画）を埋める」という意味に近いです。

DP が成立するには二つの条件が必要です。

| 条件 | 意味 | 例 |
|---|---|---|
| 最適部分構造 | 大きな問題の最適解が、小さな問題の最適解から構成される | 最短経路の一部もまた最短経路である |
| 部分問題の重複 | 同じ小さな問題が何度も再帰的に現れる | fib(5) を求めると fib(2) が複数回呼び出される |

二つ目の条件がない場合は単なる分割統治法であり、一つ目の条件がない場合は DP で解けません。重複がある場合、一度だけ計算するようにするのが DP の利点です。

## 二つの実装方法

フィボナッチ数列で考えると最も簡単です。単純に再帰で書くと同じ値を何度も計算するため、n が大きくなると使えません。これを二つの方法で修正します。

- メモ化 (top-down): 再帰はそのままにし、一度求めた値は保存しておき、次に必要な時に読み出します。
- テーブル法 (bottom-up): 小さなものから始めてループで表を埋めていきます。

```python
from functools import lru_cache

def fib_memo(n):
    @lru_cache(None)
    def f(k):
        return k if k < 2 else f(k - 1) + f(k - 2)
    return f(n)

def fib_tab(n):
    dp = [0, 1] + [0] * max(0, n - 1)
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_memo(50), fib_tab(50))  # 12586269025 12586269025
```

コーディングテストでは通常、テーブル法を使います。再帰の深さ制限（Python のデフォルトは約 1000）を気にする必要がないためです。ただし、実際に必要な状態がわからない場合はメモ化の方が使いやすかったです。必要なものだけを計算するからです。

## 解法の思考順序

問題をみて DP かどうかがわかったら、この順序で書いてみました。

1. 状態の定義: `dp[i]` が何を意味するかを一文で書きます。ここで詰まると後がすべて詰まります。
2. 漸化式: `dp[i]` をより小さな状態からどのように作るかを書きます。
3. 初期値: 漸化式が依存する最小の値（`dp[0]` など）を決定します。
4. 計算順序: 漸化式が参照する値が先に埋められるように順序を決めます。
5. 答えの位置: `dp[n]` が答えなのか、表全体の最大値が答えなのか確認します。

「この問題は DP か？」は通常、「最大値・最小値・場合の数を問う問題で、先ほどの選択が後に影響を与える」という感覚で気づきます。完全探索が指数関数的に爆発するが状態数が少ない場合は DP を疑います。

## 代表的な問題 1: バックパック (0/1 knapsack)

プログラ머스「泥棒」（動的計画法）は、同じ「盗むか盗まないか」の構造を持つ問題です。各家に金があり、隣接する家は同時に盗めない場合、盗める最大金額を求めます。制約が「重量合計」ではなく「隣接禁止」であるため漸化式は異なりますが、品物ごとに取るか捨てるかを定め価値を最大化するという骨子は同じです。以下は古典的な 0/1 バックパック問題（各品物に重量と価値があり、重量合計が K 以下になるように選び、価値合計を最大化する）の解法です。

- 状態: `dp[c]` = 重量制限 c の場合、得られる最大価値
- 漸化式: 品物 (w, v) を入れると `dp[c] = max(dp[c], dp[c-w] + v)`
- 注意: 同じ品物を二回使うことができないため、c は大きい方から小さい方へ順に回します。

```python
def knapsack(items, cap):
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(cap, w - 1, -1):   # 거꾸로 돌아야 한 물건을 한 번만 쓴다
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]

print(knapsack([(6, 13), (4, 8), (3, 6), (5, 12)], 7))  # 14
```

時間 O(N·K)、空間 O(K)。逆に c を小さい方から大きい方へ回すと、品物を複数回使える無制限バックパックになります。方向一つで問題の種類が変わることに驚きました。

## 代表的な問題 2: 最長増加部分列 (LIS)

プログラ머스「整数三角形」（動的計画法）は、「i 番目で終わる経路の最大値」のように、終点位置を状態として捉える練習になります。以下は古典的な LIS 問題（数列から順序を保ちながら選んだ増加する数列の中で最も長い長さを求める）の解法です。

- 状態: `dp[i]` = i 番目の要素で終わる最長増加部分列の長さ
- 漸化式: `dp[i] = max(dp[j] + 1)` (j < i かつ a[j] < a[i])、存在しない場合は 1
- 答え: `dp` 全体の最大値。最後の要素が答えではない点を頻繁に見落としてしまいます。

```python
import bisect

def lis_n2(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

def lis_fast(a):
    tails = []
    for x in a:
        p = bisect.bisect_left(tails, x)
        if p == len(tails):
            tails.append(x)
        else:
            tails[p] = x
    return len(tails)

print(lis_n2([10, 20, 10, 30, 20, 50]), lis_fast([10, 20, 10, 30, 20, 50]))  # 4 4
```

O(N²) の解法は時間 O(N²)、空間 O(N)。N が 100 万のように大きい場合は上記の `lis_fast` が必要で、これは O(N log N) です。ウィキペディアの LIS ドキュメントも、二分探索を使う O(n log n) アルゴリズムを説明しています。`tails[k]` は「長さ k+1 の増加数列の末尾値の中で最も小さい値」であり、この配列は常にソートされているため二分探索が可能になります。注意すべき点は `tails` 自体が実際の LIS ではないことです。長さだけが合っています。

<details>
<summary>lis_fast が正しい理由 (折りたたみ)</summary>

新しい要素 x を見たとき、`tails` から x 以上である最初の列を探します。

- 그런 칸이 없으면 x가 가장 긴 수열 뒤에 붙을 수 있으니 길이가 1 늘어난다.
- 있으면 그 길이의 끝값을 x로 바꾼다. 끝값이 작을수록 뒤에 더 많은 수가 붙을 수 있어서 손해가 없다.

`bisect_left`를 쓰는 이유는 같은 값이 나왔을 때 "증가"(엄격하게 커야 함)를 유지하려는 것이다. 같거나 커도 되는 비감소 수열이면 `bisect_right`를 쓴다. 임의 배열 300개로 `lis_n2`와 `lis_fast`가 같은 길이를 내는지 돌려 확인했다.
</details>

## 대표 문제 3: 동전 (최소 개수)

프로그래머스 "거스름돈"은 같은 동전 구조인데 최소 개수 대신 경우의 수를 센다. 아래 문제는 동전 종류가 주어지고, 합이 k가 되는 최소 동전 개수를 구한다(불가능하면 -1).

- 상태: `dp[i]` = 합 i 를 만드는 최소 동전 수
- 점화식: `dp[i] = min(dp[i - c] + 1)` (모든 동전 c)
- 초기값: `dp[0] = 0`, 나머지는 아주 큰 값

```python
def coin(coins, k):
    INF = 10**9
    dp = [0] + [INF] * k
    for i in range(1, k + 1):
        for c in coins:
            if i >= c and dp[i - c] + 1 < dp[i]:
                dp[i] = dp[i - c] + 1
    return dp[k] if dp[k] < INF else -1

print(coin([1, 5, 12], 15), coin([2], 3))  # 3 -1
```

시간 O(k × 동전 종류 수), 공간 O(k). 동전 [1, 5, 12]로 15 를 만들 때 큰 동전부터 쓰는 그리디는 12+1+1+1 로 4 개지만, 답은 5+5+5 로 3 개다. 그리디가 안 되고 DP 가 필요한 전형적인 예라서 [그리디](#/post/algo-greedy) 와 같이 보면 구분이 된다.

<details>
<summary>보너스: LCS (두 문자열의 최장 공통 부분 수열)</summary>

프로그래머스 "등굣길"(동적계획법)처럼 2 차원 표를 채우는 유형이다. LCS 도 2 차원 표를 쓴다. `dp[i][j]` 는 a 의 앞 i 글자와 b 의 앞 j 글자의 LCS 길이이고, 두 글자가 같으면 `dp[i-1][j-1] + 1`, 다르면 `max(dp[i-1][j], dp[i][j-1])`.

```python
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("ACAYKP", "CAPCAK"))  # 4
```

시간·공간 O(N·M). 한 줄만 쓰는 식으로 공간을 O(M) 까지 줄일 수 있다.
</details>

## 복잡도를 어떻게 보나

DP 의 시간은 대체로 (상태 수) × (상태 하나를 계산하는 데 드는 전이 수) 다. 배낭은 상태 K 개 × 물건 N 번, 동전은 상태 k 개 × 동전 종류 수. 이걸로 "이 풀이가 제한 시간 안에 되나" 를 먼저 어림한다. 공간은 점화식이 바로 앞 몇 칸만 보면 배열 전체 대신 몇 개 변수로 줄일 수 있다. 위키피디아 피보나치 예시도 필요한 값만 들고 있으면 공간을 상수로 줄일 수 있다고 적고 있다.

## 흔한 실수

- 상태 정의가 모호하다: "dp[i] 는 i 까지의 답"이라고만 쓰면 점화식이 안 나온다. "i 번째로 끝나는", "정확히 i 원을 만드는"처럼 조건을 박아야 했다.
- 초기값을 빼먹는다: 최솟값 문제는 INF, 경우의 수는 `dp[0] = 1`처럼 문제에 맞는 값이 따로 있다.
- 배낭에서 순회 방향을 틀린다: 위에서 말한 것처럼 0/1 배낭은 거꾸로.
- 무조건 DP 로 풀려고 한다: 그리디나 [BFS/DFS](#/post/algo-graph-search) 로 되는 문제도 많다. 부분 문제가 겹치는지부터 본다.
- 재귀 메모이제이션에서 깊이 제한에 걸린다: 파이썬에서 깊이가 크면 `sys.setrecursionlimit` 을 올리거나 bottom-up 으로 바꾼다.

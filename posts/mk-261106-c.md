마케팅 자동화로 콘텐츠를 여러 채널에 뿌리면, 어느 링크에서 방문이 왔는지 구분하는 일이 따라온다. 링크 끝에 붙이는 UTM 파라미터가 그 용도다. 값은 사람이 손으로 적으면 금방 흔들린다. 그래서 링크 생성을 코드로 고정하는 쪽을 정리했다. 근거는 Google Analytics 도움말이다.

## UTM 파라미터
도움말에 정의된 것은 다음과 같다.

| 파라미터 | 뜻 |
|---|---|
| utm_source | 유입처. 검색 엔진, 뉴스레터 등 |
| utm_medium | 매체. cpc, banner, email 등 |
| utm_campaign | 제품·슬로건·프로모션 코드. spring_sale 등 |
| utm_id | 캠페인 ID. 캠페인 데이터를 올릴 때 쓰는 ID와 맞춘다 |
| utm_term | 유료 키워드 |
| utm_content | 같은 이메일 안의 CTA 두 개처럼 소재를 구분 |

도움말은 파라미터를 붙일 때 utm_source, utm_medium, utm_campaign은 항상 쓰라고 한다. GA4는 이 값이 있으면 세션을 맞춤 캠페인으로 처리하고, 값이 리포트의 소스·매체·캠페인 차원에 그대로 대응된다.

## 흔들리면 생기는 문제
도움말에 따르면 값은 대소문자를 구분한다. `utm_source=google`과 `utm_source=Google`은 다르게 집계된다. SpringSale과 Spring_Sale도 다른 값이다. 도움말은 소문자를 표준으로 권한다. 플랫폼마다 source를 하나로 정하고, 채널마다 medium을 하나로 정하고, campaign은 캠페인 이름과 정확히 맞추라고 한다. 값이 빠지면 리포트에 "(not set)"이 나온다.

자동화에서는 글 하나를 여러 채널용으로 만들어 내니 링크도 한꺼번에 생긴다. 이때 사람이 적으면 위 문제가 그대로 커진다.

## 코드로 고정하기
규칙은 세 가지로 잡았다. 값은 소문자·밑줄로 정규화한다. medium은 허용 목록에 없으면 막는다. 기존 utm_ 파라미터는 지우고 다시 붙인다. 아래 코드는 직접 실행해서 출력을 확인했다.

```python
import re
from urllib.parse import urlsplit, urlunsplit, parse_qsl, urlencode

ALLOWED_MEDIUM = {"email", "cpc", "paid_social", "social", "referral"}

def slug(v):
    v = v.strip().lower()
    v = re.sub(r"[\s\-]+", "_", v)
    return re.sub(r"[^a-z0-9_]", "", v)

def build(url, source, medium, campaign, content=None):
    medium = slug(medium)
    if medium not in ALLOWED_MEDIUM:
        raise ValueError(f"medium not allowed: {medium}")
    p = urlsplit(url)
    q = [(k, v) for k, v in parse_qsl(p.query) if not k.startswith("utm_")]
    q += [("utm_source", slug(source)), ("utm_medium", medium), ("utm_campaign", slug(campaign))]
    if content:
        q.append(("utm_content", slug(content)))
    return urlunsplit((p.scheme, p.netloc, p.path, urlencode(q), p.fragment))
```

실행 결과다.

```
build("https://example.com/launch?ref=a", "News Letter", "Email", "Spring Sale", "Top-CTA")
-> https://example.com/launch?ref=a&utm_source=news_letter&utm_medium=email&utm_campaign=spring_sale&utm_content=top_cta

build("https://example.com/launch", "Instagram", "paid-social", "SpringSale")
-> https://example.com/launch?utm_source=instagram&utm_medium=paid_social&utm_campaign=springsale

build("https://example.com/launch", "x", "Newsletter", "a")
-> ValueError: medium not allowed: newsletter
```

세 번째처럼 허용 목록에 없는 medium은 에러로 막는다. 목록은 쓰는 채널에 맞춰 늘리면 된다. 한 가지 짚을 점이 있다. 두 번째 결과처럼 `SpringSale`을 정규화하면 `springsale`이 되고, 같은 캠페인을 `Spring Sale`로 적으면 `spring_sale`이 되어 서로 다른 값이다. 정규화는 대소문자만 맞추고 단어 구분은 못 맞추니, campaign 이름은 한 곳(캠페인 목록)에서만 가져오게 해야 한다.

## 자동화에 붙일 때
- 캠페인 목록을 한 파일에 두고, 글·영상 발행 단계에서 그 이름만 쓰게 한다.
- utm_content에는 소재 식별자를 넣어 같은 글의 버전을 구분한다.
- 도움말은 UTM 파라미터가 Landing page + query string 차원에서는 빠지고 Page location 차원에 나온다고 적었다. 리포트를 만들 때 어느 차원을 보는지 맞춰야 한다.

도움말 페이지는 사이트 안 내부 링크에 UTM을 쓰는 문제와 개인정보를 값에 넣는 문제를 다루지 않았다. 이 글에서는 그 부분을 쓰지 않았다. 기본 채널 그룹이 medium 값을 어떻게 나누는지는 별도 문서에 있고 이번에 열어 보지 않았다.

信息处理技术员考试的网络部分，核心在于记忆分层结构，题目中反复出现“该功能属于第几层”和“该 IP 段有多少个主机”这两类问题。先把这两个知识点掌握住即可。考试时间和报名费用可在官方网站查询。

## 先看整体框架

如果把网络看作一个整体，会感到无从下手；但若按层次划分，则条理清晰。上层负责“交换什么内容”，下层负责“如何传输”。每一层都只依赖下一层完成的工作，专注于自己的任务。

- 应用层的 HTTP 是请求与响应的交互规则。
- 传输层的 TCP 负责确保请求完整且有序地送达。
- 网络层的 IP 负责添加地址并选择路径。

当你在浏览器中输入网址时，这些层次实际按何种顺序工作，已在 [详细 → 网络基础 (CS)](#/post/cs-network) 和 [详细 → 一次请求的旅程](#/post/infra-request-journey) 中分别整理。此处仅聚焦考试相关内容。

## OSI 七层模型

OSI 七层模型是将通信过程划分为七个步骤的参考模型。从上至下依次为：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层。考试题目多为“下列描述指向哪一层？”的形式，因此为每层记忆一个关键词可提高效率。

| 层次 | 职责 | 关键词 |
|---|---|---|
| 7 应用 | 用户所用服务的规则 | HTTP 等协议 |
| 6 表示 | 数据表示方式的转换 | 转换、压缩、加密 |
| 5 会话 | 管理通信连接的建立与终止 | 会话、同步 |
| 4 传输 | 端到端的可靠传递 | TCP, UDP, 端口 |
| 3 网络 | 寻址与路径选择 | IP, 路由 |
| 2 数据链路 | 向相邻设备传递数据 | 帧、差错检测 |
| 1 物理 | 以电信号或光信号发送数据 | 电缆、传输介质 |

记忆技巧有两点：第一，编号从下往上递增，物理层为第 1 层，应用层为第 7 层。第二，若题目中出现“路径”、“地址”，优先考虑第 3 层；出现“端口”、“可靠性”，则先考虑第 4 层。

<details>
<summary>将 OSI 与 TCP/IP 模型并列对比</summary>

实际互联网更多采用层次较少的 TCP/IP 模型进行描述。通常划分为应用层、传输层、互联网层和网络接入层四层。其中，OSI 的第 5、6、7 层合并为应用层，第 1、2 层合并为网络接入层。

| OSI | TCP/IP |
|---|---|
| 应用·表示·会话 | 应用 |
| 传输 | 传输 |
| 网络 | 互联网 |
| 数据链路·物理 | 网络接入 |

考试中常同时给出两个模型，询问“属于哪一层”。只需记住上述合并方向即可。
</details>

## 传输层：TCP

TCP 为应用程序提供有序且可靠的字节流。依据 RFC 9293，可靠性由三个机制实现：通过序列号检测丢失的数据，利用每个段附加的校验和发现错误，并通过重传纠正两者问题。

另一个重要概念是端口号。端口用于区分数据应发送至何种应用服务；即使同一两台计算机之间存在多个并发连接，端口也能确保它们互不混淆。如果说 IP 地址是查找计算机的号码，那么端口则是计算机内部服务的查找号码。

### 三次握手

TCP 在发送数据前必须先建立连接，这是考试中几乎每道题都会涉及的内容。

1. 首先由发起连接的一方发送 SYN 报文，其中包含其初始序列号。
2. 接收方回复 SYN-ACK。
3. 发起方再发送 ACK，连接即建立完成。

因此得名“三次握手”。只需整体记忆 SYN、SYN-ACK、ACK 的顺序即可。

关闭连接时，双方分别发送 FIN，对方予以确认（ACK）。先关闭的一方进入 TIME-WAIT 状态，等待 2×MSL 时间。若收到 RST，则立即丢弃当前连接状态。考试中通常以“关闭连接时使用 FIN"、“RST 强制断开”这类区分方式出题。

[详细 → 操作系统](#/post/jb-os) 中关于进程与端口的关联内容一并阅读，有助于加深理解。

<details>
<summary>通过题目区分 TCP 与 UDP 的方法</summary>

若题目描述为“先建立连接并保证顺序与重传”，则为 TCP；反之，“无需建立连接直接发送，速度快但无保障”的描述则对应 UDP。两者同属传输层，区别在于是否提供可靠性保障。
</details>

## 应用层：HTTP

HTTP 是一种应用层协议。根据 MDN 的描述，它通常在 TCP 之上运行，或者在通过 TLS 加密的 TCP 之上运行。在客户端 - 服务器架构中，请求总是由客户端首先发起，服务器不会主动发起对话。

请求包含方法、路径、版本、头部（可选）和正文（可选），而响应则包含版本、状态码、状态消息、头部和正文（可选）。由于 HTTP 是无状态（stateless）的，在同一个连接上的连续请求之间没有任何关联。若要维持登录状态等上下文，需通过在其上叠加 Cookie 来实现。“HTTP 是无状态的，并通过 Cookie 来补充状态”这一说法是考试中常见的考点。

关于 API 中如何使用这些内容，请参见 [详细 → 集成实现与接口](#/post/jb-integration-api)。

## IP 地址与子网

网络层的核心是 IP 地址。IPv4 为 32 位，IPv6 为 128 位。在 Python `ipaddress` 文档中，也指出 IPv4 的 `max_prefixlen` 为 32，IPv6 为 128。

子网划分问题有明确的计算方法。例如 `192.168.10.77/26` 中，前 26 位是网络部分，后 6 位是主机部分。

- 子网掩码：前 26 位为 1，因此为 255.255.255.192
- 地址数量：主机位有 6 位，因此为 $2^6$，共 64 个
- 可用主机数：从 64 中减去网络地址和广播地址，剩余 62 个
- 网络地址：按 64 为单位划分，77 所属区间的起始地址为 192.168.10.64
- 广播地址：该区间的结束地址为 192.168.10.127

已通过 Python 运行代码验证上述计算。

```python
import ipaddress

def info(cidr):
    n = ipaddress.ip_network(cidr, strict=False)
    hosts = list(n.hosts())
    print(cidr, "mask", n.netmask, "network", n.network_address,
          "broadcast", n.broadcast_address, "hosts", len(hosts))

info("192.168.10.77/26")
info("10.0.0.0/24")
```

```
192.168.10.77/26 mask 255.255.255.192 network 192.168.10.64 broadcast 192.168.10.127 hosts 62
10.0.0.0/24 mask 255.255.255.0 network 10.0.0.0 broadcast 10.0.0.255 hosts 254
```

`hosts()` 函数按照文档说明，返回从 IPv4 网络中减去网络和广播地址后的列表。考试中若问及“可用主机数”，答案总是 $2^n - 2$。

### 子网划分

有时需要将一个网段进一步细分。将 `192.168.10.0/24` 划分为 `/26`，会得到四个子网。

```python
import ipaddress
print(list(ipaddress.ip_network("192.168.10.0/24").subnets(new_prefix=26)))
```

```
[IPv4Network('192.168.10.0/26'), IPv4Network('192.168.10.64/26'), IPv4Network('192.168.10.128/26'), IPv4Network('192.168.10.192/26')]
```

前缀每增加 2 位，就会分成四块，每块的地址数量为 64 个。每增加一位前缀，子网数量翻倍，而每个子网的地址数减半。掌握这一关系就不必死记硬背表格了。

<details>
<summary>解决子网问题的步骤</summary>

1. 根据前缀长度计算主机位数：用 32 减去前缀长度。
2. $2^{\text{主机位数}}$ 即为一个区间的地址数量。
3. 查看地址最后一个字节的值，除以区间大小，确定其属于第几个区间。
4. 该区间的第一个地址为网络地址，最后一个地址为广播地址。
5. 可用主机数为区间总数减去 2。

在上述示例中，区间大小为 64，因此 77 落在 64 到 127 的区间内。所以网络地址为 .64，广播地址为 .127。
</details>

## 路由

路由是根据目的地址决定将数据包发送到下一跳哪个方向的过程，由第 3 层负责。数据在传输过程中经过多个设备，逐步接近目的地，每个设备仅判断其下一跳路径。考试中常出现根据路由协议名称进行分类的题目，因此建议提前浏览教材中的协议列表。

## 常见混淆点

- **第 3 层与第 4 层的区别**：地址和路径属于第 3 层，端口和可靠性属于第 4 层。
- **端口与 IP**：IP 用于选择计算机，端口用于选择该计算机内的服务。
- **子网主机数**：必须从 $2^n$ 中减去 2，忘记减去的错误最为常见。
- **关于 HTTP 无状态的说法**：虽然使用 Cookie 可以创建会话，但协议本身仍是无状态的。

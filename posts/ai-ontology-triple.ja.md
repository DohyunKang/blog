トリプルとは、「A は B とこのような関係にある」という意味の文を、主語・述語・目的語の 3 つの欄に記述したものです。こうした文をたくさん集めるとグラフとなり、そのグラフで使用する単語の意味やルールを決めたものがオントロジーです。知識グラフを理解するにはまずこの 2 つが必要です（詳しく → [知識グラフ](#/post/ai-knowledge-graph)）。

## トリプル

W3C の RDF 1.1 Primer は、RDF の文を `<subject> <predicate> <object>` という形式で説明しています。1 つの文は 2 つのリソース間の関係を示し、3 つの部分からなっているためトリプルと呼ばれます。述語は属性（property）とも呼ばれます。

| 主語 | 述語 | 目的語 |
|---|---|---|
| ソウル | 首都である | 大韓民国 |
| 大韓民国 | 名前 | "대한민국" |
| ソウル | 種類 | 都市 |

同じリソースを共有するトリプル同士は繋がります。主語と目的語がノード、述語がノード間の矢印となるグラフです。上記の表では「ソウル」が 2 行に現れているため、1 つのノードとしてまとめられます。

表で記すと単なる 3 列のテーブルのように見えますが、違いはセルに入っている値が文字列ではなく、世界中で通用する識別子という点です。

## IRI とリテラル

Primer によると、RDF でリソースを指し示すのは IRI です。よく URI と呼ばれるものの国際化されたバージョンであり、URL も IRI の一種です。IRI はグローバルな識別子なので、他者が同じ対象を指し示す際そのまま再利用できます。トリプルの 3 つの位置すべてに置くことができます。

例えば「ソウル」を単に `서울` と書くと、文書によって意味が異なる可能性があります。`http://example.org/city/Seoul` という IRI で記述すれば、そのアドレスが指し示す対象が 1 つに固定されます（このアドレスは説明用に私が作成した例です）。

値（リテラル）は IRI ではない基本値です。文字列、日付、数値などであり、データ型を持ち、文字列には言語タグを付けることができます。リテラルはトリプルの目的語の位置にのみ置くことができます。上記の表で「대한민국」という名前の欄に引用符で記されたものがリテラルです。

識別子がないリソースはブランクノードで表現します。Primer はブランクノードを代数学の単純な変数に喩えています。

## スキーマとオントロジーが行うこと

トリプルだけでは、「首都である」という述語の意味を誰が決めるかという定義がありません。そのため、語彙を定義するスキーマが必要で、RDF においては RDF Schema (RDFS) がその役割を果たします。Primer で紹介されている構成要素は以下の通りです。

| 要素 | 行うこと |
|---|---|
| クラス | リソースを分類するカテゴリー。個体は type 属性を通じてクラスと接続されます |
| subClassOf | あるクラスが別のクラスのサブクラスであることを宣言します（階層） |
| subPropertyOf | ある属性が別の属性のサブプロパティであることを宣言します |
| domain | この属性の主語に属すべきクラス |
| range | この属性の目的語に属すべきクラス |

このようにクラスと関係の種類を定義したものをオントロジーと呼びます。OWL 2 の概要文書は、オントロジーを「特定の分野を取り扱い、ユーザー集団が共有する形式化された語彙」と説明し、用語は他の用語との関係で定義されると述べています。OWL 2 はクラス、属性、個体、データ値を提供する、形式的に意味が定義されたオントロジー言語です。RDFS よりも豊かに表現できる側面と言えます。OWL 2 オントロジーは主に RDF ドキュメントとしてやり取りされ、どの OWL 2 オントロジーでも RDF グラフとして見ることができるそうです。

### 推論

意味が形式的に定義されているため、機械が既存のトリプルから新しいトリプルを導き出すことができます。Primer の例は簡単です。

- 事実：`ex:bob foaf:knows ex:alice`
- 宣言：`foaf:knows` の domain は `foaf:Person`
- 導出：`ex:bob` は `foaf:Person` です

Bob が人間であることはどこにも書かれていませんが、述語の domain 宣言によって自動的に導き出されます。Primer は、あるトリプル集合が他のトリプルを包含することを entailment（帰結）と呼び、推論機（reasoner）は矛盾も検出できると記しています。整数として宣言された値に整数でないリテラルが入っているケースなどが例です。

OWL 2 の文書では、推論機が回答する質問として「クラスの一貫性、包含（subsumption）、インスタンス検索」を挙げます。さらに OWL 2 RL の推論は「健全だが一般的には完全ではないかもしれない」と述べています。つまり、導き出された結論は信頼できても、導き出せるものをすべて見つけてくれる保証はプロファイルによって異なります。

## プロパティグラフとの違い

グラフを扱う方法は一つではありません。ノードと関係に属性を直接付与して保存する「属性グラフ方式」は、[グラフ DB](#/post/ai-graph-db) で多く採用されています。一方、RDF はすべてトリプルとして展開し、IRI を通じて名前と語彙を共有し、スキーマと推論規則が標準化されていることが特徴です。どちらが良いかという話以前に、用途が異なる程度に理解しておけば十分です。両者の詳細な比較については、この記事で直接確認しないため一旦保留します。

## 例：シンプルなモデル

前述のソウルに関する例をスキーマと併せて示すと、以下のような形になります。実際にコードを実行したわけではないため、表形式で記述します。

| 項目 | トリプル |
|---|---|
| スキーマ | 수도（属性）の domain = 도시, range = 나라 |
| スキーマ | 도시, 나라는 クラス |
| 事実 | 서울 수도다 대한민국 |
| 導出 | 서울은 도시다, 대한민국은 나라다 |

「事実」は一行しか書いていませんが、スキーマのおかげでさらに二行が導き出されます。Primer の Bob の例と同じ構造です。

## よくある誤解

- オントロジーは哲学的な用語なので難しい：この記事で扱う範囲については、「概念と関係を定めた共有語彙」という程度に理解すれば十分です。
- RDF はデータベースの種類である：RDF はデータを表現するモデルであり、保存やクエリは別途行います。
- スキーマがあればデータの誤りを検出して防ぐ：RDFS の domain/range は基本的に導出規則です。前述の Bob の例のように、「間違っている」という意味ではなく、「ならばこれも真」という形で使われます。
- 推論を行えばすべての結論が得られる：前述した通り、OWL 2 RL は完全性を保証しません。
- IRI は開くことができる Web アドレスであるべき：URL は IRI の一種に過ぎず、IRI の本質はグローバルな識別子にあることです。

<details>
<summary>詳細解説：リテラルの目的語制限とブランクノード</summary>

Primer は「リテラルは目的語の位置でのみ使用できる」と明記しています。そのため、「文字列が与えられた文」を直接作成することはできず、必要であればその文字列を持つ属性を備えたリソースを一つ置くように迂回して扱います。

ブランクノードは、名前をつけるのが面倒な場合や、名前が必要ない中間ノードに使用します。主語や目的語の位置にも置かれます。

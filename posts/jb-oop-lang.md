정보처리기사 객체지향 단원은 용어 문제와 코드 출력 문제가 같이 나오는 곳이라, 개념을 외우는 일과 코드를 손으로 따라가는 일을 둘 다 해야 했다. 시험 일정과 응시 요건은 공식 사이트에서 확인하면 되니 여기서는 개념과 풀이 방식만 적는다.

## 객체지향이 뭔지

프로그램을 "데이터와 그 데이터를 다루는 동작을 묶은 객체"들의 상호작용으로 보는 방식이다. 절차지향은 함수를 순서대로 부르는 쪽에 무게가 있고, 객체지향은 어떤 데이터가 어떤 동작과 붙어 있어야 하는지를 먼저 나눈다.

기본 용어부터 정리한다.

| 용어 | 뜻 |
|---|---|
| 클래스 | 객체를 만들기 위한 설계도. 속성(변수)과 메서드(함수)를 정의 |
| 객체(인스턴스) | 클래스로 실제 만들어 낸 것 |
| 메서드 | 객체가 할 수 있는 동작 |
| 메시지 | 객체에게 메서드를 실행하라고 보내는 요청 |
| 생성자 | 객체를 만들 때 처음 실행되는 메서드 |

모델링 쪽 이야기(클래스 다이어그램, 관계)는 [자세히 → UML과 객체지향 분석](#/post/jb-uml)에 따로 적는다.

## 4가지 특징

시험에서는 아래 네 개를 설명과 짝지우는 문제로 나온다.

| 특징 | 한 줄 설명 | 코드에서 보이는 모습 |
|---|---|---|
| 캡슐화 | 데이터와 동작을 묶고, 내부는 숨기고 필요한 것만 공개 | private 속성 + getter/setter |
| 상속 | 부모의 속성·메서드를 자식이 물려받음 | `extends`, `class B(A)` |
| 다형성 | 같은 이름의 요청이 객체에 따라 다르게 동작 | 오버라이딩, 오버로딩 |
| 추상화 | 공통된 핵심만 뽑아 단순하게 표현 | 추상 클래스, 인터페이스 |

외울 때 헷갈리는 건 정보 은닉과 캡슐화였다. 정보 은닉은 "내부를 감춘다"는 목적이고 캡슐화는 그걸 하기 위해 묶는 방법이라고 보면 문제 보기와 맞았다.

## 다형성에서 틀리는 것들

다형성은 용어가 두 개로 갈린다.

| 구분 | 오버로딩 | 오버라이딩 |
|---|---|---|
| 하는 일 | 같은 이름, 매개변수 개수·타입이 다른 메서드 여러 개 | 부모 메서드를 자식이 같은 이름·같은 매개변수로 다시 정의 |
| 관계 | 같은 클래스 안 | 부모-자식 사이 |
| 결정 시점 | 컴파일할 때 | 실행할 때 |

Java 공식 튜토리얼은 이 실행 시점 결정을 "가상 메서드 호출"이라고 설명한다. 변수의 선언 타입이 아니라 변수가 실제로 가리키는 객체의 클래스에 있는 메서드를 JVM이 부른다. 튜토리얼 예시도 `Bicycle` 타입 변수에 `MountainBike` 객체를 넣고 메서드를 부르면 `MountainBike` 쪽 메서드가 실행된다는 내용이다.

Python 문서는 한 걸음 더 나가서 Python의 모든 메서드가 사실상 virtual이라고 적는다. Python에서는 선언 타입이라는 개념이 없으니 항상 실제 객체 기준으로 찾는다.

출력 문제에서 이 규칙이 거의 전부다. 변수 타입이 무엇이든 객체가 무엇이냐를 본다.

<details>
<summary>실행해 본 예제 1 — 오버라이딩과 super</summary>

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."
    def intro(self):
        return self.name + ":" + self.speak()

class Dog(Animal):
    def speak(self):
        return "멍"

class Puppy(Dog):
    def speak(self):
        return super().speak() + "!"

for a in [Animal("a"), Dog("b"), Puppy("c")]:
    print(a.intro())
```

실행하면 이렇게 나온다.

```
a:...
b:멍
c:멍!
```

`intro`는 `Animal`에만 있는데, 그 안에서 `self.speak()`를 부르면 self가 가리키는 실제 객체의 `speak`가 실행된다. Python 문서도 부모 메서드가 self의 다른 메서드를 부르면 자식의 오버라이딩이 대신 불릴 수 있다고 적는다. `Puppy`는 `super()`로 부모(`Dog`) 결과를 받아 "!"를 붙였다.
</details>

## 코드 읽기 요령

C, Java, Python이 다 나온다. 문법은 달라도 읽는 순서는 비슷하게 가져갔다.

1. 어디서 시작하는지부터 찾는다. C와 Java는 `main`, Python은 맨 아래쪽 실행문이다.
2. 변수마다 종이에 칸을 그려 값을 한 줄씩 적는다. 머릿속으로 하면 꼭 틀렸다.
3. 반복문은 첫 두세 번만 따라가면 규칙이 보이고, 그다음은 규칙으로 건너뛴다.
4. 객체가 나오면 "이 변수가 가리키는 실제 객체가 뭐냐"를 먼저 적는다.
5. 마지막에 출력 형식(줄바꿈, 공백)을 다시 본다.

### 언어별로 잘 걸리는 자리

| 언어 | 자주 걸리는 곳 |
|---|---|
| C | 정수끼리 나누면 소수점이 버려진다. 전위(`++i`)와 후위(`i++`)의 차이. 포인터와 배열 이름의 관계. 문자 배열은 끝에 널 문자가 붙는다 |
| Java | 오버라이딩은 실제 객체 기준, 오버로딩은 선언된 타입 기준으로 고른다. static 멤버는 객체가 아니라 클래스에 하나. 부모 생성자가 먼저 실행된다 |
| Python | 들여쓰기가 블록이다. 리스트·딕셔너리는 참조라서 같이 바뀐다. `//`는 몫, `/`는 실수 나눗셈. 슬라이싱 `a[1:3]`은 끝 번호를 포함하지 않는다 |

C와 Java 항목은 언어 기본 규칙이라 시험지에서 같은 모양으로 계속 나오는 부분이다. 직접 컴파일해서 확인하는 연습은 따로 해 두면 좋다.

## Python 쪽 함정 두 개

Python은 코드가 짧아서 오히려 함정이 숨기 쉽다. 공식 튜토리얼이 직접 경고하는 자리가 둘 있어 그걸 실행해 봤다.

### 클래스 변수와 인스턴스 변수

```python
class Counter:
    total = 0
    def __init__(self):
        self.n = 0
    def add(self):
        self.n += 1
        Counter.total += 1

x, y = Counter(), Counter()
x.add(); x.add(); y.add()
print(x.n, y.n, Counter.total)
```

결과는 `2 1 3`이다. `n`은 객체마다 따로고, `total`은 클래스에 하나라 전부 합쳐진다. Java의 static 변수와 같은 위치다.

### 리스트를 클래스 변수로 두면

```python
class Bag:
    items = []
    def put(self, v):
        self.items.append(v)

p, q = Bag(), Bag()
p.put(1); q.put(2)
print(p.items, q.items)
```

결과는 `[1, 2] [1, 2]`다. 두 객체가 같은 리스트를 공유한다. 문서도 같은 문제를 장난감 `tricks = []` 예시로 보여 주고, 해결은 `__init__`에서 `self.items = []`로 객체마다 만드는 것이라고 한다.

<details>
<summary>다중 상속과 메서드 탐색 순서</summary>

Python은 부모를 여럿 둘 수 있다. 탐색 순서는 `클래스.__mro__`로 볼 수 있다.

```python
class A:
    def hi(self): return "A"
class B(A):
    def hi(self): return "B" + super().hi()
class C(A):
    def hi(self): return "C" + super().hi()
class D(B, C):
    def hi(self): return "D" + super().hi()
print(D().hi())
print([k.__name__ for k in D.__mro__])
```

```
DBCA
['D', 'B', 'C', 'A', 'object']
```

`super()`는 "바로 위 부모"가 아니라 이 순서에서 다음 클래스를 부른다. `D`의 `super()`는 `B`, `B`의 `super()`는 `A`가 아니라 `C`로 간다. 그래서 `DBCA`다. 문서는 단순한 경우 깊이 우선·왼쪽 우선이라고 적고, 실제 규칙은 더 복잡하다고 덧붙인다. 순서를 따라가는 습관은 일반 다형성 문제에도 그대로 쓰인다.
</details>

## 접근 제한과 이름 앞의 밑줄

Python에는 진짜 private이 없다. 문서 기준으로 `_spam`은 "공개 API가 아니다"라는 관례일 뿐이고, `__spam`처럼 밑줄 두 개로 시작하면 `_클래스이름__spam`으로 이름이 바뀐다(name mangling). 막으려는 게 아니라 자식 클래스가 같은 이름을 써도 부딪히지 않게 하려는 장치다. 캡슐화 문제에서 "Python은 접근을 완전히 막는다"는 보기가 있으면 틀린 쪽으로 봤다.

Java는 `private`, `protected`, `public`, 아무것도 안 붙인 기본 접근이 있다. 이 구분은 용어 문제로 자주 묻는다.

## 자주 나오는 유형 정리

| 유형 | 풀이 방식 |
|---|---|
| 특징·용어 짝짓기 | 위 4가지 표와 오버로딩/오버라이딩 표로 풀기 |
| 상속·오버라이딩 출력 | 실제 객체의 클래스부터 적고, 그 클래스에서 메서드를 위로 찾아 올라가기 |
| 생성자 호출 순서 | 부모 생성자 → 자식 생성자 순서로 출력을 이어 적기 |
| static·클래스 변수 | 객체별 칸과 클래스 칸을 따로 그려 값 추적 |
| 연산자·반복문 출력 | 변수 칸 표를 그려 한 줄씩 |

기출 문제 원문은 여기 싣지 않았다. 문제는 공식 기출 모음이나 학습 사이트에서 직접 풀어 보는 게 맞다. 프로그래머스에서 언어별 기본 문제를 풀며 손으로 따라가는 연습을 같이 하면 도움이 된다.

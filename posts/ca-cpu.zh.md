CPU 的工作非常简单：从内存中取出一条指令，解释它要做什么，然后执行。这个过程会一直重复，直到电源关闭。寄存器、指令集和流水线都是关于如何让这个循环运行得更快、更准确的故事。操作系统如何分配 CPU 资源在 [操作系统概述](#/post/cs-os) 中有介绍，而这里我们只关注 CPU 内部。

## 冯·诺依曼结构

将程序（指令）和数据一起存储在同一个内存中，CPU 从那里逐条读取并执行指令的结构称为冯·诺依曼结构。目前使用的绝大多数计算机都基于这一架构。指令本质上也是内存中的数字，因此修改程序就是修改内存内容。数字如何以位的形式存储将在 [数据表示](#/post/ca-data-representation) 中讨论。

CPU 内部主要有三个部分：

| 组成部分 | 功能 |
|---|---|
| 控制单元 | 解释指令，并向其他设备发送“现在执行这个”的信号 |
| ALU | 执行加减法等算术运算以及 AND、OR 等逻辑运算 |
| 寄存器 | CPU 内部非常小且快速的存储空间 |

内存位于 CPU 外部，速度远慢于寄存器。因此，大多数运算会将值加载到寄存器中进行处理，然后将结果写回内存。这种速度差异引出了 [存储器层次结构与缓存](#/post/ca-memory-hierarchy)。

## 指令周期

处理一条指令的过程分为三个阶段：

1. **取指（fetch）**：从内存中读取程序计数器（PC）所指向地址处的指令，并将其放入指令寄存器。PC 则更新为下一条指令的地址。
2. **译码（decode）**：控制单元读取指令，确定要执行何种运算以及操作数是什么。
3. **执行（execute）**：ALU 进行计算，或从内存读取/写入数据，或将结果存入寄存器。

PC 通常每次递增一个地址，但在遇到分支或跳转指令时会跳转到其他地址。`if` 语句和循环在机器层面就是通过改变 PC 的指令实现的。

我们用 Python 构建了一个小型虚拟 CPU，并直接运行了该周期。以下是一个从 1 加到 5 的程序：

<details>
<summary>手动运行寄存器机器（已验证执行）</summary>

```python
prog = [
    ("LOADI", 0, 0),   # r0 = 0 (합)
    ("LOADI", 1, 5),   # r1 = 5 (카운터)
    ("LOADI", 2, 1),   # r2 = 1
    ("ADD", 0, 1),     # r0 += r1
    ("SUB", 1, 2),     # r1 -= r2
    ("JNZ", 1, 3),     # r1 != 0 이면 PC = 3
    ("HALT", 0, 0),
]
reg = [0] * 4
pc = 0
cycles = 0
while True:
    ins = prog[pc]          # fetch
    pc += 1
    op, a, b = ins          # decode
    cycles += 1
    if op == "LOADI": reg[a] = b             # execute
    elif op == "ADD": reg[a] += reg[b]
    elif op == "SUB": reg[a] -= reg[b]
    elif op == "JNZ":
        if reg[a] != 0: pc = b
    elif op == "HALT": break
print(reg[0], cycles)
# 15 19
```

结果为 15，共执行了 19 条指令：前 3 条 + 循环体 3 条 × 5 次 + HALT 1 条。从代码中可以清楚看到，循环本质上只是“将 PC 回退到 3 的跳转”。
</details>

## 指令长什么样

实际的指令也是一串比特。通常由两部分组成：给出操作类型的操作码（opcode），以及指出使用哪个寄存器或常数的操作数字段。上述示例中的 `("ADD", 0, 1)` 就是用字符形式表示的这种结构。

所有这些指令的约定统称为指令集架构（ISA）。ISA 规定了有哪些指令、有多少个寄存器、如何指定内存地址等。x86、ARM、RISC-V 都是 ISA 的名称。遵循相同的 ISA，程序就能在不同芯片制造商生产的硬件上运行，而芯片内部设计则相对自由。编译器生成的最终输出就是该 ISA 的指令序列。

ISA 大致分为两类：RISC 通过使指令简单且规则化来简化硬件加速；CISC 则让单条指令完成更多工作。在流水线讲解中常提到的经典 RISC 流水线属于 RISC 架构。

## 流水线

如果每条指令都完整走完三个阶段后再开始下一条，取指单元在执行期间就会闲置。这就像洗衣机和烘干机并存时，当第一件衣服进入烘干机后，洗衣机才能放入下一件衣服一样。流水线正是通过将指令处理划分为不同阶段，使得多条指令能同时处于不同阶段进行处理。

经典 RISC 流水线包含五个阶段：

| 阶段 | 功能 |
|---|---|
| IF | 从内存中取指 |
| ID | 译码并读取寄存器 |
| EX | ALU 执行计算（包括内存地址计算也在此阶段） |
| MEM | 读写数据内存 |
| WB | 将结果写回寄存器 |

一旦流水线被填满，每个周期就能完成一条指令。虽然单条指令的处理时间（延迟）不变，但单位时间内完成的指令数量（吞吐量）增加了。

<details>
<summary>计算所需周期数（已验证执行）</summary>

当有 n 条指令、5 个阶段时，若无流水线需 5n 个周期，若有流水线则为 5 + (n-1) 个周期。若存在延迟，则相应增加。

```python
def cycles(n, stall=0, stages=5):
    return stages + (n - 1) + stall
n = 100
print("파이프라인 없음:", n * 5)        # 500
print("파이프라인:", cycles(n))          # 104
print("load-use 20번:", cycles(n, stall=20))  # 124
print(5 / (cycles(n)/n))                 # 4.80...
```

如果指令数为 100，周期数从 500 减少到 104，速度提升约 4.8 倍。但阶段数接近 5 却无法超过。若中间停顿 20 次，则周期数为 124，速度提升降至约 4 倍。
</details>

## 危害：重叠执行引发的问题

如果重叠执行指令，后一条指令可能在先一条指令完成前就开始执行，从而产生问题。这种情况被称为“危害”（Hazard）。

- **数据危害**：后一条指令需要用到前一条指令的结果，但该结果尚未写入寄存器。例如在 `ADD r1, r2, r3` 之后立即使用 r1 的情况。解决方法是转发（旁路）：不等待结果写入寄存器，而是直接从 ALU 输出将数据传递给下一条指令的输入端。但针对从内存读取数据的 load 指令，由于数据返回较晚，若下一条指令立即使用该数据，则必须空出一个周期（即插入气泡或停顿）。
- **控制危害**：在分支指令决定跳转目标之前，流水线已经取到了后续指令。如果预测错误，则需要丢弃已取出的指令并重新取指。分支预测正是通过提前推测结果来减少此类浪费的方法。早期的 MIPS 架构也曾采用由编译器填充分支指令后的延迟槽（delay slot）的方式。
- **结构危害**：两条指令试图同时使用同一硬件资源。例如，若系统中只有一个内存访问设备，则读操作与写操作会发生冲突。

## 常见误解

- **时钟频率越高越快**：速度不仅取决于时钟频率，还与每条指令完成的周期数（IPC）以及指令总数密切相关。一旦流水线停顿，即使时钟频率相同，性能也会下降。
- **流水线越深越好**：增加阶段数可以缩短每个阶段的耗时，从而提升时钟频率；但同时，分支预测错误时丢弃的指令数量也会相应增加。
- **一条指令在一个周期内完成**：在流水线架构中，单条指令会跨越多个周期执行，只是多条指令在时间上重叠而已。
- **内存读取是 CPU 内部操作**：内存位于 CPU 外部，其访问速度通常是系统中最慢的部分。设备与 CPU 如何连接并交换数据，将在 [输入/输出与总线](#/post/ca-io-bus) 中继续探讨。

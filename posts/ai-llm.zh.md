LLM（大型语言模型，Large Language Model）是一种经过大规模训练、能够以概率预测下一个词块（token）的模型。被称为“对话式 AI"的事物，其核心原理大多基于此。

## 先说简单点

在智能手机键盘上输入“今天午餐”后，会弹出下一个词的候选项。LLM 的功能与此非常接近，只是被极大地放大了：它不是展示几个候选词，而是为所有可能的下一个词块计算概率并选择一个；将选中的词块接在后面，然后再次预测下一个词块。重复数百次这样的操作，就形成了段落。

初次听到这个解释时，可能会想“就这？”——明明也能写代码、做翻译，核心却只是“猜下一个词块”。但这确实接近事实。不过，重点不在于“仅此而已”，而在于“通过将其做到巨大规模，从而实现了更多”。下面按顺序介绍。

## Token：模型读取的基本单位

模型并非直接读取字符或单词，而是以称为"token"的词块为单位进行读取。一个 token 可能是一个完整的单词、单词的一部分，也可能只是一个字符。高频出现的组合通常作为一个 token，而罕见单词则会被拆分成多个片段。

这种方式的根源之一是子词分割（subword segmentation）。Sennrich 等人 2015 年的论文解决了翻译模型因词汇表固定而无法处理生僻词的问题，其方法是将单词表示为子词片段的序列。我只阅读了该论文的摘要，目前 LLM 所使用的 tokenizer 具体采用何种方式因模型而异。以下是为了说明概念而构建的虚构分割示例，并非实际 tokenizer 的结果。

| 原文 | 虚构的 token 分割 |
|---|---|
| 점심 | `점심` |
| 형태소분석 | `형태`, `소`, `분석` |
| unbelievable | `un`, `believ`, `able` |

Token 数量直接与费用挂钩。API 通常按输入 token 数和输出 token 数计费（Anthropic 文档中提供了预先计算 token 数的功能，并说明用于管理费用和速度限制）。即使语义相同，不同语言的 token 数量也可能不同。

正如在 [详见 → 上下文窗口](#/post/ai-context-window) 中所讨论的，单次可处理的 token 数量存在上限。

## 下一个 token 预测

从模型的角度来看，其任务只有一项：给定迄今为止的 token 序列，输出下一个 token 的概率分布。

```
입력: "대한민국의 수도는"
출력(예시용 가상의 확률):
  " 서울"  0.92
  " 부산"  0.01
  " 어디"  0.01
  ...
```

从此分布中选择一个 token。若始终选择概率最高的，则回答会趋于固定；若按概率随机采样，则对同一问题的回答会有细微差异。用于调节这种程度的参数，便是常说的 temperature 等设置。不同产品的命名和默认值各不相同。

此处有一个关键点：模型并非通过事实核查来选择“首尔是正确的”，而是因为在学习过程中，“首尔”频繁出现在此类语境之后，因此其概率较高。这一差异正是后续幻觉（hallucination）问题的根源。[详见 → 幻觉](#/post/ai-hallucination)

## 参数：学习填充的数字

模型内部包含大量数字（权重），这些被称为“参数”。输入 token 经过这些数字的转换，最终输出下一个 token 的概率分布。学习过程即逐步调整这些数字，以降低预测错误率的过程。

- 学习前：数字接近随机值，输出为无意义的文本。
- 学习中：在海量文本中解决“猜下一个 token"的问题，根据错误程度调整数字。
- 学习后：数字被固定。语法、常识、代码模式等信息便分散存储于这些数字之中。

以下用于把握规模感的数字源自论文。GPT-3 论文（2020）训练了一个拥有 1750 亿参数的自回归语言模型，并指出其参数数量是此前某些非稀疏（non-sparse）语言模型的 10 倍。其架构属于 2017 年“Attention Is All You Need”提出的 Transformer 系列。该论文提出了一种仅由注意力机制构成、无需循环或卷积的结构。本文不详细讨论注意力机制的具体计算方式，计划另行阅读并整理。

## 预训练模型生成答案的过程

名称中的“预训练（pre-trained）”意指在针对特定用途调整之前，先使用通用文本进行了大规模学习。使用时不会发生学习过程：参数已固定，仅根据输入进行计算。

单次对话的流程如下：

1. 拼接用户输入的文本、对话历史和系统指令。
2. 将拼接后的内容分割为 token。
3. 模型输出下一个 token 的概率分布。
4. 从中选择一个并追加到末尾。
5. 重复步骤 3~4，直至出现结束信号。

答案看似逐字流出的原因即在于此：实际上确实是逐个生成 token 的。

GPT-3 论文中令人印象深刻的一点是，无需单独学习特定任务，仅通过文字告知即可。论文指出，任务与示例是通过“纯粹与模型的文本交互”来指定的，并未进行梯度更新（即额外训练）。这正是如今在提示词中加入若干示例这一方式的起点。[详情 → 提示词](#/post/ai-prompt)

模型并不知晓最新信息或我的文档，因为这些内容未包含在参数中。因此，采用将所需文本一同输入的方式。[详情 → RAG](#/post/ai-rag)

## 模型规模：越大越好吗？

总体而言，大模型表现更佳，但“仅看参数量”并非答案。有两篇论文证明了这一点。

- Chinchilla (2022)：主张在计算预算固定的情况下，应同比例增加模型大小与训练 token 数。Chinchilla（700 亿参数）使用了与 Gopher（2,800 亿参数）相近的计算量，但数据量增加了 4 倍。
- InstructGPT (2022)：经人工反馈微调的 13 亿参数模型输出，在评估者偏好度上优于 175B GPT-3 的输出。尽管参数量仅为后者的约百分之一，却仍取得了更好效果。

总结来说，规模、数据量及额外调整各自影响质量。规模也直接关联成本。大模型生成每个 token 所需的计算量更大。因此，同一家公司的产品常将大模型与小模型分开销售。例如，简单的分类任务使用小模型，复杂的推理任务则使用大模型。

## 与旧式聊天机器人有何不同？

早期的基于规则的聊天机器人采用预设问答对的结构：若关键词匹配则输出既定回答；若无匹配问题，则返回“无法理解”。

| | 规则/场景型聊天机器人 | 基于 LLM |
|---|---|---|
| 答案来源 | 人工撰写的句子 | 通过学习到的参数生成 |
| 未见过的提问 | 通常失败 | 先尝试给出看似合理的回答 |
| 出错时 | 无答案或荒谬的场景 | 给出看似合理但错误的回答 |
| 制作成本 | 编写场景 | 模型训练与调用成本 |
| 行为可预测性 | 容易 | 困难 |

LLM 虽具灵活性，但难以控制。因此，实际产品通常不只部署单个 LLM，而是结合搜索、工具调用及规则。[详情 → 框架](#/post/ai-harness)

还有一点：我们日常使用的对话式 AI，并非单纯的 LLM，而是在预训练模型基础上，通过人工反馈等进行额外调整，并叠加了对话格式的提示词与产品功能。InstructGPT 论文探讨了这种额外调整。论文指出，仅靠训练模型无法使模型遵循用户意图，且可能产生虚假或有害输出，因此建议进行人工反馈微调。

## 常见误解

- **从搜索结果获取答案**：基础状态的 LLM 是基于参数中存储的模式进行生成；具备搜索功能的产品则是单独调用搜索接口。
- **模型记住我的提问并从中学习**：对话过程中并未发生学习。看似记得之前对话，是因为将记录重新输入所致。服务后续是否将数据用于训练，取决于其服务条款。
- **并非真正理解，只是模仿 / 能像人一样理解**：这两点均无法从本文得出明确结论。需分别考察“基于下一 token 预测进行训练”这一事实与“由此获得了何种能力”。
- **参数越多越好**：如 Chinchilla 和 InstructGPT 案例所示，效果取决于数据量及调整情况。

<summary>详细解析：下一 token 预测的学习方式</summary>

将学习数据的文本视为 token 序列 t1, t2, ..., tn，目标是让模型在每一位置根据前面的 token（t1..t(k-1)）预测出 tk。模型对 tk 输出的概率越低，损失（loss）越大；参数调整方向即为减小该损失。由于正确答案已包含在文本中，无需人工额外标注标签。这种学习方式称为自监督学习。

GPT-3 论文摘要中提到的“自回归（autoregressive）”指将前一步生成的输出作为下一步输入的方式。上述 5 步循环即为此过程。

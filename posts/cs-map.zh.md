CS 设计基础涵盖范围广泛，让人不知从何学起。因此，我先列出七个主题各一句，若想了解更多，请点击下方链接跳转。顺序为：如何划分代码（设计）→ 代码运行的底层（网络、操作系统）→ 构建过程（工程、Git）。

## 一览关系图

```
설계(코드를 어떻게 나눌까)
  절차지향 / 객체지향  →  SOLID(바뀔 때 덜 깨지게)  →  디자인 패턴(자주 만나는 문제의 이름표)

바닥(코드가 돌아가는 곳)
  네트워크(DNS → TCP → TLS → HTTP)    운영체제(CPU·메모리를 나눠 쓰게 하는 관리자)

과정(여럿이 만들고 고쳐 나가기)
  소프트웨어 공학(방법론·요구사항·UML·테스트)  →  Git(커밋 스냅샷과 브랜치)
```

## 1. 如何划分代码

**面向过程与面向对象**：划分同一问题的依据不同。面向过程以函数（待办事项）为单元，面向对象则以对象（数据及其操作行为）为单元。前者从“按什么顺序执行”出发，后者从“谁负责这些数据”出发。
[详情 → 面向过程与面向对象](#/post/cs-procedural-oop)

**SOLID 原则**：这是面向对象设计中五条准则，旨在使代码在变更时更不易出错。与其视为规则集合，不如将其作为检查清单，用于探究代码异常的原因。
[详情 → SOLID 原则](#/post/cs-solid)

**设计模式**：这是在面向对象设计中常见的问题及其解决方案的命名与归类汇总。单看名称和分类容易混淆，但若结合适用场景一同理解，则较为清晰。
[详情 → 设计模式](#/post/cs-design-patterns)

## 2. 代码运行的底层

**网络基础**：分层解析后便一目了然。将地址转换为 IP（DNS），建立连接（TCP），实施加密（TLS），并在此之上进行请求与响应交互（HTTP）。这四个步骤按序发生。
[详情 → 网络基础](#/post/cs-network)

**操作系统基础**：CPU 和内存等有限资源由它分配给多个程序共享使用，是系统管理员。进程、调度、虚拟内存、同步等术语，均是从不同侧面描述同一项工作的名称。
[详情 → 操作系统基础](#/post/cs-os)

## 3. 构建过程

**软件工程基础**：该领域关注的并非如何编写优质代码，而是按何种顺序构建产品、如何进行验证以及如何修复问题。仅梳理了方法论、需求分析、UML、测试和版本管理等主干内容。
[详情 → 软件工程基础](#/post/cs-sw-engineering)

**Git**：与其说是积累变更历史的工具，不如将其视为由“提交”（commit）快照串联而成的系统，而分支则是其中某一部分的标签。这样理解后，合并（merge）、变基（rebase）和冲突解决便可在同一图示中理清。
[详情 → 彻底理解 Git](#/post/cs-git)

Moonshot AI が Kimi K3 の重みを Hugging Face に公開し、モデルカードとライセンスファイルを直接確認したところ、「公開」という言葉の意味は想像以上に多層的であることが判明しました。（確認時点：2026-11-02）

## モデルとは何か

Kimi K3 はテキストと画像を入力とする Mixture-of-Experts モデルです。モデルカードでは自身を「open-weight, native multimodal agentic model」と紹介しています。数値はカードに記載されたまま転記します。

| 項目 | 値 |
|---|---|
| 総パラメータ数 | 2.8T |
| トークンあたりのアクティブパラメータ | 104B |
| レイヤー数 | 93（そのうち 1 つは dense） |
| エキスパート (expert) | 896 個中 16 個を選択、共有 2 個 |
| コンテキスト長 | 1,048,576 トークン |
| ビジョンエンコーダー | MoonViT-V2 (401M) |
| 語彙サイズ | 160K |

MoE は全パラメータを使用せず、トークンごとに一部のエキスパートのみを起動する構造です。2.8 兆のうち 104 億しか各トークンで使用しないため、計算量はアクティブパラメータ側に近く、メモリは総量側に近いです。この違いが後で「逆転可能か」という議論につながります。基本コンセプトは [詳細 → LLM とは何か](#/post/ai-llm) にあります。

## 構造で目立つ点

カードと GitHub リポジトリは同じことを述べています。93 レイヤーのうち 69 が KDA(Kimi Delta Attention)、24 が Gated MLA アテンションです。ブログでは KDA を「アテンションを育む効率的な土台」と呼び、もう一つの新しい要素である Attention Residuals(AttnRes) は、レイヤーを超えて表現を均一に積み上げるのではなく、深さ方向に必要なものを拾い上げて持ってくる方式であると説明しています。ブログはこの構造変更により K2  대비 全体のスケーリング効率が約 2.5 倍向上したと記載していますが、これは Moonshot 側の主張です。

100 万トークンのコンテキストを実際に使用する場合のコストと品質の問題は [詳細 → コンテキストウィンドウとトークン](#/post/ai-context-window) で別途整理しました。

## 重みの形式：量子化が基本

カードによると SFT ステージから量子化認識学習 (QAT) を行い、重みは MXFP4、アクティブ値は MXFP8 です。学習時から低い精度を考慮したモデルであるため、後で減らす通常の量子化とは出発点が異なります。Hugging Face ファイルのテンソルタイプは F32, BF16, U8 で表示されます。

<details>
<summary>MXFP4 なら容量はどれくらいか（概算）</summary>

パラメータ 1 つが 4 ビットであれば 0.5 バイトです。2.8 兆 × 0.5 バイトは約 1.4TB です。スケール値と一部の高精度テンソルが加わるため、実際のストレージはこのより大きくなります。これは概算であり、正確な容量はストレージのファイルリストを確認する必要があります。

アクティブパラメータが 104B とあるからといって、104B のモデルメモリだけで済むわけではありません。どのエキスパートが起動するかはトークンごとに異なるため、全エキスパートをメモリにロードしておく必要があります。一般的な VRAM 計算方法は [詳細 → ローカルモデル実行](#/post/ml-local-models) にあります。
</details>

## どのように動かすか

カードが案内する道筋は 4 つです。

- ホスティング API: platform.kimi.ai でモデル名 `kimi-k3`、OpenAI・Anthropic 互換エンドポイント
- 直接サービング：vLLM, SGLang, TokenSpeed を推奨エンジンとして記載しています
- Docker Model Runner: `docker model run hf.co/moonshotai/Kimi-K3`
- llama.cpp·Ollama·LM Studio 用の GGUF 量子化はカードの quantizations リストを通じて接続されます

サービングエンジンがリクエストをバッチ化し KV キャッシュを扱う原理は [詳細 → 推論最適化](#/post/ml-inference) に記載しました。

## 思考モードは常にオン

この部分が API を使う際により目立ちました。カード基準で Thinking は常にオンであり、結果は `reasoning_content` に含まれます。`reasoning_effort` は low, high, max を受け取りデフォルトは max です。複数のターンでツールを使用する際は、アシスタントメッセージを `content` のみならず `reasoning_content` と `tool_calls` まで丸ごと再送信する必要があります。思考トークンが出力料金と遅延に与える影響は [詳細 → 推論モデルと思考トークン](#/post/ai-reasoning) で扱いました。

API 料金はブログに記載されています。100 万トークンあたりのキャッシュヒット入力 $0.30、キャッシュミス入力 $3.00、出力 $15.00 です。キャッシュヒットが 10 倍安い構造であるため、長い会話ほどプレフィックスを固定しておくことが重要になります。この原理は [詳細 → プロンプトキャッシング](#/post/ai-prompt-caching) にあります。

Hugging Face カードのライセンス名は「Kimi K3 License」であり、コードと重みにも適用されます。LICENSE ファイルを開いて確認した内容は以下の通りです。

- 使用・複製・修正・配布・再ライセンス・販売ならびに実行・配布・ファインチューニング・派生物の作成が無料で行えます。
- 条件は著作権表示を残し、法律を遵守することです。
- 第三者に対して推論やファインチューニングを API などの形で提供する「Model as a Service（MaaS）」事業では、合計売上高が 12 ヶ月連続で 2000 万ドルを超えた場合は Moonshot と別途契約が必要です。
- 月間アクティブユーザーが 1 億人以上または月間売上が 2000 万ドルを超える製品については、UI に「Kimi K3」を目立たせるように表示する必要があります。
- 内部使用ならびに Moonshot 公式製品や認証された推論パートナーを通じた使用は、この MaaS・表示義務から除外されます。

個人や小規模チームでの利用にはほとんど問題がなく、このモデルを使って他人に対して API を販売しようとする場所だけが線引きされています。ライセンス原文は法的文書なので、実際に商用サービスで使用する際は原文を直接読む必要があります。

## 読み終えての感想

「オープンウェイト」という言葉が「自分の PC で動かすこと」を意味するわけではないことを、このモデルが最もよく示しているように思えます。重みは誰でも入手できますが、全体のプロフェッショナルなレベルで動作させるメモリを持つ環境は多くありません。そのため、カードには API、サービングエンジン、GGUF などの複数の経路を一括して案内しているようです。自分の側から利用する場合は、ローカルよりも互換性のある API に先に接続するのが現実的でしょう。キャッシュヒット率が低く設定されているため、エージェントのように長いコンテキストを繰り返し送る用途に適した価格感も受かりました。

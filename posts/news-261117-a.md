오늘 아침 GitHub 트렌딩(weekly) 두 번째에 meta/astryx가 있었다. 이번 주에만 별 13,501개, 레포 전체 별은 29,564개다(11월 17일 오전 확인). Meta가 사내에서 8년 쓰던 디자인 시스템을 오픈소스로 푼 건데, 소개 문구가 "agent ready"다. 나는 README, CLI README, 공식 블로그 몇 편을 읽었고 직접 깔아 보지는 않았다.

## 뭐 하는 물건인지
디자인 시스템은 버튼, 입력칸, 표 같은 화면 부품과 색·글꼴·간격 규칙을 한 벌로 묶어 둔 것이다. 팀마다 버튼을 새로 만들지 않게 해 준다. Astryx는 React 19 이상에서 쓰는 컴포넌트 150개 넘게, 테마 7개, 페이지 템플릿, 그리고 CLI로 되어 있다. README에는 Meta 안에서 13,000개 넘는 앱이 이걸 쓴다고 적혀 있다. 라이선스는 MIT, 아직 베타다.

스타일은 Meta의 StyleX로 짰지만 쓰는 쪽은 그걸 몰라도 된다. 미리 만든 CSS를 import하고 테마 provider로 감싸면 끝이고, 덮어쓸 땐 Tailwind든 그냥 CSS든 `className`으로 한다. 테마는 CSS 변수(색, 글꼴, 모서리 둥글기 같은 값) 묶음이라 컴포넌트 코드를 고치지 않고 브랜드 색을 입힌다. 더 깊이 바꾸고 싶으면 `swizzle`로 컴포넌트 원본을 내 프로젝트에 복사해 와서 직접 가진다.

## 에이전트용이라는 게 뭔지
여기가 다른 디자인 시스템과 갈리는 부분이다. 문서를 웹사이트로만 두지 않고 CLI가 문서 역할을 한다.

1. `astryx search button`처럼 찾으면 컴포넌트, 훅, 문서, 템플릿을 한 목록으로 보여 주고, 결과마다 다음에 칠 명령을 붙여 준다.
2. `astryx component Button`으로 props와 예시를 읽는다. 모든 명령에 `--json`이 있어서 에이전트는 정해진 모양의 JSON으로 받는다. 오타를 내면 에러에 "혹시 Button?" 같은 후보가 같이 온다.
3. `astryx build "<만들 페이지 설명>"`을 치면 어느 템플릿에서 시작할지와 빠진 부품을 알려 준다. 페이지를 처음부터 짜지 말고 템플릿에서 시작하라는 거다.
4. 끝내기 전에 날 `<div>`, 직접 쓴 `#hex` 색이나 `px` 값을 컴포넌트나 토큰으로 바꾸라고 한다.

이 흐름이 스킬 파일 한 장으로 들어 있다. 스킬은 에이전트가 필요할 때 꺼내 읽는 작업 설명서다. CLI를 전역 설치하면 `~/.agents/skills/astryx/SKILL.md`에 같은 내용이 깔리고, Claude Code와 Codex용 플러그인도 레포에 있다. 스킬에는 컴포넌트 문서를 넣지 않고 "astryx 명령에 물어봐라"만 적어 둔다. 문서는 설치된 버전의 CLI가 답하니까 스킬이 낡을 일이 적다. [자세히 → 스킬](#/post/ai-skills) [자세히 → 컨텍스트 엔지니어링](#/post/ai-context)

블로그 글 하나가 이 설계를 잘 설명한다. 처음엔 에이전트가 Astryx를 거의 안 쓰고 div만 잔뜩 낸 페이지를 돌려줬는데, 알고 보니 자기들 템플릿이 그 모양이어서 그대로 베꼈던 거라고 한다. 그래서 템플릿 채점 기준을 만들고 템플릿을 다시 다듬었더니 결과가 따라왔다고. 제목이 "AI is a copycat so we gave it good examples to copy"다.

또 하나는 "vibe test"라는 자체 평가다. 아무 맥락 없는 에이전트에게 유도 없는 프롬프트로 화면을 만들게 하고, 같은 분석기로 Astryx, Tailwind, shadcn, 그냥 HTML 결과를 똑같이 채점한다고 한다. 처음엔 "Astryx를 우리가 원하는 대로 썼나"를 쟀는데 그건 자기들한테 유리한 시험이라 바꿨다고 적혀 있다. 채점 수치는 그 글에서 확인 못 함.

## 왜 화제인지
오픈소스 공개 자체는 6월이다(공식 소개 글 6월 18일). 이번 주에 다시 뜬 건 몇 가지가 겹친 것 같다. 11월 12일 샌프란시스코 밋업이 있었고, 11월 14일에는 Vercel의 v0에서 디자인 시스템 스킬로 Astryx를 고를 수 있게 됐다. 릴리스도 11월 10일부터 14일(한국 시간)까지 v0.7.12에서 v0.7.16까지 다섯 번 나왔다.

X에서 "astryx"가 들어간 글은 11월 10일(UTC) 211건으로 가장 많았고 이후 하루 70~130건 정도였다(리트윗 제외). 같은 단어를 다른 뜻으로 쓴 글이 섞였을 수 있다. Reddit과 YouTube에서 얼마나 돌았는지는 확인 못 함.

## 입문자 입장에서
PM 입장에서 눈에 띈 건 "AI가 만든 화면이 왜 다 비슷하게 어설픈가"에 대한 답이 모델이 아니라 보여 준 예시 쪽에 있었다는 점이다. 에이전트에게 화면을 맡길 거면 좋은 템플릿과 금지 목록을 먼저 쥐여 주는 게 프롬프트를 다듬는 것보다 싸게 먹힐 수 있다.

개발 입문자라면 설치 전에 공식 사이트의 Playground나 Storybook에서 컴포넌트를 구경하고, 프로젝트에서 `npx @astryxdesign/cli search <찾는 것>`부터 쳐 보는 게 가벼운 시작 같다. README에 주의가 하나 있다. CLI를 설치하기 전에 `npx astryx`처럼 짧은 이름으로 치면 상관없는 다른 npm 패키지가 실행된다. 에이전트에게 웹 코드를 요즘 방식으로 쓰게 하는 스킬 얘기는 며칠 전 글과 같이 보면 좋다. [자세히 → Modern Web Guidance](#/post/news-261114-a)

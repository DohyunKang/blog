今天早上 GitHub 趋势榜的周榜上有 ag-ui-protocol/ag-ui。本周 2,966 星，仓库总共 21,562 星(11 月 25 日上午确认)。AG-UI 是一个公开规范，规定 AI 代理和用户看到的应用界面之间传递的数据长什么样。我读了 README、docs 里的概念文档(architecture、tools、state、interrupts)、1.0 变更页面和最近的提交记录。没有自己跑服务器。

## 它规定什么
普通的 Web 是发一个请求、收一个响应就结束。代理不是这样。它一点点地输出文字，中途调用工具，停下来等人确认，还会启动子代理。README 开头讲的就是这个：每个框架把这些展示到界面上的方式都不一样，所以每个应用都得重新写一遍对接代码。

AG-UI 把这些统一成一条事件流。事件就是"刚刚发生了这件事"的短消息。代理按顺序发出规定类型的事件，应用接收后渲染出来。不管代理是用 LangGraph 还是 CrewAI 做的，应用这边的代码都不用变。

README 里说明它定位的那张图挺好懂。MCP 给代理接上工具和数据，A2A 让代理之间协作，AG-UI 把代理带到用户面前。说法是三者不重叠。MCP 是让代理像调用工具一样调用外部程序功能的连接规范。[详细 → MCP](#/post/ai-mcp)

## 结构
开头很简单。应用用 HTTP POST 发送 `RunAgentInput`(线程 ID、运行 ID、到目前为止的消息、应用提供的工具列表、共享状态)，代理以流的形式返回事件。默认传输方式是 SSE。SSE(Server-Sent Events)是服务器保持一个连接、持续推送文本的 Web 标准。从 1.0 起，用 Protobuf 打包的二进制传输方式也写进了规范。

事件分成几组。
- 运行开始和结束: `RUN_STARTED`、`RUN_FINISHED`、`RUN_ERROR`
- 回答文字: `TEXT_MESSAGE_START` → `CONTENT`(片段) → `END`
- 工具调用: `TOOL_CALL_START` → `ARGS`(参数 JSON 分段) → `END` → `RESULT`
- 共享状态: `STATE_SNAPSHOT`(全部)、`STATE_DELTA`(只发变化的部分)

README 示例里的 Python 服务器三十行左右，做的事只是依次发送开始事件、三次文字事件和结束事件。规范要求的最低限度大概就是这些。

## 一部分工具握在界面手里
读的时候最显眼的是把工具分成两种的做法。代理服务器本来就有的工具留在服务器上。另外，应用每次运行时可以在 `RunAgentInput.tools` 里附上一个列表，说"这次可以用这些工具"，比如弹出确认框、跳转页面之类。代理调用它们时，真正执行发生在应用里。

tools 文档给出的理由是权限。给这个用户开放哪些功能由应用决定，敏感操作由应用而不是代理控制。代理只负责判断，动手的是应用。如果对工具调用本身好奇，[详细 → 工具调用](#/post/ai-tool-use)

## 状态是一起看同一个 JSON
共享状态是代理和应用一起看的一个 JSON 对象。一开始用 `STATE_SNAPSHOT` 整个发过去，之后用 `STATE_DELTA` 只发变化的部分。delta 用的是 JSON Patch(RFC 6902)格式，一种把"把这个路径的值改成这个"之类的指令写成列表的标准。连接断开重连后，重新拿一次快照来对齐。代理在填表的时候，界面也能跟着一起填。

## 停下来再接着做
需要人确认时的处理相当严格。代理不会开着运行等待。它先把继续所需的状态和消息以快照发出，再在 `RUN_FINISHED` 里带上"interrupt"结果，结束这次运行。用户批准后，应用在同一个线程上开始新的运行，把答复放进 `resume` 发过去。

规则也写在文档里。所有未关闭的 interrupt 都必须回答，不能只答一部分。在有待答 interrupt 的线程上不带 resume 发送新输入会报错。同一个 resume 发两次也必须安全，过了截止时间(`expiresAt`)的答复会被拒绝。连有人连点两次批准按钮、或者很久之后才点的情况，规范都提前定好了。

## 为什么现在火
仓库是 2025 年 5 月建的，不是新东西。1.0 也是 9 月发布的(npm `@ag-ui/core` 1.0.0 在 9 月 17 日 UTC)。根据 1.0 变更页面，0.x 时期行为规则实际上只存在于 TypeScript 客户端代码里，1.0 第一次用文档和 JSON Schema 把规则定下来。TypeScript、Python、.NET 的 SDK 都从这份 schema 生成。子代理事件、推理过程事件(取代旧的 THINKING 事件)、说明运行如何结束的 `outcome` 也是那时加入的。

这周星数集中上涨的确切原因没有确认。不过提交每天都在增加。11 月 17 日发布了 SDK 1.0.5 和 Cloudflare Agents 集成 0.1.0，之后 LangGraph、Google ADK、OpenAI Agents 的集成包也陆续更新。README 写着 Google、Microsoft、Amazon、Oracle 已经采用，这是 README 的说法，我没有另外去核对各公司自己的公告。以前在 Microsoft Agent Framework 的发布说明里见过 AG-UI 端点。[详细 → Microsoft Agent Framework](#/post/news-harness-2)

下载量很大。npm `@ag-ui/core` 在 11 月 17~23 日一周下载 8,050,853 次。这个数字包含被其他包作为依赖拉下来的部分，不能当成直接使用的人数来看。X 上提到"AG-UI"的帖子(不含转推，按 UTC 日)11 月 18 日最多，59 条，其他日子 14~25 条。Reddit 上的反应没有确认。

## 站在入门者的角度
代理演示通常就是一个聊天框，但真正的服务会加上批准按钮、进度提示、代理填写的表格这类界面。AG-UI 就是事先定好的、这个界面和代理之间的约定。前端和后端只要对齐这份事件列表，就能分开开发。

对 PM 来说有用的是 interrupt 规则。"人批准后继续"在需求文档里写一行很容易，但要真正做出来，还得定好点两次、晚点、只批准一部分时怎么办。这份规范可以当作对这些问题提前写好的一份答案来读。如果对子代理不熟，[详细 → 子代理](#/post/ai-subagent)

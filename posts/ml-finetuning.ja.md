ファインチューニングとは、事前学習が完了したモデルを自社のデータで再度学習させることです。モデル全体を変更するか一部のみを追加するかによって必要な GPU の量は大きく異なります。

## ファインチューニングとは何か

[LLM](#/post/ai-llm) はまず膨大なテキストで事前学習を行います。この段階では言語全般を習得し、ここまでは個人が実施するのは困難です。これは [事前学習から RLHF まで](#/post/ml-pretraining) で整理した部分です。ファインチューニングはその後に追加する二番目の学習工程です。すでに会話をできるモデルに対して、特定の口調、特定の形式、特定分野の問題解決を 추가로 가르친다.

まとめると以下のようになります。

| | 事前学習 | ファインチューニング |
|---|---|---|
| データ | 膨大な一般テキスト | 数百〜数万程度の目的データ |
| 目的 | 言語と知識の基盤 | 特定の行動・形式・口調 |
| 出発点 | ランダムな重み | 既に学習済みの重み |
| コスト | 個人では実施困難 | モデルや手法によって異なります |

データは通常、「入力と望ましい出力」のペアです。質問と正解、長い文書と要約などがあります。このペアをモデルに示しながら重みを少しずつ調整します。学習方法は事前学習と同じ [ニューラルネットワーク学習](#/post/ml-neural-net) であり、変わったのはデータと出発点だけです。

## なぜフルファインチューニングは重いのか

フルファインチューニング（full fine-tuning）ではモデルのすべての重みを更新します。問題はメモリです。学習するには重みの他にも勾配やオプティマイザの状態を保持する必要があります。Adam 系オプティマイザはパラメータごとに値を 2 つ追加で保存するため、学習に必要なメモリはモデルサイズの数倍になります。

数字を一つ例示すると、70 億パラメータのモデルを 16 ビット（2 バイト）で読み込むだけでも重みだけで約 14GB です。学習時にはこれに勾配とオプティマイザの状態が加わります。正確な倍率は精度とオプティマイザの設定によって異なります。

もう一つはコピーの問題です。用途ごとにファインチューニングすると、用途ごとにモデル全体のコピーが発生します。7B モデルのコピーが 14GB なら、用途が 10 つだと 140GB です。

## LoRA のアイデア

LoRA（Low-Rank Adaptation）は 2021 年に Hu らの論文で発表されました。事前学習済みの重みは凍結（freeze）し、各層に学習可能な小さな行列を挿入する方式です。論文の要約では GPT-3 175B を基準として学習すべきパラメータが約 10,000 分の 1 に減少し、GPU メモリ要件は約 3 分の 1 に減少すると記載されています。性能については RoBERTa、DeBERTa、GPT-2、GPT-3 でフルファインチューニングと同等かそれ以上であるとされています。推論時の遅延が増加しない点も要約に記載されています。

原理は以下の通りです。重みの一つ（行列 W、サイズ d×k）を直接変更する代わりに、変化量 ΔW を 2 つの小さな行列の積で表現します。

```
W' = W + (alpha / r) * B @ A
     W: d x k (고정)
     B: d x r, A: r x k (이것만 학습, r은 d, k보다 훨씬 작다)
```

r はランクです。d=k=4096 で r=8 の場合、W は約 1,678 万個、A と B を合わせると約 6 万 5 千個です。この一つの行列だけ見ても 256 分の 1 です。PEFT ドキュメントでは学習パラメータ数は「ランク r と元の行列の形状によって決定される」と説明しています。r が小さいほど行列は小さくなります。

初期値も注目すべき点です。B は 0 で、A はランダムに開始します。そのため学習開始時点では B@A は 0 であり、モデルは元のモデルと同じように動作します。そこから少しずつ逸れていきます。以下 numpy で直接確認しました。

<details>
<summary>詳細な解説：numpy で LoRA を確認したコード</summary>

```python
import numpy as np
rng = np.random.default_rng(0)
d, k, r, alpha = 64, 64, 4, 8
W = rng.normal(size=(d, k))
A = rng.normal(size=(r, k)) * 0.01
B = np.zeros((d, r))
x = rng.normal(size=(k,))

# 1) B가 0이면 LoRA를 붙여도 출력이 그대로
print(np.allclose(W @ x, (W + (alpha / r) * B @ A) @ x))   # True

# 2) 학습 후라고 치고 B를 바꾸면, 따로 계산한 것과 합쳐서 계산한 것이 같다
B = rng.normal(size=(d, r)) * 0.1
y_split  = W @ x + (alpha / r) * (B @ (A @ x))
y_merged = (W + (alpha / r) * B @ A) @ x
print(np.allclose(y_split, y_merged))                       # True
print(W.size, A.size + B.size)                              # 4096 512
```

実行結果は True, True, 4096 512 でした。二番目の確認は「足しても同じ」という部分です。以下にマージの話が出てきます。

## どこに付け、何を調整するか

PEFT ドキュメントによると LoRA はどの重み行列にも適用可能ですが、Transformer では通常アテンションブロックのみを対象とします。[Transformer とアテンション](#/post/ml-transformer) で見たクエリ・キー・バリュー射影行列がその対象です。どの層に付けるかは `target_modules` で指定します。

よく触れる値は 3 つあります。

| 設定 | 役割 |
|---|---|
| `r` | ランク。小さければパラメータ数が少なく、大きくなれば表現力が増します |
| `lora_alpha` | スケール。デフォルトでは alpha / r 倍に掛かります |
| `target_modules` | LoRA を付ける層 |

どの値が適切かはモデルとデータによって異なり、ドキュメントも値を断定していません。

## マージとアダプター

学習が完了すると B と A は容量の小さい別ファイル（アダプター）として保存されます。使い方は 2 つあります。

- 어댑터를 기본 모델 위에 얹어서 사용합니다. 하나의 기본 모델에 어댑터를 바꿔 끼우면 용도마다 사본이 필요 없습니다.
- `merge_and_unload()`로 W 에 합쳐서 일반 모델 하나로 만듭니다. 위 numpy 두 번째 확인처럼 결과가 같아서, 합친 뒤에는 추가 지연이 없습니다. PEFT 문서가 "LoRA 는 추론 지연을 더하지 않는다"고 쓰는 이유가 이것입니다.

사본 문제도 해결됩니다. 어댑터 파일은 기본 모델에 비해 훨씬 작고, 정확한 크기는 r 과 대상 층에 따라 달라집니다.

## QLoRA: 기본 모델까지 줄이기

LoRA 는 학습할 파라미터를 줄였지만 기본 모델은 여전히 16 비트로 메모리에 올려야 합니다. QLoRA(Dettmers 등, 2023) 는 기본 모델을 4 비트로 양자화해서 올려 두고, 그 위에서 LoRA 어댑터만 학습하는 방식입니다. 기울기는 얼린 4 비트 모델을 통과해서 어댑터까지 흘러갑니다.

논문 초록이 드는 기법은 세 가지입니다.

- 4 비트 NormalFloat(NF4): 정규분포를 따르는 가중치에 맞춘 4 비트 자료형
- 이중 양자화(double quantization): 양자화에 쓰는 상수까지 다시 양자화해 메모리를 더 줄임
- 페이지드 옵티마이저(paged optimizers): 학습 중 메모리가 튀는 구간을 관리

논문은 650 억 파라미터 모델을 48GB GPU 한 장에서 파인튜닝할 수 있고, 16 비트 파인튜닝 성능을 유지한다고 주장합니다. 이 비교는 저자들의 실험 조건에서 나온 결과입니다. 이 방식으로 만든 Guanaco 모델 계열은 Vicuna 벤치마크에서 당시 공개 모델 중 가장 좋았고, GPU 한 장에서 24 시간 학습으로 ChatGPT 수준의 99.3% 에 닿았다고 합니다. 벤치마크 하나 기준이라 다른 과제에서도 그런지는 별개 문제입니다. 4 비트로 양자화된 모델은 [로컬 모델 돌리기](#/post/ml-local-models) 에서 다루는 것과 같은 계열의 아이디어입니다.

## 언제 파인튜닝이고 언제 RAG 인가

둘은 풀려는 문제가 다릅니다. [RAG](#/post/ai-rag) 는 질문마다 관련 문서를 찾아 [프롬프트](#/post/ai-prompt) 에 붙여서 모르는 것을 보충합니다. 파인튜닝은 모델의 행동 자체를 바꿉니다.

| | RAG | 파인튜닝 |
|---|---|---|
| 잘 맞는 일 | 최신·사내 정보, 출처 제시 | 말투, 출력 형식, 특정 작업 방식 |
| 정보가 바뀌면 | 문서만 고치면 됨 | 다시 학습해야 함 |
| 준비물 | 문서와 검색 환경 | 입출력 쌍 데이터와 GPU |
| 추론 때 | 검색 비용과 긴 프롬프트 | 프롬프트가 짧아질 수 있음 |

지식을 모델에 넣는 용도로 파인튜닝을 쓰려는 경우가 많은데, 그 판단은 신중하게 해야 합니다. 학습시킨 내용을 모델이 정확히 기억하리라는 보장이 없고, 어느 문서에서 나온 말인지도 알려 주지 않습니다. 틀린 말을 자신 있게 하는 [할루시네이션](#/post/ai-hallucination) 문제도 그대로 남습니다.

순서로는 프롬프트를 고치는 것부터 시작하고, 정보가 모자라면 RAG, 그래도 형식이나 말투가 안 잡히면 파인튜닝을 검토하는 흐름이 보통입니다. 둘을 같이 쓰는 경우도 많습니다.

## 흔한 오해

- LoRA 는 모델을 작게 만드는 기술이다: 기본 모델 크기는 그대로고, 학습하는 부분만 작습니다. 추론 때는 기본 모델이 필요합니다. 모델 크기를 줄이는 쪽은 양자화입니다.
- QLoRA 는 LoRA 보다 성능이 낮다: 논문은 16 비트 파인튜닝 성능을 유지한다고 주장하지만 조건부 결과입니다. 늘 같다는 뜻은 아닙니다.
- 파인튜닝하면 새 지식이 들어간다: 형식·말투를 가르치는 데는 확실히 쓰이지만, 지식 주입은 RAG 가 더 안정적인 경우가 많습니다.
- 데이터가 많을수록 무조건 좋다: 양보다 품질이 더 자주 거론됩니다.

[추론 최적화](#/post/ml-inference) 는 병합하고 난 모델을 어떻게 빠르게 돌리는지를 다룹니다.

정보처리기사 자료구조 단원은 개념을 외우는 것보다 손으로 따라가는 연습이 점수로 이어지는 쪽이다. 스택에 뭐가 남는지, 트리를 돌면 어떤 순서로 나오는지, 그래프에서 어디부터 방문하는지를 종이에 그려 보는 유형이 반복된다. 이 글은 그 흐름대로 정리했다. 시험 일정과 응시 관련 내용은 공식 사이트에서 확인한다.

## 한눈에 보는 분류

| 구분 | 종류 | 핵심 질문 |
|---|---|---|
| 선형 | 배열, 연결 리스트, 스택, 큐, 덱 | 어느 쪽 끝으로 넣고 빼나 |
| 비선형 | 트리, 그래프 | 어떤 순서로 방문하나 |

선형은 데이터가 한 줄로 늘어선 구조이고, 비선형은 한 노드에서 여러 갈래로 뻗는 구조다. 시험에서는 "다음 중 선형 구조가 아닌 것" 같은 분류 확인과, 연산을 순서대로 적용한 결과를 묻는 문제로 나뉘어 나온다.

## 선형 구조

배열은 인덱스로 바로 접근하지만 중간에 끼워 넣으면 뒤를 밀어야 한다. 연결 리스트는 노드가 다음 노드를 가리키는 방식이라 끼워 넣기는 포인터만 바꾸면 되고, 대신 i번째를 찾으려면 앞에서부터 따라가야 한다.

| | 접근 | 중간 삽입·삭제 |
|---|---|---|
| 배열 | 빠름(인덱스) | 느림(밀어야 함) |
| 연결 리스트 | 느림(따라가야 함) | 빠름(포인터 변경) |

스택은 한쪽 끝에서만 넣고 빼는 후입선출(LIFO), 큐는 뒤로 넣고 앞에서 빼는 선입선출(FIFO), 덱은 양쪽 모두 가능하다. 스택은 함수 호출, 되돌리기, 괄호 검사에 쓰이고, 큐는 순서대로 처리하는 작업 대기열에 쓰인다. 파이썬에서 큐를 만들 땐 리스트의 `pop(0)`이 O(n)이라서 `deque`를 쓴다. 공식 문서에도 deque의 양 끝 추가·삭제는 대략 O(1), 리스트의 `pop(0)`은 O(n)이라고 나와 있다. 코딩 문제 쪽 이야기는 [자세히 → 스택·큐·덱](#/post/algo-stack-queue)에 따로 적었다.

시험에서 스택은 거의 "수식 표기 변환"으로 나온다.

### 수식 표기법

연산자를 어디에 두느냐에 따라 세 가지다.

| 이름 | 연산자 위치 | 예 (A+B) |
|---|---|---|
| 전위(prefix) | 피연산자 앞 | +AB |
| 중위(infix) | 가운데 | A+B |
| 후위(postfix) | 뒤 | AB+ |

중위를 후위로 바꾸는 규칙은 이렇다. 피연산자는 바로 출력하고, 연산자는 스택에 넣되 스택 맨 위 연산자의 우선순위가 같거나 높으면 먼저 꺼내 출력한다. 여는 괄호는 스택에 넣고 닫는 괄호를 만나면 여는 괄호까지 꺼낸다. 마지막에 스택에 남은 걸 전부 꺼낸다. 이 규칙대로 직접 짠 코드를 돌려 본 결과는 아래와 같다.

| 중위식 | 후위식 |
|---|---|
| A+B*C | ABC*+ |
| (A+B)*C | AB+C* |
| A-B-C | AB-C- |

세 번째처럼 우선순위가 같으면 왼쪽 것이 먼저 나간다(왼쪽 결합). 후위식 계산은 더 쉽다. 왼쪽부터 읽으며 숫자는 스택에 쌓고, 연산자를 만나면 두 개를 꺼내 계산해서 다시 넣는다. `3 4 2 * +`는 4*2=8을 만들고 3+8=11이 된다. 꺼낼 때 먼저 나온 값이 오른쪽 피연산자라는 점만 조심하면 된다(뺄셈·나눗셈에서 순서가 바뀐다).

<details>
<summary>변환·계산 코드 (직접 실행해서 위 결과를 확인함)</summary>

```python
def topost(s):
    pr = {'+': 1, '-': 1, '*': 2, '/': 2}
    st, out = [], []
    for c in s:
        if c.isalnum():
            out.append(c)
        elif c == '(':
            st.append(c)
        elif c == ')':
            while st[-1] != '(':
                out.append(st.pop())
            st.pop()
        else:
            while st and st[-1] != '(' and pr[st[-1]] >= pr[c]:
                out.append(st.pop())
            st.append(c)
    while st:
        out.append(st.pop())
    return ''.join(out)

print(topost('A+B*C'), topost('(A+B)*C'), topost('A-B-C'))
# ABC*+ AB+C* AB-C-

def ev(s):
    st = []
    for c in s.split():
        if c in '+-*/':
            b = st.pop(); a = st.pop()
            st.append({'+': a+b, '-': a-b, '*': a*b, '/': a/b}[c])
        else:
            st.append(float(c))
    return st[0]

print(ev('3 4 2 * +'))  # 11.0
```

</details>

## 트리

트리는 사이클이 없는 연결 구조다. 용어는 시험에 그대로 나온다.

| 용어 | 뜻 |
|---|---|
| 루트 | 부모가 없는 맨 위 노드 |
| 단말(리프) | 자식이 없는 노드 |
| 차수 | 한 노드의 자식 수 (트리의 차수는 노드 차수 중 최댓값) |
| 깊이·높이 | 루트에서 내려온 거리 / 가장 깊은 곳까지의 길이 |

노드가 n개인 트리의 간선은 n-1개다. 이진 트리는 노드마다 자식이 최대 2개다. 이진 트리의 레벨 i에는 노드가 최대 2^(i-1)개 있고(루트가 레벨 1일 때), 높이 h짜리 이진 트리의 노드는 최대 2^h - 1개다. 문제에서 루트를 레벨 0으로 보는지 1로 보는지에 따라 식이 달라지니 조건부터 읽어야 한다.

### 순회 (제일 자주 나오는 부분)

깊이 우선 세 가지는 "자기 자신을 언제 방문하나"만 다르다. 왼쪽 서브트리를 오른쪽보다 먼저 방문하는 건 셋 다 같다.

| 이름 | 순서 | 외우는 법 |
|---|---|---|
| 전위 | 자신 → 왼쪽 → 오른쪽 | 자신이 앞(Preorder) |
| 중위 | 왼쪽 → 자신 → 오른쪽 | 자신이 가운데 |
| 후위 | 왼쪽 → 오른쪽 → 자신 | 자신이 뒤 |

레벨 순회는 위층부터 한 층씩 방문하고, 큐로 구현한다. 아래 트리로 직접 돌려 본 결과다.

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

| 순회 | 결과 |
|---|---|
| 전위 | A B D E C F |
| 중위 | D B E A C F |
| 후위 | D E B F C A |
| 레벨 | A B C D E F |

전위·중위·후위가 한 노드를 보는 시점만 다른 것이므로, 노드마다 "세 번 들르는 점"을 찍어 가며 읽으면 실수가 줄었다. 자기를 지나는 순간 왼쪽 옆을 찍으면 전위, 아래를 찍으면 중위, 오른쪽 옆을 찍으면 후위가 되는 식이다.

순회 결과 두 개로 트리를 복원하는 문제도 나온다. 값이 중복되지 않는 트리라면 전위와 중위의 쌍이 트리 모양을 하나로 정한다. 전위·후위 쌍은 늘 그렇지는 않다는 점이 같이 알려져 있다. 복원 방법은 이렇다. 전위의 첫 값이 루트, 그 값을 중위에서 찾으면 왼쪽에 있는 것이 왼쪽 서브트리, 오른쪽이 오른쪽 서브트리다. 이걸 재귀로 반복한다.

<details>
<summary>순회·복원 코드 (실행 확인)</summary>

```python
from collections import deque

class N:
    def __init__(s, v, l=None, r=None):
        s.v, s.l, s.r = v, l, r

def pre(n):  return [] if not n else [n.v] + pre(n.l) + pre(n.r)
def ino(n):  return [] if not n else ino(n.l) + [n.v] + ino(n.r)
def post(n): return [] if not n else post(n.l) + post(n.r) + [n.v]

def level(n):
    q, out = deque([n]), []
    while q:
        x = q.popleft(); out.append(x.v)
        if x.l: q.append(x.l)
        if x.r: q.append(x.r)
    return out

t = N('A', N('B', N('D'), N('E')), N('C', None, N('F')))
print(pre(t), ino(t), post(t), level(t))

def build(p, i):                      # 전위 + 중위 -> 트리
    if not p: return None
    k = i.index(p[0])
    return N(p[0], build(p[1:k+1], i[:k]), build(p[k+1:], i[k+1:]))

print(post(build(list('ABDECF'), list('DBEACF'))))
# ['D', 'E', 'B', 'F', 'C', 'A']
```

</details>

### 이진 탐색 트리와 힙

이진 탐색 트리(BST)는 왼쪽 자식이 부모보다 작고 오른쪽이 크다는 규칙을 지키는 트리다. 이 트리를 중위 순회하면 값이 오름차순으로 나온다. 50, 30, 70, 20, 40, 60, 80을 차례로 넣고 중위 순회하면 20 30 40 50 60 70 80이 나왔다.

탐색·삽입·삭제는 평균 O(log n)이다. 다만 모양이 입력 순서에 좌우돼서, 10, 20, 30, 40처럼 정렬된 채로 넣으면 한쪽으로만 늘어진 연결 리스트 꼴이 되어 최악 O(n)이 된다. 위 트리는 높이가 3, 정렬된 4개는 높이가 4였다. 이 문제를 막으려고 균형을 유지하는 트리(AVL 등)가 있다. AVL은 최초의 자가 균형 이진 탐색 트리로 알려져 있고, 삽입·삭제 때마다 높이를 점검해 고친다.

힙은 부모가 자식보다 항상 크거나(최대 힙) 작은(최소 힙) 완전 이진 트리다. 최댓값·최솟값을 빨리 꺼내는 우선순위 큐에 쓴다. 파이썬 `heapq`로 5, 3, 8, 1, 2를 넣고 하나씩 꺼내면 1, 2, 3, 5, 8이 나왔다. 형제 사이에는 크기 규칙이 없다는 점이 BST와 다르다. 코딩 문제 관점은 [자세히 → 트리·힙·우선순위 큐](#/post/algo-tree-heap)에 있다.

## 그래프

그래프는 정점과 간선의 집합이다. 방향이 있으면 방향 그래프, 없으면 무방향 그래프다. 정점이 n개인 무방향 그래프의 간선은 최대 n(n-1)/2개다. 트리는 사이클이 없고 연결된 그래프의 한 종류라고 보면 된다.

표현 방법은 두 가지다. 아래 그래프(간선 1-2, 1-3, 2-4, 3-4, 4-5)로 확인했다.

| 방식 | 모양 | 공간 | 특징 |
|---|---|---|---|
| 인접 행렬 | n×n 표에 간선 있으면 1 | O(n²) | 두 정점이 이어졌는지 바로 확인 |
| 인접 리스트 | 정점마다 이웃 목록 | O(n+간선) | 간선이 적을 때 공간이 적음 |

무방향 그래프의 인접 행렬은 대각선 기준으로 대칭이다. 행렬의 1을 전부 더해 2로 나누면 간선 수 5가 나왔다. 정점 4의 이웃은 2, 3, 5이므로 차수가 3이다.

### 그래프 순회

깊이 우선(DFS)은 스택(또는 재귀)으로, 너비 우선(BFS)은 큐로 한다. 정점 1에서 시작하고 번호가 작은 이웃부터 방문하면 이렇게 된다.

| 방식 | 방문 순서 |
|---|---|
| DFS | 1 2 4 3 5 |
| BFS | 1 2 3 4 5 |

시험에서는 "이웃을 어느 순서로 고르는지" 조건이 문제에 적혀 있으니 그대로 따르면 된다. 트리 순회와 마찬가지로 BFS = 큐, DFS = 스택이라는 짝만 기억하면 풀이 방향은 정해진다. 구현은 [자세히 → BFS·DFS와 그래프](#/post/algo-graph-search)에 있다.

<details>
<summary>그래프 코드 (실행 확인)</summary>

```python
from collections import deque

E = [(1, 2), (1, 3), (2, 4), (3, 4), (4, 5)]
adj = {i: [] for i in range(1, 6)}
for a, b in E:
    adj[a].append(b); adj[b].append(a)

def dfs(g, s):
    seen, st = [], [s]
    while st:
        x = st.pop()
        if x in seen: continue
        seen.append(x)
        for y in sorted(g[x], reverse=True):   # 작은 번호가 먼저 나오도록
            st.append(y)
    return seen

def bfs(g, s):
    seen, q = [s], deque([s])
    while q:
        x = q.popleft()
        for y in sorted(g[x]):
            if y not in seen:
                seen.append(y); q.append(y)
    return seen

print(dfs(adj, 1), bfs(adj, 1))
# [1, 2, 4, 3, 5] [1, 2, 3, 4, 5]
```

</details>

## 자주 나오는 유형과 푸는 순서

| 유형 | 푸는 순서 |
|---|---|
| 스택·큐 연산 결과 | 연산을 하나씩 적용하며 현재 내용을 종이에 적는다 |
| 수식 표기 변환·계산 | 우선순위와 괄호 → 스택 규칙대로 |
| 트리 순회 결과 | 자신을 방문하는 시점을 확인하고 왼쪽부터 내려간다 |
| 순회 두 개로 복원 | 전위 첫 값 = 루트, 중위에서 좌우를 가른다 |
| 노드·간선 수 계산 | 노드 n개 트리는 간선 n-1, 높이 h 이진 트리는 최대 2^h - 1 |
| 그래프 순회 | 시작 정점과 이웃 선택 조건을 확인, DFS=스택 BFS=큐 |
| 시간 복잡도 비교 | BST 평균 O(log n), 최악 O(n)를 구분 |

## 흔한 실수

- 큐와 스택의 꺼내는 쪽을 바꿔서 적용한다.
- 후위식 계산에서 뺄셈·나눗셈의 피연산자 순서를 뒤집는다.
- 레벨을 0부터 세는지 1부터 세는지 확인하지 않고 2^h 식을 쓴다.
- 중위와 후위 순회 결과를 헷갈린다. 노드가 루트일 때 후위는 맨 마지막, 전위는 맨 처음이라는 점으로 거른다.
- BST를 "항상 O(log n)"으로 외운다. 모양이 한쪽으로 쏠리면 O(n)이다.

정렬·탐색과 복잡도는 [자세히 → 정렬·탐색과 알고리즘 복잡도](#/post/jb-algorithm-complexity)에서 이어진다. 기출 문제는 원문을 옮기지 않았고, 유형만 정리했다. 실제 문제 풀이는 공식 기출 공개 자료로 연습하면 된다.

빅데이터분석기사 필기는 빅데이터 개요에서 시작한다. 이 단원은 계산이 없고 용어를 정확히 구분하는 문제가 대부분이라, 어떤 단어가 어디에 속하는지만 잡아 두면 점수가 나온다. 크게 네 덩어리다. 빅데이터의 특징, 데이터 유형, 가치 창출, 개인정보 보호.

## 빅데이터가 뭔지

IT위키는 빅데이터를 기존의 데이터 처리 능력을 넘어서는 대량의 데이터, 또는 그 데이터를 분석해서 가치를 만드는 기술이라고 적는다. 양만 많다고 빅데이터인 게 아니라 분석해서 쓰는 것까지 포함한다. 시험에서는 정의 자체보다 특징을 V로 묻는 경우가 많다.

## 특징은 V로 외운다

가트너가 제시한 3V가 기본이다.

| V | 뜻 |
|---|---|
| Volume(규모) | 처리하는 데이터의 양이 기존 데이터베이스보다 거대함 |
| Velocity(속도) | 데이터가 들어오고 나가는 속도가 매우 빠름 |
| Variety(다양성) | 비정형 데이터, 다크 데이터처럼 종류가 여러 가지임 |

여기에 IBM 등이 덧붙인 항목들이 있다.

| V | 뜻 |
|---|---|
| Veracity(신뢰성) | 대용량을 빠르게 처리하면서도 품질을 유지함 |
| Value(가치) | 모아서 빠르게 처리해 새로운 가치를 만듦 |
| Validity(타당성) | 다루지 못했던 대용량 데이터로 정확하게 분석·예측함 |
| Volatility(휘발성) | 결과가 의미를 갖는 기간 안에 처리함 |

3V에 가치를 더하면 4V, 거기에 신뢰성을 더하면 5V로 정리하는 방식이 있다. 다만 교재와 기관마다 V의 개수와 구성이 다르다. 4V의 네 번째를 신뢰성으로 두는 곳도 있다. 그래서 이 부분은 문제에 'V가 몇 개인가'가 나오면 교재 기준으로 맞추고, 보기에 나온 단어가 어느 V에 해당하는지 풀어서 읽는 쪽이 안전하다.

<details>
<summary>V 이름을 뜻에서 거꾸로 찾는 연습</summary>

보기가 이름 대신 설명으로 나오면 이렇게 푼다.

1. 양, 크기, 용량이라는 말이 보이면 규모다.
2. 실시간, 입출력이 빠르다는 말이 보이면 속도다.
3. 텍스트·영상·로그처럼 종류가 섞였다는 말이 보이면 다양성이다.
4. 품질을 유지한다는 말이 보이면 신뢰성, 새로운 가치를 만든다는 말이 보이면 가치다.
5. 정확한 분석·예측이면 타당성, 결과가 유효한 기간 안에 처리하면 휘발성이다.

신뢰성과 타당성은 둘 다 '믿을 만하다'로 읽혀서 자주 섞인다. 신뢰성은 데이터 품질 쪽, 타당성은 분석·예측의 정확도 쪽으로 구분해 두면 덜 헷갈린다.
</details>

## 데이터 유형

데이터는 구조가 얼마나 정해져 있는지로 나눈다. IT위키 기준으로 정리하면 이렇다.

| 유형 | 설명 |
|---|---|
| 정형 | 정해진 형태와 규칙적인 값. 기계 판독과 자동 연산이 가능. RDBMS 테이블, 스프레드시트 |
| 반정형 | 스키마(구조 정의)는 있지만 연산은 할 수 없음 |
| 비정형 | 스키마도 없고 연산도 할 수 없음 |

스키마가 있느냐와 연산이 되느냐 두 가지 기준으로 갈린다고 보면 된다. 정형은 둘 다 되고, 반정형은 스키마만 있고, 비정형은 둘 다 없다.

빅데이터가 커진 핵심 요인으로는 정형 데이터가 아니라 비정형 데이터의 증가가 꼽힌다. SNS, 스마트폰, 사물인터넷 센서에서 글, 사진, 영상, 로그가 쏟아져 나오기 때문이다. 대량의 반정형 데이터는 NoSQL로 유연하게 조회하고 갱신한다. 저장 쪽 이야기는 [자세히 → 데이터 수집과 저장](#/post/bd-collection-storage)에서 이어진다.

반정형 데이터가 실제로 어떻게 표로 바뀌는지는 pandas로 보면 감이 온다. JSON처럼 안쪽에 구조가 겹쳐 있는 데이터를 `json_normalize`로 펼쳤다. 항목이 없는 칸은 NaN으로 채워진다.

```python
import pandas as pd

raw = [
    {"user": "u1", "tags": ["x", "y"], "geo": {"city": "서울"}},
    {"user": "u2", "geo": {"city": "부산", "dist": "해운대"}},
]
print(pd.json_normalize(raw))
```

실행하면 열이 `user`, `tags`, `geo.city`, `geo.dist` 네 개로 나오고, u1에는 `geo.dist`가, u2에는 `tags`가 비어 있다. 레코드마다 가진 항목이 달라도 괜찮은 게 반정형의 성격이고, 분석하려면 이렇게 표로 펴는 전처리가 한 번 들어간다. 그 단계는 [자세히 → 데이터 전처리](#/post/bd-preprocessing)에서 다룬다.

## 가치 창출

같은 데이터라도 누가, 언제, 어떤 목적으로 쓰느냐에 따라 가치가 달라진다. 그래서 빅데이터의 가치는 한 번에 값을 매기기 어렵다. 이유로는 활용 방식의 다양화, 새로운 가치 창출, 분석 기술의 발전 세 가지가 든다.

주체별로는 이렇게 나눠 외운다.

| 주체 | 변화 |
|---|---|
| 기업 | 고객 행동 분석으로 시장 변화 예측, 원가 절감, 제품 차별화 |
| 정부 | 기상·교통·인구 데이터로 정책 수립, 재난 대비 |
| 개인 | 저렴하게 서비스를 이용하고 목적에 맞게 데이터를 활용 |

빅데이터가 오면서 데이터를 다루는 방식이 네 군데에서 바뀌었다는 내용이 자주 나온다.

| 이전 | 이후 | 바뀐 이유 |
|---|---|---|
| 사전처리 | 사후처리 | 형식을 미리 정하지 않고 모은 뒤 조합해서 숨은 정보를 찾음 |
| 표본조사 | 전수조사 | 처리 비용이 낮아져 전체를 분석함 |
| 질 | 양 | 많이 모으면 일부 오류가 있어도 전체 경향이 드러남 |
| 인과관계 | 상관관계 | 원인을 몰라도 함께 일어나는 현상을 활용함 |

마지막 줄은 오해하기 쉽다. 상관관계를 쓴다고 해서 상관이 곧 원인이라는 뜻은 아니다. 정책 효과나 의학처럼 인과를 따져야 하는 문제에는 여전히 인과 분석이 필요하다. 이 네 쌍은 [자세히 → 데이터의 가치와 미래](#/post/adsp-data-value)에 ADsP 쪽 정리가 따로 있어서 같이 보면 겹치는 부분이 정리된다.

<details>
<summary>보기가 방향을 뒤집어 낼 때</summary>

이 표는 '이전 → 이후' 방향이 핵심이라서 보기에서 방향만 바꿔 틀린 문장을 만든다. 예를 들어 '전수조사에서 표본조사로 바뀌었다', '양에서 질로 바뀌었다'는 식이다. 이후 쪽이 사후처리·전수조사·양·상관관계라는 것만 기억하면 바로 걸러진다.
</details>

## 개인정보를 가려서 쓰기

빅데이터는 사람에 관한 데이터를 많이 쓰기 때문에 개인정보를 가리는 방법이 시험에 따라붙는다. 2016년 6월 관계부처 합동으로 나온 개인정보 비식별 조치 가이드라인은 기법 다섯 가지를 단독 또는 섞어서 쓰도록 안내한다. 금융위원회 보도자료에 나온 기법 이름은 다음과 같다.

| 기법 | 이름으로 짐작되는 방향 |
|---|---|
| 가명처리 | 식별 값을 다른 값으로 바꿈 |
| 총계처리 | 개별 값 대신 합계·평균 같은 집계 값을 씀 |
| 데이터 삭제 | 식별 요소의 전부 또는 일부를 지움 |
| 범주화 | 값을 구간·범주로 묶음 |
| 데이터 마스킹 | 일부를 가려서 보이지 않게 함 |

보도자료는 기법 이름만 나열하고 정의는 적지 않았다. 세부 정의와 예시는 교재로 맞추는 게 좋다. 이름이 비슷한 가명처리와 마스킹, 총계처리와 범주화가 서로 섞이기 쉬우니 바꾸는지 가리는지, 개별 값을 남기는지 집계하는지로 나눠서 기억한다.

조치 절차는 네 단계다.

1. 사전검토: 개인정보에 해당하는지 본다. 해당하지 않으면 별도 조치 없이 활용할 수 있다.
2. 비식별 조치: 위 기법으로 식별 요소를 없앤다.
3. 적정성 평가: 외부 평가단이 조치가 적정했는지 본다. 이때 계량적 수단으로 k-익명성을 쓴다.
4. 사후관리: 안전한 활용과 오남용 방지를 위한 보호조치를 지킨다. 목적이 끝나면 파기하고, 접근권한을 관리하며, 재식별되면 처리를 중단하고 파기한다.

k-익명성은 같은 값을 가진 레코드를 k개 이상으로 만들어 특정 개인을 추론하기 어렵게 하는 개념이다. k=5면 같은 레코드가 최소 5개 있다.

범주화와 마스킹, k 확인을 pandas로 직접 해 봤다.

```python
import pandas as pd

df = pd.DataFrame({
    "id":   [1, 2, 3, 4, 5, 6],
    "age":  [23, 27, 24, 41, 45, 43],
    "city": ["서울"] * 3 + ["부산"] * 3,
})

# 범주화: 나이를 구간으로 묶는다
df["age_grp"] = pd.cut(df["age"], bins=[20, 30, 40, 50],
                       labels=["20대", "30대", "40대"], right=False)

# k 확인: 같은 (나이대, 도시) 조합이 몇 건씩인지
sizes = df.groupby(["age_grp", "city"], observed=True).size()
print(sizes)
print("k =", sizes.min())

# 마스킹: 전화번호 뒷자리 가리기
phone = pd.Series(["010-1234-5678", "010-9876-5432"])
print(phone.str.replace(r"-\d{4}$", "-****", regex=True))
```

실행하면 20대·서울 3건, 40대·부산 3건이 나와 k=3이고, 전화번호는 `010-1234-****`, `010-9876-****`로 바뀐다. 이렇게 보면 범주화로 값을 뭉치면 같은 조합이 늘어나 k가 커진다는 게 눈에 들어온다. 이 예시는 구조를 보여 주려고 만든 작은 표라서 실제 적정성 평가 기준과는 다르다.

<details>
<summary>가명정보와 가명처리 5단계</summary>

가이드라인과 별개로 개인정보 보호법에 가명정보 개념이 있다. 개인정보보호위원회는 가명정보를 개인정보를 가명처리해서, 원래 상태로 복원하기 위한 추가 정보의 사용·결합 없이는 특정 개인을 알아볼 수 없는 정보로 설명한다. 근거 조항은 법 제2조제1호와 제28조의2다.

통계작성, 과학적 연구, 공익적 기록보존 목적일 때 활용할 수 있다. 통계작성은 특정 집단에 관한 수량적 정보를 만드는 것, 과학적 연구는 기술 개발·기초·응용 연구처럼 과학적 방법을 적용하는 것, 공익적 기록보존은 공공의 이익을 위해 열람할 가치가 있는 기록을 보존하는 것이다.

가명처리 절차는 다섯 단계다. 목적 설정 등 사전준비, 위험성 검토, 가명처리, 적정성 검토, 안전한 관리 순이다. 비식별 조치 가이드라인의 4단계(사전검토, 비식별 조치, 적정성 평가, 사후관리)와는 다른 문서의 절차다. 문제가 어느 쪽 용어로 나오는지 보고 구분한다.
</details>

개인정보 보호 쪽 큰 그림은 [자세히 → 개인정보와 프라이버시](#/post/sec-privacy)에서 따로 본다.

## 이 단원에서 자주 나오는 모양

기출 원문은 여기에 옮기지 않았다. 유형만 정리한다.

- 특징 고르기: 설명을 보고 V 이름을 매칭하거나, 특정 V가 아닌 것을 고른다. 신뢰성과 타당성, 가치가 섞이는 게 함정이다.
- 유형 분류: 로그, JSON, 테이블, 영상 같은 예시를 정형·반정형·비정형으로 나눈다. 스키마 유무와 연산 가능 여부로 풀면 된다.
- 변화 방향: 사후처리·전수조사·양·상관관계 쪽으로 방향이 맞는지 본다.
- 비식별: 기법 이름과 설명 매칭, 절차 순서 나열, k-익명성의 뜻.

시험 일정과 응시 정보는 공식 사이트에서 확인한다.

## 정리

- 3V는 규모·속도·다양성, 4V는 가치 추가, 5V는 신뢰성 추가. 교재마다 구성이 다르니 기준 교재로 확인
- 정형은 스키마와 연산 둘 다, 반정형은 스키마만, 비정형은 둘 다 없음
- 빅데이터의 변화는 사후처리, 전수조사, 양, 상관관계 방향
- 비식별 기법 다섯 가지는 가명처리·총계처리·데이터 삭제·범주화·데이터 마스킹
- 비식별 절차는 사전검토 → 비식별 조치 → 적정성 평가(k-익명성) → 사후관리

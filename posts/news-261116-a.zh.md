## 这是什么
一个本地工具：让人在浏览器里看编程代理给出的计划或代码改动，做标注，再把意见发回给代理。不用在终端里滚着长长的计划打字说“第3步去掉，第5步这样改”，而是像在文档上划荧光笔一样逐行评论，然后点发送。

支持的代理很多。README 里列了 Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、Pi 等。功能大致四块。

1. 计划审阅：代理给出计划时浏览器自动打开。批准就继续，拒绝的话我的评论会整理成结构化反馈发过去。
2. 文档和 HTML 标注:`/plannotator-annotate` 可以给 markdown、文件夹、URL、HTML 文件加评论。`/plannotator-last` 直接标注代理的最后一条回复。
3. 代码审阅:`/plannotator-review` 把未提交的改动、GitHub PR 或 GitLab MR 显示成 diff，可以逐行评论。
4. Inbox:多个代理把问题、文件、需要决定的事放在同一个窗口，我有空时再回。这是 README 最上面挂着的新功能。

## 怎么运转
计划审阅的流程 README 里写得很清楚。

1. 代理为了结束计划模式调用 `ExitPlanMode`。
2. 这时钩子被触发。钩子是代理做某个动作时自动插进来运行的脚本。在 Claude Code 里，把 `plannotator` 命令挂到 `PermissionRequest` 钩子上。
3. 本地服务器从钩子输入里读出计划，在浏览器打开审阅页面。
4. 我标注，然后批准或拒绝。
5. 拒绝时结构化反馈发给代理，代理交回修改后的计划时，用 diff 显示和上一版相比改了什么。

关键是它插在代理本来就要向人请求许可的那个点上。不改代理本身，只用 harness(包住代理、管理工具、权限和流程的外层框架)的钩子。所以同一套方式能接到很多代理上。[详细 → Harness](#/post/ai-harness) [详细 → 代理循环](#/post/ai-agent-loop)

Inbox 有点不同。代理留下问题后不用一直占着会话等，我的回复会作为提问那个会话的下一轮送进去。Claude Code、Pi、OpenCode 通过插件接入，其他代理用 `plannotator inbox mcp` 通过 MCP 接入。[详细 → MCP](#/post/ai-mcp)

计划、diff、评论默认留在本地，说是不收集使用统计。不过每次打开页面都会向 GitHub 请求检查最新版本,README 写着这个目前还关不掉。用 Ask AI 或审阅代理时，相关内容会发给你配置的模型提供方。

## 为什么火
现在同时跑好几个代理的人多了，“人在哪里插手”成了瓶颈。这个工具把这些时刻收到一个界面里。我在 X 上看到的反应，大多是喜欢能异步回复。

发版速度也有关系。11月11日到15日(韩国时间)之间，从 v0.28.61 到 v0.28.65 发了五次。最新的 v0.28.65 加了 Take back 按钮，可以撤回代理还没收到的回复。原因是之前想改回复只能再发一条，队列里可能留下两条不同的指令。

Reddit 和 YouTube 上的热度没能确认。

## 从入门者的角度
作为 PM,我又意识到给代理派活时，最便宜的纠偏时机是计划阶段。在计划的一行上写“这个别做”，比代码出来后再改便宜得多。给文档写评论和做需求评审是一样的，不懂开发也有了一个检查代理工作的入口。

开发入门的话，在自己用的代理里用 `/plannotator-last` 给最后一条回复加评论，应该是最轻的开始。想看反方向的，可以和昨天的文章对比：那边是模型写评论，这边是把人写的评论交还给模型。[详细 → Open Code Review](#/post/news-261115-a)

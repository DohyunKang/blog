## どのような問題を解決するか

コーディングエージェントを複数同時に動かす場合、それぞれ異なる作業フォルダが必要です。同じフォルダでファイルを同時に変更すると、互いに上書きしてしまうためです。git にはこの用途に `git worktree` という機能があります。これは、1 つのリポジトリ内でブランチごとにフォルダを別々に作成する機能です。

ただし、使い方が少し面倒です。プロジェクトサイトでは、新しい worktree を作成するにはブランチ名を 3 回入力しなければならないと説明されています。`git worktree add -b feat ../repo.feat` で作成し、その後 `cd ../repo.feat` で移動するという手順です。Worktrunk は worktree を「ブランチと同じくらい簡単に」扱うことを目指しています。worktree をブランチ名で参照し、フォルダパスは設定可能なテンプレートに基づいて計算します。

## いくつかのコマンド

README とサイトに記載されているコマンドは以下の通りです。

| コマンド | 動作 |
|---|---|
| `wt switch --create feature-auth` | ブランチと worktree を作成し、そのフォルダへ移動 |
| `wt switch -x claude -c feature-a -- 'Add user authentication'` | worktree を作成し、そこで即座に `claude` を実行 |
| `wt list` | worktree の一覧と状態を表示（`--full` フラグを指定すると CI 状態や AI が生成したサマリーも表示） |
| `wt step commit` | ステージされた変更をコミット。LLM を使ってコミットメッセージを作成することも可能 |
| `wt merge main` | squash、rebase、merge、整理を一括で実行 |
| `wt remove` | マージが完了した worktree を削除 |
| `wt switch pr:123` | PR ブランチをチェックアウト |

2 行目がこのツールの用途をよく表しています。各エージェントに対して `-x` で worktree を一つずつ開くと、1 つのリポジトリ内で機能 A、B、C をそれぞれ異なるエージェントに任せる構成が、たった 3 コマンドで完了します。

## インストールと設定

インストール方法は README に Homebrew（`brew install worktrunk && wt config shell install`）、Cargo、conda/pixi、Arch Linux パッケージなどが記載されています。Windows では `winget install max-sixty.worktrunk` でインストールでき、Windows Terminal の `wt` と名前が重複しないよう、`git-wt` という名前でインストールされるそうです。フォルダ移動を行うにはシェル統合（`wt config shell install`）が必要です。

その他、README で言及されている機能は以下の通りです。

- フック：worktree を作成時やマージ前後などのタイミングでコマンドを実行します。作成直後（post-start）に依存関係のインストールや開発サーバーの実行を設定することを推奨しています。
- `hash_port` テンプレートフィルター：各 worktree で開発サーバーのポートを異なる値に割り当てるためのものです。
- `target/` や `node_modules/` などのビルドキャッシュを APFS、btrfs、XFS でコピーオンライト（copy-on-write）方式で共有します。

## 使用時に考慮すべき点

worktree を分けても、同じファイルを 2 つのエージェントが変更するとマージ時に衝突が発生します。このツールが軽減するのはフォルダの作成と整理の手間であり、どのようにタスクを分割するかは依然として人間の役割です。上記の内容は README とサイトに記載された説明に基づいています。デフォルトのパステンプレートやフックの種類全体については、この記事には記載していません。

## 时间复杂度

这是一种描述当输入规模 n 增大时，运算次数增长趋势的方法。忽略常数倍和低阶项，通常以最坏情况为准。考试中记住大小顺序会更方便。

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

如果是代码形式，只需观察循环结构。

- 单个循环，执行 n 次：O(n)
- 嵌套循环两层，各执行 n 次：O(n²)
- 每次循环将变量减半（如 i = i // 2）：O(log n)
- 外层循环 n 次，内层每次减半：O(n log n)
- 多个连续循环时只保留最大阶项。若 O(n) 后接 O(n²)，则为 O(n²)

除了 Big-O，Ω（最优情况）和 Θ（平均/精确界限）的符号也只需记住名称即可。

## 排序对比表

这是最常出现的表格。稳定性指的是相等元素的原始顺序是否保持不变。

| 算法 | 平均 | 最坏 | 稳定 | 一句话特征 |
|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | 稳定 | 比较相邻元素并交换，每轮将最大值移至末尾 |
| 选择 | O(n²) | O(n²) | 不稳定 | 从剩余元素中选最小值与当前位置交换 |
| 插入 | O(n²) | O(n²) | 稳定 | 插入到已排序的前部，对几乎有序输入接近 O(n) |
| 希尔 | 依间隔而定 | O(n²) | 不稳定 | 按间隔重复进行插入排序并缩小间隔 |
| 快速 | O(n log n) | O(n²) | 不稳定 | 以枢轴为基准划分并递归，若对已排序输入选首元素为枢轴则达最坏情况 |
| 归并 | O(n log n) | O(n log n) | 稳定 | 分治后合并，需要辅助空间 |
| 堆 | O(n log n) | O(n log n) | 不稳定 | 构建堆并逐个弹出根节点 |
| 基数 | O(d(n+k)) | 相同 | 稳定 | 按数位分配，不进行元素比较 |

基于比较的排序无法突破平均 O(n log n)，归并和堆的最坏情况也是 n log n，而快速排序最坏可达 n²，这些常作为考点。

### 记忆技巧

- 稳定排序记为“冒插归基”（冒泡、插入、归并、基数），其余均为不稳定。
- O(n log n) 的排序有快速（平均）、归并和堆，其中只有快速的最坏情况是 n²。

## 动手模拟排序过程

考试中会出现“排序一步后的数组”。例如对 [5, 1, 4, 2, 8] 进行冒泡排序升序排列后如下所示：

```
시작     5 1 4 2 8
1회전    1 4 2 5 8   (5가 끝으로 이동)
2회전    1 2 4 5 8   (4와 2 교환, 이후 정렬 완료)
```

若是选择排序，第一轮会将最小值 1 与最前面的 5 交换。即使输入相同，不同算法的中间状态也不同，因此需同时阅读当前轮次和所用算法。

<details>
<summary>Python 实现与验证（冒泡、选择、插入、归并、快速）</summary>

以下代码通过比较内置 `sorted()` 结果来验证随机生成的 200 个元素数组。

```python
def bubble(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        changed = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                changed = True
        if not changed:
            break
    return a

def selection(a):
    a = a[:]
    for i in range(len(a) - 1):
        m = min(range(i, len(a)), key=a.__getitem__)
        a[i], a[m] = a[m], a[i]
    return a

def insertion(a):
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

def quick(a):
    if len(a) <= 1:
        return a
    p = a[len(a) // 2]
    return (quick([x for x in a if x < p])
            + [x for x in a if x == p]
            + quick([x for x in a if x > p]))
```

归并排序中使用 `<=` 进行比较的原因是在值相等时优先取出左侧元素，以维持稳定性。冒泡排序中的 `changed` 标志可在输入已有序时提前结束一轮，使最优情况达到 O(n)。

## 搜索

顺序查找从开头逐个查找，无论是否排序均可使用，最坏需 n 次，平均约 (n+1)/2 次比较，时间复杂度为 O(n)。

二分查找在已排序数据中通过比较中间元素逐步排除一半范围。必须满足数据已排序这一前提（考试中常考），时间复杂度为 O(log n)。若元素有 1,000 个，最多只需约 10 次比较即可完成（2¹⁰ = 1,024）。

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

binary_search([1, 3, 5, 7, 9, 11], 7)   # 3
```

该函数测试了包含随机排序数组中存在的值和缺失的值的情况，以验证结果是否正确。二分查找的执行顺序是“如果中间值大于目标值则向左查找，小于则向右查找”；在考试中，只需逐行写出区间 [lo, hi] 是如何缩小的即可解题。Python 中实际使用的方法见 [排序与二分查找](#/post/algo-sort-search)。

## 哈希

通过将键输入哈希函数来直接计算存储位置，因此平均情况下可在 O(1) 时间内找到元素。然而，如果不同的键发生冲突并映射到同一位置，性能会下降，最坏情况下时间复杂度为 O(n)。Python 官方文档的时间复杂度表中指出，`dict` 的查询、插入和删除以及 `set` 的 `in` 操作平均为 O(1)，而当所有哈希值都发生冲突时最坏情况为 O(n)。相比之下，列表的 `x in l` 是顺序查找，因此为 O(n)。

以下是几种哈希函数的分类及其含义：

| 方法 | 说明 |
|---|---|
| 取模法（除法） | 将键对表大小取余数 |
| 平方取中法 | 将键平方后取中间几位使用 |
| 折叠法 | 将键分成若干部分相加或进行异或运算 |
| 数字分析法 | 仅使用键各位数字中分布均匀的那一位 |
| 基数转换法 | 利用转换为其他进制后的值 |

冲突解决主要有两种方法：

- **开放寻址法**：寻找下一个空闲位置并插入。包括线性探测、二次探测和双重哈希。
- **链地址法（分离链接）**：在同一位置通过链表连接多个元素。

以取模法为例，在表大小为 5 的情况下，插入 12、17、22、7，它们的余数均为 2。若采用链地址法，这些键将依次存储在索引为 2 的位置：12 → 17 → 22 → 7。这正是哈希退化为 O(n) 的最坏情况。

## 常见错误点

- 二分查找的时间复杂度为 O(log n)，但必须先进行排序；未排序的数据无法使用二分查找。
- 许多人只记住快速排序的“平均 n log n"，而忽略了最坏情况下的 n²。
- 稳定性与时间复杂度无关。即使平均性能相同（如快速排序和归并排序），其稳定性也可能不同。
- 哈希并非“总是 O(1)"，而是平均为 O(1)。
- 即使存在嵌套循环，如果内层循环范围每次减半，则总复杂度并非 n²。

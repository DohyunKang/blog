## どんなものか
コーディングエージェントが出した計画やコード変更を、人がブラウザで見て印をつけ、その意見をエージェントに返すローカルツールだ。ターミナルで長い計画をスクロールしながら「3番は外して、5番はこうして」と打つ代わりに、文書に蛍光ペンを引くように行ごとにコメントをつけて送信を押す。

対応エージェントが多い。README には Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、Pi などが並んでいる。機能は大きく四つ。

1. 計画レビュー:エージェントが計画を出すとブラウザが自動で開く。承認すれば進み、却下すると自分のコメントが整理されたフィードバックとして渡る。
2. 文書・HTML への注釈:`/plannotator-annotate` でマークダウン、フォルダ、URL、HTML ファイルにコメントをつける。`/plannotator-last` はエージェントの最後の返答にそのままつける。
3. コードレビュー:`/plannotator-review` でコミット前の変更や GitHub PR、GitLab MR を diff 画面で見て行単位でコメントする。
4. Inbox:複数のエージェントが質問、ファイル、決定の依頼を一つの画面に置いていき、こちらは時間があるときに答える。README の一番上にある新機能だ。

## どう動くか
計画レビューの流れは README にそのまま書いてある。

1. エージェントが計画モードを終えるために `ExitPlanMode` を呼ぶ。
2. その瞬間にフックが動く。フックはエージェントが特定の動作をしたときに割り込んで自動で走るスクリプトだ。Claude Code では `PermissionRequest` フックに `plannotator` コマンドをかけておく。
3. ローカルサーバーがフックの入力から計画を読み、ブラウザにレビュー画面を出す。
4. 自分が印をつけて承認か却下をする。
5. 却下すると構造化されたフィードバックがエージェントに渡り、直した計画が戻ってくると前と何が変わったかを diff で見せる。

ポイントは、エージェントがもともと人に許可を求める地点に割り込むことだ。エージェント自体は変えず、ハーネス(エージェントを包んでツール・権限・流れを管理する外側の枠)のフックだけを使う。だから同じやり方で多くのエージェントにつなげられる。[詳しく → ハーネス](#/post/ai-harness) [詳しく → エージェントループ](#/post/ai-agent-loop)

Inbox は少し違う。エージェントが質問を残してもセッションを開いたまま待たず、自分の返事はその質問をしたセッションの次のターンとして届くと書いてある。Claude Code、Pi、OpenCode はプラグインで、それ以外のエージェントは `plannotator inbox mcp` で MCP 経由でつながる。[詳しく → MCP](#/post/ai-mcp)

計画、diff、コメントは基本的にローカルに残り、利用統計は集めないという。ただし画面を開くたびに GitHub へ最新リリースを確認するリクエストが出て、これはまだ切れないと README にある。Ask AI やレビューエージェントを使うと、その内容は設定したモデル提供元に送られる。

## なぜ話題なのか
エージェントを何体も同時に動かす人が増えて、「人がどこで口を挟むか」がボトルネックになった。このツールはその地点を一つの画面にまとめる。X で見た反応も、ほとんどが「非同期で答えられるのがいい」というものだった。

リリースの速さも効いている。11月11日から15日(韓国時間)の間に v0.28.61 から v0.28.65 まで5回出た。最新の v0.28.65 には、エージェントがまだ受け取っていない返事を取り消す Take back ボタンが入った。返事を直そうと二通目を送ると、違う指示が二つキューに残ってしまう問題があったからだそうだ。

Reddit と YouTube でどれくらい話題かは確認できなかった。

## 入門者の立場から
PM としては、エージェントに仕事を任せるとき一番安く方向を直せるのは計画の段階だと改めて思った。コードが出てから直すより、計画書の一行に「これはやらないで」とつけるほうがずっと安い。文書にコメントをつけるやり方は企画レビューと同じなので、開発を知らなくてもエージェントの作業を見られる入口になる。

開発入門者なら、使っているエージェントで `/plannotator-last` を使って最後の返答にコメントしてみるのが一番軽い始め方だと思う。AI が代わりにレビューする側が気になるなら、昨日の記事と比べると面白い。あちらはモデルがコメントを書き、こちらは人が書いたコメントをモデルに返す。[詳しく → Open Code Review](#/post/news-261115-a)

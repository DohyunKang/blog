这周从 GitHub Trending(weekly)里挑了 vercel-labs/agent-desktop。榜单上显示本周新增 12,120 颗星，仓库总星数是 21,362(11月11日上午查看)。X 上最近 7 天提到 "agent-desktop" 的帖子有 1,048 条(不含转推，按 X 搜索统计)。我只读了 README、CONCEPTS.md 和发布说明，没有自己装来跑。

## 这是什么
一个让 AI 代理能看到并操作桌面应用的 CLI。这类能力一般叫 computer use，就是模型像人一样看屏幕、用鼠标键盘操作应用。[详细 → 工具调用](#/post/ai-tool-use)

特别的地方是它不用截图。它不把屏幕图片发给模型、让模型猜登录按钮在第几个像素，而是读取操作系统的无障碍树。无障碍树是操作系统为读屏软件等辅助技术提供的数据，把应用界面整理成"窗口里有按钮，按钮里有文字"这样的结构。macOS 用 AX API，Windows 用 UI Automation，Linux 用 AT-SPI。

agent-desktop 里面没有模型。按 README 的说法，循环在你自己的代理那边。它只负责当眼睛和手。

## 怎么运作
流程就三行。

```bash
agent-desktop snapshot --app Finder -i   # 每个可操作元素都带 ref 的树
agent-desktop click @s8f3k2p9:e8         # 点那个 ref
agent-desktop snapshot --app Finder -i   # 再读一次确认结果
```

snapshot 把树以 JSON 返回，给每个可操作元素加上 `@s8f3k2p9:e8` 这样的 ref。前半是快照 ID，后半是元素编号。所以 ref 只在那次快照里有效。像 `@e8` 这样不带快照 ID 会被拒绝，界面变了之后再用旧 ref 会返回 `STALE_REF`。这时代理重新拍一次 snapshot 就行。

我喜欢的是它失败的方式。按像素坐标点击，窗口稍微挪一下就会点错，而且没人发现。这里会明确地失败：这个 ref 已经对不上了。错误 JSON 里有 `error.disposition.retry`，文档写着只有它是 `safe` 时才重试。

CONCEPTS.md 把这种谨慎写得更细。操作系统给出的每个属性分成"有 / 没有 / 不知道"三种，读取失败不会被当成"没有"。窗口句柄可能被系统回收再用，所以把句柄和进程启动时间绑在一起，重新确认还是不是同一个窗口。Chrome、Electron 应用里一层层没有名字的包装元素，会从深度计算里跳过，免得树太深。

默认是 headless。用 ref 的操作走无障碍 API，不移动鼠标指针，也不抢焦点。需要真实鼠标键盘输入时加 `--headed`。

## 为什么火
除了榜单数字，我看到的原因大概两个。

一个是 11月5日(韩国时间)发布的 v1.2.0 加了 `agent-desktop mcp`。每个命令都以 MCP 工具的形式提供，比如 `desktop_snapshot`、`desktop_click`。MCP 是让 AI 应用用同一种方式接入外部工具的规范。[详细 → MCP](#/post/ai-mcp) 现在在 Claude Code 这类框架里加一行配置就能接上。

另一个是它和 Vercel 的 agent-browser 是一对。文档也放在 agent-browser.dev 下面。等于把浏览器里"读树 → 点 ref → 再读"的做法扩展到了整个桌面应用。从发布说明里的链接看，它原来是 lahfir/agent-desktop，后来搬到了 vercel-labs，但什么时候、为什么搬，我没能确认。

## 对入门者来说
对 PM 或刚入门开发的人，我觉得重点是成本和可靠性。截图方式每一步都要把图片发给模型，很费 token，猜坐标本身也可能猜错。树的方式是文本 JSON，轻，而且点了什么都有记录。

代价是应用如果没好好提供无障碍信息，能做的事就少了。README 也专门写了每个平台在 headless 下能做什么、什么需要 `--headed`、什么会被拒绝。在游戏或用画布绘制的应用里好不好用，我没能确认。

README 开头的提醒也值得记住。快照、剪贴板、截图里可能直接带着桌面上的个人信息，别放进公开日志或上传。密码之类建议用 `--stdin` 传，免得留在进程参数里。

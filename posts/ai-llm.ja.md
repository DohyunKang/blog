LLM (Large Language Model, 대형 언어 모델) は、文字の断片（トークン）の次に来るものを確率的に予測できるように、非常に大規模に学習されたモデルです。会話型 AI と呼ばれるものの内実の多くはこれです。

## まず簡単な説明で

スマートフォンキーボードに「今日の昼食は」と入力すると、次の単語候補が表示されます。LLM はこの機能を極端に拡張したものに近いです。いくつかの候補を示す代わりに、次に来る可能性のあるすべての断片に確率を割り当て、その中から一つを選びます。選んだ断片を後ろに付け加え、その状態でまた次の断片を予測します。これを数百回繰り返すと文節が完成します。

初めてこの説明を聞いたときは「それだけか？」と思いました。コードも書いたり翻訳もするのにな、内実が次の単語当てただけなのかと。しかし、これが事実に近いのです。ただし、「それだけ」ではなく、「それを莫大な規模で行うことで、それ以上のことが実現した」という意味に近いです。以下、順を追って見ていきましょう。

## トークン：モデルが読む単位

モデルは文字や単語をそのまま読み取るのではなく、「トークン」という断片として読み取ります。トークンは一つの単語であることもあれば、単語の一部であることもあり、単一の文字であることもあります。頻出する塊は一つのトークンにまとめられ、稀な単語は複数の断片に分けられます。

この方式の根幹の一つにサブワード分割があります。Sennrich 他による 2015 年の論文は、翻訳モデルが固定された語彙では稀な単語を扱えない問題を、単語をサブワード断片の列として表現することで解決しました。私はこの論文の要約のみを読み、現在の LLM が使用するトークナイザーが正確にどのような方式かはモデルによって異なります。以下は概念を示すために作成した仮想的な分割です。実際のトークナイザーの結果ではありません。

| 原文 | 仮想的なトークン分割 |
|---|---|
| 昼食 | `昼食` |
| 形態素解析 | `形態`, `素`, `解析` |
| unbelievable | `un`, `believ`, `able` |

トークンは料金とも直結しています。API は通常、入力トークン数と出力トークン数で計算されます（Anthropic のドキュメントにはトークン数を事前に数える機能があり、料金と速度制限の管理に使用すると記載されています）。意味が同じでも言語によってトークン数が異なる可能性があります。

[詳細 → コンテキストウィンドウ](#/post/ai-context-window) で扱うように、一度に表示できるトークン数には上限があります。

## 次のトークン予測

モデルが行うことは一つだけです。これまでのトークンの列が与えられたとき、次のトークンは何かという分布を出力します。

```
입력: "대한민국의 수도는"
출력(예시용 가상의 확률):
  " 서울"  0.92
  " 부산"  0.01
  " 어디"  0.01
  ...
```

この分布から一つを選びます。常に最も高い確率のものを選ぶと答えは一定になり、確率に従って選ぶと同じ質問でも答えが少しずつ異なります。これを調整する値がいわゆる temperature などの設定です。製品によって名前やデフォルト値は異なります。

ここで重要な点の一つ。モデルは「ソウルが正しい」ことを事実確認して選んでいるわけではありません。学習中にこの文脈の後に「ソウル」が多く出現したため、確率が高くなるのです。この違いが後述するハルシネーション問題の根源です。[詳細 → ハルシネーション](#/post/ai-hallucination)

## パラメータ：学習で埋められた数字

モデルの中には非常に多くの数字（重み）が入っています。これをパラメータと呼びます。入力トークンはこれらの数字を通過して変換され、最後に次のトークンの確率として出力されます。学習はこれらの数字を少しずつ修正して予測の誤りを減らすプロセスです。

- 学習前：数字は無作為に近い状態で、出力は無意味な文字列です。
- 学習中：大量のテキストから「次のトークン当て」の問題を解き、間違える分だけ数字を修正します。
- 学習後：数字が固定されます。文法、常識、コードパターンなどがこれらの数字の中に分散して含まれています。

規模感を把握するための数字は論文から引用しました。GPT-3 の論文（2020 年）では、1750 億個のパラメータを持つ自己回帰言語モデルを学習し、それ以前の非疎な（non-sparse）言語モデルよりも 10 倍多いと記載されています。構造は 2017 年の「Attention Is All You Need」で提案されたトランスフォーマー系です。この論文は、循環や畳み込みを使わずにアテンションのみで構成された構造を提案しました。アテンションが正確にどのように計算されるかは本稿では扱わず、別途読み込んで整理する予定です。

## 事前学習済みモデルが答えを出すプロセス

名前にある「事前学習（pre-trained）」とは、特定の用途に合わせて調整する前に一般的なテキストで大規模にまず学習したという意味です。使用する際には学習は起こりません。数字は固定されており、入力に応じて計算だけです。

一度の対話の流れは以下の通りです。

1. 自分が入力した文章と会話履歴、システム指示文を結合します。
2. トークンに分割します。
3. モデルが次のトークンの確率分布を出力します。
4. 一つを選び、後ろに付け加えます。
5. 3〜4 を終了信号が出るまで繰り返します。

答えが一字ずつ流れ出るように見える理由はこれです。実際にはトークン単位で生成しています。

GPT-3 の論文で印象に残ったのは、タスクを別途学習させることなく、文章だけで指示すれば動作するという点です。論文ではタスクと例示を「純粋なモデルとのテキスト相互作用によって」指定し、勾配更新（追加学習）はなかったと記されています。これは現在、プロンプトにいくつかの例示を入れる方式の出発点です。[詳細 → プロンプト](#/post/ai-prompt)

モデルが知らない最新の情報や私の文書はパラメータには含まれていません。そのため、必要な文章を入力と一緒に与える方式が使われます。[詳細 → RAG](#/post/ai-rag)

## モデルサイズ：大きいほど良いのか

概して大きなモデルの方が優れているものの、「パラメータ数だけ」が答えではありません。2 つの論文がこのことを示しています。

- Chinchilla (2022): 計算予算が決まっている場合、モデルサイズと学習トークン数を同じ比率で同時に増やすべきだと主張します。700 億パラメータの Chinchilla は、2,800 億パラメータの Gopher と同程度の計算量を使いつつ、データを 4 倍使用しました。
- InstructGPT (2022): 人間のフィードバックで追加調整した 13 億パラメータモデルの出力が、175B の GPT-3 の出力よりも評価者に好まれました。パラメータ数は約 100 分の 1 にもかかわらずです。

まとめると、サイズ、データ量、追加調整はそれぞれ品質に影響を与えます。サイズはコストにも直結します。大きなモデルは 1 トークン生成するごとに計算コストが高くなります。そのため、同じ会社のモデルでも大きいものと小さいものを別々に販売することが多いです。簡単な分類は小さなモデルで、難しい推論は大きなモデルで使い分けるような具合です。

## 既存のチャットボットとの違いは何か

以前のルールベースチャットボットは、人が質問と回答を事前に設定した構造でした。キーワードが一致すれば決まった回答が返され、該当しない質問には「理解できませんでした」と返されます。

| | ルール・シナリオ型チャットボット | LLM 基盤 |
|---|---|---|
| 回答の源泉 | 人が記した文章 | 学習されたパラメータで生成 |
| 初めて見る質問 | 大抵失敗する | とりあえず 그럴듯하게 (説得力のある) 回答する |
| 間違えた場合 | 回答がないか、的外れなシナリオ | 説得力のある誤った回答 |
| 作成コスト | シナリオの記述 | モデル学習・呼び出しコスト |
| 動作予測 | 容易 | 困難 |

LLM は柔軟である反面、制御が難しいです。そのため、実際の製品では LLM のみではなく、検索やツール呼び出し、ルールも併せて組み込んでいます。[詳細 → ハネス](#/post/ai-harness)

もう一つ。私たちが使っている対話型 AI は、LLM そのものというよりは、事前学習モデルを人間のフィードバックなどで追加調整し、対話形式のプロンプトと製品機能を載せたものです。InstructGPT の論文はこの追加調整を取り扱っています。論文では、モデルを育てるだけではユーザーの意図に沿う方向には行かず、嘘や有害な出力が出る可能性があるため、人間のフィードバックによる微調整を提案していると記されています。

## よくある誤解

- 検索して回答を取得する：基本状態の LLM はパラメータに含まれるパターンで生成します。検索機能が追加された製品は別途検索を呼び出しているだけです。
- モデルが私の質問を記憶して学習する：対話中は学習は起こりません。前の対話を覚えているように見えるのは、記録を入力に再度投入するためです。サービスが後でデータを学習に使うかどうかは利用規約の問題です。
- 理解しているのではなく単なる模倣 / 人間のように理解する：どちらもこの文章から結論付けることはできません。次のトークン予測によって学習したという事実と、その結果どのような能力が生まれたかは別途見る必要があります。
- パラメータが多いほど必ず良い：前述の Chinchilla や InstructGPT の事例のように、データ量や調整によって異なります。

## 뭐 하는 물건인지
코드에서 보안 취약점을 찾고, 정말 취약한지 확인하고, 고치는 일까지 하는 OpenAI의 도구다. Codex 안에서 플러그인으로 쓰거나, 터미널에서 `cs` 명령으로 쓰거나, TypeScript SDK와 GitHub Action으로 자동화할 수 있다. 취약점(vulnerability)은 공격자가 악용할 수 있는 코드의 빈틈이다. SQL 인젝션이나 권한 확인 누락 같은 것.

기존 보안 스캐너는 정해진 규칙(패턴)에 맞는 코드를 찾는다. 이건 코딩 에이전트가 코드를 읽으면서 조사하는 방식이다. 에이전트는 모델이 도구를 써 가며 스스로 여러 단계를 밟는 프로그램이다. [자세히 → 에이전트와 에이전트 루프](#/post/ai-agent-loop)

## 어떻게 도는지
기본은 `cs scan .` 한 줄이다. 끝나면 폴더에 세 파일이 남는다.

- `report.md`: 범위와 발견 내용을 사람이 읽게 정리한 보고서
- `findings.json`: 발견마다 소스 위치와 근거
- `scan-manifest.json`: 무엇을 스캔했고 무엇을 뺐는지

스캔 범위는 레포 전체, 특정 경로(`--path`), 커밋 차이(`--diff origin/main`), 아직 커밋 안 한 변경(`--working-tree`) 중에 고른다. PR 리뷰에는 diff 스캔을 쓰는 식이다.

모드는 Standard와 Deep 두 가지다. Deep은 Standard 스캔을 여러 번 반복한다. 워커 여러 개가 동시에 조사하면서 서로 "이 위치 좀 봐 달라"고 물어볼 수 있고, 다음 배치는 앞에서 찾은 것의 제목과 위치를 받아서 다른 경로를 파고든다. 새로 나온 게 없는 스캔이 몇 번 연속되면 멈춘다(`--stop-after-no-new`). 문서에 적힌 기본 모델은 `gpt-5.6-sol`, 추론 강도는 `xhigh`이고, 부모 하나에 위임 워커 최대 8개까지 돈다. [자세히 → 서브에이전트와 멀티에이전트](#/post/ai-subagent)

찾은 다음 단계가 이 도구의 핵심 같았다.

- validate: 발견 하나를 다시 검토해 진짜인지 판정한다. 이때 도구는 코드 읽기만 되고 네트워크와 웹 검색은 꺼진다.
- patch: 발견을 고치는 패치를 만들고, 원하면 초안 PR까지 만든다. 패치 위험도 평가를 붙일 수 있다.
- verify-fix: 고친 뒤 다시 보고 fixed, still_vulnerable, inconclusive 셋 중 하나로 답한다. 종료 코드도 0, 1, 2로 나뉘어서 CI에 걸기 쉽다.

보고서에 "어디까지 봤는지"를 따로 남기는 것도 눈에 띄었다. 문서에 스캔이 끝났다는 건 작업이 끝났다는 뜻이지 모든 파일과 모든 취약점을 봤다는 뜻이 아니라고 적혀 있다. 제외한 경로와 미룬 작업, 남은 질문이 기록된다.

그 밖에 `SECURITY.md` 초안 쓰기, 위협 모델 저장, Semgrep·Snyk·Wiz 같은 다른 스캐너 결과 가져오기, Linear·Jira·GitHub로 보내기, SARIF·JSON·CSV 내보내기가 있다. 위협 모델은 "누가 어디로 공격할 수 있나"를 정리한 문서다.

## 왜 화제인지
11월 12일(한국 시간)에 0.10.0이 나왔다. 끊긴 Standard 스캔 이어서 하기, 여러 레포에 예산 하나를 나눠 쓰는 `--max-total-cost`, 패치가 막혔을 때 이유를 설명하는 기능이 들어갔다. 그 하루 전(유튜브 업로드 날짜 기준 11월 11일)에 OpenAI가 첫 스캔 안내 영상을 올렸고, X 언급은 12일(UTC)에 몰렸다. 둘 다 원인일 것 같은데 정확한 이유는 확인 못 함.

이번 주 X에서는 Claude Code 설정 파일로 비밀 키가 공개 레포에 올라간 일, Nous Research가 Hermes Agent용 보안 플러그인을 낸 일도 같이 돌았다. 코딩 에이전트가 코드를 많이 짤수록 검사도 에이전트가 하자는 흐름인 것 같다.

## 입문자 입장에서
PM 입장에서는 "찾았다"와 "확인했다"와 "고쳤다"를 단계별로 나눠 둔 게 와닿는다. AI가 낸 결과를 바로 믿지 않고 근거와 범위를 같이 남기는 설계라 보고받기 편해 보인다. 개발 입문자라면 내 작은 레포에 `cs scan . --diff origin/main`을 PR마다 거는 정도부터 시작하면 될 것 같다. GitHub Action 예시는 스캔당 예상 한도 5달러로 잡혀 있고, 진행 중인 요청은 한도를 넘을 수 있다고 적혀 있다.

주의할 점. 로그인이나 API 키가 필요하고 모델 사용료가 든다. 일부 보안 요청과 보호된 발견은 OpenAI의 Trusted Access for Cyber 승인이 있어야 한다. Bedrock, OpenRouter, Fireworks AI 같은 다른 제공자도 쓸 수 있다고 한다. 실제 탐지 정확도 수치는 확인 못 함. 레포 안에 evals 폴더는 있었지만 결과는 읽지 않았다. 스킬로 나뉜 구조가 궁금하면 이 글도 같이 보면 좋다. [자세히 → 스킬](#/post/ai-skills)

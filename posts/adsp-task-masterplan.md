ADsP 2과목(데이터 분석 기획)에서 과제 발굴부터 마스터플랜, 거버넌스, 성숙도, 프로젝트 관리까지 이어지는 구간이다. 계산 문제는 없고 용어와 분류를 정확히 구분하는지 묻는 쪽이라, 표로 묶어 두면 보기를 거르기 쉽다. 시험 일정과 응시 관련 내용은 공식 사이트에서 확인하면 된다.

앞 단원은 [분석 기획의 이해](#/post/adsp-planning)와 [분석 방법론](#/post/adsp-methodology)이다. 거기서 분석 대상과 방법에 따라 유형을 나눴다면, 이 글은 그렇게 나온 과제를 실제로 어떤 순서로 실행할지 정하는 단계다.

## 과제는 어떻게 찾나

과제를 찾는 방식은 두 갈래다.

| | 하향식 | 상향식 |
|---|---|---|
| 출발점 | 풀어야 할 문제가 이미 있다 | 문제를 모르고 데이터부터 본다 |
| 쓰는 곳 | 분석 대상이 분명할 때 | 새로운 통찰을 찾을 때 |
| 진행 | 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토 | 가설 생성 → 실험 → 실제 환경 테스트 → 가설 확인 |
| 도구 | 비즈니스 모델, 외부 참조 모델 | 탐색적 데이터 분석, 비지도 학습, 프로토타이핑 |

하향식의 문제 탐색은 다시 둘로 나뉜다. 내부 업무·제품·고객을 보는 비즈니스 모델 기반, 유사 업계를 참고하는 외부 참조 모델 기반이다. 탐색 결과는 분석 유즈 케이스(문제 설명과 해결했을 때 기대 효과)로 정리한다. 이 유즈 케이스를 데이터 분석 문제로 바꾸고 적합한지 평가하는 흐름이다. 마지막 타당성 검토에서는 경제적 타당성과 데이터·기술 적용 가능성을 같이 본다.

분석 기획 단계에서 미리 따져 볼 것도 세 가지로 정리돼 있다. 가용 데이터, 적절한 유스케이스, 장애요소(비용, 정확도, 조직 역량, 변화 관리)에 대한 사전 계획이다. 가용 인력은 이 세 가지에 들어가지 않는다고 정리한 자료가 있어서, 보기에 섞여 나오면 조심해서 봐야 한다.

과제를 풀 방법은 기존 시스템이 있는지, 분석 역량이 있는지로 갈린다.

| 기존 시스템 | 분석 역량 | 방향 |
|---|---|---|
| 있음 | 있음 | 기존 시스템과 인력을 활용 |
| 있음 | 없음 | 교육하거나 채용 |
| 없음 | 있음 | 시스템 고도화 |
| 없음 | 없음 | 전문 업체 아웃소싱 |

## 우선순위: 시급성과 난이도

찾은 과제를 전부 한꺼번에 할 수는 없어서 순서를 정한다. 기준은 두 축이다.

| 축 | 보는 것 |
|---|---|
| 시급성 | 전략적 중요도, 목표 가치. 지금 필요한가, 나중에 필요한가 |
| 난이도 | 데이터 획득·저장·가공 비용, 분석 적용 비용, 분석 수준 |

두 축을 곱하면 네 칸이 나온다.

| 시급성 | 난이도 | 비고 |
|---|---|---|
| 현재 | 쉬움 | 가장 먼저 |
| 현재 | 어려움 | 시급성 우선이면 두 번째 |
| 미래 | 쉬움 | 난이도 우선이면 두 번째 |
| 미래 | 어려움 | 가장 나중 |

가운데 두 칸의 순서가 시급성을 먼저 보느냐 난이도를 먼저 보느냐에 따라 바뀐다. 한 정리 자료(IT위키)는 사분면 번호로 시급성 우선이 III → IV → II → I, 난이도 우선이 III → II → IV → I라고 적었다. 대신 이 자료도 번호는 자료마다 다르게 쓰이니 속성으로 기억하라고 덧붙인다. 그래서 외울 때는 번호 말고 "현재·쉬움이 1순위, 미래·어려움이 꼴찌"로 잡았다. 문제에서 사분면 그림이 나오면 번호가 아니라 축 이름을 먼저 확인한다.

핵심 기준은 시급성이다. 난이도는 회사 사정에 맞춰 조정할 수 있다. 현재 필요한데 어려운 과제는 데이터 양이나 분석 범위를 줄여서 난이도를 낮춘 뒤 먼저 해 볼 수도 있다.

## 마스터플랜과 로드맵

마스터플랜은 확정된 과제를 언제, 어떤 순서로 할지 짠 계획이다. 우선순위를 정할 때 고려하는 요소는 전략적 중요도, 비즈니스 성과(ROI), 실행 용이성이다.

적용 범위와 방식을 정할 때는 세 가지를 본다.

| 요소 | 수준을 가르는 질문 |
|---|---|
| 업무 내재화 | 보고서·화면으로 제공하나, 업무 프로세스와 시스템에 녹여 자동 활용하나 |
| 분석 데이터 | 내부 데이터만 쓰나, 외부·비정형 데이터까지 넓히나 |
| 기술 | 기존 시스템과 기술로 하나, 새 분석·빅데이터 기술을 도입하나 |

이행 로드맵은 3단계다.

1. 데이터 분석 체계 도입: 분석 기회 발굴, 과제 정의, 로드맵 수립
2. 데이터 분석 유효성 검증: 알고리즘 설계, 아키텍처 설계, 파일럿 수행
3. 데이터 분석 확산 및 고도화: 변화 관리, 시스템 구축, 유관 시스템 고도화

파일럿으로 먼저 효과를 확인하고 그다음에 확산하는 순서가 핵심이다. 개인정보 비식별화 같은 항목은 이 고려 요소에 들어가지 않는다.

## 거버넌스 체계

분석 거버넌스는 조직이 분석을 계속 수행하고 업무에 정착시키도록 관리하는 체계다. 구성 요소는 다섯 가지다.

| 요소 | 내용 |
|---|---|
| Organization(조직) | 분석 기획·관리 조직의 위치와 형태 |
| Process(프로세스) | 과제 발굴, 기획, 수행, 관리 절차 |
| System(시스템) | 분석에 쓰는 IT 시스템과 도구 |
| Data(데이터) | 표준화, 품질, 보안 관리(데이터 거버넌스) |
| Human Resource(인적 자원) | 인력 확보, 역할 정의, 교육 체계 |

데이터 거버넌스는 분석 거버넌스 안에 들어가는 한 요소다. 둘을 같은 말로 쓴 보기는 틀린 쪽이다.

분석 조직 구조는 세 유형으로 나눈다.

| 유형 | 특징 | 약점 |
|---|---|---|
| 집중형 | 전담 조직이 전사 분석을 맡는다 | 현업과 업무가 겹칠 수 있다 |
| 기능 중심 | 별도 조직 없이 현업 부서가 직접 분석한다 | 전사 차원의 핵심 분석이 어렵다 |
| 분산형 | 분석 인력을 현업 부서에 배치한다 | 대신 모범 사례 공유는 쉽다 |

과제 관리는 과제 발굴(아이디어 발굴 → 과제 후보 제안 → 과제 확정)과 과제 수행(팀 구성 → 실행 → 진행 관리 → 결과 공유·개선) 순서다. 결과물과 경험은 풀(pool)로 모아 다음 과제에 재활용한다.

## 준비도와 성숙도

조직의 현재 분석 수준은 두 가지로 진단한다.

준비도는 여섯 영역을 본다: 분석 업무, 인력 및 조직, 분석 기법, 분석 데이터, 분석 문화, IT 인프라. 성숙도는 도입 → 활용 → 확산 → 최적화 네 단계 중 어디인지를 비즈니스, 조직·역량, IT 부문별로 본다.

준비도와 성숙도를 각각 높음/낮음으로 나누면 네 유형이 나온다.

| 유형 | 준비도 | 성숙도 | 방향 |
|---|---|---|---|
| 준비형 | 낮음 | 낮음 | 분석 준비부터 한다 |
| 정착형 | 낮음 | 높음 | 이미 분석 중이니 체계적으로 정착시킨다 |
| 도입형 | 높음 | 낮음 | 준비가 되어 있어 바로 도입할 수 있다 |
| 확산형 | 높음 | 높음 | 지속적으로 확산한다 |

정착형과 도입형이 헷갈린다. 이름이 아니라 "준비도와 성숙도 중 어느 쪽이 높은가"로 푼다. 정착형은 성숙도가 높고, 도입형은 준비도가 높다.

## 프로젝트 관리 10대 영역

분석 과제도 프로젝트라서 PMBOK 지식 영역으로 관리한다. PMBOK 6판 기준으로 열 가지다.

| 영역 | 하는 일 |
|---|---|
| 통합 | 프로젝트 전체 요소를 하나로 조율한다 |
| 범위 | 프로젝트에 포함되는 일을 정하고 통제한다 |
| 일정 | 작업 순서·소요 시간을 추정하고 통제한다 |
| 원가 | 예산을 추정하고 통제한다 |
| 품질 | 산출물이 기준을 충족하게 한다 |
| 자원 | 팀과 자원을 확보하고 관리한다 |
| 의사소통 | 이해관계자에게 갈 정보 흐름을 관리한다 |
| 위험 | 위험을 식별·분석·대응·감시한다 |
| 조달 | 외부 업체에서 물품·서비스를 구한다 |
| 이해관계자 | 영향을 받는 사람들을 파악하고 참여시킨다 |

PMBOK 7판(2021)은 이 지식 영역 대신 여덟 개의 성과 영역으로 바뀌었다. 시험 교재가 어느 판 기준인지는 교재 설명을 같이 본다.

## 자주 나오는 유형

- 하향식과 상향식 구분: "문제가 먼저 주어진다"면 하향식, "데이터를 먼저 본다"면 상향식.
- 우선순위 칸 고르기: 현재·쉬움이 먼저, 미래·어려움이 마지막. 가운데는 기준이 시급성인지 난이도인지 확인.
- 적용 범위·방식 요소 세 개 중 빠진 것 찾기: 업무 내재화, 분석 데이터, 기술. 그 밖의 항목이 섞여 있으면 오답.
- 거버넌스 구성 요소 다섯 개와 조직 구조 세 유형의 특징 짝 맞추기.
- 정착형·도입형처럼 준비도·성숙도 높낮이로 유형 이름 찾기.
- 로드맵 순서: 체계 도입 → 유효성 검증(파일럿) → 확산·고도화.

풀 때는 보기의 키워드를 먼저 본다. "파일럿"은 2단계, "변화 관리"는 3단계, "아이디어 발굴"은 1단계로 거의 바로 좁혀진다. 기출 문제는 공식 사이트나 교재에서 직접 풀어 보는 편이 낫다.

오늘 아침 GitHub 트렌딩을 보니 google-labs-code/stitch-skills가 주간(weekly) 2위, 일간(daily)에도 올라와 있었다. 이번 주 별 2,683개, 오늘 494개, 레포 전체 별은 11,905개다(11월 23일 오전 확인). Google Labs의 AI 화면 디자인 도구 Stitch를 코딩 에이전트가 직접 다루게 해 주는 스킬 묶음이다. 나는 README와 스킬 몇 개(stitch-loop, code-to-design, react-components, design-md, enhance-prompt)의 SKILL.md, react-components의 validate.js를 읽었다. Stitch 계정을 연결해서 직접 돌려 보지는 않았다.

## 뭐 하는 물건인지
스킬은 에이전트가 필요할 때 꺼내 읽는 설명서다. [자세히 → 스킬](#/post/ai-skills) 이 레포의 스킬은 전부 Stitch MCP 서버를 통해 움직인다. MCP는 에이전트가 바깥 서비스의 기능을 도구처럼 부를 수 있게 하는 연결 규격이다. [자세히 → MCP](#/post/ai-mcp) 그래서 스킬만 깔아서는 안 되고, Stitch 쪽 MCP 설정을 먼저 해 둬야 한다.

플러그인은 셋으로 나뉜다.

1. stitch-design: 글이나 이미지로 화면을 만들고 고치기, 이미 있는 프론트엔드 코드를 Stitch 디자인으로 옮기기, DESIGN.md 올리기.
2. stitch-build: Stitch 화면을 React, React Native 컴포넌트로 바꾸기, 화면을 넘겨 보는 소개 영상(Remotion) 만들기.
3. stitch-utilities: 막연한 요청을 Stitch용 프롬프트로 다듬기, DESIGN.md·SITE.md 만들기, 여러 페이지 사이트를 이어서 만드는 루프.

설치는 Claude Code나 Cursor에서 `npx plugins add` 한 줄, Codex는 마켓플레이스 등록이다. 스킬 형식이 공개 표준(Agent Skills)을 따라서 OpenCode에도 폴더를 복사해 넣으면 된다고 적혀 있다.

## DESIGN.md가 가운데에 있다
읽어 보니 거의 모든 스킬이 DESIGN.md라는 파일 하나를 중심으로 돈다. 색, 글꼴, 간격, 모서리 둥글기 같은 디자인 규칙을 말로 풀어 적은 파일이다. design-md 스킬 설명에 따르면 Stitch는 디자인을 "눈에 보이는 묘사"와 구체적인 색 값으로 알아듣는다. 그래서 새 화면을 만들 때마다 이 파일 내용을 프롬프트에 같이 넣어 앞 화면과 톤을 맞춘다.

방향은 두 갈래다. 디자인에서 코드로 갈 때는 Stitch 화면의 HTML을 받아 컴포넌트로 쪼갠다. 코드에서 디자인으로 갈 때는 code-to-design이 이미 돌아가는 웹앱에서 HTML 한 장을 뽑고, 소스에서 DESIGN.md를 뽑고, 둘을 Stitch에 올린다. 만들어 둔 화면을 다시 디자인 도구로 가져가서 손볼 수 있게 한 셈이다.

## 사이트를 이어서 만드는 루프
stitch-loop는 바통 넘기기 방식이다. `.stitch/next-prompt.md` 파일에 다음에 만들 페이지가 적혀 있고, 에이전트는 그걸 읽어 페이지를 만들고, 사이트에 붙이고, 사이트 지도(SITE.md)를 고친 뒤, 다음 페이지 할 일을 다시 그 파일에 적고 끝낸다. 대화 기억에 기대지 않고 파일에 상태를 남기니까, 세션이 바뀌어도 다음 에이전트가 이어받을 수 있다. 크롬 개발자도구 MCP가 있으면 만든 페이지를 띄워 스크린샷을 찍고 Stitch 원본 그림과 비교하는 단계도 있다(선택 사항).

## 규칙은 글로 쓰고, 일부는 코드로 막는다
react-components 스킬은 말투가 꽤 세다. 단계마다 GATE를 두고 "이 조건을 채우기 전엔 다음으로 가지 말라"고 적는다. 컴포넌트는 파일을 나누고, 로직은 hooks로, 문구와 이미지 주소는 mockData로 빼고, 색은 hex 값 대신 테마 클래스를 쓰라고 한다.

이 중 일부는 validate.js가 실제로 검사한다. 코드를 문법 트리(AST, 코드를 구조 단위로 쪼갠 모양)로 읽어서 이름이 Props로 끝나는 인터페이스가 있는지, className 안에 `#1a2b3c` 같은 hex 색이 박혀 있는지를 본다. 11월 20일 커밋들도 이 검사를 고친 것이었다. className을 표현식으로 조합해도 hex를 잡도록 하고, React Native 컴포넌트에 웹 전용 태그가 들어가면 거르게 했다. 모든 규칙이 코드로 막히는 건 아니다. 내가 읽은 validate.js 범위에서는 Props 인터페이스와 hex 색 두 가지였고, 나머지(파일 나누기, hooks 분리 등)는 문서로 부탁하는 수준이다.

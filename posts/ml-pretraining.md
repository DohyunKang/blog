LLM은 한 번에 만들어지지 않는다. 인터넷 글을 읽으며 다음 단어를 맞히는 사전학습, 질문에 답하는 법을 보여 주는 지시 튜닝(SFT), 사람이 더 낫다고 고른 쪽으로 밀어 주는 선호 학습, 이렇게 세 단계를 거친다.

## 먼저 큰 그림

처음 나온 사전학습 모델은 말을 잘하지만 대화는 못 한다. "프랑스의 수도는?" 하고 물으면 답 대신 "독일의 수도는?" 같은 비슷한 질문을 이어 쓰기도 한다. 다음에 올 글을 그럴듯하게 이어 쓰는 훈련만 받았기 때문이다. 그래서 그 위에 두 단계를 더 얹는다.

| 단계 | 하는 일 | 데이터 | 결과 |
|---|---|---|---|
| 1. 사전학습 | 다음 토큰 맞히기 | 웹·책·코드 등 엄청난 양의 글 | 언어와 지식을 가진 기본 모델 |
| 2. 지시 튜닝(SFT) | 질문-답 예시를 따라 쓰기 | 사람이 쓴 모범 답안 수천~수만 건 | 지시를 알아듣는 모델 |
| 3. 선호 학습(RLHF, DPO) | 사람이 더 좋다고 고른 쪽으로 조정 | 같은 질문에 대한 답 여러 개 + 순위 | 도움이 되고 덜 해로운 말투 |

토큰이 뭔지, 모델 안에서 다음 토큰을 어떻게 계산하는지는 [자세히 → 트랜스포머](#/post/ml-transformer)와 [자세히 → LLM](#/post/ai-llm)에 따로 적었다. 여기서는 각 단계에서 무엇을 어떻게 배우는지만 본다.

## 1단계: 사전학습

방식은 단순하다. 글을 잘라 넣고, 앞 토큰들을 보고 다음 토큰을 맞히게 한다. 정답은 원문에 이미 있어서 사람이 라벨을 붙일 필요가 없다. 이런 걸 자기지도 학습이라 부른다. 틀리면 오차를 줄이는 쪽으로 파라미터를 조금씩 고친다. 이 과정을 수조 단위 토큰에 대해 반복한다. 기초 개념은 [자세히 → 머신러닝 기초](#/post/ml-basics)에 있다.

이 단계에서 문법, 상식, 코드 문법, 여러 언어가 같이 딸려 온다. 다음 단어를 잘 맞히려면 그런 걸 알아야 하기 때문이다. 대신 돈도 제일 많이 든다. 이후 두 단계는 이 단계에 비하면 데이터도 계산량도 작다.

### 모델 크기와 데이터 양

얼마나 큰 모델에 얼마나 많은 글을 먹일지가 늘 문제다. DeepMind의 Chinchilla 논문(2022)은 같은 계산 예산이라면 모델 크기와 학습 토큰 수를 같은 비율로 같이 키우는 게 낫다고 했다. 모델 크기를 두 배로 하면 데이터도 두 배로. 당시 큰 모델들은 파라미터만 키우고 데이터는 거의 그대로여서 "덜 먹은" 상태라는 주장이다. 실험으로 280B짜리 Gopher와 같은 예산에 70B 모델 + 4배 데이터(Chinchilla)를 비교했더니 Chinchilla가 여러 과제에서 이겼고, MMLU 평균 정확도는 67.5%로 Gopher보다 7점 넘게 높았다.

다만 이건 2022년 시점의 연구이고,

## 2단계: 지시 튜닝(SFT)

사전학습이 끝난 모델에게 "이런 질문엔 이렇게 답한다"를 직접 보여 주는 단계다. 사람(라벨러)이 질문과 모범 답안을 써 주고, 모델은 그 답안을 사전학습 때와 똑같은 방식(다음 토큰 맞히기)으로 따라 쓰며 배운다. 달라진 건 데이터뿐이다. 그래서 SFT는 새 지식을 넣는 단계라기보다 이미 가진 능력을 "답하는 형식"으로 꺼내 쓰게 만드는 쪽에 가깝다.

예시는 모범 답안 하나뿐이라는 한계가 있다. 같은 질문에도 좋은 답은 여러 개고, 어떤 게 더 나은지는 알려 주지 못한다. 그걸 보완하는 게 다음 단계다. 다른 목적(특정 업무에 맞추기)으로 파라미터를 더 고치는 얘기는 [자세히 → 파인튜닝](#/post/ml-finetuning)에서 다룬다.

## 3단계: 선호 학습

같은 질문에 모델이 답을 여러 개 만들면, 사람이 "이게 더 낫다" 하고 순위를 매긴다. 이 비교 데이터로 모델을 사람이 좋아하는 쪽으로 민다.

### RLHF(사람 피드백 강화학습)

OpenAI의 InstructGPT 논문(2022)이 대표 사례다. 초록에 따르면 순서는 이렇다. GPT-3를 라벨러가 쓴 모범 답안으로 먼저 미세조정하고(SFT), 모델 출력에 대한 사람의 순위 데이터를 모은 다음, 사람 피드백을 이용한 강화학습으로 다시 조정한다. 결과로 1.3B짜리 InstructGPT의 출력이 175B GPT-3의 출력보다 사람 평가에서 더 선호됐다. 파라미터가 약 100배 작은데도 그랬다. 더 진실하고 덜 유해했고, 공개 NLP 벤치마크 성능 하락은 거의 없었다. 그래도 간단한 실수는 여전히 했다고 한다.

<details>
<summary>자세한 풀이: RLHF 안에서 실제로 하는 일</summary>

보통 RLHF는 둘로 나뉘어 설명된다.

1. 보상 모델 학습: 사람이 매긴 순위 데이터를 보고 "이 답은 점수 몇 점"을 내놓는 별도 모델을 학습한다. 사람 대신 점수를 매겨 주는 심판이다.
2. 강화학습: 모델이 답을 만들고, 보상 모델이 점수를 주고, 점수가 높아지는 쪽으로 모델을 고친다. 이때 원래 모델에서 너무 멀리 벗어나지 않도록 제한을 건다. 안 그러면 점수만 높고 이상한 말을 하게 된다.


</details>

### DPO

RLHF는 보상 모델을 따로 만들고 강화학습까지 돌려야 해서 복잡하고 불안정하다는 불만이 있었다. DPO(Direct Preference Optimization, 2023)는 이걸 줄인다. 논문 초록에 따르면 보상 모델을 다시 표현해 최적 정책을 닫힌 형태로 구할 수 있게 하고, 그 덕에 RLHF 목표를 간단한 분류 손실로 바꾼다. 별도의 보상 모델도, 학습 도중 모델 출력을 샘플링하는 과정도 필요 없다. 저자들은 요약과 단일 턴 대화에서 기존 방법과 같거나 더 낫다고 보고한다.

쉽게 말하면, "좋은 답 A와 나쁜 답 B 쌍"을 그대로 넣고 A의 확률은 올리고 B의 확률은 내린다. 구현이 훨씬 단순해서 널리 쓰이게 됐다. 그렇다고 RLHF가 사라졌다는 뜻은 아니고, 어느 쪽을 쓰는지는 모델마다 다르다.

## 사전학습 데이터는 어디서 오나

대체로 웹 크롤링, 책, 코드 저장소, 논문 같은 공개 텍스트다. 같은 글이 여러 번 들어 있거나 품질이 낮은 글이 섞여 있어서 중복 제거, 품질 필터링, 유해 글 걸러내기 같은 정제를 한다고 알려져 있다. 개별 상용 모델이 정확히 어떤 데이터를 얼마나 썼는지는 대부분 공개되지 않는다.

## 이걸 알면 보이는 것

- 모델이 그럴듯한 거짓말을 하는 건 사전학습이 "맞는 말"이 아니라 "다음에 올 법한 말"을 맞히는 훈련이어서다. 선호 학습이 어느 정도 보정하지만 완전히 없애지는 못한다. 더 알고 싶으면 [자세히 → 환각](#/post/ai-hallucination).
- 답변 말투가 비슷비슷하게 공손한 건 3단계에서 사람이 고른 쪽으로 밀렸기 때문이다.
- 같은 모델에서도 답이 매번 다른 건 학습이 아니라 추론 때의 샘플링 때문이다. [자세히 → 샘플링](#/post/ai-sampling).

## 흔한 오해

- 사용자 대화로 모델이 실시간 학습한다: 쓰는 도중에는 파라미터가 바뀌지 않는다. 대화 내용은 입력으로 들어갈 뿐이다. 다음 버전 학습에 쓰이는지는 서비스 약관의 문제다.
- RLHF가 지식을 넣는다: 지식은 거의 사전학습에서 온다. 선호 학습은 말하는 방식과 태도를 조정한다.
- 파라미터가 크면 무조건 낫다: InstructGPT는 1.3B가 175B보다 선호됐고, Chinchilla는 작은 모델에 데이터를 더 먹여 이겼다. 크기만이 아니라 데이터 양과 후속 단계도 영향이 크다.
- DPO는 RLHF와 완전히 다른 것: 둘 다 사람 선호 데이터를 쓴다. 보상 모델과 강화학습 단계를 건너뛰는 게 차이다.
